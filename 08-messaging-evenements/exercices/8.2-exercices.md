## Exercice 1 — Compréhension : ce qui reste après un arrêt

*Niveau 1. Aucune ligne de code à écrire.*

### 1.a — Quatre arrêts

Pour chaque moment où le programme s'arrête, dis ce qu'il reste dans la
base et chez le courtier, et ce que voient les abonnés.

1. `CommitThenPublish`, entre le `Exec` et le `Publish`.
2. `PublishThenCommit`, entre le `Publish` et le `Exec`.
3. `WithOutbox`, entre l'insertion de la cotisation et `outbox.Append`.
4. Le relais, après avoir publié le cinquième événement d'un lot de dix,
   avant le `UPDATE`.

### 1.b — Trois pourquoi

1. Pourquoi « publier puis valider » donne-t-il 51 fantômes, et pas 31 ?
2. Pourquoi quatre relais avec un `SELECT` simple sont-ils aussi lents
   qu'un seul ?
3. Pourquoi `SKIP LOCKED` sans parts inverse-t-il des événements d'un
   même tour ?

### 1.c — Le choix du relais

Pourquoi le relais publie-t-il, puis coche, et pas l'inverse ? Que
faudrait-il pour que l'inverse soit acceptable ?

## Exercice 3 — Refactoring : fermer un tour sans perdre l'annonce

*Niveau 3. Réécrire une fermeture avec l'outbox ; les tests sont
fournis.*

```go
// Close marks the round closed and announces RoundClosed, with the round
// as key; the event exists if, and only if, the round was closed by this
// call. The relay of the outbox publishes it.
//
// Today Close updates, then publishes directly to the sink.
func (c *Closer) Close(ctx context.Context, round string) error {
    var beneficiary string
    var pot int64
    err := c.Pool.QueryRow(ctx,
        `UPDATE rounds SET closed = true WHERE id = $1 AND NOT closed RETURNING beneficiary, pot`, round).
        Scan(&beneficiary, &pot)
    if err != nil {
        return ErrAlreadyClosed
    }
    if c.Crash != nil && c.Crash() {
        return ErrCrash
    }
    body, _ := json.Marshal(map[string]any{"round": round, "beneficiary": beneficiary, "pot": pot})
    return c.Sink.Publish(ctx, sink.Message{Key: round, Kind: "RoundClosed", Body: body})
}
```

## Exercice 5 — Incident : les reçus en double du 30 novembre

*Niveau 7. Un incident à mesurer, puis à rejouer comme il aurait dû
être fait.*

Le lundi 30 novembre 2026, dernier jour du mois, les paiements publient
puis valident. Des membres appuient deux fois sur « payer » ; un
déploiement à 14 h arrête le programme au milieu de 25 cotisations. Le
soir, le tableau des tours annonce plusieurs tours complets que la
trésorière ne retrouve pas dans ses comptes.

```go
// Day records the contributions of the day with way ("publish, then
// commit" or "outbox"), and returns what the database recorded: the
// amount of each contribution.
func Day(ctx context.Context, pool *pgxpool.Pool, s *sink.Sink, way string) (map[string]int64, error) {
    i := 0
    r := &record.Recorder{Pool: pool, Sink: s, Crash: func() bool { return i >= 700 && i < 725 }}
    for i = range Contributions {
        c := record.Contribution{ID: fmt.Sprintf("c%04d", i), Member: fmt.Sprintf("m%03d", i%300), Round: fmt.Sprintf("r%02d", i%48), Amount: 10000}
        taps := 1
        if i%16 == 3 {
            taps = 2 // the member did not see the first answer, and tapped again
        }
        for range taps {
            var err error
            if way == "outbox" {
                err = r.WithOutbox(ctx, c)
            } else {
                err = r.PublishThenCommit(ctx, c)
            }
            if err != nil && !errors.Is(err, record.ErrCrash) && !isDuplicate(err) {
                return nil, err
            }
        }
    }
    if way == "outbox" {
        if err := (&outbox.Relay{Pool: pool, Sink: s, Batch: 100}).Run(ctx); err != nil {
            return nil, err
        }
    }
    recorded := map[string]int64{}
    rows, err := pool.Query(ctx, `SELECT id, amount FROM contributions`)
    if err != nil {
        return nil, err
    }
    defer rows.Close()
    for rows.Next() {
        var id string
        var amount int64
        if err := rows.Scan(&id, &amount); err != nil {
            return nil, err
        }
        recorded[id] = amount
    }
    return recorded, rows.Err()
}
```
