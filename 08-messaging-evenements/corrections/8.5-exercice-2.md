# Correction 8.5 — Exercice 2 : les sagas bloquées

> Rappel de l'énoncé : écrire `Stuck`, qui rend les sagas restées trop
> longtemps dans leur étape, la plus ancienne d'abord.

La solution est dans `ex2` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Chaque étape a sa limite**, et une limite par défaut pour les
  autres.
- **Les étapes terminales** ne sont jamais bloquées.
- **Le tri** met la plus vieille en tête : c'est celle qu'on regarde
  d'abord.

## 1. La solution

```go
func Stuck(sagas []Saga, now time.Time, limits map[string]time.Duration, fallback time.Duration, done map[string]bool) []Alert {
    var out []Alert
    for _, s := range sagas {
        if done[s.Step] {
            continue
        }
        limit, ok := limits[s.Step]
        if !ok {
            limit = fallback
        }
        if age := now.Sub(s.Since); age > limit {
            out = append(out, Alert{ID: s.ID, Step: s.Step, For: age})
        }
    }
    slices.SortFunc(out, func(a, b Alert) int { return cmp.Compare(b.For, a.For) })
    return out
}
```

## 2. La limite de « money sent »

C'est l'étape la plus dangereuse : **l'argent est chez le membre, et le
prêt n'est pas encore enregistré**. Si la saga s'arrête là, personne ne
réclamera jamais ce prêt. L'étape suivante (activer le prêt) est une
écriture locale qui prend quelques millisecondes ; une saga qui y reste
plus de **cinq minutes** est en panne, pas lente. La limite est donc la
plus courte, et l'alerte réveille quelqu'un.

À l'inverse, « releasing guarantee » peut attendre une heure : une
garantie bloquée gêne le membre, elle ne fait pas perdre d'argent.

| Étape | Limite | Ce qu'elle coûte si elle dure |
|---|---|---|
| money sent | 5 min | de l'argent dehors, sans dette |
| guarantee reserved | 10 min | un membre qui attend sa réponse |
| started | 15 min (défaut) | une demande qui n'avance pas |
| releasing guarantee | 1 h | une garantie bloquée pour rien |

## 3. Où la faire tourner

`Stuck` lit la table des sagas, toutes les minutes. Elle demande un index
sur `(step, since)` : la requête ne lit que les sagas non terminées,
quelques dizaines, même avec des millions de sagas terminées dans la
table.

## Ce qu'il faut retenir

- Une limite par étape, selon ce que coûte son retard.
- L'étape juste après le point de non-retour a la limite la plus courte.
- La plus ancienne d'abord.
