# Correction 8.5 — Exercice 3 : verser une cagnotte

> Rappel de l'énoncé : réordonner la saga du versement pour que tout ce
> qui peut dire non passe avant l'envoi, et qu'un délai dépassé soit une
> question.

La solution est dans `ex3` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Fermer le tour d'abord** : c'est la seule étape métier qui peut
  refuser.
- **L'envoi est le point de non-retour** ; un refus rouvre le tour, un
  délai dépassé interroge l'opérateur.
- **Après l'envoi**, l'inscription dans les comptes ne fait que suivre.

## 1. La solution

```go
func Payout(ctx context.Context, t Tontines, o Operator, b Books, round string, pot int64) error {
    // 1. May say no: before the money.
    if err := t.Close(ctx, round); err != nil {
        return err
    }
    // 2. The pivot.
    key := "payout-" + round
    sent := false
    var last error
    for range sendAttempts {
        err := o.Send(ctx, key, pot)
        if err == nil {
            sent = true
            break
        }
        if !errors.Is(err, ErrTimeout) {
            last = err
            break // a refusal: compensate
        }
        if ok, serr := o.Status(ctx, key); serr == nil && ok {
            sent = true
            break
        }
        last = err // not sent: the same key may be tried again
    }
    if !sent {
        if err := t.Reopen(ctx, round); err != nil {
            return fmt.Errorf("%w; and reopening failed: %w", last, err)
        }
        return last
    }
    // 3. After the pivot: only forward.
    return b.Record(ctx, round, pot)
}
```

Le code d'origine envoyait d'abord, puis fermait le tour : une
annulation découverte à la fermeture arrivait **après** l'argent. Il
suffisait de changer l'ordre ; c'est souvent tout le travail de
conception d'une saga.

## 2. Si l'inscription dans les comptes échoue

Elle est après le point de non-retour : on ne rouvre pas le tour, on ne
rappelle pas l'argent. On **réessaie l'inscription**, jusqu'à ce qu'elle
passe, avec une clé (le tour) qui la rend idempotente. Si les comptes
sont fermés (une clôture mensuelle), l'inscription attend leur
réouverture, et la saga reste dans l'étape « argent envoyé, à inscrire »,
que la surveillance de l'exercice 2 montre.

Ce `Payout` est une fonction, pas encore une saga complète : elle n'a
pas d'état enregistré. Si le programme s'arrête entre l'envoi et
l'inscription, rien ne reprend. La version complète enregistre l'étape
après chaque appel, comme l'orchestrateur de la leçon.

## Ce qu'il faut retenir

- Réordonner les étapes est le premier outil d'une saga.
- Après le point de non-retour, on réessaie ; on ne compense plus.
- Une fonction sans état enregistré n'est pas encore une saga.
