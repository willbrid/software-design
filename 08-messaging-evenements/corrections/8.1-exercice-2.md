# Correction 8.1 — Exercice 2 : vérifier le câblage au démarrage

> Rappel de l'énoncé : écrire `Check`, qui trouve dans le câblage les
> événements sans auditeur ou sans émetteur, et les commandes sans
> destinataire ou avec plusieurs.

La solution est dans `ex2` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Quatre ensembles à comparer** : ce qui est publié et écouté, ce qui
  est envoyé et traité.
- **Les doublons se retirent** avant de comparer : un événement publié
  par deux parties n'est vérifié qu'une fois.
- **Un seul des quatre problèmes est toujours une erreur grave** : la
  commande sans destinataire.

## 1. La solution

```go
// Check returns the problems of w, sorted by name, then by what.
func Check(w Wiring) []Problem {
    var out []Problem
    published := set(w.Publishes)
    for e := range published {
        if len(w.Subscribes[e]) == 0 {
            out = append(out, Problem{e, NobodyListens})
        }
    }
    for e, parts := range w.Subscribes {
        if len(parts) > 0 && !published[e] {
            out = append(out, Problem{e, NobodyPublishes})
        }
    }
    for c := range set(w.Sends) {
        if len(w.Handles[c]) == 0 {
            out = append(out, Problem{c, NobodyHandles})
        }
    }
    for c, parts := range w.Handles {
        if len(parts) > 1 {
            out = append(out, Problem{c, TwoHandlers})
        }
    }
    slices.SortFunc(out, func(a, b Problem) int {
        return cmp.Or(cmp.Compare(a.Name, b.Name), cmp.Compare(a.What, b.What))
    })
    return out
}
```

Les quatre boucles parcourent des maps, dont l'ordre change à chaque
exécution : le tri final rend la sortie stable, et les tests possibles.

## 2. Lequel n'est pas toujours une erreur ?

| Problème | Grave ? |
|---|---|
| commande envoyée, personne ne la traite | **toujours** : l'expéditeur attend un résultat qui ne viendra pas ; `Send` échouera à chaque appel |
| commande traitée par deux parties | **toujours** : deux versements pour un ordre |
| événement écouté, personne ne le publie | **presque toujours** : c'est la signature d'un renommage ou d'une faute de frappe ; l'abonné attend un fait qui n'arrivera plus |
| événement publié, personne ne l'écoute | **pas forcément** : un émetteur peut publier un fait avant que quiconque en ait besoin ; c'est même le principe du découplage |

Le quatrième est un **avertissement**, pas une erreur. La vérification au
démarrage refuse de démarrer sur les trois premiers, et note le
quatrième dans le journal. Le renommage de l'exercice 5 produit les deux
derniers à la fois : c'est le premier, « écouté, personne ne le
publie », qui doit arrêter le déploiement.

## 3. Où la placer

Dans un seul programme, `Check` tourne au démarrage, sur ce que les
parties ont déclaré au bus. Entre plusieurs programmes, aucun ne voit tout
le câblage : la même vérification tourne dans la chaîne d'intégration,
sur un catalogue des messages (exercice 4) que chaque équipe tient à
jour, comme les contrats de la leçon 6.4.

## Ce qu'il faut retenir

- Le câblage se vérifie comme un contrat : au démarrage, ou dans la
  chaîne d'intégration.
- Un événement écouté que personne ne publie est presque toujours un
  renommage.
- Un événement sans auditeur est un avertissement, pas une erreur.
