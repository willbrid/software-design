# Correction 8.1 — Exercice 3 : verser, puis annoncer

> Rappel de l'énoncé : réécrire la fermeture d'un tour pour qu'une panne
> du SMS ne la fasse plus échouer, sans annoncer un tour non versé.

La solution est dans `ex3` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Le versement reste une commande**, appelée directement, et son refus
  fait échouer la fermeture.
- **Les trois réactions deviennent des abonnés** de `RoundClosed`, publié
  seulement après le versement.
- **Le champ `Notifiers` disparaît** : la fermeture ne sait plus qui
  écoute.

## 1. La solution

```go
// Tontine closes rounds.
type Tontine struct {
    Payer Payer
    Bus   *bus.Bus
}
```

```go
// Wire subscribes each notifier to RoundClosed, under its name.
func Wire(b *bus.Bus, notifiers map[string]Notifier) {
    for name, n := range notifiers {
        b.Subscribe("RoundClosed", name, func(ctx context.Context, m bus.Message) error {
            e := m.(RoundClosed)
            return n.RoundClosed(ctx, e.Round, e.Beneficiary, e.Pot)
        })
    }
}
```

```go
// Close orders the payout and, once it is done, announces RoundClosed; a
// refused payout fails the closure and announces nothing. A notifier
// that is down does not fail the closure.
func (t *Tontine) Close(ctx context.Context, round, beneficiary string, pot int64) error {
    if err := t.Payer.PayOut(ctx, round, beneficiary, pot); err != nil {
        return fmt.Errorf("pay out: %w", err)
    }
    t.Bus.Publish(RoundClosed{Round: round, Beneficiary: beneficiary, Pot: pot})
    return nil
}
```

L'ordre compte : **verser, puis annoncer**. Annoncer d'abord ferait
envoyer à la bénéficiaire un SMS « votre cagnotte est versée » pour un
versement qui peut encore être refusé.

## 2. Pourquoi le versement n'est pas un abonné

Les tontines **ont besoin** que la cagnotte soit versée : si elle ne
l'est pas, le tour ne doit pas se fermer, et quelqu'un doit le savoir
tout de suite. Un abonné de `RoundClosed` qui échoue serait réessayé en
silence, et la fermeture aurait déjà répondu « fait ». C'est la section 4
de la leçon : un événement ne transporte pas une obligation.

Le SMS, les statistiques et la trésorière, au contraire, ne changent rien
à la fermeture : s'ils apprennent la nouvelle avec une minute de retard,
le tour est quand même fermé et payé.

## 3. Ce qui reste fragile

Si le programme s'arrête **entre** le versement et la publication, la
cagnotte est versée et personne n'est prévenu : le bus est en mémoire.
La leçon 8.2 enregistre l'événement dans la même transaction que le
changement d'état, pour qu'il parte même après un arrêt.

## Ce qu'il faut retenir

- Ce dont l'action a besoin reste un appel, ou une commande, qui répond.
- Ce qui réagit à l'action devient un abonné.
- On annonce un fait une fois qu'il est vrai.
