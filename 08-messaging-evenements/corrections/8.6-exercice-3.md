# Correction 8.6 — Exercice 3 : reconstruire sans envoyer

> Rappel de l'énoncé : reconstruire la table des relances depuis le
> journal sans envoyer un seul SMS, et remettre la vraie passerelle
> ensuite, sans que `Handle` le sache.

La solution est dans `ex3` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Une passerelle muette** remplace la vraie pendant la reconstruction.
- **`defer`** remet la vraie, même quand la reconstruction échoue.
- **`Handle` ne change pas** : la logique du domaine ne sait pas qu'elle
  est rejouée.

## 1. La solution

```go
// muted is the gateway of a replay: the SMS were sent the first time.
type muted struct{}
```

```go
func Rebuild(r *Reminders, log []store.Event) error {
    live := r.Gateway
    r.Gateway = muted{}
    defer func() { r.Gateway = live }()
    r.Sent = nil
    for _, e := range log {
        if e.Type != "DeadlinePassed" {
            continue
        }
        if err := r.Handle(e); err != nil {
            return err
        }
    }
    return nil
}
```


Le troisième test vérifie le `defer` : une reconstruction qui échoue au
deuxième événement doit quand même remettre la vraie passerelle. Sans
lui, le programme continuerait avec une passerelle muette, et plus
aucune relance ne partirait, sans erreur.

## 2. Pourquoi pas un paramètre `replaying`

Un paramètre oblige **chaque** gestionnaire à y penser, et à le
transmettre à chaque appel qui sort vers le monde. Le jour où un
développeur ajoute un appel (un courriel à la trésorière) et oublie le
test `if !replaying`, le prochain rejeu envoie les courriels. La
passerelle muette met la décision **à un seul endroit** : la
reconstruction. C'est la recommandation de Martin Fowler : le domaine
appelle la passerelle de la même façon, qu'il soit rejoué ou non.

Le prix : la reconstruction ne doit pas tourner **en même temps** que le
traitement normal sur le même objet `Reminders`, puisqu'elle change sa
passerelle. En production, on reconstruit une **nouvelle** table, avec un
nouvel objet, à côté de l'ancienne, puis on bascule.

## Ce qu'il faut retenir

- Couper les effets à un seul endroit : la passerelle.
- `defer` pour remettre ce qu'on a changé, même en cas d'erreur.
- Reconstruire à côté, puis basculer.
