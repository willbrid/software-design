# Correction 8.3 — Exercice 3 : un score qui supporte tout

> Rappel de l'énoncé : réécrire le score de prêt pour qu'il supporte les
> doublons et le désordre, sans table `inbox`.

La solution est dans `ex3` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **On garde les faits**, pas le total : une ligne par cotisation, avec
  son état et la séquence du dernier événement appliqué.
- **Le score se compte à la lecture**.
- **Un doublon réécrit le même état** ; un événement plus ancien est
  ignoré.

## 1. La solution

// Schema keeps the facts, not the total: one row per contribution, with

```go
// Handle applies m. It gives the same score whatever the number of
// deliveries of each event and whatever their order: it records the
// state of the contribution, if m is newer than what it has.
func (s *Scores) Handle(ctx context.Context, m delivery.Message) error {
    var b body
    if err := json.Unmarshal(m.Body, &b); err != nil {
        return err
    }
    _, err := s.Pool.Exec(ctx, `
        INSERT INTO member_contributions (contribution, member, reversed, seq) VALUES ($1, $2, $3, $4)
        ON CONFLICT (contribution) DO UPDATE SET reversed = excluded.reversed, seq = excluded.seq
        WHERE member_contributions.seq < excluded.seq`,
        b.Contribution, b.Member, m.Kind == "ContributionReversed", m.Seq)
    return err
}
```

```go
// Score returns the score of member, counted when it is read.
func (s *Scores) Score(ctx context.Context, member string) (int, error) {
    var n int
    err := s.Pool.QueryRow(ctx, `SELECT count(*) FROM member_contributions WHERE member = $1 AND NOT reversed`, member).Scan(&n)
    return n, err
}
```

Le total disparaît de la base : il est calculé par `count(*)`, avec un
index sur `member`. Pour un membre et ses quelques dizaines de
cotisations, la lecture coûte moins d'une milliseconde. Si le score
devenait coûteux à calculer, on le garderait comme un cache recalculé
depuis les faits (leçon 5.6), jamais comme la source.

## 2. Le test qui passait déjà

`TestAReversalAheadOfItsRecording` passe avec le code d'origine : `-1`
puis `+1` puis `+1` donne `1`, comme dans l'ordre. **Une somme supporte le
désordre.** Ce qui cassait le code d'origine, c'était le doublon, pas le
désordre. Le désordre casse l'autre famille, celle qui pose un état sans
séquence, comme `LastWriteWins` dans la leçon.

## 3. Pourquoi sans inbox

L'inbox aurait corrigé les doublons du code d'origine. Mais garder les
faits rend aussi possible ce que l'inbox ne donne pas : **recalculer**.
Le jour où la règle du score change (les cotisations des six derniers
mois seulement), le nouveau score se calcule depuis les lignes déjà là ;
avec un total incrémenté, il faudrait rejouer tous les événements depuis
le début (leçon 8.6).

## Ce qu'il faut retenir

- Garder les faits, compter à la lecture.
- Un état séquencé supporte le doublon et le désordre.
- Une somme supporte le désordre, pas le doublon.
