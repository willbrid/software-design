# Correction 11.3 — Exercice 4 : l'association dans toutes les clés

> Rappel de l'énoncé : passer `members (id)` et `contributions
> (member_id)` à des clés qui commencent par `tenant_id`, sans arrêter
> le service.

## En bref

- **Étendre** : ajouter `tenant_id` partout où il manque, le remplir par
  lots, créer les nouveaux index `CONCURRENTLY`, les nouvelles
  contraintes `NOT VALID`.
- **Basculer** : le code écrit et lit avec `tenant_id`, puis les
  nouvelles contraintes remplacent les anciennes.
- **Contracter** : supprimer les anciennes contraintes et index.

## 1. Les étapes

| # | Étape | Verrou | Retour arrière |
|---|---|---|---|
| 1 | `ALTER TABLE contributions ADD COLUMN tenant_id text` | court | supprimer la colonne |
| 2 | déploiement A : le code écrit `tenant_id` à chaque nouvelle cotisation | aucun | redéployer l'ancien code |
| 3 | remplir `contributions.tenant_id` par lots, depuis `members` | lignes | rien à défaire |
| 4 | `CHECK (tenant_id IS NOT NULL) NOT VALID`, `VALIDATE`, `SET NOT NULL` | court ; `VALIDATE` ne bloque pas les écritures | supprimer la contrainte |
| 5 | `CREATE UNIQUE INDEX CONCURRENTLY members_tenant_id ON members (tenant_id, id)` | aucun pour les écritures | supprimer l'index |
| 6 | `ADD FOREIGN KEY (tenant_id, member_id) REFERENCES members (tenant_id, id) NOT VALID`, puis `VALIDATE` | court, puis lecture | supprimer la contrainte |
| 7 | déploiement B : toutes les requêtes filtrent par `tenant_id`, les index composites servent | aucun | redéployer A |
| 8 | supprimer l'ancienne clé étrangère, puis remplacer la clé primaire de `members` par `(tenant_id, id)` en s'appuyant sur l'index unique (`ADD PRIMARY KEY USING INDEX`) | court | irréversible sans recréer l'ancienne : vient en dernier |

## 2. Combien de temps

Le remplissage de 40 millions de lignes, par lots de 5 000 avec une
courte pause, prend quelques heures ; les index `CONCURRENTLY` sur 40
millions de lignes, de l'ordre de l'heure chacun (la leçon 11.1 donne la
méthode : mesurer sur une copie). Avec les deux déploiements et une
période d'observation entre chaque étape, le tout prend une à deux
semaines, sans aucune interruption.

## 3. Ce qui se dit en entretien

- Chaque étape convient au code d'avant et au code d'après.
- Les étapes destructrices viennent en dernier, une par une.
- On mesure chaque étape sur une copie de la production avant de la
  lancer, et on la lance avec `lock_timeout`.
- On n'a pas besoin d'une fenêtre de maintenance ; on a besoin de
  patience.

## Ce qu'il faut retenir

- Un changement de clé est une suite d'extensions, de bascules et de
  contractions.
- Les contraintes et index se créent sans bloquer, puis se valident.
- La durée se compte en jours, et c'est normal.
