# Correction 11.4 — Exercice 2 : le pire arriéré

> Rappel de l'énoncé : écrire `Backlog`, le plus grand nombre
> d'écritures confirmées mais pas encore sur la réplique, et le premier
> instant où il est atteint.

La solution est dans `ex2` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Deux événements par écriture** : elle entre dans l'arriéré à sa
  confirmation, elle en sort à sa réplication.
- **À instant égal, la sortie avant l'entrée** : c'est la définition de
  `replica.Lost`.
- **Le premier instant du maximum**, pour que le test retrouve la même
  perte.

## 1. La solution

```go
func Backlog(ws []replica.Write) (most int, at time.Duration) {
    type event struct {
        at    time.Duration
        delta int
    }
    events := make([]event, 0, 2*len(ws))
    for _, w := range ws {
        events = append(events, event{w.Committed, +1}, event{w.Replicated, -1})
    }
    // At the same instant, a write that reaches the replica leaves the
    // backlog before a write that is committed enters it.
    slices.SortFunc(events, func(a, b event) int {
        if c := cmp.Compare(a.at, b.at); c != 0 {
            return c
        }
        return cmp.Compare(a.delta, b.delta)
    })
    now := 0
    for _, e := range events {
        now += e.delta
        if now > most {
            most, at = now, e.at
        }
    }
    return most, at
}
```

## 2. Les égalités

À l'instant 5, deux écritures arrivent sur la réplique au moment où une
troisième est confirmée. Si l'entrée passe avant les sorties, l'arriéré
monte un instant à 3, ce qui n'a jamais été vrai : `replica.Lost` dirait
qu'un sinistre à 5 perd 1 écriture. Le test `TestBacklogTies` l'a
ajouté ; la campagne avait d'abord laissé passer l'ordre inverse.

## 3. En production

On ne connaît pas l'instant de réplication de chaque écriture, mais
PostgreSQL donne, pour chaque réplique, la position du journal qu'elle a
reçue, écrite et appliquée, et le retard en temps (la vue
`pg_stat_replication`). On surveille le **retard en secondes** et la
**quantité de journal en retard** ; multipliés par le débit d'écriture
au pic, ils donnent l'ordre de grandeur de l'arriéré. Une alerte se
déclenche quand le retard dépasse le RPO.

## Ce qu'il faut retenir

- Un arriéré se calcule par un balayage des entrées et des sorties.
- L'ordre des événements simultanés fait partie de la définition.
- En production, on surveille le retard de la réplique contre le RPO.
