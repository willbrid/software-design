# Correction 11.1 — Exercice 2 : le pic d'une série

> Rappel de l'énoncé : écrire `Peak`, qui trouve la fenêtre la plus
> chargée et la compare à la moyenne.

La solution est dans `ex2` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Compter par fenêtre**, en ignorant ce qui est hors de la période.
- **La dernière fenêtre peut être plus courte** : elle compte quand
  même.
- **Aucun événement donne 0**, pas une division par zéro.

## 1. La solution

```go
func Peak(events []time.Time, from, to time.Time, w time.Duration) (busiest int, factor float64) {
    windows := int((to.Sub(from) + w - 1) / w)
    counts := make([]int, windows)
    total := 0
    for _, e := range events {
        if e.Before(from) || !e.Before(to) {
            continue
        }
        counts[e.Sub(from)/w]++
        total++
    }
    if total == 0 {
        return 0, 0
    }
    busiest = slices.Max(counts)
    return busiest, float64(busiest) / (float64(total) / float64(windows))
}
```

## 2. Les deux cas qu'a trouvés la campagne

- **La dernière fenêtre** : 65 s en fenêtres de 30 s font trois
  fenêtres, la dernière de 5 s. Arrondir le nombre de fenêtres vers le
  bas fait tomber les événements de la fin hors du tableau (et le
  programme s'arrête). Le cas « a last, shorter window » a été ajouté.
- **Rien à compter** : sans la garde, `0 / (0 / n)` donne `NaN`, et le
  test d'origine, qui comparait avec `math.Abs(…) > 1e-9`, ne le voyait
  pas : toute comparaison avec `NaN` est fausse. Le test compare
  maintenant avec `!(… <= 1e-9)`, qui échoue sur `NaN`.

## 3. Quelles fenêtres, pour quoi

| Fenêtre | Sert à dimensionner |
|---|---|
| la seconde | la base, le pool, les limites des opérateurs, les quotas d'API |
| la minute | les files de travaux, les rafales après un rappel |
| l'heure | les équipes d'astreinte, les fenêtres de maintenance |
| le jour | le disque, les sauvegardes, la facture des fournisseurs |

## Ce qu'il faut retenir

- Le pic dépend de la fenêtre : on la choisit d'après la ressource.
- Une période qui ne tombe pas juste a une dernière fenêtre plus courte.
- Un test qui compare des flottants doit échouer sur `NaN`.
