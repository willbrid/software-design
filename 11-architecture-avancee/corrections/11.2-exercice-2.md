# Correction 11.2 — Exercice 2 : les partitions d'avance

> Rappel de l'énoncé : écrire `Ahead`, qui crée les partitions manquantes
> du mois courant et des mois suivants, et ne crée rien la seconde fois.

La solution est dans `ex2` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Partir du premier jour du mois courant**, pas du jour courant.
- **Vérifier l'existence avec `to_regclass`**, et ne créer que ce qui
  manque.
- **Le mois courant compte** : un travail qui rate le 1er doit pouvoir
  le rattraper.

## 1. La solution

```go
func Ahead(ctx context.Context, pool *pgxpool.Pool, now time.Time, ahead int) ([]string, error) {
    now = now.UTC()
    first := time.Date(now.Year(), now.Month(), 1, 0, 0, 0, 0, time.UTC)
    var created []string
    for m := range ahead + 1 {
        from := first.AddDate(0, m, 0)
        name := "contributions_" + from.Format("2006_01")
        var exists bool
        if err := pool.QueryRow(ctx, `SELECT to_regclass($1) IS NOT NULL`, name).Scan(&exists); err != nil {
            return created, err
        }
        if exists {
            continue
        }
        if err := partition.Months(ctx, pool, from, 1); err != nil {
            return created, err
        }
        created = append(created, name)
    }
    return created, nil
}
```

## 2. Si le travail n'a pas tourné

Le 1er décembre à 0 h 01, la première cotisation de décembre ne trouve
pas de partition : l'insertion échoue (`no partition of relation
"contributions" found for row`). Toutes les cotisations échouent jusqu'à
ce que quelqu'un crée la partition. C'est une panne totale, programmée
d'avance.

Pour la voir avant :

- le travail crée **plusieurs** mois d'avance (trois dans le test) : un
  oubli d'un mois ne casse rien ;
- une alerte surveille « nombre de mois futurs ayant une partition », et
  sonne sous deux ;
- un test d'intégration insère une ligne datée du mois suivant.

On peut aussi créer une partition par défaut (`DEFAULT`), qui reçoit les
lignes sans partition. Elle évite la panne, mais il faut ensuite
déplacer ses lignes vers la bonne partition, ce qui bloque ; on la garde
comme filet, surveillée, et elle doit rester vide.

## Ce qu'il faut retenir

- Les partitions se créent d'avance, par un travail qu'on peut relancer.
- Une partition manquante est une panne à date fixe.
- On surveille l'avance, pas seulement le succès du travail.
