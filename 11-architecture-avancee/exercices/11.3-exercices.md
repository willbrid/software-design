# Exercices 11.3 — Changer sans arrêter

Cinq exercices, du plus simple au plus ouvert. Traite-les **dans l'ordre** et
écris tes réponses dans `mes-reponses/` avant d'ouvrir les corrections.

Les exercices s'appuient sur les paquets de la
[leçon 11.3](../cours/11.3-changer-sans-arreter.md) (`internal/pg`,
`migrate`, `rename`), recopiés tels quels dans le module des exercices.
Ils utilisent le PostgreSQL 17 du niveau 5 (`sd-pg`, port 55432). Tout
le code ci-dessous compile et passe `go vet` ; l'incident est **fictif**.

---

## Exercice 1 — Compréhension : bloque, bloque pas ?

*Niveau 1. Aucune ligne de code à écrire.*

### 1.a — Six instructions

Pour chacune, sur une table de deux millions de lignes en production,
dis si elle bloque les écritures, combien de temps à peu près, et ce que
tu ferais à la place.

1. `ALTER TABLE members ADD COLUMN locale text DEFAULT 'fr'`
2. `ALTER TABLE members ADD COLUMN created_at timestamptz DEFAULT now()`
3. `ALTER TABLE members ALTER COLUMN phone TYPE varchar(20)`
4. `CREATE UNIQUE INDEX ON members (phone)`
5. `ALTER TABLE members ADD FOREIGN KEY (tenant_id) REFERENCES associations (id)`
6. `ALTER TABLE members RENAME TO people`

### 1.b — Trois pourquoi

1. Pourquoi une migration instantanée peut-elle bloquer tout le monde
   pendant des secondes ?
2. Pourquoi la recopie de l'expansion doit-elle attendre le départ de
   la dernière ancienne instance ?
3. Pourquoi la contraction (supprimer l'ancienne colonne) vient-elle en
   dernier, et seule ?

### 1.c — Le sens des mesures

Dans `cmd/ddl`, `CREATE INDEX CONCURRENTLY` dure plus longtemps que
`CREATE INDEX`, et l'insertion la plus longue y est encore de 89 ms (et
jusqu'à 570 ms une fois). Pourquoi n'est-elle pas nulle ? Pourquoi
est-ce quand même la bonne instruction ?

## Exercice 3 — Évolution : changer un type sans réécrire la table

*Niveau 8. Écrire une migration en plusieurs étapes ; le test est fourni.*

La colonne `amount` est un `int` ; elle doit devenir un `bigint`.
`ALTER COLUMN ... TYPE bigint` réécrit la table (leçon, section 1) :

```go
// Steps returns the statements of the migration of a table whose ids go
// up to maxID, to run one after the other, each with a short lock_timeout
// and retries (migrate.Cautiously). The version below rewrites the table
// in one statement; replace it with steps that never block the writers
// for long, and end with members.amount a bigint holding every value, the
// rows written during the migration included.
func Steps(maxID int64) []string {
    return []string{
        `ALTER TABLE members ALTER COLUMN amount TYPE bigint`,
    }
}
```

## Exercice 5 — Incident : le 30 novembre à 17 h 58

*Niveau 7. Un incident à mesurer, puis à rejouer comme il aurait dû
être fait.*

Le lundi 30 novembre 2026, à 17 h 58, un déploiement ajoute une colonne
à la table des membres. Pendant deux minutes et demie, l'écran des
trésorières ne répond plus ; à 18 h, le rappel du dernier soir part. La
soirée se rejoue ainsi, le temps divisé par cinquante :

```go
// Deploy plays the evening, time shrunk fifty times: the monthly report
// reads the members (3 s here, two and a half minutes that evening); 0.5 s
// later the deploy adds a column with change; the treasurers' screen
// reads a member 200 times a second for 5 s. It returns the screens
// served.
func Deploy(ctx context.Context, change Migration) ([]Request, error) {
    pool, drop, err := pg.FreshConns(ctx, migrate.Schema, 24)
    if err != nil {
        return nil, err
    }
    defer drop()
    if err := migrate.Seed(ctx, pool, 100000); err != nil {
        return nil, err
    }
    start := time.Now()
    var wg sync.WaitGroup
    errs := make(chan error, 2)
    wg.Go(func() {
        errs <- pgx.BeginFunc(ctx, pool, func(tx pgx.Tx) error {
            if _, err := tx.Exec(ctx, `SELECT count(*) FROM members`); err != nil {
                return err
            }
            _, err := tx.Exec(ctx, `SELECT pg_sleep(3)`)
            return err
        })
    })
    wg.Go(func() {
        time.Sleep(500 * time.Millisecond)
        errs <- change(ctx, pool, `ALTER TABLE members ADD COLUMN reminder_sent_at timestamptz`)
    })
    var mu sync.Mutex
    var log []Request
    r := rand.New(rand.NewPCG(2026, 11))
    for i := range 1000 {
        at := time.Duration(i) * 5 * time.Millisecond
        time.Sleep(time.Until(start.Add(at)))
        id := 1 + r.IntN(100000)
        wg.Go(func() {
            t := time.Now()
            pool.Exec(ctx, `SELECT phone FROM members WHERE id = $1`, id)
            mu.Lock()
            log = append(log, Request{at, time.Since(t)})
            mu.Unlock()
        })
    }
    wg.Wait()
    close(errs)
    for err := range errs {
        if err != nil {
            return log, err
        }
    }
    return log, nil
}
```
