# Correction 3.6 — Exercice 3 : les alertes SMS

> Rappel de l'énoncé : dire pourquoi `alerts.Notify` ne se teste pas ;
> introduire le plus petit changement qui le permette et caractériser,
> défauts compris ; refactorer vers `Alerter` sans casser le serveur web ;
> corriger le SMS en échec ; lancer une campagne.

Tout ce qui suit est dans le module de correction, vert sous
`go vet ./...` et `go test -race -count=1 ./...` :

- `ex3/seams` : le paquet d'origine, avec deux coutures et rien d'autre ;
- `ex3/alerting` : la nouvelle forme ;
- `ex3/alerts` : l'ancien point d'entrée, réécrit au-dessus de
  `alerting` ;
- `ex3/payroll` : le premier appelant, migré.

## En bref

- **Quatre obstacles** : la passerelle est construite à l'initialisation,
  l'heure vient de `time.Now`, l'historique des alertes est global, le seuil
  est une variable exportée.
- **Deux coutures suffisent** pour caractériser : deux variables de
  paquet, `now` et `send`, que les tests remplacent. Quatre défauts sont
  épinglés, dont un que personne n'avait vu : les heures calmes suivent
  l'horloge du **serveur**, en UTC.
- **L'ancien `Notify` reste**, marqué `Deprecated`, et délègue à un
  `Alerter` construit au premier usage. Le serveur web ne change pas une
  ligne.
- **La campagne a trouvé trois trous**, dont un bout de code qui ne servait
  à rien : il a été supprimé.

## 1. Pourquoi on ne peut pas tester `Notify`

| Obstacle | Pourquoi il bloque | Ce qu'il faut |
|---|---|---|
| `gateway` est construit à l'initialisation, avec `os.Getenv("SMS_URL")` | l'URL est lue **avant** `TestMain` ; un test ne peut pas la faire pointer vers un faux serveur | lire l'URL plus tard, ou remplacer l'envoi |
| `time.Now()` | « 23 h » ou « 59 minutes plus tard » demandent d'attendre | une horloge remplaçable |
| `last`, une `map` de paquet | chaque test hérite des alertes du précédent ; impossible de tester en parallèle | un historique par instance |
| `Threshold`, exportée | un test qui la change la change pour tous, comme la promotion de la leçon | un seuil par instance |

Le premier obstacle est le plus sournois. `t.Setenv` existe, mais arrive
trop tard : la spécification initialise les variables de paquet avant
`main`, donc avant tout test. Il faudrait lancer `go test` avec
`SMS_URL=...` déjà positionnée, vers un serveur dont le port n'est connu
qu'une fois le test lancé.

## 2. Caractériser : deux coutures

Le plus petit changement possible : deux variables, que la production
laisse à leur valeur et que les tests remplacent. Michael Feathers appelle
cela une **couture** (*seam*) : un endroit où l'on peut changer le
comportement sans modifier le code qui s'en sert.

```go
// The two seams. Production uses these values; a test replaces them.
var (
    now  = time.Now
    send = func(ctx context.Context, phone, text string) error { return gateway.Send(ctx, phone, text) }
)
```

`Notify` n'appelle plus `time.Now()` ni `gateway.Send`, mais `now()` et
`send(...)`. C'est tout. Chaque test remplace les deux coutures et vide
l'historique, puis remet tout en place :

```go
func setup(t *testing.T, at time.Time) *recorder {
    r := &recorder{at: at}
    oldNow, oldSend, oldLast := now, send, last
    now = func() time.Time { return r.at }
    send = func(_ context.Context, phone, text string) error {
        if r.fail != nil {
            return r.fail
        }
        r.sent = append(r.sent, phone+": "+text)
        return nil
    }
    last = map[string]time.Time{}
    t.Cleanup(func() { now, send, last = oldNow, oldSend, oldLast })
    return r
}
```

Ces tests ne peuvent **pas** tourner en parallèle : ils partagent les
coutures. C'est le prix d'une caractérisation qui ne change rien, et une
raison de plus d'aller jusqu'au refactoring.

Les quatre défauts, chacun épinglé par un test vert sur le code
d'origine :

```go
// Flaw: the comment says "from which", the code says "above". A transfer of
// exactly one million is not alerted.
func TestFlawTheThresholdItselfIsNotAlerted(t *testing.T) {
    r := setup(t, utc(10, 0))
    Notify(context.Background(), "ACC-1", "237690000001", 1_000_000)
    if len(r.sent) != 0 {
        t.Fatalf("sent %q", r.sent)
    }
}
```

```go
// Flaw: a night transfer is never alerted, not even in the morning. A fraud
// at 23:00 is found when the customer reads the statement.
func TestFlawANightTransferIsNeverAlerted(t *testing.T) {
    r := setup(t, utc(23, 0))
    ctx := context.Background()
    Notify(ctx, "ACC-1", "237690000001", 1_500_000)
    r.at = utc(8, 0).AddDate(0, 0, 1)
    Notify(ctx, "ACC-2", "237690000002", 50_000) // the next morning, an ordinary transfer
    if len(r.sent) != 0 {
        t.Fatalf("sent %q", r.sent)
    }

```

C'est le plus grave. L'alerte existe pour qu'une fraude soit vue **en
quelques minutes** ; or les fraudes ont souvent lieu la nuit, justement.
Un virement frauduleux à 23 h n'est signalé ni à 23 h, ni à 7 h.

```go
// Flaw: the quiet hours follow the server's clock, UTC, not the customer's,
// UTC+1. At 22:30 in Douala the SMS is sent; at 07:30 in Douala it is not.
func TestFlawTheQuietHoursFollowTheServersClock(t *testing.T) {
    r := setup(t, utc(21, 30)) // 22:30 in Douala
    Notify(context.Background(), "ACC-1", "237690000001", 1_500_000)
    r.at = utc(6, 30) // 07:30 in Douala
    Notify(context.Background(), "ACC-2", "237690000002", 1_500_000)
    if len(r.sent) != 1 || r.sent[0][:12] != "237690000001" {
        t.Fatalf("sent %q, want only the 22:30 one", r.sent)
    }
}
```

Les serveurs sont en UTC, les clients en UTC+1. Les heures calmes réelles
vont de 23 h à 8 h, heure de Douala : un client est réveillé à 22 h 30, et
une fraude à 7 h 30 n'est pas signalée.

```go
// Flaw: an SMS that failed counts as sent. The next alert of the hour is
// dropped, though the customer never got the first.
func TestFlawAFailedSMSCountsAsSent(t *testing.T) {
    r := setup(t, utc(10, 0))
    ctx := context.Background()

    if err := Notify(ctx, "ACC-1", "237690000001", 1_500_000); err == nil {
        t.Fatal("no error from a failed SMS")
```

Un cinquième défaut n'a pas de test, parce qu'il ne se voit qu'en
mémoire : `last` garde une entrée par compte alerté, et n'en supprime
jamais. La mémoire du serveur grossit jusqu'au redémarrage.

## 3. Refactorer : `Alerter`

```go
// Sender sends one text message. sms.Gateway is one.
type Sender interface {
    Send(ctx context.Context, phone, text string) error
}
```

```go
type Alerter struct {
    send      Sender
    now       func() time.Time
    loc       *time.Location // where the quiet hours are read
    threshold int64          // transfers above it are alerted

    mu   sync.Mutex
    last map[string]time.Time // account -> time of the last alert sent
}
```

```go
// New returns an Alerter. loc is the zone of the quiet hours: time.Local
// keeps the old behaviour, the customer's zone fixes it.
func New(send Sender, now func() time.Time, loc *time.Location, threshold int64) *Alerter {
    return &Alerter{send: send, now: now, loc: loc, threshold: threshold, last: map[string]time.Time{}}
}
```

```go
// Notify sends at most one alert per account and per hour, and none from
// 22:00 to 07:00 in loc. An SMS that fails does not count.
func (a *Alerter) Notify(ctx context.Context, account, phone string, amount int64) error {
    if amount <= a.threshold {
        return nil
    }
    now := a.now()
    if h := now.In(a.loc).Hour(); h >= 22 || h < 7 {
        return nil
    }
    a.mu.Lock()
    if t, ok := a.last[account]; ok && now.Sub(t) < time.Hour {
        a.mu.Unlock()
        return nil
    }
    a.last[account] = now // reserved: a second call at the same time sends nothing
    a.mu.Unlock()

    text := fmt.Sprintf("Transfert de %d FCFA depuis votre compte. Ce n'est pas vous ? Appelez le 8000.", amount)
    err := a.send.Send(ctx, phone, text)
    if err != nil {
        a.mu.Lock()
        if a.last[account].Equal(now) { // nobody sent since: give the reservation back
            delete(a.last, account)
        }
        a.mu.Unlock()
    }
    return err
}
```

Ce qui a changé, et ce qui n'a pas changé :

- **Les quatre dépendances** (envoi, horloge, fuseau, seuil) sont des
  paramètres. L'historique appartient à l'instance.
- **Le fuseau est un paramètre**, et c'est ce qui rend le troisième défaut
  **visible** : `time.Local` garde l'ancien comportement, `Africa/Douala`
  le corrige. Le choix n'est plus caché dans l'environnement du serveur,
  il est écrit dans `main`.
- **Le seuil reste exclu** (`<=`) et **la nuit reste muette** : ce sont
  des défauts, mais aussi des comportements que des clients connaissent.
  Les changer, c'est une décision du métier, pas un effet secondaire d'un
  refactoring. Les tests de la nouvelle forme le disent dans leur nom :
  `TestTheThresholdItselfIsStillNotAlerted`.

### Le serveur web ne change pas

L'ancien paquet garde sa fonction et sa variable, marquées `Deprecated`
(les éditeurs et `staticcheck` le signalent aux appelants) :

```go
// The default alerter is built on first use, not at init: SMS_URL is read
// when the first alert is sent, as a test can set it before.
var defaultAlerter = sync.OnceValue(func() *alerting.Alerter {
    gw := sms.Gateway{URL: os.Getenv("SMS_URL"), HTTP: &http.Client{Timeout: 5 * time.Second}}
    return alerting.New(gw, time.Now, time.Local, 0)
})

// Notify is the old function.
//
// Deprecated: build an alerting.Alerter in main and pass it to the code
// that needs it. Kept until the web server has moved.
func Notify(ctx context.Context, account, phone string, amount int64) error {
    if amount <= Threshold { // read on every call, as before
        return nil
    }
    return defaultAlerter().Notify(ctx, account, phone, amount)
}
```

```go
// Notify is the old function.
//
// Deprecated: build an alerting.Alerter in main and pass it to the code
// that needs it. Kept until the web server has moved.
func Notify(ctx context.Context, account, phone string, amount int64) error {
    if amount <= Threshold { // read on every call, as before
        return nil
    }
    return defaultAlerter().Notify(ctx, account, phone, amount)
}
```

Deux détails :

- **Le seuil est vérifié dans l'enveloppe**, et l'`Alerter` par défaut est
  construit avec un seuil de 0. L'ancien code relisait `Threshold` à
  chaque appel : si quelqu'un la modifie, il faut que ça marche encore.
  Construire l'`Alerter` avec `Threshold` l'aurait figée au premier appel.
- **`SMS_URL` est lue au premier usage**, plus à l'initialisation. C'est
  ce qui permet enfin un test de l'ancien point d'entrée, avec `t.Setenv`
  et un faux serveur.

Ce test garde une trace du singleton : l'`Alerter` par défaut est
construit **une fois par binaire de test**, avec l'URL du premier faux
serveur. Lancé deux fois (`-count=2`), le second passage enverrait ses SMS
à un serveur fermé. Le test le sait et se saute lui-même. L'enveloppe
disparaîtra avec la migration du serveur web, et ce test avec elle.

### Le premier appelant migré


`payroll` ne connaît plus `alerts` : il reçoit quelque chose qui sait

quatre lignes.

## 4. Le défaut corrigé, et les autres

**Le SMS en échec.** L'alerte est **réservée** avant l'envoi, pour qu'un
second appel simultané n'envoie rien, puis la réservation est rendue si
l'envoi échoue. Réserver après l'envoi aurait été plus simple, et faux :
deux transferts simultanés du même compte enverraient deux SMS.

Ce que je ferais des autres :

| Défaut | Proposition | Qui décide |
|---|---|---|
| le seuil exclu | aligner le code sur la doc (`>=`), ou la doc sur le code | le métier, avec la conformité |
| la nuit muette | envoyer quand même au-delà d'un second seuil (10 000 000 FCFA), ou mettre en file pour 7 h | le métier ; la sécurité a son mot à dire |
| le fuseau du serveur | passer `Africa/Douala` dans `main` : une ligne | le métier, après avoir choisi les heures calmes |
| l'historique sans fin | supprimer les entrées de plus d'une heure, à chaque appel ou par une tâche | l'équipe, seule |

Trois survivantes, et une qui ne compilait pas :

- **« 59 minutes »** : le test d'origine envoyait à 10 h 59 **et** à
  11 h 00. Avec 59 minutes, l'envoi de 10 h 59 part, et celui de 11 h 00
  est bloqué : trois SMS dans les deux cas. Le test ne pouvait pas
  distinguer 59 minutes de 60.
- **« noté après l'envoi »** : vingt goroutines lancées ensemble ne se
  chevauchaient pas assez. La première finissait souvent avant que la
  deuxième ne commence.
- **« un échec efface l'alerte d'avant »** : c'est une mutation
  **équivalente**. La première version gardait l'alerte précédente pour la
  remettre en cas d'échec. Mais si l'envoi a été tenté, c'est que l'alerte
  précédente avait plus d'une heure : la remettre ou l'effacer donne le
  même comportement. Le code ne servait à rien ; il a été **supprimé**, et
  la mutation avec lui.
- **« un échec arrête le lot »** ne compilait pas (le paquet `log`
  devenait inutilisé) ; elle a été réécrite, et elle a survécu : aucun
  faux de `payroll` n'échouait.

Pour le chevauchement, un téléphone lent, qui retient chaque SMS jusqu'à
l'arrivée d'un deuxième, ou 200 ms. Avec la réservation, un seul SMS part
et attend les 200 ms. Sans elle, le deuxième arrive pendant que le premier
attend :

```go
// slowPhone holds each SMS until a second one arrives, or 200 ms. With the
// reservation, only one SMS is ever sent, and it waits the 200 ms. Without
// it, the second arrives while the first waits.
type slowPhone struct {
    phone
    second chan struct{}
    once   sync.Once
    calls  atomic.Int32
}

func (p *slowPhone) Send(ctx context.Context, to, text string) error {
    if p.calls.Add(1) == 2 {
        p.once.Do(func() { close(p.second) })
    }
    select {
    case <-p.second:
    case <-time.After(200 * time.Millisecond):
    }
    return p.phone.Send(ctx, to, text)
}
```

## Ce qu'il faut retenir

1. Pour caractériser du code qui ne se teste pas, le plus petit changement
   est une **couture** : une variable que la production laisse et que le
   test remplace. C'est une étape, pas une destination.
2. Un refactoring garde les comportements, défauts compris. Chaque défaut
   devient un test au nom explicite, et une décision à faire prendre.
3. Une vieille fonction globale peut rester, comme **enveloppe** d'une
   instance construite au premier usage, le temps que ses appelants
   migrent. Marque-la `Deprecated`.
4. Une mutation qui survit sans jamais pouvoir être tuée désigne du code
   inutile. Supprime le code.
