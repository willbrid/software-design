# Correction 3.2 — Exercice 3 : le planificateur

> Rappel de l'énoncé : un constructeur à sept paramètres positionnels, dont
> quatre entiers côte à côte, six traitements déclarés, et un appel presque
> sûrement faux.

Le code d'origine et le code refactorisé tournent dans un module vert sous
`go vet ./...` et `go test -race -count=1 ./...`.

## 1. L'appel faux

C'est `dormant` : `2, 1`. Avec la convention du paquet — si `FromHour >
ToHour`, la fenêtre passe minuit —, ce traitement hebdomadaire peut démarrer
à **toutes les heures sauf une** :

```
dormant    every=168h0m0s retries=3 maxRows=0      dryRun=true  x.xxxxxxxxxxxxxxxxxxxxxx
```

Vingt-trois heures sur vingt-quatre, dont l'après-midi, au pic de charge.
Aujourd'hui il tourne à blanc, donc il ne modifie rien ; le jour où
quelqu'un retire le `true` — le dernier argument, que rien ne nomme —, il
modifie les comptes dormants en pleine journée. L'intention la plus probable
est `1, 2` : deux arguments inversés.

Ni le compilateur ni les tests ne peuvent le voir, parce que **le
constructeur donne la même écriture à deux choses différentes** : une fenêtre
qui passe minuit et deux arguments inversés. `22, 6` pour `reconcile` est
correct, `2, 1` pour `dormant` ne l'est pas, et les deux ont exactement la
même forme — quatre entiers de suite, sans nom, dont une permutation reste un
appel valide.

## 3. La forme

Le défaut n'est pas le nombre de paramètres, c'est **la fenêtre** : deux
entiers dont l'ordre porte un sens que rien n'écrit. La réparation donne un
nom à chaque sens.

```go
// Window is the hours of the day a job may start in. It is built by
// Between or Overnight, and the name says which way the hours go.
type Window struct {
    from, to  int
    overnight bool
}
```

```go
// Between is a window inside one day: from 0 to 24, from before to.
func Between(from, to int) Window { return Window{from: from, to: to} }
```

```go
// Overnight is a window that crosses midnight: it starts in the evening,
// from 12 to 23, and ends in the morning, from 0 to 12.
func Overnight(from, to int) Window { return Window{from: from, to: to, overnight: true} }
```

```go
func (w Window) check() error {
    if w.overnight {
        if w.from < 12 || w.from > 23 || w.to < 0 || w.to > 12 {
            return fmt.Errorf("overnight window %d->%d: starts from 12 to 23, ends from 0 to 12", w.from, w.to)
        }
        return nil
    }
    if w.from < 0 || w.to > 24 || w.from >= w.to {
        return fmt.Errorf("window %d->%d: from 0 to 24, from before to (Overnight crosses midnight)", w.from, w.to)
    }
    return nil
}
```

Ce sont deux **fabriques de valeurs** — des constructeurs nommés — et c'est le
nom qui ferme la faute. `Between(2, 1)` est refusé : une fenêtre de jour va
dans le sens des heures. `Overnight(2, 1)` est refusé aussi : une fenêtre de
nuit commence le soir et finit le matin. La faute de `dormant` ne s'écrit plus
dans aucune des deux formes, et `Overnight(22, 6)` reste correct.

Le reste suit la leçon : les valeurs requises en paramètres, les facultatives
en options, et le booléen anonyme devient une option qui dit son nom.

```go
// Jobs are the jobs of the bank, as declared in the scheduler.
func Jobs() ([]*Job, error) {
    var d declare
    d.job("statements", 24*time.Hour, Between(1, 5), WithMaxRows(100_000))
    d.job("interest", 24*time.Hour, Between(0, 4))
    d.job("reminders", time.Hour, Between(8, 20), WithRetries(1), WithMaxRows(5_000))
    // dormant was declared (2, 1): 23 hours a day. Overnight(2, 1) is
    // refused, Between(2, 1) too; the arguments are assumed swapped.
    d.job("dormant", 7*24*time.Hour, Between(1, 2), DryRun())
    d.job("fx-rates", 15*time.Minute, Between(0, 24), WithRetries(5))
    d.job("reconcile", time.Hour, Overnight(22, 6), WithMaxRows(50_000))
    return d.jobs, d.err
}
```

### Le refactoring a posé la question

En réécrivant `dormant` dans la nouvelle forme, `Overnight(2, 1)` est refusé :

```
batch: invalid job: dormant: overnight window 2->1: starts from 12 to 23, ends from 0 to 12
```

C'est le résultat le plus utile de l'exercice : **le refactoring n'a pas pu
recopier la faute**, il a dû poser la question. Dans une vraie équipe, la
réponse vient du propriétaire du traitement, et elle part dans un commit à
part, nommé, plutôt que dans le refactoring. Cette correction suppose les
arguments inversés et écrit `Between(1, 2)` ; le commentaire dans le code le
dit.

La caractérisation, sur le code refactorisé, ne diffère que d'une ligne, et
la différence est exactement le complément :

```
avant  dormant    every=168h0m0s retries=3 maxRows=0      dryRun=true  x.xxxxxxxxxxxxxxxxxxxxxx
après  dormant    every=168h0m0s retries=3 maxRows=0      dryRun=true  .x......................
```

## 4. Les zéros

**`MaxRows`.** « Pas de limite » est l'absence de l'option ; `WithMaxRows(0)`
est refusé, parce qu'une limite de zéro ligne n'est une intention de personne.

Ma première version avait la faute de la leçon, section 5. Pour distinguer
« pas donné » de « donné », j'avais initialisé `maxRows` à `-1` — une
sentinelle. Le test des règles l'a trouvée :

```
job_test.go:64: max rows -1: <nil>
```

`WithMaxRows(-1)` était accepté comme « pas de limite », parce que la
sentinelle était aussi une valeur qu'un appelant peut donner. La réparation
est celle des corrections précédentes, un booléen « donné » :

```go
type config struct {
    retries    int
    maxRows    int
    maxRowsSet bool
    dryRun     bool
}
```

```go
// WithMaxRows limits the rows of one run. Without it, there is no limit.
func WithMaxRows(n int) Option {
    return func(c *config) { c.maxRows, c.maxRowsSet = n, true }
}
```

**`FromHour: 0`** — minuit — n'a plus de défaut : c'est un argument de
`Between`, requis, et zéro n'y veut rien dire d'autre que minuit.

**Avec une structure de configuration à défauts**, les deux auraient marché :
le zéro de `MaxRows` est déjà le défaut, et la fenêtre n'a pas de défaut
raisonnable, donc elle serait requise. Le défaut du code d'origine n'est pas
un zéro ambigu ; c'est **l'ordre** de quatre entiers. Une structure aurait
aussi nommé les champs — `FromHour: 2, ToHour: 1` se lit mieux que `2, 1` —,
sans empêcher de l'écrire.

Ce tableau est la deuxième version de la mesure. La première disait la même
chose, et elle mentait : le constructeur déprécié de la question 6 assemblait
le `Job` lui-même, donc les quarante dépôts qui l'appellent auraient reçu un
délai maximal de **zéro**. Zéro test rouge ; une sonde l'a montré :

```
NewJob: max run 0s; New: max run 1h0m0s
```

Deux corrections. Un test qui compare, champ par champ, ce que construisent
l'ancienne et la nouvelle porte pour la même déclaration — avec lui, la
mesure donne **1 test rouge** sur l'ancienne structure :

```go
// TestNewJobAndNewAgree: the same declaration, the old way and the new
// way, gives the same Job, field by field. A setting added to New and
// forgotten in NewJob turns it red.
func TestNewJobAndNewAgree(t *testing.T) {
    for _, c := range []struct {
        old *Job
        w   Window
        o   []Option
    }{
        {NewJob("statements", 24*time.Hour, 3, 1, 5, 100_000, false), Between(1, 5), []Option{WithMaxRows(100_000)}},
        {NewJob("interest", 24*time.Hour, 3, 0, 4, 0, false), Between(0, 4), nil},
        {NewJob("reminders", time.Hour, 1, 8, 20, 5_000, false), Between(8, 20), []Option{WithRetries(1), WithMaxRows(5_000)}},
        {NewJob("fx-rates", 15*time.Minute, 5, 0, 24, 0, false), Between(0, 24), []Option{WithRetries(5)}},
        {NewJob("reconcile", time.Hour, 3, 22, 6, 50_000, false), Overnight(22, 6), []Option{WithMaxRows(50_000)}},
        {NewJob("audit", time.Hour, 3, 22, 6, 0, true), Overnight(22, 6), []Option{DryRun()}},
    } {
        nu, err := New(c.old.name, c.old.every, c.w, c.o...)
        if err != nil {
            t.Fatal(err)
        }
        if *c.old != *nu {
            t.Errorf("\nNewJob %+v\n   New %+v", *c.old, *nu)
        }
    }
}
```

Et une structure où les deux portes partagent les défauts et l'assemblage —
un seul endroit où un champ de `config` devient un champ de `Job` :

```go
// defaults are the settings of a job declared without options. New and
// the deprecated NewJob both start from them.
func defaults() config { return config{retries: 3} }
```

```go
// job assembles a Job from its settings: the one place where a field of
// config becomes a field of Job.
func (c config) job(name string, every time.Duration, w Window) *Job {
    return &Job{name: name, every: every, window: w, retries: c.retries, maxRows: c.maxRows, dryRun: c.dryRun}
}
```

```go
// NewJob returns a batch job, as before the refactoring: no check, and a
// window that wraps midnight whenever fromHour > toHour.
//
// Deprecated: use New, with Between or Overnight. NewJob will be removed
// in v3.
func NewJob(name string, every time.Duration, retries int, fromHour, toHour int, maxRows int, dryRun bool) *Job {
    c := defaults()
    c.retries, c.maxRows, c.dryRun = retries, maxRows, dryRun
    return c.job(name, every, Window{from: fromHour, to: toHour, overnight: fromHour > toHour})
}
```

Avec elle, la mesure ci-dessus : zéro test rouge, et la sonde rend une heure
des deux côtés.

> Deux portes vers le même type, c'est deux endroits où un réglage nouveau
> peut être oublié. Elles partagent leurs défauts, ou un test les compare.

## 6. La migration

`apidiff`, entre le paquet d'origine et le paquet refactorisé :

```
Incompatible changes:
- Job.DryRun: removed
- Job.Every: removed
- Job.FromHour: removed
- Job.MaxRows: removed
- Job.Name: removed
- Job.Retries: removed
- Job.ToHour: removed
- Jobs: changed from func() []*Job to func() ([]*Job, error)
Compatible changes:
- (*Job).Every: added
- (*Job).IsDryRun: added
- (*Job).MaxRows: added
- (*Job).Name: added
- (*Job).Retries: added
- Between: added
- DryRun: added
- ErrJob: added
- New: added
- Option: added
- Overnight: added
- Window: added
- WithMaxRows: added
- WithRetries: added
```

Huit changements incompatibles, et le constructeur déprécié n'en couvre
**aucun** : il garde `NewJob` vivant, mais les quarante dépôts qui lisent
`j.Name` ou appellent `Jobs()` cassent quand même. Les champs ne peuvent pas
rester exportés à côté des accesseurs — un champ et une méthode ne peuvent
pas porter le même nom —, et les garder exportés rouvrirait le chemin que le
refactoring ferme.

Le plan :

| Version | Contenu | Ce que les quarante dépôts changent |
|---|---|---|
| v1.9 | `New`, `Between`, `Overnight` et les options, **ajoutés** au paquet actuel sans rien retirer — ce qu'`apidiff` classe compatible | rien ; ceux qui veulent commencent à appeler `New` |
| v2.0 | le paquet refactorisé, sous le chemin `…/batch/v2`, `NewJob` déprécié | leurs lectures de champs et leur appel à `Jobs`, quand ils passent en v2 ; `NewJob` continue de marcher |
| v3.0 | `NewJob` retiré | leurs derniers `NewJob` |

Combien de temps : autant que les dépôts mettent à passer en v2, mesuré, pas
décidé — un tableau des importateurs par version, revu chaque mois, et v3 ne
part que quand la colonne v1 est vide.

Et ce que les outils leur disent pendant ce temps, mesuré sur un dépôt qui
appelle `NewJob` : **rien**. `staticcheck ./...` et `gopls check` sortent
sans un message. `staticcheck` 2026.2.2 signale pourtant bien `strings.Title`, déprécié dans la
bibliothèque standard, dans le même fichier ; il ne dit rien du `NewJob`
déprécié d'un module local, ni dans le même module, ni depuis un autre module
branché par `replace`. Je n'ai pas établi pourquoi ; le résultat suffit pour
la décision : **le commentaire `Deprecated:` est une documentation** —
`go doc` l'affiche —, **pas une alarme**. L'annonce se fait par la note de
version et par le tableau des importateurs.

**« NewJob : fenêtre égale devient la journée ».** Avec `>=` au lieu de `>`,
un ancien appel `5, 5` passe de « jamais » à « toujours ». Aucune des six
déclarations n'a deux heures égales, donc la caractérisation ne le voyait
pas. Le code d'origine, sondé, ne démarre jamais une telle fenêtre :


## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | Quatre entiers côte à côte : une permutation reste un appel valide. Le compilateur vérifie des types, pas des sens. |
| ⚫ | Des constructeurs nommés — `Between`, `Overnight` — ferment une faute que des types ne ferment pas, parce que le nom porte le sens que l'ordre portait. |
| ⚫ | Un refactoring qui ne peut pas recopier une faute pose la question au lieu de la corriger en silence : la réponse part dans un commit à part. |
| ⚫ | Une sentinelle (`-1`) pour « pas donné » est une valeur qu'un appelant peut donner. Ma première version l'a prouvé ; un booléen « donné » la remplace. |
| ⚫ | Deux portes vers le même type oublient un réglage l'une après l'autre : défauts et assemblage partagés, ou un test qui les compare. Mesuré : 0 test rouge pour un délai de zéro, avant ce test. |
| ⚫ | Un constructeur déprécié ne couvre pas les champs retirés : `apidiff` en compte huit incompatibles, et c'est une version majeure. |
| ⚫ | `Deprecated:` est une documentation ; mesuré ici, ni `staticcheck` ni `gopls` ne l'ont signalé. |
