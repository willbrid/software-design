# Correction 3.6 — Exercice 5 : la promotion que personne n'avait lancée

> Rappel de l'énoncé : la version 4.12 a facturé 0,5 % au lieu de 1 %, et
> laissé passer des clients au-delà de 500 000 FCFA par jour, alors que
> `main` désigne le bon fichier. Expliquer, chiffrer, corriger, écrire le
> test qui manquait, proposer une métrique, rédiger le compte rendu.

Tout est dans `ex5` du module de correction, vert sous `go vet ./...` et
`go test -race -count=1 ./...`.

## En bref

- **L'ordre d'initialisation** : la variable `schedule` du paquet
  `pricing` est calculée **avant** `main`. Elle appelle `global.Get()`
  alors que `Path` vaut encore `"bank.conf"`, et le répertoire de travail
  de l'image en contient un : le fichier de développement. `Once` le garde,
  et le `Get()` de `main` le rend aussi.
- **Le journal affiche ce qui était demandé, pas ce qui a été lu.**
- **48 683 766 FCFA** de frais manquants sur les trois jours rejoués, et
  3 094 transferts au-delà du vrai plafond.
- **La 4.13** n'a plus de singleton : `main` lit le fichier qu'on lui
  donne, journalise les valeurs lues, et les passe. Un test de fumée lance
  le binaire **dans l'image**, et un test interdit au serveur de dépendre
  du paquet `global`.

## 1. Pourquoi 0,5 % et 5 000 000 FCFA

La spécification de Go dit comment un programme démarre. Les paquets
importés sont initialisés d'abord, l'un après l'autre : « *Package
initialization—variable initialization and the invocation of init
functions—happens in a single goroutine, sequentially, one package at a
time* ». Puis seulement `main` s'exécute.

Pour la 4.12, la chronologie est donc :

| Moment | Ce qui se passe | `global.Path` |
|---|---|---|
| initialisation de `pricing` | `schedule = load()` appelle `global.Get()` | `"bank.conf"`, la valeur par défaut |
| | `Once` lit `./bank.conf`, **le fichier de développement** : 50 bp, 5 000 000 FCFA | |
| `main`, ligne 1 | `global.Path = "etc/bank.conf"` : trop tard, `Once` a déjà servi | `"etc/bank.conf"` |
| `main`, ligne 2 | le journal affiche `config etc/bank.conf` | |
| `main`, ligne 3 | `global.Get().DailyLimit` rend **la même** configuration : 5 000 000 | |

Trois choses ont dû arriver ensemble :

1. un paquet qui lit le singleton **pendant l'initialisation** ;
2. un `Once`, qui garde ce premier chargement ;
3. un `bank.conf` dans le répertoire de travail, arrivé par `COPY . .`.

Un test de `pricing` tournerait dans le répertoire du paquet, où il n'y a
pas de `bank.conf` : `load()` y prendrait le tarif publié, et **tout
aurait l'air juste**. Le défaut n'existe que dans l'image.

Remarque que `pricing` voulait bien faire : « *so that a fee costs no file
access* ». Lire la configuration une fois est la bonne idée. La lire
**depuis un paquet**, au moment où ce paquet s'initialise, est la mauvaise.

## 2. Pourquoi le journal ment

```text
bankd 4.12 starting, config etc/bank.conf
```

Il affiche la **variable** `global.Path`, c'est-à-dire ce que `main` a
demandé. Ce qui a été lu, et d'où, n'apparaît nulle part. Un journal de
démarrage doit dire ce que le programme **utilise** :

```text
bankd 4.13 starting, config etc/bank.conf (sha256 68846193cf46ad1c5fa92e3e): fee 100 bp, minimum 100, daily limit 500000
```

Les valeurs lues, et l'empreinte du fichier, à comparer avec celle du
fichier déployé. Avec cette ligne, la première personne qui aurait regardé
le journal du lundi aurait vu `fee 50 bp`.

## 3. Combien

La finance compare ce qui a été facturé avec ce qui était dû, transfert
par transfert, au tarif publié. Le même trafic, rejoué avec le même
générateur (`go run ./ex5/cmd/due`) :

```text
replay of 4.12, to check it is the same traffic:
day 1: 40000 transfers, 3287973527 FCFA sent, 16889244 FCFA of fees, 1042 took the account past 500000
day 2: 40000 transfers, 3275874134 FCFA sent, 16824085 FCFA of fees, 984 took the account past 500000
day 3: 40000 transfers, 3320297072 FCFA sent, 17037459 FCFA of fees, 1068 took the account past 500000
day 1: charged 16889244, due 33081202, missing 16191958 FCFA
day 2: charged 16824085, due 32960109, missing 16136024 FCFA
day 3: charged 17037459, due 33393243, missing 16355784 FCFA
three days: charged 50750788, due 99434554, missing 48683766 FCFA; 3094 transfers past the real limit
```

Les trois premières lignes reproduisent exactement la sortie de la 4.12 :
c'est bien le même trafic. Sur trois jours : **48 683 766 FCFA** de frais
non facturés, soit presque la moitié des 99 434 554 dus. Pas exactement la
moitié, parce que le minimum de 100 FCFA, lui, était juste : les petits
transferts ont payé le bon prix.

Ce chiffre est le manque à gagner **sur les transferts faits**. Il en
compte 3 094 qui n'auraient pas dû l'être, parce qu'ils faisaient passer
le client au-delà de 500 000 FCFA dans la journée. Ceux-là ne sont pas
une question de frais : c'est un sujet pour la conformité, puisque le
plafond sert aussi à la lutte contre le blanchiment.

## 4. La version 4.13

```go
func main() {
    log.SetFlags(0)
    path := flag.String("config", "etc/bank.conf", "settings file, mounted by the platform")
    flag.Parse()

    raw, err := os.ReadFile(*path)
    if err != nil {
        log.Fatalf("config: %v", err)
    }
    cfg, err := config.Load(*path)
    if err != nil {
        log.Fatalf("config %s: %v", *path, err)
    }
    // What was read, not what was asked for: the values, and a hash of the
    // file to compare with the one in the deployment.
    log.Printf("bankd 4.13 starting, config %s (sha256 %.12x): fee %d bp, minimum %d, daily limit %d",
        *path, sha256.Sum256(raw), cfg.FeeBP, cfg.FeeMin, cfg.DailyLimit)

    sched := fees.Schedule{RateBP: cfg.FeeBP, Min: cfg.FeeMin}
    traffic.Replay(3, cfg.DailyLimit, sched.Fee, os.Stdout)
}
```

Ce qui a changé :

- **Le paquet `pricing` a disparu**, et `global` n'est plus importé. Le
  barème est une valeur construite par `main` et passée.
- **Le chemin est un paramètre** (`-config`), avec pour défaut le fichier
  monté par la plateforme. Il n'existe plus de valeur par défaut
  « relative au répertoire courant » qui irait chercher ce qui traîne.
- **Une erreur arrête le démarrage.** Dans la 4.12, faute de fichier,
  `pricing` prenait le tarif publié en silence, et `main` paniquait un peu
  plus loin sur un pointeur nul. La 4.13 refuse de démarrer, avec un
  message.
- **Le journal dit ce qui est lu.**

Le même répertoire d'image, fichier de développement compris :

```text

day 1: 39250 transfers, 3025196853 FCFA sent, 30453711 FCFA of fees, 0 took the account past 500000
day 2: 39309 transfers, 3025140753 FCFA sent, 30452972 FCFA of fees, 0 took the account past 500000
day 3: 39254 transfers, 3040051130 FCFA sent, 30591097 FCFA of fees, 0 took the account past 500000
```

Le fichier de développement est toujours là, et il ne sert plus à rien :
personne ne le lit. Il faut quand même l'enlever de l'image
(`.dockerignore`, ou une construction qui ne copie que le binaire), mais
la correction ne **dépend** plus de ce ménage.

## 5. Le test qui manquait

Aucun test unitaire ne pouvait voir ce défaut : il n'existe que quand le
binaire démarre dans le répertoire de l'image. Le test qui manquait est un
**test de fumée** de l'artefact : construire le binaire, le lancer comme
le conteneur le lance, et vérifier ce qu'il facture.

```go
func TestTheImageChargesThePublishedRateAndLimit(t *testing.T) {
    tmp := t.TempDir()
    bin := filepath.Join(tmp, "bankd")
    if out, err := exec.Command("go", "build", "-o", bin, target).CombinedOutput(); err != nil {
        t.Fatalf("build %s: %v\n%s", target, err, out)
    }
    image := filepath.Join(tmp, "image")
    if err := os.CopyFS(image, os.DirFS("../../../e36/ex5/image")); err != nil {
        t.Fatal(err)
    }
    cmd := exec.Command(bin)
    cmd.Dir = image
    out, err := cmd.Output()
    if err != nil {
        t.Fatalf("run: %v", err)
    }
    n := 0
    for _, l := range strings.Split(string(out), "\n") {
        m := day.FindStringSubmatch(l)
        if m == nil {
            continue
        }
        n++
        sent, _ := strconv.ParseFloat(m[1], 64)
        charged, _ := strconv.ParseFloat(m[2], 64)
        if r := charged / sent; r < 0.0095 || r > 0.011 {
            t.Errorf("%s\n  fees are %.2f %% of the amounts, want about 1 %%", l, 100*r)
        }
        if m[3] != "0" {
            t.Errorf("%s\n  transfers past the 500000 limit", l)
        }
    }
    if n != 3 {
        t.Fatalf("%d day lines in:\n%s", n, out)
    }
}
```

Ici, le serveur rejoue du trafic, et le test lit ses lignes. Un vrai
serveur exposerait sa configuration effective (une page d'administration,
ou la ligne de journal de la section 2), ou ferait un transfert de test :
l'idée est la même, interroger **le binaire déployé**, pas le code.

Et pour que le singleton ne revienne pas par un autre paquet, un second
test interdit au serveur d'en dépendre, même indirectement :

```go
// The singleton cannot come back by accident: the server must not depend on
// the package that holds it, even through another package.
func TestTheServerDoesNotDependOnTheSingleton(t *testing.T) {
    out, err := exec.Command("go", "list", "-deps", target).Output()
    if err != nil {
        t.Fatal(err)
    }
    for _, p := range strings.Fields(string(out)) {
        if p == "example/exercises36/global" {
            t.Fatalf("%s depends on %s", target, p)
        }
    }
}
```

### La campagne

```text
fichier par défaut du répertoire             tuee
plafond codé en dur                          tuee
taux codé en dur                             tuee
minimum ignoré                               SURVIT
3/4 tuees
```

« minimum ignoré » survit, et c'est attendu : un test de fumée regarde le
**taux moyen**, que le minimum ne change presque pas. Il n'est pas fait
pour voir chaque règle ; les tests unitaires de `fees` et de `transfer` le
sont. Le test de fumée répond à une seule question : « l'artefact
déployé utilise-t-il la bonne configuration ? ».

## 6. Le tableau de bord

| Métrique | Seuil | Pourquoi |
|---|---|---|
| **frais facturés ÷ montants envoyés**, par heure | hors de 0,9 % à 1,2 % pendant une heure : alerte | le taux effectif est stable d'une heure à l'autre ; ici, 0,51 % chacun des trois jours, donc dès les premières heures du lundi |
| transferts **refusés** pour plafond, par heure, comparés à la semaine précédente | chute de plus de 80 % : alerte | à 5 000 000 FCFA, presque plus personne n'atteint le plafond |
| **empreinte** de la configuration chargée, par instance | différente de celle du déploiement : alerte | voit le défaut au démarrage, avant le premier transfert |

La première ligne est la plus robuste : elle ne dépend pas de la cause.
Un fichier faux, un barème mal câblé, une promotion lancée par erreur, ou
une modification du code des frais donnent tous le même signal.

## Le compte rendu, en cinq lignes

1. **Quoi** : du lundi au jeudi, la version 4.12 a facturé 0,5 % au lieu
   de 1 % et appliqué un plafond de 5 000 000 FCFA au lieu de 500 000.
   Sur les trois jours rejoués : 48 683 766 FCFA non facturés, 3 094
   transferts au-delà du plafond.
2. **Pourquoi** : un nouveau paquet lisait la configuration globale
   pendant l'initialisation, avant que `main` ne donne le chemin ; il a lu
   un fichier de développement copié dans l'image, et `sync.Once` l'a
   gardé pour tout le programme.
3. **Pourquoi personne ne l'a vu** : le défaut n'existe que dans l'image,
   aucun test ne lançait le binaire, et le journal affichait le chemin
   demandé au lieu des valeurs lues.
4. **Correction** : version 4.13 sans configuration globale ; journal des
   valeurs lues et de l'empreinte ; test de fumée de l'image ; test qui
   interdit la dépendance à `global` ; alerte sur le taux effectif des
   frais.
5. **Ce qui reste ouvert** : la conformité examine les 3 094 transferts ;
   la direction décide si les frais manquants sont réclamés ; l'image ne
   doit plus être construite par `COPY . .`.

## Ce qu'il faut retenir

1. Une variable de paquet calculée à partir d'un singleton s'exécute
   **avant** `main`, et lit donc un état que `main` n'a pas encore préparé.
2. `sync.Once` transforme une lecture trop précoce en erreur permanente.
3. Un journal de démarrage affiche ce que le programme **utilise**, pas ce
   qu'on lui a demandé.
4. Certains défauts n'existent que dans l'artefact : il faut un test qui
   le lance comme en production.
5. La métrique qui ne dépend pas de la cause, ici le taux effectif des
   frais, voit aussi les causes qu'on n'a pas imaginées.
