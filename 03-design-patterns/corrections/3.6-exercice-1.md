# Correction 3.6 — Exercice 1 : prévoir avant d'exécuter

> Rappel de l'énoncé : prévoir les cinq lignes de `ex1/predict` ; classer
> six variables de paquet ; expliquer pourquoi le mauvais test échoue.

## En bref

- `sync.OnceValues` garde **l'erreur** aussi bien que la valeur : un
  premier chargement raté le reste.
- Un annuaire accepte n'importe quoi à l'enregistrement, et ne vérifie le
  type qu'à la lecture. Le compilateur, lui, aurait refusé la même valeur
  passée à `New`.
- `http.DefaultClient` est un **pointeur** : qui le modifie le modifie pour
  tous. Une copie de la `struct` est un autre client.
- La question pour une variable de paquet n'est pas « est-elle globale ? »
  mais « **quelqu'un en voudra-t-il une autre** ? ».

## 1.a — Les quatre scénarios

La sortie de `go run ./ex1/predict` :

```text
1: 1 true true
2: first Get ok
2: panic: locator: "ledger" is a fake.Ledger
3: 2s 5s
4: false unknown operator "Kola"
```

**Ligne 1 : `1 true true`.** `OnceValues` appelle la fonction une seule
fois, d'où `calls` à 1, et garde **ce qu'elle a rendu** : une
configuration vide et l'erreur « fichier absent ». Le second appel ne
relit pas le fichier, apparu entre-temps ; il rend la même erreur. La
documentation ne promet pas autre chose : « *OnceValues returns a function
that invokes f only once and returns the values returned by f* ». C'est la
section 2 de la leçon, sans le `nil` : l'erreur est rendue au lieu d'être
avalée, mais elle est gardée pour toujours.

**Lignes 2.** Le premier `Get` réussit : `&fake.Ledger{}` est un pointeur,
et ses méthodes ont un récepteur pointeur. Le second enregistre une
**valeur** `fake.Ledger{}`. `Register` l'accepte, puisqu'il prend un
`any` : aucun contrôle. C'est `Get` qui découvre que la valeur n'a pas les
méthodes de `transfer.Ledger`, et panique avec le message de `locator.go`.

La règle du langage : « *The method set of a defined type T consists of all
methods declared with receiver type T* ». Les méthodes déclarées sur
`*Ledger` n'en font pas partie. La même erreur, passée à `New` au lieu de
l'annuaire, est refusée à la compilation (sonde `ex1/probe`, étiquette
`probe`) :

```text
# example/corrections36/ex1/probe
ex1/probe/main.go:16:37: cannot use fake.Ledger{} (value of struct type fake.Ledger) as transfer.Ledger value in argument to transfer.New: fake.Ledger does not implement transfer.Ledger (method Hold has pointer receiver)
```

Le message dit même pourquoi : `method Hold has pointer receiver`. Avec
l'annuaire, la même information arrive à l'exécution, sous forme de
panique, au premier appel qui passe par là.

**Ligne 3 : `2s 5s`.** `a := http.DefaultClient` copie un **pointeur** :
`a` et `http.DefaultClient` désignent le même client, et `a.Timeout = 2s`
change le délai de tout le programme. `b := *http.DefaultClient` copie la
**`struct`** : `b` est un autre client, et son délai ne regarde que lui.
Une nuance qui compte : `b.Transport` est `nil`, donc `b` utilise encore
`http.DefaultTransport`, partagé. Copier un client ne suffit pas à le
rendre indépendant ; en créer un, avec son propre `Transport` si besoin,
oui.

**Ligne 4 : `false unknown operator "Kola"`.** Les clés d'une `map` sont
sensibles à la casse : `"Kola"` n'est pas `"kola"`. `Build` refuse, et le
programme s'arrêterait **au démarrage**, avec un message qui donne la
valeur fautive. C'est ce qu'on attend d'une racine de composition. On
pourrait accepter `strings.ToLower(cfg.Operator)`, mais une configuration
stricte, qui refuse ce qu'elle ne connaît pas, reste plus sûre qu'une
configuration qui devine.

## 1.b — Variable de paquet, ou paramètre ?

| # | Déclaration | Verdict | Pourquoi |
|---|---|---|---|
| 1 | `ErrLimit` | **reste** | une erreur sentinelle ne change jamais ; on la compare avec `errors.Is` |
| 2 | `msisdn`, une expression compilée | **reste** | immuable, sans entrée-sortie, et « *safe for concurrent use by multiple goroutines* » d'après la documentation de `regexp` |
| 3 | `db` ouvert à l'initialisation | **paramètre** | il lit l'environnement avant `main`, jette l'erreur, et aucun test ne peut le remplacer ; `sql.Open` « *may just validate its arguments without creating a connection* », donc une base injoignable n'est même pas vue au démarrage |
| 4 | `holidays` | **paramètre**, ou donnée | la `map` n'est jamais écrite, mais le calendrier change chaque année, et certaines fêtes ne sont fixées que peu de temps avant : c'est une donnée métier, à charger et à passer |
| 5 | `DefaultTimeout`, exportée | **constante** ou **paramètre** | une variable exportée se modifie depuis n'importe quel paquet : c'est `http.DefaultClient` en petit. Une `const` ne le peut pas |
| 6 | `logger` | **toléré**, à passer si un test lit les journaux | un journal n'est pas un comportement métier ; `log/slog` a d'ailleurs son propre journal par défaut. Mais dès qu'un test doit vérifier ce qui est journalisé, ou qu'une partie du programme écrit ailleurs, il devient un paramètre |

Le critère commun : un test, ou un second client, en voudrait-il une autre
version ? Pour 1 et 2, jamais. Pour 3, 4 et 5, dès le premier test. Le 6
est le cas limite.

## 1.c — Le mauvais coupable

Trois phrases pour un collègue :

1. `TestTheFeeReadsTheGlobalConfiguration` est juste, mais il lit un taux
   que **le test de la promotion**, exécuté avant lui avec cette graine, a
   mis à 50 et n'a pas remis.
2. Le message désigne le test qui **constate** le défaut, pas celui qui
   l'a **causé**, parce que les deux partagent le singleton.
3. `-shuffle` affiche sa graine (`-test.shuffle 2`) : on rejoue exactement
   le même ordre, et l'on retire les tests un par un (`-run`) jusqu'à
   trouver celui dont la présence avant le test rouge suffit à le faire
   échouer.

La vraie correction n'est pas de remettre la valeur (la section 3 de la
leçon montre que ça ne suffit pas en parallèle). C'est de donner à chaque
test **son** barème, comme dans `transfer`.

## Ce qu'il faut retenir

1. `Once` et `OnceValues` gardent le premier résultat, erreur comprise.
   Une initialisation qui peut échouer se fait au démarrage, où l'on peut
   s'arrêter.
2. Un annuaire repousse à l'exécution les erreurs de type que le
   compilateur trouve dans une signature.
3. Copier un pointeur partage l'objet ; copier une `struct` le duplique,
   mais pas forcément ce qu'elle désigne.
4. Une variable de paquet est acceptable si elle est immuable, sans
   entrée-sortie, et si personne n'en voudra jamais une autre.
