# Correction 3.1 — Exercice 2 : l'arrondi par devise

> Rappel de l'énoncé : cinq devises, dont le naira, arrondi au kobo en
> comptabilité et au naira entier à l'affichage ; une règle d'arrondi
> désignable sur le reçu, une seule batterie, et les deux changements de la
> leçon à mesurer.

Un paquet, `rounding`, vert sous `go vet ./...` et `go test -race -count=1
./...`. Campagne de onze modifications, 11/11 après deux passes.

## 1. Des entiers, et pourquoi

> **Un montant ne passe jamais par un `float64`** : un flottant binaire ne
> représente pas 0,1, et une somme de flottants dérive.

Mesuré, en dix additions de 0,1 :

```
0.9999999999999999 false
```

Et un piège dans le piège : en Go, `0.1+0.2 == 0.3` vaut `true`, parce qu'une
expression **constante** est calculée exactement à la compilation. La dérive
n'apparaît qu'à l'exécution, sur des variables — c'est-à-dire en production,
pas dans le test qu'on écrit pour s'en convaincre.

Le montant exact est donc un entier en **millièmes de l'unité comptable** —
le franc pour XAF, le centime pour EUR, le kobo pour NGN. C'est ce que produit
un calcul de frais en points de base, et c'est assez fin pour que le demi
soit exact.

```go
// Milli is an exact amount, in thousandths of the accounting unit.
type Milli int64
```

## 2. La forme : un type paramétré

La règle 3 de méthode tranche : la règle doit être **désignable** — le reçu
l'imprime. Ça écarte la fonction (leçon, section 4). Restent l'interface et le
type. Et les cinq devises ne diffèrent pas par leur **code**, elles diffèrent
par leurs **paramètres** : un pas d'affichage et un nom d'unité. Un type par
devise répéterait cinq fois la même méthode. C'est le cas `Tiered` de la
leçon : **une valeur d'un seul type par règle.**

```go
// Rule rounds a currency for display. It is a value of one type, not a type
// per currency: the currencies differ by their parameters, not by their
// code. A Rule can be compared, printed and named on a receipt.
type Rule struct {
    Currency string
    // Step is the display step, in thousandths of the accounting unit: 1,000
    // for a rounding to the unit, 100,000 for NGN displayed in whole naira.
    Step int64
    // Unit names the display step on the receipt.
    Unit string
}
```

```go
// Round returns the amount rounded to the nearest step, a half away from
// zero, in accounting units.
func (r Rule) Round(m Milli) int64 {
    v := int64(m)
    q, rem := v/r.Step, v%r.Step
    if 2*abs(rem) >= r.Step {
        if v < 0 {
            q--
        } else {
            q++
        }
    }
    return q * r.Step / 1_000
}
```

```go
// Describe is the line of the receipt.
func (r Rule) Describe() string {
    return fmt.Sprintf("rounding: %s, %s, to the nearest, half away from zero", r.Currency, r.Unit)
}
```

Une `Rule` se compare, s'imprime, se nomme :

```
rounding: NGN, to the naira, to the nearest, half away from zero
{Currency:NGN Step:100000 Unit:to the naira}
```

Le naira montre pourquoi le pas est un paramètre et pas une constante :
**l'unité comptable et l'unité d'affichage diffèrent**. Le pas de NGN est
100 000 millièmes de kobo — un naira.

## 4. Une batterie, et le test qui la garde

Chaque cas est écrit une fois, et toutes les devises passent dans la même
boucle :

```go
// schedule is written once: every rule goes through it, and a broken case
// names its currency.
var schedule = []struct {
    currency string
    in       Milli
    want     int64
}{
    {"XAF", 2_400, 2}, {"XAF", 2_500, 3}, {"XAF", 2_600, 3},
    {"XAF", -2_400, -2}, {"XAF", -2_500, -3}, {"XAF", -2_600, -3},
    {"XOF", 1_499, 1}, {"XOF", 1_500, 2},
    {"EUR", 123_456, 123}, {"EUR", 123_500, 124}, {"EUR", -123_500, -124},
    {"USD", 999, 1}, {"USD", 499, 0},
    // NGN: the accounting unit is the kobo, the display is the whole naira.
    {"NGN", 123_456_789, 123_500}, {"NGN", 123_449_999, 123_400},
    {"NGN", 123_450_000, 123_500}, {"NGN", -123_450_000, -123_500},
}
```

Une batterie a un trou classique : une devise **inscrite** sans **cas**. Elle
passe la batterie en n'y passant pas. Le test qui ferme ce trou parcourt le
registre, pas la batterie :

```go
// TestEveryRuleIsInTheSchedule: a currency registered without a case in the
// schedule is a rule nobody checked.
func TestEveryRuleIsInTheSchedule(t *testing.T) {
    seen := map[string]bool{}
    for _, c := range schedule {
        seen[c.currency] = true
    }
    for name := range Default() {
        if !seen[name] {
            t.Errorf("%s has no case in the schedule", name)
        }
    }
}
```

## 5. Les deux changements

Mesurés sur une copie verte.

**Une devise de plus** — le franc guinéen :

```
== GNF dans le registre seulement : +1 -0 lignes, 0 erreur(s) de compilation, 1 test(s) rouge(s)
   --- FAIL: TestEveryRuleIsInTheSchedule (0.00s)
   rounding_test.go:47: GNF has no case in the schedule
== GNF, avec ses cas du bareme : +2 -0 lignes, 0 erreur(s) de compilation, 0 test(s) rouge(s)
```

Une ligne de registre, et un test rouge qui **nomme la devise oubliée**.
Deux lignes de plus et c'est vert. C'est le meilleur cas des quatre formes de
la leçon : une règle nouvelle est une **donnée**.

**Une opération de plus** — le symbole, pour le reçu. Avec un type paramétré,
une opération qui n'est qu'une valeur par devise devient un **champ** :

```
== Symbol, le champ seul : +2 -0 lignes, 0 erreur(s) de compilation, 0 test(s) rouge(s)
== Symbol renseigne partout sauf NGN : +6 -4 lignes, 0 erreur(s) de compilation, 1 test(s) rouge(s)
   --- FAIL: TestARuleIsDesignable (0.00s)
   rounding_test.go:64: a rule does not compare
== puis le test de completude : +16 -4 lignes, 0 erreur(s) de compilation, 2 test(s) rouge(s)
   --- FAIL: TestEveryRuleIsComplete (0.00s)
   rounding_test.go:57: NGN is incomplete: {Currency:NGN Step:100000 Unit:to the naira Symbol:}
   --- FAIL: TestARuleIsDesignable (0.00s)
   rounding_test.go:74: a rule does not compare
```

La mesure dit ce que le type paramétré coûte, et c'est son défaut exact :

1. **Le champ seul : zéro erreur, zéro test rouge.** Un littéral à champs
   nommés n'exige pas les champs nouveaux. Le compilateur, qui listait trois
   erreurs pour une méthode ajoutée à l'interface de la leçon, se tait.
2. **NGN oublié : un test rouge, et ce n'est pas le bon.** Il tombe parce
   qu'un test compare un littéral XAF complet, qui ne correspond plus. Il ne
   voit pas le naira ; il tomberait aussi si les cinq symboles étaient là.
3. **Le test de complétude nomme le naira.** C'est lui, et lui seul, qui
   remplace le compilateur sur ce type :

```go
// TestEveryRuleIsComplete: a field of Rule is a field every currency must
// fill, and the compiler does not require it in a keyed literal.
func TestEveryRuleIsComplete(t *testing.T) {
    for name, r := range Default() {
        if r.Currency != name || r.Unit == "" || r.Step <= 0 || r.Step%1_000 != 0 {
            t.Errorf("%s is incomplete: %+v", name, r)
        }
    }
}
```

> Une interface fait lister par le compilateur les implémentations
> incomplètes. Un type paramétré ne le fait pas : **un champ nouveau est
> optionnel pour le compilateur**, et c'est un test sur le registre qui doit le
> rendre obligatoire. C'est le prix d'avoir fait des règles des données.

## 6. Le demi

**La règle retenue : au plus proche, le demi à l'opposé de zéro.** 2,5 → 3,
−2,5 → −3. Les quatre cas qui la fixent sont dans la batterie, pour XAF :
2,4 → 2, 2,5 → 3, 2,6 → 3, et leurs négatifs.

Elle est **symétrique** — un remboursement s'arrondit comme le paiement qu'il
annule, ce que « demi vers le haut » ne fait pas. Mais symétrique ne veut pas
dire sans biais, et la question demandait ce que la règle produit sur un
relevé de mille lignes. Mesuré, avec un cinquième des lignes sur un demi exact :

```
219 exact halves, 46 of them negative
half up (toward +inf)  sum of rounded    51580, exact sum  51469.457, gap +111
half away from zero    sum of rounded    51534, exact sum  51469.457, gap +65
half to even           sum of rounded    51481, exact sum  51469.457, gap +12
```

- **demi vers le haut** : +111 francs. Chaque demi pousse dans le même sens.
- **demi à l'opposé de zéro** : +65. Les demis positifs dominent ici
  (173 contre 46), et chacun pousse vers le haut.
- **demi au pair** (l'arrondi bancaire) : +12, le bruit des autres lignes.

Et la vraie réponse n'est pas dans le choix de la règle :

> **Le total d'un relevé est l'arrondi de la somme exacte, jamais la somme des
> lignes arrondies.** L'arrondi est une opération d'**affichage** ; il se fait
> une fois, au bord, sur chaque nombre affiché. Additionner des nombres déjà
> arrondis, c'est additionner les erreurs.

« Au plus proche » sans règle pour le demi n'est pas une règle : c'est un
arrondi qui dépend de l'implémentation, et deux services de la même banque
n'afficheront pas le même total.

Le survivant réclame un test, et c'est une faute de lecture de l'énoncé : la
ligne du reçu est une **exigence** (question 2), et le test ne faisait que
l'imprimer. Un journal n'est pas une vérification :

```go
// TestARuleIsDesignable: it prints, it compares, it names itself.
func TestARuleIsDesignable(t *testing.T) {
    reg := Default()
    if reg["XAF"] != (Rule{Currency: "XAF", Step: 1_000, Unit: "to the franc"}) {
        t.Fatal("a rule does not compare")
    }
    if reg["XAF"] == reg["XOF"] {
        t.Fatal("two currencies compare equal")
    }
    // The receipt line is a requirement, not a log: it is checked word for
    // word.
    want := "rounding: NGN, to the naira, to the nearest, half away from zero"
    if got := reg["NGN"].Describe(); got != want {
        t.Fatalf("Describe = %q, want %q", got, want)
    }
    t.Logf("%s", reg["NGN"].Describe())
    t.Logf("%+v", reg["NGN"])
}
```

Deuxième passe :

```
11/11 tuees
```

## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | Un montant est un entier dans une unité fixée. Mesuré : dix fois 0,1 en `float64` ne font pas 1 — et `0.1+0.2 == 0.3` est vrai, parce que les constantes sont exactes. |
| ⚫ | Une règle désignable n'est pas une fonction. Des règles qui ne diffèrent que par leurs paramètres sont **des valeurs d'un seul type**. |
| ⚫ | Une devise de plus : une ligne de registre, et un test rouge qui la nomme si son cas manque. |
| ⚫ | Une opération de plus, sur un type paramétré, est un champ — et un champ nouveau est optionnel pour le compilateur. Un test de complétude sur le registre le rend obligatoire. |
| ⚫ | Une batterie a besoin d'un test qui parcourt le **registre** : une règle inscrite sans cas passe la batterie en n'y passant pas. |
| ⚫ | Le demi se choisit et s'écrit en quatre cas. Le total se calcule sur les montants exacts, et s'arrondit une fois. |
| ⚫ | Une exigence imprimée dans un journal de test n'est pas vérifiée. |
