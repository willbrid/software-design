# Correction 3.1 — Exercice 5 : la gratuité comptée par instance

> Rappel de l'énoncé : « vos 5 premiers virements de novembre offerts »,
> codée comme une règle de frais qui compte dans sa fermeture ; deux instances
> le lundi, six le mardi, un redémarrage le mercredi, et des frais à 31 % de la
> prévision le jeudi.

Le code de l'énoncé, l'incident rejoué, la correction et la garantie tiennent
dans un module vert sous `go vet ./...` et `go test -race -count=1 ./...`.
Campagne de dix modifications, 10/10 après trois passes.

## 1. Le mécanisme, en trois phrases

> Le nombre de virements gratuits déjà accordés vit dans la mémoire du
> processus qui calcule les frais. Chaque processus accorde donc ses cinq
> virements, sans savoir ce que les autres ont accordé, et en repart de zéro
> chaque fois qu'il redémarre. Le client n'a pas droit à cinq virements
> gratuits : il a droit à cinq par processus vivant, et le répartiteur de
> charge choisit pour lui.

## 2. Le maximum, étape par étape

Rejoué avec la chronologie de l'énoncé — deux registres le lundi, quatre de
plus le mardi à 14:00, six neufs le mercredi à 11:20 — et un client qui fait
assez de virements pour épuiser chaque compteur :

```go
// TestTheMaximumAtEachStep replays the chronology: 2 instances on Monday, 6
// from Tuesday 14:00 (2 old, 4 new), 6 new on Wednesday 11:20. The balancer
// picks an instance at random. A customer making many transfers per step
// gets, at most, five per instance alive in the step.
func TestTheMaximumAtEachStep(t *testing.T) {
    rng := rand.New(rand.NewPCG(5, 11))
    instances := []func(Transfer) int64{Rules()["promo-nov"], Rules()["promo-nov"]}
    free := 0
    step := func(name string, transfers int) {
        for range transfers {
            if instances[rng.IntN(len(instances))](Transfer{Account: "CM-0001", Amount: 100_000}) == 0 {
                free++
            }
        }
        t.Logf("%-28s %d instance(s), %d free so far", name, len(instances), free)
    }
    step("Monday", 200)
    for range 4 {
        instances = append(instances, Rules()["promo-nov"])
    }
    step("Tuesday after 14:00", 200)
    for i := range instances {
        instances[i] = Rules()["promo-nov"]
    }
    step("Wednesday after 11:20", 200)
    if free != 60 {
        t.Fatalf("free = %d, want 60", free)
    }
}
```

```
Monday                       2 instance(s), 10 free so far
Tuesday after 14:00          6 instance(s), 30 free so far
Wednesday after 11:20        6 instance(s), 60 free so far
```

| | Instances vivantes | Compteurs neufs | Maximum cumulé |
|---|---|---|---|
| lundi | 2 | 2 | **10** |
| mardi après 14:00 | 6 | 4 de plus | **30** |
| mercredi après 11:20 | 6 | 6, tous remis à zéro | **60** |

Le maximum **observé** est 30 parce qu'il faut beaucoup de virements pour
toucher tous les compteurs : avec un répartiteur au hasard, le dernier
compteur est le plus long à atteindre. Rejoué sur deux mille clients par
nombre de virements :

```
 5 transfers:   5.0 free on average,   0% of customers above 5
 6 transfers:   6.0 free on average, 100% of customers above 5
 8 transfers:   8.0 free on average, 100% of customers above 5
12 transfers:  12.0 free on average, 100% of customers above 5
20 transfers:  19.5 free on average, 100% of customers above 5
40 transfers:  33.5 free on average, 100% of customers above 5
```

Et ce tableau dit pourquoi **41 % et pas tous** : **tout** client qui a fait
plus de cinq virements entre lundi et jeudi en a eu plus de cinq gratuits —
100 % dès le sixième virement, parce que deux instances en accordaient déjà
dix le lundi. Les 41 % sont simplement la part des clients actifs qui ont
fait au moins six virements. Les autres n'ont pas été protégés par le code ;
ils n'ont pas fait assez de virements pour que la faute se voie.

## 3. Ce que le verrou a corrigé, et ce qu'il a caché

Le relecteur qui a lancé `go test -race` a trouvé une vraie faute : la carte
des compteurs était écrite depuis plusieurs goroutines. Le verrou l'a
corrigée. Il **ne pouvait pas** corriger les deux autres, parce qu'un verrou
protège une mémoire, et que le défaut était que la mémoire soit **là** :

| Défaut | Corrigé par le verrou ? |
|---|---|
| deux goroutines d'un même processus écrivent la carte | **oui** |
| deux processus ont deux cartes | non — un verrou n'est partagé que dans un processus |
| un processus qui redémarre perd sa carte | non — un verrou ne survit pas au processus non plus |

Et il a fait pire que ne pas les corriger : `go test -race` est devenu vert,
et le vert a été lu comme « le compteur est sûr ». La sonde de la section 8
voit les deux à la fois :

```
promo.go:23: closure modifies the captured variable used
promo.go:4: imports sync
```

## 4. Le test qui aurait échoué

Le test vert vérifiait une phrase exacte — *sur un registre, les cinq premiers
virements sont gratuits* — dans un monde qui n'existe pas en production : un
seul registre. Le test qui aurait échoué construit **deux** registres, comme
deux instances, et ne demande ni réseau ni base :

```go
// TestTwoInstancesGiveTen is the test that would have failed before the
// release: two registries, as two instances build them, and seven transfers.
func TestTwoInstancesGiveTen(t *testing.T) {
    a, b := Rules()["promo-nov"], Rules()["promo-nov"]
    free := 0
    for i := range 12 {
        r := a
        if i%2 == 1 {
            r = b
        }
        if r(Transfer{Account: "CM-0001", Amount: 100_000}) == 0 {
            free++
        }
    }
    if free != 10 {
        t.Fatalf("%d free transfers", free)
    }
    t.Logf("two instances, 12 transfers: %d free, for a campaign that gives 5", free)
}
```

```
two instances, 12 transfers: 10 free, for a campaign that gives 5
```

Il est écrit ici pour **fixer** la faute du code de l'énoncé — il passe parce
qu'il trouve dix. Sur le code corrigé, la même question a la réponse cinq,
avec six instances et six cents virements (section 6).

## 5. Trois jours de détection

| Phase | De | À | Durée |
|---|---|---|---|
| **détection** | lun. 08:00, lancement | jeu. 09:15, signalement de la comptabilité | **3 j 1 h 15** |
| qualification | jeu. 09:15 | jeu. 16:00, reconstitution | 6 h 45 |

L'énoncé demande l'indicateur qui aurait tiré le mardi après-midi. **Il aurait
tiré le lundi.** Avec deux instances, le sixième virement d'un client était
déjà gratuit le lundi : la montée à six instances a multiplié le dégât, elle
n'a pas créé la faute. L'indicateur :

- **la mesure** : le nombre de virements gratuits accordés par compte et par
  campagne, lu dans le **grand livre** — pas dans les métriques du service de
  frais, qui partagent sa faute ;
- **le seuil** : un compte au-delà de cinq. Un seul ;
- **le plancher de bruit** : **zéro**. Une campagne qui accorde un sixième
  virement gratuit n'a pas de marge d'erreur légitime ; le premier
  dépassement est un incident, pas une statistique.

Il aurait tiré au premier client qui faisait son sixième virement de novembre,
le lundi matin.

## 6. « Simple et autonome »

Pour l'auteur, **autonome** voulait dire : *pas de changement de base, pas de
migration, pas d'autre équipe*. Pour le système, ça voulait dire : *un état
que personne d'autre ne voit*. Les deux sont la même phrase, lue des deux
côtés.

> **« Où vit ce compteur quand il y a deux instances, et que devient-il au
> redémarrage ? »**

C'est la question de la leçon (section 6), et elle a deux réponses fausses
évidentes et une vraie : là où vit déjà l'argent.

## 7. La correction

| | Ce qu'elle empêche | Ce qu'elle n'empêche pas | Ce qu'elle coûte | Au prochain redémarrage |
|---|---|---|---|---|
| **A** une instance unique | le compte par instance | la perte au redémarrage ; la course entre goroutines | la tenue de charge de la paie de fin de mois, et un point de défaillance unique | **les compteurs repartent de zéro** |
| **B** le compteur dans Redis | le compte par instance, la perte au redémarrage — si Redis persiste | qu'un compteur incrémenté ne corresponde à aucun virement passé (virement refusé après l'incrément) ; qu'une éviction ou une purge redonne cinq virements | un appel réseau par virement, et une **deuxième source de vérité** sur de l'argent | tenu, tant que Redis ne perd rien |
| **C** l'usage lu dans le grand livre | tout ce qui précède, dans la même source que la comptabilité | une lecture-puis-écriture non atomique — voir ci-dessous | une requête par virement, dans la base qui fait déjà la transaction | **tenu** : le grand livre ne redémarre pas |
| **D** plus de campagnes | tout | — | le métier | sans objet |

**Je choisis C**, avec une condition que la proposition ne dit pas : la
consommation doit être **atomique**. « Lire le compte, décider, écrire le
compte » perd sur la concurrence, même dans le bon magasin :

```go
// ReadThenWrite is the version a cache in front of the ledger produces: read
// the count, decide, write the count. Each step is safe; the sequence is not.
type ReadThenWrite struct {
    Max  int
    mu   sync.Mutex
    used map[string]int
    // between is called between the read and the write: the tests use it to
    // make two instances interleave.
    between func()
}
```

```
count at 4, two instances at once: both free, count written 5
```

La consommation est une seule opération — en base, un `UPDATE … WHERE used <
max` dont on lit le nombre de lignes modifiées :

```go
// Memory stands for the ledger's table of grants. Its Consume is ONE
// operation, as the database's would be:
//
//    UPDATE grants SET used = used + 1
//    WHERE campaign = $1 AND account = $2 AND used < max
//
// one row updated means one free transfer granted.
type Memory struct {
    Max  int
    mu   sync.Mutex
    used map[string]int
}
```

```go
// Grants is the campaign's allowance, held where the money is held. Consume
// takes one free transfer if the account has one left, ATOMICALLY: two
// instances that ask at the same time cannot both get the last one.
type Grants interface {
    Consume(campaign, account string) (bool, error)
}
```

```go
// Fee returns the fee. If the ledger cannot answer, the transfer pays the
// ordinary fee and the error is returned: a missing free transfer can be
// refunded, a free transfer given twice cannot be taken back.
func (c Campaign) Fee(t Transfer) (int64, error) {
    if c.Grants == nil {
        return c.Then(t), ErrNoGrants
    }
    free, err := c.Grants.Consume(c.Name, t.Account)
    if err != nil {
        return c.Then(t), err
    }
    if free {
        return 0, nil
    }
    return c.Then(t), nil
}
```

```
six instances, 600 transfers, one atomic ledger: 5 free
```

Et un choix à dire : **si le grand livre ne répond pas, le virement paie le
tarif normal.** Un virement gratuit manquant se rembourse ; un virement
gratuit donné deux fois ne se reprend pas.

## 8. La garantie

> *« Plus jamais une règle de frais dont le résultat dépend de l'instance qui
> la calcule. »*

**La propriété** : un paquet de frais ne garde aucun état. Ses règles sont des
fonctions de leurs entrées ; ce qui doit être partagé passe par une interface
vers une source commune. Elle se vérifie **en lisant le code**, par un test qui
tourne à chaque modification du paquet, **avant la revue** :

```go
// Check returns one line per finding in the package in dir.
func Check(dir string) ([]string, error) {
    fset := token.NewFileSet()
    pkgs, err := parser.ParseDir(fset, dir, func(fi fs.FileInfo) bool {
        return !strings.HasSuffix(fi.Name(), "_test.go")
    }, 0)
    if err != nil {
        return nil, err
    }
    var out []string
    report := func(n ast.Node, format string, a ...any) {
        p := fset.Position(n.Pos())
        out = append(out, fmt.Sprintf("%s:%d: ", p.Filename[strings.LastIndex(p.Filename, "/")+1:], p.Line)+fmt.Sprintf(format, a...))
    }
    for _, pkg := range pkgs {
        for _, f := range pkg.Files {
            for _, imp := range f.Imports {
                switch path := strings.Trim(imp.Path.Value, `"`); path {
                case "sync", "sync/atomic", "math/rand", "math/rand/v2":
                    report(imp, "imports %s", path)
                }
            }
            for _, d := range f.Decls {
                if g, ok := d.(*ast.GenDecl); ok && g.Tok == token.VAR {
                    for _, s := range g.Specs {
                        vs := s.(*ast.ValueSpec)
                        if !isSentinel(vs) {
                            report(vs, "package-level variable %s", vs.Names[0].Name)
                        }
                    }
                }
            }
            ast.Inspect(f, func(n ast.Node) bool {
                switch n := n.(type) {
                case *ast.SelectorExpr:
                    if id, ok := n.X.(*ast.Ident); ok && id.Name == "time" && (n.Sel.Name == "Now" || n.Sel.Name == "Since" || n.Sel.Name == "Until") {
                        report(n, "reads the clock: time.%s", n.Sel.Name)
                    }
                case *ast.FuncLit:
                    for _, name := range capturedWrites(n) {
                        report(n, "closure modifies the captured variable %s", name)
                    }
                }
                return true
            })
        }
    }
    sort.Strings(out)
    return out, nil
}
```

```go
// capturedWrites returns the variables a function literal assigns, increments
// or indexes into for writing, when they are declared OUTSIDE it.
func capturedWrites(lit *ast.FuncLit) []string {
    inside := func(obj *ast.Object) bool {
        if obj == nil || obj.Decl == nil {
            return true
        }
        n, ok := obj.Decl.(ast.Node)
        return !ok || (n.Pos() >= lit.Pos() && n.End() <= lit.End())
    }
    seen := map[string]bool{}
    var out []string
    target := func(e ast.Expr) {
        for {
            switch x := e.(type) {
            case *ast.IndexExpr:
                e = x.X
                continue
            case *ast.SelectorExpr:
                e = x.X
                continue
            case *ast.Ident:
                if x.Obj != nil && x.Obj.Kind == ast.Var && !inside(x.Obj) && !seen[x.Name] {
                    seen[x.Name] = true
                    out = append(out, x.Name)
                }
            }
            return
        }
    }
    ast.Inspect(lit.Body, func(n ast.Node) bool {
        switch s := n.(type) {
        case *ast.AssignStmt:
            if s.Tok != token.DEFINE {
                for _, l := range s.Lhs {
                    target(l)
                }
            }
        case *ast.IncDecStmt:
            target(s.X)
        }
        return true
    })
    return out
}
```

Sur le code de l'incident, elle trouve la fermeture qui compte et le verrou
qui l'a masquée ; sur le paquet corrigé, rien. **Ce qu'elle interdit** : une
variable de paquet qui n'est pas une sentinelle d'erreur, une fermeture qui
modifie ce qu'elle a capturé, `sync`, `math/rand`, et la lecture de
l'horloge — dans le paquet des frais, et nulle part ailleurs.

**Attrape-t-elle une règle qui lit l'heure ?** Mesuré sur trois façons de
l'écrire :

```
== time.Now dans la regle                 VU : night.go:7: reads the clock: time.Now
== l'heure recue en argument              pas vu
== l'heure lue par une horloge injectee   pas vu
```

- **`time.Now` dans la règle : vu.** C'est le cas le plus courant.
- **L'heure reçue en argument : pas vu, et c'est juste.** Une règle qui reçoit
  l'instant du virement donne le même résultat sur toutes les instances : elle
  est déterministe, et c'est la bonne façon d'écrire une règle qui dépend de
  l'heure.
- **Une horloge injectée : pas vu.** C'est la limite honnête de la sonde : elle
  lit un paquet, pas ce qu'on lui branche. Une horloge par instance, mal
  synchronisée, ferait dépendre le frais de l'instance. Ce qui la rattrape est
  ailleurs — la revue du montage, et l'indicateur de la section 5, qui compare
  au grand livre.

Une sonde comme celle-là a besoin de son test négatif, sinon elle peut perdre
une règle sans que rien ne change (leçon 2.4). D'où la campagne.

## 9. La campagne

Dix modifications, jouées sous `go test -race -count=1 ./ex5/...`. Première
passe :

```
le grand livre sans verrou                                 tuee
un virement gratuit de trop                                tuee
grand livre en panne : gratuit                             SURVIT
la condition inversee                                      tuee
purete : sync accepte                                      tuee
purete : time.Now accepte                                  SURVIT
purete : toute variable avec une valeur est une sentinelle SURVIT
purete : les fermetures ne sont plus lues                  tuee
purete : used++ n'est plus une ecriture                    tuee
purete : une ecriture dans une carte n'est plus vue        tuee
7/10 tuees
```

Trois survivants, trois tests :

- **« grand livre en panne : gratuit »** — le chemin d'erreur n'avait pas de
  test ; il en a un, qui vérifie le tarif normal ;
- **« time.Now accepté »** et **« toute variable avec une valeur est une
  sentinelle »** — la sonde n'était testée que sur le code de l'incident, qui
  ne contient ni l'un ni l'autre. Elle a maintenant une **fixture** qui
  contient chaque impureté une fois.

Deuxième passe :

```
le grand livre sans verrou                                 tuee
un virement gratuit de trop                                tuee
grand livre en panne : gratuit                             tuee
la condition inversee                                      tuee
purete : sync accepte                                      tuee
purete : time.Now accepte                                  tuee
purete : toute variable avec une valeur est une sentinelle SURVIT
purete : les fermetures ne sont plus lues                  tuee
purete : used++ n'est plus une ecriture                    tuee
purete : une ecriture dans une carte n'est plus vue        tuee
9/10 tuees
```

La règle « les sentinelles commencent par `Err` » survivait encore : aucune
variable de la fixture n'avait **la forme** d'une sentinelle sans en être une.
Le cas réel existe — `var pending = list.New()` est un appel à `New`, et c'est
de l'état mutable :

```go
// pending has the shape of a sentinel — a call to New — and it is mutable
// state.
var pending = list.New()
```

Troisième passe :

```
10/10 tuees
```

## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | Un état dans une fermeture vit dans un processus : un compteur par instance, remis à zéro à chaque redémarrage. Mesuré : 10, puis 30, puis 60 virements gratuits pour une campagne de 5. |
| ⚫ | Un verrou protège une mémoire ; il ne la partage pas entre processus et ne la fait pas survivre. Il a corrigé une faute et rendu vert le test qui aurait pu montrer les deux autres. |
| ⚫ | Le test qui aurait échoué construit deux registres, comme deux instances : moins de vingt lignes, ni réseau ni base. |
| ⚫ | L'indicateur se lit dans le grand livre, avec un plancher de bruit à zéro. Il aurait tiré le lundi, pas le mardi : la montée en charge a multiplié la faute, elle ne l'a pas créée. |
| ⚫ | Le bon magasin ne suffit pas : lire, décider, écrire perd sur la concurrence. La consommation est une seule opération atomique. |
| ⚫ | En cas de doute, le virement paie : un gratuit manquant se rembourse, un gratuit donné deux fois ne se reprend pas. |
| ⚫ | « Pas d'état dans une règle » se vérifie en lisant le code, avant la revue. La sonde voit `time.Now` ; elle ne voit pas une horloge injectée, et elle a besoin de sa fixture négative. |
