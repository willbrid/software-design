## Exercice 1 — Compréhension

Quatre extraits, tirés du même service bancaire.

```go
// A — opening an account.

// Account is a bank account.
type Account struct {
    ID        string
    Owner     string
    Overdraft int64
}

// NewAccount returns an account.
func NewAccount(id, owner string, overdraft int64) *Account {
    return &Account{ID: id, Owner: owner, Overdraft: overdraft}
}
```

```go
// B — the statement server.

// ServerConfig configures the statement server. A zero field takes its
// default.
type ServerConfig struct {
    Addr        string        // default ":8080"
    ReadTimeout time.Duration // default 30s
    MaxBody     int64         // default 1 MiB
}
```

```go
func (c ServerConfig) withDefaults() ServerConfig {
    if c.Addr == "" {
        c.Addr = ":8080"
    }
    if c.ReadTimeout == 0 {
        c.ReadTimeout = 30 * time.Second
    }
    if c.MaxBody == 0 {
        c.MaxBody = 1 << 20
    }
    return c
}
```

```go
// C — the rate limiter of the public API.

// Limiter lets rate requests per second through, with bursts of burst.
type Limiter struct {
    rate, burst int
}
```

```go
// Option configures a Limiter.
type Option func(*Limiter) error

// WithRate sets the number of requests per second.
func WithRate(n int) Option {
    return func(l *Limiter) error {
        if n <= 0 {
            return errors.New("limiter: rate must be positive")
        }
        l.rate = n
        return nil
    }
}

// WithBurst sets the size of a burst, which cannot be below the rate.
func WithBurst(n int) Option {
    return func(l *Limiter) error {
        if n < l.rate {
            return errors.New("limiter: burst below rate")
        }
        l.burst = n
        return nil
    }
}

// NewLimiter returns a limiter of 10 requests per second, bursts of 10.
func NewLimiter(opts ...Option) (*Limiter, error) {
    l := &Limiter{rate: 10, burst: 10}
    for _, o := range opts {
        if err := o(l); err != nil {
            return nil, err
        }
    }
    return l, nil
}
```

```go
// D — the in-memory ledger.

// Entry is one line of the ledger.
type Entry struct {
    Account string
    Amount  int64
}

// Ledger records entries. Its zero value is an empty ledger, ready to use.
type Ledger struct {
    mu      sync.Mutex
    entries []Entry
}
```

```go
// NewLedger returns an empty ledger.
func NewLedger() *Ledger { return &Ledger{} }

// Add records an entry.
func (l *Ledger) Add(e Entry) {
    l.mu.Lock()
    defer l.mu.Unlock()
    l.entries = append(l.entries, e)
}
```

1. **Les chemins.** Pour A, C et D : quels objets invalides un autre paquet
   peut-il fabriquer ? Donne un exemple d'une ligne pour chacun, ou dis
   pourquoi il n'y en a pas.

2. **La valeur zéro** de `Account`, de `Limiter` et de `Ledger` : utile,
   détectée, ou piège ? Pour `Limiter`, dis ce que fait un limiteur à zéro
   requête par seconde, selon la façon dont on l'écrirait.

3. **Prédiction, extrait B.** Une équipe déclare un point d'entrée qui doit
   **refuser tout corps de requête**, avec `ServerConfig{MaxBody: 0}`. Quelle
   taille de corps accepte-t-il réellement ? Propose deux réparations, et dis
   ce que chacune coûte aux autres équipes.

4. **Prédiction, extrait C.** Un débit de 100 requêtes par seconde et des
   rafales de 50 : `NewLimiter(WithRate(100), WithBurst(50))`, puis
   `NewLimiter(WithBurst(50), WithRate(100))`. Pour chacun, l'erreur ou le
   limiteur obtenu. Puis réécris l'extrait pour que l'ordre ne compte plus.

5. **Extrait D.** `NewLedger` sert-il à quelque chose ? Puis un collègue écrit
   `snapshot := *ledger` pour figer le grand livre avant un export. Prédis ce
   qu'en dit `go vet`, et ce qui se passe sans `go vet`.

6. **Question ouverte.** L'extrait A est un constructeur qui ne peut pas
   échouer et qui ne fait que recopier ses arguments dans des champs exportés.
   Dis s'il sert à quelque chose aujourd'hui, et ce qu'il deviendrait le jour
   où le découvert doit être positif ou nul.

## Exercice 2 — Code

La banque ouvre des comptes. **Écris le paquet `account`**, et il doit
vérifier tout ce qui suit :

1. **Un compte a des règles** : un identifiant au format `CM-` suivi de
   quatre chiffres, un titulaire non vide, une devise parmi XAF et EUR (XAF
   par défaut), un niveau de vérification d'identité de 1 à 3 (1 par défaut),
   un découvert autorisé positif ou nul (**zéro par défaut, et zéro veut dire
   zéro**). Aucun autre paquet ne peut obtenir un compte qui viole une règle,
   sauf la valeur zéro.

2. **Une règle lie deux valeurs** : un découvert non nul exige un niveau de
   vérification d'au moins 2. Elle est contrôlée une fois, et l'ordre dans
   lequel l'appelant donne les deux valeurs ne change rien — écris le test
   qui le prouve dans les deux ordres.

3. **Choisis la forme** des réglages facultatifs, et justifie-la par une
   mesure de la leçon. Les valeurs requises ne sont pas facultatives.

4. **`Debit(amount int64) error`** respecte le découvert. Sur la valeur zéro,
   il rend une erreur nommée — pas une panique, pas un débit.

5. **Le geste d'une minute** : un test déclare `var a account.Account` et
   appelle **chacune** des méthodes exportées. Aucune ne panique.

6. **Mesure un réglage de plus** — un plafond de retrait journalier,
   facultatif, zéro voulant dire « pas de plafond » — : fichiers, lignes,
   appelants touchés. Puis dis ce que ta forme aurait coûté si zéro avait
   voulu dire « aucun retrait ».

Puis :

7. **Campagne de modifications**, au moins dix, dont une qui contrôle la règle
   du découvert dans le réglage au lieu du constructeur, une qui remplace un
   découvert de zéro par un défaut non nul, une qui retire la garde de la
   valeur zéro, et une qui accepte `CM-123`. Publie le relevé, et pour chaque
   survivant : un test, une suppression de branche, ou rien.

## Exercice 3 — Refactoring

Le planificateur des traitements de nuit, tel qu'il est en production :

```go
// Job is a batch job.
type Job struct {
    Name     string
    Every    time.Duration
    Retries  int
    FromHour int  // the job may start at FromHour or later...
    ToHour   int  // ...and before ToHour; if FromHour > ToHour, the window wraps midnight
    MaxRows  int  // 0 means no limit
    DryRun   bool // log what would be done, change nothing
}

// NewJob returns a batch job.
func NewJob(name string, every time.Duration, retries int, fromHour, toHour int, maxRows int, dryRun bool) *Job {
    return &Job{
        Name:     name,
        Every:    every,
        Retries:  retries,
        FromHour: fromHour,
        ToHour:   toHour,
        MaxRows:  maxRows,
        DryRun:   dryRun,
    }
}
```

```go
// MayStartAt reports whether the job may start at the given hour.
func (j *Job) MayStartAt(hour int) bool {
    if j.FromHour <= j.ToHour {
        return hour >= j.FromHour && hour < j.ToHour
    }
    return hour >= j.FromHour || hour < j.ToHour
}
```

Les six traitements déclarés :

```go
// Jobs are the jobs of the bank, as declared in the scheduler.
func Jobs() []*Job {
    return []*Job{
        NewJob("statements", 24*time.Hour, 3, 1, 5, 100_000, false),
        NewJob("interest", 24*time.Hour, 3, 0, 4, 0, false),
        NewJob("reminders", time.Hour, 1, 8, 20, 5_000, false),
        NewJob("dormant", 7*24*time.Hour, 3, 2, 1, 0, true),
        NewJob("fx-rates", 15*time.Minute, 5, 0, 24, 0, false),
        NewJob("reconcile", time.Hour, 3, 22, 6, 50_000, false),
    }
}
```

Les tests passent :

```go
func TestMayStartAt(t *testing.T) {
    day := NewJob("day", 0, 0, 8, 20, 0, false)
    night := NewJob("night", 0, 0, 22, 6, 0, false)
    for _, c := range []struct {
        j    *Job
        hour int
        want bool
    }{
        {day, 7, false}, {day, 8, true}, {day, 19, true}, {day, 20, false},
        {night, 21, false}, {night, 22, true}, {night, 3, true}, {night, 6, false},
    } {
        if got := c.j.MayStartAt(c.hour); got != c.want {
            t.Errorf("%s at %d: %v", c.j.Name, c.hour, got)
        }
    }
}
```

1. **Lis les six appels.** L'un d'eux est presque sûrement faux. Lequel, et
   que fait-il en production ? Dis pourquoi ni le compilateur ni les tests ne
   peuvent le voir — en une phrase sur la **forme** du constructeur.

2. **Caractérise d'abord.** Avant de toucher au code, écris le test qui fixe,
   pour chaque traitement, les 24 heures où il peut démarrer, et tous ses
   autres réglages. Il doit être vert sur le code d'origine.

3. **Refactorise.** Choisis la forme, écris-la, et fais en sorte que l'erreur
   de la question 1 devienne **impossible à écrire** ou **refusée à la
   construction** — sans interdire la fenêtre de `reconcile`, qui passe
   vraiment minuit. Le test de caractérisation reste vert, sauf pour le
   traitement fautif : dis ce que tu changes pour lui, et pourquoi c'est la
   seule différence.

4. **Les zéros.** `MaxRows: 0` veut dire « pas de limite », `FromHour: 0` veut
   dire minuit. Dis ce que ta forme fait de chacun, et ce qu'en aurait fait
   une structure de configuration à défauts.

5. **Mesure avant et après** : ajoute un délai maximal d'exécution par
   traitement (facultatif, défaut une heure). Fichiers, lignes, erreurs de
   compilation, appelants touchés.

6. **La migration.** Le planificateur est importé par quarante autres dépôts
   qui appellent `NewJob`. Dis comment tu livres ta nouvelle forme sans les
   casser le même jour, ce que tu gardes, combien de temps, et ce que
   `go vet` ou `staticcheck` leur dira pendant ce temps.

## Exercice 4 — Design

La banque publie un **SDK Go** pour son API de paiements interne. Douze
équipes vont l'importer, et il doit vivre trois ans sans casser l'une
d'elles.

| | |
|---|---|
| requis | l'adresse de l'API, un identifiant client et un secret |
| facultatifs aujourd'hui | délai, reprises, limite de débit, journal (`*slog.Logger`), métriques, configuration TLS |
| attendus dans l'année | générateur de clés d'idempotence, horloge injectable, proxy, région |
| d'où viennent les réglages | un fichier YAML, puis des variables d'environnement, puis des drapeaux, chacun écrasant le précédent |
| contraintes | le secret n'apparaît dans aucun journal ; les équipes testent sans réseau |

1. **La forme du constructeur public.** Écris sa signature, et justifie-la par
   la ligne « attendus dans l'année » et par la durée de vie du SDK.

2. **Requis ou facultatif ?** Dis pourquoi le secret n'est pas une option, et
   ce qui se passe s'il l'est.

3. **Une règle qui lie deux réglages** : des reprises sur une opération qui
   déplace de l'argent exigent un générateur de clés d'idempotence. Où la
   contrôles-tu, et que fait le SDK quand une équipe donne
   `WithRetries(3)` sans générateur ?

4. **Trois sources de réglages.** Le fichier, l'environnement et les drapeaux
   remplissent les réglages en trois étapes, dans trois paquets différents.
   Dis si c'est le cas où le builder paie, et écris comment les trois étapes
   s'enchaînent avant un seul contrôle. Puis : un drapeau `--retries=0`
   doit écraser un `retries: 3` du fichier. Que doit faire ta forme pour que ça
   marche ?

5. **La valeur zéro** de `Client`, et celle d'un `*Client` nul : que font
   leurs méthodes ?

6. **Le secret.** Une équipe journalise la configuration effective au
   démarrage, avec `slog.Any("config", cfg)`. Dis ce qui protège le secret,
   et ce qui le protège encore quand l'équipe écrit `fmt.Printf("%+v", cfg)`.

7. **Ajouter, retirer.** Écris ce que contient la version 1.4 qui ajoute le
   proxy, et la version 1.7 qui retire un réglage devenu inutile. Dis ce que
   chaque équipe doit changer dans chacune.

8. **Question ouverte.** Une équipe demande un `sdk.DefaultClient` global,
   « comme `http.DefaultClient` ». Dis ce que tu réponds, et garde ta réponse :
   la leçon 3.6 y reviendra.

## Exercice 5 — Incident de production

Service de règlement, deux partenaires : **Delta** (latence habituelle :
médiane 780 ms, 90ᵉ centile 1,4 s) et **Epsilon** (99ᵉ centile 300 ms). Delta
n'est **pas idempotent** : un ordre reçu deux fois est payé deux fois.
Extrait du post-mortem.

```
mar. 10/11 10:00  deploiement v2.14 : « sondes de sante des partenaires » ;
                  une sonde par partenaire, construite au demarrage
mar. 10/11 10:02  erreurs des reglements Delta : 0,4 % -> 61 % ;
                  le tableau de bord affiche « Delta : degrade »
mar. 10/11 10:05  l'astreinte ouvre un incident chez Delta
mar. 10/11 10:40  le support signale des doubles credits chez des
                  beneficiaires Delta
mar. 10/11 11:35  retour arriere en v2.13 ; erreurs Delta : 0,4 %
mer. 11/11        reconstitution : 3 520 ordres Delta pendant la fenetre,
                  dont 2 146 envoyes plus d'une fois, pour 6 811 envois ;
                  Epsilon : aucun ordre envoye deux fois
```

Le code du client :

```go
// Package settle sends settlement orders to the partners of the bank.
package settle

import "time"

type settings struct {
    Timeout time.Duration
    Retries int
}

// defaults are the settings of a client built without options.
var defaults = &settings{Timeout: 3 * time.Second, Retries: 3}

// Option changes one setting.
type Option func(*settings)

// WithTimeout sets the timeout of one attempt.
func WithTimeout(d time.Duration) Option {
    return func(s *settings) { s.Timeout = d }
}

// WithRetries sets the number of retries after the first attempt.
func WithRetries(n int) Option {
    return func(s *settings) { s.Retries = n }
}

// Client sends orders to one partner.
type Client struct {
    partner string
    s       settings
}

// New returns a client of the partner.
func New(partner string, opts ...Option) *Client {
    s := defaults
    for _, o := range opts {
        o(s)
    }
    return &Client{partner: partner, s: *s}
}
```

Le démarrage, modifié en v2.14 :

```go
// Start builds, for each partner, a health probe and the client that
// sends the orders. The probes are new in v2.14: a probe must fail fast.
func Start(partners []string) (clients, probes map[string]*Client) {
    clients, probes = map[string]*Client{}, map[string]*Client{}
    for _, p := range partners {
        probes[p] = New(p, WithTimeout(500*time.Millisecond))
    }
    for _, p := range partners {
        clients[p] = New(p)
    }
    return clients, probes
}
```

Les tests, verts en v2.14 :

```go
func TestDefaults(t *testing.T) {
    c := New("delta")
    if c.s.Timeout != 3*time.Second || c.s.Retries != 3 {
        t.Fatalf("defaults: %+v", c.s)
    }
}
```

```go
func TestOptions(t *testing.T) {
    c := New("delta", WithTimeout(time.Second), WithRetries(1))
    if c.s.Timeout != time.Second || c.s.Retries != 1 {
        t.Fatalf("options: %+v", c.s)
    }
}
```

Établi après coup :

- La revue a approuvé : *« la sonde a son propre client, aucun risque pour les
  règlements »*.
- Delta traite un ordre même quand le client a abandonné l'attente.
- La CI lance `go test ./...`, sans autre drapeau.

### Les questions

1. **Explique le mécanisme en trois phrases**, de la ligne `s := defaults`
   jusqu'au double crédit.

2. **Pourquoi Delta et pas Epsilon**, avec les chiffres de l'énoncé. Puis le
   nombre maximal d'envois d'un même ordre, et d'où il vient.

3. **Les chiffres de la reconstitution.** Si chaque tentative dépassait le
   délai indépendamment des autres, avec la probabilité observée de 61 %,
   combien d'ordres auraient été envoyés plus d'une fois, et combien d'envois
   pour ces ordres ? Compare aux chiffres réels et dis ce que l'écart
   apprend sur les tentatives d'un même ordre.

4. **Les tests étaient verts.** Lance-les avec `-shuffle=on`, plusieurs fois,
   et rapporte ce que tu vois. Puis écris le test qui échoue **à chaque
   fois** sur le code de la v2.14, sans dépendre de l'ordre.

5. **Quarante minutes sur la mauvaise piste.** Le tableau de bord disait
   « Delta : dégradé ». Dis pourquoi c'était vrai et trompeur à la fois, et
   quel indicateur aurait désigné le client au lieu du partenaire, avec son
   seuil.

6. **« La sonde a son propre client. »** Dis ce que voulait dire « propre »
   pour l'auteur, et ce qu'il voulait dire dans le code. La question que la
   revue aurait dû poser tient en une ligne.

7. **La correction.** Quatre propositions :

   | | Proposition |
   |---|---|
   | A | ajouter l'étoile : `s := *defaults` |
   | B | construire les clients avant les sondes dans `Start` |
   | C | remplacer la variable par une fonction `func defaults() settings` |
   | D | `WithRetries(0)` pour Delta, et une clé d'idempotence quand Delta la proposera |

   Pour chacune : ce qu'elle empêche, ce qu'elle n'empêche pas, ce qu'elle
   coûte. Lesquelles livres-tu, et dans quel ordre ?

8. **Question ouverte.** La direction demande une garantie : *« construire un
   client ne modifie jamais un autre client »*. Propose une propriété du code
   qui la tient, dis à quel moment elle tire — revue, compilation, test,
   production — et réponds à la question qui décide : **ta propriété
   attrape-t-elle une option qui ajoute un en-tête à une carte partagée ?**
