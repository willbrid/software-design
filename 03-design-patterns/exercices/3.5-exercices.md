écris tes réponses dans `mes-reponses/` avant d'ouvrir les corrections.

Les exercices s'appuient sur les paquets `payout`, `flags`, `store`,
`service`, `batch`, `pipeline` et `fake` de la
[leçon 3.5](../cours/3.5-etats-etapes.md), recopiés tels quels dans le module
des exercices. Tout le code ci-dessous compile et passe `go vet` ; la
banque, l'opérateur Mobile Money et l'incident sont **fictifs**.

```go
    before := runtime.NumGoroutine()

    time.Sleep(50 * time.Millisecond)

}
```

## Exercice 3 — Refactoring : le dossier de prêt

*Niveau 3. Caractériser, puis refactorer sans casser ce qui doit rester.*

Le service des prêts a été écrit comme le premier paiement de la leçon : un
booléen par décision.

```go
// Application is a customer's request for a loan.
type Application struct {
    ID        string
    Amount    int64 // FCFA
    Submitted bool
    Approved  bool
    Rejected  bool
    Cancelled bool
    Disbursed bool
}
```

```go
// Approve is the credit officer's yes.
func (a *Application) Approve() error {
    if !a.Submitted {
        return ErrNotSubmitted
    }
    a.Approved = true
    return nil
}
```

```go
// Reject is the credit officer's no.
func (a *Application) Reject() error {
    if !a.Submitted {
        return ErrNotSubmitted
    }
    if a.Disbursed {
        return ErrAlreadyDisbursed
    }
    a.Rejected = true
    return nil
}
```

```go
// Cancel is the customer changing their mind, before the money is paid.
func (a *Application) Cancel() error {
    if a.Disbursed {
        return ErrAlreadyDisbursed
    }
    a.Cancelled = true
    return nil
}
```

```go
// Do loads the application, applies change, and saves it.
func (s *Service) Do(id string, change func(*Application) error) error {
    a, err := s.Get(id)
    if err != nil {
        return err
    }
    if err := change(&a); err != nil {
        return err
    }
    s.Save(a)
    return nil
}
```

```go
// Disburse pays an approved loan out to the customer's account.
func (s *Service) Disburse(ctx context.Context, id string) error {
    a, err := s.Get(id)
    if err != nil {
        return err
    }
    if !a.Approved {
        return ErrNotApproved
    }
    if err := s.Ledger.Credit(ctx, a.ID, a.Amount); err != nil {
        return err
    }
    a.Disbursed = true
    s.Save(a)
    return nil
}
```

```go
// Pending lists the approved loans still waiting for their money, sorted:
// the treasury reads it every morning to plan the day's cash.
func (s *Service) Pending() []string {
    s.mu.Lock()
    defer s.mu.Unlock()
    var ids []string
    for id, a := range s.apps {
        if a.Approved && !a.Disbursed {
            ids = append(ids, id)
        }
    }
    slices.Sort(ids)
    return ids
}
```

Ses tests passent :


## Exercice 4 — Conception : les virements permanents

*Niveau 4. Concevoir, puis vérifier ce qui peut l'être.*

Un client peut programmer un virement permanent : « 50 000 FCFA à ma mère,
le 25 de chaque mois ». Une tâche planifiée tourne chaque jour à 6 h 00 et
exécute les ordres du jour. La banque en a 40 000. Les règles du métier :

- si le solde est insuffisant, on réessaie le lendemain et le surlendemain,
  puis on abandonne pour ce mois et l'on prévient le client par SMS ;
- le client peut **suspendre** son ordre, et le reprendre ;
- un mois **ne se paie qu'une fois**, quoi qu'il arrive.

Questions :

1. **Les statuts d'une exécution** (un ordre, un mois) : donne la table et
   le diagramme. Vérifie-la avec `Problems`.
2. **La commande** : quels champs, et quelle **clé** ? Pourquoi un UUID tiré
   au moment de l'exécution serait-il une erreur ?
3. **Deux instances** de la tâche démarrent le 25 à 6 h 00, après un
   déploiement raté. Que se passe-t-il avec ta conception ? Qu'est-ce qui
   garantit qu'un mois n'est payé qu'une fois ?
4. **La tâche est en panne** le 25 et le 26, et redémarre le 27. Qu'exécute-t-
   elle ? Et si elle redémarre le 10 du mois suivant ?
5. **Le client suspend** son ordre le 25 à 6 h 00 min 00 s 300 ms, pendant
   l'exécution. Que garantit ta conception, et que doit-on lui répondre ?

Écris tes réponses en texte et en tables. Si tu as le temps, vérifie les
questions 3 et 4 par un petit programme, comme `cmd/double` dans la leçon.
