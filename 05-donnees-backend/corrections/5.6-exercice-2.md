# Correction 5.6 — Exercice 2 : un seul chargement pour tous

> Rappel de l'énoncé : un chargeur qui partage un seul chargement entre
> les appelants simultanés, ne garde pas les erreurs, et ne laisse pas un
> appelant pressé faire échouer les autres.

La solution est dans `ex2` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **`singleflight`** regroupe les appelants : un chargement pour cent.
- **Le chargement partagé a son propre contexte** : sans cela, le premier
  appelant qui abandonne fait échouer tous les autres.
- **Chaque appelant garde son délai** : il peut abandonner seul, sans
  arrêter le chargement.

## 1. La solution

```go
// Get returns the value of key, from the cache, or from load. Callers that
// ask for the same key at the same time share one load; an error is
// returned to them, and never kept.
func (l *Loader[V]) Get(ctx context.Context, key int64, load Load[V]) (V, error) {
    if v, ok := l.cache.Get(key); ok {
        return v, nil
    }
    // The shared load must not die with the first caller's context: it
    // runs on a context of its own, bounded so that it cannot hang.
    shared := context.WithoutCancel(ctx)
    ch := l.group.DoChan(strconv.FormatInt(key, 10), func() (any, error) {
        ctx, cancel := context.WithTimeout(shared, 10*time.Second)
        defer cancel()
        v, version, err := load(ctx)
        if err == nil {
            l.cache.Put(key, v, version)
        }
        return v, err
    })
    var zero V
    select {
    case r := <-ch:
        if r.Err != nil {
            return zero, r.Err
        }
        return r.Val.(V), nil
    case <-ctx.Done():
        return zero, ctx.Err()
    }
}
```

## 2. Le piège de l'appelant pressé

La première correction qui vient à l'esprit passe le contexte de
l'appelant au chargement partagé : `group.Do(key, func() { load(ctx) })`.
Mais `singleflight` exécute la fonction **du premier appelant**, avec
**son** contexte. Si ce premier appelant abandonne au bout de 10 ms (un
téléphone qui perd le réseau, un client pressé), le chargement est
annulé, et **tous** ceux qui attendaient reçoivent son erreur :

```text
--- FAIL: TestACallerWhoGivesUpDoesNotFailTheOthers (0.01s)
    loader_test.go:84: 20 patient callers failed, 1 loads
FAIL
FAIL    example/corr56/ex2      0.165s
FAIL
```

20 appelants patients sur 20 ont échoué à cause d'un seul impatient. La
solution sépare les deux :

- le chargement tourne sur `context.WithoutCancel(ctx)` : il garde les
  valeurs du contexte (traces, identifiants), mais pas son annulation ;
- chaque appelant attend avec `DoChan` et un `select` sur **son**
  contexte : l'impatient repart avec son erreur, les autres attendent le
  résultat.

## 3. La limite de durée

Sans limite, un chargement partagé que la base ne termine jamais
bloquerait pour toujours tous les appelants suivants de cette clé : ils
rejoindraient un chargement qui ne finit pas. Le
`context.WithTimeout(shared, 10*time.Second)` borne ce chargement. Après
10 s, il échoue ; l'erreur n'est pas gardée, et l'appelant suivant en
relance un.

## Ce qu'il faut retenir

- `singleflight` partage un chargement, et donc aussi le contexte de
  celui qui l'a lancé.
- Un travail partagé tourne sur un contexte à lui, borné ; chaque
  appelant garde le sien pour attendre.
- Une erreur ne se met pas en cache : la suivante doit pouvoir réussir.
