# Correction 5.4 — Exercice 3 : la recopie par lots

> Rappel de l'énoncé : recopier `phone` dans `phone_e164` sur une très
> grande table, par lots validés un par un, et pouvoir reprendre après
> une coupure.

La solution est dans `ex3` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Une instruction unique** tient 50 millions de verrous de ligne
  pendant des minutes, et repart de zéro après une coupure.
- **Un lot par instruction**, chaque lot validé seul : les verrous sont
  courts, et la reprise repart là où l'on s'est arrêté.
- **La condition `phone_e164 IS NULL`** rend la recopie rejouable, et le
  déclencheur de la leçon garde juste ce qui change pendant ce temps.

## 1. Le coût de l'instruction unique

- **Verrous** : chaque ligne modifiée est verrouillée jusqu'à la fin.
  Un membre qui change de téléphone pendant ce temps attend des minutes.
- **Journal** : 50 millions de lignes réécrites dans une seule
  transaction. Le WAL grossit d'un coup, et les réplicas prennent du
  retard.
- **Durée et nettoyage** : les anciennes versions des lignes restent
  jusqu'à la fin de la transaction, et le nettoyage (`VACUUM`) ne peut
  rien libérer avant.
- **Reprise** : une coupure à 95 % annule tout. On recommence de zéro.

## 2. La solution

```go
// Backfill copies phone into phone_e164 where it is empty, batch rows at a
// time, and calls after with the number of rows filled so far once each
// batch is committed. An error from after stops it there; running it again
// carries on. It returns the number of rows it filled.
func Backfill(ctx context.Context, db *pgxpool.Pool, batch int, after func(filled int) error) (int, error) {
    filled := 0
    for {
        // One statement is one transaction: each batch holds its rows only
        // for the time of its own UPDATE.
        tag, err := db.Exec(ctx, `
            UPDATE member SET phone_e164 = phone
            WHERE id IN (
                SELECT id FROM member WHERE phone_e164 IS NULL
                ORDER BY id LIMIT $1
                FOR UPDATE SKIP LOCKED)`, batch)
        if err != nil {
            return filled, err
        }
        n := int(tag.RowsAffected())
        if n == 0 {
            return filled, nil
        }
        filled += n
        if err := after(filled); err != nil {
            return filled, err
        }
    }
}
```

Trois choix :

- **chaque lot est une instruction**, donc sa propre transaction : les
  verrous ne durent que le temps de 1 000 lignes ;
- **la sélection porte sur `phone_e164 IS NULL`** : une seconde exécution
  ne voit que ce qui reste, sans avoir besoin de noter où l'on s'était
  arrêté ;
- **`FOR UPDATE SKIP LOCKED`** : une ligne qu'un membre est en train de
  modifier est sautée, au lieu de faire attendre le lot. Elle sera prise
  par un lot suivant, ou par la prochaine exécution.

Sur la vraie table, on ajouterait une courte pause entre deux lots, pour
laisser le nettoyage et les réplicas suivre, et un index partiel
`WHERE phone_e164 IS NULL` pour que chaque lot trouve vite ses lignes.

## 3. Un téléphone changé pendant la recopie

C'est le déclencheur de la leçon qui garde le résultat juste :

- si v1 change `phone` **avant** que le lot passe, le déclencheur a
  déjà recopié la nouvelle valeur dans `phone_e164` : la ligne n'est
  plus `NULL`, le lot l'ignore ;
- si v1 change `phone` **pendant** que le lot tient la ligne, la mise à
  jour de v1 attend la fin du lot, puis le déclencheur recopie la
  nouvelle valeur ;
- si v1 tient la ligne quand le lot passe, `SKIP LOCKED` la saute, et
  le déclencheur fait la recopie.

Dans les trois cas, `phone_e164` finit égal à `phone`. Sans le
déclencheur, la recopie par lots aurait une mise à jour perdue : le lot
lit l'ancien `phone`, v1 écrit le nouveau, et `phone_e164` garde
l'ancien pour toujours.

## Ce qu'il faut retenir

- Une écriture sur toute une grande table se fait par lots courts,
  validés un par un.
- Une condition sur « ce qui reste à faire » rend la recopie rejouable
  sans état à garder.
- Ce qui change pendant la recopie est tenu juste par le déclencheur de
  l'expand, pas par la recopie elle-même.
