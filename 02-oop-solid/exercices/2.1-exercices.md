# Exercices 2.1 — Modéliser : ce qui a une identité, ce qui n'en a pas

**Règles.** Réponds avant d'ouvrir la correction. Pour tous les exercices, la
question n'est jamais *« ce modèle est-il élégant ? »* mais *« deux de ces
choses sont-elles la même chose, et qu'est-ce qui se casse quand on se
trompe ? »*

Trois obligations de méthode, valables partout dans ce chapitre :

1. **Pour chaque type, écris la liste de ses champs et barre ceux qui peuvent
   changer sans que la chose change.** Ce qui reste est l'identité.
2. **Chaque fois que tu déclares qu'une chose est une valeur, dis ce que tu
   gagnes** — clé de map, cache sans invalidation, partage entre goroutines.
   Si tu ne gagnes rien, c'est peut-être une entité.
3. **Chaque fois que tu affirmes qu'un état est impossible, casse le code et
   vérifie-le.** Le niveau 1 t'a appris pourquoi.

Écris tes réponses dans `02-oop-solid/mes-reponses/2.1.md` (dossier local,
ignoré par Git).

## Exercice 1 — Compréhension

Service de mobile money, en production depuis trois ans. Deux millions de
comptes.

```go
// Package mobile est le modele d'un service de mobile money.
package mobile

import (
    "errors"
    "time"
)

var (
    ErrSoldeInsuffisant = errors.New("mobile : solde insuffisant")
    ErrPlafondDepasse   = errors.New("mobile : plafond depasse")
    ErrCompteInconnu    = errors.New("mobile : compte inconnu")
    ErrCompteBloque     = errors.New("mobile : compte bloque")
)

// Compte est le type central du service.
type Compte struct {
    Numero      string // 237691234567
    Nom         string
    Prenom      string
    DateNais    time.Time
    NumeroCNI   string
    NiveauKYC   int // 0 non verifie, 1 CNI, 2 CNI + justificatif
    SoldeFCFA   int64
    PlafondJour int64
    Bloque      bool
    CreeLe      time.Time
    ModifieLe   time.Time
}

// Operation est un mouvement d'argent.
type Operation struct {
    Reference    string // reference fournie par le canal appelant
    Emetteur     string // numero
    Destinataire string
    MontantFCFA  int64
    FraisFCFA    int64
    Horodatage   time.Time
    Statut       string // "en_cours", "confirme", "echoue"
    Motif        string
}

type Service struct {
    Comptes    map[string]*Compte
    Operations []Operation
}

// Transferer deplace de l'argent d'un compte a un autre.
func (s *Service) Transferer(deNumero, versNumero string, montant int64, reference string, maintenant time.Time) error {
    de, connu := s.Comptes[deNumero]
    if !connu {
        return ErrCompteInconnu
    }
    vers, connu := s.Comptes[versNumero]
    if !connu {
        return ErrCompteInconnu
    }
    if de.Bloque || vers.Bloque {
        return ErrCompteBloque
    }

    frais := montant * 15 / 1000
    if de.SoldeFCFA < montant+frais {
        return ErrSoldeInsuffisant
    }

    var cumule int64
    for _, o := range s.Operations {
        if o.Emetteur == deNumero && o.Statut == "confirme" &&
            o.Horodatage.Year() == maintenant.Year() &&
            o.Horodatage.YearDay() == maintenant.YearDay() {
            cumule += o.MontantFCFA
        }
    }
    if cumule+montant > de.PlafondJour {
        return ErrPlafondDepasse
    }

    de.SoldeFCFA -= montant + frais
    vers.SoldeFCFA += montant
    de.ModifieLe = maintenant
    vers.ModifieLe = maintenant

    s.Operations = append(s.Operations, Operation{
        Reference:    reference,
        Emetteur:     deNumero,
        Destinataire: versNumero,
        MontantFCFA:  montant,
        FraisFCFA:    frais,
        Horodatage:   maintenant,
        Statut:       "confirme",
    })
    return nil
}

// MettreAJourKYC enregistre une verification d'identite.
func (s *Service) MettreAJourKYC(numero, cni string, niveau int, maintenant time.Time) error {
    c, connu := s.Comptes[numero]
    if !connu {
        return ErrCompteInconnu
    }
    c.NumeroCNI = cni
    c.NiveauKYC = niveau
    switch niveau {
    case 0:
        c.PlafondJour = 50_000
    case 1:
        c.PlafondJour = 500_000
    case 2:
        c.PlafondJour = 5_000_000
    }
    c.ModifieLe = maintenant
    return nil
}

// MemeCompte est la fonction de comparaison utilisee par le travail de
// dedoublonnage nocturne.
func MemeCompte(a, b Compte) bool {
    return a.Nom == b.Nom && a.Prenom == b.Prenom &&
        a.DateNais.Equal(b.DateNais) && a.NumeroCNI == b.NumeroCNI
}
```

1. **Applique le test décisif à chaque type** — `Compte`, `Operation` — puis à
   chaque champ de `Compte`. Pour chacun : *si je change ce champ, est-ce
   toujours la même chose ?*

   Rends le résultat sous cette forme :

   | Champ | Change sans que la chose change ? | Donc |
   |---|---|---|

2. **`Compte` mélange combien de concepts métier ?** Nomme-les, et pour chacun
   dis quelle est son identité. Indice sur le compte des concepts : il y en a
   plus que deux, et le métier a un mot pour chacun.

3. `Numero` est une chaîne. Liste **cinq** états qu'une chaîne permet et que le
   métier interdit. Puis dis lequel des cinq est le plus dangereux et pourquoi —
   ce n'est pas le plus invraisemblable.

4. **`Operation.Statut` est une chaîne de trois valeurs possibles.** Quels états
   ce choix autorise-t-il ? Combien de fois cette chaîne est-elle comparée dans
   le code fourni, et que se passe-t-il le jour où quelqu'un écrit `"confirmé"`
   avec un accent ?

5. **`MemeCompte` sert à un travail de dédoublonnage nocturne.** Lis-la, puis
   réponds :
   - sur quels champs compare-t-elle, et pourquoi ce choix a l'air raisonnable ?
   - construis **deux comptes distincts** que cette fonction déclare identiques.
     Donne les valeurs exactes.
   - construis **un même compte** que cette fonction déclare différent de
     lui-même à deux instants.
   - que fait le travail de dédoublonnage, concrètement, dans le premier cas ?

6. Le plafond journalier est recalculé dans `MettreAJourKYC` à partir du niveau
   KYC. **Où vit l'invariant « le plafond correspond au niveau KYC » ?** Que se
   passe-t-il si quelqu'un écrit `c.PlafondJour = 10_000_000` ailleurs dans le
   code ? Combien d'endroits faut-il relire pour en être sûr ?

7. `Transferer` recalcule le cumulé journalier en parcourant **toutes** les
   opérations. Au-delà du coût : **quel invariant cette boucle essaie-t-elle de
   tenir, et sur combien d'entités porte-t-il ?** Peut-il avoir un foyer dans
   les types ?

## Exercice 3 — Refactoring

Cabinet médical, quatre ans de production, un seul type.

```go
// Package cabinet est le modele d'un cabinet medical, tel qu'il est en
// production depuis quatre ans.
package cabinet

import (
    "errors"
    "time"
)

var ErrIntrouvable = errors.New("cabinet : introuvable")

// Fiche est le type unique du modele. Elle sert au patient, a la consultation
// et a l'ordonnance.
type Fiche struct {
    // Patient
    IDPatient  int64
    NomPatient string
    DateNais   time.Time
    Telephone  string
    GroupeSang string
    Allergies  string

    // Consultation
    DateConsult time.Time
    Praticien   string
    Motif       string
    TensionSys  int
    TensionDia  int
    PoidsKg     float64

    // Ordonnance
    Medicament   string
    DosageMg     float64
    ParJour      int
    DureeJours   int
    Renouvelable bool
    Delivree     bool
    DelivreeLe   time.Time
}

type Depot interface {
    Fiches(idPatient int64) ([]Fiche, error)
    Enregistrer(f Fiche) error
}

type Service struct {
    depot Depot
}

func Nouveau(d Depot) *Service { return &Service{depot: d} }

// Prescrire ajoute une ligne d'ordonnance.
func (s *Service) Prescrire(f Fiche) error {
    if f.DosageMg <= 0 || f.ParJour <= 0 || f.DureeJours <= 0 {
        return errors.New("cabinet : posologie invalide")
    }
    return s.depot.Enregistrer(f)
}

// Delivrer marque un medicament comme delivre.
func (s *Service) Delivrer(idPatient int64, medicament string, maintenant time.Time) error {
    fiches, err := s.depot.Fiches(idPatient)
    if err != nil {
        return err
    }
    for _, f := range fiches {
        if f.Medicament == medicament && !f.Delivree {
            f.Delivree = true
            f.DelivreeLe = maintenant
            return s.depot.Enregistrer(f)
        }
    }
    return ErrIntrouvable
}

// MettreAJourTelephone corrige le numero d'un patient.
func (s *Service) MettreAJourTelephone(idPatient int64, telephone string) error {
    fiches, err := s.depot.Fiches(idPatient)
    if err != nil {
        return err
    }
    if len(fiches) == 0 {
        return ErrIntrouvable
    }
    for _, f := range fiches {
        f.Telephone = telephone
        if err := s.depot.Enregistrer(f); err != nil {
            return err
        }
    }
    return nil
}

// DoseJournaliere calcule la dose quotidienne.
func DoseJournaliere(f Fiche) float64 { return f.DosageMg * float64(f.ParJour) }
```

1. **Combien de concepts le type `Fiche` porte-t-il ?** Pour chacun, dis son
   identité et le mot que le métier utilise. Attention au piège : il y a un
   concept de plus que ce que les trois commentaires du code suggèrent.

2. Les trois méthodes du service contiennent chacune un bug de modélisation
   différent. Pour chacune, décris **le scénario patient** — pas le bug
   technique, ce que le patient vit :
   - `Delivrer`
   - `MettreAJourTelephone`
   - `Prescrire`

3. `DoseJournaliere(f Fiche) float64` prend une fiche entière pour lire deux
   champs. **Sur quel concept cette fonction porte-t-elle vraiment ?** Écris sa
   bonne signature. Puis : qu'est-ce que `float64` autorise ici qu'une posologie
   interdit ?

4. **Découpe.** Donne les types, et pour chacun : valeur ou entité, son
   identité, ses invariants, et la phrase de sa raison de changer. Si tu
   n'arrives pas à écrire cette phrase pour un type, c'est la réponse.

5. Deux pièges t'attendent dans cette découpe, et ils sont de sens contraire.
   Dis lequel tu as rencontré :
   - **trop peu de types** : tu as gardé ensemble deux choses dont les identités
     diffèrent ;
   - **trop de types** : tu as fait une entité de quelque chose qui n'a pas de
     cycle de vie propre.

   Quel critère tranche ? Il ne tient pas en « ça dépend ».

6. Écris le code de **un seul** de tes types — celui qui porte le plus
   d'invariants — avec ses tests. Puis applique la campagne de modifications de
   la leçon 1.6 : cinq modifications, le relevé de qui crie, et les survivantes
   nommées.

7. **Le compteur.** `Allergies` est une chaîne. `GroupeSang` est une chaîne.
   Combien de tes nouveaux types ont été créés uniquement pour remplacer une
   chaîne, et **lesquels ne valaient pas le coup ?** Sois sévère : c'est la
   question qui sépare un modèle d'une cérémonie.

## Exercice 4 — Design

Reprends le service de mobile money.

1. **D'où vient l'identité d'un portefeuille ?** Trois propositions :

   | | Identité |
   |---|---|
   | A | le numéro de téléphone |
   | B | un identifiant interne attribué par la base |
   | C | le numéro de CNI du titulaire |

   Pour chacune : ce qu'elle garantit, ce qu'elle coûte, et **ce qui arrive le
   jour où elle change**. Parce qu'elles changent toutes les trois — dis
   comment, pour chacune.

2. Un client perd son téléphone et obtient le même numéro après six mois de
   recyclage par l'opérateur. **Est-ce le même portefeuille ?** Réponds, puis
   dis ce que ta réponse implique sur ton choix du §1. Puis : **le métier
   est-il d'accord avec toi ?** Comment le sais-tu ?

3. **Le cache.** Le service met en cache les portefeuilles pour tenir la charge.
   - Pourquoi un `Numero` peut-il être mis en cache sans invalidation, et pas un
     `Portefeuille` ?
   - Quelqu'un propose de mettre en cache `(Numero, PlafondJour)` — une paire
     immuable extraite du portefeuille. Est-ce une valeur ? Est-ce **sûr** ?
   - Quelle propriété du modèle décide, dans les deux cas ?

4. **L'identité d'une opération.** Elle a une `Reference` fournie par le canal
   appelant. Trois questions :
   - est-ce une identité, ou une clé d'idempotence, ou les deux ?
   - deux canaux différents peuvent-ils fournir la même référence ?
   - si oui, que devient l'identité, et qu'est-ce que ça change dans le modèle ?

   Rattache ta réponse à la clé d'idempotence de la correction 1.6/4.

5. **L'invariant inter-entités, encore.** « La somme de tous les soldes des
   portefeuilles est égale à la somme des dépôts moins les retraits moins les
   frais. » C'est l'invariant comptable, et c'est le seul qui compte vraiment
   dans ce métier.
   - a-t-il un foyer dans les types ? Explique pourquoi la réponse est non.
   - où vit-il alors ?
   - **par quoi remplace-t-on une garantie qu'on ne peut pas avoir ?** Tu as la
     réponse depuis la correction 1.6/4 — applique-la ici : la grandeur, sa
     valeur de référence, son seuil, et sa fréquence.

6. **Question ouverte.** Un collègue dit : *« tout ça est très joli, mais notre
   base a une table `comptes` avec vingt-deux colonnes, et il y a quatre
   services qui écrivent dedans. Ton modèle ne survivra pas à la première
   requête SQL. »*

   Il a raison sur les faits. Réponds-lui, et ne réponds pas « il faut tout
   réécrire ». Décris une **stratégie incrémentale** : par quoi tu commences, ce
   qui te dit que ça a marché, et ce que tu ne feras pas. Donne un critère
   mesurable pour savoir si le premier pas a gagné quelque chose.

## Exercice 5 — Incident de production

Plateforme de mobile money. Extrait du post-mortem.

```
sam. 02h00  le travail de dedoublonnage nocturne demarre (il tourne depuis 14 mois)
sam. 02h41  il termine : « 1 843 doublons fusionnes »
sam. 08h12  premier appel au service client : « mon solde est a zero »
sam. 09h30  47 appels. Le travail est desactive a la main
sam. 14h00  reconstitution a partir du journal des operations : 1 843 portefeuilles
            fusionnes, dont 1 790 a tort. 12,4 millions FCFA de soldes perdus
lun. 09h00  reunion de crise. La question posee est « comment on a pu faire ca »
```

Établi après coup :

- Le travail de dédoublonnage utilise `MemeCompte` pour détecter les doublons,
  puis additionne les soldes et supprime le second compte.
- Il tourne depuis quatorze mois et avait fusionné 11 comptes au total, tous
  légitimement.
- La semaine précédente, une campagne de vérification d'identité a enregistré
  les CNI de 340 000 clients en masse, par un import de fichier.
- L'import renseignait `NumeroCNI` pour les clients vérifiés et laissait la
  chaîne **vide** pour les autres.
- La campagne a aussi normalisé les noms en majuscules, sans accents, et au
  format `NOM PRENOM` — alors que le modèle a deux champs séparés.
- `DateNais` était absente pour 60 % des comptes ouverts avant 2022.
- Les tests du travail de dédoublonnage : 96 % de couverture, 23 tests, tous
  verts.

1. **La cause immédiate n'est pas l'import.** Nomme les **quatre décisions de
   modélisation** qui ont rendu cet incident possible. Pour chacune, dis à quel
   endroit de la leçon elle correspond.

2. **Fais le calcul.** Après l'import, combien de comptes `MemeCompte` déclare-t-il
   identiques ? Donne le raisonnement, pas un chiffre au hasard — les
   informations nécessaires sont dans le post-mortem.

3. 23 tests, 96 % de couverture. **Quelle propriété du modèle rendait ce
   scénario inobservable par ces tests ?** Et quel test, en une phrase, l'aurait
   attrapé ?

4. **Six heures et douze minutes** entre la fin du travail et le premier appel.
   Puis **une heure et dix-huit** de plus avant la désactivation. Qu'est-ce que
   le modèle a à voir avec ces deux durées ? Rattache aux deux termes du MTTR.

5. La reconstitution a été possible « à partir du journal des opérations ».
   **Qu'est-ce que ça dit du journal, et qu'est-ce que ça dit des soldes ?**
   Formule la distinction en termes de cette leçon : qu'est-ce qui est la source
   de vérité, et qu'est-ce qui est un cache ?

6. **La correction.** Trois propositions arrivent en réunion :

   | | Proposition |
   |---|---|
   | A | ajouter `&& a.NumeroCNI != ""` à `MemeCompte` |
   | B | exiger une validation humaine avant chaque fusion |
   | C | rendre la fusion de deux portefeuilles impossible, et traiter le doublon autrement |

   Pour chacune : ce qu'elle empêche, ce qu'elle n'empêche pas, et ce qu'elle
   coûte. Laquelle choisis-tu, et **qu'est-ce que tu fais des 1 790 fusions déjà
   faites ?**

7. **Question ouverte.** La direction demande une garantie : *« que plus jamais
   un travail automatique ne puisse détruire de l'argent client ».*

   « On va faire plus attention » est faux. « On va rendre ça impossible » est
   faux aussi, et tu dois pouvoir expliquer pourquoi en deux phrases.

   Propose donc :
   - **une propriété du modèle** qui rend la classe entière de ce bug
     impossible — pas ce bug-là, la classe ;
   - **ce qu'elle coûte**, chiffré en ce qu'elle interdit de faire ;
   - **une mesure** pour ce que la propriété ne couvre pas, avec son seuil ;
   - et la question qui compte : **à quelle condition ta propriété survit-elle
     au prochain développeur pressé ?** Tu as un outil pour ça depuis la
     leçon 2.1 et un autre depuis la 1.6.
