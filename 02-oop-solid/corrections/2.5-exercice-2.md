# Correction 2.5 — Exercice 2 : le service d'octroi de crédit

> Rappel de l'énoncé : un métier qui consulte un bureau de crédit (HTTP),
> l'historique des comptes (PostgreSQL), un barème (YAML), et notifie par
> SMTP — avec ses ports, quatre adaptateurs, une racine de composition, un
> test d'architecture et une batterie.

Sept paquets — `lending`, `creditbureau`, `history`, `scale`,
`notification`, `wiring`, `archi` —, verts sous `go vet ./...` et
`go test -race -count=1 ./...`. Campagne de dix-huit modifications, 18/18
après deux passes. Le barème est lu avec `gopkg.in/yaml.v3`, pour que le test
d'architecture ait une vraie bibliothèque tierce à interdire.

## 1. Le métier et ses ports

Un port par source, chacun avec les seules méthodes qu'`lending` appelle, et
le vocabulaire d'erreurs qui leur est commun :

```go
// The ports' vocabulary. An adapter that returns these errors imports this
// package: the legitimate exception of lesson 2.4.
var (
    ErrBureauUnavailable = errors.New("lending: credit bureau unavailable")
    ErrUnknownProfile    = errors.New("lending: unknown profile")
)

// Incident is a payment incident reported to the credit bureau.
type Incident struct {
    Date   time.Time
    Amount int64
}

// Application is a loan application.
type Application struct {
    Applicant   string
    Profile     string
    Installment int64 // in cents
}

// Decision is the answer given to the applicant.
type Decision struct {
    Approved bool
    Reason   string
}

// Bureau reads an applicant's payment incidents.
type Bureau interface {
    Incidents(applicant string) ([]Incident, error)
}

// History reads, in the bank's account keeping, what makes the regular
// income and the current commitments.
type History interface {
    MonthlyIncomes(applicant string, months int) ([]int64, error)
    CurrentInstallments(applicant string) (int64, error)
}

// Scale returns a profile's maximum debt ratio, in basis points: 3300 for
// 33 %.
type Scale interface {
    MaxRate(profile string) (int64, error)
}

// Notifier writes the decision to the applicant.
type Notifier interface {
    Notify(applicant string, d Decision) error
}

// Service is the lending business.
type Service struct {
    Bureau   Bureau
    History  History
    Scale    Scale
    Notifier Notifier
}
```

Deux choix méritent d'être dits.

- **Le barème rend des points de base**, pas un `float64`. « 33 % » devient
  3300, et la comparaison se fait en entiers, sans arrondi.
- **`History` a deux méthodes**, `Bureau` une seule. Le critère est
  l'usage (leçon 2.5, section 5), pas la taille : les deux lectures de
  l'historique viennent de la même source et changent ensemble.

La règle, en entier :

```go
func (s Service) rule(a Application, now time.Time) (Decision, error) {
    incidents, err := s.Bureau.Incidents(a.Applicant)
    if err != nil {
        return Decision{}, err
    }
    limit := now.AddDate(0, -IncidentWindow, 0)
    for _, i := range incidents {
        if i.Date.After(limit) {
            return Decision{Reason: "payment incident less than 24 months old"}, nil
        }
    }
    incomes, err := s.History.MonthlyIncomes(a.Applicant, IncomeMonths)
    if err != nil {
        return Decision{}, err
    }
    if len(incomes) < IncomeMonths {
        return Decision{Reason: "less than six months of income"}, nil
    }
    // The regular income is the SMALLEST of the six: an exceptional month
    // must not get a file through.
    regular := incomes[0]
    for _, r := range incomes[1:] {
        regular = min(regular, r)
    }
    current, err := s.History.CurrentInstallments(a.Applicant)
    if err != nil {
        return Decision{}, err
    }
    rate, err := s.Scale.MaxRate(a.Profile)
    if err != nil {
        return Decision{}, err
    }
    if (current+a.Installment)*10_000 > rate*regular {
        return Decision{Reason: "debt ratio above the scale"}, nil
    }
    return Decision{Approved: true}, nil
}
```

La preuve que le métier ne connaît aucune technologie, demandée par la
question 1 :

```

gopkg.in/yaml.v3   lending=0 wiring=1
```

`lending` a 60 dépendances, toutes de la bibliothèque standard ; l'adaptateur
`creditbureau`, à lui seul, en a 200.

## 2. Les quatre adaptateurs

Chacun **traduit** — c'est son seul travail. Le bureau de crédit, par
exemple, transforme un 404 en « aucun incident » et tout autre échec en
`ErrBureauUnavailable` :

```go
// Incidents translates the bureau's answer into lending's vocabulary: a 404
// means "unknown to the bureau", hence no incident; anything else that is not
// a 200 means "unavailable".
func (c Client) Incidents(applicant string) ([]lending.Incident, error) {
    r, err := c.HTTP.Get(c.Base + "/incidents?person=" + url.QueryEscape(applicant))
    if err != nil {
        return nil, fmt.Errorf("%w: %v", lending.ErrBureauUnavailable, err)
    }
    defer r.Body.Close()
    switch {
    case r.StatusCode == http.StatusNotFound:
        return nil, nil
    case r.StatusCode != http.StatusOK:
        return nil, fmt.Errorf("%w: status %d", lending.ErrBureauUnavailable, r.StatusCode)
    }
    var raw []incidentJSON
    if err := json.NewDecoder(r.Body).Decode(&raw); err != nil {
        return nil, fmt.Errorf("%w: unreadable answer: %v", lending.ErrBureauUnavailable, err)
    }
    out := make([]lending.Incident, 0, len(raw))
    for _, i := range raw {
        out = append(out, lending.Incident{Date: i.Date, Amount: i.Amount})
    }
    return out, nil
}
```

Le barème valide le fichier entier au chargement, et refuse un taux hors de
[1, 10 000] — la faute visée est un zéro de trop, qui ferait accorder des
crédits à 330 % d'endettement :

```go
// Load reads and validates the file: one rate per profile, in basis points,
// between 1 and 10,000.
func Load(path string) (*File, error) {
    b, err := os.ReadFile(path)
    if err != nil {
        return nil, err
    }
    var raw struct {
        Rates map[string]int64 `yaml:"max_rate_basis_points"`
    }
    if err := yaml.Unmarshal(b, &raw); err != nil {
        return nil, fmt.Errorf("scale: %w", err)
    }
    if len(raw.Rates) == 0 {
        return nil, fmt.Errorf("scale: no profile in %s", path)
    }
    for p, r := range raw.Rates {
        if r < 1 || r > 10_000 {
            return nil, fmt.Errorf("scale: profile %q, rate %d outside [1, 10000]", p, r)
        }
    }
    return &File{rates: raw.Rates}, nil
}
```

L'historique, sur PostgreSQL, **compile mais n'est jamais exécuté** : il n'y a
pas de base dans ce module. C'est la limite de l'exercice, et il faut la
dire : ses requêtes SQL ne sont vérifiées par rien ici. En production, il
lui faut une batterie du port `History` passée contre une vraie base
jetable — c'est le seul adaptateur dont le contrat ne se vérifie pas avec une
doublure.

## 3. La racine de composition

```go
// Assemble wires the four adapters onto the business.
func Assemble(c Config, db *sql.DB, h *http.Client) (lending.Service, error) {
    s, err := scale.Load(c.ScalePath)
    if err != nil {
        return lending.Service{}, err
    }
    return lending.Service{
        Bureau:  creditbureau.Client{Base: c.BureauURL, HTTP: h},
        History: history.Postgres{DB: db},
        Scale:   s,
        Notifier: notification.SMTP{
            Server: c.SMTPServer, Sender: "loans@bank.example",
            Address: c.Address, Send: smtp.SendMail,
        },
    }, nil
}
```

**Si un adaptateur cesse de satisfaire son port, c'est ici que ça casse** —
et la question 7 le mesure. Mais la campagne a montré qu'elle ne suffit
pas : un port câblé à `nil` compile. D'où le test :

```go
// TestEverythingIsWired: the compiler checks the type of each wired port, not
// that each port is wired.
func TestEverythingIsWired(t *testing.T) {
    s, err := Assemble(Config{ScalePath: "../scale/testdata/scale.yaml"}, nil, http.DefaultClient)
    if err != nil {
        t.Fatal(err)
    }
    v := reflect.ValueOf(s)
    for i := range v.NumField() {
        if v.Field(i).IsNil() {
            t.Errorf("port %s is not wired", v.Type().Field(i).Name)
        }
    }
}
```

## 4. Le test d'architecture

```go
const module = "example/c25/ex2/"

// forbidden: what the business must never pull, directly or not.
var forbidden = map[string][]string{
    "lending": {
        "net/http", "database/sql", "net/smtp", "gopkg.in/yaml.v3",
        module + "creditbureau", module + "history", module + "scale", module + "notification",
    },
}

// infrastructure: the packages that may import anything.
var infrastructure = map[string]bool{
    "creditbureau": true, "history": true, "scale": true, "notification": true,
    "wiring": true, "archi": true,
}

func violations(t *testing.T, pkg string, refused []string) []string {
    t.Helper()
    out, err := exec.Command("go", "list", "-deps", pkg).Output()
    if err != nil {
        t.Fatalf("go list %s: %v", pkg, err)
    }
    deps := map[string]bool{}
    for _, d := range strings.Fields(string(out)) {
        deps[d] = true
    }
    var found []string
    for _, r := range refused {
        if deps[r] {
            found = append(found, r)
        }
    }
    return found
}

func TestTheBusinessPullsNoTechnology(t *testing.T) {
    for p, refused := range forbidden {
        for _, v := range violations(t, "../"+p, refused) {
            t.Errorf("%s depends on %s", p, v)
        }
    }
}

// TestTheTestSeesARealViolation: the HTTP adapter pulls net/http, and it is a
// real dependency, not a string written for the occasion. It also "depends"
// on itself: go list -deps counts the package among its dependencies.
func TestTheTestSeesARealViolation(t *testing.T) {
    got := violations(t, "../creditbureau", forbidden["lending"])
    if strings.Join(got, " ") != "net/http "+module+"creditbureau" {
        t.Fatalf("creditbureau's violations: %v", got)
    }
}

func TestTheListCoversTheWholeModule(t *testing.T) {
    out, err := exec.Command("go", "list", "../...").Output()
    if err != nil {
        t.Fatal(err)
    }
    for _, p := range strings.Fields(string(out)) {
        name := strings.TrimPrefix(p, module)
        if !infrastructure[name] && forbidden[name] == nil {
            t.Errorf("%s is neither infrastructure nor business", name)
        }
    }
}
```

Le test négatif tire sur une **vraie** violation : l'adaptateur `creditbureau`,
qui importe réellement `net/http`. Et il m'a appris une chose en tirant : il
a rendu **deux** violations, pas une — `net/http` et `creditbureau` lui-même.
`go list -deps` compte le paquet parmi ses propres dépendances. Sans
conséquence pour `lending`, qui ne s'interdit pas lui-même, mais une liste
d'interdits qui contiendrait le paquet testé serait toujours rouge.

## 5. La batterie du port `Bureau`

Écrite dans `lending`, qui déclare le port :

```go
// BureauFixture is what the Bureau port's battery asks for: a bureau that
// knows Awa (two incidents), Bala (none), and a bureau that is down.
type BureauFixture struct {
    New  func(incidents map[string][]Incident) Bureau
    Down func() Bureau
}

var (
    old    = time.Date(2021, time.June, 1, 0, 0, 0, 0, time.UTC)
    recent = time.Date(2025, time.November, 3, 0, 0, 0, 0, time.UTC)
    file   = map[string][]Incident{"awa": {{Date: old, Amount: 120_000}, {Date: recent, Amount: 45_000}}}
)

// VerifyBureau runs the three clauses of the Bureau port. It lives here: it
// is lending that declares the port, it is lending that says what it expects
// from it.
func VerifyBureau(f BureauFixture) []string {
    var out []string
    b := f.New(file)
    is, err := b.Incidents("awa")
    if err != nil || len(is) != 2 || !is[0].Date.Equal(old) || !is[1].Date.Equal(recent) || is[1].Amount != 45_000 {
        out = append(out, fmt.Sprintf("clause 1: awa's incidents = %v, %v", is, err))
    }
    if is, err := b.Incidents("bala"); err != nil || len(is) != 0 {
        out = append(out, fmt.Sprintf("clause 2: an applicant with no incident returns %v, %v — want nothing and no error", is, err))
    }
    if _, err := f.Down().Incidents("awa"); !errors.Is(err, ErrBureauUnavailable) {
        out = append(out, fmt.Sprintf("clause 3: a bureau that is down returns %v, not ErrBureauUnavailable", err))
    }
    return out
}
```

Le relevé : l'adaptateur HTTP, branché sur un `httptest.Server`, et la
doublure des tests du métier **tiennent les trois clauses**. Et un fautif
écrit pour la vérifier — un bureau qui rend « aucun incident » quand il est en
panne, c'est-à-dire qui laisse passer un dossier à risque — en casse une :

```go
// swallower returns "no incident" when the bureau is down: a risky file gets
// through. The battery must see it.
type swallower struct{}

func (swallower) Incidents(string) ([]Incident, error) { return nil, nil }

func TestTheBatterySeesASwallowedOutage(t *testing.T) {
    failures := VerifyBureau(BureauFixture{
        New:  func(is map[string][]Incident) Bureau { return bureau(is) },
        Down: func() Bureau { return swallower{} },
    })
    if len(failures) != 1 || !strings.HasPrefix(failures[0], "clause 3:") {
        t.Fatalf("%v", failures)
    }
}
```

## 6. Le sondage sur mes propres ports

Le sondage de la leçon cherche `pkg.Interface` ; ici les ports sont déclarés
et appelés dans le même paquet. J'en ai écrit la variante, qui lit les champs
de `Service` et les appels `s.Field.Method` :

```go
// TestEveryPortMethodIsCalled: the lesson's probe, applied to the ports
// lending declares. A method lending does not call has no business in its
// port.
func TestEveryPortMethodIsCalled(t *testing.T) {
    ports, _, calls := read(t)
    var names []string
    for p := range ports {
        names = append(names, p)
    }
    sort.Strings(names)
    for _, p := range names {
        for _, m := range ports[p] {
            if calls[p+"."+m] {
                t.Logf("%-8s %-20s called", p, m)
            } else {
                t.Errorf("%s.%s: declared, never called by lending", p, m)
            }
        }
    }
    if len(names) != 4 {
        t.Fatalf("%d ports read, want 4: %v", len(names), names)
    }
}
```

Les quatre modifications exigées par l'énoncé sont tuées, chacune par le
garde prévu pour elle :

| Modification | Tuée par |
|---|---|
| `lending` importe un adaptateur | le test d'architecture |
| un `*http.Response` dans un type du port | le test d'architecture — `lending` importe alors `net/http` |
| `lending` retiré de la liste du test | le garde de la liste |
| une méthode de port que personne n'appelle | le sondage de la question 6 |

La deuxième était impossible telle quelle — changer la signature d'un port
casse toutes ses implémentations — et je l'ai jouée sous la forme qui compile
et qui arrive vraiment : un champ `Raw *http.Response` ajouté à
`Incident`, « pour le débogage ». Un type de l'adaptateur entre dans le métier
par une structure, pas par une méthode.

Deux modifications ne compilaient pas — une variable devenue inutilisée, un
import devenu inutilisé — et ont été rejouées sous une forme qui compile
(`current*0`, un port câblé à `nil`). Une modification qui ne compile pas
n'a pas été jouée.

Le survivant, « batterie `Bureau` : clause 3 muette », **réclame un test** :
aucune implémentation ne rendait autre chose que la bonne sentinelle en
panne. C'est le fautif de la question 5.

## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | Un port par source, avec les seules méthodes que le métier appelle. Le critère est l'usage : `History` a deux méthodes, et c'est juste. |
| ⚫ | Le métier tire 60 dépendances standard ; un seul adaptateur HTTP en tire 200. `go list -deps` le prouve en une ligne. |
| ⚫ | Un adaptateur traduit : statuts HTTP vers sentinelles, fichier vers taux validés. La validation à la frontière refuse le fichier entier. |
| ⚫ | Un adaptateur qu'on ne peut pas exécuter ici — l'historique SQL — n'est vérifié par rien. Il faut le dire, et lui donner une batterie contre une base jetable. |
| ⚫ | La racine de composition casse quand un adaptateur ne satisfait plus son port ; elle ne casse pas quand un port est câblé à `nil`. Un test le fait. |
| ⚫ | `go list -deps` compte le paquet parmi ses dépendances. Un test négatif qui tire sur une vraie violation l'apprend. |
| ⚫ | La mesure A donne deux paquets : la racine, et les tests de l'adaptateur qui le branchent sur la batterie. Le métier ne bouge pas. |
| ⚫ | Un type d'infrastructure entre dans le métier par un champ de structure plus souvent que par une signature. Le test d'architecture le voit quand même. |
