# Correction 2.2 — Exercice 4 : la plateforme d'intégration

> Rappel de l'énoncé : des connecteurs qui arrivent par deux ou trois par
> trimestre — parfois écrits par le partenaire lui-même — et trois appelants
> aux besoins différents. Il fallait déclarer les interfaces, poser le
> vocabulaire partagé, mesurer, loger la sélection, et proposer une garantie.

L'axe est l'inverse de celui de l'exercice 2 : **variantes ouvertes,
opérations fermées**. C'est donc le cas de l'interface, et pas celui du type
somme. Tout ce qui suit est mesuré sur un module de sept paquets de test, tous
verts sous `go vet` et `go test -race -count=1`.

## 1. Les interfaces (question 1)

### Trois appelants, trois interfaces

| Appelant | Interface déclarée | Méthodes | Pourquoi exactement celles-là |
|---|---|---|---|
| `scheduler` | `Collector` | **2** | il nomme une source dans ses journaux, et il lance une collecte |
| `monitoring` | `Watched` | **2** | il nomme une source dans son tableau, et il lit son état |
| `catalog` | `Documented` | **3** | il nomme une source, liste ses champs, et cite sa fréquence contractuelle |

```
$ ...                              Collector : 2 methodes
$ ...                              Watched  : 2 methodes
$ ...                              Documented : 3 methodes
$ connecteurs (chaque connecteur)             : 5 methodes
```

Cinq méthodes implémentées, et **aucun appelant n'en voit plus de trois**. Une
seule — `Source()` — est partagée par les trois interfaces, et ce n'est pas un
hasard : c'est le seul besoin que les trois ont en commun.

```go
// Collector is THIS PACKAGE's interface. Two methods.
// Its signature names only types of package collect, that is of the
// shared vocabulary: it is on this condition, and on this condition
// only, that a connector need not import its caller.
type Collector interface {
    Source() collect.Source
    Collect(p collect.Window) ([]collect.Record, error)
}

// Journal records what the scheduler does.
//
// Selection is called at the moment of CHOICE, before knowing whether it works. Without
// this line, an incomplete collection cannot be attributed: whoever writes
// the result line does not know which connector was chosen. It is the
// answer to question 7 of the statement.
type Journal interface {
    Selection(execution string, source collect.Source, window collect.Window)
    Result(execution string, source collect.Source, records int, err error)
}
```

### Pourquoi pas une interface unique

Si on avait écrit une seule interface à cinq méthodes, le compte des doubles
de test aurait été :

| | Interface unique à 5 méthodes | Trois interfaces |
|---|---|---|
| double d'`scheduler` | 5 méthodes, 3 jamais lues | **2**, 0 jamais lue |
| double de `monitoring` | 5 méthodes, 3 jamais lues | **2**, 0 jamais lue |
| double de `catalog` | 5 méthodes, 2 jamais lues | **3**, 0 jamais lue |
| **total** | **15 méthodes, 8 jamais lues** | **7 méthodes, 0 jamais lue** |

> Huit méthodes inutiles dans des doubles, ce ne sont pas huit lignes de trop :
> ce sont huit endroits où une future méthode ira se cacher, et huit valeurs
> que personne ne vérifie.

## 2. Le vocabulaire partagé (question 2)

La prédiction, avant d'écrire une ligne : si les signatures nommaient
`scheduler.Window` ou `monitoring.Health`, **chaque connecteur devrait
importer ses appelants**. L'interface serait bien déclarée chez l'appelant, et
la flèche serait quand même inversée — seulement déguisée.

Les types partagés vont donc dans leur propre paquet, en bas du graphe :

```go
// Package collect holds the vocabulary shared between the platform and its
// connectors.
//
// This package exists because of a measure. The three interfaces are declared
// at their callers, which is the right rule; but if their signatures
// named scheduler.Window or monitoring.Health, each connector
// would have to import its callers, and the arrow would only be disguised.
//
// Rule: declaring an interface at the caller decouples only if its
// signature names only SHARED types. Decoupling by interface
// moves the dependency to the vocabulary; if the vocabulary has no
// package, it falls back on the caller.
package collect
```

Et la mesure, après :

```
$ for p in collecte connecteurs ordonnanceur supervision catalogue registre; do
>   printf '%-14s : ' $p; go list -f '{{join .Imports " "}}' ./$p
> done
collecte       : errors fmt slices strings time
connecteurs    : errors example/integration/collect fmt time
ordonnanceur   : errors example/integration/collect fmt
supervision    : errors example/integration/collect time
catalogue      : errors example/integration/collect fmt slices
registre       : errors exemple/integration/catalogue example/integration/collect exemple/integration/connecteurs exemple/integration/ordonnanceur exemple/integration/supervision fmt
```

`connectors` n'importe **aucun** des trois appelants. `collect` n'importe
rien du module. Et `registry` importe tout — c'est la seule ligne qui a le
droit d'être longue, et la section 5 dit pourquoi.

## 3. Les connecteurs (question 3)

```go
// Package connectors holds the concrete implementations.
//
// It imports NONE of the three calling packages: neither scheduler, nor
// monitoring, nor catalog. It is the measure to remember, and it is checked
// by go list.
//
// Each connector carries FIVE methods. The scheduler sees two of them, the
// monitoring two, the catalog three, and a single one, Source, is shared
// by the three. No caller sees all five.
package connectors

import (
    "errors"
    "fmt"
    "time"

    "example/integration/collect"
)
```

Les quatre connecteurs partagent un champ `base` dont les méthodes sont
promues. **Incorporation, pas héritage** : `base` n'est pas une classe mère,
c'est un champ. La différence est le sujet de la leçon 2.3 ; ici elle sert
seulement à ne pas recopier cinq fois le même code.

Deux décisions de conception méritent un mot, et la première est la plus
importante du module.

**La provenance est posée par le connecteur, à un seul endroit.**

```go
func (b base) collect(p collect.Window) ([]collect.Record, error) {
    now := time.Time{}
    if b.clock != nil {
        now = b.clock.Now()
    }
    lines, err := b.transport.Read(p)
    if err != nil {
        *b.lastState = collect.Health{
            State: collect.Unavailable, Detail: err.Error(), Measured: now,
        }
        return nil, fmt.Errorf("%w: %s: %w", ErrTransport, b.source, err)
    }
    batch := make([]collect.Record, 0, len(lines))
    for i, l := range lines {
        key, ok := l["key"]
        if !ok {
            return nil, fmt.Errorf("%w: %s rank %d, \"key\" field missing",
                ErrUnreadableLine, b.source, i)
        }
        // The origin is set HERE, by the connector, and nowhere
        // else. No caller can make another one.
        e, err := collect.New(b.source, key, l)
        if err != nil {
            return nil, fmt.Errorf("%s rank %d: %w", b.source, i, err)
        }
        batch = append(batch, e)
    }
    state := collect.Healthy
    detail := fmt.Sprintf("%d records from %s", len(batch), p)
    if len(batch) == 0 {
        // Zero records is not an outage, but it is not healthy
        // either: a source contractually daily that returns zero
        // line is a source to look at.
        state = collect.Degraded
        detail = "no record from " + p.String()
    }
    *b.lastState = collect.Health{State: state, Detail: detail, Measured: now}
    return batch, nil
}
```

**La sonde ne refait pas la collecte.** `Health()` lit le dernier état connu et
ne déclenche rien. Un test le garde en comptant les appels au transport :

> Une sonde qui refait une collecte pour savoir si la collecte marche est une
> sonde qui double la charge du partenaire. Et quand le partenaire limite le
> débit, c'est la sonde qui fait tomber la collecte.

## 4. La garantie, et le ⚫ (question 8)

L'énoncé demandait une propriété qui rende le problème **visible** — pas
détectable, visible. La voilà :

```go
// Record is a piece of data collected at a partner.
// The source field is the ⚫ of this module, and it is the answer to question 8
// of the statement. It is PRIVATE, it has no setter, and the only constructor
// requires it. Consequence: there is no path in the program that
// produces a record without origin.
//
// The state "data in the warehouse whose connector we do not know
// produced it" therefore cannot be represented. It is not a piece of data one
// watches: it is data that cannot be missing.
type Record struct {
    source Source
    key    string
    values map[string]string
}

// New builds a record. The origin and the key are
// required.
func New(source Source, key string, values map[string]string) (Record, error) {
    if strings.TrimSpace(string(source)) == "" {
        return Record{}, ErrEmptySource
    }
    if strings.TrimSpace(key) == "" {
        return Record{}, fmt.Errorf("%w: source %s", ErrEmptyKey, source)
    }
    // The map is copied: returning it as is would give the caller the
    // right to modify it after construction.
    cp := make(map[string]string, len(values))
    for k, v := range values {
        cp[k] = v
    }
    return Record{source: source, key: key, values: cp}, nil
}
```

> Le champ `source` est privé, il n'a pas de setter, et le seul constructeur
> l'exige. **Il n'existe aucun chemin dans le programme qui produise un
> enregistrement sans provenance.** Ce n'est pas une donnée qu'on surveille :
> c'est une donnée qui ne peut pas manquer.

Quatre programmes qui ne compilent pas le gardent, et chacun porte le fragment
de message attendu :

```
./main.go:12:30: cannot refer to unexported field source in struct literal of type collect.Record
./main.go:13:4:  e.source undefined (type collect.Record has no field or
                 method source, but does have method Source)
./main.go:12:21: cannot refer to unexported field debut in struct literal of type collect.Window
./main.go:13:26: cannot use nom (variable of type string) as collect.Source value
```

Le deuxième message est le plus agréable à lire : le compilateur dit non, et
il indique l'accesseur au passage.

### Ce que le ⚫ ne couvre pas, et comment on le complète

Trois trous, et il faut les nommer plutôt que de prétendre qu'une propriété
couvre tout.

**La valeur zéro du type.** `var e collect.Record` compile et n'a pas
de provenance. Le ⚫ ferme le chemin du **constructeur**, pas celui de la
déclaration.

**Une provenance fausse.** Le type exige qu'une provenance *existe* ; il ne
peut pas exiger qu'elle soit celle du connecteur qui a produit
l'enregistrement.

Les deux se ferment au même endroit, et c'est l'ordonnanceur :

```go
// Collect starts a collection on a source.
// It checks the origin of each record returned. It is the only
// guarantee the Record type cannot carry alone: it requires
// that an origin exists, it cannot require that it be the one of the
// connector that produced it.
func (o *Scheduler) Collect(execution string, source collect.Source, p collect.Window) ([]collect.Record, error) {
    c, ok := o.connectors[source]
    if !ok {
        err := fmt.Errorf("%w: %s", ErrNoConnector, source)
        o.journal.Result(execution, source, 0, err)
        return nil, err
    }
    // The choice is logged BEFORE the call: if the collection times out
    // ten minutes and then the process is killed, the line already exists.
    o.journal.Selection(execution, source, p)
    batch, err := c.Collect(p)
    if err != nil {
        err = fmt.Errorf("%w: %s: %w", ErrCollectFailed, source, err)
        o.journal.Result(execution, source, 0, err)
        return nil, err
    }
    for i, e := range batch {
        if e.Source() != source {
            err := fmt.Errorf("%w: %s returned a record from %s (rank %d)",
                ErrWrongOrigin, source, e.Source(), i)
            o.journal.Result(execution, source, 0, err)
            return nil, err
        }
    }
    o.journal.Result(execution, source, len(batch), nil)
    return batch, nil
}
```

Le contrôle refuse **le lot entier** et non la ligne fautive. C'est un choix,
et il se défend : un connecteur qui se trompe de provenance sur une ligne
n'est pas un connecteur dont on garde les autres lignes.

**L'incomplétude.** Le type garantit qu'on sait *qui* a produit un
enregistrement. Il ne garantit pas que l'enregistrement est complet. Ça, c'est
une **mesure**, pas une propriété — et c'est le quatrième tiret de la
question 8 :

| | La mesure | Le seuil | Son plancher de bruit |
|---|---|---|---|
| champs manquants par source et par champ | `catalog.ChampsManquants` | **tout champ manquant sur plus de 1 % d'un lot** | oui, et il est connu : certains champs sont contractuellement facultatifs |

Le plancher de bruit est la question que la leçon 2.2 oblige à poser, et la
réponse honnête est : **oui, il y en a un**, et on le traite comme l'incident
de la monétique — en séparant ce qui est une réponse normale de ce qui est une
anomalie. Concrètement : la fiche de catalogue doit distinguer les champs
**obligatoires** des champs **facultatifs**, et la mesure ne porte que sur les
premiers. Je ne l'ai pas implémenté, et il faut le dire : la fiche actuelle a
une seule liste de champs, donc la mesure a un plancher de bruit non nul et
le seuil de 1 % est un compromis, pas une vérité.

## 5. Le registre, et la quatrième interface (question 4)

**Oui, il lui faut une quatrième interface.** Et c'est légitime pour une
raison précise.

```go
// Connector is the FOURTH interface, and it is the sum of the three.
// Note how it is written: by embedding the other three, and not
// by copying their five methods. The day the scheduler adds a
// method to its own, this one follows without being touched, and the
// implementations that do not follow break compilation here.
type Connector interface {
    scheduler.Collector
    monitoring.Watched
    catalog.Documented
}

// Config is the configuration: the list of sources to activate.
type Config struct {
    Active []collect.Source
}
```

Noter comment elle est écrite : **par incorporation des trois autres**, pas
par recopie de leurs cinq méthodes. Le jour où l'ordonnanceur ajoute une
méthode à la sienne, celle-ci suit sans qu'on y touche.

```go
// Mount builds the three views from the configuration and the
// available connectors.
//
// It returns all THREE, and each sees only what concerns it. It is here,
// and only here, that a connector is seen as the three things at once.
func Mount(c Config, journal scheduler.Journal, available ...Connector) (
    *scheduler.Scheduler, *monitoring.Dashboard, []catalog.Entry, error) {

    bySource := map[collect.Source]Connector{}
    for _, d := range available {
        if _, already := bySource[d.Source()]; already {
            return nil, nil, nil, fmt.Errorf("%w: %s", ErrDuplicate, d.Source())
        }
        bySource[d.Source()] = d
    }
    if len(c.Active) == 0 {
        return nil, nil, nil, ErrNoActiveSource
    }

    var collectors []scheduler.Collector
    var watched []monitoring.Watched
    var documented []catalog.Documented
    for _, s := range c.Active {
        d, ok := bySource[s]
        if !ok {
            return nil, nil, nil, fmt.Errorf("%w: %s", ErrUnknownSource, s)
        }
        collectors = append(collectors, d)
        watched = append(watched, d)
        documented = append(documented, d)
    }

    o, err := scheduler.New(journal, collectors...)
    if err != nil {
        return nil, nil, nil, err
    }
    entries, err := catalog.Build(documented...)
    if err != nil {
        return nil, nil, nil, err
    }
    return o, monitoring.New(watched...), entries, nil
}
```

> Le registre est la **racine de composition** : l'endroit où les choix de
> branchement sont faits. C'est le seul endroit du programme qui a le droit de
> tout connaître. Un paquet qui connaît tout et qui n'est pas la racine de
> composition est un paquet mal placé.

Et `Mount` rend les trois vues séparément : chaque appelant ne reçoit que ce
qui le concerne, et le fait qu'un connecteur soit les trois choses à la fois
ne sort jamais de ce fichier.

## 6. Le connecteur du partenaire (question 6)

Un partenaire écrit son connecteur dans son propre dépôt. Qu'est-ce qu'il doit
importer ? La réponse est dans le fichier, et elle est courte :

```go
// PartnerConnector is written as a partner's would be,
// in its own module.
//
// It is the answer to question 6 of the statement. It imports ONLY collect:
// the shared vocabulary. It knows neither scheduler, nor monitoring, nor
// catalog, nor registry, and it does not even know the names of the interfaces it
// satisfies it.
type PartnerConnector struct {
    health collect.Health
}

func (PartnerConnector) Source() collect.Source { return "PARTENAIRE-X" }

func (c *PartnerConnector) Collect(p collect.Window) ([]collect.Record, error) {
    lines, err := partnerTransport{}.Read(p)
    if err != nil {
        return nil, err
    }
    batch := make([]collect.Record, 0, len(lines))
    for _, l := range lines {
        e, err := collect.New(c.Source(), l["key"], l)
        if err != nil {
            return nil, err
        }
        batch = append(batch, e)
    }
    c.health = collect.Health{State: collect.Healthy, Measured: time.Now()}
    return batch, nil
}

func (c *PartnerConnector) Health() collect.Health { return c.health }

func (PartnerConnector) ExposedFields() []string { return []string{"key", "amount"} }

func (PartnerConnector) ContractFrequency() string { return "daily" }

// The three conformance assertions. It is the answer to the second half of
// question 6: how to make sure the partner does not break
// compilation when a method is added to an interface. Answer: we cannot
// make sure of it for THEIR repository, but we can make sure of it for the
// ours: these three lines break HERE, at home, and before publication.
var (
    _ scheduler.Collector = (*PartnerConnector)(nil)
    _ monitoring.Watched  = (*PartnerConnector)(nil)
    _ catalog.Documented  = (*PartnerConnector)(nil)
)
```

**Il n'importe que `collect`.** Il ne connaît ni `scheduler`, ni
`monitoring`, ni `catalog`, ni `registry`, et il ignore jusqu'au nom des
interfaces qu'il satisfait. C'est le typage structurel de Go, et c'est ce qui
rend ce découpage possible.

### Et la seconde moitié de la question : comment ne pas le casser

La réponse honnête commence par ce qu'on ne peut pas faire : **on ne peut rien
garantir pour le dépôt du partenaire.** Ajouter une méthode à
`scheduler.Collector` cassera son code, et aucune astuche ne l'évitera —
c'est le prix de l'axe qu'on a choisi, et la leçon 2.2 le dit : *ajouter une
opération coûte N implémentations*.

Ce qu'on peut faire, c'est le savoir **avant lui**. Et c'est là que la mesure
a donné un résultat que je n'attendais pas.

## 7. Les assertions de conformité, et où elles doivent vivre

J'avais mis les douze assertions dans `connectors/connecteurs_test.go`. Puis
j'ai ajouté une méthode à `scheduler.Collector` et compté :

```
  erreurs de compilation du module  : 0
  erreurs dans les tests            : 4
```

**Zéro erreur au `go build`.** Un pipeline qui compile un binaire sans lancer
les tests aurait livré. Et il y a une tension réelle derrière ce chiffre :

| Où mettre l'assertion | Ce qu'on gagne | Ce qu'on perd |
|---|---|---|
| `connectors/connectors.go` | `go build` la voit | **`connectors` importe ses trois appelants** — le couplage qu'on vient de retirer |
| `connectors/connecteurs_test.go` | le découplage est préservé | `go build` ne voit rien |
| **`registry/registry.go`** | `go build` la voit | **rien** — ce paquet importe déjà les deux côtés |

```go
// The conformance assertions of the four in-house connectors.
// They are HERE, and not in connectors/, for a measured reason.
//
// Putting them in connectors/connectors.go would force this package to import
// its three callers: exactly the coupling we just removed, and
// that go list lets us check.
//
// Putting them in connectors/connectors_test.go keeps the decoupling,
// but the guarantee becomes weaker than it looks. Measured, by
// adding a method to scheduler.Collector:
//
//    assertions in _test.go    -> go build ./...  0 errors, go vet ./...  4
//    assertions in registry/   -> go build ./...  4 errors
//
// A pipeline that builds a binary without running the tests would ship the
// first case. The registry is already the only package importing all three
// callers AND the connectors: so it is the only place where the assertion
// costs no new coupling.
//
//    Conformance assertions belong to the composition root.
//    It is the only place in the program that knows both sides, and the
//    only place where "go build" can do its job.
var (
    _ Connector = connectors.SFTPFlatFile{}
    _ Connector = connectors.APIRest{}
    _ Connector = connectors.ReplicatedBase{}
    _ Connector = connectors.KafkaStream{}
)
```

Après déplacement :

```
$ go build ./...
registre/registry.go:124:17: connectors.SFTPFlatFile does not implement
    Connector (missing method Annuler)
... 4 erreurs
```

> **Les assertions de conformité appartiennent à la racine de composition.**
> C'est le seul endroit du programme qui connaît les deux côtés, et donc le
> seul où elles ne coûtent aucun couplage nouveau — et où `go build` peut
> faire son travail.

## 8. La sélection journalisée (question 7)

L'énoncé posait la question au futur : *six mois plus tard, une collecte sur
deux rend des données incomplètes et personne ne sait laquelle. Qu'est-ce que
tu as mis dans le code dès le premier jour ?*

Trois choses, et elles sont indépendantes.

**La provenance dans le type.** C'est le ⚫ de la section 4 : la phrase
« personne ne sait laquelle » est **non représentable** pour les données déjà
chargées, parce qu'aucun enregistrement ne peut exister sans provenance.

**Le journal au point de sélection, avant l'appel.** Pour les collectes qui
n'ont rien chargé, la provenance ne sert à rien — il n'y a pas
d'enregistrement. Il faut donc une ligne écrite **avant** que la collecte
commence, parce qu'une collecte qui part en timeout de dix minutes puis un
processus tué ne laissent rien derrière eux.

**La santé datée.** Un état `SAIN` mesuré il y a trois jours n'est pas une
information, c'est un souvenir. Deux mesures indépendantes, et il faut les
deux :

```go
// Package monitoring watches the sources.
//
// Its interface has TWO methods, and they are not the two of
// the scheduler. Same implementation, two different views, each the
// size of its caller's need.
package monitoring
```

Et deux décisions d'énumération qui viennent de la leçon 2.1 :

> `Inconnu` est la **valeur zéro** de `State`, et `Degradees()` la compte comme
> une dégradation. Un tableau de bord qui affiche vert par défaut est un
> tableau de bord qui mentira au démarrage. Et un lot vide n'est pas une panne,
> mais ce n'est pas sain non plus : une source contractuellement quotidienne
> qui rend zéro ligne est une source à regarder.

## 9. La campagne de modifications

Dix-sept modifications, sept paquets de test.

```
modification                                                       | tests qui tombent
-------------------------------------------------------------------+------------------
 1. un enregistrement sans provenance est accepte                  | 1
 2. la key vide est acceptee                                       | 1
 3. les valeurs ne sont plus copiees                               | 1
 4. Value() ne distingue plus l'absent du vide                    | 1
 5. une plage inversee est acceptee                                | 1
 6. l'heure n'est plus ecartee d'une plage                         | 1
 7. la valeur zero d'un State devient Healthy                          | 4
 8. la provenance n'est plus verifiee par l'ordonnanceur           | 2
 9. la selection est journalisee APRES l'appel                     | 1
10. un lot vide est declare sain                                   | 1
11. la sante par defaut devient saine                              | 1
12. une ligne sans key est ignoree au lieu de faire tomber le lot  | 1
13. ExposedFields rend la tranche interne                          | 1
14. Inconnu ne compte plus comme degrade                           | 1
15. une mesure absente n'est plus perimee                          | 1
16. une configuration vide est acceptee                            | 1
17. ChampsManquants ne filtre plus par provenance                  | 1

17/17 modifications detectees
```

Trois ont d'abord survécu, et les trois diagnostics sont **différents**. C'est
le passage le plus utile de cet exercice.

### Survivant 1 — un mutant équivalent

La modification faisait rendre à `Champs()` sa tranche interne au lieu d'une
copie. Elle a survécu, et avant de chercher le test manquant il faut regarder
le code :

`Champs()` **construit une tranche neuve à chaque appel**, depuis la carte
interne. Il n'y a aucune tranche interne à fuiter. Les deux versions calculent
la même chose, pour toutes les entrées. **Mutant équivalent**, aucun test à
écrire, et la modification a été remplacée par une autre qui a du sens — sur
le booléen de `Value()`.

### Survivant 2 — du code mort, et un test qui passait pour la mauvaise raison

`base.Health()` portait une branche *« si `lastState` est nil, rendre
`Inconnu` »*. Changer le défaut de `Inconnu` à `Healthy` dans cette branche n'a
rien cassé.

Raison : **les quatre constructeurs posent tous un pointeur non nul.** La
branche ne pouvait pas être atteinte. Et le test
`TestLaSanteEstInconnueAvantLaPremiereCollecte` passait — mais parce que la
valeur zéro de `Health` a déjà `Inconnu` pour état, pas grâce au garde.

```go
// Health returns the last known state, without triggering anything.
// The first version of this method had a branch "if lastState
// is nil, return UNKNOWN". The change campaign pointed it out as
// DEAD CODE: the four constructors all set a non-nil pointer, and
// the zero value of Health already has Unknown as state. The branch could not
// be reached, and the test that checked the initial state passed for a
// other reason than the one I thought.
//
//    A change that survives on a branch sometimes points to an
//    branch that cannot be reached. The remedy is not one more
//    test, it is to remove the branch.
func (b base) Health() collect.Health { return *b.lastState }
```

> Une modification qui survit sur une branche désigne parfois une branche qui
> **ne peut pas être atteinte**. Le remède n'est pas un test de plus, c'est de
> retirer la branche.

Et une fois la branche retirée, la modification se réécrit sur les
constructeurs — où elle tombe. Détail qui a son charme : elle n'a été
appliquée qu'à un seul des quatre constructeurs, et c'est le test qui parcourt
**les quatre** qui l'a attrapée. Le test spécifique, lui, portait sur un autre
connecteur.

### Survivant 3 — un garde qui n'était pas redondant, et qu'il fallait prouver

`Perimees` teste `health.Measured.IsZero() || now.Sub(...) > age`.
Retirer le premier terme a survécu : une mesure à l'an 1 est vieille de deux
mille ans, donc périmée de toute façon.

Il ne cesse de l'être que dans un cas : **si l'heure courante est elle aussi
la valeur zéro**. Une horloge non initialisée — et ce jour-là, sans le garde,
*toutes* les sources se déclareraient fraîches en même temps.

Le garde n'était donc pas redondant ; il manquait son test. Celui-ci passe
`time.Time{}` comme heure courante, et la modification tombe.

> Trois survivants, trois remèdes différents : **remplacer la modification**
> (mutant équivalent), **retirer la branche** (code mort), **écrire le test
> qui manquait** (garde réel mais non prouvé). Lire le code avant d'écrire un
> test est ce qui permet de choisir.

## 10. Ce que cet exercice devait faire comprendre

1. **Variantes ouvertes, opérations fermées** : c'est le cas de l'interface,
   et l'exercice 2 était l'inverse. Le même chapitre, deux réponses opposées.
2. **Trois appelants, trois interfaces**, de deux, deux et trois méthodes pour
   une implémentation qui en porte cinq.
3. **Le vocabulaire a besoin de son paquet**, sinon la dépendance revient par
   les arguments — et `go list` le dit sans discussion.
4. **La provenance dans le type** rend « personne ne sait laquelle » non
   représentable, et quatre programmes qui ne compilent pas le gardent.
5. **Un ⚫ a des trous, et il faut les nommer** : la valeur zéro, la
   provenance fausse, l'incomplétude. Les deux premiers se ferment chez
   l'appelant, le troisième est une mesure avec un plancher de bruit.
6. **La racine de composition a le droit de tout connaître**, et c'est là que
   vivent les assertions de conformité — mesure : 0 erreur au `go build`
   quand elles sont dans un `_test.go`, 4 quand elles sont au bon endroit.
7. **On ne peut rien garantir pour le dépôt du partenaire.** On peut
   seulement le savoir avant lui.
8. **Trois survivants, trois remèdes.** Un mutant équivalent, une branche
   morte, un garde non prouvé — et la première chose à faire devant un
   survivant est de lire le code, pas d'écrire un test.
