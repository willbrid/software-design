# Correction 2.5 — Exercice 4 : le SDK interne de douze équipes

> Rappel de l'énoncé : un module `banksdk` qui exporte une interface
> `Client` de 23 méthodes et des types générés depuis protobuf, utilisé par
> douze équipes dans neuf dépôts ; 9 versions mineures en un an, dont 7 ont
> cassé la compilation d'au moins une équipe.

Un exercice de conception, mais la question 1 exige de **vérifier** et non de
se souvenir. J'ai donc construit deux modules Go séparés — `banksdk`, qui
importe réellement `google.golang.org/grpc` v1.83.2, et `team`, une équipe
consommatrice branchée dessus par un `replace` — en deux versions : la v1 de
l'énoncé, et la v2 que je propose. Chaque changement du tableau de la
question 2 a été joué sur une copie, et l'équipe recompilée. Campagne de cinq
modifications sur les deux modules, 5/5 après deux passes.

## 1. Pourquoi des versions mineures cassent

Le SDK v1, réduit à deux méthodes :

```go
// Client is the SDK's public interface.
type Client interface {
    Balance(id string) (Amount, error)
    Transfer(from, to string, a Amount) error
}

type grpcClient struct{ conn *grpc.ClientConn }

// New returns a Client connected to the banking service.
func New(target string) (Client, error) {
    conn, err := grpc.NewClient(target, grpc.WithTransportCredentials(insecure.NewCredentials()))
    if err != nil {
        return nil, err
    }
    return &grpcClient{conn: conn}, nil
}

func (c *grpcClient) Balance(id string) (Amount, error)      { return Amount{}, ErrUnknownAccount }
func (c *grpcClient) Transfer(from, to string, a Amount) error { return nil }
```

Et la façon dont une équipe le teste — comme les douze, avec une doublure :

```go
package transfers

import (
    "testing"

    "example/banksdk"
)

// double of banksdk.Client: the way the twelve teams test.
type double struct{ transfers int }

func (d *double) Balance(string) (banksdk.Amount, error) { return banksdk.Amount{}, nil }
func (d *double) Transfer(string, string, banksdk.Amount) error {
    d.transfers++
    return nil
}

func TestPay(t *testing.T) {
    d := &double{}
    if err := Pay(d, "E", map[string]int64{"A": 1, "B": 2}); err != nil || d.transfers != 2 {
        t.Fatalf("%v %d", err, d.transfers)
    }
}
```

Ajouter une méthode à l'interface `Client` :

```
== method added to the Client interface     code: compiles tests: break
   transfers/transfers_test.go:20:16: cannot use d (variable of type *double) as banksdk.Client value in argument to Pay: *double does not implement banksdk.Client (missing method History)
```

**Le code de l'équipe compile ; ses tests ne compilent plus.** Ajouter une
méthode à une interface exportée ne casse pas ceux qui l'**appellent** — ils
n'appellent pas la nouvelle —, il casse ceux qui l'**implémentent**. Et dans
douze équipes qui testent, il y a au moins douze implémentations : leurs
doublures. Les 7 versions mineures cassantes de l'énoncé, ce sont très
probablement ces doublures.

Ajouter une méthode à une **structure** exportée :

```
== method added to a struct                 code: compiles tests: compile
```

Rien. Personne n'implémente une structure.

## 2. Le tableau

Les six changements, joués sur le SDK v1 :

```
== method added to the Client interface     code: compiles tests: break
   transfers/transfers_test.go:20:16: cannot use d (variable of type *double) as banksdk.Client value in argument to Pay: *double does not implement banksdk.Client (missing method History)
== method added to a struct                 code: compiles tests: compile
== field added to a struct                  code: breaks   tests: break
   payroll/payroll.go:8:30: too few values in struct literal of type banksdk.Amount
== return type changed                      code: compiles tests: break
   transfers/transfers_test.go:20:16: cannot use d (variable of type *double) as banksdk.Client value in argument to Pay: *double does not implement banksdk.Client (wrong type for method Balance)
== package added                            code: compiles tests: compile
== method removed from the interface        code: compiles tests: compile
```

| Changement dans `banksdk` | Verdict | Pour qui |
|---|---|---|
| ajouter une méthode à l'interface `Client` | **incompatible** | les implémenteurs — donc toutes les doublures de test |
| ajouter une méthode à une structure exportée | compatible | — |
| ajouter un champ à une structure exportée | **incompatible** pour qui l'écrit sans noms de champs | les appelants qui écrivent `banksdk.Amount{0, "XAF"}` — dans le code de production |
| changer le type de retour d'une méthode | **incompatible** | les appelants, **et les implémenteurs même s'ils n'appellent pas la méthode** : mesuré, l'équipe n'appelle jamais `Balance` et ses tests cassent quand même |
| ajouter un paquet | compatible | — |
| retirer une méthode que personne n'appelle | compatible **ici** | et incompatible pour toute équipe qui l'appelle — ce que ce dépôt ne peut pas savoir |

Deux lignes demandent un mot.

**Le champ ajouté** casse le code de production, pas seulement les tests :
`too few values in struct literal`. La ligne fautive est un littéral sans
noms de champs, et `go vet` la signale déjà — elle est restée dans le code de
l'équipe, volontairement, parce qu'elle est la mesure de cette ligne du
tableau. Les règles de compatibilité de Go supposent qu'on écrit les champs
par leur nom ; une équipe qui ne le fait pas a renoncé à la compatibilité.

**La dernière ligne** n'a pas de réponse locale. Pour savoir que **personne**
n'appelle une méthode quand les appelants sont dans neuf dépôts, il n'y a que
deux moyens : un **index de code** qui couvre les neuf dépôts, ou **compiler
les neuf dépôts** contre la version candidate avant de la publier — la
question 5 y revient. Le sondage de la leçon ne voit que les répertoires
qu'on lui donne.

## 3. La nouvelle API

> **`New` rend une structure. Les interfaces sont déclarées par les
> équipes, chez elles, avec les seules méthodes qu'elles appellent.**

```go
// Client talks to the banking service. It is a struct: adding a method
// breaks nobody.
type Client struct{ conn *grpc.ClientConn }

// New returns a Client connected to the banking service.
func New(target string) (*Client, error) {
    conn, err := grpc.NewClient(target, grpc.WithTransportCredentials(insecure.NewCredentials()))
    if err != nil {
        return nil, err
    }
    return &Client{conn: conn}, nil
}

func (c *Client) Balance(id string) (money.Amount, error) {
    return money.Amount{}, money.ErrUnknownAccount
}

func (c *Client) Transfer(from, to string, a money.Amount) error { return nil }
```

L'équipe déclare son port :

```go
// Transfers is what paying the salaries needs. *banksdk.Client satisfies it
// without knowing.
type Transfers interface {
    Transfer(from, to string, a money.Amount) error
}

// Pay transfers each salary from the employer's account.
func Pay(c Transfers, employer string, salaries map[string]int64) error {
    for account, s := range salaries {
        if err := c.Transfer(employer, account, money.Amount{Cents: s, Currency: "XAF"}); err != nil {
            return err
        }
    }
    return nil
}
```

Et les trois changements qui cassaient ses tests, rejoués sur la v2 :

```
== method added to the Client               code: compiles tests: compile
== return type changed                      code: compiles tests: compile
== method removed from the Client           code: compiles tests: compile
```

Plus rien ne casse. Le jour où une méthode que l'équipe **appelle** change,
c'est sa racine de composition qui casse — une ligne, à l'endroit où le SDK
est branché sur son port :

```go
// Package wiring plugs the SDK into the team's business.
package wiring

import (
    "example/banksdk"
    "example/team/transfers"
)

// Wire checks, at compile time, that the SDK's Client satisfies the team's
// port.
func Wire(c *banksdk.Client) transfers.Transfers { return c }
```

**Ce que la migration coûte à chaque équipe**, ma prédiction d'abord :
« quelques lignes par paquet qui importe le SDK, plus une racine ». Mesuré
sur l'équipe type, avec `diff` :

| Fichier | lignes retirées | lignes ajoutées |
|---|---|---|
| `payroll/payroll.go` — chemin d'import et nom du type | 3 | 3 |
| `transfers/transfers.go` — le port déclaré chez elle | 3 | 9 |
| `transfers/transfers_test.go` — la doublure perd `Balance` | 4 | 3 |
| `wiring/wiring.go` — nouveau | — | 11 |
| `archi/archi_test.go` — nouveau | — | 12 |

**Dix lignes retirées, quinze ajoutées** dans le code existant, et deux
petits fichiers. Une fois, contre sept compilations cassées par an.

## 4. Les types, et gRPC

Le paquet `payroll` de l'équipe additionne des montants. Rien d'autre :

```go
// Package payroll is a team's business package: it adds up amounts.
package payroll

import "example/banksdk"

// Total adds up amounts of a single currency.
func Total(as []banksdk.Amount) banksdk.Amount {
    t := banksdk.Amount{0, "XAF"}
    for _, a := range as {
        t.Cents += a.Cents
    }
    return t
}
```

Mesuré : **323 dépendances, dont `google.golang.org/grpc`**. Pour additionner
deux entiers, parce que le type `Amount` vit dans le même paquet que le
client gRPC.

La v2 met le vocabulaire — types et sentinelles — dans un paquet à part, qui
n'importe rien d'autre que la bibliothèque standard :

```go
// Package money is the SDK's vocabulary: the types and errors the teams name
// in their business code. It imports nothing but the standard library, and
// that is its only rule.
package money

import "errors"

var ErrUnknownAccount = errors.New("banksdk: unknown account")

// Amount is an amount in cents, in a currency.
type Amount struct {
    Cents    int64
    Currency string
}
```

Après la migration :

```
payroll deps: 35, grpc: 0
transfers deps: 35, grpc: 0
wiring deps: 325, grpc: 1
```

`payroll` passe de **323 à 35** dépendances. gRPC n'est plus tiré que par la
racine de composition — le seul paquet de l'équipe qui a besoin du vrai
client. Une nuance honnête : le **module** de l'équipe exige toujours gRPC
dans son `go.mod`, puisqu'il dépend du module `banksdk` ; ce sont les
**paquets** métier qui en sont libérés, et c'est ce qui compte pour la
compilation, les tests et la lecture.

**La contrainte de stabilité** : `money` doit changer **moins souvent que
chacun de ses consommateurs** — c'est la règle de la leçon. Elle se mesure
dans le dépôt du SDK, par version publiée : le nombre de changements
incompatibles de l'API de `money`, que l'outil `apidiff` calcule entre deux
étiquettes. L'objectif chiffré est **zéro** changement incompatible de
`money` par an ; un seul justifie une version majeure. Et la stabilité
**à travers les neuf dépôts** n'a pas besoin des neuf dépôts : elle est une
propriété de `money`, mesurée là où `money` vit.

## 5. Le test d'architecture qui traverse les dépôts

Il tourne **dans chaque dépôt d'équipe**, sur les paquets de l'équipe — c'est
là que sont les flèches à vérifier. Mais son **code appartient au SDK**, qui
le publie :

```go
// Forbid fails if one of the packages pulls one of the forbidden ones,
// directly or not. Package paths are relative to the test's directory.
func Forbid(t testing.TB, packages []string, forbidden ...string) {
    t.Helper()
    for _, p := range packages {
        out, err := exec.Command("go", "list", "-deps", p).Output()
        if err != nil {
            t.Fatalf("go list %s: %v", p, err)
        }
        deps := map[string]bool{}
        for _, d := range strings.Fields(string(out)) {
            deps[d] = true
        }
        for _, f := range forbidden {
            if deps[f] {
                t.Errorf("%s pulls %s", p, f)
            }
        }
    }
}
```

L'équipe l'appelle en trois lignes :

```go
// Package archi holds the SDK's rule in the team's repository.
package archi

import (
    "testing"

    "example/banksdk/archtest"
)

func TestTheBusinessDoesNotPullGRPC(t *testing.T) {
    archtest.Forbid(t, []string{"../payroll", "../transfers"}, "google.golang.org/grpc")
}
```

Ce qui le fait échouer : un paquet métier de l'équipe qui tire gRPC, ou
**le SDK lui-même** qui ferait importer gRPC par `money` — la campagne
joue les deux, et les deux sont tuées. Le second cas est le plus important :
c'est le test d'une équipe qui protège toutes les autres contre une faute du
SDK.

Et le SDK, lui, doit faire une chose de plus avant chaque version : **compiler
les neuf dépôts contre la version candidate**. C'est la seule façon de savoir
qui casse — et c'est la réponse à la dernière ligne du tableau.

## 6. La règle de revue

> **Pour toute méthode publique ajoutée à `banksdk` : montre-moi pourquoi ce
> n'est pas une fonction qui prend un `*Client`, et dis-moi quel type elle
> nomme dans sa signature — s'il n'est pas dans `money`, il tire gRPC chez
> tous ses appelants.**

## 7. « Sinon les équipes ne peuvent plus nous mocker »

C'est faux en Go, en une phrase : **une équipe déclare l'interface dont elle
a besoin, et `*banksdk.Client` la satisfait sans le savoir** — c'est
`transfers.Transfers` plus haut, et sa doublure d'une méthode :

```go
// Transfers is what paying the salaries needs. *banksdk.Client satisfies it
// without knowing.
type Transfers interface {
    Transfer(from, to string, a money.Amount) error
}
```

Ce que l'équipe du SDK perd vraiment en retirant `type Client interface` :
la possibilité de **changer d'implémentation derrière `New`** — rendre un
client en mémoire en développement, un client gRPC en production, sans que
personne ne le sache. C'est une vraie perte. Mais elle se rachète autrement
— une fonction `NewMemory` qui rend une autre structure satisfaisant les
mêmes ports d'équipe —, et l'échange est bon : le SDK perd une souplesse qu'il
utilise rarement, les douze équipes perdent sept ruptures par an.

## 8. La campagne

### Première passe

```
archtest : ne refuse plus rien               SURVIT
monnaie tire grpc                            tuee
paie importe le client du SDK                tuee
virements : une erreur de virement ignoree   SURVIT
paie : total faux                            SURVIT
2/5 tuees
```

Trois survivants, trois tests manquants. `archtest` n'avait jamais été vu en
train de tirer — dans le dépôt de l'équipe, il ne passe que sur du code
conforme. Il a maintenant son test négatif, **dans le SDK**, sur le paquet du
client, qui tire réellement gRPC :

```go
// recorder is a testing.TB that keeps the failures instead of failing.
type recorder struct {
    testing.TB
    failures []string
}

func (r *recorder) Helper()                   {}
func (r *recorder) Errorf(f string, a ...any) { r.failures = append(r.failures, f) }
func (r *recorder) Fatalf(f string, a ...any) { r.failures = append(r.failures, "FATAL "+f) }

// TestForbidSeesARealDependency: the SDK's client pulls grpc. If Forbid does
// not say so, no team is protected.
func TestForbidSeesARealDependency(t *testing.T) {
    r := &recorder{TB: t}
    Forbid(r, []string{".."}, "google.golang.org/grpc")
    if len(r.failures) != 1 || strings.HasPrefix(r.failures[0], "FATAL") {
        t.Fatalf("failures %v", r.failures)
    }
    r = &recorder{TB: t}
    Forbid(r, []string{"../money"}, "google.golang.org/grpc")
    if len(r.failures) != 0 {
        t.Fatalf("money: %v", r.failures)
    }
}
```

Les deux autres — une erreur de virement ignorée, un total faux — étaient
simplement des comportements de l'équipe sans test ; ils en ont un.

### Deuxième passe

```
5/5 tuees
```

## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | Ajouter une méthode à une interface exportée casse ceux qui l'**implémentent**, pas ceux qui l'appellent. Dans une organisation qui teste, les implémenteurs sont les doublures de toutes les équipes. |
| ⚫ | Changer le type de retour d'une méthode casse aussi les doublures des équipes qui ne l'appellent jamais. Mesuré. |
| ⚫ | Ajouter un champ casse les littéraux sans noms de champs, dans le code de production. `go vet` les signale avant. |
| ⚫ | Une bibliothèque rend des structures ; ses consommateurs déclarent leurs interfaces. Mesuré : trois changements qui cassaient, zéro. |
| ⚫ | Le vocabulaire d'un SDK — types et sentinelles — vit dans un paquet qui n'importe rien. Mesuré : 323 dépendances avec gRPC pour additionner deux montants, 35 sans. |
| ⚫ | Un test d'architecture peut appartenir au SDK et tourner chez les équipes : il protège aussi les équipes contre le SDK. |
| ⚫ | « Personne n'appelle cette méthode » ne se sait pas depuis un seul dépôt. Il faut un index de code, ou compiler les dépôts en aval avant de publier. |
| ⚫ | Une interface exportée « pour qu'on puisse nous mocker » n'est pas nécessaire en Go. Ce qu'on perd en la retirant se rachète ; ce qu'elle coûte, non. |
