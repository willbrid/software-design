# Correction 2.5 — Exercice 4 : le SDK interne de douze équipes

> Rappel de l'énoncé : un module `banquesdk` qui exporte une interface
> `Client` de 23 méthodes et des types générés depuis protobuf, utilisé par
> douze équipes dans neuf dépôts ; 9 versions mineures en un an, dont 7 ont
> cassé la compilation d'au moins une équipe.

Un exercice de conception, mais la question 1 exige de **vérifier** et non de
se souvenir. J'ai donc construit deux modules Go séparés — `banquesdk`, qui
importe réellement `google.golang.org/grpc` v1.83.2, et `equipe`, une équipe
consommatrice branchée dessus par un `replace` — en deux versions : la v1 de
l'énoncé, et la v2 que je propose. Chaque changement du tableau de la
question 2 a été joué sur une copie, et l'équipe recompilée. Campagne de cinq
modifications sur les deux modules, 5/5 après deux passes.

## 1. Pourquoi des versions mineures cassent

Le SDK v1, réduit à deux méthodes :

```go
// Client est l'interface publique du SDK.
type Client interface {
    Solde(id string) (Montant, error)
    Virer(de, vers string, m Montant) error
}

type grpcClient struct{ conn *grpc.ClientConn }

// Nouveau rend un Client branche sur le service bancaire.
func Nouveau(cible string) (Client, error) {
    conn, err := grpc.NewClient(cible, grpc.WithTransportCredentials(insecure.NewCredentials()))
    if err != nil {
        return nil, err
    }
    return &grpcClient{conn: conn}, nil
}

func (c *grpcClient) Solde(id string) (Montant, error)      { return Montant{}, ErrCompteInconnu }
func (c *grpcClient) Virer(de, vers string, m Montant) error { return nil }
```

Et la façon dont une équipe le teste — comme les douze, avec une doublure :

```go
package virements

import (
    "testing"

    "exemple/banquesdk"
)

// doublure de banquesdk.Client : la facon dont les douze equipes testent.
type doublure struct{ virements int }

func (d *doublure) Solde(string) (banquesdk.Montant, error) { return banquesdk.Montant{}, nil }
func (d *doublure) Virer(string, string, banquesdk.Montant) error {
    d.virements++
    return nil
}

func TestVerser(t *testing.T) {
    d := &doublure{}
    if err := Verser(d, "E", map[string]int64{"A": 1, "B": 2}); err != nil || d.virements != 2 {
        t.Fatalf("%v %d", err, d.virements)
    }
}
```

Ajouter une méthode à l'interface `Client` :

```
== methode ajoutee a l'interface Client       code : compile  tests : casse
   virements/virements_test.go:20:19: cannot use d (variable of type *doublure) as banquesdk.Client value in argument to Verser: *doublure does not implement banquesdk.Client (missing method Historique)
```

**Le code de l'équipe compile ; ses tests ne compilent plus.** Ajouter une
méthode à une interface exportée ne casse pas ceux qui l'**appellent** — ils
n'appellent pas la nouvelle —, il casse ceux qui l'**implémentent**. Et dans
douze équipes qui testent, il y a au moins douze implémentations : leurs
doublures. Les 7 versions mineures cassantes de l'énoncé, ce sont très
probablement ces doublures.

Ajouter une méthode à une **structure** exportée :

```
== methode ajoutee a une structure            code : compile  tests : compilent
```

Rien. Personne n'implémente une structure.

## 2. Le tableau

Les six changements, joués sur le SDK v1 :

```
== methode ajoutee a l'interface Client       code : compile  tests : casse
   virements/virements_test.go:20:19: cannot use d (variable of type *doublure) as banquesdk.Client value in argument to Verser: *doublure does not implement banquesdk.Client (missing method Historique)
== methode ajoutee a une structure            code : compile  tests : compilent
== champ ajoute a une structure               code : casse    tests : casse
   paie/paie.go:8:33: too few values in struct literal of type banquesdk.Montant
== type de retour change                      code : compile  tests : casse
   virements/virements_test.go:20:19: cannot use d (variable of type *doublure) as banquesdk.Client value in argument to Verser: *doublure does not implement banquesdk.Client (wrong type for method Solde)
== paquet ajoute                              code : compile  tests : compilent
== methode retiree de l'interface             code : compile  tests : compilent
```

| Changement dans `banquesdk` | Verdict | Pour qui |
|---|---|---|
| ajouter une méthode à l'interface `Client` | **incompatible** | les implémenteurs — donc toutes les doublures de test |
| ajouter une méthode à une structure exportée | compatible | — |
| ajouter un champ à une structure exportée | **incompatible** pour qui l'écrit sans noms de champs | les appelants qui écrivent `banquesdk.Montant{0, "XAF"}` — dans le code de production |
| changer le type de retour d'une méthode | **incompatible** | les appelants, **et les implémenteurs même s'ils n'appellent pas la méthode** : mesuré, l'équipe n'appelle jamais `Solde` et ses tests cassent quand même |
| ajouter un paquet | compatible | — |
| retirer une méthode que personne n'appelle | compatible **ici** | et incompatible pour toute équipe qui l'appelle — ce que ce dépôt ne peut pas savoir |

Deux lignes demandent un mot.

**Le champ ajouté** casse le code de production, pas seulement les tests :
`too few values in struct literal`. La ligne fautive est un littéral sans
noms de champs, et `go vet` la signale déjà — elle est restée dans le code de
l'équipe, volontairement, parce qu'elle est la mesure de cette ligne du
tableau. Les règles de compatibilité de Go supposent qu'on écrit les champs
par leur nom ; une équipe qui ne le fait pas a renoncé à la compatibilité.

**La dernière ligne** n'a pas de réponse locale. Pour savoir que **personne**
n'appelle une méthode quand les appelants sont dans neuf dépôts, il n'y a que
deux moyens : un **index de code** qui couvre les neuf dépôts, ou **compiler
les neuf dépôts** contre la version candidate avant de la publier — la
question 5 y revient. Le sondage de la leçon ne voit que les répertoires
qu'on lui donne.

## 3. La nouvelle API

> **`Nouveau` rend une structure. Les interfaces sont déclarées par les
> équipes, chez elles, avec les seules méthodes qu'elles appellent.**

```go
// Client parle au service bancaire. C'est une structure : ajouter une methode
// ne casse personne.
type Client struct{ conn *grpc.ClientConn }

// Nouveau rend un Client branche sur le service bancaire.
func Nouveau(cible string) (*Client, error) {
    conn, err := grpc.NewClient(cible, grpc.WithTransportCredentials(insecure.NewCredentials()))
    if err != nil {
        return nil, err
    }
    return &Client{conn: conn}, nil
}

func (c *Client) Solde(id string) (monnaie.Montant, error) {
    return monnaie.Montant{}, monnaie.ErrCompteInconnu
}

func (c *Client) Virer(de, vers string, m monnaie.Montant) error { return nil }
```

L'équipe déclare son port :

```go
// Virements est ce dont le versement des salaires a besoin. *banquesdk.Client
// le satisfait sans le savoir.
type Virements interface {
    Virer(de, vers string, m monnaie.Montant) error
}

// Verser vire chaque salaire depuis le compte de l'employeur.
func Verser(c Virements, employeur string, salaires map[string]int64) error {
    for compte, s := range salaires {
        if err := c.Virer(employeur, compte, monnaie.Montant{Centimes: s, Devise: "XAF"}); err != nil {
            return err
        }
    }
    return nil
}
```

Et les trois changements qui cassaient ses tests, rejoués sur la v2 :

```
== methode ajoutee au Client                  code : compile  tests : compilent
== type de retour change                      code : compile  tests : compilent
== methode retiree du Client                  code : compile  tests : compilent
```

Plus rien ne casse. Le jour où une méthode que l'équipe **appelle** change,
c'est sa racine de composition qui casse — une ligne, à l'endroit où le SDK
est branché sur son port :

```go
// Package montage branche le SDK sur le metier de l'equipe.
package montage

import (
    "exemple/banquesdk"
    "exemple/equipe/virements"
)

// Cabler verifie, a la compilation, que le Client du SDK satisfait le port
// de l'equipe.
func Cabler(c *banquesdk.Client) virements.Virements { return c }
```

**Ce que la migration coûte à chaque équipe**, ma prédiction d'abord :
« quelques lignes par paquet qui importe le SDK, plus une racine ». Mesuré
sur l'équipe type, avec `diff` :

| Fichier | lignes retirées | lignes ajoutées |
|---|---|---|
| `paie/paie.go` — chemin d'import et nom du type | 3 | 3 |
| `virements/virements.go` — le port déclaré chez elle | 3 | 9 |
| `virements/virements_test.go` — la doublure perd `Solde` | 4 | 3 |
| `montage/montage.go` — nouveau | — | 11 |
| `archi/archi_test.go` — nouveau | — | 12 |

**Dix lignes retirées, quinze ajoutées** dans le code existant, et deux
petits fichiers. Une fois, contre sept compilations cassées par an.

## 4. Les types, et gRPC

Le paquet `paie` de l'équipe additionne des montants. Rien d'autre :

```go
// Package paie est un paquet metier d'une equipe : il additionne des montants.
package paie

import "exemple/banquesdk"

// Total additionne des montants d'une meme devise.
func Total(ms []banquesdk.Montant) banquesdk.Montant {
    t := banquesdk.Montant{0, "XAF"}
    for _, m := range ms {
        t.Centimes += m.Centimes
    }
    return t
}
```

Mesuré : **323 dépendances, dont `google.golang.org/grpc`**. Pour additionner
deux entiers, parce que le type `Montant` vit dans le même paquet que le
client gRPC.

La v2 met le vocabulaire — types et sentinelles — dans un paquet à part, qui
n'importe rien d'autre que la bibliothèque standard :

```go
// Package monnaie est le vocabulaire du SDK : les types et les erreurs que les
// equipes nomment dans leur code metier. Il n'importe rien d'autre que la
// bibliotheque standard, et c'est sa seule regle.
package monnaie

import "errors"

var ErrCompteInconnu = errors.New("banquesdk : compte inconnu")

// Montant est un montant en centimes, dans une devise.
type Montant struct {
    Centimes int64
    Devise   string
}
```

Après la migration :

```
paie deps: 35, grpc: 0
virements deps: 35, grpc: 0
montage deps: 325, grpc: 1
```

`paie` passe de **323 à 35** dépendances. gRPC n'est plus tiré que par la
racine de composition — le seul paquet de l'équipe qui a besoin du vrai
client. Une nuance honnête : le **module** de l'équipe exige toujours gRPC
dans son `go.mod`, puisqu'il dépend du module `banquesdk` ; ce sont les
**paquets** métier qui en sont libérés, et c'est ce qui compte pour la
compilation, les tests et la lecture.

**La contrainte de stabilité** : `monnaie` doit changer **moins souvent que
chacun de ses consommateurs** — c'est la règle de la leçon. Elle se mesure
dans le dépôt du SDK, par version publiée : le nombre de changements
incompatibles de l'API de `monnaie`, que l'outil `apidiff` calcule entre deux
étiquettes. L'objectif chiffré est **zéro** changement incompatible de
`monnaie` par an ; un seul justifie une version majeure. Et la stabilité
**à travers les neuf dépôts** n'a pas besoin des neuf dépôts : elle est une
propriété de `monnaie`, mesurée là où `monnaie` vit.

## 5. Le test d'architecture qui traverse les dépôts

Il tourne **dans chaque dépôt d'équipe**, sur les paquets de l'équipe — c'est
là que sont les flèches à vérifier. Mais son **code appartient au SDK**, qui
le publie :

```go
// Interdire echoue si l'un des paquets tire l'un des interdits, directement
// ou non. Les chemins de paquets sont relatifs au repertoire du test.
func Interdire(t testing.TB, paquets []string, interdits ...string) {
    t.Helper()
    for _, p := range paquets {
        sortie, err := exec.Command("go", "list", "-deps", p).Output()
        if err != nil {
            t.Fatalf("go list %s : %v", p, err)
        }
        deps := map[string]bool{}
        for _, d := range strings.Fields(string(sortie)) {
            deps[d] = true
        }
        for _, i := range interdits {
            if deps[i] {
                t.Errorf("%s tire %s", p, i)
            }
        }
    }
}
```

L'équipe l'appelle en trois lignes :

```go
// Package archi tient la regle du SDK dans le depot de l'equipe.
package archi

import (
    "testing"

    "exemple/banquesdk/archtest"
)

func TestLeMetierNeTirePasGRPC(t *testing.T) {
    archtest.Interdire(t, []string{"../paie", "../virements"}, "google.golang.org/grpc")
}
```

Ce qui le fait échouer : un paquet métier de l'équipe qui tire gRPC, ou
**le SDK lui-même** qui ferait importer gRPC par `monnaie` — la campagne
joue les deux, et les deux sont tuées. Le second cas est le plus important :
c'est le test d'une équipe qui protège toutes les autres contre une faute du
SDK.

Et le SDK, lui, doit faire une chose de plus avant chaque version : **compiler
les neuf dépôts contre la version candidate**. C'est la seule façon de savoir
qui casse — et c'est la réponse à la dernière ligne du tableau.

## 6. La règle de revue

> **Pour toute méthode publique ajoutée à `banquesdk` : montre-moi pourquoi ce
> n'est pas une fonction qui prend un `*Client`, et dis-moi quel type elle
> nomme dans sa signature — s'il n'est pas dans `monnaie`, il tire gRPC chez
> tous ses appelants.**

## 7. « Sinon les équipes ne peuvent plus nous mocker »

C'est faux en Go, en une phrase : **une équipe déclare l'interface dont elle
a besoin, et `*banquesdk.Client` la satisfait sans le savoir** — c'est
`virements.Virements` plus haut, et sa doublure d'une méthode :

```go
// Virements est ce dont le versement des salaires a besoin. *banquesdk.Client
// le satisfait sans le savoir.
type Virements interface {
    Virer(de, vers string, m monnaie.Montant) error
}
```

Ce que l'équipe du SDK perd vraiment en retirant `type Client interface` :
la possibilité de **changer d'implémentation derrière `Nouveau`** — rendre un
client en mémoire en développement, un client gRPC en production, sans que
personne ne le sache. C'est une vraie perte. Mais elle se rachète autrement
— une fonction `NouveauMemoire` qui rend une autre structure satisfaisant les
mêmes ports d'équipe —, et l'échange est bon : le SDK perd une souplesse qu'il
utilise rarement, les douze équipes perdent sept ruptures par an.

## 8. La campagne

### Première passe

```
archtest : ne refuse plus rien               SURVIT
monnaie tire grpc                            tuee
paie importe le client du SDK                tuee
virements : une erreur de virement ignoree   SURVIT
paie : total faux                            SURVIT
2/5 tuees
```

Trois survivants, trois tests manquants. `archtest` n'avait jamais été vu en
train de tirer — dans le dépôt de l'équipe, il ne passe que sur du code
conforme. Il a maintenant son test négatif, **dans le SDK**, sur le paquet du
client, qui tire réellement gRPC :

```go
// enregistreur est un testing.TB qui garde les echecs au lieu d'echouer.
type enregistreur struct {
    testing.TB
    echecs []string
}

func (e *enregistreur) Helper()                   {}
func (e *enregistreur) Errorf(f string, a ...any) { e.echecs = append(e.echecs, f) }
func (e *enregistreur) Fatalf(f string, a ...any) { e.echecs = append(e.echecs, "FATAL "+f) }

// TestInterdireVoitUneVraieDependance : le client du SDK tire grpc. Si
// Interdire ne le dit pas, aucune equipe n'est protegee.
func TestInterdireVoitUneVraieDependance(t *testing.T) {
    e := &enregistreur{TB: t}
    Interdire(e, []string{".."}, "google.golang.org/grpc")
    if len(e.echecs) != 1 || strings.HasPrefix(e.echecs[0], "FATAL") {
        t.Fatalf("echecs %v", e.echecs)
    }
    e = &enregistreur{TB: t}
    Interdire(e, []string{"../monnaie"}, "google.golang.org/grpc")
    if len(e.echecs) != 0 {
        t.Fatalf("monnaie : %v", e.echecs)
    }
}
```

Les deux autres — une erreur de virement ignorée, un total faux — étaient
simplement des comportements de l'équipe sans test ; ils en ont un.

### Deuxième passe

```
5/5 tuees
```

## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | Ajouter une méthode à une interface exportée casse ceux qui l'**implémentent**, pas ceux qui l'appellent. Dans une organisation qui teste, les implémenteurs sont les doublures de toutes les équipes. |
| ⚫ | Changer le type de retour d'une méthode casse aussi les doublures des équipes qui ne l'appellent jamais. Mesuré. |
| ⚫ | Ajouter un champ casse les littéraux sans noms de champs, dans le code de production. `go vet` les signale avant. |
| ⚫ | Une bibliothèque rend des structures ; ses consommateurs déclarent leurs interfaces. Mesuré : trois changements qui cassaient, zéro. |
| ⚫ | Le vocabulaire d'un SDK — types et sentinelles — vit dans un paquet qui n'importe rien. Mesuré : 323 dépendances avec gRPC pour additionner deux montants, 35 sans. |
| ⚫ | Un test d'architecture peut appartenir au SDK et tourner chez les équipes : il protège aussi les équipes contre le SDK. |
| ⚫ | « Personne n'appelle cette méthode » ne se sait pas depuis un seul dépôt. Il faut un index de code, ou compiler les dépôts en aval avant de publier. |
| ⚫ | Une interface exportée « pour qu'on puisse nous mocker » n'est pas nécessaire en Go. Ce qu'on perd en la retirant se rachète ; ce qu'elle coûte, non. |
