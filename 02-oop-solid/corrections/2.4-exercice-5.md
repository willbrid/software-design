# Correction 2.4 — Exercice 5 : le cache de taux qui n'expirait jamais

> Rappel de l'énoncé : un cache sans expiration mis en production un vendredi
> à 16 h 05 derrière l'interface `Rates`, une batterie de six clauses verte,
> 212 tests verts, un tableau de bord plat, et 1 142 paiements du week-end
> convertis au taux du vendredi.

Quatre paquets — `rates` (le port, le fil simulé, la batterie), `direct`,
`cache` (le cache du 12/09 et deux autres), `indicator` —, verts sous
`go vet ./...` et `go test -race -count=1 ./...`. Campagne de douze
modifications, 11 tuées et un survivant diagnostiqué « rien ».

## 1. Le mécanisme, en trois phrases

> L'implémentation mise en production retient la première réponse du fil
> pour chaque paire de devises, et ne la redemande jamais. Le vendredi à
> 16 h 04, elle a lu la cote EUR/XAF, et c'est cette cote qu'elle a rendue à
> chaque paiement jusqu'au lundi. Rien n'a échoué : chaque appel a reçu un
> taux valide, positif, rendu vite — simplement plus le bon.

## 2. Pourquoi aucune des six clauses ne pouvait voir

Les six clauses de la batterie, écrites comme elles l'étaient :

```go
// SixClauses are those of the battery that has existed for ten months,
// written as they were. None changes the world between two calls.
func SixClauses() []Clause {
    return []Clause{
        {"a known rate is returned", func(h Harness) string {
            if v, err := h.New(world()).Rate("EUR", "XAF"); err != nil || v != oldQuote {
                return fmt.Sprintf("EUR/XAF = %v, %v", v, err)
            }
            return ""
        }},
        {"an unknown currency returns ErrUnknownCurrency", func(h Harness) string {
            if _, err := h.New(world()).Rate("EUR", "ZZZ"); !errors.Is(err, ErrUnknownCurrency) {
                return fmt.Sprintf("EUR/ZZZ: %v", err)
            }
            return ""
        }},
        {"a rate is strictly positive", func(h Harness) string {
            if v, _ := h.New(world()).Rate("EUR", "XAF"); v <= 0 {
                return fmt.Sprintf("EUR/XAF = %v", v)
            }
            return ""
        }},
        {"identical source and target return 1", func(h Harness) string {
            if v, err := h.New(world()).Rate("XAF", "XAF"); err != nil || v != 1 {
                return fmt.Sprintf("XAF/XAF = %v, %v", v, err)
            }
            return ""
        }},
        {"concurrent calls do not panic", func(h Harness) string {
            r := h.New(world())
            var g sync.WaitGroup
            for range 8 {
                g.Add(1)
                go func() {
                    defer g.Done()
                    for range 200 {
                        _, _ = r.Rate("EUR", "XAF")
                    }
                }()
            }
            g.Wait()
            return ""
        }},
        {"a feed outage is propagated as is", func(h Harness) string {
            w := world()
            r := h.New(w)
            w.Down(true)
            if _, err := r.Rate("EUR", "XAF"); !errors.Is(err, ErrFeed) {
                return fmt.Sprintf("feed down: %v", err)
            }
            return ""
        }},
    }
}
```

Lues une à une, elles ont un point commun : **aucune ne change le monde entre
deux appels.** Chacune fabrique un fil, pose une cote, et regarde ce que `Rate`
en fait. La clause 6 fait tomber le fil — mais **avant** le premier appel,
donc sur un cache vide. Dans un monde qui ne change jamais, une
implémentation qui retient tout pour toujours est **indiscernable** de sa
source : elle rend exactement ce que le fil rendrait.

Le relevé le confirme — les quatre implémentations que j'ai écrites passent
les six clauses, le cache du 12/09 compris :

```
Direct          six clauses 6/6
Cache (12/09)   six clauses 6/6
Expiring 30 s   six clauses 6/6
Sliding 30 s    six clauses 6/6
```

Ce que ça apprend sur les batteries en général :

> **Une batterie ne voit que ce que son `Harness` peut provoquer.** Si le `Harness` ne
> sait pas faire changer le monde, aucune clause ne peut parler du temps — et
> un décorateur est exactement une implémentation dont les fautes vivent dans
> le temps (correction 2.4/3, question 8). Le `Harness` définit l'univers
> observable de la batterie ; tout ce qui est hors de cet univers passe.

Le `Harness` de cette batterie ne fabriquait qu'une implémentation. Celui qui
peut voir le 12/09 donne à l'implémentation un **monde** — le fil et
l'horloge — que la batterie fait bouger :

```go
// World is the simulated quote feed AND the clock. The battery gives it to
// each implementation it makes: it is through it that the battery changes
// the world between two calls — publish a quote, move time forward, bring
// the feed down.
type World struct {
    mu     sync.Mutex
    now    time.Time
    quotes map[string]float64
    down   bool
}

func NewWorld(start time.Time) *World {
    return &World{now: start, quotes: map[string]float64{}}
}

// Now is the clock the implementations must use.
func (w *World) Now() time.Time {
    w.mu.Lock()
    defer w.mu.Unlock()
    return w.now
}

func (w *World) Advance(d time.Duration) {
    w.mu.Lock()
    defer w.mu.Unlock()
    w.now = w.now.Add(d)
}

// Publish publishes a quote on the feed.
func (w *World) Publish(source, target string, v float64) {
    w.mu.Lock()
    defer w.mu.Unlock()
    w.quotes[source+"/"+target] = v
}

func (w *World) Down(down bool) {
    w.mu.Lock()
    defer w.mu.Unlock()
    w.down = down
}
```

Et c'est une contrainte de construction : une implémentation qui lit
`time.Now()` au lieu de l'horloge qu'on lui donne **ne peut pas être passée à
la batterie**. L'horloge fait partie de ce qu'on exige d'une implémentation,
au même titre que la signature de `Rate`.

## 3. La clause manquante

En une phrase :

> **Une cote publiée sur le fil est rendue par `Rate` à tout appel fait
> `MaxAge` ou plus après sa publication — et une fois rendue,
> l'ancienne ne l'est plus jamais.**

Elle ne sait rien du cache : elle parle d'une cote publiée et de ce que `Rate`
rend. `Direct` la tient trivialement ; un cache la tient si son TTL est sous
la borne. Mais l'énoncé prévient que la formulation naïve ne marche pas, et il
y en a **trois**. Je les ai écrites toutes les trois, avec la bonne, et passé
les quatre implémentations dans chacune :

```go
// The three naive wordings of clause 7, for the measurement.

func naiveA(h rates.Harness) string { // "two calls return the same value"
    r := h.New(rates.NewQuotedWorld())
    a, _ := r.Rate("EUR", "XAF")
    b, _ := r.Rate("EUR", "XAF")
    if a != b {
        return "two calls, two values"
    }
    return ""
}

func naiveB(h rates.Harness) string { // "after a publication, Rate returns the new quote"
    w := rates.NewQuotedWorld()
    r := h.New(w)
    _, _ = r.Rate("EUR", "XAF")
    w.Publish("EUR", "XAF", 659.40)
    if v, _ := r.Rate("EUR", "XAF"); v != 659.40 {
        return fmt.Sprintf("right after the publication: %v", v)
    }
    return ""
}

func naiveC(h rates.Harness) string { // "... at most MaxAge after", read only once
    w := rates.NewQuotedWorld()
    r := h.New(w)
    _, _ = r.Rate("EUR", "XAF")
    w.Publish("EUR", "XAF", 659.40)
    w.Advance(rates.MaxAge)
    if v, _ := r.Rate("EUR", "XAF"); v != 659.40 {
        return fmt.Sprintf("MaxAge after the publication: %v", v)
    }
    return ""
}
```

Le relevé :

| | naïve A — « deux appels, même valeur » | naïve B — « la nouvelle cote, tout de suite » | naïve C — « au bout de `MaxAge`, lue une fois » | **clause 7** |
|---|---|---|---|---|
| `Direct` | tient | tient | tient | tient |
| cache du 12/09 | tient | casse | casse | **casse** |
| `Expiring` 30 s | tient | **casse** | tient | tient |
| `Sliding` 30 s | tient | casse | **tient** | **casse** |

- **La naïve A ne voit rien.** Elle vérifie la stabilité — et la stabilité est
  la qualité d'un cache. Le cache du 12/09 la tient mieux que `Direct`.
- **La naïve B interdit tous les caches**, le bon compris. Elle dit « aucune
  fraîcheur tolérée », ce que personne n'a demandé ; un contrat qui interdit
  l'optimisation légitime sera contourné, pas respecté.
- **La naïve C a l'air juste, et c'est la plus dangereuse.** Elle lit, publie,
  avance d'une minute, relit. Elle laisse passer `Sliding` — un cache dont
  l'expiration recule à chaque lecture, optimisation qu'on trouve dans
  beaucoup de bibliothèques :

```go
// Sliding is an Expiring whose expiry is PUSHED BACK at each read, "to keep
// the hot pairs in cache". It is an optimization found in many libraries.
// Under continuous traffic, a pair read more often than TTL never expires.
type Sliding struct{ e *Expiring }

func NewSliding(next rates.Rates, ttl time.Duration, now func() time.Time) Sliding {
    return Sliding{e: NewExpiring(next, ttl, now)}
}

func (s Sliding) Rate(source, target string) (float64, error) {
    return s.e.rate(source, target, true)
}
```

Lu une seule fois au bout d'une minute, il a expiré. Lu en continu — à
95 000 transactions par jour, une paire chaude est lue plus d'une fois par
seconde —, **il n'expire jamais**. C'est l'incident du 12/09 avec un TTL.

La clause 7 lit donc **pendant** l'attente, une fois par seconde, comme le
trafic :

```go
// Clause7 is the missing clause. In one sentence: a quote published on the
// feed is returned by Rate, at EVERY call made MaxAge or more after its
// publication, and once returned, the old one never is again.
//
// It reads DURING the wait, once per second, as traffic of 95,000
// transactions a day does. A clause that only read at the end would let
// through an implementation whose expiry moves back at each read.
func Clause7() Clause {
    return Clause{"a published quote is returned at most MaxAge after", func(h Harness) string {
        w := world()
        r := h.New(w)
        if _, err := r.Rate("EUR", "XAF"); err != nil {
            return "first read: " + err.Error()
        }
        w.Publish("EUR", "XAF", newQuote)
        seen := false
        for elapsed := time.Duration(0); elapsed <= MaxAge; elapsed += time.Second {
            v, err := r.Rate("EUR", "XAF")
            switch {
            case err != nil:
                return fmt.Sprintf("at +%v: %v", elapsed, err)
            case v == newQuote:
                seen = true
            case seen:
                return fmt.Sprintf("at +%v: the old quote came back", elapsed)
            case elapsed == MaxAge:
                return fmt.Sprintf("at +%v: still %v, quote %v published %v ago", elapsed, v, newQuote, elapsed)
            }
            w.Advance(time.Second)
        }
        return ""
    }}
}
```

La seconde moitié — « une fois rendue, l'ancienne ne l'est plus jamais » —
a l'air d'une précaution. Elle a besoin d'un fautif pour prouver qu'elle sert
à quelque chose : sans lui, la retirer ne changerait aucun relevé, et la
campagne la compterait survivante. Le fautif est banal : **deux instances
derrière un répartiteur**, chacune dans la borne, l'une chaude et l'autre
arrivée à froid pendant un déploiement :

```go
// TestTwoInstancesThatDoNotRefreshTogether: two 30 s caches, each within the
// bound, behind a load balancer. The first read filled only one of them —
// it is what happens during a rolling deployment, when a new instance
// arrives cold. The cold instance serves the new quote, the warm instance
// the old one, alternately. Clause 7 forbids it, and it is the only one to
// see it.
func TestTwoInstancesThatDoNotRefreshTogether(t *testing.T) {
    h := rates.Harness{New: func(w *rates.World) rates.Rates {
        d := direct.New(w)
        return &alternating{
            a: cache.NewExpiring(d, 30*time.Second, w.Now),
            b: cache.NewExpiring(d, 30*time.Second, w.Now),
        }
    }}
    if got, want := brokenClauses(h), []string{"clause 7 "}; !slices.Equal(got, want) {
        t.Fatalf("%v, want %v", got, want)
    }
    t.Log(rates.Check(h))
}
```

```
clause 7 (a published quote is returned at most MaxAge after): at +1s: the old quote came back
```

Un paiement à 657,10, le suivant à 659,40, le suivant à 657,10. Chaque
instance tient la fraîcheur ; le système ne la tient pas.

## 4. Les 212 tests du service

Ils étaient verts parce que le bouchon de `Rates` rend des **constantes** :
le service a été testé dans un monde où les taux ne changent jamais —
exactement le monde où le cache du 12/09 est correct.

| Un bouchon qui rend des constantes **peut** prouver | Il **ne peut pas** prouver |
|---|---|
| que le service multiplie par le bon taux, arrondit correctement, choisit la bonne paire | que le taux utilisé est celui **du moment** du paiement |
| que le service traite `ErrUnknownCurrency` et `ErrFeed` | que le service réagit à un taux **qui change** pendant une opération |
| que le service ne convertit pas deux fois | quoi que ce soit sur le **temps** |

Ce n'est pas un défaut du bouchon : un bouchon de service n'a pas à vérifier
le port. C'est le rôle de la batterie, et c'est elle qui avait le trou. Les
212 tests et les six clauses partageaient la même hypothèse — *le monde ne
bouge pas* —, et deux vérifications qui partagent une hypothèse n'en font
qu'une.

le week-end, ce qui est une hypothèse à vérifier dans les journaux.

## 6. Le tableau de bord

Les trois indicateurs suivaient le taux d'erreur du fil, sa latence, et le
succès des paiements. Aucun ne pouvait bouger, pour une seule raison :

> **La panne ne produisait ni erreur ni lenteur.** Elle produisait des
> réponses **fausses**, rendues **plus vite**.

Le cache réduit les appels au fil — ses erreurs et sa latence ne peuvent que
baisser. Et chaque paiement réussit. Les trois indicateurs mesurent la
disponibilité ; la panne était une panne d'**exactitude**.

L'indicateur qui aurait tiré mesure ce que la panne a changé : **le retard de
la cote servie sur le fil**. Il exige de savoir de quelle cote vient le taux
servi — c'est la proposition D de la question 8 —, et il se compte d'une façon
précise, que ma première version avait fausse :

```go
// Lag counts the quotes published by the feed AFTER the one served. It is
// counted in publications, not in duration: after the night, a single
// publication of lag lasts nine hours, and a healthy cache serves it for at
// most its TTL. published is sorted, and only holds what is already
// published.
func Lag(served time.Time, published []time.Time) int {
    i := sort.Search(len(published), func(k int) bool { return published[k].After(served) })
    return len(published) - i
}

// Alarm fires from Threshold publications of lag.
type Alarm struct{ Threshold int }

func (a Alarm) Fires(served time.Time, published []time.Time) bool {
    return Lag(served, published) >= a.Threshold
}
```

Ma première version mesurait le retard en **durée** — l'instant de la
dernière publication moins celui de la cote servie —, seuil trente minutes.
Simulée, elle **tirait sur le cache sain** le samedi à 7 h 00, avec un retard
de 9 h 15 : la première publication du matin suit la dernière de la veille de
neuf heures, et pendant les 30 secondes de son TTL, un cache sain sert la
cote de 21 h 45. Une publication de retard, neuf heures de durée. Le retard
se compte en **publications**.

La simulation du 12/09, avec ses hypothèses écrites — le fil publie une cote
commerciale toutes les 15 minutes de 7 h à 22 h, tous les jours ; un paiement
toutes les 0,9 s :

```
Direct        max lag   0 publication(s)  fires 0      first Mon 00:00:00   | age against the clock: fires 105000 first Fri 22:15:00
Expiring 30 s max lag   1 publication(s)  fires 0      first Mon 00:00:00   | age against the clock: fires 105024 first Fri 22:15:00
Cache 12/09   max lag 149 publication(s)  fires 256000 first Fri 16:30:00   | age against the clock: fires 256000 first Fri 16:30:00
```

(« first Mon 00:00:00 » est la date zéro de Go : l'alarme n'a jamais tiré.)

- **Le seuil** : **deux** publications de retard.
- **Le plancher de bruit** : **une** publication de retard, pendant au plus le
  TTL après chaque publication. Le cache sain l'atteint et ne le dépasse
  jamais.
- **L'heure à laquelle il aurait tiré** : vendredi **16 h 30**, vingt-cinq
  minutes après la mise en production — au moment où le fil publie la
  deuxième cote que le cache ignore.

La dernière colonne est la raison de compter contre le fil et pas contre
l'horloge : une alarme sur l'âge de la cote tire **105 000 fois** sur
l'implémentation saine, toutes les nuits, parce que la nuit le fil ne publie
pas. Une alarme qui tire toutes les nuits est coupée au bout d'une semaine.

## 7. « Les taux ne changent pas assez vite pour que ça compte »

La phrase est **vraie pour la parité EUR/XAF**. Le franc CFA est arrimé à
l'euro à 655,957 : ce taux n'a pas bougé depuis 1999, et pour lui, un cache
sans expiration est correct. Un développeur qui travaille sur une plateforme
de la zone CFA pense naturellement à ce taux-là.

Et c'est l'incident qui dit qu'elle était fausse ici : un écart de
486 000 FCFA sur des paiements **en euros** prouve que le port ne sert pas la
parité fixe. Il sert un **taux commercial** — la parité plus une marge révisée
dans la journée —, sinon l'écart serait nul. Le port s'appelle `Rates`, il sert
toutes les paires et tous les taux, et sa signature ne dit pas lesquels
bougent.

Ce qui manquait à la demande de fusion pour que les relecteurs puissent
juger, c'est **un nombre** :

> **La borne de fraîcheur du contrat.** « Les taux ne changent pas assez vite »
> est une opinion. « Le contrat tolère une minute ; ce cache n'expire jamais »
> est une violation qu'un relecteur voit en une ligne.

Deux relecteurs ont approuvé une opinion contre une absence d'opinion. Ils
n'avaient rien à quoi la comparer : le contrat ne disait pas combien de
temps un taux peut avoir. Le nombre aurait aussi forcé la vraie question —
*quels taux sert ce port ?* —, celle dont la réponse rend la phrase fausse.

## 8. La correction

| | Ce qu'elle empêche | Ce qu'elle n'empêche pas | Ce qu'elle coûte | Quand un deuxième décorateur arrive |
|---|---|---|---|---|
| **A** expiration au cache | l'âge illimité | un TTL glissant ; un TTL choisi sans borne écrite | un nombre choisi par le développeur, sans contrat pour le juger | rien ne le vérifie : on recommence |
| **B** retirer le cache | tout ce qui est arrivé | rien de ce qui arrivera | la charge et la latence du fil reviennent | rien ne le vérifie : on recommence |
| **C** la clause 7, et le cache échoue | toute implémentation hors de la borne, **avant la fusion** | ce que le `Harness` ne peut pas provoquer | la batterie gagne un monde et une horloge ; chaque implémentation doit accepter l'horloge | **il passe la batterie, ou il ne fusionne pas** |
| **D** `Rate` rend l'instant de cotation | qu'un appelant utilise un taux sans pouvoir savoir son âge | qu'un décorateur **mente** sur l'instant | l'interface change : toutes les implémentations, tous les appelants — l'axe fermé, le compilateur les liste | il doit transmettre l'instant ; une clause doit vérifier qu'il ne le réécrit pas |

D est la seule qui **déplace** la garantie : avec l'instant de cotation dans
la réponse, c'est le service de paiement — celui qui sait qu'un paiement ne
tolère pas un taux de plus d'une minute — qui refuse, et c'est D qui rend
possible l'indicateur de la question 6. Mais D seul se contourne : un
décorateur qui écrirait `time.Now()` comme instant de cotation rendrait la
garantie silencieuse. D a besoin de sa propre clause — *l'instant rendu est
celui de la publication* — et donc de C.

**Je choisis les quatre, dans cet ordre :**

1. **B, lundi** — c'est fait à 14 h 00. On arrête l'écart avant de comprendre.
2. **C, dans la semaine** — la clause 7 entre dans la batterie, et le cache du
   12/09 y échoue. C'est le test de non-régression de l'incident, et c'est
   lui qui protège contre le décorateur suivant.
3. **D, ensuite** — l'interface change, le compilateur liste les
   implémentations à reprendre, et l'indicateur de la question 6 devient
   possible.
4. **A, en dernier, et seulement si la mesure de B le justifie** — le cache
   revient avec un TTL sous la borne, passe C, transmet l'instant de D.

L'ordre compte : A avant C remettrait en production un cache que rien ne
vérifie, et c'est exactement ce qui s'est passé le 12/09.

## 9. La garantie demandée par la direction

> *« Qu'une implémentation d'une interface ne puisse plus jamais introduire un
> comportement que la batterie ne vérifie pas. »*

**Pourquoi c'est impossible, en deux phrases :** une batterie est un nombre
fini d'observations, et une implémentation peut se comporter différemment sur
tout ce qu'aucune observation ne provoque — une date, une charge, un ordre
d'appels. Savoir si deux programmes se comportent pareil sur **toutes** les
entrées est indécidable en général (théorème de Rice) : ce n'est pas difficile,
c'est démontré impossible.

**La reformulation tenable :**

> *Toute implémentation qui n'est pas la source — tout décorateur — déclare,
> avant sa fusion, ce qu'elle change sur quatre dimensions : le **temps**,
> l'**état**, les **erreurs**, la **concurrence**. Chaque dimension déclarée
> modifiée a une clause dans la batterie, et l'implémentation la passe.*

On ne garantit plus qu'aucun comportement ne passe ; on garantit qu'aucun
comportement ne passe **sans avoir été nommé**. Le 12/09, le cache aurait dû
cocher « temps : modifié » — et la question « quelle clause ? » n'avait pas de
réponse.

**Le contrôle, et quand il tire :**

| Moment | Ce qui tire |
|---|---|
| **revue** | la déclaration des quatre dimensions est un champ obligatoire du modèle de demande de fusion pour tout paquet qui implémente un port ; « temps : modifié » sans numéro de clause bloque |
| **test** | la batterie passe sur **chaque implémentation inscrite au registre** (correction 2.4/4), pas sur une liste écrite à côté |
| **production** | l'indicateur de la question 6, et la lecture fantôme ci-dessous |

**Ce qu'il coûte, chiffré en ce qu'il interdit :** il interdit à tout
décorateur de lire `time.Now()` — l'horloge doit être injectée, sinon la
clause 7 ne peut pas le passer ; sur les quatre implémentations de ce corrigé,
les deux qui expirent ont dû la prendre en paramètre. Il interdit aussi de
fusionner un décorateur sans déclaration — et ce chiffre-là se mesure dans
le relevé des demandes de fusion, pas dans un corrigé.

**La mesure pour ce qu'il ne couvre pas :** une **lecture fantôme**. Un
appel sur cent est aussi posé à l'implémentation de référence — `Direct` —,
et les deux réponses sont comparées. À 95 000 transactions par jour, c'est
950 appels de plus au fil. Seuil : un écart qui dure plus de `MaxAge` ;
plancher de bruit : les écarts de moins de `MaxAge` après chaque
publication, que la borne autorise.

**La question qui décide : le contrôle attrape-t-il une implémentation qui
tient toutes les clauses et change quand même le comportement du système ?**

**Non.** Ce corrigé en contient un exemple :
deux instances, chacune dans la borne, chacune verte sur les sept clauses
prises seule — et le système sert l'ancienne cote un paiement sur deux. La
clause 7 l'a vu parce que je l'ai testé **ensemble** ; aucune déclaration
d'une implémentation seule ne l'aurait signalé. Et il y a pire, parce que ça
ne viole aucune clause du tout : un cache qui tient la fraîcheur mais concentre
toutes les relectures du fil sur la même seconde après chaque publication,
ou qui fait disparaître la latence dont un autre service se servait comme
contre-pression.

> **Ce qui reste vit hors du code : dans le rapprochement comptable.** C'est
> lui qui a trouvé l'incident du 12/09, et c'est lui l'oracle final — il
> compare ce que le système a fait à ce qui devait arriver, sans rien savoir
> de son implémentation. La conception ne le remplace pas ; elle peut le
> rendre **quotidien**, chiffré, et lu le jour même — au lieu d'un lundi
> matin.

Les deux « clause muette » sont tuées par un fautif écrit pour ça — une
implémentation qui rend 1 quand le fil échoue, « mieux vaut un taux qu'une
erreur » :

```go
// swallower returns 1 when the layer below fails: "better a rate than an
// error". The battery must see it.
type swallower struct{ next rates.Rates }

func (s swallower) Rate(src, dst string) (float64, error) {
    if v, err := s.next.Rate(src, dst); err == nil {
        return v, nil
    }
    return 1, nil
}

// alternating simulates two instances of the service behind a load
// balancer: each has its own cache, and calls go to one then to the other.
type alternating struct {
    a, b rates.Rates
    n    atomic.Int64
}

func (r *alternating) Rate(src, dst string) (float64, error) {
    if r.n.Add(1)%2 == 0 {
        return r.a.Rate(src, dst)
    }
    return r.b.Rate(src, dst)
}

func brokenClauses(h rates.Harness) []string {
    var out []string
    for _, f := range rates.Check(h) {
        out = append(out, f[:9])
    }
    return out
}

func TestTheBatterySeesASwallower(t *testing.T) {
    got := brokenClauses(rates.Harness{New: func(w *rates.World) rates.Rates {
        return swallower{direct.New(w)}
    }})
    if want := []string{"clause 2 ", "clause 6 "}; !slices.Equal(got, want) {
        t.Fatalf("%v, want %v", got, want)
    }
}
```

Et le survivant est **rien**. « Expiring : seuil inclus » rend la valeur
retenue un instant de plus — à l'instant exact de l'expiration. Le TTL est de
30 secondes, la borne du contrat d'une minute : l'implémentation reste dans
le contrat, avec trente secondes de marge. Écrire un test qui la tue, ce
serait tester la précision du TTL — une propriété que l'implémentation ne
promet à personne. **Un survivant qui ne viole aucune promesse ne réclame pas
de test** : il dit où est la marge du contrat.
