# Correction 2.3 — Exercice 1 : la plateforme portée depuis Java

> Rappel de l'énoncé : un type `Base` qui porte une « méthode modèle »
> `Send`, quatre morceaux non exportés, deux types qui incorporent `Base`
> et en « surchargent » trois et deux. Vingt-trois tests verts, 94 % de
> couverture.

Tout ce qui suit est mesuré sur un module qui compile, dont les deux paquets
de test passent sous `go vet` et `go test -race -count=1`. Le paquet `before`
— le code de l'énoncé — est **conservé** dans le module : sans lui, « les
trois canaux rendaient le même texte » serait une affirmation, et l'épreuve
de non-régression de la section 6 n'aurait rien à comparer.

## 1. Les trois appels

### Ce qu'un développeur venu de Java écrit

| | Prédiction naturelle |
|---|---|
| `a` (SMS) | accepté, pas de ligne `Subject:`, corps tronqué à 160 |
| `b` (Courrier) | `Sender: BANQUE (mail)`, corps en majuscules, daté |
| `c` (Base) | l'entête et le corps par défaut |

### Ce que le programme rend

```
=== a / SMS ===
err = notification: send refused
(0 octets)

=== b / Mail ===
err = <nil>
De: BANQUE
A: client@example.cm
Subject: [NOTIF] Balance

Votre solde est de 12 400 FCFA
(84 octets)

=== c / Base ===
err = <nil>
De: BANQUE
A: client@example.cm
Subject: [NOTIF] Balance

Votre solde est de 12 400 FCFA
(84 octets)
```

**Zéro sur trois.** Et le troisième est le plus parlant : `b` et `c` rendent
les **mêmes 84 octets**. `Mail` déclare deux méthodes, et il se comporte
exactement comme s'il n'en déclarait aucune.

Voilà la mesure, pas la prédiction :

```go
// TestTheThreePredictions measures the three calls of question 1, and each
// contradicts what a developer coming from Java predicts.
func TestTheThreePredictions(t *testing.T) {
    b := before.Base{Sender: "BANQUE", Clock: fixedClock}

    // 1. The SMS is REFUSED, although it overrides validRecipient to
    //    accept nine digits. Base.Send calls b.validRecipient
    //    with a receiver of type Base, which requires an at sign.
    sms := before.SMS{Base: b, Operator: "MTN"}
    if _, err := sms.Send("677123456", "Balance", "12 400 FCFA"); !errors.Is(err, before.ErrSendRefused) {
        t.Errorf("the SMS was accepted: the override was called: %v", err)
    }

    // 2. The mail goes through, but with the DEFAULT header and body.
    mail := before.Mail{Base: b, PostalCode: "BP 1234"}
    output, err := mail.Send("client@example.cm", "Statement", "votre releve")
    if err != nil {
        t.Fatalf("Send: %v", err)
    }
    if !strings.HasPrefix(output, "De: BANQUE") {
        t.Errorf("header = %q, want Base's", firstLine(output))
    }
    if strings.Contains(output, "Expediteur:") {
        t.Error("Mail's header was called")
    }
    if strings.Contains(output, "VOTRE RELEVE") {
        t.Error("Mail's body was called")
    }
    if strings.Contains(output, "Fait a Douala") {
        t.Error("Mail's date was added")
    }

    // 3. Base returns exactly the same thing as Mail.
    base, err := b.Send("client@example.cm", "Statement", "votre releve")
    if err != nil {
        t.Fatal(err)
    }
    if base != output {
        t.Fatal("Base and Mail return different texts")
    }
    t.Logf("Base and Mail return the same %d bytes", len(base))
}
```

## 2. Pourquoi le SMS est refusé

`SMS` déclare bien `validRecipient` qui accepte neuf chiffres. Elle n'est
jamais appelée.

`Send` est déclarée sur `Base`. Son récepteur `b` est de type `Base`. À la
ligne `if !b.validRecipient(recipient)`, le compilateur cherche une
méthode `validRecipient` **sur le type `Base`**, la trouve, et écrit
l'appel. Définitivement. `Base` ne sait pas que `SMS` existe, et il n'y a
aucun mécanisme en Go pour le lui apprendre : **l'incorporation ne crée pas de
dispatch virtuel**.

L'écart entre les deux journaux est la partie qui coûte le plus cher :

| | Ce qui est visible |
|---|---|
| le client | *« envoi refusé »*, sans autre indication, pour un numéro parfaitement valide |
| les journaux du développeur | `notification: send refused` — **la même ligne**, sans le canal, sans le destinataire, sans la raison |

L'erreur est une variable de paquet partagée par tous les canaux. Elle ne
nomme ni le canal ni le motif. Un développeur qui lit cette ligne ne peut pas
distinguer « le numéro est mal formé » de « ce canal n'a jamais eu le droit de
valider ». C'est le deuxième défaut, et il est indépendant du premier : même
avec le dispatch virtuel, ce message resterait inutilisable.

## 3. Le critère appliqué à `Base`

> Un type est sûr à incorporer-et-surcharger si et seulement si **aucune de
> ses méthodes n'appelle une autre de ses méthodes sur son propre récepteur**.

`Base` a cinq méthodes. Une seule en appelle d'autres, et elle en appelle
**quatre** :

| Méthode de `Base` | Appelle sur `b` |
|---|---|
| `validRecipient` | — |
| `subject` | — |
| `body` | — |
| `header` | — |
| `Send` | `validRecipient`, `header`, `subject`, `body` |

Quatre appels internes. `Base` échoue au critère, et il y échoue de la pire
façon : **les quatre méthodes qu'on est censé surcharger sont exactement les
quatre qui sont appelées en interne**. Ce n'est pas un type qui a un appel
interne par accident ; c'est un type dont tout l'intérêt supposé repose sur
des appels internes.

Conséquence pour `SMS` et `Mail` : **aucune de leurs cinq méthodes
déclarées n'est atteignable par `Send`**. Elles compilent, elles sont
correctes, elles sont couvertes par les tests, et elles sont mortes.

## 4. Les méthodes exportées — et le chiffre qui surprend

La question attend « combien de méthodes `SMS` exporte-t-il de trop ». La
réponse mesurée est **aucune** :

```go
// TestTheNumberOfExportedMethodsIsATrap is the answer to question 4, and
// it does not give the expected figure.
//
// The three types export ONLY ONE method each, because the four
// pieces are unexported. So there is no method leak here, and
// it is good news that hides bad news.
//
// The leak is elsewhere: the Clock field is EXPORTED, so any
// caller can replace the clock of any channel. Embedding
// also promotes FIELDS, and one thinks of it less than of methods.
func TestTheNumberOfExportedMethodsIsATrap(t *testing.T) {
    for name, typ := range map[string]reflect.Type{
        "Base": reflect.TypeOf(before.Base{}),
        "SMS":  reflect.TypeOf(before.SMS{}),
        "Mail": reflect.TypeOf(before.Mail{}),
    } {
        if n := typ.NumMethod(); n != 1 {
            t.Errorf("%s exports %d methods, want 1", name, n)
        }
    }
    // But the promoted fields are exported.
    sms := reflect.TypeOf(before.SMS{})
    if _, ok := sms.FieldByName("Clock"); !ok {
        t.Error("the Clock field is not promoted to SMS's level")
    }
    if _, ok := sms.FieldByName("Sender"); !ok {
        t.Error("the Sender field is not promoted to SMS's level")
    }
    t.Log("SMS exports 1 method and 3 fields, 2 of them promoted")
}
```

Les trois types exportent **une** méthode chacun, parce que les quatre
morceaux sont non exportés. De ce côté-là, le modèle est propre.

La fuite est ailleurs, et elle est plus insidieuse : **l'incorporation promeut
aussi les champs**. `SMS` a trois champs exportés, dont deux promus :

| Champ de `SMS` | D'où | Ce qu'il permet |
|---|---|---|
| `Operator` | déclaré | rien (section 5) |
| `Sender` | promu de `Base` | n'importe qui peut réécrire l'expéditeur d'un canal construit |
| `Clock` | promu de `Base` | **n'importe qui peut remplacer l'horloge de n'importe quel canal, en production** |

`sms.Clock = func() time.Time { return temps.Zero }` compile et s'exécute,
depuis n'importe quel paquet. Une dépendance qu'on croyait injectée à la
construction est en fait modifiable à vie, sur chaque exemplaire.

> On compte les méthodes promues parce que la leçon parle de méthodes.
> Les champs promus se comptent aussi, et ils ouvrent l'état, pas le
> comportement.

## 5. Pourquoi `Operator` et `PostalCode` ne servent à rien

Ce n'est pas un oubli : **la forme du code les rend inutilisables**.

`Operator` est un champ de `SMS`. Pour l'utiliser dans la mise en forme, il
faudrait l'atteindre depuis le code qui met en forme. Or ce code est dans
`Base.Send`, dont le récepteur est de type `Base` — un type qui ne connaît
pas `SMS` et ne peut donc pas voir ses champs.

Le seul endroit d'où `Operator` est visible, c'est une méthode de `SMS` ; et
les méthodes de `SMS` ne sont jamais appelées. Les deux moitiés du problème se
referment l'une sur l'autre :

```
Base.Send  voit le squelette, ne voit pas Operator
SMS.body     voit Operator, n'est jamais appelee
```

C'est la différence qui compte avec l'héritage classique : là-bas, le
squelette est résolu **sur le type dynamique**, donc il atteint les champs du
sous-type via les méthodes redéfinies. Ici, le squelette est résolu **sur le
type statique**, donc il n'atteint rien.

> Deux champs morts dans un type qui compile, ce n'est pas un code
> négligé : c'est la signature d'un dispatch qui n'a pas lieu.

## 6. La correction

Un seul changement de forme, et tout le reste en découle : **le squelette
devient une fonction**, et ce qui variait devient une interface déclarée par
cette fonction.

### Le diff conceptuel

| | Avant | Après |
|---|---|---|
| le squelette | méthode `Send` sur `Base` | **fonction** `notification.Send` |
| les morceaux | méthodes non exportées de `Base`, redéclarées | **méthodes exportées** des types de canal |
| le lien | incorporation de `Base` | **paramètre** de type `Channel` |
| `Base` | existe | **n'existe plus** |
| l'horloge | champ exporté promu | paramètre du squelette, redescendu en argument |

### L'interface

```go
// Channel is the SKELETON's interface. Five methods: the four pieces
// of the statement, which vary in all three channels, plus Name, which is not used
// to format but to write a refusal one can read at three in the
// morning.
//
// It is declared here, at the caller. Its signature names only
// strings and a time.Time: universal vocabulary, so an
// implementation need not import this package.
//
// Five methods is a lot, and it must be said: Valid is a
// VALIDATION, three others are FORMATTING, and Name is an
// IDENTITY. A caller that only wanted to validate would still carry the
// other four in its test double. It is the subject of lesson 2.5;
// here we keep an interface, because there is only one caller.
type Channel interface {
    Name() string
    Valid(recipient string) bool
    Header(sender string) string
    Subject(object string) string
    Body(message string, now time.Time) string
}
```

**Cinq méthodes**, et il faut dire pourquoi c'est beaucoup : quatre sont les
morceaux de l'énoncé, la cinquième (`Name`) existe uniquement pour que le refus
soit lisible. C'est déjà une interface qui mélange une validation, trois mises
en forme et une identité — la leçon 2.5 y reviendra. Ici on la garde entière,
parce qu'il n'y a **qu'un seul appelant**.

Elle est déclarée **chez l'appelant**, dans `notification`, et sa signature ne
nomme que `string` et `time.Time`. Conséquence mesurée :

```
$ go list -f '{{join .Imports " "}}' ./ex1/canaux
strings time unicode/utf8
```

`channels` **n'importe pas** `notification`. Un quatrième canal peut vivre dans
un autre dépôt.

### Le squelette

```go
// Send assembles the message. It is the skeleton, and it is a function.
func Send(c Channel, sender, recipient, object, message string, clock func() time.Time) (string, error) {
    if c == nil {
        return "", ErrMissingChannel
    }
    if clock == nil {
        return "", ErrMissingClock
    }
    if !c.Valid(recipient) {
        return "", fmt.Errorf("%w: %q for channel %s",
            ErrInvalidRecipient, recipient, c.Name())
    }
    now := clock()
    var sb strings.Builder
    sb.WriteString(c.Header(sender))
    sb.WriteString("\nA: ")
    sb.WriteString(recipient)
    // An empty subject does not produce an empty "Sujet:" line: an SMS has
    // no subject, and the empty line would end up in the message.
    if subject := c.Subject(object); subject != "" {
        sb.WriteString("\nSujet: ")
        sb.WriteString(subject)
    }
    sb.WriteString("\n\n")
    sb.WriteString(c.Body(message, now))
    return sb.String(), nil
}
```

Trois choses à noter, dans l'ordre où elles coûteraient cher si elles
manquaient :

1. **`c == nil` est traité en premier.** Un canal absent est une erreur, pas
   un canal par défaut — l'énoncé est précisément l'histoire d'un
   comportement par défaut qui s'est appliqué sans que personne ne le voie.
2. **`clock == nil` aussi.** Sans cette ligne, un canal qui date ses envois
   panique au premier appel, en production, et pas en test.
3. **Le sujet vide ne produit pas de ligne vide.** Le SMS n'a pas de sujet ;
   dans le modèle d'origine, `subject()` rendant `""` laissait quand même la
   ligne `Subject: ` dans le message, et personne ne l'avait vue.

### Le canal SMS, avec son `Operator` vivant

```go
// SMS is the short-message channel.
// Operator is used, this time: it appears in the header. In the original
// model the field existed and could not be used, because the
// skeleton never saw the type that carried it.
type SMS struct {
    Operator string
    // MaxLength is 160 when it is zero. The zero value of an
    // integer truncates nothing, and an SMS without a limit is not an SMS.
    MaxLength int
}

const defaultSMSLength = 160

func (SMS) Name() string { return "SMS" }

func (SMS) Valid(d string) bool {
    if len(d) != 9 {
        return false
    }
    for _, r := range d {
        if r < '0' || r > '9' {
            return false
        }
    }
    return true
}

func (s SMS) Header(sender string) string {
    if s.Operator == "" {
        return "De: " + sender
    }
    return "De: " + sender + " via " + s.Operator
}

// Subject returns the empty string: an SMS has no subject, and the skeleton knows
// what to do with an empty subject.
func (SMS) Subject(string) string { return "" }

func (s SMS) Body(message string, _ time.Time) string {
    max := s.MaxLength
    if max <= 0 {
        max = defaultSMSLength
    }
    if len(message) <= max {
        return message
    }
    if max <= 3 {
        return message[:max]
    }
    // The cut is made on RUNES and not on bytes: cutting "é" in the
    // middle produces an invalid byte, and the client sees a black diamond.
    cut := message
    for len(cut) > max-3 {
        _, taille := utf8.DecodeLastRuneInString(cut)
        cut = cut[:len(cut)-taille]
    }
    return cut + "..."
}
```

`Operator` sert, maintenant, parce que la méthode qui le lit est celle que le
squelette appelle. Et la troncature compte en **runes** : 158 caractères
accentués font 316 octets, et couper à l'octet 157 produit un caractère
invalide — le losange noir côté client.

### La non-régression

Un refactoring doit prouver qu'il n'a rien changé pour ce qui marchait :

```go
// TestTheEmailFormatIsKeptByteForByte: the check a
// refactoring must always carry.
//
// The fixed skeleton, with the Email channel, returns exactly what
// made the skeleton broken. The refactoring changed nothing for the only
// channel that worked.
func TestTheEmailFormatIsKeptByteForByte(t *testing.T) {
    old, err := before.Base{Sender: "BANQUE", Clock: clock}.
        Send("client@example.cm", "Statement", "votre releve")
    if err != nil {
        t.Fatal(err)
    }
    fresh, err := notification.Send(channels.Email{}, "BANQUE",
        "client@example.cm", "Statement", "votre releve", clock)
    if err != nil {
        t.Fatal(err)
    }
    if old != fresh {
        t.Fatalf("the default format changed\nold:\n%s\nnew:\n%s", old, fresh)
    }
    t.Logf("%d identical bytes", len(fresh))
}
```

```
=== RUN   TestTheEmailFormatIsKeptByteForByte
    notification_test.go:78: 67 octets identiques
--- PASS
```

Le canal `Email` rend **octet pour octet** ce que rendait `Base`. C'est
pour cette seule ligne que le paquet `before` reste dans le module.

Et l'inverse du défaut :

```
=== RUN   TestLesTroisCanauxRendentTroisTextesDifferents
    notification_test.go:55: courriel 67 octets, sms 45, courrier 121
--- PASS
```

Trois canaux, trois longueurs. Dans l'énoncé, deux des trois faisaient 84.

### Les assertions de conformité

```go
// The conformance assertions. Without them, adding a method to Channel
// produces no compile error.
var (
    _ notification.Channel = channels.Email{}
    _ notification.Channel = channels.SMS{}
    _ notification.Channel = channels.Mail{}
)
```

Sans ces trois lignes, ajouter une méthode à `Channel` ne produit **aucune**
erreur de compilation tant que personne ne construit la liste des canaux —
c'est la mesure de la correction 2.2/4, et elle vaut ici aussi. Dans ce
module elles vivent dans le fichier de test parce que le module n'a pas de
racine de composition ; dès qu'il en aura une, elles y descendront.

## 7. La forme qu'avaient forcément les 23 tests

Pour être verts sur un code faux, ils ne pouvaient avoir qu'**une** forme :
chaque morceau appelé **directement**, jamais le squelette.

```go
// TestTheOverriddenPiecesAreCorrect is the shape the 23 tests had
// green ones of the statement, and it is the answer to question 7.
//
// It calls each piece DIRECTLY. The overrides are correct, so
// it passes. It never touches the skeleton, so it cannot see that
// the skeleton does not call them.
//
//    A test that checks the pieces one by one says nothing of their
//    assembly. And it is the assembly that goes to the client.
func TestTheOverriddenPiecesAreCorrect(t *testing.T) {
    b := Base{Sender: "BANQUE", Clock: func() time.Time {
        return time.Date(2026, 6, 15, 10, 0, 0, 0, time.UTC)
    }}

    sms := SMS{Base: b, Operator: "MTN"}
    if !sms.validRecipient("677123456") {
        t.Error("SMS.validRecipient refuses nine digits")
    }
    if sms.subject("Balance") != "" {
        t.Error("SMS.subject does not return the empty string")
    }

    mail := Mail{Base: b, PostalCode: "BP 1234"}
    if mail.header() != "Expediteur: BANQUE (courrier)" {
        t.Errorf("Mail.header = %q", mail.header())
    }
    if got := mail.body("votre releve"); got == "votre releve" {
        t.Error("Mail.body does not upper-case")
    }
    t.Log("the four overridden pieces are correct, and none is called by Send")
}
```

Ce test passe. Il est honnête, il est précis, il couvre 94 % des lignes — et
il ne dit rien de ce qui part chez le client, parce qu'il ne traverse jamais
`Send`.

La couverture le confirme : les quatre morceaux de `SMS` et de `Mail` sont
appelés, donc comptés. Les lignes sont couvertes. **Le chemin ne l'est pas.**

> Un test qui vérifie les morceaux un par un ne dit rien de leur
> assemblage. Et c'est l'assemblage qui part chez le client.

### Le test qui aurait été rouge le premier jour

En une phrase : **deux canaux différents doivent rendre deux textes
différents.**

```go
// TestTheSkeletonCallsOnlyItsOwnPieces is the test that would have been
// red on day one, and it fits in four lines.
//
// It checks no format: it checks that TWO different channels return
// different texts. It is the property the business asked for, and it is
// the only one none of the 23 tests checked.
func TestTheSkeletonCallsOnlyItsOwnPieces(t *testing.T) {
    b := Base{Sender: "BANQUE", Clock: time.Now}
    mail, err := Mail{Base: b, PostalCode: "BP 1234"}.
        Send("client@example.cm", "Statement", "votre releve")
    if err != nil {
        t.Fatal(err)
    }
    base, err := b.Send("client@example.cm", "Statement", "votre releve")
    if err != nil {
        t.Fatal(err)
    }
    if mail == base {
        t.Log("the skeleton returns the same text for Mail and for Base:" +
            " it is the flaw the correction removes")
        return
    }
    t.Fatal("the two texts differ: virtual dispatch appeared")
}
```

Quatre lignes utiles. Il ne vérifie **aucun format** — c'est ce qui le rend
robuste : il n'a pas à être mis à jour quand l'entête change. Il vérifie la
seule propriété que le métier demandait et qu'aucun des 23 tests ne touchait.

Noter sa forme : il est écrit à l'envers, il **réussit quand le défaut est
là**, et il échouerait si le dispatch virtuel apparaissait. C'est un test de
l'énoncé, pas de la correction ; il documente le défaut dans le module qui le
porte.

## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | Une méthode d'un type est résolue **sur le type du récepteur**, pas sur ce qui l'incorpore. Il n'y a pas de dispatch virtuel en Go. |
| ⚫ | Un squelette qui doit appeler des morceaux variables ne peut pas être une méthode du type qui porte les morceaux par défaut. **C'est une fonction**, et les morceaux sont une interface. |
| ⚫ | `Base` échoue au critère de façon maximale : les quatre méthodes à surcharger sont les quatre appelées en interne. |
| ⚫ | L'incorporation promeut aussi les **champs**. Ici, `Clock` exporté rend l'horloge de tout canal modifiable depuis n'importe où. |
| ⚫ | Un champ de sous-type inutilisable depuis le squelette est le **symptôme visible** d'un dispatch qui n'a pas lieu. |
| ⚫ | 94 % de couverture et 23 tests verts sont compatibles avec un code entièrement faux, si les tests appellent les morceaux et jamais l'assemblage. |
| ⚫ | Le test qui sauvait la mise ne vérifiait **aucun format** : seulement que deux canaux différents diffèrent. |
| ⚫ | Un refus qui ne nomme ni le canal ni le motif coûte autant que le défaut lui-même, et il survit à sa correction. |
| ⚫ | Un refactoring se prouve par une **égalité octet pour octet** sur le cas qui marchait déjà. C'est pour ça que le code de l'énoncé reste dans le module. |
