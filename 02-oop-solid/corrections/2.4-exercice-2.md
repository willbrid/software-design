# Correction 2.4 — Exercice 2 : les notifications de virements

> Rappel de l'énoncé : trois canaux, deux langues, et un relevé de dix-huit
> mois qui donne **2 canaux ajoutés, 1 langue, et 11 types de notification**.

Cinq paquets et le sondage, verts sous `go vet ./...` et `go test -race -count=1 ./...`.
Campagne de seize modifications, 16/16 après deux passes.

## 1. L'axe, dicté par le relevé

| | Sur dix-huit mois | Un tous les… |
|---|---|---|
| canaux | 2 | 9 mois |
| langues | 1 | 18 mois |
| **types de notification** | **11** | **7 semaines** |

L'axe à ouvrir n'est pas celui qu'on ouvre d'habitude. La structure réflexe
devant « trois canaux » est une interface `Channel` avec un type de
notification par méthode, ou un type Go par notification. Les deux font du
**type de notification** un élément de code — et le relevé dit qu'il en arrive
un toutes les sept semaines.

> **Décision : un type de notification est une DONNÉE, pas un type Go.** Une
> clé et des champs nommés, rendus par un gabarit. Ce qui reste du code, c'est
> le canal — qui bouge une fois tous les neuf mois.

```go
// Message is a fact to notify.
//
// Note that it carries NO text. It is the whole axis choice of the exercise:
// a notification type is a KEY and named data, not a Go type.
type Message struct {
    Key       string
    Data      map[string]string
    Urgency   Urgency
    Instant   time.Time
    Reference string
}

// Fields returns the names of the data, sorted.
//
// It serves the error messages of the skeleton: a template that asks for a
// missing field must be able to say which ones are there.
func (m Message) Fields() []string {
    names := make([]string, 0, len(m.Data))
    for n := range m.Data {
        names = append(names, n)
    }
    sort.Strings(names)
    return names
}
```

Et ce que ça ferme, explicitement : **une notification ne peut pas avoir sa
propre logique**. Pas de calcul, pas de condition, pas de mise en forme
particulière. Si un jour « plafond atteint » doit afficher un graphique, il
faudra ou bien un canal qui sait le faire pour tous, ou bien rouvrir le
choix. C'est le prix, et il est connu d'avance.

### Les deux interfaces

```go
// Channel is the CLOSED axis of the exercise: two methods, three
// implementations, and the record says one arrives every nine months.
type Channel interface {
    Name() string
    Format(r model.Render, m model.Message) (string, error)
}

// Catalog returns the template of a key in a language.
//
// It is through it that the OPEN axis goes: adding a notification type is
// one more entry in the catalog, and zero lines of code.
type Catalog interface {
    Template(key string, l model.Language) (model.Render, error)
}
```

### Le squelette

```go
// field recognizes a marker of the form {name}.
var field = regexp.MustCompile(`\{([a-z_]+)\}`)

// Send returns the message ready to go.
//
// Four steps, and none knows any notification type in particular: it is
// what makes adding a type free in code.
func Send(reg Registry, cat Catalog, channel string,
    l model.Language, m model.Message) (string, error) {
    if cat == nil {
        return "", ErrNoCatalog
    }
    c, err := reg.For(channel)
    if err != nil {
        return "", err
    }
    template, err := cat.Template(m.Key, l)
    if err != nil {
        return "", err
    }
    filled, err := fill(template, m)
    if err != nil {
        return "", fmt.Errorf("%w (channel %s, language %s)", err, c.Name(), l)
    }
    return c.Format(filled, m)
}
```

```go
// fill replaces the markers of the template with the data of the message.
//
// A marker without data is an ERROR, not an empty string. A message that
// announces "transfer of  XAF" is worse than a message that does not go.
func fill(t model.Render, m model.Message) (model.Render, error) {
    var missing error
    replace := func(s string) string {
        return field.ReplaceAllStringFunc(s, func(marker string) string {
            name := marker[1 : len(marker)-1]
            v, known := m.Data[name]
            if !known {
                if missing == nil {
                    missing = fmt.Errorf("%w: %q for key %q (present: %v)",
                        ErrMissingField, name, m.Key, m.Fields())
                }
                return marker
            }
            return v
        })
    }
    filled := model.Render{Subject: replace(t.Subject), Body: replace(t.Body)}
    if missing != nil {
        return model.Render{}, missing
    }
    return filled, nil
}
```

Quatre étapes, et **aucune ne connaît un type de notification en
particulier**. C'est ça qui rend l'ajout d'un type gratuit en code.

Un marqueur sans donnée est une **erreur**, pas une chaîne vide : un message
qui annonce « virement de  FCFA » est pire qu'un message qui ne part pas. La
campagne a une modification là-dessus, et elle tombe.

### Ce que la mesure a cassé, et qu'elle ne devait pas casser

À la première exécution, **deux** tests sont tombés au lieu d'un :

```
--- FAIL: TestTheKnownChannels
--- FAIL: TestAnUnknownChannelIsAnError
```

Le second affirmait qu'un canal nommé `"whatsapp"` était inconnu. Il l'était
— jusqu'à ce que la mesure l'ajoute.

```go
// TestAnUnknownChannelIsAnError: no default channel.
//
// The name of the unknown channel was "whatsapp" in the first version of
// this test. The measurement of the axis brought it down: whatsapp was
// added, and the test that asserted it was unknown became false.
//
//    A test that names a case "unknown" must choose a name that can never
//    exist. Otherwise it measures the calendar.
func TestAnUnknownChannelIsAnError(t *testing.T) {
    _, err := notif.Send(wiring.Channels(), wiring.Catalog(),
        "carrier-pigeon", model.FR, message())
    if !errors.Is(err, notif.ErrUnknownChannel) {
        t.Fatalf("err = %v, want ErrUnknownChannel", err)
    }
    t.Logf("%v", err)
}
```

Le même défaut existait sur les langues, avec `model.EWO`, et la mesure de
l'axe des langues l'a fait tomber aussi. Deux fois la même faute, dans le même
fichier.

> Un test qui nomme un cas « inconnu » ou « absent » doit choisir un nom qui
> **ne pourra jamais exister**. Sinon il ne mesure pas une propriété, il
> mesure le calendrier.

Le code ISO 639-1 `zz` est réservé à l'usage privé et ne sera jamais attribué
à une langue : c'est ce qui en fait un bon nom de cas absent.

### Les deux mesures ne sont pas les mêmes, et voilà pourquoi

| | Ajouter un **type de notification** | Ajouter une **méthode à `Channel`** |
|---|---|---|
| ce que c'est | une donnée de plus dans une table | une **opération** de plus sur l'axe fermé |
| coût | 2 entrées, 0 ligne de code | 3 implémentations, dont une dans un autre dépôt le jour où il y en a un |
| le compilateur | muet | **3 erreurs, toutes au bon endroit** |

Les deux sont des « ajouts », et ils n'ont rien à voir. Le premier est un
ajout **sur l'axe ouvert** : il est gratuit, et il est invisible pour le
compilateur. Le second est un ajout **sur l'axe fermé** : il coûte N, et le
compilateur te tient la main.

## 4. La langue n'est pas sur le même axe que le canal

Non, et c'est le cœur de l'exercice.

| | Canal | Langue |

| ce que c'est | du **code** | une **donnée** |

// TestTheCatalogIsComplete: each type exists in each language.

func TestTheCatalogIsComplete(t *testing.T) {

### Et si les deux axes étaient du code ?

Trois canaux fois quatre langues, chacun un type Go : **douze types**, et
treize avec un canal de plus, seize avec une langue de plus. C'est la
multiplication, et c'est ce qu'il faut refuser.

> Deux axes ne se multiplient que si on en fait **deux axes de code**. En
> faire un de code et un de donnée les additionne : 3 canaux + 24 gabarits,
> et le second nombre ne demande pas de relecture.

Ce qui rend la séparation possible est que **le canal décide de la forme et
le gabarit du texte**, et qu'aucun des deux n'a besoin de l'autre :

```go
// TestTheChannelDecidesWhatItKeeps: the SMS drops the subject, the mobile
// keeps the data. A template can do neither.
func TestTheChannelDecidesWhatItKeeps(t *testing.T) {
    reg, cat := wiring.Channels(), wiring.Catalog()
    sms, err := notif.Send(reg, cat, "sms", model.FR, message())
    if err != nil {
        t.Fatal(err)
    }
    if strings.Contains(sms, "Virement recu de") {
        t.Error("the SMS kept the subject")
    }
    mobile, err := notif.Send(reg, cat, "mobile", model.FR, message())
    if err != nil {
        t.Fatal(err)
    }
    if !strings.Contains(mobile, `"sender":"SARL BETA"`) {
        t.Errorf("the mobile did not pass on the data:\n%s", mobile)
    }
    t.Log("the SMS drops the subject, the mobile passes on the data:" +
        " two decisions a template cannot take")
}
```

```
the SMS drops the subject, the mobile passes on the data: two decisions a
template cannot take
```

```go
// payload is the JSON payload of a push notification.
type payload struct {
    Application string            `json:"application,omitempty"`
    Title       string            `json:"title"`
    Body        string            `json:"body"`
    Priority    string            `json:"priority"`
    Data        map[string]string `json:"data,omitempty"`
}

// Format returns the JSON payload.
//
// It is the only one of the three channels that passes on the DATA of the
// message on top of the text: the mobile application needs it to open the
// right screen. A template could not do that, and it is the second argument
// for the channel being code.
func (mo Mobile) Format(r model.Render, m model.Message) (string, error) {
    if strings.TrimSpace(r.Body) == "" {
        return "", ErrEmptyBody
    }
    priority := "normal"
    if m.Urgency == model.Critical {
        priority = "high"
    }
    raw, err := json.Marshal(payload{
        Application: mo.Application,
        Title:       r.Subject,
        Body:        r.Body,
        Priority:    priority,
        Data:        m.Data,
    })
    if err != nil {
        return "", err
    }
    return string(raw), nil
}
```

Le canal mobile transmet les **données** du message en plus du texte, parce
que l'application en a besoin pour ouvrir le bon écran. Un gabarit ne peut pas
faire ça. C'est le second argument pour que le canal reste du code, et c'est
une mesure, pas une opinion.

### L'invariant que personne n'écrit

```go
// TestTheMarkersAreTheSameInAllLanguages is the invariant nobody writes and
// that breaks in production.
//
// If the French template asks for {balance} and the English one does not,
// the producer of the message has no way of knowing it must send it: it
// tests in French, it works, and the English-speaking customer receives an
// error.
func TestTheMarkersAreTheSameInAllLanguages(t *testing.T) {
    cat := wiring.Catalog()
    for _, k := range catalog.Keys() {
        var reference []string
        for _, l := range catalog.Languages() {
            g, err := cat.Template(k, l)
            if err != nil {
                t.Fatalf("%s / %s: %v", k, l, err)
            }
            markers := notif.Markers(g)
            if reference == nil {
                reference = markers
                continue
            }
            if strings.Join(markers, ",") != strings.Join(reference, ",") {
                t.Errorf("%s: %s asks for %v, the first language asks for %v",
                    k, l, markers, reference)
            }
        }
    }
}
```

Si le gabarit français réclame `{balance}` et l'anglais ne le réclame pas, le
producteur du message n'a **aucun moyen** de savoir qu'il doit l'envoyer : il
teste en français, ça marche, et le client anglophone reçoit une erreur. C'est
la panne la plus probable de ce modèle, et elle coûte une boucle de vingt
lignes.

## 5. Un canal inconnu est une erreur

En une phrase, avec la correction 2.3/5 : **un repli silencieux coûte onze
jours de détection, parce que rien ne distingue un repli qui marche d'un code
qui marche** — là-bas 214 000 réponses fausses derrière un tableau de bord
vert ; ici un client qui a demandé un SMS et reçoit un courriel.

```
notif: unknown channel: "carrier-pigeon" (known: [email mobile sms])
```

Et la même décision pour la langue, qui est moins évidente :

```
notif: missing template: key "transfer.received", language "zz"
an English-speaking customer who receives a message in French is a silent
incident, and silence costs eleven days
```

**Pas de repli sur le français.** C'est contre-intuitif — un message en
français vaut mieux que pas de message — et c'est faux pour une raison
mesurable : un repli qui marche ne produit aucune alerte, donc la langue
manquante n'est jamais corrigée. Le refus, lui, remonte dans le taux d'erreur
du jour même.

## 6. Le sondage de cohésion

```go
// TestTheSkeletonHasNoStruct is the sharpest result of the probe, and it was
// not planned.
//
// The notif package holds NO struct: two interfaces, a map type, and
// functions. A package without a struct has no cohesion question to ask —
// it is the strongest form of the answer to question 6, and it is a direct
// consequence of the axis choice: the skeleton carries no state because all
// the state is in the catalog and in the channels.
func TestTheSkeletonHasNoStruct(t *testing.T) {
    path, err := filepath.Abs(filepath.Join("..", "notif"))
    if err != nil {
        t.Fatalf("path: %v", err)
    }
    reports, err := probe.Analyze(path, nil)
    if err != nil {
        t.Fatalf("Analyze: %v", err)
    }
    if len(reports) != 0 {
        for name := range reports {
            t.Errorf("the notif package holds the struct %s", name)
        }
    }
    t.Log("notif: 0 struct, so 0 cohesion question")
}
```

```
notif: 0 struct, so 0 cohesion question
```

C'est le résultat le plus net, et il n'était pas prévu : **le paquet du
squelette ne contient aucune structure.** Deux interfaces, un type de carte,
et des fonctions. Un paquet sans struct n'a pas de question de cohésion à se
poser — et c'est une conséquence directe du choix d'axe : le squelette ne
porte pas d'état parce que tout l'état est dans le catalogue et dans les
canaux.

```
channels   Email      1 field(s), 2 method(s), 1 component(s), isolated [Name]
channels   Mobile     1 field(s), 2 method(s), 1 component(s), isolated [Name]
channels   SMS        2 field(s), 2 method(s), 1 component(s), isolated [Name]
channels   payload    5 field(s), 0 method(s), 0 component(s), isolated []
catalog    Memory     1 field(s), 1 method(s), 1 component(s), isolated []
catalog    key        2 field(s), 0 method(s), 0 component(s), isolated []
model      Message    5 field(s), 1 method(s), 1 component(s), isolated []
model      Render     2 field(s), 0 method(s), 0 component(s), isolated []
```

Une composante par type, et `Name` isolée sur les trois canaux. C'est la
**troisième** lecture possible d'une méthode isolée, après les deux de
l'exercice 1 :

| Méthode isolée | Ce que ça veut dire | Ce qu'on en fait |
|---|---|---|
| `FormatReceipt` (ex. 1) | ne lit que son argument | une fonction |
| `Total` (ex. 1) | ne lit qu'un champ exclu | elle reste |
| **`Name`** (ici) | ne lit rien, et son résultat est une **constante du type** | elle reste : c'est une identité, pas un comportement |

> Le sondage dit « cette méthode ne touche aucun champ ». Il y a trois
> raisons possibles, et c'est au lecteur de trancher. L'outil pose la
> question ; il ne répond jamais.

Le sondage a d'ailleurs été **corrigé** pendant cet exercice : sa première
version laissait tomber les méthodes à récepteur anonyme — `func (SMS) Name()
string` — au lieu de les compter comme isolées. Le nombre de méthodes du
rapport était donc faux, et aucun test de la leçon ne le voyait, parce
qu'aucun de ses types n'avait de récepteur anonyme.

## 7. Le compilateur et toi

| Axe | Fichiers touchés | Erreurs de compilation | Tests rouges |
|---|---|---|---|
| **canal** (ouvert, code) | 1 neuf + 1 racine | **0** | 1 |
| **type de notification** (ouvert, donnée) | 1 (la table) | **0** | 1 |
| **langue** (ouvert, donnée) | 1 (la table) | **0** | 3, dont un qui nomme les 11 manquants |
| **méthode sur `Channel`** (fermé) | 3 implémentations | **3** | — rien ne compile |

Et la réponse à la question qui en découle :

> **Je travaille sans filet sur les trois premières lignes**, c'est-à-dire sur
> tout ce qui arrive souvent. Le compilateur ne m'aide que sur la quatrième,
> qui n'est jamais arrivée en dix-huit mois.

C'est l'inversion exacte de l'intuition. On croit que le compilateur protège
le travail quotidien ; il protège le travail rare. Ce qui protège le travail
quotidien, ici, ce sont trois tests : la liste des canaux, la liste des types,
et la complétude du catalogue.

> Sur un axe ouvert, **le test de la liste n'est pas une formalité : c'est le
> compilateur**. Il doit donc être traité comme tel — mis à jour
> volontairement, jamais « corrigé pour repasser au vert ».

### Les deux survivantes

**11 — le mobile met toujours la priorité normale.** Vrai manque. Les trois
canaux traduisent l'urgence, et c'était la seule traduction non testée — celle
qui décide si le téléphone sonne la nuit. Un test, trois cas.

**12 — `Markers` ne regarde que le sujet.** C'est la survivante
intéressante, et elle accuse un test.

```go
// TestMarkersReadsSubjectAndBody was born of a modification that survived.
//
// The test of consistency of the markers across languages compared two sets
// computed by the SAME function: when that function stopped reading the
// body, the two sets stayed equal — empty aside — and the test stayed
// green.
//
//    Two values computed by the same faulty function stay equal. Comparing
//    A and B does not check the function that produced A and B.
func TestMarkersReadsSubjectAndBody(t *testing.T) {
    g := model.Render{
        Subject: "Subject with {one}",
        Body:    "Body with {two} and {three}",
    }
    got := notif.Markers(g)
    if strings.Join(got, ",") != "one,three,two" {
        t.Fatalf("Markers = %v, want [one three two]", got)
    }
    // And the case that catches precisely the modification: a template whose
    // markers are ALL in the body.
    bodyOnly := notif.Markers(model.Render{Subject: "No marker", Body: "{a} {b}"})
    if strings.Join(bodyOnly, ",") != "a,b" {
        t.Fatalf("Markers = %v, want [a b]", bodyOnly)
    }
    t.Logf("subject + body: %v; body only: %v", got, bodyOnly)
}
```

Le test de cohérence des marqueurs entre langues comparait deux ensembles
calculés par **la même fonction**. Quand cette fonction a cessé de lire le
corps, les deux ensembles sont restés égaux — à vide près — et le test est
resté vert.

> Deux valeurs calculées par la même fonction fautive restent égales.
> Comparer A et B ne vérifie pas la fonction qui a produit A et B.

C'est la même famille de faute que « un test d'ordre s'observe depuis le point
intermédiaire » (correction 2.2) et que « le sondage ne qualifie plus par le
récepteur » (leçon 2.4) : un test qui passe par l'outil qu'il devrait
surveiller.

### Deuxième passe

```
16/16 modifications detectees
```

## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | L'axe à ouvrir se lit dans le relevé, pas dans la structure du problème. Ici : un type de notification toutes les sept semaines contre un canal tous les neuf mois. |
| ⚫ | **La chose qui change le plus souvent doit être une donnée, pas un type Go.** Mesuré : ajouter un type de notification coûte zéro ligne de code. |
| ⚫ | Ce que ça ferme se dit à l'avance : une notification ne peut pas avoir sa propre logique. |
| ⚫ | Deux axes ne se multiplient que si on en fait deux axes de **code**. Un de code et un de donnée s'additionnent. |
| ⚫ | Le canal décide de la **forme**, le gabarit du **texte**. Le canal mobile transmet les données du message : un gabarit ne peut pas faire ça, et c'est la mesure qui tranche. |
| ⚫ | Pas de repli sur la langue par défaut. Un repli qui marche ne produit aucune alerte, donc la langue manquante n'est jamais corrigée. |
| ⚫ | Un test qui nomme un cas « inconnu » doit choisir un nom qui **ne pourra jamais exister**. Sinon il mesure le calendrier. Deux fois la même faute dans le même fichier. |
| ⚫ | Sur les trois axes qui bougent, le compilateur donne **zéro erreur**. Il n'aide que sur l'axe qui n'a jamais bougé en dix-huit mois. |
| ⚫ | Sur un axe ouvert, le test de la liste **est** le compilateur. Il se met à jour volontairement, jamais pour repasser au vert. |
| ⚫ | Un paquet sans structure n'a pas de question de cohésion. C'est la forme la plus forte de la réponse à SRP, et ici c'est une conséquence du choix d'axe. |
| ⚫ | Une méthode isolée a trois lectures possibles : elle doit être une fonction, elle lit un champ exclu, ou son résultat est une constante du type. L'outil pose la question. |
| ⚫ | Deux valeurs calculées par la même fonction fautive restent égales. Comparer A et B ne vérifie pas la fonction qui les a produites. |
| ⚫ | Un marqueur sans donnée est une erreur, pas une chaîne vide : « virement de  FCFA » est pire qu'un message qui ne part pas. |
