# Correction 2.4 — Exercice 2 : les notifications de virements

> Rappel de l'énoncé : trois canaux, deux langues, et un relevé de dix-huit
> mois qui donne **2 canaux ajoutés, 1 langue, et 11 types de notification**.

Cinq paquets, verts sous `go vet ./...` et `go test -race -count=1 ./...`.
Campagne de seize modifications, 16/16 après deux passes.

## 1. L'axe, dicté par le relevé

| | Sur dix-huit mois | Un tous les… |
|---|---|---|
| canaux | 2 | 9 mois |
| langues | 1 | 18 mois |
| **types de notification** | **11** | **7 semaines** |

L'axe à ouvrir n'est pas celui qu'on ouvre d'habitude. La structure réflexe
devant « trois canaux » est une interface `Canal` avec un type de
notification par méthode, ou un type Go par notification. Les deux font du
**type de notification** un élément de code — et le relevé dit qu'il en arrive
un toutes les sept semaines.

> **Décision : un type de notification est une DONNÉE, pas un type Go.** Une
> clé et des champs nommés, rendus par un gabarit. Ce qui reste du code, c'est
> le canal — qui bouge une fois tous les neuf mois.

```go
// Message est un fait a notifier.
//
// Noter qu'il ne porte AUCUN texte. C'est tout le choix d'axe de l'exercice :
// un type de notification est une CLE et des donnees nommees, pas un type Go.
type Message struct {
    Cle       string
    Donnees   map[string]string
    Urgence   Urgence
    Instant   time.Time
    Reference string
}

// Champs rend les noms des donnees, tries.
//
// Il sert aux messages d'erreur du squelette : un gabarit qui reclame un
// champ absent doit pouvoir dire lesquels sont la.
func (m Message) Champs() []string {
    noms := make([]string, 0, len(m.Donnees))
    for n := range m.Donnees {
        noms = append(noms, n)
    }
    sort.Strings(noms)
    return noms
}
```

Et ce que ça ferme, explicitement : **une notification ne peut pas avoir sa
propre logique**. Pas de calcul, pas de condition, pas de mise en forme
particulière. Si un jour « plafond atteint » doit afficher un graphique, il
faudra ou bien un canal qui sait le faire pour tous, ou bien rouvrir le
choix. C'est le prix, et il est connu d'avance.

### Les deux interfaces

```go
// Canal est l'axe FERME de l'exercice : deux methodes, trois
// implementations, et le relevé dit que c'en est un tous les neuf mois.
type Canal interface {
    Nom() string
    Formater(r modele.Rendu, m modele.Message) (string, error)
}

// Catalogue rend le gabarit d'une cle dans une langue.
//
// C'est par lui que passe l'axe OUVERT : ajouter un type de notification est
// une entree de plus dans le catalogue, et zero ligne de code.
type Catalogue interface {
    Modele(cle string, l modele.Langue) (modele.Rendu, error)
}
```

### Le squelette

```go
// champ reconnait un marqueur de la forme {nom}.
var champ = regexp.MustCompile(`\{([a-z_]+)\}`)

// Envoyer rend le message pret a partir.
//
// Quatre etapes, et aucune ne connait un type de notification en
// particulier : c'est ce qui rend l'ajout d'un type gratuit en code.
func Envoyer(reg Registre, cat Catalogue, canal string,
    l modele.Langue, m modele.Message) (string, error) {
    if cat == nil {
        return "", ErrCatalogueAbsent
    }
    c, err := reg.Pour(canal)
    if err != nil {
        return "", err
    }
    gabarit, err := cat.Modele(m.Cle, l)
    if err != nil {
        return "", err
    }
    rempli, err := remplir(gabarit, m)
    if err != nil {
        return "", fmt.Errorf("%w (canal %s, langue %s)", err, c.Nom(), l)
    }
    return c.Formater(rempli, m)
}
```

```go
// remplir substitue les marqueurs du gabarit par les donnees du message.
//
// Un marqueur sans donnee est une ERREUR, pas une chaine vide. Un message
// qui annonce « virement de  FCFA » est pire qu'un message qui ne part pas.
func remplir(g modele.Rendu, m modele.Message) (modele.Rendu, error) {
    var manquant error
    substituer := func(s string) string {
        return champ.ReplaceAllStringFunc(s, func(marqueur string) string {
            nom := marqueur[1 : len(marqueur)-1]
            v, connu := m.Donnees[nom]
            if !connu {
                if manquant == nil {
                    manquant = fmt.Errorf("%w : %q pour la cle %q (presents : %v)",
                        ErrChampAbsent, nom, m.Cle, m.Champs())
                }
                return marqueur
            }
            return v
        })
    }
    rempli := modele.Rendu{Sujet: substituer(g.Sujet), Corps: substituer(g.Corps)}
    if manquant != nil {
        return modele.Rendu{}, manquant
    }
    return rempli, nil
}
```

Quatre étapes, et **aucune ne connaît un type de notification en
particulier**. C'est ça qui rend l'ajout d'un type gratuit en code.

Un marqueur sans donnée est une **erreur**, pas une chaîne vide : un message
qui annonce « virement de  FCFA » est pire qu'un message qui ne part pas. La
campagne a une modification là-dessus, et elle tombe.

### Ce que la mesure a cassé, et qu'elle ne devait pas casser

À la première exécution, **deux** tests sont tombés au lieu d'un :

```
--- FAIL: TestLesCanauxConnus
--- FAIL: TestUnCanalInconnuEstUneErreur
```

Le second affirmait qu'un canal nommé `"whatsapp"` était inconnu. Il l'était
— jusqu'à ce que la mesure l'ajoute.

```go
// TestUnCanalInconnuEstUneErreur : pas de canal par defaut.
//
// Le nom du canal inconnu etait « whatsapp » dans la premiere version de ce
// test. La mesure de l'axe l'a fait tomber : whatsapp a ete ajoute, et le
// test qui affirmait qu'il etait inconnu est devenu faux.
//
//    Un test qui nomme un cas « inconnu » doit choisir un nom qui ne pourra
//    jamais exister. Sinon il mesure le calendrier.
func TestUnCanalInconnuEstUneErreur(t *testing.T) {
    _, err := notif.Envoyer(montage.Canaux(), montage.Catalogue(),
        "pigeon-voyageur", modele.FR, message())
    if !errors.Is(err, notif.ErrCanalInconnu) {
        t.Fatalf("err = %v, attendu ErrCanalInconnu", err)
    }
    t.Logf("%v", err)
}
```

Le même défaut existait sur les langues, avec `modele.EWO`, et la mesure de
l'axe des langues l'a fait tomber aussi. Deux fois la même faute, dans le même
fichier.

> Un test qui nomme un cas « inconnu » ou « absent » doit choisir un nom qui
> **ne pourra jamais exister**. Sinon il ne mesure pas une propriété, il
> mesure le calendrier.

Le code ISO 639-1 `zz` est réservé à l'usage privé et ne sera jamais attribué
à une langue : c'est ce qui en fait un bon nom de cas absent.

### Ajouter une méthode à `Canal`

Une méthode `CoutUnitaireFCFA() int` sur l'interface. Une ligne.

```
ex2/montage/montage.go:16:15: cannot use canaux.SMS{…} ... does not implement
  notif.Canal (missing method CoutUnitaireFCFA)
ex2/montage/montage.go:17:15: ... canaux.Courriel ... (missing method CoutUnitaireFCFA)
ex2/montage/montage.go:18:15: ... canaux.Mobile ... (missing method CoutUnitaireFCFA)

erreurs de compilation : 3
```

### Les deux mesures ne sont pas les mêmes, et voilà pourquoi

| | Ajouter un **type de notification** | Ajouter une **méthode à `Canal`** |
|---|---|---|
| ce que c'est | une donnée de plus dans une table | une **opération** de plus sur l'axe fermé |
| coût | 2 entrées, 0 ligne de code | 3 implémentations, dont une dans un autre dépôt le jour où il y en a un |
| le compilateur | muet | **3 erreurs, toutes au bon endroit** |

Les deux sont des « ajouts », et ils n'ont rien à voir. Le premier est un
ajout **sur l'axe ouvert** : il est gratuit, et il est invisible pour le
compilateur. Le second est un ajout **sur l'axe fermé** : il coûte N, et le
compilateur te tient la main.

## 4. La langue n'est pas sur le même axe que le canal

Non, et c'est le cœur de l'exercice.

| | Canal | Langue |
|---|---|---|
| ce qu'il décide | la **forme** : que garder, que jeter, quel format de charge | le **texte** |
| ce que c'est | du **code** | une **donnée** |
| coût d'un ajout | 1 fichier + 1 ligne | **1 entrée par type de notification** |

```go
// TestLeCatalogueEstComplet : chaque type existe dans chaque langue.
//
// Sans ce test, ajouter une langue a un seul type passe au vert, et le

func TestLeCatalogueEstComplet(t *testing.T) {
    cat := montage.Catalogue()
    manquants := 0
    for _, c := range catalogue.Cles() {
        for _, l := range catalogue.Langues() {
            if _, err := cat.Modele(c, l); err != nil {

            len(catalogue.Cles())*len(catalogue.Langues()))
    }

```

### Et si les deux axes étaient du code ?

Trois canaux fois quatre langues, chacun un type Go : **douze types**, et
treize avec un canal de plus, seize avec une langue de plus. C'est la
multiplication, et c'est ce qu'il faut refuser.

> Deux axes ne se multiplient que si on en fait **deux axes de code**. En
> faire un de code et un de donnée les additionne : 3 canaux + 24 gabarits,
> et le second nombre ne demande pas de relecture.

Ce qui rend la séparation possible est que **le canal décide de la forme et
le gabarit du texte**, et qu'aucun des deux n'a besoin de l'autre :

```go
// TestLeCanalDecideDeCeQuIlGarde : le SMS jette le sujet, le mobile garde
// les donnees. Un gabarit ne peut faire ni l'un ni l'autre.
func TestLeCanalDecideDeCeQuIlGarde(t *testing.T) {
    reg, cat := montage.Canaux(), montage.Catalogue()
    sms, err := notif.Envoyer(reg, cat, "sms", modele.FR, message())
    if err != nil {
        t.Fatal(err)
    }
    if strings.Contains(sms, "Virement recu de") {
        t.Error("le SMS a garde le sujet")
    }
    mobile, err := notif.Envoyer(reg, cat, "mobile", modele.FR, message())
    if err != nil {
        t.Fatal(err)
    }
    if !strings.Contains(mobile, `"emetteur":"SARL BETA"`) {
        t.Errorf("le mobile n'a pas transmis les donnees :\n%s", mobile)
    }
    t.Log("le SMS jette le sujet, le mobile transmet les donnees :" +
        " deux decisions qu'un gabarit ne peut pas prendre")
}
```

```
le SMS jette le sujet, le mobile transmet les donnees : deux decisions qu'un
gabarit ne peut pas prendre
```

```go
// charge est la charge utile JSON d'une notification poussee.
type charge struct {
    Application string            `json:"application,omitempty"`
    Titre       string            `json:"titre"`
    Corps       string            `json:"corps"`
    Priorite    string            `json:"priorite"`
    Donnees     map[string]string `json:"donnees,omitempty"`
}

// Formater rend la charge JSON.
//
// C'est le seul des trois canaux qui transmette les DONNEES du message en
// plus du texte : l'application mobile en a besoin pour ouvrir le bon ecran.
// Un gabarit ne pourrait pas faire ca, et c'est le deuxieme argument pour que
// le canal soit du code.
func (mo Mobile) Formater(r modele.Rendu, m modele.Message) (string, error) {
    if strings.TrimSpace(r.Corps) == "" {
        return "", ErrCorpsVide
    }
    priorite := "normale"
    if m.Urgence == modele.Critique {
        priorite = "haute"
    }
    brut, err := json.Marshal(charge{
        Application: mo.Application,
        Titre:       r.Sujet,
        Corps:       r.Corps,
        Priorite:    priorite,
        Donnees:     m.Donnees,
    })
    if err != nil {
        return "", err
    }
    return string(brut), nil
}
```

Le canal mobile transmet les **données** du message en plus du texte, parce
que l'application en a besoin pour ouvrir le bon écran. Un gabarit ne peut pas
faire ça. C'est le second argument pour que le canal reste du code, et c'est
une mesure, pas une opinion.

### L'invariant que personne n'écrit

```go
// TestLesMarqueursSontLesMemesDansToutesLesLangues est l'invariant que
// personne n'ecrit et qui casse en production.
//
// Si le gabarit francais reclame {solde} et l'anglais ne le reclame pas, le
// producteur du message n'a aucun moyen de savoir qu'il doit l'envoyer : il
// teste en francais, ca marche, et le client anglophone recoit une erreur.
func TestLesMarqueursSontLesMemesDansToutesLesLangues(t *testing.T) {
    cat := montage.Catalogue()
    for _, c := range catalogue.Cles() {
        var reference []string
        for _, l := range catalogue.Langues() {
            g, err := cat.Modele(c, l)
            if err != nil {
                t.Fatalf("%s / %s : %v", c, l, err)
            }
            marqueurs := notif.Marqueurs(g)
            if reference == nil {
                reference = marqueurs
                continue
            }
            if strings.Join(marqueurs, ",") != strings.Join(reference, ",") {
                t.Errorf("%s : %s reclame %v, la premiere langue reclame %v",
                    c, l, marqueurs, reference)
            }
        }
    }
}
```

Si le gabarit français réclame `{solde}` et l'anglais ne le réclame pas, le
producteur du message n'a **aucun moyen** de savoir qu'il doit l'envoyer : il
teste en français, ça marche, et le client anglophone reçoit une erreur. C'est
la panne la plus probable de ce modèle, et elle coûte une boucle de vingt
lignes.

## 5. Un canal inconnu est une erreur

En une phrase, avec la correction 2.3/5 : **un repli silencieux coûte onze
jours de détection, parce que rien ne distingue un repli qui marche d'un code
qui marche** — là-bas 214 000 réponses fausses derrière un tableau de bord
vert ; ici un client qui a demandé un SMS et reçoit un courriel.

```
notif : canal inconnu : "pigeon-voyageur" (connus : [courriel mobile sms])
```

Et la même décision pour la langue, qui est moins évidente :

```
notif : gabarit absent : cle "virement.recu", langue "zz"
un client anglophone qui recoit un message en francais est un incident
silencieux, et le silence coute onze jours
```

**Pas de repli sur le français.** C'est contre-intuitif — un message en
français vaut mieux que pas de message — et c'est faux pour une raison
mesurable : un repli qui marche ne produit aucune alerte, donc la langue
manquante n'est jamais corrigée. Le refus, lui, remonte dans le taux d'erreur
du jour même.

## 6. Le sondage de cohésion

```go
// TestLeSqueletteNAAucunStruct est le resultat le plus net du sondage, et il
// n'etait pas prevu.
//
// Le paquet notif ne contient AUCUNE structure : deux interfaces, un type de
// carte, et des fonctions. Un paquet sans struct n'a pas de question de
// cohesion a se poser — c'est la forme la plus forte de la reponse a la
// question 6, et c'est une consequence directe du choix d'axe : le squelette
// ne porte pas d'etat parce que tout l'etat est dans le catalogue et dans les
// canaux.
func TestLeSqueletteNAAucunStruct(t *testing.T) {
    chemin, err := filepath.Abs(filepath.Join("..", "notif"))
    if err != nil {
        t.Fatalf("chemin : %v", err)
    }
    rapports, err := sondage.Analyser(chemin, nil)
    if err != nil {
        t.Fatalf("Analyser : %v", err)
    }
    if len(rapports) != 0 {
        for nom := range rapports {
            t.Errorf("le paquet notif contient la structure %s", nom)
        }
    }
    t.Log("notif : 0 structure, donc 0 question de cohesion")
}
```

```
notif : 0 structure, donc 0 question de cohesion
```

C'est le résultat le plus net, et il n'était pas prévu : **le paquet du
squelette ne contient aucune structure.** Deux interfaces, un type de carte,
et des fonctions. Un paquet sans struct n'a pas de question de cohésion à se
poser — et c'est une conséquence directe du choix d'axe : le squelette ne
porte pas d'état parce que tout l'état est dans le catalogue et dans les
canaux.

```
canaux     Courriel   1 champ(s), 2 methode(s), 1 composante(s), isolees [Nom]
canaux     Mobile     1 champ(s), 2 methode(s), 1 composante(s), isolees [Nom]
canaux     SMS        2 champ(s), 2 methode(s), 1 composante(s), isolees [Nom]
canaux     charge     5 champ(s), 0 methode(s), 0 composante(s), isolees []
catalogue  Memoire    1 champ(s), 1 methode(s), 1 composante(s), isolees []
catalogue  cle        2 champ(s), 0 methode(s), 0 composante(s), isolees []
modele     Message    5 champ(s), 1 methode(s), 1 composante(s), isolees []
modele     Rendu      2 champ(s), 0 methode(s), 0 composante(s), isolees []
```

Une composante par type, et `Nom` isolée sur les trois canaux. C'est la
**troisième** lecture possible d'une méthode isolée, après les deux de
l'exercice 1 :

| Méthode isolée | Ce que ça veut dire | Ce qu'on en fait |
|---|---|---|
| `FormaterRecu` (ex. 1) | ne lit que son argument | une fonction |
| `Total` (ex. 1) | ne lit qu'un champ exclu | elle reste |
| **`Nom`** (ici) | ne lit rien, et son résultat est une **constante du type** | elle reste : c'est une identité, pas un comportement |

> Le sondage dit « cette méthode ne touche aucun champ ». Il y a trois
> raisons possibles, et c'est au lecteur de trancher. L'outil pose la
> question ; il ne répond jamais.

Le sondage a d'ailleurs été **corrigé** pendant cet exercice : sa première
version laissait tomber les méthodes à récepteur anonyme — `func (SMS) Nom()
string` — au lieu de les compter comme isolées. Le nombre de méthodes du
rapport était donc faux, et aucun test de la leçon ne le voyait, parce
qu'aucun de ses types n'avait de récepteur anonyme.

## 7. Le compilateur et toi

| Axe | Fichiers touchés | Erreurs de compilation | Tests rouges |
|---|---|---|---|
| **canal** (ouvert, code) | 1 neuf + 1 racine | **0** | 1 |
| **type de notification** (ouvert, donnée) | 1 (la table) | **0** | 1 |
| **langue** (ouvert, donnée) | 1 (la table) | **0** | 2, dont un qui nomme les 11 manquants |
| **méthode sur `Canal`** (fermé) | 3 implémentations | **3** | — rien ne compile |

Et la réponse à la question qui en découle :

> **Je travaille sans filet sur les trois premières lignes**, c'est-à-dire sur
> tout ce qui arrive souvent. Le compilateur ne m'aide que sur la quatrième,
> qui n'est jamais arrivée en dix-huit mois.

C'est l'inversion exacte de l'intuition. On croit que le compilateur protège
le travail quotidien ; il protège le travail rare. Ce qui protège le travail
quotidien, ici, ce sont trois tests : la liste des canaux, la liste des types,
et la complétude du catalogue.

> Sur un axe ouvert, **le test de la liste n'est pas une formalité : c'est le
> compilateur**. Il doit donc être traité comme tel — mis à jour
> volontairement, jamais « corrigé pour repasser au vert ».

### Les deux survivantes

**11 — le mobile met toujours la priorité normale.** Vrai manque. Les trois
canaux traduisent l'urgence, et c'était la seule traduction non testée — celle
qui décide si le téléphone sonne la nuit. Un test, trois cas.

**12 — `Marqueurs` ne regarde que le sujet.** C'est la survivante
intéressante, et elle accuse un test.

```go
// TestMarqueursLitLeSujetEtLeCorps est ne d'une modification qui a survecu.
//
// Le test de coherence des marqueurs entre langues comparait deux ensembles
// calcules par la MEME fonction : quand cette fonction a cesse de lire le
// corps, les deux ensembles sont restes egaux — a vide pres — et le test est
// reste vert.
//
//    Deux valeurs calculees par la meme fonction fautive restent egales.
//    Comparer A et B ne verifie pas la fonction qui a produit A et B.
func TestMarqueursLitLeSujetEtLeCorps(t *testing.T) {
    g := modele.Rendu{
        Sujet: "Sujet avec {un}",
        Corps: "Corps avec {deux} et {trois}",
    }
    got := notif.Marqueurs(g)
    if strings.Join(got, ",") != "deux,trois,un" {
        t.Fatalf("Marqueurs = %v, attendu [deux trois un]", got)
    }
    // Et le cas qui attrape precisement la modification : un gabarit dont
    // TOUS les marqueurs sont dans le corps.
    corpsSeul := notif.Marqueurs(modele.Rendu{Sujet: "Sans marqueur", Corps: "{a} {b}"})
    if strings.Join(corpsSeul, ",") != "a,b" {
        t.Fatalf("Marqueurs = %v, attendu [a b]", corpsSeul)
    }
    t.Logf("sujet + corps : %v ; corps seul : %v", got, corpsSeul)
}
```

Le test de cohérence des marqueurs entre langues comparait deux ensembles
calculés par **la même fonction**. Quand cette fonction a cessé de lire le
corps, les deux ensembles sont restés égaux — à vide près — et le test est
resté vert.

> Deux valeurs calculées par la même fonction fautive restent égales.
> Comparer A et B ne vérifie pas la fonction qui a produit A et B.

C'est la même famille de faute que « un test d'ordre s'observe depuis le point
intermédiaire » (correction 2.2) et que « le sondage ne qualifie plus par le
récepteur » (leçon 2.4) : un test qui passe par l'outil qu'il devrait
surveiller.

## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | L'axe à ouvrir se lit dans le relevé, pas dans la structure du problème. Ici : un type de notification toutes les sept semaines contre un canal tous les neuf mois. |
| ⚫ | **La chose qui change le plus souvent doit être une donnée, pas un type Go.** Mesuré : ajouter un type de notification coûte zéro ligne de code. |
| ⚫ | Ce que ça ferme se dit à l'avance : une notification ne peut pas avoir sa propre logique. |
| ⚫ | Deux axes ne se multiplient que si on en fait deux axes de **code**. Un de code et un de donnée s'additionnent. |
| ⚫ | Le canal décide de la **forme**, le gabarit du **texte**. Le canal mobile transmet les données du message : un gabarit ne peut pas faire ça, et c'est la mesure qui tranche. |
| ⚫ | Pas de repli sur la langue par défaut. Un repli qui marche ne produit aucune alerte, donc la langue manquante n'est jamais corrigée. |
| ⚫ | Un test qui nomme un cas « inconnu » doit choisir un nom qui **ne pourra jamais exister**. Sinon il mesure le calendrier. Deux fois la même faute dans le même fichier. |
| ⚫ | Sur les trois axes qui bougent, le compilateur donne **zéro erreur**. Il n'aide que sur l'axe qui n'a jamais bougé en dix-huit mois. |
| ⚫ | Sur un axe ouvert, le test de la liste **est** le compilateur. Il se met à jour volontairement, jamais pour repasser au vert. |
| ⚫ | Un paquet sans structure n'a pas de question de cohésion. C'est la forme la plus forte de la réponse à SRP, et ici c'est une conséquence du choix d'axe. |
| ⚫ | Une méthode isolée a trois lectures possibles : elle doit être une fonction, elle lit un champ exclu, ou son résultat est une constante du type. L'outil pose la question. |
| ⚫ | Deux valeurs calculées par la même fonction fautive restent égales. Comparer A et B ne vérifie pas la fonction qui les a produites. |
| ⚫ | Un marqueur sans donnée est une erreur, pas une chaîne vide : « virement de  FCFA » est pire qu'un message qui ne part pas. |
