# Correction 2.6 — Exercice 3 : effondrer le service de plafonds

> Rappel de l'énoncé : le plafond d'une carte, lire et modifier en HTTP, avec
> une règle de bornes — écrit en six paquets : contrôleur, service, dépôt,
> correspondance, DTO, entité, et une interface devant chacun des trois
> premiers.

Deux instantanés, `before` et `after`, verts sous `go vet ./...` et
`go test -race -count=1 ./...`. Campagne de huit modifications, 8/8 après
deux passes.

## 1. Le relevé, et l'interface qu'il oublie

Trois interfaces, une implémentation chacune, aucune doublure :
`Mapper`, `CardLimitStore`, `CardLimitService`. Le sondage en oublie une
quatrième : **`CardLimitController`**, qui ne déclare aucune méthode — elle
incorpore `http.Handler`. Le sondage ne lit que les méthodes **nommées** dans
le corps de l'interface ; une interface faite seulement d'incorporations lui
paraît vide, et il l'écarte :

```go
    for key, i := range interfaces {
        ms := interfaceMethods[key]
        if len(ms) == 0 {
            continue
        }
```

C'est la limite que son commentaire annonce, et c'est aussi la plus inutile
des quatre : une interface qui rebaptise `http.Handler` sans rien y ajouter.

## 2. La co-variation, mesurée

Une date d'expiration, exposée en JSON et stockée. Une sonde fait un `PUT`
avec une expiration, puis un `GET`, et affiche ce qu'elle relit :

```
== before : compiles True, tests RED, files: dto/dto.go, entity/entity.go, mapping/mapping.go
   expiration read back: 2026-12-31T00:00:00Z
== before, mapping forgotten : compiles True, tests RED, files: dto/dto.go, entity/entity.go
   expiration read back: 0001-01-01T00:00:00Z
== after : compiles True, tests RED, files: cardlimit/cardlimit.go
   expiration read back: 2026-12-31T00:00:00Z
```

- **Trois fichiers** dans la version en couches : l'entité, le DTO, la
  correspondance.
- **La correspondance oubliée compile**, et l'expiration est perdue :
  la sonde relit `0001-01-01`, la date zéro de Go.
- **Les tests sont rouges dans les trois cas, et ce n'est pas eux qui voient
  la perte.** Le test existant compare le JSON exact
  `{"card":"4970","amount":200000}` ; le nouveau champ change cette forme,
  dans les trois versions. Il est rouge pour la même raison quand la donnée
  est perdue et quand elle ne l'est pas. Seule la sonde distingue.

## 3. Effondrer

Un paquet, `cardlimit` : la donnée, sa règle, son stockage, son gestionnaire
HTTP.

```go
// Package cardlimit is a card's spending limit: the data, its rule, its
// storage and its HTTP handler. A single actor — the cards business — asks
// for its changes.
package cardlimit

import (
    "encoding/json"
    "errors"
    "net/http"
    "sync"
)

var (
    ErrUnknown     = errors.New("cardlimit: unknown card")
    ErrOutOfBounds = errors.New("cardlimit: out of bounds")
)

// CardLimit is the data, as it is stored and exposed.
type CardLimit struct {
    Card   string `json:"card"`
    Amount int64  `json:"amount"`
}

// Validate applies the rule: between 100 and 500,000 EUR.
func (l CardLimit) Validate() error {
    if l.Amount < 10_000 || l.Amount > 50_000_000 {
        return ErrOutOfBounds
    }
    return nil
}

// Book stores the limits.
type Book struct {
    mu sync.Mutex
    m  map[string]CardLimit
}

func NewBook() *Book { return &Book{m: map[string]CardLimit{}} }

func (b *Book) Read(card string) (CardLimit, error) {
    b.mu.Lock()
    defer b.mu.Unlock()
    l, ok := b.m[card]
    if !ok {
        return l, ErrUnknown
    }
    return l, nil
}

// Update validates, then stores.
func (b *Book) Update(l CardLimit) error {
    if err := l.Validate(); err != nil {
        return err
    }
    b.mu.Lock()
    defer b.mu.Unlock()
    b.m[l.Card] = l
    return nil
}
```

**168 lignes de production en six paquets deviennent 85 en un.** Le test du
contrôleur passe, et ce qui change dans son fichier se compte :

```
1c1

---
> package cardlimit
9,12d8
<
<     "example/c26/ex3/before/mapping"
<     "example/c26/ex3/before/service"
<     "example/c26/ex3/before/store"

<     mux.Handle("/cards/{card}/limit", NewCardLimitController(
<         service.NewCardLimitService(store.NewCardLimitStore(), mapping.NewMapper())))
---
>     mux.Handle("/cards/{card}/limit", NewBook())
```

L'énoncé disait « au chemin d'import près » ; c'est au chemin d'import **et à
la ligne de construction** près — deux lignes qui en deviennent une. Toutes
les assertions HTTP sont inchangées.

## 4. La même mesure, effondrée

La troisième ligne du relevé de la question 2 : **un fichier**, et
l'expiration relue. Il n'y a plus de correspondance à oublier : la structure
qu'on décode du JSON est celle qu'on range.

| | en couches | effondrée |
|---|---|---|
| fichiers touchés pour un champ | 3 | **1** |
| endroits où l'oubli compile et perd la donnée | 2 — les deux sens de la correspondance | **0** |

## 5. Ce qui doit rester séparé — et quand

Aujourd'hui, rien : le stockage est une carte en mémoire, dans le même paquet
que la règle, et il n'a qu'un acteur.

**Le jour où le stockage passe sur PostgreSQL**, le paquet `cardlimit`
importerait `database/sql`, et tout ce qui l'importe — la règle comprise —
tirerait la base dans ses dépendances. C'est le jour de la coupe de la leçon
2.5 : une interface `Storage` de deux méthodes, **déclarée dans `cardlimit`**,
chez celui qui l'appelle ; l'implémentation PostgreSQL dans son propre paquet,
qui importe `cardlimit` pour le type `CardLimit`.

Ce que je mesure pour savoir que c'est le jour : un test d'architecture qui
interdit `database/sql` à `cardlimit`. Il est vert aujourd'hui ; il deviendra
rouge **à l'instant précis** où quelqu'un écrira le stockage SQL dans le
paquet — et c'est lui qui dira de couper, pas un pressentiment.

## 6. `Version`

Le champ est **écrit** à chaque modification et **lu** une seule fois, pour
s'incrémenter lui-même :

```
store/store.go:38:    l.Version = s.m[l.Card].Version + 1
```

Aucun autre usage, ni en lecture ni en JSON. Je le **supprime** — la version
effondrée ne l'a pas. Lui donner un usage, ce serait la concurrence
optimiste : un `ETag` rendu au `GET`, exigé par `If-Match` au `PUT`, pour
qu'une modification ne remplace pas en silence une autre faite entre-temps.
C'est une vraie fonctionnalité ; elle se décide si quelqu'un l'a demandée,
pas parce qu'un champ traîne.

## 7. « L'architecture standard de l'entreprise »

L'argument est réel : un développeur qui change de service retrouve ses
repères. Chiffré sur ce service, ce que rapporte et ce que coûte le standard :

| | |
|---|---|
| lignes de production | 168 au lieu de 85 — **le double** |
| fichiers touchés par un champ ajouté | 3 au lieu de 1 |
| endroits où un oubli compile et perd une donnée | 2 au lieu de 0 |
| ce que le standard rapporte | des noms de paquets familiers |

Ce que je propose à l'échelle de l'entreprise : **standardiser les frontières,
pas les couches**. Un standard qui dit « un paquet par fonctionnalité ; une
interface seulement là où il y a deux choses derrière ou une frontière à
garder ; et ce test d'architecture-ci, qui interdit l'infrastructure au
métier » donne les mêmes repères — on sait où chercher la règle, où est la
base — sans faire payer à chaque service la forme du plus gros. Et il se
**vérifie** : un test d'architecture standard est un standard qui tient tout
seul, là où une arborescence standard ne tient que par la revue.

« GET : plus de 404 » ne compilait pas — la variable d'erreur devenait
inutilisée — et a été rejouée sous la forme `if false && …`. Les quatre
survivants disent la même chose : **le test reçu avec le code ne regardait
aucun bord**. Ni les bornes exactes, ni un corps illisible, ni une carte
inconnue. C'était vrai dans la version en couches aussi : le test est le même.
Un test de plus, sans toucher au premier :

```go
// TestEdgesAndErrors: the exact bounds, an unreadable body, an unknown card.
// The original test looked at none of the four.
func TestEdgesAndErrors(t *testing.T) {
    mux := http.NewServeMux()
    mux.Handle("/cards/{card}/limit", NewBook())
    srv := httptest.NewServer(mux)
    defer srv.Close()
    put := func(body string) int {
        req, _ := http.NewRequest(http.MethodPut, srv.URL+"/cards/4970/limit", strings.NewReader(body))
        r, err := http.DefaultClient.Do(req)
        if err != nil {
            t.Fatal(err)
        }
        return r.StatusCode
    }
    for body, want := range map[string]int{
        `{"amount":9999}`:     http.StatusUnprocessableEntity,
        `{"amount":10000}`:    http.StatusNoContent,
        `{"amount":50000000}`: http.StatusNoContent,
        `{"amount":50000001}`: http.StatusUnprocessableEntity,
        `{"amount":`:          http.StatusBadRequest,
    } {
        if got := put(body); got != want {
            t.Errorf("%s: %d, want %d", body, got, want)
        }
    }
    if r, _ := http.Get(srv.URL + "/cards/0000/limit"); r.StatusCode != http.StatusNotFound {
        t.Errorf("unknown card: %d", r.StatusCode)
    }
}
```

## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | Le sondage ne voit pas une interface faite seulement d'incorporations — et celle-ci ne faisait que rebaptiser `http.Handler`. |
| ⚫ | Un champ ajouté : trois fichiers en couches, un effondré. L'oubli de la correspondance compile et perd la donnée. |
| ⚫ | Un test rouge n'est pas un test qui voit. Ici, il était rouge pour la forme du JSON, dans les trois versions ; seule une sonde voyait la perte. |
| ⚫ | 168 lignes en six paquets deviennent 85 en un ; le test change d'une ligne de construction. |
| ⚫ | La séparation se fait le jour où la frontière existe — la première importation de `database/sql` — et c'est un test d'architecture qui le dit. |
| ⚫ | Un champ écrit et jamais lu se supprime ; lui donner un usage est une fonctionnalité, qui se décide pour elle-même. |
