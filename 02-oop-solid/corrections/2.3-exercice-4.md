## 1. Le mécanisme, par la question des trois

L'héritage accorde trois choses d'un coup : la **réutilisation** de code, le
**sous-typage**, et la **spécialisation ouverte**. Ce dont l'exercice a
besoin, préoccupation par préoccupation :

| | Réutilisation | Sous-typage | Spécialisation ouverte |
|---|---|---|---|
| les six préoccupations | non — elles ne partagent aucun code | **oui** — elles doivent être interchangeables dans une liste | non |

Une seule des trois. Donc : **une interface**, et rien d'autre. Pas de type de
base, pas de `PreoccupationAbstraite`.

### Est-ce que l'incorporation a un rôle ici ?

Oui, exactement un, et il n'a rien à voir avec les six préoccupations
elles-mêmes : il concerne les **enveloppes de `http.ResponseWriter`** dont la
journalisation et la compression ont besoin.

```go
// Recorder records the status written to the response.
// It EMBEDS http.ResponseWriter, and it is the most
// justified use of the course: the interface has three methods, we redefine one, and
// we delegate the other two without writing them.
//
// The trap is known and it is measured in the tests: the Recorder exposes
// ONLY the three methods of ResponseWriter. An http.Flusher or an
// http.Hijacker underneath becomes invisible, and a server event
// stream stops working without an error message.
type Recorder struct {
    http.ResponseWriter
    Status  int
    Bytes   int
    written bool
}

// WriteHeader keeps the status and passes it on.
func (c *Recorder) WriteHeader(status int) {
    if c.written {
        return
    }
    c.Status = status
    c.written = true
    c.ResponseWriter.WriteHeader(status)
}

// Write counts the bytes and forces a status if nobody wrote one.
func (c *Recorder) Write(p []byte) (int, error) {
    if !c.written {
        c.WriteHeader(http.StatusOK)
    }
    n, err := c.ResponseWriter.Write(p)
    c.Bytes += n
    return n, err
}
```

C'est l'incorporation dans son emploi légitime, et le seul du cours : une
interface à trois méthodes, on en redéfinit une ou deux, et on délègue les
autres **sans les écrire**. `Recorder` redéfinit `WriteHeader` et `Write` ;
`Header` est promue telle quelle.

Et elle coûte quelque chose, mesuré :

```go
// TestTheRecorderHidesTheFlusher measures the price of embedding an
// interface, and it is the only place in the course where embedding is the right
// choice while costing something.
func TestTheRecorderHidesTheFlusher(t *testing.T) {
    rec := httptest.NewRecorder()
    if _, ok := any(rec).(http.Flusher); !ok {
        t.Skip("the test recorder is not a Flusher: the measure does not" +
            " does not apply on this Go version")
    }
    c := &concerns.Recorder{ResponseWriter: rec}
    if _, ok := any(c).(http.Flusher); ok {
        t.Fatal("the Recorder exposes Flush: embedding an interface" +
            " promotes only the methods of this interface, the measure changed")
    }
    t.Log("the underlying ResponseWriter is an http.Flusher, the Recorder" +
        " is no longer: a server event stream stops working without" +
        " no message")
}
```

```
the underlying ResponseWriter is an http.Flusher, the Recorder l'est plus :
un flux d'evenements serveur cesse de functionner sans no message
```

> Incorporer une interface ne promeut **que** les méthodes de cette
> interface. Tout ce que la valeur sous-jacente savait faire en plus
> disparaît, silencieusement, et un `http.Flusher` perdu casse les flux
> d'événements serveur sans aucune erreur.

C'est le prix à connaître avant de choisir cette incorporation, pas après. La
parade, quand on en a besoin, est d'écrire les délégations à la main ou de
déclarer `Flush()` sur le capteur.

## 2. L'interface

```go
// Handler is what serves a request.
// Note the signature: the trace is a PARAMETER, not a context
// value. So a handler cannot be called without a trace
// being named at the call site, and it is half the guarantee asked for in
// question 8.
type Handler interface {
    Serve(w http.ResponseWriter, r *http.Request, t Trace)
}

// HandlerFunc adapts a function into a Handler.
type HandlerFunc func(w http.ResponseWriter, r *http.Request, t Trace)

// Serve calls f.
func (f HandlerFunc) Serve(w http.ResponseWriter, r *http.Request, t Trace) {
    f(w, r, t)
}

// Concern is the interface of the six cross-cutting concerns.
//
// TWO methods, and the second must be justified. Handle would be enough for
// behavior: it is the usual shape of a middleware in Go. Name
// serves no purpose at run time: it serves so that the chain can DESCRIBE itself,
// and question 8 asks for a guarantee on the order and presence of the
// concerns. A guarantee on a list of anonymous functions
// is not written.
type Concern interface {
    Name() string
    Handle(next Handler) Handler
}
```

**Deux méthodes**, et la seconde demande une justification.

`Handle` suffirait au comportement : la forme habituelle d'un intergiciel en
Go est `func(http.Handler) http.Handler`, sans interface du tout. `Name` ne
sert à rien à l'exécution. Elle sert à ce que la chaîne puisse **se décrire**,
et la question 8 demande une garantie sur la présence et l'ordre des
préoccupations.

> Une garantie sur une liste de fonctions anonymes ne s'écrit pas. C'est
> `Name()` qui transforme « il faut relire l'ordre » en « il y a un test sur
> l'ordre ».

### Où elle est déclarée, et la preuve

Elle est dans `web`, pas dans `chain`. C'est la leçon de l'exercice 2 :
l'interface nomme `Handler` et `Trace`, qui ne sont pas des types
universels, donc ils descendent dans un paquet que les deux côtés importent
sans se voir.

```
$ go list -f '{{join .Imports " "}}' ./ex4/...
web              net/http
chaine           example/c23/ex4/web net/http
preoccupations   compress/gzip example/c23/ex4/web fmt io net/http strings sync time
partenaire       crypto/hmac crypto/sha256 encoding/hex example/c23/ex4/web net/http
heritage         example/c23/ex4/chain example/c23/ex4/web net/http
```

Ni `concerns` ni `partner` n'importent `chain`. Le seul paquet qui
l'importe est `inheritance`, et il est là pour échouer — c'est aussi la raison
pour laquelle il est dans son propre paquet : le laisser dans `partner`
aurait fait mentir cette mesure.

## 3. Les deux formes de composition

### La forme fonction

```go
// Chain is the FIRST OF THE TWO FORMS: a function that takes a
// list.
//
// The order of the list is the order of application, from the outermost to the
// innermost. So chaining is done in reverse, and the comment
// is there so that nobody "fixes" it.
func Chain(ps []web.Concern) func(web.Handler) web.Handler {
    return func(final web.Handler) web.Handler {
        g := final
        for i := len(ps) - 1; i >= 0; i-- {
            g = ps[i].Handle(g)
        }
        return g
    }
}
```

### La forme enveloppe

```go
// Wrapper is the SECOND OF THE TWO FORMS: a wrapper that embeds
// the interface.
//
// It is written to be compared, not to be used. Three things
// condemn it, and the third is fatal:
//
//  1. it adds a type where the first form added nothing;
//  2. its Next field is exported, so changeable after mounting;
//  3. it EMBEDS an interface, so a partner can embed it in
//     turn to "inherit the default behavior", and it is the
//     that lesson 2.3 applies, see section 7 of the correction.
type Wrapper struct {
    web.Concern
    Next web.Handler
}

// Serve applies the embedded concern then passes on.
func (e Wrapper) Serve(w http.ResponseWriter, r *http.Request, t web.Trace) {
    e.Concern.Handle(e.Next).Serve(w, r, t)
}
```

Les deux rendent la même réponse :

```go
// TestBothFormsGiveTheSameResponse answers question 3 by
// measure: both forms are equivalent at run time.
func TestBothFormsGiveTheSameResponse(t *testing.T) {
    ps := theChosenOrder(io.Discard, io.Discard)

    // Form 1: the function that takes a list.
    byFunction := chain.Chain(ps)(business(false))

    // Form 2: the wrappers, nested by hand. They must be built
    // the wrong way round, and it is already information: the function form hides
    // this inversion in a loop, the wrapper exposes it at each use.
    byWrapper := business(false)
    for i := len(ps) - 1; i >= 0; i-- {
        byWrapper = chain.Wrapper{Concern: ps[i], Next: byWrapper}
    }

    for name, g := range map[string]web.Handler{
        "function": byFunction,
        "wrapper":  byWrapper,
    } {
        rec := httptest.NewRecorder()
        g.Serve(rec, req("/accounts", validToken),
            web.NewTrace("", generate))
        if rec.Code != http.StatusOK {
            t.Fatalf("%s: status = %d", name, rec.Code)
        }
        if !strings.Contains(rec.Body.String(), "correlation corr-fixe") {
            t.Errorf("%s: body = %q", name, rec.Body.String())
        }
    }
    t.Log("both forms give the same response: so the choice is made" +
        " not on behavior")
}
```

### Les trois critères mesurables

```go
// TestTheThreeChoiceCriteria is the measure that decides between the two
// forms.
func TestTheThreeChoiceCriteria(t *testing.T) {
    ps := theChosenOrder(io.Discard, io.Discard)

    // Criterion 1: the number of types added. The function form adds
    // zero; the wrapper adds one, and this type has a public interface.
    ty := reflect.TypeOf(chain.Wrapper{})
    var methods []string
    for i := 0; i < ty.NumMethod(); i++ {
        methods = append(methods, ty.Method(i).Name)
    }
    sort.Strings(methods)
    if got := strings.Join(methods, " "); got != "Name Serve Handle" {
        t.Fatalf("methods of Wrapper = [%s]", got)
    }
    t.Logf("criterion 1: Wrapper exposes [%s], two of them PROMOTED from"+
        " the embedded interface; the function form exposes 0 methods",
        strings.Join(methods, " "))

    // Criterion 2: can the chain describe itself? The list can, in one line.
    t.Logf("criterion 2: chain.Names(list) = %v; on wrappers"+
        " nested, one would have to walk down the structure and each level"+
        " knows only the next one", chain.Names(ps))

    // Criterion 3: what can a third party do with it? A wrapper
    // can be embedded; a list cannot.
    if _, ok := any(chain.Wrapper{}).(web.Concern); !ok {
        t.Fatal("Wrapper does not satisfy Concern: the measure changed")
    }
    t.Log("criterion 3: Wrapper satisfies web.Concern BY PROMOTION," +
        " so it can be embedded, so it invites the trap of section 7")
}
```

```
critere 1 : Wrapper expose [Name Serve Handle] — dont deux PROMUES de
            the embedded interface; the function form exposes 0 methods
critere 2 : chain.Names(liste) = [journalisation recuperation
            authentification limitation compression] ; sur des wrappers
            nested, one would have to walk down the structure and each level
            knows only the next one
criterion 3: Wrapper satisfies web.Concern BY PROMOTION, donc elle
            s'incorpore, donc elle invite au piege de la section 7
```

| Critère | Forme fonction | Forme enveloppe |
|---|---|---|
| types publics ajoutés | **0** | 1, avec 3 méthodes dont 2 promues |
| la chaîne se décrit-elle ? | **oui**, `Names(liste)` en une ligne | non : chaque niveau ne connaît que le suivant |
| qu'un tiers peut-il en faire ? | rien : on ne s'incorpore pas dans une tranche | **l'incorporer**, et tomber dans le piège de la section 7 |

La forme fonction gagne les trois. La forme enveloppe est écrite dans le
module pour être mesurée, pas pour être utilisée, et son commentaire de
déclaration le dit.

## 4. La récupération de panique : ni la première ni la dernière

La réponse aux deux termes de la question est **non**, et la démonstration
tient dans deux contraintes qui se croisent.

| Contrainte | Conséquence |
|---|---|
| elle doit attraper les paniques de tout ce qui est en dessous | elle est **au-dessus** de l'authentification, de la limitation, de la compression et du métier |
| la ligne de journal doit porter le statut réellement envoyé | elle est **en dessous** de la journalisation |
| le 500 doit porter l'identifiant de corrélation | elle est **en dessous** de la trace |

Donc : deuxième, après la journalisation, la trace étant hors de la liste.

```go
// TestAPanicBecomesA500CarryingTheID answers question 4.
func TestAPanicBecomesA500CarryingTheID(t *testing.T) {

    if rec.Code != http.StatusInternalServerError {

    // is ABOVE recovery, so it sees the response that

        t.Fatalf("the log line does not carry status 500: %q", line)
    }

    t.Logf("panic    : %s", strings.TrimSpace(panicked.String()))

```

```
journal  : GET /accounts status=500 octets=35 duree=1ms correlation=corr-fixe
panique  : panique sur /accounts correlation=corr-fixe : le metier a explose
corps    : error interne, reference corr-fixe
```

### Le test qui échoue si on inverse

```go
// TestSwappingLoggingAndRecoveryBreaksTheLogLine is the test
// that question 4 asks for: it FAILS if the order is reversed.
//
// It is written the wrong way round: it mounts the reversed chain and asserts that the
// line is wrong, because a test that only checks the order
// correct does not say what the inversion costs.
func TestSwappingLoggingAndRecoveryBreaksTheLogLine(t *testing.T) {
    var journal, panicked strings.Builder
    ps := theChosenOrder(&journal, &panicked)
    ps[0], ps[1] = ps[1], ps[0]

    h := chain.Mount(business(true), generate, ps...)
    rec := httptest.NewRecorder()
    h.ServeHTTP(rec, req("/accounts", validToken))

    if rec.Code != http.StatusInternalServerError {
        t.Fatalf("status = %d: the 500 should still come out", rec.Code)
    }
    line := strings.TrimSpace(journal.String())
    if strings.Contains(line, "status=500") {
        t.Fatalf("the line carries 500 although logging is BELOW"+
            " recovery: the measure changed\n%s", line)
    }
    t.Logf("reversed order: %s", strings.Join(chain.Names(ps), " → "))
    t.Logf("the client gets 500, and the log says: %s", line)
    t.Log("so the dashboard will see no 500, and that is the incident" +
        " of correction 2.2/5 through another door")
}
```

```
ordre inverse : recuperation → journalisation → authentification →
                limitation → compression
le client recoit 500, et le journal dit :
  GET /accounts statut=0 octets=0 duree=1ms correlation=corr-fixe
```

**`status=0`.** Le client reçoit un 500 et le journal n'en sait rien, parce
que la journalisation est alors *sous* la récupération : sa ligne est écrite
pendant le déroulement de la panique, avant que la récupération n'ait écrit
quoi que ce soit.

C'est l'incident de la correction 2.2/5 par une autre porte : le tableau de
bord reste vert pendant que les clients reçoivent des 500.

> Un `defer` s'exécute aussi pendant le déroulement d'une panique. C'est ce
> qui fait que la ligne de journal existe même sur une requête qui panique —
> et c'est aussi ce qui fait qu'elle est écrite **trop tôt** si l'ordre est
> inversé.

## 5. L'ordre des six, et ce que chaque inversion casse

```go
// TestTheChosenOrder freezes the order of the five concerns.
// An order that lives in a function call can be reread; an order that lives
// in a test can be checked.
func TestTheChosenOrder(t *testing.T) {
    names := chain.Names(theChosenOrder(io.Discard, io.Discard))
    want := "logging recovery authentication ratelimit compression"
    if got := strings.Join(names, " "); got != want {
        t.Fatalf("order = %q\nwant  %q", got, want)
    }
    t.Logf("from outside to inside: %s", strings.Join(names, " → "))
    t.Log("and the trace is not in the list: it is in Mount")
}
```

```
de l'exterieur vers l'interieur : journalisation → recuperation →
authentification → limitation → compression
and the trace is not in the list: it is in Mount
```

| Paire adjacente | Ce qui casse si on l'inverse |
|---|---|
| trace ↔ journalisation | la ligne de journal n'a pas d'identifiant de corrélation : plus aucun moyen de relier le rapport d'un client à une ligne |
| journalisation ↔ récupération | **`status=0`** dans le journal pour tous les 500 produits par une panique. Mesuré ci-dessus |
| récupération ↔ authentification | une panique dans l'authentification — un jeton malformé, un index hors bornes — ferme la connexion sans réponse. Le client voit un délai, pas un 500 |
| authentification ↔ limitation | **la limitation ne sait pas par quoi compter.** Mesuré ci-dessous |
| limitation ↔ compression | aucune conséquence fonctionnelle, et une conséquence de coût : on compresserait des réponses qu'on va jeter en 429 |

L'énoncé dit « par client ». Une limitation placée avant l'authentification

### Une mesure que l'énoncé ne demandait pas

```go
// TestCompressionIsInnermost: it must wrap the writer
// before the handler writes.
func TestCompressionIsInnermost(t *testing.T) {
    var journal strings.Builder
    h := chain.Mount(business(false), generate, theChosenOrder(&journal, io.Discard)...)
    r := req("/accounts", validToken)
    r.Header.Set("Accept-Encoding", "gzip")
    rec := httptest.NewRecorder()
    h.ServeHTTP(rec, r)

    if got := rec.Header().Get("Content-Encoding"); got != "gzip" {
        t.Fatalf("Content-Encoding = %q", got)
    }
    compressed := rec.Body.Len()
    z, err := gzip.NewReader(rec.Body)
    if err != nil {
        t.Fatalf("the body is not gzip: %v", err)
    }
    plain, err := io.ReadAll(z)
    if err != nil {
        t.Fatalf("read: %v", err)
    }
    if !strings.Contains(string(plain), "correlation corr-fixe") {
        t.Fatalf("decompressed body = %q", plain)
    }
    // And the log line counts the COMPRESSED bytes, because
    // logging is above compression. It is intended: it is what
    // that goes out on the network.
    t.Logf("journal: %s", strings.TrimSpace(journal.String()))

    // And the disturbing measure: gzip on a 56-byte body produces
    // 81. Compression is not free below a certain
    // size, and a concern that compresses everything ADDS bytes to
    // most responses of a read API.
    if compressed <= len(plain) {
        t.Errorf("%d compressed bytes for %d plain: the measure changed",
            compressed, len(plain))
    }
    t.Logf("%d compressed bytes for %d body bytes, that is +%d %%",
        compressed, len(plain), (compressed-len(plain))*100/len(plain))
    t.Log("a compression concern needs a size threshold," +
        " and the statement did not ask for it")
}
```

```
81 octets compresses pour 56 octets de corps, soit +44 %
a compression concern needs a size threshold, et l'enonce
ne le demandait pas
```

Sur une réponse de 56 octets, gzip en produit 81. Une préoccupation qui
compresse *tout* ajoute des octets sur la majorité des réponses d'une API de
consultation de comptes. Le seuil manquant est une décision de produit ; la
mesure est dans une assertion, pour qu'un changement la fasse bouger.

## 6. Les routes sans authentification

| | Ce qu'elle permet | Ce qu'elle coûte | Le jour de la septième préoccupation |
|---|---|---|---|
| **A** liste de chemins exemptés dans l'authentification | marche tout de suite | l'exemption devient une propriété de l'**authentification** alors qu'elle est une propriété de la **route** ; deux endroits décrivent le routage | la septième porte sa propre liste, et il y a maintenant deux listes de chemins à garder cohérentes avec le routeur |
| **B** une chaîne par groupe de routes | l'exemption est là où elle appartient : au montage | il faut nommer les groupes, et deux groupes peuvent dériver | **rien ne change** : la septième entre dans les listes où elle doit être |
| **C** `Exempte(path string) bool` sur l'interface | uniforme | **l'interface passe à trois méthodes**, donc les six implémentations changent, y compris les quatre qui n'exemptent jamais rien — et celle du partenaire aussi | la septième aussi doit l'implémenter, et le partenaire doit republier son paquet |

**Je retiens B**, et la raison est celle de la leçon 2.2 : *une méthode
appartient à la variante si et seulement si elle se répond avec les champs de
la variante*. `Exempte("/health")` ne se répond pas avec les champs de la
compression ; elle se répond avec la table de routage. Elle n'appartient donc
pas à l'interface.

C est la pire des trois, et elle est la plus tentante, parce qu'elle a l'air
régulière. Son coût se chiffre : une méthode de plus sur l'interface, c'est
**six implémentations à modifier**, dont la cinquième et la sixième sont dans
d'autres dépôts.

```go
// TestTwoChainsForTwoRouteGroups is proposal B of question
// 6, put into practice.
func TestTwoChainsForTwoRouteGroups(t *testing.T) {
    var journal strings.Builder
    complete := theChosenOrder(&journal, io.Discard)

    // The health page: logging and recovery, nothing else. No
    // no exemption list, no flag, no extra method on
    // the interface: just another list.
    health := complete[:2]
    // Internal calls: everything but rate limiting.
    internal := []web.Concern{complete[0], complete[1], complete[2], complete[4]}

    router := http.NewServeMux()
    router.Handle("/health", chain.Mount(business(false), generate, health...))
    router.Handle("/internal/", chain.Mount(business(false), generate, internal...))
    router.Handle("/accounts", chain.Mount(business(false), generate, complete...))

    tc := []struct {
        path   string
        token  string
        status int
    }{
        {"/health", "", http.StatusOK},
        {"/accounts", "", http.StatusUnauthorized},
        {"/accounts", validToken, http.StatusOK},
        {"/internal/purge", validToken, http.StatusOK},
    }
    for _, c := range tc {
        rec := httptest.NewRecorder()
        router.ServeHTTP(rec, req(c.path, c.token))
        if rec.Code != c.status {
            t.Errorf("%s (token %q): status = %d, want %d",
                c.path, c.token, rec.Code, c.status)
        }
    }
    // And the rate limit of the internal route never bites: five calls
    // pass, where the full chain refuses the third.
    for i := 0; i < 5; i++ {
        rec := httptest.NewRecorder()
        router.ServeHTTP(rec, req("/internal/purge", validToken))
        if rec.Code != http.StatusOK {
            t.Fatalf("internal call %d: status = %d", i, rec.Code)
        }
    }
    t.Logf("health: %v", chain.Names(health))
    t.Logf("internal: %v", chain.Names(internal))
    t.Logf("complete: %v", chain.Names(complete))
    t.Log("5 internal calls in a row, no refusal: the exemption is an" +
        " other LIST, not a flag in a concern")
}
```

## 7. L'équipe partenaire

### Ce qu'elle doit importer

**`web`**, et c'est tout — le vocabulaire : `Handler`, `Trace`,
`Concern`.

```go
// Package partner is the partner team's concern, in its
// own repository.
//
// It does NOT import chain. It imports web, that is the vocabulary,
// and net/http. It is the measurable answer to question 7.
package partner

import (
    "crypto/hmac"
    "crypto/sha256"
    "encoding/hex"
    "net/http"

    "example/c23/ex4/web"
)

// Signature checks the HMAC signature of the request body.
type Signature struct {
    Key []byte
}

// Name returns the concern's name.
func (Signature) Name() string { return "partner-signature" }

// Handle wraps the next handler.
func (s Signature) Handle(next web.Handler) web.Handler {
    return web.HandlerFunc(func(w http.ResponseWriter, r *http.Request, t web.Trace) {
        wanted := r.Header.Get("X-Signature")
        mac := hmac.New(sha256.New, s.Key)
        mac.Write([]byte(r.URL.Path))
        computed := hex.EncodeToString(mac.Sum(nil))
        if !hmac.Equal([]byte(wanted), []byte(computed)) {
            w.WriteHeader(http.StatusForbidden)
            return
        }
        next.Serve(w, r, t)
    })
}
```

```
partenaire   crypto/hmac crypto/sha256 encoding/hex example/c23/ex4/web net/http
```

### Ce qu'elle ne doit surtout pas avoir à importer

**`chain`.** Si elle devait l'importer, chaque montée de version de notre
composeur casserait sa compilation, et notre chaîne et la sienne seraient
couplées dans les deux sens. Le test le vérifie plutôt que le promettre.

### Et si elle incorpore notre enveloppe

```go

//
// It is in ITS package, and not in partner, for a reason that is
// the response itself: it is the only code of this exercise that needs
// to import chain. Leaving it in partner would have made the

package inheritance

// the caller to "inherit the default behavior".
//
// This type is written on purpose, and it is the only one of this package that imports
// chain. The three things that will go wrong are measured in
// inheritance_test.go.
type FailedInheritance struct {
    chain.Wrapper
}

// Name declares its own name, and it HIDES the wrapper's, or rather
// that of the concern the wrapper embeds.
func (FailedInheritance) Name() string { return "failed-inheritance" }

// Handle is the method the author of FailedInheritance believes they override.
//
// Wrapper.Serve calls e.Concern.Handle, where e is of type
// Wrapper. So this method is NEVER called by Serve.
func (h FailedInheritance) Handle(next web.Handler) web.Handler {
    return web.HandlerFunc(func(w http.ResponseWriter, r *http.Request, t web.Trace) {
        w.Header().Set("X-Partner", "passed")
        next.Serve(w, r, t)
    })
}
```

Trois choses vont mal se passer, et les trois sont mesurées.

**Un.** `FailedInheritance{}` compile, satisfait `web.Handler` parce que
`Serve` est promue, et panique au premier appel : l'interface incorporée vaut
`nil`.

```go
        t.Fatal("no panic: the measure changed")
    }
    t.Logf("FailedInheritance{} is a valid web.Handler at compile time," +
        " and it panics on the call")
    t.Logf("panic: %v", panicked)
```


**Deux.** Même correctement remplie, l'enveloppe n'appelle **jamais** la
méthode du partenaire. `Wrapper.Serve` appelle `e.Concern.Handle`,
où `e` est de type `Wrapper` — et `Wrapper` ne sait rien de ce qui
l'incorpore. C'est la leçon 2.3 mot pour mot, et c'est l'exercice 1 une
troisième fois.


livre, ses tests unitaires sur `Handle` sont verts — appelée directement,
elle fonctionne — et la préoccupation ne s'applique pas en production.

> c'est que nous ayons exporté un type qui incorpore une interface. La forme

## 8. La garantie : aucune requête ne traverse la chaîne sans être tracée

### La propriété du modèle

Deux décisions, et la seconde est celle qui tranche.

**La trace est un paramètre, pas une valeur de contexte.** `Handler.Serve`
prend un `web.Trace`. Un gestionnaire ne peut donc pas être appelé sans
qu'une trace soit **nommée au point d'appel**. Avec un `context.Value`, le
compilateur ne voit rien et l'oubli est muet.

**La trace n'est pas une préoccupation.** Elle est dans `Mount`.

```go
// Mount returns the complete HTTP handler.
// It is the ONLY place in the program where a trace is made, and it is
// intended: the trace is not one concern among six, it is the mounting
// itself. A concern is by definition something one can
// remove from a chain; the guarantee asked for in question 8 is exactly
// one cannot remove that one.
func Mount(final web.Handler, generate func() string, ps ...web.Concern) http.Handler {
    chained := Chain(ps)(final)
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        t := web.NewTrace(r.Header.Get(web.CorrelationHeader), generate)
        w.Header().Set(web.CorrelationHeader, t.ID())
        chained.Serve(w, r, t)
    })
}
```

Une préoccupation est par définition quelque chose qu'on peut retirer de la
liste. La garantie demandée est exactement qu'on ne puisse pas retirer
celle-là — donc elle ne peut pas être une préoccupation. C'est la seule
conclusion possible, et elle n'est pas intuitive : l'énoncé liste la trace
comme la quatrième des six.

### Ce qu'elle interdit, chiffré — par le compilateur

### Ce qu'elle ne couvre pas

```go
// TestWhatThePropertyDoesNotCover is the honest part of the answer.
// The zero value of web.Trace can be built from anywhere:
// web.Trace{} compiles. What it cannot be is VALID. A
// direct call to the final handler with an empty trace is therefore possible, and
// it is the only gap: an expression, greppable, that exists nowhere
// else in production code.
func TestWhatThePropertyDoesNotCover(t *testing.T) {
    empty := web.Trace{}
    if empty.Valid() {
        t.Fatal("the zero value declares itself valid")
    }
    if empty.ID() != "" {
        t.Fatalf("ID() = %q", empty.ID())
    }
    t.Log("web.Trace{} compiles, and Valid() returns false: the gap is" +
        " to call the final handler by hand, not to forge a" +
        " identifier")

    // And the measure: the expression must appear in no file of the
    // production of the exercise.
    root, err := filepath.Abs("..")
    if err != nil {
        t.Fatalf("root: %v", err)
    }
    occurrences := 0
    err = filepath.Walk(root, func(p string, info os.FileInfo, err error) error {
        if err != nil || info.IsDir() || !strings.HasSuffix(p, ".go") ||
            strings.HasSuffix(p, "_test.go") {
            return err
        }
        bytes, err := os.ReadFile(p)
        if err != nil {
            return err
        }
        occurrences += strings.Count(string(bytes), "web.Trace{}")
        occurrences += strings.Count(string(bytes), "Trace{}")
        return nil
    })
    if err != nil {
        t.Fatalf("walk: %v", err)
    }
    if occurrences != 0 {
        t.Fatalf("%d occurrence(s) of Trace{} in production code", occurrences)
    }
    t.Log("0 occurrences of Trace{} in production code")

```

```

gestionnaire final a la main, pas de forger un identifier
0 occurrences of Trace{} in production code
```

`web.Trace{}` — la valeur zéro — est constructible depuis n'importe où. La
brèche n'est donc pas de forger un identifiant, c'est d'appeler le
gestionnaire final à la main avec une trace vide, en court-circuitant
`Mount`. C'est **une expression, grepable**, et le test compte ses
occurrences dans le code de production : zéro.

Et une seconde chose qu'elle ne couvre pas : une route enregistrée
directement sur le routeur, sans passer par `Mount`. Le modèle ne l'empêche
pas.

### La mesure pour le reste, avec son seuil et son plancher de bruit

| | |
|---|---|
| l'indicateur | part des réponses **sortantes** sans en-tête `X-Correlation-Id`, mesurée au point d'entrée du réseau et non dans l'application |
| pourquoi au bord | une route montée hors de `Mount` est invisible depuis `Mount`. L'indicateur doit vivre **au-dessus** de ce qu'il surveille |
| le seuil | **une** réponse sans en-tête sur une fenêtre de cinq minutes déclenche une alerte |
| le plancher de bruit | il est **nul**, et c'est tout l'intérêt : `Mount` pose l'en-tête avant la première préoccupation, donc une absence ne peut pas venir d'un timing, d'un échantillonnage ou d'un rejet métier. C'est la différence avec un taux d'erreur, qui mélange refus et pannes et a donc un plancher — correction 2.2/5 |

Un indicateur à plancher de bruit nul peut avoir un seuil de un. C'est rare,
et c'est ce qui le rend exploitable.

### À quelle condition la propriété survit-elle au prochain développeur ?

**À une seule : qu'ajouter une préoccupation ne donne jamais l'occasion de
toucher à `Mount`.**

La propriété ne tient pas parce qu'elle est écrite dans un commentaire ; elle
tient parce que la seule chose qu'un développeur ait à écrire pour ajouter une
préoccupation est un type à deux méthodes et une entrée dans une liste. Tant
que c'est vrai, `Mount` n'est jamais rouvert, et les trois lignes qui
fabriquent la trace restent les trois seules.

Ce qui la casserait, concrètement :

| Changement | Pourquoi il la casse |
|---|---|
| une préoccupation a besoin de modifier la trace | elle demandera un `Trace` mutable, ou un second paramètre, et `Mount` sera rouvert |
| une préoccupation a besoin de court-circuiter la chaîne avec sa propre trace | même chose |
| `Mount` gagne un second rôle (le routage, la configuration) | il devient un endroit qu'on modifie pour d'autres raisons, et les trois lignes finissent au milieu de quarante |

> Une propriété de modèle survit au prochain développeur si et seulement si
> le travail normal ne passe pas par l'endroit qui la porte.

## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | Des préoccupations composables ont besoin d'**une** des trois choses que l'héritage accorde — le sous-typage. Donc une interface, et rien d'autre. |
| ⚫ | L'incorporation a exactement un rôle ici, et ce n'est pas celui qu'on attend : les enveloppes de `http.ResponseWriter`. Une interface à trois méthodes, on en redéfinit deux, on délègue la troisième sans l'écrire. |
| ⚫ | Incorporer une interface ne promeut **que** ses méthodes. Un `http.Flusher` sous-jacent devient invisible, et les flux d'événements serveur cessent de marcher sans message. |
| ⚫ | `Name()` sur une préoccupation ne sert à rien à l'exécution. Elle sert à ce qu'un **test** puisse vérifier l'ordre, là où une liste de fonctions anonymes ne se vérifie que par relecture. |
| ⚫ | Entre une enveloppe qui incorpore l'interface et une fonction qui prend une liste, trois critères mesurables tranchent — et l'argument décisif est qu'une enveloppe exportée **s'incorpore**, donc invite au piège. |
| ⚫ | Un `defer` s'exécute pendant le déroulement d'une panique. C'est ce qui sauve la ligne de journal, et ce qui l'écrit trop tôt si l'ordre est inversé : `status=0`, tableau de bord vert, clients en 500. |
| ⚫ | Une limitation de débit placée avant l'authentification n'a pas de client : elle refuse tout le monde, ou elle offre un déni de service dans un seau commun. |
| ⚫ | Une exemption de route est une propriété de la **route**, pas de la préoccupation. Elle se règle par une autre liste, pas par une méthode de plus sur l'interface — qui coûterait six implémentations, dont deux dans d'autres dépôts. |
| ⚫ | Une équipe partenaire doit importer le **vocabulaire**, jamais le composeur. Ce qui l'invite à incorporer notre enveloppe, c'est que nous l'ayons exportée. |
| ⚫ | La préoccupation qui porte une garantie ne peut pas être une préoccupation : par définition, une préoccupation se retire de la liste. Elle appartient au **montage**. |
| ⚫ | Passer la preuve en **paramètre** plutôt qu'en valeur de contexte met le compilateur dans la boucle : l'oubli devient visible au point d'appel. |
| ⚫ | Un test qui attend un échec de compilation doit vérifier la **raison**. Mes trois attentes étaient fausses : le message est `cannot refer to unexported field`, pas `unknown field`. |
| ⚫ | Un indicateur à **plancher de bruit nul** peut avoir un seuil de un. C'est rare, et ça vient de ce qu'il mesure la présence d'un en-tête, pas un mélange de refus et de pannes. |
| ⚫ | Une propriété de modèle survit au prochain développeur si et seulement si le travail normal ne passe pas par l'endroit qui la porte. |
