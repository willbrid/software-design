# Correction 2.3 — Exercice 4 : la chaîne de traitement HTTP

> Rappel de l'énoncé : six préoccupations transverses composables, un ordre
> significatif, des routes exemptées, et une équipe partenaire qui doit
> pouvoir ajouter la sienne depuis son dépôt.

Six paquets, tous verts sous `go vet ./...` et `go test -race -count=1
./...`. Le découpage est le résultat de l'exercice, donc il arrive en
premier :

```
web              le vocabulaire : Trace, Gestionnaire, Preoccupation
chaine           l'appelant : Enchainer, Enveloppe, Monter, Noms
preoccupations   cinq des six
partenaire       la sixieme preoccupation, « dans un autre depot »
heritage         la tentative d'heritage de la question 7, isolee
garde            les tests de decision : ce que le compilateur refuse
```

## 1. Le mécanisme, par la question des trois

L'héritage accorde trois choses d'un coup : la **réutilisation** de code, le
**sous-typage**, et la **spécialisation ouverte**. Ce dont l'exercice a
besoin, préoccupation par préoccupation :

| | Réutilisation | Sous-typage | Spécialisation ouverte |
|---|---|---|---|
| les six préoccupations | non — elles ne partagent aucun code | **oui** — elles doivent être interchangeables dans une liste | non |

Une seule des trois. Donc : **une interface**, et rien d'autre. Pas de type de
base, pas de `PreoccupationAbstraite`.

### Est-ce que l'incorporation a un rôle ici ?

Oui, exactement un, et il n'a rien à voir avec les six préoccupations
elles-mêmes : il concerne les **enveloppes de `http.ResponseWriter`** dont la
journalisation et la compression ont besoin.

```go
// Capteur enregistre le statut ecrit dans la reponse.
//
// Il INCORPORE http.ResponseWriter, et c'est l'incorporation la plus
// justifiee du cours : l'interface a trois methodes, on en redefinit une, et
// on delegue les deux autres sans les ecrire.
//
// Le piege est connu et il est mesure dans les tests : le Capteur n'expose
// QUE les trois methodes de ResponseWriter. Un http.Flusher ou un
// http.Hijacker sous-jacent devient invisible, et un flux d'evenements
// serveur cesse de fonctionner sans message d'erreur.
type Capteur struct {
    http.ResponseWriter
    Statut  int
    Octets  int
    ecrites bool
}

// WriteHeader retient le statut et le transmet.
func (c *Capteur) WriteHeader(statut int) {
    if c.ecrites {
        return
    }
    c.Statut = statut
    c.ecrites = true
    c.ResponseWriter.WriteHeader(statut)
}

// Write compte les octets et force un statut si personne ne l'a ecrit.
func (c *Capteur) Write(p []byte) (int, error) {
    if !c.ecrites {
        c.WriteHeader(http.StatusOK)
    }
    n, err := c.ResponseWriter.Write(p)
    c.Octets += n
    return n, err
}
```

C'est l'incorporation dans son emploi légitime, et le seul du cours : une
interface à trois méthodes, on en redéfinit une ou deux, et on délègue les
autres **sans les écrire**. `Capteur` redéfinit `WriteHeader` et `Write` ;
`Header` est promue telle quelle.

Et elle coûte quelque chose, mesuré :

```go
// TestLeCapteurMasqueLeFlusher mesure le prix de l'incorporation d'une
// interface, et c'est le seul endroit du cours ou l'incorporation est le bon
// choix tout en coutant quelque chose.
func TestLeCapteurMasqueLeFlusher(t *testing.T) {
    rec := httptest.NewRecorder()
    if _, est := any(rec).(http.Flusher); !est {
        t.Skip("l'enregistreur de test n'est pas un Flusher : la mesure ne" +
            " s'applique pas sur cette version de Go")
    }
    c := &preoccupations.Capteur{ResponseWriter: rec}
    if _, est := any(c).(http.Flusher); est {
        t.Fatal("le Capteur expose Flush : l'incorporation d'une interface" +
            " ne promeut que les methodes de cette interface, la mesure a change")
    }
    t.Log("le ResponseWriter sous-jacent est un http.Flusher, le Capteur ne" +
        " l'est plus : un flux d'evenements serveur cesse de fonctionner sans" +
        " aucun message")
}
```

```
le ResponseWriter sous-jacent est un http.Flusher, le Capteur ne l'est plus :
un flux d'evenements serveur cesse de fonctionner sans aucun message
```

> Incorporer une interface ne promeut **que** les méthodes de cette
> interface. Tout ce que la valeur sous-jacente savait faire en plus
> disparaît, silencieusement, et un `http.Flusher` perdu casse les flux
> d'événements serveur sans aucune erreur.

C'est le prix à connaître avant de choisir cette incorporation, pas après. La
parade, quand on en a besoin, est d'écrire les délégations à la main ou de
déclarer `Flush()` sur le capteur.

## 2. L'interface

```go
// Gestionnaire est ce qui sert une requete.
//
// Noter la signature : la trace est un PARAMETRE, pas une valeur de
// contexte. Un gestionnaire ne peut donc pas etre appele sans qu'une trace
// soit nommee au point d'appel, et c'est la moitie de la garantie demandee a
// la question 8.
type Gestionnaire interface {
    Servir(w http.ResponseWriter, r *http.Request, t Trace)
}

// GestionnaireFunc adapte une fonction en Gestionnaire.
type GestionnaireFunc func(w http.ResponseWriter, r *http.Request, t Trace)

// Servir appelle f.
func (f GestionnaireFunc) Servir(w http.ResponseWriter, r *http.Request, t Trace) {
    f(w, r, t)
}

// Preoccupation est l'interface des six preoccupations transverses.
//
// DEUX methodes, et il faut justifier la seconde. Traiter suffirait au
// comportement : c'est la forme habituelle d'un intergiciel en Go. Nom ne
// sert a rien a l'execution — il sert a ce que la chaine puisse se DECRIRE,
// et la question 8 demande une garantie sur l'ordre et la presence des
// preoccupations. Une garantie sur une liste de fonctions anonymes ne
// s'ecrit pas.
type Preoccupation interface {
    Nom() string
    Traiter(suivant Gestionnaire) Gestionnaire
}
```

**Deux méthodes**, et la seconde demande une justification.

`Traiter` suffirait au comportement : la forme habituelle d'un intergiciel en
Go est `func(http.Handler) http.Handler`, sans interface du tout. `Nom` ne
sert à rien à l'exécution. Elle sert à ce que la chaîne puisse **se décrire**,
et la question 8 demande une garantie sur la présence et l'ordre des
préoccupations.

> Une garantie sur une liste de fonctions anonymes ne s'écrit pas. C'est
> `Nom()` qui transforme « il faut relire l'ordre » en « il y a un test sur
> l'ordre ».

### Où elle est déclarée, et la preuve

Elle est dans `web`, pas dans `chaine`. C'est la leçon de l'exercice 2 :
l'interface nomme `Gestionnaire` et `Trace`, qui ne sont pas des types
universels, donc ils descendent dans un paquet que les deux côtés importent
sans se voir.

```
$ go list -f '{{join .Imports " "}}' ./ex4/...
web              net/http
chaine           exemple/c23/ex4/web net/http
preoccupations   compress/gzip exemple/c23/ex4/web fmt io net/http strings sync time
partenaire       crypto/hmac crypto/sha256 encoding/hex exemple/c23/ex4/web net/http
heritage         exemple/c23/ex4/chaine exemple/c23/ex4/web net/http
```

Ni `preoccupations` ni `partenaire` n'importent `chaine`. Le seul paquet qui
l'importe est `heritage`, et il est là pour échouer — c'est aussi la raison
pour laquelle il est dans son propre paquet : le laisser dans `partenaire`
aurait fait mentir cette mesure.

## 3. Les deux formes de composition

### La forme fonction

```go
// Enchainer est la PREMIERE DES DEUX FORMES : une fonction qui prend une
// liste.
//
// L'ordre de la liste est l'ordre d'application, de la plus exterieure a la
// plus interieure. L'enchainement se fait donc a l'envers, et le commentaire
// est la pour que personne ne le « corrige ».
func Enchainer(ps []web.Preoccupation) func(web.Gestionnaire) web.Gestionnaire {
    return func(final web.Gestionnaire) web.Gestionnaire {
        g := final
        for i := len(ps) - 1; i >= 0; i-- {
            g = ps[i].Traiter(g)
        }
        return g
    }
}
```

### La forme enveloppe

```go
// Enveloppe est la SECONDE DES DEUX FORMES : une enveloppe qui incorpore
// l'interface.
//
// Elle est ecrite pour etre comparee, pas pour etre utilisee. Trois choses
// la condamnent, et la troisieme est fatale :
//
//  1. elle ajoute un type la ou la premiere forme n'ajoutait rien ;
//  2. son champ Suivante est exporte, donc modifiable apres montage ;
//  3. elle INCORPORE une interface, donc un partenaire peut l'incorporer a
//     son tour pour « heriter du comportement par defaut » — et c'est la
//     que la lecon 2.3 s'applique, voir la section 7 de la correction.
type Enveloppe struct {
    web.Preoccupation
    Suivante web.Gestionnaire
}

// Servir applique la preoccupation incorporee puis passe la main.
func (e Enveloppe) Servir(w http.ResponseWriter, r *http.Request, t web.Trace) {
    e.Preoccupation.Traiter(e.Suivante).Servir(w, r, t)
}
```

Les deux rendent la même réponse :

```go
// TestLesDeuxFormesRendentLaMemeReponse repond a la question 3 par la
// mesure : les deux formes sont equivalentes a l'execution.
func TestLesDeuxFormesRendentLaMemeReponse(t *testing.T) {
    ps := lOrdreRetenu(io.Discard, io.Discard)

    // Forme 1 : la fonction qui prend une liste.
    parFonction := chaine.Enchainer(ps)(metier(false))

    // Forme 2 : les enveloppes, emboitees a la main. Il faut les construire
    // a l'envers, et c'est deja une information : la forme fonction cache
    // cette inversion dans une boucle, l'enveloppe l'expose a chaque usage.

            t.Fatalf("%s : statut = %d", nom, rec.Code)
        }
        if !strings.Contains(rec.Body.String(), "correlation corr-fixe") {
            t.Errorf("%s : corps = %q", nom, rec.Body.String())
        }
    }
    t.Log("les deux formes rendent la meme reponse : le choix ne se fait donc" +

}
```

### Les trois critères mesurables

```go
// TestLesTroisCriteresDeChoix est la mesure qui tranche entre les deux
// formes.
func TestLesTroisCriteresDeChoix(t *testing.T) {
    ps := lOrdreRetenu(io.Discard, io.Discard)

    // Critere 1 : le nombre de types ajoutes. La forme fonction en ajoute
    // zero ; l'enveloppe en ajoute un, et ce type a une interface publique.
    ty := reflect.TypeOf(chaine.Enveloppe{})
    var methodes []string
    for i := 0; i < ty.NumMethod(); i++ {
        methodes = append(methodes, ty.Method(i).Name)
    }
    sort.Strings(methodes)
    if got := strings.Join(methodes, " "); got != "Nom Servir Traiter" {
        t.Fatalf("methodes de Enveloppe = [%s]", got)
    }
    t.Logf("critere 1 : Enveloppe expose [%s] — dont deux PROMUES de"+
        " l'interface incorporee ; la forme fonction expose 0 methode",
        strings.Join(methodes, " "))

    // Critere 2 : la chaine se decrit-elle ? La liste, oui, en une ligne.
    t.Logf("critere 2 : chaine.Noms(liste) = %v ; sur des enveloppes"+
        " emboitees, il faudrait descendre la structure et chaque niveau"+
        " ne connait que le suivant", chaine.Noms(ps))

    // s'incorpore ; une liste ne s'incorpore pas.
    if _, est := any(chaine.Enveloppe{}).(web.Preoccupation); !est {
        t.Fatal("Enveloppe ne satisfait pas Preoccupation : la mesure a change")

        " donc elle s'incorpore, donc elle invite au piege de la section 7")

```

```
critere 1 : Enveloppe expose [Nom Servir Traiter] — dont deux PROMUES de
            l'interface incorporee ; la forme fonction expose 0 methode
critere 2 : chaine.Noms(liste) = [journalisation recuperation
            authentification limitation compression] ; sur des enveloppes
            emboitees, il faudrait descendre la structure et chaque niveau
            ne connait que le suivant

```

| Critère | Forme fonction | Forme enveloppe |
|---|---|---|
| types publics ajoutés | **0** | 1, avec 3 méthodes dont 2 promues |
| la chaîne se décrit-elle ? | **oui**, `Noms(liste)` en une ligne | non : chaque niveau ne connaît que le suivant |
| qu'un tiers peut-il en faire ? | rien : on ne s'incorpore pas dans une tranche | **l'incorporer**, et tomber dans le piège de la section 7 |

La forme fonction gagne les trois. La forme enveloppe est écrite dans le
module pour être mesurée, pas pour être utilisée, et son commentaire de
déclaration le dit.

## 4. La récupération de panique : ni la première ni la dernière

La réponse aux deux termes de la question est **non**, et la démonstration
tient dans deux contraintes qui se croisent.

| Contrainte | Conséquence |
|---|---|
| elle doit attraper les paniques de tout ce qui est en dessous | elle est **au-dessus** de l'authentification, de la limitation, de la compression et du métier |
| la ligne de journal doit porter le statut réellement envoyé | elle est **en dessous** de la journalisation |
| le 500 doit porter l'identifiant de corrélation | elle est **en dessous** de la trace |

Donc : deuxième, après la journalisation, la trace étant hors de la liste.

```go
// TestUnePaniqueDevientUn500QuiPorteLIdentifiant repond a la question 4.
func TestUnePaniqueDevientUn500QuiPorteLIdentifiant(t *testing.T) {

    rec := httptest.NewRecorder()
    h.ServeHTTP(rec, requete("/comptes", jetonValide))

    if rec.Code != http.StatusInternalServerError {
        t.Fatalf("statut = %d, attendu 500", rec.Code)
    }
    if !strings.Contains(rec.Body.String(), "corr-fixe") {
        t.Errorf("le 500 ne porte pas l'identifiant : %q", rec.Body.String())
    }
    // Et la ligne de journal existe, avec le statut 500 : la journalisation
    // est AU-DESSUS de la recuperation, donc elle voit la reponse que la
    // recuperation a ecrite.

    if !strings.Contains(ligne, "statut=500") {
        t.Fatalf("la ligne de journal ne porte pas le statut 500 : %q", ligne)
    }
    t.Logf("journal  : %s", ligne)
    t.Logf("panique  : %s", strings.TrimSpace(panique.String()))
    t.Logf("corps    : %s", rec.Body.String())
}
```

```
journal  : GET /comptes statut=500 octets=35 duree=1ms correlation=corr-fixe
panique  : panique sur /comptes correlation=corr-fixe : le metier a explose
corps    : erreur interne, reference corr-fixe
```

### Le test qui échoue si on inverse

```go
// TestInverserJournalisationEtRecuperationCasseLaLigneDeJournal est le test
// que la question 4 demande : il ECHOUE si l'ordre est inverse.
//
// Il est ecrit a l'envers — il monte la chaine inversee et affirme que la
// ligne est fausse — parce qu'un test qui se contente de verifier l'ordre
// correct ne dit pas ce que l'inversion coute.
func TestInverserJournalisationEtRecuperationCasseLaLigneDeJournal(t *testing.T) {
    var journal, panique strings.Builder
    ps := lOrdreRetenu(&journal, &panique)
    ps[0], ps[1] = ps[1], ps[0]

    h := chaine.Monter(metier(true), generer, ps...)
    rec := httptest.NewRecorder()
    h.ServeHTTP(rec, requete("/comptes", jetonValide))

    if rec.Code != http.StatusInternalServerError {
        t.Fatalf("statut = %d : le 500 devrait quand meme sortir", rec.Code)
    }
    ligne := strings.TrimSpace(journal.String())
    if strings.Contains(ligne, "statut=500") {
        t.Fatalf("la ligne porte 500 alors que la journalisation est SOUS la"+
            " recuperation : la mesure a change\n%s", ligne)
    }
    t.Logf("ordre inverse : %s", strings.Join(chaine.Noms(ps), " → "))
    t.Logf("le client recoit 500, et le journal dit : %s", ligne)
    t.Log("le tableau de bord ne verra donc aucun 500, et c'est l'incident" +
        " de la correction 2.2/5 par une autre porte")
}
```

```
ordre inverse : recuperation → journalisation → authentification →
                limitation → compression
le client recoit 500, et le journal dit :
  GET /comptes statut=0 octets=0 duree=1ms correlation=corr-fixe
```

**`statut=0`.** Le client reçoit un 500 et le journal n'en sait rien, parce
que la journalisation est alors *sous* la récupération : sa ligne est écrite
pendant le déroulement de la panique, avant que la récupération n'ait écrit
quoi que ce soit.

C'est l'incident de la correction 2.2/5 par une autre porte : le tableau de
bord reste vert pendant que les clients reçoivent des 500.

> Un `defer` s'exécute aussi pendant le déroulement d'une panique. C'est ce
> qui fait que la ligne de journal existe même sur une requête qui panique —
> et c'est aussi ce qui fait qu'elle est écrite **trop tôt** si l'ordre est
> inversé.

## 5. L'ordre des six, et ce que chaque inversion casse

```go
// TestLOrdreRetenu fige l'ordre des cinq preoccupations.
//
// Un ordre qui vit dans l'appel d'une fonction se relit ; un ordre qui vit
// dans un test se verifie.
func TestLOrdreRetenu(t *testing.T) {
    noms := chaine.Noms(lOrdreRetenu(io.Discard, io.Discard))
    attendu := "journalisation recuperation authentification limitation compression"
    if got := strings.Join(noms, " "); got != attendu {
        t.Fatalf("ordre = %q\nattendu  %q", got, attendu)
    }
    t.Logf("de l'exterieur vers l'interieur : %s", strings.Join(noms, " → "))
    t.Log("et la trace n'est pas dans la liste : elle est dans Monter")
}
```

```
de l'exterieur vers l'interieur : journalisation → recuperation →
authentification → limitation → compression
et la trace n'est pas dans la liste : elle est dans Monter
```

| Paire adjacente | Ce qui casse si on l'inverse |
|---|---|
| trace ↔ journalisation | la ligne de journal n'a pas d'identifiant de corrélation : plus aucun moyen de relier le rapport d'un client à une ligne |
| journalisation ↔ récupération | **`statut=0`** dans le journal pour tous les 500 produits par une panique. Mesuré ci-dessus |
| récupération ↔ authentification | une panique dans l'authentification — un jeton malformé, un index hors bornes — ferme la connexion sans réponse. Le client voit un délai, pas un 500 |
| authentification ↔ limitation | **la limitation ne sait pas par quoi compter.** Mesuré ci-dessous |
| limitation ↔ compression | aucune conséquence fonctionnelle, et une conséquence de coût : on compresserait des réponses qu'on va jeter en 429 |

### Les deux inversions attrapées par un test

La première est celle de la section 4. La seconde :

```go
// TestUneRequeteNonAuthentifieeNeConsommePasDeQuota est la deuxieme
// inversion attrapee par un test.
func TestUneRequeteNonAuthentifieeNeConsommePasDeQuota(t *testing.T) {

```

Inversée :

```
ordre inverse : journalisation → recuperation → limitation →
                authentification → compression
une requete parfaitement authentifiee recoit 401 : la limitation arrive

```

L'énoncé dit « par client ». Une limitation placée avant l'authentification
n'a pas de client, et elle n'a que deux choix, tous les deux faux : refuser
tout le monde (mesuré : 401 sur une requête valide) ou compter tout le monde
dans le même seau, c'est-à-dire **offrir un déni de service au premier
venu**. Le code refuse explicitement, et le commentaire dit pourquoi.

### Une mesure que l'énoncé ne demandait pas

```go
// TestLaCompressionEstLaPlusInterieure : elle doit envelopper l'ecrivain
// avant que le gestionnaire n'ecrive.
func TestLaCompressionEstLaPlusInterieure(t *testing.T) {
    var journal strings.Builder
    h := chaine.Monter(metier(false), generer, lOrdreRetenu(&journal, io.Discard)...)
    r := requete("/comptes", jetonValide)
    r.Header.Set("Accept-Encoding", "gzip")
    rec := httptest.NewRecorder()
    h.ServeHTTP(rec, r)

    if got := rec.Header().Get("Content-Encoding"); got != "gzip" {
        t.Fatalf("Content-Encoding = %q", got)
    }
    compresses := rec.Body.Len()
    z, err := gzip.NewReader(rec.Body)
    if err != nil {
        t.Fatalf("le corps n'est pas du gzip : %v", err)
    }
    clair, err := io.ReadAll(z)
    if err != nil {
        t.Fatalf("lecture : %v", err)
    }
    if !strings.Contains(string(clair), "correlation corr-fixe") {
        t.Fatalf("corps decompresse = %q", clair)
    }
    // Et la ligne de journal compte les octets COMPRESSES, parce que la
    // journalisation est au-dessus de la compression. C'est voulu : c'est ce
    // qui sort sur le reseau.
    t.Logf("journal : %s", strings.TrimSpace(journal.String()))

    // Et la mesure qui derange : gzip sur un corps de 56 octets en produit
    // 81. La compression n'est pas gratuite en dessous d'une certaine
    // taille, et une preoccupation qui compresse tout AJOUTE des octets sur
    // la majorite des reponses d'une API de consultation.
    if compresses <= len(clair) {
        t.Errorf("%d octets compresses pour %d en clair : la mesure a change",
            compresses, len(clair))
    }
    t.Logf("%d octets compresses pour %d octets de corps, soit +%d %%",
        compresses, len(clair), (compresses-len(clair))*100/len(clair))
    t.Log("une preoccupation de compression a besoin d'un seuil de taille," +
        " et l'enonce ne le demandait pas")
}
```

## 6. Les routes sans authentification

| | Ce qu'elle permet | Ce qu'elle coûte | Le jour de la septième préoccupation |
|---|---|---|---|
| **A** liste de chemins exemptés dans l'authentification | marche tout de suite | l'exemption devient une propriété de l'**authentification** alors qu'elle est une propriété de la **route** ; deux endroits décrivent le routage | la septième porte sa propre liste, et il y a maintenant deux listes de chemins à garder cohérentes avec le routeur |
| **B** une chaîne par groupe de routes | l'exemption est là où elle appartient : au montage | il faut nommer les groupes, et deux groupes peuvent dériver | **rien ne change** : la septième entre dans les listes où elle doit être |
| **C** `Exempte(chemin string) bool` sur l'interface | uniforme | **l'interface passe à trois méthodes**, donc les six implémentations changent, y compris les quatre qui n'exemptent jamais rien — et celle du partenaire aussi | la septième aussi doit l'implémenter, et le partenaire doit republier son paquet |

**Je retiens B**, et la raison est celle de la leçon 2.2 : *une méthode
appartient à la variante si et seulement si elle se répond avec les champs de
la variante*. `Exempte("/sante")` ne se répond pas avec les champs de la
compression ; elle se répond avec la table de routage. Elle n'appartient donc
pas à l'interface.

C est la pire des trois, et elle est la plus tentante, parce qu'elle a l'air
régulière. Son coût se chiffre : une méthode de plus sur l'interface, c'est
**six implémentations à modifier**, dont la cinquième et la sixième sont dans
d'autres dépôts.

## 7. L'équipe partenaire

### Ce qu'elle doit importer

**`web`**, et c'est tout — le vocabulaire : `Gestionnaire`, `Trace`,
`Preoccupation`.

```go

// propre depot.
//
// Elle n'importe PAS chaine. Elle importe web, c'est-a-dire le vocabulaire,
// et net/http. C'est la reponse mesurable a la question 7.
package partenaire

import (
    "crypto/hmac"
    "crypto/sha256"
    "encoding/hex"
    "net/http"

    "exemple/c23/ex4/web"
)

// Signature verifie la signature HMAC du corps de la requete.
type Signature struct {
    Cle []byte
}

// Nom rend le nom de la preoccupation.
func (Signature) Nom() string { return "signature-partenaire" }

// Traiter enveloppe le gestionnaire suivant.
func (s Signature) Traiter(suivant web.Gestionnaire) web.Gestionnaire {
    return web.GestionnaireFunc(func(w http.ResponseWriter, r *http.Request, t web.Trace) {
        attendue := r.Header.Get("X-Signature")
        mac := hmac.New(sha256.New, s.Cle)
        mac.Write([]byte(r.URL.Path))
        calculee := hex.EncodeToString(mac.Sum(nil))
        if !hmac.Equal([]byte(attendue), []byte(calculee)) {
            w.WriteHeader(http.StatusForbidden)
            return
        }
        suivant.Servir(w, r, t)
    })
}
```

## 8. La garantie : aucune requête ne traverse la chaîne sans être tracée

### La propriété du modèle

Deux décisions, et la seconde est celle qui tranche.

**La trace est un paramètre, pas une valeur de contexte.** `Gestionnaire.Servir`
prend un `web.Trace`. Un gestionnaire ne peut donc pas être appelé sans
qu'une trace soit **nommée au point d'appel**. Avec un `context.Value`, le
compilateur ne voit rien et l'oubli est muet.

**La trace n'est pas une préoccupation.** Elle est dans `Monter`.

```go
// Monter rend le gestionnaire HTTP complet.
//
// C'est le SEUL endroit du programme ou une trace est fabriquee, et c'est
// voulu : la trace n'est pas une preoccupation parmi six, c'est le montage
// lui-meme. Une preoccupation est par definition quelque chose qu'on peut
// retirer d'une chaine ; la garantie demandee a la question 8 est exactement
// qu'on ne puisse pas retirer celle-la.
func Monter(final web.Gestionnaire, generer func() string, ps ...web.Preoccupation) http.Handler {
    enchainee := Enchainer(ps)(final)
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        t := web.NouvelleTrace(r.Header.Get(web.EnteteCorrelation), generer)
        w.Header().Set(web.EnteteCorrelation, t.ID())
        enchainee.Servir(w, r, t)
    })
}
```

Une préoccupation est par définition quelque chose qu'on peut retirer de la
liste. La garantie demandée est exactement qu'on ne puisse pas retirer
celle-là — donc elle ne peut pas être une préoccupation. C'est la seule
conclusion possible, et elle n'est pas intuitive : l'énoncé liste la trace
comme la quatrième des six.

### Ce qu'elle interdit, chiffré — par le compilateur

### La mesure pour le reste, avec son seuil et son plancher de bruit

| | |
|---|---|
| l'indicateur | part des réponses **sortantes** sans en-tête `X-Correlation-Id`, mesurée au point d'entrée du réseau et non dans l'application |
| pourquoi au bord | une route montée hors de `Monter` est invisible depuis `Monter`. L'indicateur doit vivre **au-dessus** de ce qu'il surveille |
| le seuil | **une** réponse sans en-tête sur une fenêtre de cinq minutes déclenche une alerte |
| le plancher de bruit | il est **nul**, et c'est tout l'intérêt : `Monter` pose l'en-tête avant la première préoccupation, donc une absence ne peut pas venir d'un timing, d'un échantillonnage ou d'un rejet métier. C'est la différence avec un taux d'erreur, qui mélange refus et pannes et a donc un plancher — correction 2.2/5 |

Un indicateur à plancher de bruit nul peut avoir un seuil de un. C'est rare,
et c'est ce qui le rend exploitable.

### À quelle condition la propriété survit-elle au prochain développeur ?

**À une seule : qu'ajouter une préoccupation ne donne jamais l'occasion de
toucher à `Monter`.**

La propriété ne tient pas parce qu'elle est écrite dans un commentaire ; elle
tient parce que la seule chose qu'un développeur ait à écrire pour ajouter une
préoccupation est un type à deux méthodes et une entrée dans une liste. Tant
que c'est vrai, `Monter` n'est jamais rouvert, et les trois lignes qui
fabriquent la trace restent les trois seules.

Ce qui la casserait, concrètement :

| Changement | Pourquoi il la casse |
|---|---|
| une préoccupation a besoin de modifier la trace | elle demandera un `Trace` mutable, ou un second paramètre, et `Monter` sera rouvert |
| une préoccupation a besoin de court-circuiter la chaîne avec sa propre trace | même chose |
| `Monter` gagne un second rôle (le routage, la configuration) | il devient un endroit qu'on modifie pour d'autres raisons, et les trois lignes finissent au milieu de quarante |

> Une propriété de modèle survit au prochain développeur si et seulement si
> le travail normal ne passe pas par l'endroit qui la porte.

## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | Des préoccupations composables ont besoin d'**une** des trois choses que l'héritage accorde — le sous-typage. Donc une interface, et rien d'autre. |
| ⚫ | L'incorporation a exactement un rôle ici, et ce n'est pas celui qu'on attend : les enveloppes de `http.ResponseWriter`. Une interface à trois méthodes, on en redéfinit deux, on délègue la troisième sans l'écrire. |
| ⚫ | Incorporer une interface ne promeut **que** ses méthodes. Un `http.Flusher` sous-jacent devient invisible, et les flux d'événements serveur cessent de marcher sans message. |
| ⚫ | `Nom()` sur une préoccupation ne sert à rien à l'exécution. Elle sert à ce qu'un **test** puisse vérifier l'ordre, là où une liste de fonctions anonymes ne se vérifie que par relecture. |
| ⚫ | Entre une enveloppe qui incorpore l'interface et une fonction qui prend une liste, trois critères mesurables tranchent — et l'argument décisif est qu'une enveloppe exportée **s'incorpore**, donc invite au piège. |
| ⚫ | Un `defer` s'exécute pendant le déroulement d'une panique. C'est ce qui sauve la ligne de journal, et ce qui l'écrit trop tôt si l'ordre est inversé : `statut=0`, tableau de bord vert, clients en 500. |
| ⚫ | Une limitation de débit placée avant l'authentification n'a pas de client : elle refuse tout le monde, ou elle offre un déni de service dans un seau commun. |
| ⚫ | Une exemption de route est une propriété de la **route**, pas de la préoccupation. Elle se règle par une autre liste, pas par une méthode de plus sur l'interface — qui coûterait six implémentations, dont deux dans d'autres dépôts. |
| ⚫ | Une équipe partenaire doit importer le **vocabulaire**, jamais le composeur. Ce qui l'invite à incorporer notre enveloppe, c'est que nous l'ayons exportée. |
| ⚫ | La préoccupation qui porte une garantie ne peut pas être une préoccupation : par définition, une préoccupation se retire de la liste. Elle appartient au **montage**. |
| ⚫ | Passer la preuve en **paramètre** plutôt qu'en valeur de contexte met le compilateur dans la boucle : l'oubli devient visible au point d'appel. |
| ⚫ | Un test qui attend un échec de compilation doit vérifier la **raison**. Mes trois attentes étaient fausses : le message est `cannot refer to unexported field`, pas `unknown field`. |
| ⚫ | Un indicateur à **plancher de bruit nul** peut avoir un seuil de un. C'est rare, et ça vient de ce qu'il mesure la présence d'un en-tête, pas un mélange de refus et de pannes. |
| ⚫ | Une propriété de modèle survit au prochain développeur si et seulement si le travail normal ne passe pas par l'endroit qui la porte. |
