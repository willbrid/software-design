# Correction 2.3 — Exercice 2 : la chaîne de virements internationaux

> Rappel de l'énoncé : cinq étapes toujours dans le même ordre, trois
> variables selon le corridor et deux fixes. Trois corridors en production,
> un quatrième annoncé. Dix exigences, quatre mesures.

Le module a six paquets, 31 tests, et il passe sous `gofmt -l`, `go vet
./...` et `go test -race -count=1 ./...`. Chaque bloc de Go de cette
correction est un extrait de ce module, inséré par substitution et vérifié
octet pour octet.

## 1. Les paquets, et pourquoi il en faut six

```
domaine     Devise, Montant, Ordre, Cle        — le vocabulaire
virement    Corridor, Traiter, Registre        — le squelette
corridors   VersEuro, VersDollar, Interne, VersNaira
registre    Tous()                             — la racine de composition
avant       la version a ne pas ecrire         — la demonstration
sondage     le controle d'incorporation        — tests seuls
```

La découpe qui demande une justification est la première. Dans l'exercice 1,
l'interface ne nommait que `string` et `time.Time` : du vocabulaire universel,
donc rien à placer en dessous. Ici l'interface doit nommer `Ordre` et
`Montant`.

> Un type du domaine n'est pas un type universel. Dès que la signature
> d'une interface en nomme un, ce type doit vivre dans un paquet que les
> deux côtés peuvent importer **sans se voir**.

```go
// Package domaine porte le vocabulaire des virements.
//
// Il est SOUS les deux cotes. Le squelette le nomme dans son interface, les
// corridors le nomment dans leurs methodes, et aucun des deux n'importe
// l'autre.
//
// C'est la difference avec l'exercice 1 : la-bas l'interface ne nommait que
// des chaines et un time.Time, du vocabulaire universel, donc il n'y avait
// rien a mettre en dessous. Ici l'interface nomme Ordre et Montant. Un type
// du domaine n'est pas un type universel : il faut donc qu'il vive dans un
// paquet que les deux cotes peuvent importer sans se voir.
package domaine
```

### La preuve par `go list`

```
$ go list -f '{{join .Imports " "}}' ./ex2/...
domaine    errors fmt strconv strings
corridors  errors exemple/c23/ex2/domaine fmt strings unicode
virement   errors exemple/c23/ex2/domaine fmt sort
registre   exemple/c23/ex2/corridors exemple/c23/ex2/domaine exemple/c23/ex2/virement
avant      errors exemple/c23/ex2/domaine fmt

$ paquets qui importent exemple/c23/ex2/virement
exemple/c23/ex2/registre
```

**Un seul paquet importe le squelette, et c'est la racine de composition.**
`corridors` ne connaît pas `virement` : il satisfait une interface qu'il ne
nomme pas. Un cinquième corridor peut vivre dans un autre dépôt.

## 2. L'interface du squelette : exactement trois méthodes

```go
// Corridor est l'interface DU SQUELETTE, et elle a exactement trois
// methodes : les trois etapes qui varient par corridor.
//
// Consigner et notifier n'y sont pas, et le critere de la lecon 2.2 le dit
// sans discussion : une methode appartient a la variante si et seulement si
// elle se repond avec les champs de la variante. Un corridor repond Valider
// avec son plafond et son format de compte, Convertir avec sa parite,
// Tarifer avec sa grille. Il ne peut pas repondre Consigner : il faudrait un
// journal, et un journal n'est pas une propriete du corridor FCFA vers EUR.
//
// Le NOM du corridor n'y est pas non plus. Il n'est pas une variation de
// calcul : c'est la cle qui a servi a le trouver, et l'appelant la tient
// deja.
type Corridor interface {
    Valider(o domaine.Ordre) error
    Convertir(m domaine.Montant) (domaine.Montant, error)
    Tarifer(m domaine.Montant) domaine.Montant
}
```

### Pourquoi consigner et notifier n'y sont pas (exigence 3)

Le critère de la leçon 2.2 répond sans discussion :

> Une méthode appartient à la variante **si et seulement si elle se répond
> avec les champs de la variante**.

| Étape | Avec quoi le corridor y répond | Dans l'interface ? |
|---|---|---|
| valider | son plafond, son format de compte | **oui** |
| convertir | sa parité | **oui** |
| tarifer | sa grille | **oui** |
| consigner | il faudrait un journal, et un journal n'est pas une propriété du corridor FCFA→EUR | non |
| notifier | il faudrait une passerelle | non |

Les deux dernières sont des **ports de sortie**. Les mettre dans `Corridor`
obligerait chaque corridor à porter un journal, donc à être construit avec
lui, donc à exister en autant d'exemplaires qu'il y a de journaux.

Et le **nom** du corridor n'y est pas non plus, alors qu'il apparaît au
journal. Il n'est pas une variation de calcul : c'est la clé qui a servi à
trouver le corridor, et l'appelant la tient déjà. Une méthode `Nom()` aurait
permis au corridor FCFA→EUR de se déclarer FCFA→USD.

## 3. Le squelette

```go
// Traiter execute les six etapes, dans l'ordre.
func Traiter(cle string, o domaine.Ordre, d Dependances) (Resultat, error) {
    if err := d.verifier(); err != nil {
        return Resultat{}, err
    }
    corridor, err := d.Registre.Pour(cle)
    if err != nil {
        return Resultat{}, err
    }

    // 1. valider
    if err := corridor.Valider(o); err != nil {
        return Resultat{}, d.refuser(cle, o, err)
    }

    // 2. verifier la liste des personnes sanctionnees
    for _, nom := range []string{o.Donneur, o.Beneficiaire} {
        sanctionne, err := d.Sanctions.EstSanctionne(nom)
        if err != nil {
            return Resultat{}, fmt.Errorf("virement : liste des sanctions : %w", err)
        }
        if sanctionne {
            return Resultat{}, d.refuser(cle, o,
                fmt.Errorf("%w : %q", ErrSanctionne, nom))
        }
    }

    // 3. convertir
    cible, err := corridor.Convertir(o.Montant)
    if err != nil {
        return Resultat{}, d.refuser(cle, o, err)
    }

    // 4. tarifer
    frais := corridor.Tarifer(o.Montant)

    // 5. consigner
    ecriture := Ecriture{
        Reference: o.Reference,
        Corridor:  cle,
        Source:    o.Montant,
        Cible:     cible,
        Frais:     frais,
        Issue:     IssueAcceptee,
    }
    if err := d.Journal.Consigner(ecriture); err != nil {
        return Resultat{}, fmt.Errorf("%w : %v", ErrConsignation, err)
    }

    // 6. notifier
    avis := Avis{
        Reference:    o.Reference,
        Destinataire: o.Donneur,
        Texte: fmt.Sprintf("virement %s accepte : %s debites, %s credites, frais %s",
            o.Reference, o.Montant, cible, frais),
    }
    notifie := d.Avis.Notifier(avis) == nil

    return Resultat{Corridor: cle, Credite: cible, Frais: frais, Notifie: notifie}, nil
}
```

Trois décisions à relever, parce que chacune a été mise à l'épreuve par la
campagne de modifications.

**Les dépendances nulles sont refusées avant la première étape.** Sans ce
bloc, un journal nul passe les quatre premières étapes et panique à la
cinquième : le virement est à moitié fait, le client est débité et rien n'est
tracé.

**Un journal qui refuse annule le virement.** Une opération absente du journal
ne se rapproche pas, donc elle n'a pas eu lieu. Mesuré :

```
=== RUN   TestUnJournalQuiRefuseAnnuleLeVirement
    virement_test.go:223: virement : consignation impossible : disque plein
--- PASS
```

**Un avis qui échoue n'annule pas le virement**, et l'échec se lit dans le
résultat, pas dans l'erreur :

```
=== RUN   TestUnAvisQuiEchoueNAnnulePasLeVirement
    virement_test.go:240: resultat : corridor=XAF→EUR credite=15,26 EUR
                          frais=5 000 XAF notifie=false
--- PASS
```

Rendre à la fois un résultat et une erreur obligerait chaque appelant à
choisir lequel des deux il croit. Un `bool` dans le résultat ne laisse pas ce
choix.

## 4. Un corridor absent est une erreur (exigence 4)

```go
// Pour rend le corridor de la cle, ou ErrCorridorInconnu.
func (r Registre) Pour(cle string) (Corridor, error) {
    if len(r) == 0 {
        return nil, ErrRegistreAbsent
    }
    c, connu := r[cle]
    if !connu {
        return nil, fmt.Errorf("%w : %q (connus : %v)",
            ErrCorridorInconnu, cle, r.Cles())
    }
    return c, nil
}
```

En une phrase, avec l'incident de la correction 2.2/5 : **un repli silencieux
coûte onze jours de détection parce que rien ne distingue un repli qui marche
d'un code qui marche** — là-bas, 214 000 réponses fausses derrière un tableau
de bord vert ; ici, un virement vers Lagos tarifé au corridor SEPA.

```
=== RUN   TestUnCorridorInconnuEstUneErreur
    virement_test.go:143: virement : corridor inconnu : "XAF→GBP" (connus : [XAF→EUR])
--- PASS
```

Le message liste les clés connues, **triées**. Un message dont l'ordre change
à chaque appel n'est pas un message : il n'est pas diffable entre deux
incidents.

## 5. Le test d'ordre, observé depuis le point intermédiaire (exigence 1)

La correction 2.2 a vu une modification « sélection journalisée après
l'appel » survivre **deux fois**, parce que le test d'ordre comparait deux
journaux séparés, où l'ordre était identique dans les deux sens. La leçon
publiée était : *un test d'ordre s'observe depuis le point intermédiaire*.

Ici, les quatre doubles écrivent dans la **même** trace :

```go
// trace est le POINT INTERMEDIAIRE, et il est unique.
//
// La correction 2.2 a vu une modification survivre deux fois parce que le
// test d'ordre comparait deux journaux separes : l'ordre y etait identique
// dans les deux sens. Ici les quatre doubles ecrivent dans la MEME trace, et
// un test d'ordre s'observe depuis ce point-la.
type trace struct {
    etapes []string
}

func (t *trace) noter(f string, a ...any) { t.etapes = append(t.etapes, fmt.Sprintf(f, a...)) }

// faux est le double du corridor, du journal, des sanctions et de l'avis.
//
// Un seul type pour les quatre : ce n'est pas de l'economie, c'est ce qui
// garantit que les quatre ecrivent dans la meme trace.
type faux struct {
    t              *trace
    refusValider   error
    refusConvertir error
    refusJournal   error
    refusAvis      error
    sanctionne     string
    erreurListe    error
    ecritures      []virement.Ecriture
    avis           []virement.Avis
}
```

```go
// TestLOrdreDesSixEtapes verifie l'exigence 1 et l'exigence 6 d'un coup.
func TestLOrdreDesSixEtapes(t *testing.T) {
    tr := &trace{}
    f := &faux{t: tr}
    r, err := virement.Traiter(cle, ordre(), monter(f))
    if err != nil {
        t.Fatalf("Traiter : %v", err)
    }
    attendu := []string{
        "valider:V-1",
        "sanctions:Abena",
        "sanctions:Dupont",
        "convertir:1 000 000 XAF",
        "tarifer:1 000 000 XAF",
        "consigner:XAF→EUR:acceptee",
        "notifier:Abena",
    }
    if got := strings.Join(tr.etapes, " | "); got != strings.Join(attendu, " | ") {
        t.Fatalf("ordre des etapes :\n  obtenu  %s\n  attendu %s", got, strings.Join(attendu, " | "))
    }
    if !r.Notifie {
        t.Error("Notifie devrait etre vrai")
    }
    t.Logf("trace : %s", strings.Join(tr.etapes, " | "))
}
```

```
=== RUN   TestLOrdreDesSixEtapes
    virement_test.go:129: trace : valider:V-1 | sanctions:Abena | sanctions:Dupont
                          | convertir:1 000 000 XAF | tarifer:1 000 000 XAF
                          | consigner:XAF→EUR:acceptee | notifier:Abena

```

Un seul type pour les quatre doubles. Ce n'est pas de l'économie de code :
c'est ce qui **garantit** que les quatre écrivent dans la même trace, et donc
que l'ordre mesuré est l'ordre réel.

La campagne le confirme : la modification « convertir avant valider » est
attrapée **par ce test seul**. Aucun autre ne la voit, parce que le résultat
final est identique dans les deux ordres.

## 6. Le corridor retenu est consigné dans les deux issues (exigence 6)

L'exigence dit « le journal enregistre le corridor retenu **avant** la
conversion ». Prise au pied de la lettre, elle contredit l'ordre du tableau de
l'énoncé, où consigner est l'étape 4. Ce que l'exigence demande vraiment,
c'est que **le journal ne contienne jamais une opération sans corridor**, y
compris quand la conversion échoue. La clé est décidée avant la première
étape ; elle est recopiée dans l'écriture des deux issues.

```go
// refuser consigne le refus puis rend la cause.
//
// Le corridor retenu est dans l'ecriture, et le motif aussi. Une operation
// refusee laisse donc exactement une ligne au journal.
func (d Dependances) refuser(cle string, o domaine.Ordre, cause error) error {
    e := Ecriture{
        Reference: o.Reference,
        Corridor:  cle,
        Source:    o.Montant,
        Issue:     IssueRefusee,
        Motif:     cause.Error(),
    }
    if err := d.Journal.Consigner(e); err != nil {
        return fmt.Errorf("%w : %v (cause initiale : %v)", ErrConsignation, err, cause)
    }
    return cause
}
```

```go
// TestLeCorridorRetenuEstConsigneDansLesDeuxIssues verifie l'exigence 6 par
// sa face difficile : le corridor est decide AVANT la conversion, donc il
// est au journal meme quand la conversion echoue.
func TestLeCorridorRetenuEstConsigneDansLesDeuxIssues(t *testing.T) {
    panne := errors.New("fil de cotation indisponible")
    for _, c := range []struct {
        nom            string
        refusConvertir error
        issue          virement.Issue
    }{
        {"conversion reussie", nil, virement.IssueAcceptee},
        {"conversion en panne", panne, virement.IssueRefusee},
    } {
        t.Run(c.nom, func(t *testing.T) {
            f := &faux{t: &trace{}, refusConvertir: c.refusConvertir}
            _, err := virement.Traiter(cle, ordre(), monter(f))
            if (err != nil) != (c.refusConvertir != nil) {
                t.Fatalf("err = %v", err)
            }
            if len(f.ecritures) != 1 {
                t.Fatalf("%d ecriture(s), attendu exactement 1", len(f.ecritures))
            }
            e := f.ecritures[0]
            if e.Corridor != cle {
                t.Errorf("Corridor = %q, attendu %q", e.Corridor, cle)
            }
            if e.Issue != c.issue {
                t.Errorf("Issue = %q, attendu %q", e.Issue, c.issue)
            }
            t.Logf("ecriture : corridor=%s issue=%s motif=%q", e.Corridor, e.Issue, e.Motif)
        })
    }
}
```

```
=== RUN   TestLeCorridorRetenuEstConsigneDansLesDeuxIssues
    virement_test.go:175: ecriture : corridor=XAF→EUR issue=acceptee motif=""
    virement_test.go:175: ecriture : corridor=XAF→EUR issue=refusee
```

Et **exactement une** écriture par issue. Un refus qui laisserait deux lignes,

## 7. Les corridors

### Les parités en entiers, pas en flottants

```go
// parite est le rapport de conversion, ecrit en entiers.
//
// Une parite en float64 serait plus courte a lire et fausse a l'arrondi :
// 655.957 n'est pas representable en binaire, et la conversion d'un million
// de francs se decalerait d'un centime selon l'ordre des operations. Les
// deux entiers sont exacts.
type parite struct {
    numerateur   int64
    denominateur int64
}

// appliquer rend le nombre de sous-unites cibles pour unites sources.
//
// L'arrondi est au plus proche, moitie vers le haut. C'est une DECISION :
// voir TestLaConversionNEstPasAdditive, qui mesure ce qu'elle coute.
func (p parite) appliquer(unites int64) int64 {
    produit := unites * p.numerateur
    return (produit + p.denominateur/2) / p.denominateur
}
```

La parité FCFA/EUR est **fixe par convention monétaire** : 1 EUR = 655,957
FCFA. En `float64`, 655.957 n'est pas représentable, et la conversion d'un
million de francs se décale selon l'ordre des opérations. Deux entiers sont
exacts :

```
=== RUN   TestLeTemoin
    sondage_test.go:163: 655 957 XAF = 1 000,00 EUR, a la parite fixe
--- PASS
```

C'est le seul des quatre corridors dont la parité peut être une constante. Le
dollar et le naira sont **cotés**, donc paramètres — et on verra en 8 que ce
détail décide de ce que le compilateur trouve.

### L'arrondi est une décision, et elle a un coût

```go
// TestLArrondiEstAuPlusProche attrape la modification 11.
//
// Cinq francs valent 0,0076 euro. Au plus proche, c'est un centime ; par
// troncature, c'est zero. Aucun des montants des autres tests ne separe les
// deux, parce qu'ils sont tous assez gros pour que le reste se perde.
func TestLArrondiEstAuPlusProche(t *testing.T) {
    c := corridors.NouveauVersEuro()
    for _, cas := range []struct {
        francs  int64
        attendu int64
    }{
        {3, 0}, // 0,00457 euro
        {5, 1}, // 0,00762 euro
        {655_957, 100_000},
    } {
        m, err := c.Convertir(domaine.MustNouveau(domaine.FCFA, cas.francs))
        if err != nil {
            t.Fatalf("Convertir(%d) : %v", cas.francs, err)
        }
        if m.Unites() != cas.attendu {
            t.Errorf("%d XAF = %d centimes, attendu %d", cas.francs, m.Unites(), cas.attendu)
        }
    }
    t.Log("3 XAF -> 0 centime, 5 XAF -> 1 centime : l'arrondi est au plus proche")
}
```

```
=== RUN   TestLaConversionNEstPasAdditive
    registre_test.go:174: 501 ecarts sur 1001 montants :
                          convertir(n)+convertir(n) != convertir(2n)
--- PASS
```

**Un montant sur deux.** Aucun arrondi ne supprime ça ; le choisir en
connaissance de cause, oui. Le test interdit que l'écart passe à zéro, parce
qu'un zéro signifierait que l'arrondi a disparu.

### L'identité est une étape, pas une absence d'étape

```go
// Convertir rend le montant INCHANGE.
//
// Ce n'est pas une etape vide qu'on aurait pu sauter : le squelette appelle
// les six etapes pour tous les corridors, et c'est ce qui fait qu'ajouter un
// corridor ne touche pas le squelette. Un squelette qui demanderait « est-ce
// que ce corridor convertit ? » aurait un if par corridor, c'est-a-dire
// exactement ce que l'interface a supprime.
func (c Interne) Convertir(m domaine.Montant) (domaine.Montant, error) {
    if m.Devise() != domaine.FCFA {
        return domaine.Montant{}, fmt.Errorf("%w : %s", ErrDeviseSource, m.Devise())
    }
    return m, nil
}
```

Un squelette qui demanderait « est-ce que ce corridor convertit ? » aurait un
`if` par corridor, c'est-à-dire exactement ce que l'interface a supprimé.

### Les quatre corridors, bout à bout

```
=== RUN   TestLesQuatreCorridorsBoutAbout

    XAF→USD : 1 000 000 XAF → 1 660,00 USD, frais 12 000 XAF

    XAF→NGN : 1 000 000 XAF → 2 550 000,00 NGN, frais 9 000 XAF
```

Deux de ces quatre lignes attendues ont été écrites **fausses** de ma main à
la première rédaction : 1 524,39 au lieu de 1 524,49, par transposition, et
25 500 NGN au lieu de 2 550 000, par confusion entre le naira et le kobo. Le
test a attrapé mon arithmétique, pas celle du code.

> Une attente calculée à la main est une mesure comme une autre : elle se
> vérifie. Dans un tableau de cas, c'est l'attente qui est le plus souvent
> fausse, pas le code.

### Ce que les formats de compte ne distinguent pas

```
=== RUN   TestLesFormatsDeCompteSontDistincts
    registre_test.go:143: 11 refus sur 12 paires croisees
--- PASS
```

Onze sur douze, pas douze. Le NUBAN nigérian à dix chiffres passe la
validation du corridor dollar, qui accepte huit à dix-sept chiffres. **Le
compte seul ne suffit donc pas à distinguer deux corridors**, et c'est une
limite qu'il valait mieux écrire dans le test que découvrir en production.

## 8. Mesure 7 : ajouter le quatrième corridor

Mesuré dans le sens de l'ajout, sur un instantané du module à trois
corridors, vert.

### Les fichiers de production

| | |
|---|---|
| fichiers neufs | **1** — `corridors/naira.go`, 59 lignes |
| fichiers modifiés | **1** — `registre/registre.go` |
| corridors existants touchés | **0** |
| lignes du squelette touchées | **0** |

```diff
-func Tous(centimesParMilleFrancsUSD int64) virement.Registre {
+func Tous(centimesParMilleFrancsUSD, kobosParFrancNGN int64) virement.Registre {
     return virement.Registre{
         domaine.Cle(domaine.FCFA, domaine.EUR):  corridors.NouveauVersEuro(),
         domaine.Cle(domaine.FCFA, domaine.USD):  corridors.NouveauVersDollar(centimesParMilleFrancsUSD),
         domaine.Cle(domaine.FCFA, domaine.FCFA): corridors.NouveauInterne(),
+        domaine.Cle(domaine.FCFA, domaine.NGN):  corridors.NouveauVersNaira(kobosParFrancNGN),
     }
 }
```

### Ce que le compilateur trouve

**Étape A — le fichier seul.** `go build ./...` : 0 erreur. `go vet ./...` :
0. Tous les tests verts. Un corridor écrit et jamais inscrit est du code mort
que rien ne signale.

**Étape B — l'inscription au registre.** `go build` sur le code de
production : **toujours 0 erreur**. Une entrée de table n'est pas une
signature.

Mais la compilation des **tests** casse, à trois endroits dans deux
paquets :

```
vet: ex2/registre/registre_test.go:29:51: not enough arguments in call to registre.Tous
    have (number)
    want (int64, int64)
vet: ex2/sondage/sondage_test.go:150:44: not enough arguments in call to registre.Tous
    have (number)
    want (int64, int64)
```

Et c'est un accident heureux dont il faut connaître la cause : le compilateur
ne trouve ces trois appels **que parce que la parité du naira est un
paramètre**. Le corridor euro, dont la parité est une constante, serait passé
en silence complet.

> Le compilateur trouve les changements de **signature**, pas les ajouts
> d'entrée dans une table. Un corridor à parité fixe s'ajoute sans qu'une
> seule ligne du reste du programme ne bronche.

**Étape C — les appels corrigés, les tests inchangés.** Un seul test tombe,
et c'est celui qui existe pour ça :

```
--- FAIL: TestLesCorridorsConnus
    registre_test.go:46: corridors = [XAF→EUR XAF→NGN XAF→USD XAF→XAF],
                         attendu [XAF→EUR XAF→USD XAF→XAF]
```

L'ordre complet est donc : **compilation des tests → la liste des corridors →
le cas de comportement à ajouter**. Le dernier n'est pas une chute, c'est du
travail : la ligne NGN du tableau bout-à-bout, et le compte de paires croisées
qui passe de 6 à 11.

`TestLesCorridorsConnus` **remplace le compilateur**. Sans lui, un corridor
inscrit par accident — un mauvais copier-coller de clé, une parité oubliée —
part en production sans que personne ne l'ait décidé.

## 9. Mesure 8 : ajouter une sixième étape

« Vérifier la liste des personnes sanctionnées », qui ne varie pas par
corridor. Même protocole : instantané à cinq étapes, vert, puis ajout du seul
code de production.

| | |
|---|---|
| fichiers de production modifiés | **1** — `virement/virement.go` (+31 lignes, −9) |
| corridors modifiés | **0** |
| erreurs de compilation | **0** |
| tests de premier niveau rouges | **9**, plus 6 sous-tests, dans 2 paquets |

Zéro erreur de compilation, et pourtant neuf tests rouges — tous avec le même
message :

```
--- FAIL: TestLesQuatreCorridorsBoutAbout/XAF→EUR
    registre_test.go:76: Traiter : virement : dependance absente : liste des sanctions
```

**L'asymétrie est le résultat de la mesure.** Ajouter un champ à une structure
ne casse aucun littéral existant en Go : les tests compilent et passent une
dépendance nulle. C'est le refus explicite du squelette qui les arrête tous,
d'un coup, avec un message qui nomme ce qui manque.

L'alternative aurait été une liste vide par défaut. Elle donnait **zéro test
rouge** — et une chaîne de virements internationaux qui ne vérifie plus
personne, sans qu'une seule ligne ne le dise.

> Zéro test rouge n'est pas une bonne nouvelle quand on vient d'ajouter une
> étape. C'est le symptôme d'un défaut silencieux.

Zéro corridor touché, en revanche, est la bonne nouvelle, et c'est
exactement ce que l'interface à trois méthodes achetait : une étape fixe de
plus ne concerne pas les variantes.

## 10. L'incorporation est interdite, et c'est vérifié (exigence 5)

L'exigence demande qu'aucun type n'incorpore un type qui a des appels
internes. La forme forte est plus facile à vérifier et plus solide : **aucun
type de production n'incorpore rien**. Elle ne dépend pas de ce que les
méthodes du type incorporé feront dans six mois.

```go
// Package sondage repond a l'exigence 5 : aucun type de l'exercice 2
// n'incorpore un type qui a des appels internes.
//
// Il le repond par la forme forte : aucun type n'incorpore RIEN. C'est plus
// facile a verifier que le critere complet, et c'est plus solide, parce que
// ca ne depend pas de ce que les methodes du type incorpore feront dans six
// mois.
package sondage

import (
    "go/ast"
    "go/parser"
    "go/token"
    "path/filepath"
    "sort"
    "strings"
    "testing"

    // Ces quatre imports sont la GARDE DU CACHE, comme dans la correction
    // 2.1 : un test qui lit des fichiers ne depend de rien au sens du
    // compilateur, donc Go a le droit de rendre un resultat perime. Les
    // importer cree la dependance, et le temoin ci-dessous les utilise.
    "exemple/c23/ex2/corridors"
    "exemple/c23/ex2/domaine"
    "exemple/c23/ex2/registre"
    "exemple/c23/ex2/virement"
)

// paquetsDeProduction sont les quatre paquets sondes. Le paquet avant n'y
// est PAS : il incorpore exprimement, c'est tout son objet.
var paquetsDeProduction = []string{"domaine", "virement", "corridors", "registre"}

    Struct  string

```

```

--- PASS
=== RUN   TestLeSondageVoitUneIncorporationQuandIlYEnA
```

Deux garde-fous que la leçon 2.3 a payés cher :

1. **Le test négatif.** Sans lui, un sondage qui ne trouve jamais rien passe
   au vert pour la mauvaise raison. La leçon a eu le cas : sa première version
   confondait deux types homonymes, et le rapport paraissait juste.
2. **La garde du cache.** Un test qui lit des fichiers ne dépend de rien au
   sens du compilateur, donc Go a le droit de rendre un résultat périmé. Les
   quatre paquets sondés sont **importés**, et `TestLeTemoin` les utilise
   vraiment.

Ce sondage gagne sa place dans la campagne : la modification *« `Dependances`
`Journal` devient un champ incorporé »* compile, se comporte à l'identique, et
**il est le seul des 31 tests à la voir**. Elle ferait de `Dependances` un
`virement.Journal` — une interface que personne n'a voulue.

## 11. La démonstration : la version à ne pas écrire (exigence 9)

```go
// Base porte le squelette et les valeurs par defaut des trois etapes.
type Base struct {
    Plafond domaine.Montant
    Trace   *[]string
}

// valider est l'etape 1 par defaut : un compte non vide et le plafond.
func (b Base) valider(o domaine.Ordre) error {
    b.noter("valider/base")
    if o.Compte == "" {
        return fmt.Errorf("%w : compte vide", ErrRefuse)
    }
    if o.Montant.Depasse(b.Plafond) {
        return fmt.Errorf("%w : %s au-dela de %s", ErrRefuse, o.Montant, b.Plafond)
    }
    return nil
}

// convertir est l'etape 2 par defaut : l'identite.
func (b Base) convertir(m domaine.Montant) (domaine.Montant, error) {
    b.noter("convertir/base")
    return m, nil
}

// tarifer est l'etape 3 par defaut : cinq cents francs.
func (b Base) tarifer(m domaine.Montant) domaine.Montant {
    b.noter("tarifer/base")
    return domaine.MustNouveau(domaine.FCFA, 500)
}

// Traiter est le squelette.
//
// Les trois appels sont resolus A LA COMPILATION vers les methodes de Base,
// parce que le recepteur b est de type Base et que Base ne sait rien de ce
// qui l'incorpore. C'est le meme mecanisme que mecanique.Base de la lecon
// 2.3, applique a cinq etapes au lieu d'une.
func (b Base) Traiter(o domaine.Ordre) (Resultat, error) {
    if err := b.valider(o); err != nil {
        return Resultat{}, err
    }
    cible, err := b.convertir(o.Montant)
    if err != nil {
        return Resultat{}, err
    }
    frais := b.tarifer(o.Montant)
    b.noter("consigner")
    b.noter("notifier")
    return Resultat{Credite: cible, Frais: frais}, nil
}
```

```
=== RUN   TestLesTroisCorridorsRendentLeMemeResultat
    avant_test.go:43: VersEuro   credite=1 000 000 XAF frais=500 XAF
    avant_test.go:43: VersDollar credite=1 000 000 XAF frais=500 XAF
    avant_test.go:43: Interne    credite=1 000 000 XAF frais=500 XAF
--- PASS
=== RUN   TestLaTraceNeContientQueLesEtapesDeLaBase
    avant_test.go:78: trace de VersEuro.Traiter : valider/base | convertir/base
                      | tarifer/base | consigner | notifier
--- PASS
=== RUN   TestLesMethodesSurchargeesSontCorrectes
    interne_test.go:36: les trois etapes surchargees sont correctes, et aucune
```

Trois faits, dans l'ordre où ils apparaîtraient en production :

- les trois corridors rendent **le même résultat**, en FCFA, frais de 500 ;
- la trace ne contient **que** les étapes de `Base` ;
- les étapes « surchargées » sont **correctes**, et aucune ne tourne.

C'est l'exercice 1 à l'échelle de cinq étapes. Le seul des trois types qui se
comporte comme son auteur l'attend est `Interne`, **par accident** : il ne
surcharge rien.

Les deux dernières lignes sont les plus instructives. Une modification qui
supprime une branche inatteignable **survit toujours**, et la réponse n'est
pas un test : c'est la suppression de la branche. C'est la même conclusion
que la correction 2.2/3, où `p > plafond` devenu `p >= plafond` survivait
parce que les deux rendaient le même nombre à l'égalité, et où la réponse
avait été de remplacer la branche par `min`.

```go
// grille est la tarification : une part fixe et une part en dix-milliemes.
//
// Il y avait un troisieme champ, plancher, et la campagne de modifications
// l'a tue : dans les quatre grilles, fixe valait plancher, donc la part fixe
// etait DEJA le plancher et la branche ne pouvait pas s'executer. Une
// modification qui supprime une branche inatteignable survit toujours, et la
// reponse n'est pas un test : c'est la suppression de la branche.
type grille struct {
    fixe           int64
    dixMilliemes   int64
    plafondDeFrais int64
}

// appliquer rend les frais en sous-unites de la devise source.
func (g grille) appliquer(unites int64) int64 {
    frais := g.fixe + unites*g.dixMilliemes/10_000
    if g.plafondDeFrais > 0 && frais > g.plafondDeFrais {
        frais = g.plafondDeFrais
    }
    return frais
}
```

## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | Quand l'interface d'un squelette nomme un type du domaine, ce type descend dans un paquet que les deux côtés importent sans se voir. Un type du domaine n'est pas un type universel. |
| ⚫ | Une méthode appartient à la variante **si et seulement si** elle se répond avec les champs de la variante. Un journal n'est pas une propriété du corridor FCFA→EUR. |
| ⚫ | Le nom d'une variante n'est pas une de ses méthodes : c'est la clé qui a servi à la trouver, et l'appelant la tient déjà. |
| ⚫ | Un test d'ordre s'observe depuis le **point intermédiaire** : un seul double pour toutes les étapes, une seule trace. Sinon l'ordre est identique dans les deux sens. |
| ⚫ | Le compilateur trouve les changements de **signature**, pas les ajouts d'entrée dans une table ni les ajouts de champ dans une structure. Ce qui reste se teste. |
| ⚫ | **Zéro test rouge après l'ajout d'une étape est un symptôme**, pas un succès : c'est la signature d'un défaut par défaut. |
| ⚫ | Une parité se code en deux entiers. `655.957` n'est pas représentable en `float64`, et l'erreur se voit au millier de francs. |
| ⚫ | Un arrondi n'est jamais additif. Mesuré : 501 écarts sur 1 001 montants. Le choisir, oui ; l'ignorer, non. |
| ⚫ | Dans un tableau de cas, c'est l'attente écrite à la main qui est le plus souvent fausse. Deux sur quatre, ici. |
| ⚫ | Une modification qui supprime une branche inatteignable survit toujours. La réponse est la suppression de la branche, pas un test. |
| ⚫ | Un sondage structurel a besoin de son **test négatif** et de sa **garde du cache**, sinon il passe au vert pour la mauvaise raison. |
| ⚫ | L'identité est une étape, pas une absence d'étape. Un `if` par corridor dans le squelette annule ce que l'interface a acheté. |
