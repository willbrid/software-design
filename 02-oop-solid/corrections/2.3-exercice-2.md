# Correction 2.3 — Exercice 2 : la chaîne de virements internationaux

> Rappel de l'énoncé : cinq étapes toujours dans le même ordre, trois
> variables selon le corridor et deux fixes. Trois corridors en production,
> un quatrième annoncé. Dix exigences, quatre mesures.

Le module a six paquets, 31 tests, et il passe sous `gofmt -l`, `go vet
./...` et `go test -race -count=1 ./...`. Chaque bloc de Go de cette
correction est un extrait de ce module, inséré par substitution et vérifié
octet pour octet.

## 1. Les paquets, et pourquoi il en faut six

```
domain     Currency, Amount, Order, Key        — le vocabulaire
transfer    Corridor, Handle, Registry        — le squelette
corridors   VersEuro, VersDollar, Internal, VersNaira
registry    Tous()                             — la racine de composition
avant       la version a ne pas ecrire         — la demonstration
sondage     le controle d'incorporation        — tests seuls
```

La découpe qui demande une justification est la première. Dans l'exercice 1,
l'interface ne nommait que `string` et `time.Time` : du vocabulaire universel,
donc rien à placer en dessous. Ici l'interface doit nommer `Order` et
`Amount`.

> Un type du domaine n'est pas un type universel. Dès que la signature
> d'une interface en nomme un, ce type doit vivre dans un paquet que les
> deux côtés peuvent importer **sans se voir**.

```go
// Package domain holds the vocabulary of transfers.
//
// It is BELOW both sides. The skeleton names it in its interface, the
// corridors name it in their methods, and neither imports
// the other.
//
// It is the difference with exercise 1: there the interface named only
// strings and a time.Time, universal vocabulary, so there was
// nothing to put below. Here the interface names Order and Amount. A type
// of the domain is not a universal type: so it must live in a
// package both sides can import without seeing each other.
package domain
```

### La preuve par `go list`

```
$ go list -f '{{join .Imports " "}}' ./ex2/...
domain    errors fmt strconv strings
corridors  errors example/c23/ex2/domain fmt strings unicode
transfer   errors example/c23/ex2/domain fmt sort

avant      errors example/c23/ex2/domain fmt

$ paquets qui importent example/c23/ex2/transfer
example/c23/ex2/registry
```

**Un seul paquet importe le squelette, et c'est la racine de composition.**
`corridors` ne connaît pas `transfer` : il satisfait une interface qu'il ne
nomme pas. Un cinquième corridor peut vivre dans un autre dépôt.

## 2. L'interface du squelette : exactement trois méthodes

```go
// Corridor is the SKELETON's interface, and it has exactly three
// methods: the three steps that vary by corridor.
//
// Record and notify are not there, and the criterion of lesson 2.2 says so
// without discussion: a method belongs to the variant if and only if
// it is answered with the variant's fields. A corridor answers Validate
// with its cap and its account format, Convert with its parity,
// Price with its grid. It cannot answer Record: it would need a
// journal, and a journal is not a property of the FCFA to EUR corridor.
//
// The corridor's NAME is not there either. It is not a variation of the
// computation: it is the key that served to find it, and the caller holds it
// already.
type Corridor interface {
    Validate(o domain.Order) error
    Convert(m domain.Amount) (domain.Amount, error)
    Price(m domain.Amount) domain.Amount
}
```

### Pourquoi consigner et notifier n'y sont pas (exigence 3)

Le critère de la leçon 2.2 répond sans discussion :

> Une méthode appartient à la variante **si et seulement si elle se répond
> avec les champs de la variante**.

| Étape | Avec quoi le corridor y répond | Dans l'interface ? |
|---|---|---|
| valider | son plafond, son format de compte | **oui** |
| convertir | sa parité | **oui** |
| tarifer | sa grille | **oui** |
| consigner | il faudrait un journal, et un journal n'est pas une propriété du corridor FCFA→EUR | non |
| notifier | il faudrait une passerelle | non |

Les deux dernières sont des **ports de sortie**. Les mettre dans `Corridor`
obligerait chaque corridor à porter un journal, donc à être construit avec
lui, donc à exister en autant d'exemplaires qu'il y a de journaux.

Et le **nom** du corridor n'y est pas non plus, alors qu'il apparaît au
journal. Il n'est pas une variation de calcul : c'est la clé qui a servi à
trouver le corridor, et l'appelant la tient déjà. Une méthode `Name()` aurait
permis au corridor FCFA→EUR de se déclarer FCFA→USD.

## 3. Le squelette

```go
// Handle runs the six steps, in order.
func Handle(key string, o domain.Order, d Dependencies) (Result, error) {
    if err := d.check(); err != nil {
        return Result{}, err
    }
    corridor, err := d.Registry.For(key)
    if err != nil {
        return Result{}, err
    }

    // 1. validate
    if err := corridor.Validate(o); err != nil {
        return Result{}, d.refuse(key, o, err)
    }

    // 2. check the list of sanctioned people
    for _, name := range []string{o.Payer, o.Beneficiary} {
        sanctioned, err := d.Sanctions.IsSanctioned(name)
        if err != nil {
            return Result{}, fmt.Errorf("transfer: sanctions list: %w", err)
        }
        if sanctioned {
            return Result{}, d.refuse(key, o,
                fmt.Errorf("%w: %q", ErrSanctioned, name))
        }
    }

    // 3. convert
    target, err := corridor.Convert(o.Amount)
    if err != nil {
        return Result{}, d.refuse(key, o, err)
    }

    // 4. price
    fees := corridor.Price(o.Amount)

    // 5. record
    entry := Entry{
        Reference: o.Reference,
        Corridor:  key,
        Source:    o.Amount,
        Target:    target,
        Fees:      fees,
        Outcome:   OutcomeAccepted,
    }
    if err := d.Journal.Record(entry); err != nil {
        return Result{}, fmt.Errorf("%w: %v", ErrRecord, err)
    }

    // 6. notify
    notice := Notice{
        Reference: o.Reference,
        Recipient: o.Payer,
        Text: fmt.Sprintf("transfer %s accepted: %s debited, %s credited, fees %s",
            o.Reference, o.Amount, target, fees),
    }
    notified := d.Notice.Notify(notice) == nil

    return Result{Corridor: key, Credited: target, Fees: fees, Notified: notified}, nil
}
```

Trois décisions à relever, parce que chacune a été mise à l'épreuve par la
campagne de modifications.

**Les dépendances nulles sont refusées avant la première étape.** Sans ce
bloc, un journal nul passe les quatre premières étapes et panique à la
cinquième : le virement est à moitié fait, le client est débité et rien n'est
tracé.

**Un journal qui refuse annule le virement.** Une opération absente du journal
ne se rapproche pas, donc elle n'a pas eu lieu. Mesuré :

```
=== RUN   TestUnJournalQuiRefuseAnnuleLeVirement
    transfer_test.go:223: transfer : consignation impossible : disque plein
--- PASS
```

**Un avis qui échoue n'annule pas le virement**, et l'échec se lit dans le
résultat, pas dans l'erreur :

```
=== RUN   TestUnAvisQuiEchoueNAnnulePasLeVirement
    transfer_test.go:240: resultat : corridor=XAF→EUR credite=15,26 EUR
                          frais=5 000 XAF notifie=false
--- PASS
```

Rendre à la fois un résultat et une erreur obligerait chaque appelant à
choisir lequel des deux il croit. Un `bool` dans le résultat ne laisse pas ce
choix.

## 4. Un corridor absent est une erreur (exigence 4)

```go
// For returns the key's corridor, or ErrUnknownCorridor.
func (r Registry) For(key string) (Corridor, error) {
    if len(r) == 0 {
        return nil, ErrMissingRegistry
    }
    c, known := r[key]
    if !known {
        return nil, fmt.Errorf("%w: %q (known: %v)",
            ErrUnknownCorridor, key, r.Keys())
    }
    return c, nil
}
```

En une phrase, avec l'incident de la correction 2.2/5 : **un repli silencieux
coûte onze jours de détection parce que rien ne distingue un repli qui marche
d'un code qui marche** — là-bas, 214 000 réponses fausses derrière un tableau
de bord vert ; ici, un virement vers Lagos tarifé au corridor SEPA.

```
=== RUN   TestUnCorridorInconnuEstUneErreur
    transfer_test.go:143: transfer : corridor inconnu : "XAF→GBP" (connus : [XAF→EUR])
--- PASS
```

Le message liste les clés connues, **triées**. Un message dont l'ordre change
à chaque appel n'est pas un message : il n'est pas diffable entre deux
incidents.

## 5. Le test d'ordre, observé depuis le point intermédiaire (exigence 1)

La correction 2.2 a vu une modification « sélection journalisée après
l'appel » survivre **deux fois**, parce que le test d'ordre comparait deux
journaux séparés, où l'ordre était identique dans les deux sens. La leçon
publiée était : *un test d'ordre s'observe depuis le point intermédiaire*.

Ici, les quatre doubles écrivent dans la **même** trace :

```go
// trace is the INTERMEDIATE POINT, and it is unique.
// Correction 2.2 saw a change survive twice because the
// order test compared two separate journals: the order was identical
// both ways. Here the four doubles write into the SAME trace, and
// an order test is observed from that point.
type trace struct {
    steps []string
}

func (t *trace) record(f string, a ...any) { t.steps = append(t.steps, fmt.Sprintf(f, a...)) }

// fake is the double of the corridor, the journal, the sanctions and the notice.
//
// A single type for the four: it is not thrift, it is what
// guarantees that all four write into the same trace.
type fake struct {
    t               *trace
    validateRefusal error
    convertRefusal  error
    journalRefusal  error
    noticeRefusal   error
    sanctioned      string
    errList         error
    entries         []transfer.Entry
    notice          []transfer.Notice
}
```

```go
// TestTheOrderOfTheSixSteps checks requirement 1 and requirement 6 at once.
func TestTheOrderOfTheSixSteps(t *testing.T) {
    tr := &trace{}
    f := &fake{t: tr}
    r, err := transfer.Handle(key, order(), mount(f))
    if err != nil {
        t.Fatalf("Handle: %v", err)
    }
    want := []string{
        "validate:V-1",
        "sanctions:Abena",
        "sanctions:Dupont",
        "convertir:1 000 000 XAF",
        "tarifer:1 000 000 XAF",
        "record:XAF→EUR:accepted",
        "notify:Abena",
    }
    if got := strings.Join(tr.steps, " | "); got != strings.Join(want, " | ") {
        t.Fatalf("order of steps:\n  got  %s\n  want %s", got, strings.Join(want, " | "))
    }
    if !r.Notified {
        t.Error("Notified should be true")
    }
    t.Logf("trace: %s", strings.Join(tr.steps, " | "))
}
```

```
=== RUN   TestTheOrderOfTheSixSteps
    transfer_test.go:129: trace : validate:V-1 | sanctions:Abena | sanctions:Dupont
                          | convertir:1 000 000 XAF | tarifer:1 000 000 XAF
                          | record:XAF→EUR:accepted | notify:Abena
--- PASS
```

Un seul type pour les quatre doubles. Ce n'est pas de l'économie de code :
c'est ce qui **garantit** que les quatre écrivent dans la même trace, et donc
que l'ordre mesuré est l'ordre réel.

La campagne le confirme : la modification « convertir avant valider » est
attrapée **par ce test seul**. Aucun autre ne la voit, parce que le résultat
final est identique dans les deux ordres.

## 6. Le corridor retenu est consigné dans les deux issues (exigence 6)

L'exigence dit « le journal enregistre le corridor retenu **avant** la
conversion ». Prise au pied de la lettre, elle contredit l'ordre du tableau de
l'énoncé, où consigner est l'étape 4. Ce que l'exigence demande vraiment,
c'est que **le journal ne contienne jamais une opération sans corridor**, y
compris quand la conversion échoue. La clé est décidée avant la première
étape ; elle est recopiée dans l'écriture des deux issues.

```go
// refuse records the refusal then returns the cause.
// The chosen corridor is in the entry, and so is the reason. A refused
// operation therefore leaves exactly one line in the log.
func (d Dependencies) refuse(key string, o domain.Order, cause error) error {
    e := Entry{
        Reference: o.Reference,
        Corridor:  key,
        Source:    o.Amount,
        Outcome:   OutcomeRefused,
        Reason:    cause.Error(),
    }
    if err := d.Journal.Record(e); err != nil {
        return fmt.Errorf("%w: %v (initial cause: %v)", ErrRecord, err, cause)
    }
    return cause
}
```

```go
// TestTheChosenCorridorIsRecordedInBothOutcomes checks requirement 6 from
// its hard side: the corridor is decided BEFORE conversion, so it
// is in the log even when the conversion fails.
func TestTheChosenCorridorIsRecordedInBothOutcomes(t *testing.T) {

    for _, c := range []struct {
        name           string

        })
    }
}
```

## 7. Les corridors

### Les parités en entiers, pas en flottants

```go
// parity is the conversion ratio, written in integers.
// A float64 parity would be shorter to read and wrong in rounding:
// 655.957 cannot be represented in binary, and converting a million
// francs would shift by one cent depending on the order of operations. The
// two integers are exact.
type parity struct {
    numerator   int64
    denominator int64
}

// apply returns the number of target sub-units for units source units.
//
// Rounding is to nearest, half up. It is a DECISION:
// see TestConversionIsNotAdditive, which measures what it costs.
func (p parity) apply(units int64) int64 {
    product := units * p.numerator
    return (product + p.denominator/2) / p.denominator
}
```

La parité FCFA/EUR est **fixe par convention monétaire** : 1 EUR = 655,957
FCFA. En `float64`, 655.957 n'est pas représentable, et la conversion d'un
million de francs se décale selon l'ordre des opérations. Deux entiers sont
exacts :

```
=== RUN   TestLeTemoin
    sondage_test.go:163: 655 957 XAF = 1 000,00 EUR, a la parite fixe
--- PASS
```

C'est le seul des quatre corridors dont la parité peut être une constante. Le
dollar et le naira sont **cotés**, donc paramètres — et on verra en 8 que ce
détail décide de ce que le compilateur trouve.

### L'arrondi est une décision, et elle a un coût

```go
// TestRoundingIsToNearest catches change 11.
// Five francs are worth 0.0076 euro. To the nearest, it is one cent; by
// truncation, it is zero. None of the amounts of the other tests separates the
// two, because they are all big enough for the rest to get lost.
func TestRoundingIsToNearest(t *testing.T) {
    c := corridors.NewToEuro()
    for _, tc := range []struct {
        francs int64
        want   int64
    }{
        {3, 0}, // 0.00457 euro
        {5, 1}, // 0.00762 euro
        {655_957, 100_000},
    } {
        m, err := c.Convert(domain.MustNew(domain.FCFA, tc.francs))
        if err != nil {
            t.Fatalf("Convert(%d): %v", tc.francs, err)
        }
        if m.Units() != tc.want {
            t.Errorf("%d XAF = %d cents, want %d", tc.francs, m.Units(), tc.want)
        }
    }
    t.Log("3 XAF -> 0 cents, 5 XAF -> 1 cent: rounding is to nearest")
}
```

```
=== RUN   TestConversionIsNotAdditive
    registry_test.go:174: 501 ecarts sur 1001 montants :
                          convert(n)+convert(n) != convert(2n)
--- PASS
```

**Un montant sur deux.** Aucun arrondi ne supprime ça ; le choisir en
connaissance de cause, oui. Le test interdit que l'écart passe à zéro, parce
qu'un zéro signifierait que l'arrondi a disparu.

### L'identité est une étape, pas une absence d'étape

```go
// Convert returns the amount UNCHANGED.
// It is not an empty step that could have been skipped: the skeleton calls
// the six steps for all corridors, and it is what makes adding a
// corridor does not touch the skeleton. A skeleton that asked "is this
// corridor converting?" would have one if per corridor, that is
// exactly what the interface removed.
func (c Internal) Convert(m domain.Amount) (domain.Amount, error) {
    if m.Currency() != domain.FCFA {
        return domain.Amount{}, fmt.Errorf("%w: %s", ErrSourceCurrency, m.Currency())
    }
    return m, nil
}
```

Un squelette qui demanderait « est-ce que ce corridor convertit ? » aurait un
`if` par corridor, c'est-à-dire exactement ce que l'interface a supprimé.

### Ce que les formats de compte ne distinguent pas


Onze sur douze, pas douze. Le NUBAN nigérian à dix chiffres passe la

Mesuré dans le sens de l'ajout, sur un instantané du module à trois
corridors, vert.

| | |
|---|---|

| fichiers modifiés | **1** — `registre/registre.go` |
| corridors existants touchés | **0** |
| lignes du squelette touchées | **0** |

```diff
-func Tous(centimesParMilleFrancsUSD int64) transfer.Registry {
+func Tous(centimesParMilleFrancsUSD, kobosParFrancNGN int64) transfer.Registry {
     return transfer.Registry{

```

### Ce que le compilateur trouve

**Étape A — le fichier seul.** `go build ./...` : 0 erreur. `go vet ./...` :
0. Tous les tests verts. Un corridor écrit et jamais inscrit est du code mort
que rien ne signale.

**Étape B — l'inscription au registre.** `go build` sur le code de
production : **toujours 0 erreur**. Une entrée de table n'est pas une
signature.

Mais la compilation des **tests** casse, à trois endroits dans deux
paquets :

```
vet: ex2/registry/registry_test.go:29:51: not enough arguments in call to registry.Tous
    have (number)
    want (int64, int64)
vet: ex2/sondage/sondage_test.go:150:44: not enough arguments in call to registry.Tous
    have (number)
    want (int64, int64)
```

Et c'est un accident heureux dont il faut connaître la cause : le compilateur
ne trouve ces trois appels **que parce que la parité du naira est un
paramètre**. Le corridor euro, dont la parité est une constante, serait passé
en silence complet.

> Le compilateur trouve les changements de **signature**, pas les ajouts
> d'entrée dans une table. Un corridor à parité fixe s'ajoute sans qu'une
> seule ligne du reste du programme ne bronche.

**Étape C — les appels corrigés, les tests inchangés.** Un seul test tombe,
et c'est celui qui existe pour ça :

```
--- FAIL: TestLesCorridorsConnus
    registry_test.go:46: corridors = [XAF→EUR XAF→NGN XAF→USD XAF→XAF],
                         attendu [XAF→EUR XAF→USD XAF→XAF]
```

L'ordre complet est donc : **compilation des tests → la liste des corridors →
le cas de comportement à ajouter**. Le dernier n'est pas une chute, c'est du
travail : la ligne NGN du tableau bout-à-bout, et le compte de paires croisées
qui passe de 6 à 11.

`TestLesCorridorsConnus` **remplace le compilateur**. Sans lui, un corridor
inscrit par accident — un mauvais copier-coller de clé, une parité oubliée —
part en production sans que personne ne l'ait décidé.

## 9. Mesure 8 : ajouter une sixième étape

« Vérifier la liste des personnes sanctionnées », qui ne varie pas par
corridor. Même protocole : instantané à cinq étapes, vert, puis ajout du seul
code de production.

| | |
|---|---|
| fichiers de production modifiés | **1** — `transfer/transfer.go` (+31 lignes, −9) |
| corridors modifiés | **0** |
| erreurs de compilation | **0** |
| tests de premier niveau rouges | **9**, plus 6 sous-tests, dans 2 paquets |

Zéro erreur de compilation, et pourtant neuf tests rouges — tous avec le même
message :

```
--- FAIL: TestLesQuatreCorridorsBoutAbout/XAF→EUR
    registry_test.go:76: Handle : transfer : dependance absente : liste des sanctions
```

**L'asymétrie est le résultat de la mesure.** Ajouter un champ à une structure
ne casse aucun littéral existant en Go : les tests compilent et passent une
dépendance nulle. C'est le refus explicite du squelette qui les arrête tous,
d'un coup, avec un message qui nomme ce qui manque.

L'alternative aurait été une liste vide par défaut. Elle donnait **zéro test
rouge** — et une chaîne de virements internationaux qui ne vérifie plus
personne, sans qu'une seule ligne ne le dise.

> Zéro test rouge n'est pas une bonne nouvelle quand on vient d'ajouter une
> étape. C'est le symptôme d'un défaut silencieux.

Zéro corridor touché, en revanche, est la bonne nouvelle, et c'est
exactement ce que l'interface à trois méthodes achetait : une étape fixe de
plus ne concerne pas les variantes.

## 10. L'incorporation est interdite, et c'est vérifié (exigence 5)

L'exigence demande qu'aucun type n'incorpore un type qui a des appels
internes. La forme forte est plus facile à vérifier et plus solide : **aucun
type de production n'incorpore rien**. Elle ne dépend pas de ce que les
méthodes du type incorporé feront dans six mois.

```go
// Package survey answers requirement 5: no type of exercise 2
// embeds a type that has internal calls.
//
// It answers in the strong form: no type embeds ANYTHING. It is
// easier to check than the full criterion, and it is sturdier, because
// it does not depend on what the embedded type's methods will do in six
```

## 11. La démonstration : la version à ne pas écrire (exigence 9)

```go
// Base holds the skeleton and the defaults of the three steps.
type Base struct {
    Cap   domain.Amount
    Trace *[]string
}

// validate is the default step 1: a non-empty account and the cap.
func (b Base) validate(o domain.Order) error {
    b.record("validate/base")
    if o.Account == "" {
        return fmt.Errorf("%w: empty account", ErrRefused)
    }
    if o.Amount.Exceeds(b.Cap) {
        return fmt.Errorf("%w: %s beyond %s", ErrRefused, o.Amount, b.Cap)
    }
    return nil
}

// convert is the default step 2: identity.
func (b Base) convert(m domain.Amount) (domain.Amount, error) {
    b.record("convert/base")
    return m, nil
}

// price is the default step 3: five hundred francs.
func (b Base) price(m domain.Amount) domain.Amount {
    b.record("price/base")
    return domain.MustNew(domain.FCFA, 500)
}

// Handle is the skeleton.
//
// The three calls are resolved AT COMPILE TIME to Base's methods,
// because the receiver b is of type Base and Base knows nothing of what
// embeds it. It is the same mechanism as mechanics.Base of lesson
// 2.3, applied to five steps instead of one.
func (b Base) Handle(o domain.Order) (Result, error) {
    if err := b.validate(o); err != nil {
        return Result{}, err
    }
    target, err := b.convert(o.Amount)
    if err != nil {
        return Result{}, err
    }
    fees := b.price(o.Amount)
    b.record("record")
    b.record("notify")
    return Result{Credited: target, Fees: fees}, nil
}
```

comporte comme son auteur l'attend est `Internal`, **par accident** : il ne

### Les sept survivantes, et ce que chacune réclame

| | Diagnostic | Action |
|---|---|---|
| 5 | mutant équivalent **ici** : rien ne formate un corridor. Mais la méthode est promue dans les trois types, et si elle s'appelle `String` les trois deviennent des `fmt.Stringer` | un test qui compte les méthodes exportées |
| 11 | vrai manque : aucun montant des autres tests ne sépare l'arrondi de la troncature | un test |
| 12 | vrai manque : la borne elle-même n'était testée ni d'un côté ni de l'autre | un test |
| 14 | vrai manque : la garde est dans une fonction partagée, aucun des quatre corridors ne la testait | un test, sur les quatre |
| 15 | vrai manque | un test |
| 16 | **branche inatteignable** : dans les quatre grilles, `fixed` valait `plancher`, donc la part fixe était déjà le plancher | **suppression de la branche** |
| 17 | **moitié-moitié** : le plafond de frais du corridor dollar est inatteignable (au plafond du corridor, les frais valent 52 500 pour un plafond de 150 000), celui du corridor interne mord | suppression pour le dollar, un test pour l'interne |

Les deux dernières lignes sont les plus instructives. Une modification qui
supprime une branche inatteignable **survit toujours**, et la réponse n'est
pas un test : c'est la suppression de la branche. C'est la même conclusion
que la correction 2.2/3, où `p > plafond` devenu `p >= plafond` survivait
parce que les deux rendaient le même nombre à l'égalité, et où la réponse
avait été de remplacer la branche par `min`.

```go
// grid is the pricing: a fixed share and a share in ten-thousandths.
// There was a third field, floor, and the change campaign
// killed it: in the four grids, fixed equaled floor, so the fixed share
// was ALREADY the floor and the branch could not run. A
// change that removes an unreachable branch always survives, and the
// answer is not a test: it is removing the branch.
type grid struct {
    fixed          int64
    tenThousandths int64
    feeCap         int64
}

// apply returns the fees in sub-units of the source currency.
func (g grid) apply(units int64) int64 {
    fees := g.fixed + units*g.tenThousandths/10_000
    if g.feeCap > 0 && fees > g.feeCap {
        fees = g.feeCap
    }
    return fees
}
```

Le test du minimum du corridor dollar imprime un chiffre qui n'était pas

Le minimum protège donc contre des frais **supérieurs** au montant, pas contre
des frais disproportionnés. Pour que les frais restent sous 10 %, il faudrait
un minimum de 78 535 FCFA. Lequel des deux seuils retenir est une décision de
produit, pas de conception ; la mesure, non, et elle est désormais dans une
assertion pour qu'une révision de la grille la fasse bouger.

## Ce qu'il faut retenir

| | |
|---|---|
| ⚫ | Quand l'interface d'un squelette nomme un type du domaine, ce type descend dans un paquet que les deux côtés importent sans se voir. Un type du domaine n'est pas un type universel. |
| ⚫ | Une méthode appartient à la variante **si et seulement si** elle se répond avec les champs de la variante. Un journal n'est pas une propriété du corridor FCFA→EUR. |
| ⚫ | Le nom d'une variante n'est pas une de ses méthodes : c'est la clé qui a servi à la trouver, et l'appelant la tient déjà. |
| ⚫ | Un test d'ordre s'observe depuis le **point intermédiaire** : un seul double pour toutes les étapes, une seule trace. Sinon l'ordre est identique dans les deux sens. |
| ⚫ | Le compilateur trouve les changements de **signature**, pas les ajouts d'entrée dans une table ni les ajouts de champ dans une structure. Ce qui reste se teste. |
| ⚫ | **Zéro test rouge après l'ajout d'une étape est un symptôme**, pas un succès : c'est la signature d'un défaut par défaut. |
| ⚫ | Une parité se code en deux entiers. `655.957` n'est pas représentable en `float64`, et l'erreur se voit au millier de francs. |
| ⚫ | Un arrondi n'est jamais additif. Mesuré : 501 écarts sur 1 001 montants. Le choisir, oui ; l'ignorer, non. |
| ⚫ | Dans un tableau de cas, c'est l'attente écrite à la main qui est le plus souvent fausse. Deux sur quatre, ici. |
| ⚫ | Une modification qui supprime une branche inatteignable survit toujours. La réponse est la suppression de la branche, pas un test. |
| ⚫ | Un sondage structurel a besoin de son **test négatif** et de sa **garde du cache**, sinon il passe au vert pour la mauvaise raison. |
| ⚫ | L'identité est une étape, pas une absence d'étape. Un `if` par corridor dans le squelette annule ce que l'interface a acheté. |
