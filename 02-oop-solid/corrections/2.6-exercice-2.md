# Correction 2.6 — Exercice 2 : défaire la chaîne de règles de frais

> Rappel de l'énoncé : une interface `Regle` posée à la deuxième règle, un
> `Contexte` de neuf champs, cinq règles appliquées dans l'ordre d'une
> `Chaine` — et une sixième annoncée : un plafond de frais à 20 EUR pour les
> virements internationaux des clients premium, après la remise premium.

Quatre instantanés — la chaîne, la chaîne avec la sixième règle, la version
défaite, la version défaite avec la sixième règle —, et un test d'équivalence
entre eux. Verts sous `go vet ./...` et `go test -race -count=1 ./...`.
Campagne de onze modifications, 11/11 après deux passes.

**Une prémisse de l'énoncé est fausse**, et c'est la mesure de la question 6
qui le montre : je l'écris ici d'emblée pour qu'on ne cherche pas un test qui
ne peut pas exister.

## 1. La matrice

Un test lit, dans le source, les champs du `Contexte` que chaque méthode
`Frais` touche, et si elle lit `courant` :

```
Base           0 champ(s)                                                    courant : true
International  2 champ(s) Montant, PaysDest                                  courant : true
Instantane     3 champ(s) Ferie, Heure, Instantane                           courant : true
Premium        1 champ(s) ClientPremium                                      courant : true
Gratuite       4 champ(s) Canal, Instantane, NbVirementsMois, PaysDest       courant : true
10 cases remplies sur 45
```

**Dix cases remplies sur quarante-cinq.** Aucune règle ne lit plus de quatre
champs, et **`Devise` n'est lu par aucune** : un champ ajouté au contexte
pour une règle qui n'a jamais existé, ou qui a disparu.

Toutes les règles lisent `courant`, mais pas pour la même chose. `Base`,
`International` et `Instantane` y **ajoutent** ; `Premium` le **divise** ;
`Gratuite` le **remplace** par zéro ou le laisse passer. Trois natures de
règles derrière une seule signature — c'est ce que l'abstraction cache, et
c'est pourquoi l'ordre de `Chaine` porte des règles métier sans le dire.

## 2. La sixième règle, dans la chaîne

```go
type PlafondPremium struct{}

func (PlafondPremium) Frais(c Contexte, courant int64) int64 {
    if c.ClientPremium && c.PaysDest != "FR" {
        return min(courant, 2000)
    }
    return courant
}
```

```go
// Chaine est l'ordre d'application. L'ordre compte : Premium divise ce que
// les regles precedentes ont accumule, Gratuite annule tout.
var Chaine = []Regle{Base{}, International{}, Instantane{}, Premium{}, PlafondPremium{}, Gratuite{}}
```

Mesuré : un fichier, **−1 +10**, zéro erreur de compilation. Ce n'est pas le
coût en lignes qui compte, c'est ce que la règle oblige à savoir : elle doit
être placée **après `Premium`** — le métier dit « après la remise » —, et sa
position par rapport à `Gratuite` est indifférente, parce que l'une ne
s'applique qu'à l'international et l'autre qu'au domestique. Rien de cela
n'est écrit dans le type ; c'est dans la position d'un élément d'une tranche.

## 3. Défaire

```go
// Package regles calcule les frais d'un virement, sans chaine de regles : une
// fonction, et les conditions dans l'ordre ou le metier les enonce.
package regles

// Contexte est ce que le calcul lit d'un virement. Devise n'y est plus :
// aucune regle ne la lisait.
type Contexte struct {
    Montant         int64
    PaysDest        string
    Instantane      bool
    ClientPremium   bool
    NbVirementsMois int
    Canal           string // "agence", "web", "mobile"
    Heure           int
    Ferie           bool
}

// Calculer rend les frais, en centimes.
func Calculer(c Contexte) int64 {
    // Gratuite : les cinq premiers virements domestiques du mois, hors agence
    // et hors instantane, ne coutent rien — quelles que soient les autres
    // regles.
    if c.Canal != "agence" && c.NbVirementsMois < 5 && c.PaysDest == "FR" && !c.Instantane {
        return 0
    }
    f := int64(50)
    if c.PaysDest != "FR" {
        f += 500 + c.Montant/1000
    }
    if c.Instantane {
        f += 100
        if c.Ferie || c.Heure < 8 || c.Heure >= 20 {
            f += 50
        }
    }
    // Premium divise par deux tout ce qui precede.
    if c.ClientPremium {
        f /= 2
    }
    return f
}
```

79 lignes deviennent 41. L'ordre n'est plus une position dans une tranche,
c'est **le flot du code** : la gratuité sort d'abord, les suppléments
s'ajoutent, la remise premium divise ce qui précède. Les trois natures de
règles sont visibles comme telles.

Les tests existants passent **sans être modifiés** — le fichier de test est
identique octet pour octet. Et un test d'équivalence compare la chaîne et la
version défaite sur une grille de contextes :

```go
func grille() []cas {
    var out []cas
    for _, m := range []int64{10_000, 900_000, 9_000_000} {
        for _, pays := range []string{"FR", "SN"} {
            for _, inst := range []bool{false, true} {
                for _, prem := range []bool{false, true} {
                    for _, nb := range []int{0, 4, 5, 7} {
                        for _, canal := range []string{"agence", "web"} {
                            for _, h := range []int{7, 8, 10, 19, 20, 22} {
                                for _, ferie := range []bool{false, true} {
                                    out = append(out, cas{m, pays, inst, prem, nb, canal, h, ferie})
                                }
                            }
                        }
                    }
                }
            }
        }
    }
    return out
}

func TestLaVersionDefaiteCalculeLaMemeChose(t *testing.T) {
    g := grille()
    for _, c := range g {
        a := avant.Calculer(avant.Contexte{Montant: c.m, PaysDest: c.pays, Instantane: c.inst,
            ClientPremium: c.prem, NbVirementsMois: c.nb, Canal: c.canal, Heure: c.h, Ferie: c.ferie})
        d := defaite.Calculer(defaite.Contexte{Montant: c.m, PaysDest: c.pays, Instantane: c.inst,
            ClientPremium: c.prem, NbVirementsMois: c.nb, Canal: c.canal, Heure: c.h, Ferie: c.ferie})
        a6 := avant6.Calculer(avant6.Contexte{Montant: c.m, PaysDest: c.pays, Instantane: c.inst,
            ClientPremium: c.prem, NbVirementsMois: c.nb, Canal: c.canal, Heure: c.h, Ferie: c.ferie})
        d6 := defaite6.Calculer(defaite6.Contexte{Montant: c.m, PaysDest: c.pays, Instantane: c.inst,
            ClientPremium: c.prem, NbVirementsMois: c.nb, Canal: c.canal, Heure: c.h, Ferie: c.ferie})
        if a != d || a6 != d6 {
            t.Errorf("%+v : chaine %d / %d, defaite %d / %d", c, a, a6, d, d6)
        }
    }
    t.Logf("%d contextes, aucun ecart, avec et sans la sixieme regle", len(g))
}
```

```
2304 contextes, aucun ecart, avec et sans la sixieme regle
```

## 4. La sixième règle, dans la version défaite

```go
    // Premium divise par deux tout ce qui precede.
    if c.ClientPremium {
        f /= 2
        // Plafond premium, apres la remise : 20 EUR a l'international.
        if c.PaysDest != "FR" {
            f = min(f, 2000)
        }
    }
    return f
}
```

| | dans la chaîne | dans la version défaite |
|---|---|---|
| lignes | −1 +10 | **+4** |
| erreurs de compilation | 0 | 0 |
| ce qu'il faut savoir de l'ordre | sa position dans `Chaine`, après `Premium` | rien : elle s'écrit **dans** le bloc premium, après la division |

## 5. Faut-il ré-abstraire ?

Une fois défaites, les six règles ont en commun **trois formes**, pas une :
une **exemption** qui court-circuite tout, des **suppléments** qui
s'additionnent, et des **ajustements** — la remise, le plafond — qui
s'appliquent à la somme. L'ancienne interface les forçait dans une seule
forme, `Frais(c, courant) int64`, et payait la différence par l'ordre.

Je ne ré-abstrais pas aujourd'hui. Le signal qui me ferait changer d'avis :
**les suppléments**. Si le relevé montre qu'il en arrive régulièrement — plus
de trois par an, par exemple, ou que le métier veut en ajouter sans
livraison —, ils deviennent une **donnée** : une table de `(condition,
montant)` additionnés, et seulement eux. L'exemption et les ajustements
restent du code. Ce serait une abstraction qui unit ce qui se ressemble
**vraiment** — des additions — et qui laisse dehors ce qui ne se ressemble
pas. La mesure qui tranche : `git log` sur ce fichier, en comptant les
commits qui ajoutent un supplément.

## 6. L'ordre — et la prémisse fausse

L'énoncé demande le test qui échoue si l'on permute `Premium` et
`Gratuite`. Avant de l'écrire, je l'ai mesuré : chaque paire de règles
permutée, sur une grille de 256 contextes.

```go
// TestQuellesPermutationsChangentLeResultat permute chaque paire de regles de
// la chaine, et compte les contextes ou le resultat change.
func TestQuellesPermutationsChangentLeResultat(t *testing.T) {
    cs := contextes()
    noms := func(r Regle) string { return fmt.Sprintf("%T", r)[len("regles."):] }
    for i := range Chaine {
        for j := i + 1; j < len(Chaine); j++ {
            ch := append([]Regle(nil), Chaine...)
            ch[i], ch[j] = ch[j], ch[i]
            differe := 0
            for _, c := range cs {
                if calculer(ch, c) != Calculer(c) {
                    differe++
                }
            }
            t.Logf("%-13s <-> %-13s : %3d contexte(s) sur %d changent", noms(Chaine[i]), noms(Chaine[j]), differe, len(cs))
        }
    }
}
```

```
Base          <-> International :   0 contexte(s) sur 256 changent
Base          <-> Instantane    :   0 contexte(s) sur 256 changent
Base          <-> Premium       : 120 contexte(s) sur 256 changent
Base          <-> Gratuite      : 136 contexte(s) sur 256 changent
International <-> Instantane    :   0 contexte(s) sur 256 changent
International <-> Premium       :  96 contexte(s) sur 256 changent
International <-> Gratuite      :  64 contexte(s) sur 256 changent
Instantane    <-> Premium       :  64 contexte(s) sur 256 changent
Instantane    <-> Gratuite      :  64 contexte(s) sur 256 changent
Premium       <-> Gratuite      :   0 contexte(s) sur 256 changent
```

**Permuter `Premium` et `Gratuite` ne change rien, dans aucun contexte.**
L'une rend zéro ou laisse passer, l'autre divise par deux ; dans les deux
ordres, le résultat est zéro ou la moitié. Elles **commutent**, et le test
demandé ne peut pas exister. Le commentaire du code de départ — *« l'ordre
compte : Premium divise ce que les règles précédentes ont accumulé, Gratuite
annule tout »* — désigne la mauvaise paire ; l'énoncé l'a cru, et je l'ai
écrit sans le mesurer.

Les paires qui ne commutent pas sont celles qui mélangent les natures : un
supplément contre la remise (`Base`, `International`, `Instantane` contre
`Premium`), un supplément contre l'exemption. Les tests existants en couvrent
déjà : « premium, domestique, agence » vaut 25 — la moitié de la base — et
casse si `Base` passe après `Premium` ; « instantané la nuit, premium » vaut
100 — la moitié de 200 — et casse si `Instantane` passe après `Premium`.

> **Un commentaire qui affirme une propriété d'ordre est une hypothèse.** Il
> se vérifie en permutant, et ça prend dix lignes. Ici, il était faux, et il
> avait trompé l'énoncé.

Les trois modifications exigées par l'énoncé sont tuées : la remise déplacée
avant les suppléments, le férié oublié, le plafond avant la remise. Les deux
survivants **réclament un test**, et ils disent la même chose : **une grille
d'équivalence ne voit pas une borne qu'elle ne contient pas**. Elle avait
7 h et 10 h, pas 8 h ; 0 et 7 virements, pas 5. Après ajout de 8 h, 19 h, 4 et
5 virements — 2 304 contextes au lieu de 768 :

```
11/11 tuees
```
