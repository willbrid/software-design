# Correction 2.6 — Exercice 2 : défaire la chaîne de règles de frais

> Rappel de l'énoncé : une interface `Rule` posée à la deuxième règle, un
> `Context` de neuf champs, cinq règles appliquées dans l'ordre d'une
> `Chain` — et une sixième annoncée : un plafond de frais à 20 EUR pour les
> virements internationaux des clients premium, après la remise premium.

Quatre instantanés — la chaîne, la chaîne avec la sixième règle, la version
défaite, la version défaite avec la sixième règle —, et un test d'équivalence
entre eux. Verts sous `go vet ./...` et `go test -race -count=1 ./...`.
Campagne de onze modifications, 11/11 après deux passes.

**La première version de l'énoncé reposait sur une prémisse fausse** : elle
demandait le test qui échoue si l'on permute `Premium` et `Free`, en
croyant le commentaire du code. La mesure de la question 6 montre que ce test
ne peut pas exister ; l'énoncé a été corrigé pour demander de vérifier le
commentaire avant de le croire.

## 1. La matrice

Un test lit, dans le source, les champs du `Context` que chaque méthode
`Fees` touche, et si elle lit `current` :

```
Base           0 field(s)                                                    current: true
International  2 field(s) Amount, DestCountry                                current: true
Instant        3 field(s) Holiday, Hour, Instant                             current: true
Premium        1 field(s) PremiumCustomer                                    current: true
Free           4 field(s) Channel, DestCountry, Instant, TransfersThisMonth  current: true
10 cells filled out of 45
```

**Dix cases remplies sur quarante-cinq.** Aucune règle ne lit plus de quatre
champs, et **`Currency` n'est lu par aucune** : un champ ajouté au contexte
pour une règle qui n'a jamais existé, ou qui a disparu.

Toutes les règles lisent `current`, mais pas pour la même chose. `Base`,
`International` et `Instant` y **ajoutent** ; `Premium` le **divise** ;
`Free` le **remplace** par zéro ou le laisse passer. Trois natures de
règles derrière une seule signature — c'est ce que l'abstraction cache, et
c'est pourquoi l'ordre de `Chain` porte des règles métier sans le dire.

## 2. La sixième règle, dans la chaîne

```go
type PremiumCap struct{}

func (PremiumCap) Fees(c Context, current int64) int64 {
    if c.PremiumCustomer && c.DestCountry != "FR" {
        return min(current, 2000)
    }
    return current
}
```

```go
// Chain is the order of application. Order matters: Premium halves what the
// previous rules accumulated, Free cancels everything.
var Chain = []Rule{Base{}, International{}, Instant{}, Premium{}, PremiumCap{}, Free{}}
```

Mesuré : un fichier, **−1 +10**, zéro erreur de compilation. Ce n'est pas le
coût en lignes qui compte, c'est ce que la règle oblige à savoir : elle doit
être placée **après `Premium`** — le métier dit « après la remise » —, et sa
position par rapport à `Free` est indifférente, parce que l'une ne
s'applique qu'à l'international et l'autre qu'au domestique. Rien de cela
n'est écrit dans le type ; c'est dans la position d'un élément d'une tranche.

## 3. Défaire

```go
// Package rules computes a transfer's fees, without a chain of rules: one
// function, and the conditions in the order the business states them.
package rules

// Context is what the computation reads from a transfer. Currency is gone:
// no rule read it.
type Context struct {
    Amount             int64
    DestCountry        string
    Instant            bool
    PremiumCustomer    bool
    TransfersThisMonth int
    Channel            string // "branch", "web", "mobile"
    Hour               int
    Holiday            bool
}

// Compute returns the fees, in cents.
func Compute(c Context) int64 {
    // Free: the first five domestic transfers of the month, outside a branch
    // and not instant, cost nothing — whatever the other rules say.
    if c.Channel != "branch" && c.TransfersThisMonth < 5 && c.DestCountry == "FR" && !c.Instant {
        return 0
    }
    f := int64(50)
    if c.DestCountry != "FR" {
        f += 500 + c.Amount/1000
    }
    if c.Instant {
        f += 100
        if c.Holiday || c.Hour < 8 || c.Hour >= 20 {
            f += 50
        }
    }
    // Premium halves everything above.
    if c.PremiumCustomer {
        f /= 2
    }
    return f
}
```

79 lignes deviennent 40. L'ordre n'est plus une position dans une tranche,
c'est **le flot du code** : la gratuité sort d'abord, les suppléments
s'ajoutent, la remise premium divise ce qui précède. Les trois natures de
règles sont visibles comme telles.

Les tests existants passent **sans être modifiés** — le fichier de test est
identique octet pour octet. Et un test d'équivalence compare la chaîne et la
version défaite sur une grille de contextes :

```go
func grid() []point {
    var out []point
    for _, a := range []int64{10_000, 900_000, 9_000_000} {
        for _, country := range []string{"FR", "SN"} {

                for _, prem := range []bool{false, true} {
                    for _, n := range []int{0, 4, 5, 7} {
                        for _, channel := range []string{"branch", "web"} {
                            for _, h := range []int{7, 8, 10, 19, 20, 22} {
                                for _, holiday := range []bool{false, true} {
                                    out = append(out, point{a, country, inst, prem, n, channel, h, holiday})
                                }
                            }
                        }
                    }
                }
            }
        }
    }
    return out
}

func TestTheUndoneVersionComputesTheSame(t *testing.T) {
    g := grid()
    for _, p := range g {
        b := before.Compute(before.Context{Amount: p.a, DestCountry: p.country, Instant: p.inst,
            PremiumCustomer: p.prem, TransfersThisMonth: p.n, Channel: p.channel, Hour: p.h, Holiday: p.holiday})
        u := undone.Compute(undone.Context{Amount: p.a, DestCountry: p.country, Instant: p.inst,
            PremiumCustomer: p.prem, TransfersThisMonth: p.n, Channel: p.channel, Hour: p.h, Holiday: p.holiday})
        b6 := before6.Compute(before6.Context{Amount: p.a, DestCountry: p.country, Instant: p.inst,
            PremiumCustomer: p.prem, TransfersThisMonth: p.n, Channel: p.channel, Hour: p.h, Holiday: p.holiday})
```

## 4. La sixième règle, dans la version défaite

```go
    // Premium halves everything above.

```

|---|---|---|
| lignes | −1 +10 | **+4** |
| erreurs de compilation | 0 | 0 |

## 5. Faut-il ré-abstraire ?

Une fois défaites, les six règles ont en commun **trois formes**, pas une :
une **exemption** qui court-circuite tout, des **suppléments** qui
s'additionnent, et des **ajustements** — la remise, le plafond — qui
s'appliquent à la somme. L'ancienne interface les forçait dans une seule
forme, `Fees(c, current) int64`, et payait la différence par l'ordre.

Je ne ré-abstrais pas aujourd'hui. Le signal qui me ferait changer d'avis :
**les suppléments**. Si le relevé montre qu'il en arrive régulièrement — plus
de trois par an, par exemple, ou que le métier veut en ajouter sans
livraison —, ils deviennent une **donnée** : une table de `(condition,
montant)` additionnés, et seulement eux. L'exemption et les ajustements
restent du code. Ce serait une abstraction qui unit ce qui se ressemble
**vraiment** — des additions — et qui laisse dehors ce qui ne se ressemble
pas. La mesure qui tranche : `git log` sur ce fichier, en comptant les
commits qui ajoutent un supplément.

## 6. L'ordre — et la prémisse fausse

Le commentaire de `Chain` dit que l'ordre compte, et nomme `Premium` et
`Free`. Avant de le croire, je l'ai mesuré : chaque paire de règles
permutée, sur une grille de 256 contextes.

```go
// TestWhichSwapsChangeTheResult swaps each pair of rules in the chain, and
// counts the contexts where the result changes.
func TestWhichSwapsChangeTheResult(t *testing.T) {
    cs := contexts()
    name := func(r Rule) string { return fmt.Sprintf("%T", r)[len("rules."):] }
    for i := range Chain {
        for j := i + 1; j < len(Chain); j++ {
            ch := append([]Rule(nil), Chain...)
            ch[i], ch[j] = ch[j], ch[i]
            differ := 0
            for _, c := range cs {
                if compute(ch, c) != Compute(c) {
                    differ++
                }
            }
            t.Logf("%-13s <-> %-13s : %3d context(s) out of %d change", name(Chain[i]), name(Chain[j]), differ, len(cs))
        }
    }
}
```

```
Base          <-> International :   0 context(s) out of 256 change
Base          <-> Instant       :   0 context(s) out of 256 change
Base          <-> Premium       : 120 context(s) out of 256 change
Base          <-> Free          : 136 context(s) out of 256 change
International <-> Instant       :   0 context(s) out of 256 change
International <-> Premium       :  96 context(s) out of 256 change
International <-> Free          :  64 context(s) out of 256 change
Instant       <-> Premium       :  64 context(s) out of 256 change
Instant       <-> Free          :  64 context(s) out of 256 change
Premium       <-> Free          :   0 context(s) out of 256 change
```

**Permuter `Premium` et `Free` ne change rien, dans aucun contexte.**
L'une rend zéro ou laisse passer, l'autre divise par deux ; dans les deux
ordres, le résultat est zéro ou la moitié. Elles **commutent**, et le test
demandé ne peut pas exister. Le commentaire du code de départ — *« Order matters:
Premium halves what the previous rules accumulated, Free cancels
everything »* — désigne la mauvaise paire. La première version de l'énoncé
l'avait cru, et je l'avais écrite sans le mesurer.

Les paires qui ne commutent pas sont celles qui mélangent les natures : un
supplément contre la remise (`Base`, `International`, `Instant` contre
`Premium`), un supplément contre l'exemption. Les tests existants en couvrent
déjà : « premium, domestic, branch » vaut 25 — la moitié de la base — et
casse si `Base` passe après `Premium` ; « instant at night, premium » vaut
100 — la moitié de 200 — et casse si `Instant` passe après `Premium`.

> **Un commentaire qui affirme une propriété d'ordre est une hypothèse.** Il
> se vérifie en permutant, et ça prend dix lignes. Ici, il était faux, et il
> avait trompé l'énoncé.

## 7. La campagne

### Première passe

```
premium deplacee avant les supplements (et appliquee deux fois)  tuee
le cas ferie oublie                                              tuee
plafond applique avant la remise                                 tuee
nuit : borne de 20 h exclue                                      tuee
matin : borne de 8 h incluse                                     SURVIT
gratuite : cinq inclus                                           SURVIT
international : taux                                             tuee
premium : un tiers                                               tuee
gratuite : agence comprise                                       tuee
plafond a 25 EUR                                                 tuee
gratuite : plus gratuite                                         tuee
9/11 tuees
```

Les trois modifications exigées par l'énoncé sont tuées : la remise déplacée
avant les suppléments, le férié oublié, le plafond avant la remise. Les deux
survivants **réclament un test**, et ils disent la même chose : **une grille
d'équivalence ne voit pas une borne qu'elle ne contient pas**. Elle avait
7 h et 10 h, pas 8 h ; 0 et 7 virements, pas 5. Après ajout de 8 h, 19 h, 4 et
5 virements — 2 304 contextes au lieu de 768 :

```
11/11 tuees
```
