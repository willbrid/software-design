# Correction 2.2 — Exercice 2 : la chaîne de dématérialisation

> Rappel de l'énoncé : quatre types de document, un ensemble fermé par le
> métier, et une question nouvelle par trimestre. Il fallait écrire le paquet
> `document` avec son scellement, ses deux tests d'exhaustivité, son test de
> non-compilation, ses assertions de conformité, puis mesurer les deux
> expériences et publier une campagne.

Tout ce qui suit est extrait d'un module qui compile, dont les 6 paquets de
test passent sous `go vet` et `go test -race -count=1`, et dont chaque chiffre
cité est une sortie de commande.

## 1. L'ensemble scellé

### La décision d'axe, avant d'écrire une ligne

L'énoncé donne les deux moitiés de la réponse, et elles sont explicites :

| | Ce que dit l'énoncé | Donc |
|---|---|---|
| **les variantes** | « il n'y en aura pas un cinquième avant au moins deux ans, parce que chaque type suppose un accord avec l'ordre » | ensemble **fermé**, et fermé par le métier |
| **les opérations** | « il en arrive une nouvelle par trimestre » | ensemble **ouvert** |

Fermé sur les variantes, ouvert sur les opérations : c'est le cas du type
somme scellé, et pas celui de l'interface. Si le relevé avait été l'inverse —
un type de document par trimestre, trois questions figées — la réponse serait
une interface, et tout ce qui suit serait faux.

### Le paquet, et son interface à une méthode

```go
// Package document defines the document types that the
// accepts paperless.
//
// The set is CLOSED, and it is closed by the trade: each type assumes
// an agreement with the order of accountants, so there will not be a
// fifth one within two years. This package tells the compiler with an
// unexported method.
//
// The four types are VALUES in the sense of lesson 2.1: private fields,
// constructor that refuses the non-canonical, immutable, comparable. Two
// invoices whose fields are all equal ARE the same invoice: what
// identifies an invoice is its number and its issuer, and one changes neither
// one nor the other without issuing another document.
//
// The import list of this file is the lesson's measure: sum, day,
// and the minimum of the standard library. Neither the commercial code, nor the
// role matrix.
package document
```

```go
// Document is the closed set of document types.
// document() is not exported: no type from another package can
// satisfy this interface, even by declaring a method
// document(), because the name of an unexported method includes the path of
// its package. The set of implementations fits in this file.
//
// It is a ⚫: the state "a document type this package does not know"
// cannot be represented.
//
// Label is the ONLY operation carried by the variants, and the criterion is
// the lesson's: a method belongs to the variant if and only if
// it IS ANSWERED with the variant's fields.
//
//    Label                  -> yes, with the fields. It is here.
//    RetentionPeriod        -> no, it needs the commercial code. Package
//                              retention.
//    AccessRights           -> no, it needs the firm's role matrix.
//                              Package access.
//    MustBeSigned           -> no, it needs the eIDAS regulation and the policy
//                              of the firm. Package signature.
type Document interface {
    document()
    Label() string
}
```

Le critère, appliqué aux quatre questions de l'énoncé :

| Question | Se répond avec les champs du document ? | Où elle va |
|---|---|---|
| `Label` | **oui** | sur la variante |
| durée de conservation | non — il faut le code de commerce | paquet `retention` |
| droits d'accès | non — il faut la matrice des rôles | paquet `access` |
| signature électronique | non — il faut le règlement et la politique du cabinet | paquet `signature` |

Et la preuve que rien n'a fui est la liste des imports, pas une relecture :

```
$ go list -f '{{join .Imports " "}}' ./document
errors example/firm/day example/firm/sum fmt strings

$ go list -f '{{join .Imports " "}}' ./conservation
errors exemple/cabinet/commerce example/firm/document example/firm/day fmt

$ go list -f '{{join .Imports " "}}' ./acces
errors example/firm/document example/firm/roles fmt

$ go list -f '{{join .Imports " "}}' ./signature
errors example/firm/document fmt
```

`document` n'importe ni `commerce` ni `roles`. Les paquets `commerce` et
`roles` n'existent dans ce module que pour **rendre cette question
mesurable** : chaque paquet qui les importe est un paquet à qui on a demandé
de connaître le droit ou l'organigramme.

### Une variante, en entier

```go
// Invoice is an invoice received or issued.
type Invoice struct {
    number string
    siren  string
    gross  sum.Sum
}

// NewInvoice builds an invoice, or refuses to.
func NewInvoice(number, siren string, gross sum.Sum) (Invoice, error) {
    if strings.TrimSpace(number) == "" {
        return Invoice{}, fmt.Errorf("%w: empty number", ErrFormat)
    }
    if err := checkSiren(siren); err != nil {
        return Invoice{}, err
    }
    return Invoice{number: number, siren: siren, gross: gross}, nil
}

func (f Invoice) document()      {}
func (f Invoice) Number() string { return f.number }
func (f Invoice) Siren() string  { return f.siren }
func (f Invoice) Gross() sum.Sum { return f.gross }
func (f Invoice) Label() string  { return "Invoice " + f.number + " / SIREN " + f.siren }
```

C'est une **valeur** au sens de la leçon 2.1 : champs privés, constructeur qui
refuse le non-canonique, immuable, comparable. Et le gain n'est pas théorique
— une facture est une clé de map, et le test le vérifie plutôt que de
l'affirmer.

### Le détail de modélisation qui n'était pas dans l'énoncé

L'énoncé dit que le relevé bancaire porte « un solde de clôture ». J'ai
d'abord écrit `sum.Sum`, comme pour le TTC de la facture. C'est faux :

> Un solde de clôture peut être **négatif** — c'est un découvert. Un montant
> facturé ne peut pas l'être. Deux choses qui s'écrivent toutes les deux « de
> l'argent » et qui n'ont pas le même ensemble de valeurs valides ne sont pas
> le même type.

Donc `closingCents int64` pour le relevé, et `sum.Sum` — positif ou
nul, garanti par son constructeur — pour la facture. C'est la question de la
leçon 2.1 sur la valeur zéro, posée une variante à la fois.

## 2. Les deux tests d'exhaustivité

```go
// Package exhaustiveness_test buys what Go does not give.
//
// Go gives the CLOSURE of the set of implementations: unexported document()
// method makes any implementation outside the package impossible, and it is
// free. It gives neither EXHAUSTIVENESS of handling (a type switch with
// three cases plus a default compiles perfectly), nor the closure of
// the set of VALUES, since nil satisfies every interface.
//
// Two tests, and they do not replace each other:
//
//   - by REPETITION: walk document.Variants() and require that no
//     operation falls into its default. Simple, and worth something only if
//     Variants() is complete.
//   - by READING THE SOURCE: read document/*.go with go/ast to
//     establish the true list, then read the module's type switches. It is
//     that one that guards the other.
package exhaustiveness_test
```

### Celui qui lit la source

```go
// variantsFromSource: every type of package document that carries the
// unexported document(). It is the exact definition of "belonging to
// the sealed set", and it depends on no hand-written list.
func variantsFromSource(t *testing.T) []string {
    t.Helper()
    fset := token.NewFileSet()
    pkgs, err := parser.ParseDir(fset, sealedPkg, nil, 0)
    if err != nil {
        t.Fatalf("reading %s: %v", sealedPkg, err)
    }
    var names []string
    for _, p := range pkgs {
        for _, f := range p.Files {
            for _, d := range f.Decls {
                fn, ok := d.(*ast.FuncDecl)
                if !ok || fn.Recv == nil || fn.Name.Name != sealMethod {
                    continue
                }
                if n := receiverName(fn.Recv); n != "" {
                    names = append(names, n)
                }
            }
        }
    }
    slices.Sort(names)
    if len(names) == 0 {
        t.Fatalf("no variant found: the seal method is no longer called %q", sealMethod)
    }
    return names
}
```

La définition de « appartenir à l'ensemble scellé » est **opérationnelle** :
tout type du paquet qui porte la méthode non exportée. Elle ne dépend d'aucune
liste écrite à la main, et c'est tout l'intérêt.

Puis le parcours des `switch`, avec le cas `nil` exigé :

```go
// TestEachTypeSwitchOnADocumentIsExhaustive pays back the debt of the
// default.
//
// NOT GUARANTEED: the criterion "at least one case names a variant" is a
// heuristic. Handling written as if/else escapes it entirely. This test
// catches by far the most frequent case, the variant added and the
// switch forgotten, and not every case.
func TestEachTypeSwitchOnADocumentIsExhaustive(t *testing.T) {
    variants := variantsFromSource(t)
    examined := 0
    err := filepath.WalkDir(root, func(path string, d fs.DirEntry, err error) error {
        if err != nil {
            return err
        }
        if d.IsDir() || !strings.HasSuffix(path, ".go") || strings.HasSuffix(path, "_test.go") {
            return nil
        }
        fset := token.NewFileSet()
        f, err := parser.ParseFile(fset, path, nil, 0)
        if err != nil {
            return fmt.Errorf("%s: %w", path, err)
        }
        if !imported(f, importPath) {
            return nil
        }
        ast.Inspect(f, func(n ast.Node) bool {
            sw, ok := n.(*ast.TypeSwitchStmt)
            if !ok {
                return true
            }
            handled := casesOfATypeSwitch(sw, variants)
            if len(handled) == 0 {
                return true
            }
            examined++
            line := fset.Position(sw.Pos()).Line
            for _, v := range variants {
                if !slices.Contains(handled, v) {
                    t.Errorf("%s:%d: does not handle document.%s (handled: %v)",
                        path, line, v, handled)
                }
            }
            if !handlesNilCase(sw) {
                t.Errorf("%s:%d: does not handle the nil case", path, line)
            }
            return true
        })
        return nil
    })
    if err != nil {
        t.Fatalf("walk: %v", err)
    }
    if examined == 0 {
        t.Fatal("no type switch examined: the test watches nothing any more")
    }
    t.Logf("%d production type switches examined: %d variants required in each, plus the nil case",
        examined, len(variants))
}
```

Une propriété de ce test qu'on n'attend pas et qui se mesure : il a **découvert
tout seul** le troisième `switch`. Avant l'ajout du paquet `signature` il en
examinait deux, après il en examine trois, et personne n'a touché à sa
configuration.

```
2 type switch de production examines : 4 variantes exigees dans chacun, plus le cas nil
3 type switch de production examines : 4 variantes exigees dans chacun, plus le cas nil
```

Et la clause **NON GARANTI**, qui fait partie du test : le critère « au moins
un cas nomme une variante » est une heuristique, et un traitement écrit en
`if`/`else` lui échappe entièrement.

### Celui par la répétition, et pourquoi il ne suffit pas

```go
// TestNoOperationFallsIntoItsDefault is the test by repetition. It
// is guarded by TestTheVariantsListIsComplete: without this safeguard, it
// would make a three-case switch green as soon as Variants() had
// forgets one.
func TestNoOperationFallsIntoItsDefault(t *testing.T) {
    for _, v := range document.Variants() {
        if _, _, err := retention.Duration(v); err != nil {
            t.Errorf("retention.Duration(%T): %v", v, err)
        }
        if _, err := retention.Due(v, day.MustParse("2026-01-15")); err != nil {
            t.Errorf("retention.Due(%T): %v", v, err)
        }
        for _, r := range roles.All() {
            // ErrForbidden is a business ANSWER, not a forgotten variant:
            // telling them apart is the whole point of having two errors.
            if _, err := access.For(v, r); err != nil && !errors.Is(err, access.ErrForbidden) {
                t.Errorf("access.For(%T, %s): %v", v, r, err)
            }
        }
    }
}
```

Il parcourt `Variants()`, qui est une liste écrite à la main. La section 4
montre ce qui arrive quand cette liste est incomplète : **ce test passe au
vert** alors que trois `switch` sont incomplets. C'est pour ça que celui qui
lit la source le **garde** au lieu de le remplacer.

Noter aussi la distinction entre les deux erreurs d'`access` : `ErrForbidden`
est une **réponse métier** — un stagiaire n'a rien à voir sur un relevé
bancaire — et `ErrTypeNotHandled` est une **variante oubliée**. Le test accepte
la première et refuse la seconde. Avec une seule erreur pour les deux, il
n'aurait pu refuser ni l'une ni l'autre.

## 3. Le test de non-compilation

Cinq cas, chacun avec le fragment du message attendu, et un témoin qui tourne
en processus.

```go
// Package guard holds only decision tests.
package guard

import (
    "os"
    "os/exec"
    "path/filepath"
    "strings"
    "testing"

    // CACHE GUARD, and it is not decorative: a test that checks by
    // running "go build" in a subprocess depends on nothing in the sense
    // of the compiler, so Go has the right to serve it a stale result.
    // By importing what it watches, the test becomes sensitive again, and the
    // witness below really uses them.
    "example/firm/access"
    "example/firm/day"
    "example/firm/document"
    "example/firm/retention"
    "example/firm/roles"
    "example/firm/sum"
)
```

Les deux premiers cas méritent d'être lus ensemble, parce que leurs messages
diffèrent et que la différence **est** la preuve du mécanisme :

```go
        {
            name: "declare a fifth document type outside the package",
            declarations: `type VATReturn struct{ Period string }

func (d VATReturn) Label() string { return "VAT " + d.Period }

var _ document.Document = VATReturn{}`,
            want: "missing method document",
            guard:   "the set of document types would stop being closed",
        },
        {
            // The message is NOT the same as in the previous case, and
            // it is the proof of the mechanism. With no document() method at all,
            // the compiler says "missing method". With a method
            // document() declared in another package, it says
            // "UNEXPORTED method": it sees it, and refuses it because
            // the name of an unexported method includes the package where it
            // is declared.
            name: "copy the seal method",
            declarations: `type VATReturn struct{ Period string }

func (d VATReturn) Label() string { return "VAT " + d.Period }
func (d VATReturn) document()       {}

var _ document.Document = VATReturn{}`,
            want: "unexported method document",
            guard:   "the seal could be bypassed by copying a method name",
        },
```

```
./main.go:13:27: DeclarationVAT does not implement document.Document (missing method document)
./main.go:14:27: DeclarationVAT does not implement document.Document (unexported method document)
```

« *missing* » quand il n'y a pas de méthode `document()`. « *unexported* »
quand on la recopie dans un autre paquet : le compilateur **la voit**, et il
la refuse, parce que le nom d'une méthode non exportée inclut le chemin du
paquet où elle est déclarée. Les deux `document()` ne portent pas le même nom.

Les trois autres cas et leurs messages mesurés :

```
./main.go:15:23: cannot refer to unexported field numero in struct literal of type document.Invoice
./main.go:15:12: undefined: roles.inconnu
./main.go:15:6: invalid operation: sum.MustCents(100) + 1 (mismatched types sum.Sum and untyped int)
```

Trois précautions dans ce fichier, et chacune répond à un mode de panne connu
depuis la leçon 2.1 :

1. **le fragment de message attendu par cas**, sinon n'importe quelle erreur
   satisfait le test et la première faute de frappe le rend définitivement
   vert ;
2. **le témoin en processus**, parce qu'un témoin qui passe par le même
   `go build` que ce qu'il surveille tombe en même temps que lui ;
3. **les imports du paquet surveillé**, qui sont la garde du cache — un test
   qui valide dans un sous-processus ne dépend de rien au sens du
   compilateur, donc Go a le droit de lui servir un résultat périmé.

Et un détail de construction qui a son importance : le gabarit du programme
d'essai utilise **les trois imports dans tous les cas**, par trois lignes
`_ = ...` dans `main`. Sans ça, un cas qui n'utilise pas `roles` échoue à
compiler pour « *imported and not used* » — et il passerait, pour la mauvaise
raison, exactement comme en 2.1.

## 4. Les assertions de conformité, mesurées en trois points

C'est la question 7, et la mesure donne mieux que ce que j'attendais.

J'ajoute une deuxième méthode à `Document`, et je compte les erreurs de
compilation dans trois configurations :

```
Une deuxieme methode est ajoutee a l'interface Document.
  avec les 4 assertions explicites ET Variants()            : 8 err(s)
  sans les assertions explicites, mais avec Variants()      : 4 err(s)
  sans assertion explicite ET sans Variants()               : 0 err(s)
```

Trois choses à en tirer.

**Zéro erreur sans aucune assertion.** Go n'a pas de déclaration `implements`,
donc le compilateur n'a rien à vérifier. Quatre types qui n'implémentent plus
l'interface, et il se tait.

**`Variants()` est une assertion de conformité qui ne se présente pas comme
telle.** Son littéral de slice assigne les quatre variantes à `Document`,
donc il déclenche la vérification. Il en donne quatre.

**Les assertions explicites doublent le compte, et c'est voulu.** Les huit
erreurs ne sont pas une redondance inutile : `Variants()` existe pour les
tests, et rien ne garantit qu'elle existera toujours. Si quelqu'un la
remplace par un autre mécanisme, la garantie disparaîtrait **sans que rien ne
le signale**. Les quatre lignes explicites la rendent indépendante de l'usage
qu'on fait du paquet.

```go
// Variants returns one instance of each variant.
// A hand-written list, so fallible: it is what the package
// exhaustiveness watches by reading this file. It also serves as a
// conformance without looking like it: the slice literal assigns the four
// variants to Document, so adding a method to the interface gives four
// compile errors here.
func Variants() []Document {
    return []Document{
        Invoice{number: "F-2026-001", siren: "552100554", gross: sum.MustCents(120_00)},
        DeliveryNote{number: "BL-77", orderRef: "CMD-12"},
        BankStatement{iban: "FR7630006000011234567890189", month: "2026-03", closingCents: -4_250},
        Contract{reference: "CTR-9", partA: "FIRM", partB: "CLIENT", effect: day.MustParse("2026-01-01")},
    }
}

// The four conformance assertions, written explicitly on top of the
// literal of Variants(). They are the "implements" declaration Go
// does not have, and without them the compiler has nothing to check.
var (
    _ Document = Invoice{}
    _ Document = DeliveryNote{}
    _ Document = BankStatement{}
    _ Document = Contract{}
)
```

> Une garantie qui dépend d'un détail d'implémentation ailleurs dans le
> fichier n'est pas une garantie, c'est une coïncidence qui tient.

### Ce que l'expérience a trouvé dans mon propre test

À l'étape 3, un test a **paniqué** au lieu d'échouer :

```

// TestLabelsAreReadable is keyed by the TYPE NAME and not by
// position.
//
// The first version walked Variants() with an index and read a
// hand-written slice. Adding a fifth type for the experiment,
// it did not fail: it PANICKED on an index out of range, and it
// shifts the four previous comparisons along the way.
//
//    A test that indexes one list by the position of another panics instead
//    of failing, and a test that panics does not say what is missing.
//
// Keyed by the type's name, it fails cleanly and names the variant
// whose label was not decided.
func TestLabelsAreReadable(t *testing.T) {
    wanted := map[string]string{
        "document.Facture":        "Invoice F-2026-001 / SIREN 552100554",
        "document.BonDeLivraison": "Delivery note BL-77 (order CMD-12)",
        "document.ReleveBancaire": "Statement 2026-03 / FR763000...",
        "document.Contrat":        "Contract CTR-9 (FIRM / CLIENT)",
    }
    seen := map[string]bool{}
    for _, v := range document.Variants() {
        key := fmt.Sprintf("%T", v)
        seen[key] = true
        want, ok := wanted[key]
        if !ok {
            t.Errorf("%s: no expected label is declared for this type", key)
            continue
        }
        if got := v.Label(); got != want {
            t.Errorf("%s: label = %q, want %q", key, got, want)
        }
    }
    for key := range wanted {
        if !seen[key] {
            t.Errorf("%s: expected label declared, but the type is no longer in Variants()", key)
        }
    }
}
```

### Expérience 2 — ajouter une quatrième question

C'est la question 9, et le paquet `signature` **est** la réponse.

```go
// Package signature answers the fourth question, the one of the quarter
// next one: "must this document be signed electronically?"
//
// This package IS the measure of the second experiment. It cost one package
// new, and nothing else: package document did not move, its four
// variants did not move, and none of them learned what the
// eIDAS regulation.
package signature

import (
    "errors"
    "fmt"

    "example/firm/document"
)
```

```go
// Required says whether the document must be signed, and why.
// The "why" is not decorative: a signature obligation is
// is justified before an audit, and a boolean alone cannot be justified.
func Required(d document.Document, p Policy) (bool, string, error) {
    switch v := d.(type) {
    case nil:
        return false, "", fmt.Errorf("%w: nil interface", ErrTypeNotHandled)
    case document.Invoice:
        if p.AllInvoices {
            return true, "firm policy: every invoice", nil
        }
        if p.ThresholdCents > 0 && v.Gross().Cents() > p.ThresholdCents {
            return true, fmt.Sprintf("amount %s above the threshold", v.Gross()), nil
        }
        return false, "invoice below the threshold", nil
    case document.DeliveryNote:
        return false, "a delivery note is not legally binding", nil
    case document.BankStatement:
        // It is received from the bank, which already sealed it. Signing it a
        // second time adds nothing and would hide the original seal.
        return false, "already sealed by the issuing institution", nil
    case document.Contract:
        return true, "a contract is signed by definition", nil
    default:
        return false, "", fmt.Errorf("%w: %T", ErrTypeNotHandled, d)
    }
}
```

Le bilan, mesuré :

| | Coût |
|---|---|
| paquet nouveau | 61 lignes + 77 de test |
| modifications du paquet `document` | **0** |
| méthodes ajoutées à l'interface | **0** |
| variantes modifiées | **0** |
| nouvelles connaissances dans `document` | **0** — il importe toujours `errors fmt strings day sum` |

Et le tableau des deux axes, rempli avec les chiffres de ce module :

| | ajouter une variante | ajouter une opération |
|---|---|---|
| **ensemble fermé** | 4 fichiers, 0 erreur de compilation, 3 tests | **1 paquet neuf, rien d'autre** |

Deux remarques sur la conception de `signature`, parce que ce ne sont pas des
détails.

`Required` rend **un booléen et une justification**. Une obligation de signature
se justifie devant un contrôle, et un booléen seul ne se justifie pas. C'est
la leçon 1.3 sur ce qu'une fonction doit rendre pour que son appelant puisse
agir.

`Policy.ThresholdCents` à zéro signifie **« pas de seuil »** et non
« seuil à zéro ». Si c'était l'inverse, toute facture non nulle serait à
signer, et la valeur zéro d'un champ de configuration serait le choix le plus
contraignant au lieu du plus neutre. Un test le garde, et une modification de
la campagne le confirme.

## 6. La campagne de modifications

Quatorze modifications, sur six paquets de test.

```
modification                                                       | tests qui tombent
-------------------------------------------------------------------+------------------
 1. checkSiren ne verifie plus la key de Luhn                   | 2
 2. verifierIban ne verifie plus le modulo 97                      | 1
 3. l'IBAN n'est plus canonise                                     | 1
 4. un contrat avec soi-meme est accepte si la casse differe       | 1
 5. Variants() oublie le contrat                                  | 3
 6. retention.Duration perd son cas nil                            | 1
 7. retention.Duration perd le cas du bon de livraison             | 4
 8. la bascule de 2008 est inclusive au lieu d'exclusive           | 2
 9. PlusAnnees ajoute des mois au lieu d'annees                    | 2
10. le stagiaire voit les releves bancaires                        | 2
11. la valeur zero d'un Droit devient Lecture                      | 1
12. le seuil de signature devient inclusif                         | 1
13. sum.Cents accepte le negatif                              | 1
14. roles.Parse n'uniformise plus la casse                      | 1

14/14 modifications detectees
```

Quatre remarques de méthode, parce que le relevé final cache le chemin.

**Trois modifications n'ont d'abord pas compilé** — les 6, 13 et 14. À chaque
fois, retirer le code laissait une variable ou un import inutilisé. Une
modification qui ne compile pas n'est ni détectée ni survivante : **elle n'a
pas été jouée**. Il faut la rejouer sous une forme qui compile, et ça prend
deux minutes : `if false && n < 0` plutôt que la suppression de la ligne.

**La modification 6 est la plus instructive.** Retirer le `case nil` de
`retention.Duration` ne fait pas tomber le test qui passe `nil` — il passe
toujours, parce que le `default` l'attrape et rend la même erreur. Elle fait
tomber **le test d'exhaustivité**, qui exige le cas `nil` dans chaque
`switch`. Autrement dit : le garde-fou qui tient ici est celui qui lit la
source, pas celui qui essaie une valeur.

**La modification 8 est celle qui cherche la frontière.** Faire passer
`< AnneeDeLaReforme` à `<= AnneeDeLaReforme` ne change le résultat que pour
les contrats de l'année 2008 exactement. Elle tombe parce que le tableau de
test contient trois cas et que l'un d'eux est **le jour de l'an de 2008**. Un
tableau qui aurait testé 2007 et 2026 seulement aurait laissé passer une
erreur de cinq contre trente ans sur une année entière de contrats.

> Dans une règle qui dépend d'une date de réforme, le cas de test obligatoire
> n'est pas « avant » et « après » : c'est **la veille, le jour, et le
> lendemain**.

**La modification 9 est un rappel.** Elle casse `PlusAnnees` en ajoutant des
mois, et elle fait tomber deux tests dont l'un est le 29 février. Ce test
existe parce que `PlusAnnees` **documente son choix** plutôt que de le subir :
un 29 février plus cinq ans n'existe pas, et il tombe au 1er mars. Un
comportement documenté est un comportement testable ; un comportement subi ne
l'est pas.

## 7. Ce que cet exercice devait faire comprendre

1. **L'axe se lit dans l'énoncé**, et ici il y était en toutes lettres :
   « pas un cinquième avant deux ans » d'un côté, « une nouvelle par
   trimestre » de l'autre.
2. **Le critère de la méthode décide seul** de ce qui va sur la variante.
   `Label` oui, les trois autres non, et la liste des imports le prouve.
3. **La clôture est gratuite, l'exhaustivité se paie** : 236 lignes de test,
   dont une centaine de `go/ast`.
4. **`nil` est la cinquième variante**, et elle ne se déclare nulle part.
5. **Les assertions de conformité sont mesurables** : 8, 4, 0 selon la
   configuration — et le 4 vient d'un littéral de slice que personne n'avait
   écrit pour ça.
6. **Un test qui indexe par position panique au lieu d'échouer.** C'est
   l'expérience qui me l'a appris, pas la relecture.
7. **Une modification qui ne compile pas n'a pas été jouée.** Rejoue-la.
