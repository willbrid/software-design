# Correction 2.2 — Exercice 1 : la plateforme de notification

> Rappel de l'énoncé : une interface `Channel` à huit méthodes, cinq
> implémentations, trois appelants aux besoins différents, et un relevé de
> quatorze mois qui donne un canal ajouté contre quatre méthodes ajoutées.

La réponse n'est ni « une interface » ni « un ensemble scellé ». C'est qu'il
**n'y a pas un seul ensemble**, et que cinq des huit méthodes n'ont jamais été
du polymorphisme. Tout ce qui suit est mesuré sur un module qui compile, dont
les cinq paquets de test passent sous `go vet` et `go test -race -count=1`.

## 1. L'axe du changement

### Ce que dit le relevé

| | Sur quatorze mois |
|---|---|
| canaux ajoutés | **1** |
| méthodes ajoutées à `Channel` | **4** |
| modifications d'implémentations existantes | **31** |

Les deux premières lignes donnent l'axe sans ambiguïté : **les opérations
arrivent, les variantes non**. Un canal tous les quatorze mois, une question
nouvelle tous les trois mois et demi. Avec l'interface actuelle, chaque
question nouvelle a coûté **cinq modifications** — une par implémentation — et
le métier n'a jamais rien demandé de ce qui aurait rendu ces cinq
modifications utiles.

### Ce que la troisième ligne ajoute, et que la plupart des réponses oublient

Trente-et-une modifications d'implémentations existantes, c'est **plus de deux
par mois**. Ce chiffre ne s'explique pas par les quatre méthodes ajoutées : il
faut aller voir ce qu'elles changeaient.

Et quand on va voir, on trouve des tarifs, des plafonds, des numéros de
compte. `UnitCostFCFA` qui passe de 14 à 15 FCFA. `MaxLength` d'un
canal WhatsApp qui passe de 1 024 à 4 096. Une ligne de refacturation
renumérotée par le cabinet comptable.

> Trente-et-une modifications de code pour trente-et-un changements de
> **données**. Le relevé ne dit pas seulement sur quel axe le changement
> arrive : il dit aussi que **la moitié de cette interface n'aurait jamais dû
> être du code**.

C'est le fil à tirer, et il mène à la vraie réponse.

## 2. Les huit méthodes, une par une

Le critère de la leçon : *une méthode appartient à la variante si et seulement
si elle se répond avec les champs de la variante*. Appliqué aux huit, il donne
trois groupes et non deux.

| Méthode | Se répond avec les champs ? | Verdict |
|---|---|---|
| `Name()` | oui | identité du canal — **reste** |
| `Send()` | oui, avec son transport | comportement — **reste** |
| `IsAvailable()` | oui, avec son transport | comportement — **reste** |
| `UnitCostFCFA()` | elle rend **une constante** | ce n'est pas une méthode, c'est une **donnée** |
| `MaxLength()` | elle rend **une constante** | donnée |
| `BillingLine()` | elle rend **une constante** | donnée |
| `MeanDelaySeconds()` | elle rend **une constante** | donnée |
| `SupporteAccuseDeReception()` | elle rend **une constante** | donnée |

Cinq des huit rendent une constante différente par implémentation. C'est mot
pour mot le cas de la leçon :

> Quand deux implémentations ne diffèrent que par des **constantes**, le
> polymorphisme est un tableau qui s'ignore.

Et on ne s'arrête pas à l'affirmation.

## 3. Le test qui tranche

```go
// TestFiveMethodsOutOfEightReduceToTheTable is the test that decides.
// It does not say the table is "cleaner". It says that for each of the
// five implementations, the five constant methods return exactly what
// the catalog entry returns. If it is true, these five methods
// told nothing apart: twenty-five methods replaced by five fields.
//
// The three remaining methods (Name, IsAvailable, Send) do not
// reduce: the first identifies, the other two are behavior.
func TestFiveMethodsOutOfEightReduceToTheTable(t *testing.T) {
    compare := 0
    for _, c := range before.All() {
        name, err := catalog.Parse(c.Name())
        if err != nil {
            t.Fatalf("%s missing from the catalog: %v", c.Name(), err)
        }
        entry, err := catalog.Read(name)
        if err != nil {
            t.Fatal(err)
        }
        if got, want := c.UnitCostFCFA(), entry.UnitCostFCFA; got != want {
            t.Errorf("%s: cost %d, table %d", c.Name(), got, want)
        }
        if got, want := c.MaxLength(), entry.MaxLength; got != want {
            t.Errorf("%s: max length %d, table %d", c.Name(), got, want)
        }
        if got, want := c.BillingLine(), entry.BillingLine; got != want {
            t.Errorf("%s: line %q, table %q", c.Name(), got, want)
        }
        if got, want := c.MeanDelaySeconds(), entry.MeanDelaySeconds; got != want {
            t.Errorf("%s: delay %d, table %d", c.Name(), got, want)
        }
        if got, want := c.SupporteAccuseDeReception(), entry.DeliveryReceipt; got != want {
            t.Errorf("%s: receipt %v, table %v", c.Name(), got, want)
        }
        compare += 5
    }
    if compare != 25 {
        t.Fatalf("%d comparisons, want 25", compare)
    }
    t.Logf("%d comparisons over 5 channels: the 5 constant methods and the table return the same thing",
        compare)
}
```

```
25 comparaisons sur 5 canaux : les 5 methodes constantes et la table rendent la meme chose
```

Vingt-cinq comparaisons, vingt-cinq égalités. Les cinq méthodes ne
distinguaient rien : **vingt-cinq méthodes remplacées par cinq champs.**

Les trois autres ne s'y ramènent pas, et c'est aussi important : `Name`
identifie, `IsAvailable` et `Send` sont du comportement réel qui dépend
d'un réseau. Le test ne les compare pas, parce qu'il n'y a rien à comparer.

## 4. La conception qui en découle

### Le catalogue — ce qui n'était jamais du polymorphisme

```go
// Entry is a channel's catalog line.
// Five fields, replacing five methods. Note that none is a
// behavior: they are contractual facts, they change by amendment, and
// they never needed to be code.
type Entry struct {
    // UnitCostFCFA is the cost of one send, billed back to the client.
    UnitCostFCFA int
    // MaxLength is the number of bytes beyond which the message is
    // refused. Zero means "no limit", and it is the fix of the
    // flaw of the statement: PostalMail returned 0 for "no limit"
    // while SMS returned 160 for "160".
    MaxLength int
    // BillingLine is the rebilling account.
    BillingLine string
    // MeanDelaySeconds is the observed delivery delay, not the promised one.
    MeanDelaySeconds int
    // DeliveryReceipt says whether the channel can confirm delivery.
    DeliveryReceipt bool
}
```

Deux détails qui règlent la question 3 de l'énoncé.

**`MaxLength` à zéro signifie « sans limite »**, et c'est écrit dans la
documentation du champ. Dans le modèle d'origine, `PostalMail` rendait `0`
pour « pas de limite » et `SMS` rendait `160` pour « 160 octets » — la même
signature, deux sens incompatibles, et aucun appelant capable de les
distinguer. Ici le sens est décidé **à un seul endroit**, et un test le garde.

**`Read` rend une erreur et non une fiche vide.** Une fiche vide signifierait
« gratuit, sans limite, remise instantanée » : exactement le contraire du
choix le plus restrictif, qui est la règle de la leçon 2.1 sur la valeur zéro.

```go
// Read returns a channel's entry, or says it does not exist.
// It returns an error and not an empty entry: an empty entry would mean
// "free, no limit, instant delivery", that is the opposite of
// most restrictive choice.
func Read(n Name) (Entry, error) {
    f, ok := entries[n]
    if !ok {
        return Entry{}, fmt.Errorf("%w: %q", ErrUnknownChannel, n)
    }
    return f, nil
}

// Parse canonicalizes a name that came from configuration.
//
// The ORDER of the three normalizations is not commutative, and a test
// showed it. My first version replaced spaces with underscores
// BEFORE trimming the edges: "  WhatsApp  " became "__WHATSAPP__", and
// the channel was not found. The edges must be trimmed first.
func Parse(s string) (Name, error) {
    n := Name(strings.ReplaceAll(strings.ToUpper(strings.TrimSpace(s)), " ", "_"))
    if _, ok := entries[n]; !ok {
        return "", fmt.Errorf("%w: %q", ErrUnknownChannel, s)
    }
    return n, nil
}
```

Et une chose que je n'avais pas vue en écrivant `Parse` :

> **L'ordre des normalisations n'est pas commutatif.** Ma première version
> remplaçait les espaces par des tirets bas **avant** de couper ceux du bord :
> `"  WhatsApp  "` devenait `"__WHATSAPP__"`, et le canal n'était pas trouvé.
> Un test l'a dit, pas une relecture.

### L'interface, et elle n'a que trois méthodes

```go
// Sender is THIS PACKAGE's interface. Three methods, because this
// package calls three, and not eight.
//
// It is declared here and not next to the implementations. Its signature
// names only shared types (string and catalog.Name), so an
// implementation need not import this package.
type Sender interface {
    Channel() catalog.Name
    IsAvailable() bool
    Send(recipient, body string) (id string, err error)
}

// Journal records what dispatch does.
//
// Selection is called at the moment of CHOICE, before knowing whether it works:
// without this line, a channel outage cannot be attributed, because whoever
// who writes the result line does not know which channel was chosen.
type Journal interface {
    Selection(reference string, channel catalog.Name)
    Result(reference string, channel catalog.Name, err error)
}
```

Elle est déclarée chez `dispatch`, parce que c'est `dispatch` qui s'en
sert. Elle a trois méthodes parce que `dispatch` en appelle trois. Et sa
signature ne nomme que `string` et `catalog.Name` — du vocabulaire partagé —
donc une implémentation n'a pas à importer son appelant. La mesure :

```
$ for p in catalogue expedition canaux redaction facturation; do
>   printf '%-14s : ' $p; go list -f '{{join .Imports " "}}' ./$p
> done
catalogue      : errors fmt strings
expedition     : errors example/notification/catalog fmt
canaux         : errors example/notification/catalog fmt
redaction      : example/notification/catalog strings unicode/utf8
facturation    : example/notification/catalog fmt
```

`channels` n'importe pas `dispatch`. Et `catalog` n'importe rien du module :
c'est le vocabulaire, il est en bas.

### Les deux autres appelants ne déclarent aucune interface

C'est le résultat de l'exercice, et c'est celui qui surprend.

```go
// Package redact truncates and formats a message.
//
// It declares NO interface, and that is the result of the exercise.
//
// The statement says it calls only MaxLength(). A maximum length
// is not a behavior, it is a number: so this package does not need
// of a channel, it needs an entry. It declares no interface, it has
// no double to write, and none of its tests needs a fake channel.
package redact

import (
    "strings"
    "unicode/utf8"

    "example/notification/catalog"
)

// Marker is what we add when we cut.
const Marker = "..."
```

L'énoncé dit que `redact` n'appelle que `MaxLength()`. Une longueur
maximale n'est pas un comportement, c'est un nombre. Ce paquet n'a donc pas
besoin d'un canal : **il a besoin d'une fiche**. Il ne déclare pas
d'interface, il n'a pas de double à écrire, et aucun de ses tests n'a besoin
d'un faux canal.

Même chose pour `facturation`, qui n'appelait que `UnitCostFCFA` et
`BillingLine`.

| Appelant | Interface déclarée | Méthodes | Double de test |
|---|---|---|---|
| `dispatch` | `Sender` | 3 | 3 méthodes, toutes lues |
| `redact` | **aucune** | — | **aucun** |
| `facturation` | **aucune** | — | **aucun** |

> Deux appelants sur trois n'avaient pas besoin de polymorphisme. Ils avaient
> besoin d'une donnée, et on leur avait donné une interface à huit méthodes.

## 5. Les doubles, comptés (question 4)

L'énoncé demandait le compte. Il est dans le code, pas dans une estimation.

### Avant

Trois appelants, chacun avec son double de l'interface à huit méthodes. Voilà
celui d'`dispatch`, écrit en entier et conservé dans le dépôt pour être
compté :

```go
// --- The double the original interface would have needed ---

// doubleWithEightMethods is used by no test. It is here to be
// COUNT: it is what would have had to be written, in each of the three
// callers, with the statement's eight-method interface.
//
// Five of its eight methods are never read by the dispatch code. And
// five useless methods in a double are not five lines too many:
// they are five places where a future method will hide, and five values
// that nobody checks.
type doubleWithEightMethods struct{ available bool }

func (doubleWithEightMethods) Name() string                     { return "SMS" }
func (d doubleWithEightMethods) IsAvailable() bool              { return d.available }
func (doubleWithEightMethods) Send(d, c string) (string, error) { return "SMS-1", nil }
func (doubleWithEightMethods) UnitCostFCFA() int                { return 0 }     // never read here
func (doubleWithEightMethods) MaxLength() int                   { return 0 }     // never read here
func (doubleWithEightMethods) SupporteAccuseDeReception() bool  { return false } // never read here
func (doubleWithEightMethods) MeanDelaySeconds() int            { return 0 }     // never read here
func (doubleWithEightMethods) BillingLine() string              { return "" }    // never read here
```

| Appelant | Méthodes à écrire | Méthodes réellement lues | **Vides** |
|---|---|---|---|
| `dispatch` | 8 | `Name`, `IsAvailable`, `Send` → 3 | **5** |
| `facturation` | 8 | `Name`, `UnitCostFCFA`, `BillingLine` → 3 | **5** |
| `redact` | 8 | `MaxLength` → 1 | **7** |
| **total** | **24** | **7** | **17** |

### Après

```go
// --- The double this package needs: THREE methods ---

// doubleWithThreeMethods is the double of the interface declared by dispatch.
//
// Three methods, and all three are called by the tested code. Zero empty
// empty. It is the measure of the exercise, and it compares with the double of
// next section.
type doubleWithThreeMethods struct {
    channel   catalog.Name
    available bool
    err       error
    calls     []string
    // journal is not a convenience: it is the observation point.
    //
    // My first version of this double wrote nothing to the journal, and the
    // order test compared only "selection" then "result". A
    // change of the campaign laid it bare: by moving the call to
    // Selection AFTER e.Send(...), the journal's sequence stays the same,
    // because Result comes after Selection in both cases. The test
    // survived the change it was supposed to catch, and it is the
    // SECOND time in this chapter, after the lesson itself.
    //
    //    An order test must be observed from the INTERMEDIATE point, not
    //    from the end of the chain. Knowing the rule is not enough: one
    //    takes the test that applies it.
    journal *orderedJournal
}

func (d *doubleWithThreeMethods) Channel() catalog.Name { return d.channel }
func (d *doubleWithThreeMethods) IsAvailable() bool     { return d.available }
func (d *doubleWithThreeMethods) Send(dest, body string) (string, error) {
    d.calls = append(d.calls, dest+"/"+body)
    if d.journal != nil {
        d.journal.rest = append(d.journal.rest, "call:"+string(d.channel))
    }
    if d.err != nil {
        return "", d.err
    }
    return string(d.channel) + "-1", nil
}
```

| Appelant | Méthodes à écrire | Vides |
|---|---|---|
| `dispatch` | 3 | 0 |
| `facturation` | 0 | 0 |
| `redact` | 0 | 0 |
| **total** | **3** | **0** |

**Vingt-quatre méthodes de double devenues trois, dix-sept méthodes vides
devenues zéro.** Et le chiffre qui compte le plus est le dix-sept :

> Cinq méthodes inutiles dans un double, ce ne sont pas cinq lignes de trop :
> ce sont cinq endroits où une future méthode ira se cacher, et cinq valeurs
> que personne ne vérifie.

## 6. Les deux questions difficiles

### Question 5 — `PostalMail.Send` et `SMS.Send` sont-ils la même opération ?

**Oui pour la signature, non pour le contrat.** Et c'est la seule réponse
honnête.

Les deux acceptent un destinataire et un corps, et rendent un identifiant ou
une erreur. C'est la même opération au sens de l'interface, et le type switch
serait ici une erreur.

Mais l'identifiant ne garantit pas la même chose. Pour le SMS, il dit « la
passerelle a accepté ». Pour le courrier postal, il dit « le fichier est
écrit », et la remise aura lieu douze heures plus tard — ou pas.

```go
// PostalMail files a document that a provider picks up twice a
// day.
//
// It is the answer to question 5: Send is indeed the same OPERATION as
// as SMS (accept a message and return an identifier), but
// the identifier does NOT guarantee the same thing. For SMS it says "the
// gateway accepted". Here it says "the file is written", and delivery
// will happen twelve hours later.
//
// So the difference is not in the interface, it is in the CONTRACT of
// the interface, and that is why it is written here.
type PostalMail struct {
    Repo Gateway
}

func (PostalMail) Channel() catalog.Name { return catalog.PostalMail }

func (c PostalMail) IsAvailable() bool { return c.Repo != nil }

func (c PostalMail) Send(recipient, body string) (string, error) {
    if c.Repo == nil {
        return "", fmt.Errorf("%w: no repo configured", ErrGateway)
    }
    ref, err := c.Repo.Deliver(recipient, body)
    if err != nil {
        return "", fmt.Errorf("%w: repo: %w", ErrGateway, err)
    }
    // The prefix says what the identifier guarantees, and what it does not
    // not. A caller reading it knows it does not have a delivery.
    return "FILED:" + ref, nil
}
```

La différence n'est donc pas dans l'interface, elle est dans le **contrat** de
l'interface. Et puisqu'un contrat non écrit n'est pas un contrat, il est
écrit : le préfixe `FILED:` dit ce que l'identifiant ne garantit pas, et un
test le vérifie.

> Deux implémentations qui satisfont la même signature avec des garanties
> différentes ne sont pas substituables. L'interface ne le voit pas ; c'est le
> sujet de la leçon 2.4.

### Question 6 — pourquoi « sceller `Channel` et mettre les quatre dernières méthodes dans des `switch` » est la mauvaise réponse

Deux raisons, et elles sont indépendantes.

**La première : quatre de ces questions ne sont pas des questions.** Mettre
`UnitCostFCFA` dans un `switch` chez `facturation`, c'est déplacer une
table de tarifs du code vers… du code. On garde les trente-et-une
modifications de code pour trente-et-un changements de données, et on ajoute
un test d'exhaustivité pour les surveiller. Le scellement est l'outil juste
pour un ensemble fermé de variantes avec des opérations ouvertes ; il n'est
pas l'outil pour des constantes.

**La seconde : l'ensemble n'est pas fermé, il est en train de s'ouvrir** — et
c'est la question 7 qui le dit.

### Question 7 — les trois agrégateurs SMS en A/B

Le marketing veut tester trois agrégateurs sur le trafic réel, et pouvoir en
changer sans redéploiement. Ça change la réponse à la question 1, mais **pas
partout** :

| | Avant la demande | Après |
|---|---|---|
| l'ensemble des **canaux** | fermé (1 en 14 mois) | toujours fermé |
| l'ensemble des **transports d'un canal** | 1 par canal | **ouvert**, et il bouge à la semaine |

C'est un deuxième ensemble, et il s'ouvre **sur une branche** du premier. La
réponse de la leçon s'applique telle quelle : *les deux autant → tu as deux
ensembles, pas un. Sépare-les.*

```go
// SMS sends through an SMS aggregator.
// Note the Aggregator field: it is the answer to question 7 of the statement.
// The day marketing wants to A/B test three aggregators, the set
// of variants opens ON THIS BRANCH and on it alone, and it is already
// an interface, so there is nothing to redo.
type SMS struct {
    Aggregator string
    Gateway    Gateway
}

func (SMS) Channel() catalog.Name { return catalog.SMS }

func (s SMS) IsAvailable() bool { return s.Gateway != nil }

func (s SMS) Send(recipient, body string) (string, error) {
    if s.Gateway == nil {
        return "", fmt.Errorf("%w: %s without a gateway", ErrGateway, s.Aggregator)
    }
    id, err := s.Gateway.Deliver(recipient, body)
    if err != nil {
        return "", fmt.Errorf("%w: %s: %w", ErrGateway, s.Aggregator, err)
    }
    return s.Aggregator + ":" + id, nil
}
```

L'interface `Gateway` a **une** méthode, elle est déclarée par `channels`, et
le champ `Aggregator` nomme celui qui a été retenu. Le découpage fait que cet
ajout ne touche à rien d'autre : ni au catalogue, ni à `dispatch`, ni aux
quatre autres canaux.

Et ce que la leçon dit d'indispensable, et qui est le vrai sujet de la
question 7 :

> Toute sélection dynamique doit être journalisée **au point de sélection**,
> et **avant** l'appel. Sans ça, le jour où l'agrégateur B se dégrade, le taux
> d'échec global monte de deux points et personne ne sait lequel des trois en
> est la cause.

C'est pour ça que `Journal` a deux méthodes et que `Selection` est appelée
avant `Send` :

```go
// Send tries the senders in order and returns the first that succeeds.
func Send(j Journal, reference, recipient, body string, candidates ...Sender) (string, error) {
    if len(candidates) == 0 {
        return "", fmt.Errorf("%w: %s", ErrNoChannel, reference)
    }
    var last error
    for _, e := range candidates {
        entry, err := catalog.Read(e.Channel())
        if err != nil {
            last = err
            continue
        }
        if entry.MaxLength > 0 && len(body) > entry.MaxLength {
            last = fmt.Errorf("%w: %d bytes for %s which accepts %d",
                ErrTooLong, len(body), e.Channel(), entry.MaxLength)
            continue
        }
        if !e.IsAvailable() {
            last = fmt.Errorf("%w: %s", ErrUnavailable, e.Channel())
            continue
        }
        // The choice is logged BEFORE the call: if the send times out
        // and the process is then killed, the selection line already exists.
        j.Selection(reference, e.Channel())
        id, err := e.Send(recipient, body)
        j.Result(reference, e.Channel(), err)
        if err == nil {
            return id, nil
        }
        last = err
    }
    return "", last
}
```

## 7. Les assertions de conformité

Le modèle d'origine n'en avait aucune. Mesure, sur l'ajout d'une neuvième
méthode à `Channel` :

```
Une neuvieme methode est ajoutee a before.Channel.
  avec les 5 assertions : 10 err(s) de compilation
  sans les assertions   :  5 err(s) de compilation
```

Les cinq du bas viennent du littéral de `All()`, qui assigne les cinq
implémentations à `Channel` — une assertion de conformité qui ne se présente pas
comme telle. Les cinq du haut sont les lignes explicites.

Sans `All()` **et** sans les assertions, il y en aurait zéro : Go n'a pas de
déclaration `implements`, donc le compilateur n'a rien à vérifier.

## 8. La campagne de modifications

Onze modifications, cinq paquets de test.

```
modification                                                  | tests qui tombent
--------------------------------------------------------------+------------------
 1. le catalogue perd la fiche du courrier postal             | 7
 2. Read rend une fiche vide au lieu d'une erreur             | 3
 3. Parse ne coupe plus les espaces du bord                | 1
 4. une longueur maximale nulle devient un refus              | 1
 5. la selection est journalisee APRES l'appel                | 2
 6. la disponibilite est verifiee apres l'envoi               | 2
 7. la coupe se fait sur les octets et non les runes          | 1
 8. Preparer ne dit plus qu'il a tronque                      | 2
 9. la refacturation oublie la quantite                       | 4
10. le SMS n'enveloppe plus l'erreur de sa passerelle         | 1
11. l'identifiant du courrier ne dit plus ce qu'il garantit   | 1

11/11 modifications detectees
```

Et l'aveu qui va avec, parce qu'il vaut plus que le relevé.

**La modification 5 a d'abord survécu.** Exactement comme dans la leçon, pour
exactement la même raison : mon `orderedJournal` n'enregistrait que les appels
au journal, donc déplacer `Selection` après `Send` laissait la suite
inchangée — *sélection* puis *résultat* dans les deux cas.

J'avais écrit la règle dans la leçon 2.2 une heure plus tôt. Je l'ai refaite.

> **Connaître la règle ne suffit pas : il faut le test qui l'applique.** Un
> test d'ordre s'observe depuis le point intermédiaire, et le seul moyen de s'y
> tenir est que le double lui-même écrive son passage dans la suite observée.

La modification 7 mérite un mot aussi. Couper un message sur les **octets**
plutôt que sur les **runes** casse un caractère accentué en deux, et le client
reçoit un losange noir à la place. Le test qui l'attrape utilise 81 fois « é »
— 162 octets sur un canal à 160, donc la coupe tombe pile au milieu du dernier
caractère. Sans ce cas limite, la modification survivait.

## 9. Ce que cet exercice devait faire comprendre

1. **Le relevé a trois colonnes, pas deux.** Les deux premières donnent l'axe,
   la troisième dit si l'interface contient des données déguisées en code.
2. **Cinq méthodes sur huit n'étaient pas du polymorphisme**, et un test
   d'équivalence le démontre en vingt-cinq comparaisons.
3. **La bonne réponse n'était ni l'interface ni le type somme** : c'était une
   table plus une interface à trois méthodes.
4. **Deux appelants sur trois n'avaient besoin d'aucune interface.** Ils
   avaient besoin d'un nombre.
5. **Le compte des doubles est la mesure**, et il passe de 24 méthodes dont 17
   vides à 3 méthodes dont 0 vide.
6. **Deux implémentations peuvent satisfaire la même signature avec des
   garanties différentes.** L'interface ne le voit pas, le contrat doit le
   dire, et c'est la leçon 2.4.
7. **Un ensemble peut s'ouvrir sur une seule de ses branches.** Deux
   ensembles, deux mécanismes, et le découpage fait que l'ouverture ne coûte
   rien ailleurs.
