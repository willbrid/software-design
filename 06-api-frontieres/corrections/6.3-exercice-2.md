# Correction 6.3 — Exercice 2 : une clé par membre

> Rappel de l'énoncé : rendre les cotisations idempotentes avec une clé
> unique pour un membre.

La solution est dans `ex2` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **La clé primaire est `(member, key)`** : deux membres peuvent tirer la
  même clé sans se gêner.
- **Le reste est le serveur de la leçon** : la clé prise d'abord, la
  cotisation, la réponse rangée, dans une transaction.
- **Le membre vient de l'authentification**, jamais du corps.

## 1. La solution

```go
// Handler serves POST /contributions. The key is claimed for the member,
// in the transaction that records the contribution.
func Handler(pool *pgxpool.Pool) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        member, key := r.Header.Get("X-Member"), r.Header.Get("Idempotency-Key")
        body, err := io.ReadAll(http.MaxBytesReader(w, r.Body, 4<<10))
        var req Request
        if err == nil {
            err = json.Unmarshal(body, &req)
        }
        if err != nil || key == "" {
            http.Error(w, "a body and an Idempotency-Key", http.StatusBadRequest)
            return
        }
        hash := sha256.Sum256(body)
        ctx := r.Context()
        var replay bool
        var status int
        var stored, storedHash []byte
        err = pgx.BeginFunc(ctx, pool, func(tx pgx.Tx) error {
            tag, err := tx.Exec(ctx, `INSERT INTO idempotency_key (member, key, request_hash) VALUES ($1, $2, $3)
                ON CONFLICT (member, key) DO NOTHING`, member, key, hash[:])
            if err != nil {
                return err
            }
            if tag.RowsAffected() == 0 {
                replay = true
                return tx.QueryRow(ctx, `SELECT request_hash, status, response FROM idempotency_key
                    WHERE member = $1 AND key = $2`, member, key).Scan(&storedHash, &status, &stored)
            }
            var c Contribution
            if err := tx.QueryRow(ctx, `INSERT INTO contribution (member, round, amount_fcfa) VALUES ($1, $2, $3)
                RETURNING id, member, round, amount_fcfa`, member, req.Round, req.AmountFCFA).Scan(&c.ID, &c.Member, &c.Round, &c.AmountFCFA); err != nil {
                return err
            }
            status = http.StatusCreated
            if stored, err = json.Marshal(c); err != nil {
                return err
            }
            _, err = tx.Exec(ctx, `UPDATE idempotency_key SET status = $3, response = $4
                WHERE member = $1 AND key = $2`, member, key, status, stored)
            return err
        })
        switch {
        case err != nil:
            http.Error(w, "unavailable", http.StatusServiceUnavailable)
        case replay && !bytes.Equal(hash[:], storedHash):
            http.Error(w, "this key was used for another request", http.StatusUnprocessableEntity)
        default:
            w.Header().Set("Content-Type", "application/json")
            w.WriteHeader(status)
            _, _ = w.Write(stored)
        }
    })
}
```

## 2. Pourquoi le membre vient de l'authentification

Si le membre venait du corps, un client pourrait envoyer la clé d'un
autre membre avec le nom de cet autre membre, et recevoir **sa**
réponse gardée : l'identifiant, le montant, et ce que contient la
réponse. La portée de la clé n'a de sens que si celui qui la présente ne
peut pas choisir à qui elle appartient. En production, `X-Member` est
remplacé par l'identité tirée du jeton d'authentification (niveau 10).

## 3. Ce qui change pour la purge

La purge garde son critère, `created_at`, et la clé primaire composée ne
la ralentit pas. Pour un membre très actif, un index sur
`(created_at)` permet de purger par tranche sans lire toute la table
(leçon 5.5).

## Ce qu'il faut retenir

- Une clé est unique pour celui qui la tire : `(client, key)`.
- Le client de la clé est celui qui est authentifié.
- Le mécanisme ne change pas : prendre, faire, ranger, dans une
  transaction.
