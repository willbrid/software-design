## Exercice 1 — Compréhension

Un cron horaire synchronise l'annuaire de l'entreprise vers la base applicative.

```go
package annuaire

import (
    "bytes"
    "context"
    "database/sql"
    "fmt"
    "os"
    "strings"
)

type Entree interface{ Attr(nom string) string }

type Annuaire interface {
    Rechercher(filtre string) ([]Entree, error)
}

type Expediteur interface {
    Envoyer(dest, sujet, corps string) error
}

type Metriques interface{ Inc(nom string) }

type Service struct {
    ldap      Annuaire
    db        *sql.DB
    smtp      Expediteur
    metriques Metriques
}

func (s *Service) SynchroniserUtilisateurs(ctx context.Context) error {
    entrees, err := s.ldap.Rechercher("(objectClass=person)")
    if err != nil {
        return err
    }

    var rapport bytes.Buffer
    fmt.Fprintln(&rapport, "login;email;statut")

    for _, e := range entrees {
        login := strings.ToLower(strings.TrimSpace(e.Attr("uid")))
        email := login + "@exemple.cm"

        res, err := s.db.ExecContext(ctx,
            "INSERT INTO utilisateurs (login, email) VALUES ($1, $2) ON CONFLICT DO NOTHING",
            login, email,
        )
        if err != nil {
            return err
        }

        if n, _ := res.RowsAffected(); n == 1 {
            corps := fmt.Sprintf("Bienvenue %s, ton compte est actif.", login)
            if err := s.smtp.Envoyer(email, "Bienvenue", corps); err != nil {
                return err
            }
            s.metriques.Inc("utilisateurs_crees")
        }

        fmt.Fprintf(&rapport, "%s;%s;ok\n", login, email)
    }

    return os.WriteFile("/var/rapports/sync.csv", rapport.Bytes(), 0o644)
}
```

1. **Recense les décideurs.** Pour chaque bloc de la fonction, dis ce qui y est
   décidé et **qui**, dans l'entreprise, peut exiger que ça change. Sois
   précis : « le métier » n'est pas une réponse, « l'équipe qui administre
   l'annuaire » en est une.
2. Trois demandes arrivent le même trimestre :
   - (a) l'annuaire expose désormais un attribut `department` qu'il faut stocker ;
   - (b) le marketing réécrit le texte de bienvenue ;
   - (c) le rapport doit passer du CSV au JSON.

   Pour **chacune** : quels blocs faut-il ouvrir, et quels blocs risquent de
   casser alors qu'on n'y a pas touché ?
3. Le cron tourne toutes les heures. Un jour, l'envoi d'email échoue au 40ᵉ
   utilisateur sur 200. Décris l'état du système à cet instant, puis ce que fera
   l'exécution suivante. Le résultat final est-il correct ? Est-il **prévisible** ?
4. Voici deux découpes proposées en réunion. Laquelle découpe par **étapes** et
   laquelle par **raison de changer** ?

   - **A** — `lire()`, `transformer()`, `ecrire()`, `notifier()`, `rapporter()`
   - **B** — `annuaire` (le protocole et le format LDAP), `comptes` (la règle de
     création d'un compte), `notif`, `rapport`

   Justifie autrement que par les noms : trouve une demande de changement qui
   coûte cher dans l'une et pas dans l'autre.

## Exercice 3 — Refactoring

Un service de facturation SaaS, trois ans d'existence.

```go
package facturation

import (
    "database/sql"
    "log/slog"
    "net/http"
)

type Cache interface {
    Get(cle string) ([]byte, bool)
    Set(cle string, v []byte)
    Supprimer(motif string)
}

type Expediteur interface {
    Envoyer(dest, sujet, corps string) error
}

type Config struct {
    SeuilQuota int
    TauxTVA    int64
}

type Service struct {
    db        *sql.DB
    cache     Cache
    smtp      Expediteur
    facturier *http.Client
    log       *slog.Logger
    cfg       Config
}
```

Huit méthodes : `CreerAbonnement`, `ResilierAbonnement`, `CalculerQuota`,
`ConsommerQuota`, `GenererFacture`, `EnvoyerFacture`, `ExporterComptabilite`,
`PurgerCache`.

Voici les dix derniers commits qui ont touché ce fichier.

| # | Message de commit | Méthodes modifiées |
|---|---|---|
| 1 | feat: palier 100 Go | `CalculerQuota`, `ConsommerQuota`, `PurgerCache` |
| 2 | fix: quota non décrémenté sur les comptes suspendus | `ConsommerQuota`, `CalculerQuota` |
| 3 | feat: quotas différenciés par pays | `CalculerQuota`, `ConsommerQuota`, `PurgerCache` |
| 4 | chore: TVA 19,25 % → 20 % | `GenererFacture`, `ExporterComptabilite` |
| 5 | fix: arrondi comptable sur les avoirs | `GenererFacture`, `ExporterComptabilite`, `PurgerCache` |
| 6 | feat: résiliation avec préavis de 30 jours | `CreerAbonnement`, `ResilierAbonnement`, `PurgerCache` |
| 7 | fix: date d'effet de la résiliation | `ResilierAbonnement`, `CreerAbonnement` |
| 8 | chore: migration Mailgun → Sendgrid | `EnvoyerFacture` |
| 9 | feat: relance automatique à J+7 | `EnvoyerFacture` |
| 10 | feat: export au format FEC | `ExporterComptabilite`, `GenererFacture`, `PurgerCache` |

1. **À partir du seul historique**, propose les frontières. Combien de modules,
   lesquels, et quelles méthodes dans chacun ?
2. Une découpe qui paraît évidente à la lecture des **noms** est démentie par
   l'historique. Laquelle ? Et laquelle des deux crois-tu — pourquoi ?
3. `PurgerCache` apparaît dans 5 commits sur 10, répartis sur tous les groupes.
   Que révèle ce chiffre ? Est-ce une responsabilité ? Que proposes-tu ?
4. Répartis les six champs de la struct entre tes modules. Un champ peut-il
   apparaître dans deux modules ? Un module peut-il n'en avoir aucun ?
5. Quel changement futur rendrait ta découpe fausse ? Nomme-le précisément.

## Exercice 4 — Design

Règle métier : **une facture de plus de 1 000 000 FCFA exige une double
validation avant d'être envoyée au client.**

Cinq emplacements possibles :

| | Emplacement |
|---|---|
| A | le handler HTTP |
| B | le service applicatif |
| C | le type `Facture` lui-même |
| D | une contrainte `CHECK` en base |
| E | un *trigger* en base |

1. Pour chaque emplacement : ce qu'il garantit **vraiment**, et ce qu'il coûte
   (ergonomie, testabilité, maintenance, portabilité).
2. Six mois plus tard arrivent un import batch CSV, puis une API partenaire, puis
   un script de rattrapage lancé à la main par le support. Quels emplacements
   survivent à ces trois nouveaux points d'entrée, lesquels sont contournés ?
3. Le seuil va évoluer : indexé sur l'inflation, puis différencié par pays, puis
   par segment client. Ton emplacement encaisse-t-il ça ? **Le demandeur du
   seuil et le demandeur du mécanisme de double validation sont-ils la même
   personne ?** Qu'est-ce que ça implique sur la découpe ?
4. Peut-on rendre l'état « facture au-dessus du seuil, envoyée sans double
   validation » **non représentable** (⚫) ? Si oui, décris le mécanisme. Si non,
   dis ce qui l'en empêche et quel est le meilleur niveau atteignable.

## Exercice 5 — Incident de production

Plateforme SaaS. Extrait du post-mortem.

```
14h02  déploiement du commit « fix: typo dans l'email de bienvenue »
14h03  taux d'erreur 5xx sur POST /factures : 100 %
14h05  alerte PagerDuty
14h31  décision de rollback
14h42  service rétabli
```

Cause immédiate établie après coup : le commit touchait `service.go`, fichier qui
contient aussi `GenererFacture`. Le même commit embarquait un `go get` de mise à
jour du client HTTP interne, dont la nouvelle version fait passer le timeout par
défaut de 30 s à 5 s. L'appel au prestataire de paiement dépasse régulièrement
5 s.

1. Le typo n'est pas la cause. Nomme les **trois décisions de conception** qui
   ont rendu possible qu'un changement de libellé mette la facturation à terre.
2. Pourquoi 26 minutes entre l'alerte et la décision de rollback ? Qu'est-ce que
   la découpe en responsabilités a à voir avec le MTTR ?
3. Quelle découpe aurait borné le rayon d'explosion ? Sois concret : **quel
   artefact se déploie séparément**, et qu'est-ce qui reste partagé malgré tout ?
4. La CI était verte. Qu'est-ce qui aurait dû attraper ça, et pourquoi ne l'a pas
   fait ?
5. **Question ouverte.** Séparer le libellé du moteur de facturation a un coût :
   un contrat entre les deux, peut-être deux pipelines, peut-être deux dépôts. À
   partir de quel moment ce coût devient-il justifié ? Donne un **critère
   mesurable** — quelque chose qu'on peut lire dans le dépôt ou dans les
   métriques —, pas une intuition.
