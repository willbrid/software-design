# Leçon 1.5 — Erreurs et contrats

## L'essentiel en deux minutes

**Le problème, en une phrase.** Une opération peut finir de plusieurs
façons, et l'appelant doit savoir **laquelle** pour décider quoi faire.

**L'image.** Au guichet, tu demandes un retrait. Le guichetier peut te
répondre quatre choses très différentes : « solde insuffisant » (c'est une
réponse, pas une panne), « ce montant n'est pas valide » (c'est toi qui dois
corriger), « le système est en panne, revenez dans dix minutes » (il faut
réessayer), ou il se fige devant son écran (c'est un bug, il faut appeler
quelqu'un). Quatre réponses, **quatre conduites**. Si le guichetier disait
« erreur » pour les quatre, tu ne saurais pas quoi faire.

**Le code, en une cinquantaine de lignes.**

```go
// Package e15 is the two-minute version of lesson 1.5.
package e15

import (
    "errors"
    "fmt"
)

// One error per thing the caller does differently.
var (
    ErrNoFunds     = errors.New("insufficient funds") // a business answer: tell the customer
    ErrBadAmount   = errors.New("invalid amount")     // the caller's fault: fix the request
    ErrUnavailable = errors.New("ledger unavailable") // the environment: retry later
)

// Ledger is where balances live.
type Ledger interface {
    Balance(account string) (int64, error) // ErrUnavailable when it cannot answer
    Debit(account string, amount int64) error
}

// Withdraw debits amount, or says which of the outcomes happened. On any
// error, the balance is unchanged.
func Withdraw(l Ledger, account string, amount int64) error {
    if amount <= 0 {
        return fmt.Errorf("%w: %d", ErrBadAmount, amount)
    }
    b, err := l.Balance(account)
    if err != nil {
        return err
    }
    if b < amount {
        return fmt.Errorf("%w: balance %d, asked %d", ErrNoFunds, b, amount)
    }
    return l.Debit(account, amount)
}

// Conduct is what the caller does with each outcome. Anything else is a
// bug, and a bug is not handled: it is reported.
func Conduct(err error) string {
    switch {
    case err == nil:
        return "done"
    case errors.Is(err, ErrNoFunds):
        return "show the customer"
    case errors.Is(err, ErrBadAmount):
        return "fix the request"
    case errors.Is(err, ErrUnavailable):
        return "retry later"
    }
    return "alert: bug"
}
```

Chaque erreur exportée correspond à **une conduite** de l'appelant, et
`Conduct` le montre : afficher, corriger, réessayer. Ce qui ne correspond à
aucune est un bug — on ne le « gère » pas, on le signale. Et le commentaire
de `Withdraw` promet ce que la plupart des contrats oublient : **en cas
d'erreur, le solde n'a pas bougé**.

**Les règles à retenir.**

1. Concevoir une opération, c'est **énumérer ses issues** et dire, pour
   chacune, ce que l'appelant doit faire.
2. Quatre natures d'issues : une réponse métier, une faute de l'appelant,
   une défaillance de l'environnement, un bug. Elles demandent quatre
   conduites, donc quatre choses distinguables.
3. « Pas trouvé » ou « solde insuffisant » ne sont pas des pannes : ce sont
   des **réponses**.
4. Exporte autant d'erreurs que l'appelant a de conduites différentes, pas
   une de plus.
5. Un contrat dit ce qu'il faut fournir, ce qu'on obtient, et **ce qui reste
   vrai en cas d'échec**. C'est la troisième partie qui décide si une reprise
   est sûre.

La leçon 1.4 a posé une règle sans la développer : *les erreurs font partie du
vocabulaire, pas de l'implémentation*. On va la développer, et elle va plus
loin qu'il n'y paraît.

Parce que la vraie question n'est pas *« comment gérer les erreurs »*. C'est :
**quelles sont les issues possibles de cette opération, et qui décide de quoi
faire de chacune ?**

## 1. Le concept, simplement

### Une erreur est une issue, pas un accident

> Concevoir une opération, c'est énumérer ses **issues** — toutes — et leur
> associer une conduite. Ce qu'on appelle « gestion d'erreur » n'est que la
> moitié de ce travail, faite après coup.

Un `error` en Go n'est pas une exception : c'est une valeur de retour. Le
langage te force à la regarder, et c'est une chance, parce que la difficulté
n'a jamais été de propager une erreur — elle a toujours été de la
**classifier**.

### Les quatre natures d'une issue

Elles exigent quatre conduites différentes. C'est tout l'enjeu : si ton API ne
permet pas de les distinguer, tu as transféré à l'appelant un travail de
classification qu'il ne peut pas faire.

| Nature | Exemple | Qui est en cause | Conduite de l'appelant |
|---|---|---|---|
| **Réponse métier** | « niveau complet », « déjà inscrit », « pas trouvé » | personne | le dire à l'utilisateur, proposer autre chose |
| **Faute de l'appelant** | argument invalide, ordre d'appel, identité réutilisée | **lui** | corriger son code — réessayer ne changera rien |
| **Défaillance d'environnement** | réseau, disque, base saturée | personne | réessayer avec recul, se replier, délester |
| **Bug** | un invariant interne violé | **toi** | `panic` — et c'est le seul cas légitime |

La première ligne est celle qu'on range à tort parmi les erreurs. « Pas
trouvé » n'est pas un échec : c'est une **réponse**. Le code qui la reçoit a
une conduite prévue, souvent la plus banale du monde — afficher un message.

### Le test décisif

Une taxonomie d'erreurs peut déraper dans l'autre sens : quarante types
d'erreurs, et un seul `if err != nil` chez l'appelant. Le critère qui coupe
court :

> Le nombre d'erreurs distinctes qu'une API doit exposer est le nombre de
> **conduites distinctes** que son appelant peut tenir. Pas une de plus.

Deux issues qui mènent à la même conduite n'ont pas besoin d'être
distinguées. Et une issue qui ne mène à **aucune** conduite n'aurait pas dû
être rendue — elle appartient au journal, pas au contrat.

## 2. L'intuition

Un guichet d'inscription, au lycée, en septembre.

Tu présentes ton dossier. Quatre choses peuvent arriver :

- *« Il manque l'extrait de naissance. »* Tu sais quoi faire : tu reviens avec
  la pièce. **Le dossier est en cause.**
- *« La classe de sixième est complète. »* Ton dossier est parfait. Il n'y a
  rien à corriger. Tu demandes la liste d'attente ou un autre établissement.
  **C'est une réponse, pas un reproche.**
- *« Le logiciel est en panne, repassez cet après-midi. »* Personne n'est
  fautif. Tu reviens plus tard, et revenir a du sens.
- *« L'agent s'est trompé de registre. »* Ça, tu ne le sais pas et tu ne le
  sauras jamais. C'est un problème interne, qui se règle entre eux.

Quatre issues, quatre conduites. Maintenant imagine un guichet qui répondrait
seulement : *« ça n'a pas marché ».*

Tout le monde reviendrait le lendemain, y compris ceux dont le dossier est
incomplet — qui reviendraient avec le même dossier. Et la file serait trois
fois plus longue.

> C'est exactement ce que fait une API qui rend un `error` indifférencié : elle
> fait réessayer ceux qui n'ont aucune raison de réessayer, et elle fait
> abandonner ceux qui auraient dû insister.

## 3. Le mécanisme — un contrat a trois parties, et on n'en écrit qu'une

| Partie | Qui la tient | Ce qu'elle dit |
|---|---|---|
| **précondition** | l'**appelant** | ce qui doit être vrai avant l'appel |
| **postcondition** | l'appelé | ce qui sera vrai après, en cas de succès |
| **ce qui reste vrai en cas d'échec** | l'appelé | et c'est celle que personne n'écrit |

### La précondition, et qui la vérifie

Une précondition non vérifiée est une **obligation transférée en silence**. La
question n'est donc pas *« faut-il valider ? »* mais *« qui est le dernier à
pouvoir rendre la chose impossible ? »*

Et la réponse mène à une échelle, celle de la leçon 1.1 :

> Toute validation est l'aveu qu'un type manquait. Ce n'est pas un reproche :
> c'est une échelle. Chaque `if x < 0 { return err }` est un candidat à un
> type qui ne peut pas être négatif.

### Analyser, pas valider

D'où la règle qui structure tout le bon exemple :

> **Analyse une fois, à la frontière, et ne valide plus jamais.** Ce qui entre
> est une chaîne venue du monde ; ce qui en sort est une valeur dont la
> validité n'a plus à être vérifiée par personne.

La différence entre valider et analyser tient dans le type de retour :

```go
func ValidateStudentID(s string) error           // validate: returns a verdict
func ParseStudentID(s string) (StudentID, error) // parse: returns a value
```

Avec la première, la chaîne continue de circuler, et chaque fonction qui la
reçoit doit se demander si quelqu'un l'a vérifiée. Avec la seconde,
l'information « c'est valide » est portée par le **type**, donc par le
compilateur, donc une fois pour toutes.

### Ce qui reste vrai en cas d'échec

C'est la partie la plus utile et la plus rare. Une erreur qui ne dit pas dans
quel état se trouve le système est inexploitable : l'appelant ne peut ni
réessayer ni abandonner en connaissance de cause.

Trois garanties possibles, et il faut en choisir une :

| Garantie | Ce qu'elle permet |
|---|---|
| **atomique** — rien n'a été fait | réessayer sans risque |
| **partielle, et nommée** — voilà ce qui a été fait | reprendre où ça s'est arrêté |
| **indéterminée** | rien. Il faut aller regarder à la main |

La deuxième est parfaitement acceptable **à condition d'être écrite**. C'est
son absence qui est fautive, pas la partialité elle-même.

Et un corollaire sur le réessai :

> La réessayabilité n'est pas une propriété de l'erreur. C'est une propriété du
> couple **(erreur, état)**. « Conflit » est réessayable si rien n'a changé, et
> ne l'est pas sinon.

## 4. Le bon exemple

Un service d'inscription scolaire, et l'import du fichier de rentrée.

### Des types qui ne peuvent pas être invalides

```go
// Package school holds the school vocabulary as types that
// cannot be invalid.
//
// Reason to change: what a student ID, a level, a school year are.
//
// There is no Validate function in this package, and that is the point: we
// parse only once, at the entrance, and what comes out is a value whose
// validity nobody has to check any more.
package school

import (
    "errors"
    "fmt"
    "regexp"
    "strings"
)

var (
    ErrStudentIDFormat = errors.New("school: invalid student ID format")
    ErrUnknownLevel    = errors.New("school: unknown level")
    ErrInvalidYear     = errors.New("school: invalid school year")
)

// StudentID is a student identifier.
//
// Its field is unexported: outside this package, the only way to get
// one is ParseStudentID. So there is not, in the whole program, a
// malformed StudentID: it is a ⚫ and not a convention.
type StudentID struct{ s string }

var formeMatricule = regexp.MustCompile(`^[A-Z]{2}[0-9]{6}$`)

// ParseStudentID is the boundary. It parses a string from the outside
// world and returns a value, or an error, never both.
func ParseStudentID(s string) (StudentID, error) {
    s = strings.ToUpper(strings.TrimSpace(s))
    if !formeMatricule.MatchString(s) {
        return StudentID{}, fmt.Errorf("%w: %q", ErrStudentIDFormat, s)
    }
    return StudentID{s: s}, nil
}

func (m StudentID) String() string { return m.s }
func (m StudentID) IsEmpty() bool  { return m.s == "" }

// MarshalText and UnmarshalText close the back door of lesson 1.4: the
// deserialization goes through the SAME parser as the rest of the world. Without
// them, json.Unmarshal would make empty StudentID values without error.
func (m StudentID) MarshalText() ([]byte, error) { return []byte(m.s), nil }

func (m *StudentID) UnmarshalText(b []byte) error {
    p, err := ParseStudentID(string(b))
    if err != nil {
        return err
    }
    *m = p
    return nil
}

// Level is a closed enumeration.
type Level uint8

const (
    Sixth Level = iota + 1
    Seventh
    Eighth
    Ninth
)

var levelNames = map[Level]string{
    Sixth:   "6th",
    Seventh: "7th",
    Eighth:  "8th",
    Ninth:   "9th",
}

func (n Level) String() string {
    if s, ok := levelNames[n]; ok {
        return s
    }
    return fmt.Sprintf("level(%d)", uint8(n))
}

// Valid says whether the value belongs to the enumeration. It exists because
// a Level is a uint8: Level(42) can be represented, and it is the price
// of choosing a numeric type rather than a struct.
func (n Level) Valid() bool {
    _, ok := levelNames[n]
    return ok
}

func ParseLevel(s string) (Level, error) {
    s = strings.ToLower(strings.TrimSpace(s))
    for n, name := range levelNames {
        if s == name {
            return n, nil
        }
    }
    return 0, fmt.Errorf("%w: %q", ErrUnknownLevel, s)
}

// MustLevel is for literal values, known when writing the code: a
// test constant, a compiled table. It panics, and that is its role.
//
// A wrong literal is a programming bug, not a run-time error:
// there is nothing clever to do with a bug, and passing it up in the
// form of an error would force every caller to handle a case that cannot
// happen in production.
//
// Never call it on data that came from outside.
func MustLevel(s string) Level {
    n, err := ParseLevel(s)
    if err != nil {
        panic(err)
    }
    return n
}

// Year is a school year: 2026 means 2026-2027.
type Year struct{ start int }

func ParseYear(start int) (Year, error) {
    if start < 2000 || start > 2100 {
        return Year{}, fmt.Errorf("%w: %d", ErrInvalidYear, start)
    }
    return Year{start: start}, nil
}

func (a Year) String() string { return fmt.Sprintf("%d-%d", a.start, a.start+1) }
func (a Year) Start() int     { return a.start }
```

Trois choses à relever.

**Le champ de `StudentID` est non exporté.** Hors de ce paquet, la seule façon
d'en obtenir une est `ParseStudentID`. Il n'existe donc, dans tout le
programme, **aucune** `StudentID` mal formée. C'est un ⚫, pas une convention —
et c'est ce qui permet à toutes les fonctions en aval de ne rien vérifier.

**`UnmarshalText` ferme la porte dérobée de la leçon 1.4.**

```go
func (m *StudentID) UnmarshalText(b []byte) error {
    p, err := ParseStudentID(string(b))
    ...
}
```

La leçon 1.4 nommait le problème : *toute frontière de sérialisation est une
porte dérobée vers les invariants d'un type*. Voilà comment on la ferme — en
faisant passer la désérialisation par le **même analyseur** que le reste du
monde. Sans ces huit lignes, `json.Unmarshal` fabriquerait des `StudentID`
vides sans une seule erreur.

**Et l'honnêteté sur `Level` :**

```go
// Valid says whether the value belongs to the enumeration. It exists because
// a Level is a uint8: Level(42) can be represented, and it is the price
// of choosing a numeric type rather than a struct.
```

Un type numérique est pratique — comparable, utilisable en clé de `map`,
sérialisable — et il laisse `Level(42)` représentable. C'est un compromis,
assumé et écrit. Une `struct{n uint8}` l'aurait fermé au prix de l'ergonomie.

### L'opération, et le tableau de ses issues

```go
// Package enrollment enrolls a student at a level for a year.
//
// Reason to change: the admission rules.
package enrollment

import (
    "context"
    "errors"
    "fmt"

    "example/school/school"
)

// ID is the idempotency key, provided by the caller: only the sender of
// the intent knows whether two identical requests are a replay or two
// enrollments.
type ID string

// Request is built from already parsed types. So it cannot
// hold a malformed student ID nor a missing level, and that is
// why Enroll holds no format check.
type Request struct {
    ID        ID
    StudentID school.StudentID
    Level     school.Level
    Year      school.Year
}

type Receipt struct {
    ID        ID
    StudentID school.StudentID
    Level     school.Level
    Year      school.Year
    Rank      int
    // Replay is true if this call had no effect: the enrollment
    // already existed under this ID.
    Replay bool
}

// The outcomes of the operation. There are six, and there are six because there are
// six different conducts for the caller, not one more.
//
//    outcome                | kind            | caller's conduct     | state after
//    -----------------------|-----------------|----------------------|-------------
//    success                | —               | go on                | written
//    Receipt.Replay == true | —               | go on, redo nothing  | unchanged
//    ErrIdentityReused      | caller at fault | fix the calling code | unchanged
//    ErrAlreadyEnrolled     | business answer | tell the user        | unchanged
//    ErrLevelClosed         | business answer | offer something else | unchanged
//    ErrNoSeatLeft          | business answer | waiting list         | unchanged
//    ErrUnavailable         | environment     | retry with backoff   | UNDETERMINED
//
// The last column is the one nobody writes, and it is the most useful:
// an error that does not say what stays true cannot be used.
var (
    ErrNoIdentity      = errors.New("enrollment: request without identity")
    ErrIdentityReused  = errors.New("enrollment: identity already used for another request")
    ErrAlreadyEnrolled = errors.New("enrollment: this student is already enrolled for this year")
    ErrLevelClosed     = errors.New("enrollment: enrollments for this level are closed")
    ErrNoSeatLeft      = errors.New("enrollment: no seat left at this level")
    ErrUnavailable     = errors.New("enrollment: service unavailable")
)

// Registry is the persistence contract, declared here.
//
// Its implementations may return any error: an interface
// cannot forbid it. So the service translates: see Enroll.
type Registry interface {
    // Save writes the enrollment and counts the seat, atomically.
    // If the ID already exists, it returns the existing receipt without
    // write.
    Save(ctx context.Context, d Request) (Receipt, error)
}

// Capacities says whether a level is open.
type Capacities interface {
    Open(ctx context.Context, n school.Level, a school.Year) (bool, error)
    Remaining(ctx context.Context, n school.Level, a school.Year) (int, error)
}

type Service struct {
    Registry   Registry
    Capacities Capacities
}

// Enroll handles a request.
//
// Every error returned matches one of the sentinels of this package.
// No driver, database or network error crosses: see
// unavailable().
func (s *Service) Enroll(ctx context.Context, d Request) (Receipt, error) {
    if d.ID == "" {
        return Receipt{}, ErrNoIdentity
    }

    open, err := s.Capacities.Open(ctx, d.Level, d.Year)
    if err != nil {
        return Receipt{}, unavailable("opening", err)
    }
    if !open {
        return Receipt{}, fmt.Errorf("%w: %s", ErrLevelClosed, d.Level)
    }

    remaining, err := s.Capacities.Remaining(ctx, d.Level, d.Year)
    if err != nil {
        return Receipt{}, unavailable("seats left", err)
    }
    if remaining <= 0 {
        // The error carries the data the caller needs to act: here,
        // that the level is full. If it had to read a message back to
        // learn it, it would not be a contract.
        return Receipt{}, fmt.Errorf("%w: %s", ErrNoSeatLeft, d.Level)
    }

    rcpt, err := s.Registry.Save(ctx, d)
    if err != nil {
        // The registry's business errors come up as they are; everything
        // rest becomes ErrUnavailable.
        switch {
        case errors.Is(err, ErrAlreadyEnrolled), errors.Is(err, ErrIdentityReused):
            return Receipt{}, err
        default:
            return Receipt{}, unavailable("saving", err)
        }
    }
    return rcpt, nil
}

// unavailable translates an environment failure.
//
// The detail that matters is the choice of format verbs: %w on OUR
// sentinel, %v on the error received. The driver's message is kept for
// diagnosis; its IDENTITY does not become public, so no caller
// can test it, so we keep the right to change drivers.
func unavailable(step string, cause error) error {
    return fmt.Errorf("%w: %s: %v", ErrUnavailable, step, cause)
}

// Retryable says whether an error deserves another attempt.
//
// It is a function and not a property of the error, because the answer
// depends on the error AND on what the caller knows of the state. It lives here so
// the caller does not have to rebuild the list.
func Retryable(err error) bool {
    return errors.Is(err, ErrUnavailable)
}
```

Le commentaire qui porte le contrat :

```
issue                 | nature          | conduite de l'appelant      | etat apres
----------------------|-----------------|-----------------------------|------------
succes                | —               | continuer                   | ecrit
Receipt.Replay == true    | —               | continuer, sans rien refaire| inchange
ErrIdentityReused | appelant fautif | corriger le code appelant   | inchange
ErrAlreadyEnrolled        | reponse metier  | le dire a l'utilisateur     | inchange
ErrLevelClosed        | reponse metier  | proposer autre chose        | inchange
ErrNoSeatLeft  | reponse metier  | liste d'attente             | inchange
ErrUnavailable       | environnement   | reessayer avec recul        | INDETERMINE
```

Six sentinelles, et **six parce qu'il y a six conduites** — c'est le test
décisif de la section 1, appliqué. La troisième colonne justifie l'existence
de chaque ligne ; la quatrième est celle que personne n'écrit.

Et regarde ce que la fonction `Enroll` **ne contient pas** : aucune
vérification de format. Pas de `if len(studentID) != 8`, pas de liste de
niveaux valides. Parce que `Request` est construite à partir de types déjà
analysés, et qu'elle ne peut donc pas être invalide.

> Le signe d'une bonne frontière d'analyse, c'est le code de validation qui a
> **disparu** du cœur du système. S'il y est encore, c'est que les types
> transportent toujours des chaînes.

### La traduction d'erreur, et les deux verbes de formatage

Voici le détail le plus précis de cette leçon :

```go
func unavailable(step string, cause error) error {
    return fmt.Errorf("%w: %s: %v", ErrUnavailable, step, cause)
}
```

`%w` sur **notre** sentinelle. `%v` sur l'erreur reçue.

Conséquences, et elles sont exactement celles qu'on veut :

- `errors.Is(err, ErrUnavailable)` est **vrai** : l'appelant peut agir ;
- `errors.Is(err, errDuPilote)` est **faux** : l'identité du pilote n'est pas
  devenue publique, donc personne ne peut la tester, donc on garde le droit de
  changer de base ;
- et le **message** du pilote est conservé dans le texte, donc le diagnostic
  reste possible.

> `%w` est un **engagement**. Ce que tu enveloppes avec `%w` devient testable
> par tes appelants, donc public, donc définitif. Enveloppe avec `%w` ce que tu
> promets ; enveloppe avec `%v` ce que tu veux seulement pouvoir lire.

Le choix entre `%w` et `%v` n'est pas une question de style. C'est une
décision de contrat, prise caractère par caractère.

### Le test qui vérifie les deux moitiés

```go
// THE test of this lesson.
// It checks both halves of an error translation: the identity of the
// driver does not cross, and its message is kept for diagnosis.
// Almost nobody writes the second assertion, and it is the one that stops us from
// "translate" by throwing information away.
func TestDriverIdentityDoesNotCrossButItsMessageDoes(t *testing.T) {
    s := &enrollment.Service{
        Registry:   &registry{err: errDriver},
        Capacities: capacities{open: true, remaining: 10},
    }

    _, err := s.Enroll(context.Background(), req(t, "i-1"))
    if err == nil {
        t.Fatal("an error was expected")
    }

    if !errors.Is(err, enrollment.ErrUnavailable) {
        t.Errorf("errors.Is(err, ErrUnavailable) = false, err = %v", err)
    }
    if errors.Is(err, errDriver) {
        t.Error("the driver's identity crossed the boundary: a caller could test it")
    }
    if !strings.Contains(err.Error(), "SQLSTATE 08006") {
        t.Errorf("the driver's message was lost, no diagnosis possible: %v", err)
    }
    if !enrollment.Retryable(err) {
        t.Error("an environment failure must be retryable")
    }
}

```

La troisième assertion est celle que presque personne n'écrit :

```go
if !strings.Contains(err.Error(), "SQLSTATE 08006") {
    t.Errorf("the driver's message was lost, no diagnosis possible: %v", err)
}
```

Sans elle, on peut « traduire » une erreur en **jetant** l'information —
`return ErrUnavailable` tout court. Le contrat est respecté, et l'astreinte se
retrouve à trois heures du matin avec un message qui dit « service
indisponible » et rien d'autre.

> Traduire une erreur n'est pas la remplacer. On change son **identité** pour
> l'appelant ; on garde son **texte** pour celui qui diagnostique.

Note aussi ce que les tests ne font pas : aucun ne compare un message complet.
Ils testent des sentinelles. Changer un libellé ne doit casser aucun test —
c'est la définition opérationnelle de « le message n'est pas un contrat ».

### Le lot : erreur de ligne contre erreur de lot

```go
// Package batch imports a file of enrollments.
//
// Reason to change: the file format and the interruption policy.
//
// Its contract rests on a single distinction, and it is the most useful of
// this lesson:
//
//    a LINE error is data in the report.
//    a BATCH error is an error.
//
// Mixing them up gives either an import that stops at the first faulty
// line, or an import we do not know what it did.
package batch

import (
    "context"
    "encoding/csv"
    "errors"
    "fmt"
    "io"
    "strconv"

    "example/school/enrollment"
    "example/school/school"
)

var (
    ErrBadHeader = errors.New("batch: invalid file header")
    ErrRead      = errors.New("batch: file reading interrupted")
)

// Rejection is a refused line. Cause is a domain error, not a
// string: whoever reads the report can group, count and filter
// with errors.Is, without parsing text.
type Rejection struct {
    Line  int
    Field string
    Value string
    Cause error
}

func (r Rejection) String() string {
    return fmt.Sprintf("line %d, field %s = %q: %v", r.Line, r.Field, r.Value, r.Cause)
}

// Report says what happened. It is returned EVEN on a batch error:
// it is what answers "what stays true".
type Report struct {
    Read        int
    Accepted    int
    Rejections  []Rejection
    Interrupted bool
}

// Importer writes through the enrollment service: it does not know the database.
type Importer struct {
    Enrollments interface {
        Enroll(ctx context.Context, d enrollment.Request) (enrollment.Receipt, error)
    }
    Year school.Year
}

// Import reads a CSV "student_id;level" and enrolls each line.
//
// GUARANTEED
//
//   - The report is always returned, even with a batch error. Read,
//     Accepted and Rejections describe exactly what was done.
//   - A refused line stops nothing and appears in Rejections.
//   - Each line is enrolled with a deterministic identity, derived from the
//     line number: replaying the same file creates no duplicate.
//
// NOT GUARANTEED
//
//   - The order of Rejections follows the file's order, but nothing says there is
//     than one rejection per line.
//   - Atomicity of the batch. There is no enclosing transaction: an
//     interrupted batch leaves the lines already accepted in place. It is a choice,
//     and Report.Interrupted is how to know it.
func (i *Importer) Import(ctx context.Context, src io.Reader, fileName string) (Report, error) {
    var r Report

    reader := csv.NewReader(src)
    reader.Comma = ';'
    reader.FieldsPerRecord = 2

    if _, err := reader.Read(); err != nil {
        // No readable header: it is a BATCH error. Nothing was tried.
        return r, fmt.Errorf("%w: %v", ErrBadHeader, err)
    }

    for line := 2; ; line++ {
        if err := ctx.Err(); err != nil {
            r.Interrupted = true
            return r, err
        }

        fields, err := reader.Read()
        if errors.Is(err, io.EOF) {
            return r, nil
        }
        if err != nil {
            // A line malformed in the CSV sense (unclosed quote, wrong number
            // of fields) does not stop us: it is a rejection.
            r.Read++
            r.Rejections = append(r.Rejections, Rejection{Line: line, Field: "line", Cause: err})
            continue
        }

        r.Read++
        if rejection, ok := i.line(ctx, line, fileName, fields); !ok {
            r.Rejections = append(r.Rejections, rejection)
            // An unavailability is not a line problem: insisting
            // on the next 5,000 lines would amplify the outage.
            if enrollment.Retryable(rejection.Cause) {
                r.Interrupted = true
                return r, fmt.Errorf("%w: line %d: %w", ErrRead, line, rejection.Cause)
            }
            continue
        }
        r.Accepted++
    }
}

func (i *Importer) line(ctx context.Context, number int, fileName string, fields []string) (Rejection, bool) {
    m, err := school.ParseStudentID(fields[0])
    if err != nil {
        return Rejection{Line: number, Field: "student_id", Value: fields[0], Cause: err}, false
    }
    n, err := school.ParseLevel(fields[1])
    if err != nil {
        return Rejection{Line: number, Field: "level", Value: fields[1], Cause: err}, false
    }

    // Deterministic identity: the file and the line number. Replaying the
    // same file after an interruption creates no duplicate.
    id := enrollment.ID(fileName + "#" + strconv.Itoa(number))

    if _, err := i.Enrollments.Enroll(ctx, enrollment.Request{
        ID: id, StudentID: m, Level: n, Year: i.Year,
    }); err != nil {
        return Rejection{Line: number, Field: "enrollment", Value: m.String(), Cause: err}, false
    }
    return Rejection{}, true
}
```

Toute la conception tient dans deux lignes du commentaire de paquet :

```
une erreur de LIGNE est une donnee du rapport.
une erreur de LOT   est une erreur.
```

Donc `Rejection` n'est pas une erreur rendue : c'est une **valeur** dans le
rapport, avec son numéro de ligne, son champ, sa valeur fautive, et sa raison
— qui est elle-même une erreur du domaine, pas une chaîne. Celui qui lit le
rapport peut donc compter, grouper et filtrer avec `errors.Is`.

Et `Report` est rendu **même en cas d'erreur de lot** :

```go
return r, fmt.Errorf("%w: line %d: %w", ErrRead, line, rejection.Cause)
```

C'est la troisième partie du contrat, celle de la section 3 : l'erreur dit ce
qui a échoué, et le rapport dit ce qui reste vrai. `Interrupted`, `Accepted` et
`Rejections` permettent de reprendre.

Deux décisions de plus, qui viennent des leçons précédentes :

**L'identité est déterministe**, dérivée du nom de fichier et du numéro de
ligne. Rejouer le même fichier après une interruption ne crée aucun doublon —
la correction 1.1 / 5, appliquée à un import.

**Une indisponibilité interrompt le lot** au lieu d'être comptée comme un
rejet de ligne :

```go
// An unavailability is not a line problem: insisting
// on the next 5,000 lines would amplify the outage.
```

C'est la règle de la correction 1.4 / 5 : ne pas ajouter de charge quand une
dépendance est en train de tomber. La classification des erreurs n'est pas un
exercice de rangement — elle décide ici du comportement du système sous panne.

### La table de correspondance, et le niveau de journalisation

```go
// Package api translates domain outcomes into HTTP responses.
//
// Reason to change: the HTTP contract and the texts the user sees.
//
// It is here, and nowhere else, that status codes and
// French sentences live. The domain knows neither HTTP nor the language of whoever
// reads.
package api

import (
    "errors"
    "log/slog"
    "net/http"

    "example/school/enrollment"
    "example/school/school"
)

// status is the program's only mapping table.
//
// The default case is the most important: 500 means "we do not
// know". So, for an error coming from the domain, it admits it has not
// classified: in other words a flaw of this table, not of the caller.
func status(err error) int {
    switch {
    case err == nil:
        return http.StatusOK

    // Caller errors: the request is faulty, retrying it as is
    // will not help.
    case errors.Is(err, school.ErrStudentIDFormat),
        errors.Is(err, school.ErrUnknownLevel),
        errors.Is(err, school.ErrInvalidYear),
        errors.Is(err, enrollment.ErrNoIdentity):
        return http.StatusBadRequest
    case errors.Is(err, enrollment.ErrIdentityReused):
        return http.StatusConflict

    // Business answers: the request is correct, the answer is "no".
    case errors.Is(err, enrollment.ErrAlreadyEnrolled):
        return http.StatusConflict
    case errors.Is(err, enrollment.ErrLevelClosed),
        errors.Is(err, enrollment.ErrNoSeatLeft):
        return http.StatusUnprocessableEntity

    // Environment failure: the only category that should count
    // against the announced availability.
    case errors.Is(err, enrollment.ErrUnavailable):
        return http.StatusServiceUnavailable
    }
    return http.StatusInternalServerError
}

// message is the text for the human. It is here because the language,
// the tone and the level of detail are presentation decisions.
//
// It never reuses err.Error(): a technical error message holds
// table names, values and sometimes secrets.
func message(err error) string {
    switch {
    case errors.Is(err, school.ErrStudentIDFormat):
        return "Le matricule doit comporter deux lettres suivies de six chiffres."
    case errors.Is(err, school.ErrUnknownLevel):
        return "Niveau inconnu. Valeurs acceptees : 6e, 5e, 4e, 3e."
    case errors.Is(err, school.ErrInvalidYear):
        return "Annee scolaire invalide."
    case errors.Is(err, enrollment.ErrNoIdentity):
        return "Requete incomplete : identifiant de demande manquant."
    case errors.Is(err, enrollment.ErrIdentityReused):
        return "Cet identifiant de demande a deja servi pour une autre inscription."
    case errors.Is(err, enrollment.ErrAlreadyEnrolled):
        return "Cet eleve est deja inscrit pour cette annee."
    case errors.Is(err, enrollment.ErrLevelClosed):
        return "Les inscriptions a ce niveau sont closes."
    case errors.Is(err, enrollment.ErrNoSeatLeft):
        return "Ce niveau est complet. Vous pouvez demander la liste d'attente."
    case errors.Is(err, enrollment.ErrUnavailable):
        return "Service momentanement indisponible. Reessayez dans quelques instants."
    }
    return "Une erreur inattendue est survenue."
}

// logLevel is a contract with the on-call: ERROR means "someone
// must get up". A business answer logged at ERROR destroys this
// contract, and after three weeks nobody looks any more.
func logLevel(err error) slog.Level {
    switch s := status(err); {
    case s < 400:
        return slog.LevelDebug
    case s < 500:
        return slog.LevelInfo
    case s == http.StatusServiceUnavailable:
        return slog.LevelWarn
    default:
        // 500: unclassified. It is a flaw in the mapping table,
        // and it is the only case worth waking someone.
        return slog.LevelError
    }
}
```

C'est ici, et nulle part ailleurs, que vivent les codes HTTP et les phrases en
français. Le domaine ne connaît ni l'un ni l'autre.

Trois décisions.

**Les trois catégories sont séparées** : 400 et 409 pour les fautes de
l'appelant, 422 pour les réponses métier, 503 pour les défaillances
d'environnement. La section 6 dit pourquoi ça compte.

**Le `default: 500` est un détecteur de trou.**

```go
// The default case is the most important: 500 means "we do not
// know". So, for an error coming from the domain, it admits it has not
// classified: in other words a flaw of this table, not of the caller.
```

**Le message utilisateur ne reprend jamais `err.Error()`.** Un message
technique contient des noms de table, des valeurs, parfois un fragment de
requête, parfois un secret. Et surtout, le domaine ne connaît pas la langue de
celui qui lira.

> Le domaine ne sait pas qui le lit. Une erreur qui contient une phrase
> destinée à un humain a franchi une frontière de trop.

### Le test de la table

```go
// Every outcome declared by the domain must be classified. A 500
// is a hole in the table, not a caller error.
func TestEveryOutcomeIsClassified(t *testing.T) {
    outcomes := []error{
        school.ErrStudentIDFormat,
        school.ErrUnknownLevel,
        school.ErrInvalidYear,
        enrollment.ErrNoIdentity,
        enrollment.ErrIdentityReused,
        enrollment.ErrAlreadyEnrolled,
        enrollment.ErrLevelClosed,
        enrollment.ErrNoSeatLeft,
        enrollment.ErrUnavailable,
    }

    for _, err := range outcomes {
        if s := status(err); s == http.StatusInternalServerError {
            t.Errorf("%v is classified 500: the mapping table has a hole", err)
        }
        if m := message(err); m == "Une erreur inattendue est survenue." {
            t.Errorf("%v has no user message", err)
        }
        if n := logLevel(err); n == slog.LevelError {
            t.Errorf("%v logged at ERROR: it would wake someone for nothing", err)
        }
    }
}
```

Ce test a trouvé trois trous au moment où je l'ai écrit : trois issues du
domaine n'avaient pas de message utilisateur. C'est sa raison d'être — une
table de correspondance est un endroit qu'on oublie de compléter quand on
ajoute une erreur.

> Chaque fois que tu ajoutes une sentinelle au domaine, il existe au moins une
> table ailleurs qui devient incomplète. Un test qui énumère les issues est le
> seul moyen de le savoir le jour même.

## 5. Le mauvais exemple, et pourquoi il fait mal

```go
// Package before is the counter-example of lesson 1.5.
//
// It compiles, it works, and it is in production in many
// places. All its errors are strings, and its
// caller parses them with strings.Contains.
package before

import (
    "database/sql"
    "errors"
    "fmt"
    "log/slog"
    "net/http"
    "strings"
)

var DB *sql.DB

// Enroll returns an error for everything: invalid argument, student not found,
// duplicate, network outage. One value, one possible conduct for
// the caller.
func Enroll(studentID, level string, year int) error {
    // A caller error handled by panic: the library decides
    // to stop its client's program.
    if len(studentID) != 8 {
        panic("invalid student ID: " + studentID)
    }

    var open bool
    err := DB.QueryRow(
        "SELECT open FROM levels WHERE code = $1 AND year = $2", level, year,
    ).Scan(&open)
    if err == sql.ErrNoRows {
        // The HTTP code in the message: the caller will have to parse it back.
        return errors.New("level not found (404)")
    }
    if err != nil {
        // The driver's error crosses as is. The caller who wants to
        // tell an outage from a duplicate will have to read PostgreSQL text.
        return err
    }
    if !open {
        // A message for a human, in French, decided by the domain.
        return errors.New("Les inscriptions a ce niveau sont closes.")
    }

    _, err = DB.Exec(
        "INSERT INTO enrollments (student_id, level, year) VALUES ($1, $2, $3)",
        studentID, level, year,
    )
    if err != nil {
        // Classifying an error by parsing its message. It works
        // until the next version of the driver, or of PostgreSQL, or the
        // day the server is set up in another language.
        if strings.Contains(err.Error(), "duplicate key") {
            return errors.New("already enrolled")
        }
        if strings.Contains(err.Error(), "violates foreign key") {
            return errors.New("unknown student")
        }
        return fmt.Errorf("enrollment failed: %w", err)
    }
    return nil
}

// ImportBatch stops at the first faulty line, and does not say what it had
// done before.
func ImportBatch(lines [][]string, year int) error {
    for _, l := range lines {
        if err := Enroll(l[0], l[1], year); err != nil {
            return err
        }
    }
    return nil
}

// Handler is the caller. It is the one that pays.
func Handler(w http.ResponseWriter, r *http.Request, log *slog.Logger) {
    err := Enroll(r.FormValue("student_id"), r.FormValue("level"), 2026)
    if err == nil {
        w.WriteHeader(http.StatusCreated)
        return
    }

    // A decision tree built on substrings. Each line is
    // a coupling to the wording of an error, that is to something
    // nobody considers a public interface.
    switch {
    case strings.Contains(err.Error(), "(404)"):
        w.WriteHeader(http.StatusNotFound)
    case err.Error() == "already enrolled":
        w.WriteHeader(http.StatusConflict)
    case strings.Contains(err.Error(), "closed"):
        w.WriteHeader(http.StatusBadRequest)
    default:
        // Everything else, including "unknown student", which is an error of
        // the caller, becomes a 500 and wakes the on-call.
        log.Error("enrollment", "err", err)
        w.WriteHeader(http.StatusInternalServerError)
    }

    // And the technical message goes to the user, with the names of the
    // tables.
    fmt.Fprintln(w, err.Error())
}
```

### Le relevé

| Défaut | Conséquence |
|---|---|
| `panic` sur un argument invalide | une bibliothèque décide d'arrêter le programme de son client |
| `errors.New("level introuvable (404)")` | le code HTTP est dans le message, l'appelant doit le relire |
| `return err` du pilote | `sql.ErrNoRows` et les erreurs PostgreSQL deviennent publiques |
| `errors.New("Les enrollments... closed.")` | une phrase en français, décidée par le domaine |
| `strings.Contains(err.Error(), "duplicate key")` | la classification repose sur un texte que personne ne considère comme une interface |
| `ImportBatch` s'arrête au premier échec | et ne dit pas ce qu'il a fait avant |
| le `switch` du `Handler` sur des sous-chaînes | chaque ligne est un couplage à un libellé |
| `fmt.Fprintln(w, err.Error())` | le nom des tables part chez l'utilisateur |
| `default: 500` qui attrape « élève inconnu » | une faute de l'appelant réveille l'astreinte |

### Les trois qui méritent un développement

**`strings.Contains(err.Error(), "duplicate key")`.** Tout le monde l'a écrit
une fois. Ça marche, et ça cesse de marcher le jour d'une mise à jour du
pilote, d'une version majeure de PostgreSQL, ou — le meilleur — quand le
serveur est configuré avec `lc_messages` dans une autre langue. Le test passe,
la production classe les doublons comme des pannes, et le symptôme est une
hausse du taux de 500 sans aucun déploiement.

> Un message d'erreur n'est pas un contrat. C'est la seule partie d'une erreur
> dont on a le droit de changer sans prévenir, donc c'est la seule sur laquelle
> il ne faut jamais s'appuyer.

**`panic` sur un matricule invalide.** Un matricule mal formé est une faute de
l'appelant — nature 2 de la section 1. La conduite correcte est de la lui
rendre pour qu'il corrige **son** code. Au lieu de ça, cette bibliothèque
arrête le processus de son client. Un `panic` qui traverse une frontière d'API
n'est pas une erreur de programmation : c'est une **décision** prise à la place
de quelqu'un d'autre.

**Le `default: 500` qui attrape « élève inconnu ».** Le `Handler` classe trois
cas et jette le reste en 500. Donc une violation de clé étrangère — une faute
de l'appelant — devient une erreur serveur, journalisée en `ERROR`, comptée
contre la disponibilité. Le service fonctionne parfaitement, et son tableau de
bord dit qu'il tombe.

> Dans ce fichier, il n'y a pas de bug. Il y a une **absence de
> classification**, et toutes ses conséquences.

## 6. Le lien avec la production

### La taxonomie des erreurs détermine la mesure de disponibilité

C'est le point le plus concret de cette leçon, et il n'apparaît dans aucun
livre de conception.

Un SLO de disponibilité se calcule sur les **erreurs serveur**. Pas sur les
réponses métier, pas sur les fautes du client. Donc :

Imagine un service où 2 % des requêtes reçoivent légitimement « niveau
complet ». Si cette réponse part en 500 :

```
disponibilité mesurée = 98 %
disponibilité réelle  = 100 %
```

Un budget d'erreur de 99,9 % est consommé **vingt fois** par un service qui
fonctionne parfaitement. Conséquence pratique : l'alerte sonne, personne ne
trouve rien, et au bout de trois semaines l'équipe relève le seuil — ce qui
revient à désactiver la surveillance.

Et l'erreur symétrique est pire : classer ses propres défaillances en 4xx
**cache** les pannes réelles. Le tableau de bord reste vert pendant que la base
est injoignable.

> La classification des erreurs n'est pas une question de propreté : c'est la
> définition de ton indicateur de disponibilité. Une erreur mal classée ne
> rend pas le code moins beau, elle rend la mesure fausse — dans un sens ou
> dans l'autre.

### Le niveau de journalisation est un contrat avec l'astreinte

```go
// logLevel is a contract with the on-call: ERROR means "someone
// must get up".
```

`ERROR` sur un cas normal détruit ce contrat. Le mécanisme est connu et
irréversible : trois semaines de bruit, et plus personne ne lit les `ERROR`.

Le barème qui marche :

| Niveau | Signification |
|---|---|
| `DEBUG` | pour comprendre après coup |
| `INFO` | un fait notable, aucune action |
| `WARN` | une dégradation ; action si ça persiste |
| `ERROR` | **quelqu'un doit se lever** |

Et la conséquence sur la conception : `logLevel` est **dérivé** de
`status`, pas choisi à la main sur chaque site d'appel. Un développeur qui
écrit `log.Error` au cas par cas finira par en mettre partout.

### Le 500 par défaut est un détecteur

C'est l'usage le plus élégant d'une table de correspondance. Puisque `default`
signifie « non classé », et puisque non classé donne `ERROR` :

> Mets une alerte sur le taux de 500. Elle ne détecte pas les pannes — les 503
> les détectent. Elle détecte les **trous de ta classification**, c'est-à-dire
> les erreurs auxquelles personne n'a encore réfléchi.

### Et la classification décide du comportement sous panne

Le `batch` l'a montré : une indisponibilité interrompt l'import, un rejet de
ligne ne l'interrompt pas. Si les deux étaient le même `error`, il n'y aurait
que deux conceptions possibles, toutes deux mauvaises — s'arrêter à la première
ligne fautive, ou s'acharner cinq mille fois sur une base qui tombe.

> Sans classification, il n'y a pas de politique de réessai possible. Il n'y a
> que « toujours » ou « jamais », et les deux sont faux.

## 7. Ce qu'il faut retenir

1. Concevoir une opération, c'est énumérer ses issues et leur associer une
   conduite. Le reste est de la plomberie.
2. Quatre natures : réponse métier, faute de l'appelant, défaillance
   d'environnement, bug. Quatre conduites, donc quatre choses distinguables.
3. « Pas trouvé » n'est pas un échec : c'est une réponse.
4. Le nombre d'erreurs à exposer est le nombre de conduites distinctes de
   l'appelant. Pas une de plus.
5. Toute validation est l'aveu qu'un type manquait. Analyse une fois à la
   frontière, et ne valide plus jamais.
6. Un contrat a trois parties, et la troisième — *ce qui reste vrai en cas
   d'échec* — est celle que personne n'écrit.
7. La réessayabilité est une propriété du couple (erreur, état), pas de
   l'erreur.
8. `%w` est un engagement : ce qu'il enveloppe devient public et définitif.
   `%v` garde le texte sans promettre l'identité.
9. Traduire une erreur, c'est changer son identité en gardant son texte.
10. Une erreur de ligne est une donnée du rapport ; une erreur de lot est une
    erreur.
11. Un message d'erreur n'est pas un contrat — c'est la seule partie qu'on a
    le droit de changer sans prévenir.
12. La classification des erreurs définit la mesure de disponibilité. Mal
    classer rend l'indicateur faux, pas le code laid.

## 8. Approfondissement : la chaîne d'erreurs, et ce qu'elle promet

### `errors.Is`, `errors.As`, et ce qu'ils supposent

`errors.Is` remonte la chaîne construite par `%w` et compare par identité.
`errors.As` fait de même en cherchant un **type**, ce qui permet de porter des
données :

```go
type ErrQuota struct {
    Level    school.Level
    Request  int
    Remaining int
}

func (e ErrQuota) Error() string { ... }
func (e ErrQuota) Is(target error) bool { return target == ErrNoSeatLeft }
```

Quand utiliser quoi :

| | Sentinelle (`errors.Is`) | Type (`errors.As`) |
|---|---|---|
| l'appelant a besoin de | savoir **quoi faire** | savoir quoi faire **et avec quelles données** |
| coût | une variable | un type exporté, donc un contrat de plus |
| exemple | `ErrLevelClosed` | `ErrQuota{Remaining: 0}` pour afficher « 12 places restantes » |

La règle : commence par une sentinelle. Passe au type le jour où un appelant
doit lire une **donnée** de l'erreur pour agir — et pas pour l'afficher, car
afficher se fait avec `%w` et le texte.

### `errors.Join` et les erreurs multiples

On l'a utilisé aux leçons 1.2 et 1.3 pour accumuler. Sa subtilité :
`errors.Is` fonctionne sur **chacune** des erreurs jointes. Donc un
`errors.Join(ErrA, ErrB)` satisfait les deux, et un `switch` sur `errors.Is`
prendra la première branche — pas forcément celle qu'on veut.

> `errors.Join` convient pour **rendre compte** de plusieurs échecs. Il ne
> convient pas pour en faire **décider** un appelant : un appelant ne peut
> tenir qu'une conduite à la fois.

C'est pour ça que le `batch` ne joint pas les rejets de ligne : il les met dans
un rapport. Une liste de problèmes est une donnée ; une erreur est une
instruction.

### Quand ne pas envelopper du tout

Trois cas :

1. **Quand l'erreur est déjà la bonne**, et que ton enveloppe n'ajoute aucune
   information. `fmt.Errorf("echec : %w", err)` sans contexte ajoute du bruit
   dans la chaîne.
2. **Quand l'appelant ne doit pas voir la cause.** C'est le `%v` du bon
   exemple.
3. **Quand l'erreur contient une donnée sensible.** Une erreur de connexion
   contient parfois une chaîne de connexion complète, avec le mot de passe. Il
   faut alors la réduire délibérément, et le dire.

### La panique, et son seul usage légitime

`panic` est pour les **invariants internes violés**, c'est-à-dire pour tes
propres bugs :

```go
// MustLevel is for literal values, known when writing the code: a
// test constant, a compiled table. It panics, and that is its role.
//
// A wrong literal is a programming bug, not a run-time error:
// there is nothing clever to do with a bug, and passing it up in the
// form of an error would force every caller to handle a case that cannot
// happen in production.
//
// Never call it on data that came from outside.
func MustLevel(s string) Level {
    n, err := ParseLevel(s)
    if err != nil {
        panic(err)
    }
    return n
}
```

Jamais pour une faute de l'appelant — on la lui rend. Jamais pour une
défaillance d'environnement — on la classe.

Et dans un serveur, un `recover` par requête est légitime : il isole un *bug*
de l'une des requêtes du reste du service, ce qui est une cloison, pas un
camouflage. À deux conditions :

- **compter** les paniques récupérées, avec une alerte dès la première ;
- ne jamais les transformer en réponse métier. Une panique récupérée est un
  500, et c'est honnête : nous ne savons pas ce qui s'est passé.

## 9. Ce que les erreurs ne sont pas

**Une erreur n'est pas un échec.** Section 1.

**Une taxonomie n'est pas une conception.** Quarante codes et un seul
`if err != nil` chez l'appelant : zéro valeur ajoutée, et quarante choses à
maintenir.

**Une erreur n'est pas un journal.** N'y mets pas d'identifiant de trace, de
horodatage ni de niveau de gravité : ce sont des affaires du journal, et le
journal a accès au contexte. Une erreur porte ce dont l'appelant a besoin pour
**agir**.

**`return err` n'est pas une gestion d'erreur.** C'est un report, et c'est
souvent la bonne chose à faire — à condition que quelqu'un, plus haut, ait une
conduite.

> Une chaîne de dix `if err != nil { return err }` sans personne au bout n'est
> pas de la propagation : c'est une erreur qui arrive chez l'utilisateur sous
> forme de 500. Quelque part, quelqu'un doit **décider**.

**Un message n'est pas un contrat.** Section 5.

**Et l'absence d'exceptions n'est pas le sujet.** Go rend les erreurs
explicites, ce qui aide ; mais un langage à exceptions a exactement le même
problème de classification, avec la propagation en moins à écrire. Le mécanisme
de transport n'a jamais été la difficulté.

## 10. Le réflexe à installer

Avant d'écrire la signature d'une opération, écris son tableau. Quatre
colonnes, une ligne par issue :

> | issue | nature | conduite de l'appelant | ce qui reste vrai |

Puis trois vérifications :

- **deux lignes ont la même conduite ?** Fusionne-les. Une distinction sans
  conséquence est une dette.
- **une ligne n'a aucune conduite ?** Elle n'a rien à faire dans le contrat.
  Elle appartient au journal.
- **une case « ce qui reste vrai » est vide ?** Tu ne connais pas encore ton
  opération.

Et devant toute erreur que tu t'apprêtes à rendre :

> **Est-ce que j'enveloppe pour promettre, ou pour pouvoir lire ?** `%w` dans
> le premier cas, `%v` dans le second.
