# Correction — Exercice 1.5 / 3 (refactoring)

## L'énoncé

Un client de prestataire de paiement, trois ans, **dix-huit erreurs
exportées**, et le dépouillement d'un `grep` sur tout le dépôt : qui teste
quoi, et ce qu'il en fait.

La méthode est la même qu'à l'exercice 1.2 / 3 : on ne lit pas le code, on lit
la **preuve de l'usage**. Là-bas c'était l'historique git ; ici c'est le
`grep errors.Is`.

## Question 1 — Les sentinelles qui survivent

### Du dépouillement aux conduites

On ne compte pas les erreurs, on compte les **conduites distinctes** qui
apparaissent dans la colonne de droite du dépouillement :

| Conduite observée | Erreurs qui la déclenchent |
|---|---|
| réessayer 3 fois | `ErrTimeout`, `ErrConnexion` |
| attendre 60 s puis réessayer | `ErrQuota` |
| alerter l'astreinte, ne pas insister | `ErrAuth` |
| renouveler le jeton et rejouer | `ErrAuthExpiree` — mais c'est `clientpsp` lui-même |
| message à l'utilisateur | `ErrCompteInconnu`, `ErrSoldeInsuffisant`, `ErrPlafondAtteint` |
| considérer l'opération acquise | `ErrReferenceDupliquee` |

Six conduites, dont une interne. Et onze erreurs qui n'en déclenchent
**aucune**.

### Le résultat : sept sentinelles

```go
// Package clientpsp est le client du prestataire de paiement, apres
// reduction : dix-huit sentinelles ramenees a sept.
//
// Raison de changer : les conduites que ce client permet a ses appelants.
//
// Le critere de la reduction n'est pas esthetique. Chaque sentinelle survit
// parce qu'un appelant reel fait quelque chose de DIFFERENT avec elle. Les
// douze autres ne disparaissent pas : leur information part dans Detail, qui
// sert au diagnostic et non a la decision.
package clientpsp

import (
    "errors"
    "fmt"
)

// Les sept conduites, et rien d'autre.
//
//    sentinelle           | conduite de l'appelant                  | reessayable
//    ---------------------|-----------------------------------------|------------
//    ErrIndisponible      | reessayer avec recul                    | oui
//    ErrQuota             | attendre le delai indique puis reessayer| oui, apres
//    ErrIssueIncertaine   | NE PAS reessayer, reconcilier           | non
//    ErrRefus             | le dire a l'utilisateur                 | non
//    ErrDejaFait          | considerer l'operation acquise          | non
//    ErrConfiguration     | alerter l'astreinte, ne pas insister    | non
//    ErrNonClasse         | alerter, et completer cette table       | non
//
// ErrIndisponible et ErrIssueIncertaine sont separees alors que l'historique
// des appelants leur donnait la meme conduite : voir la correction, question
// 2. Une connexion refusee signifie que la requete n'est jamais partie ; un
// delai depasse signifie qu'elle est peut-etre arrivee. Ce ne sont pas deux
// facons de dire la meme chose.
var (
    ErrIndisponible    = errors.New("psp : prestataire indisponible")
    ErrQuota           = errors.New("psp : quota d'appels depasse")
    ErrIssueIncertaine = errors.New("psp : issue indeterminee, reconciliation requise")
    ErrRefus           = errors.New("psp : operation refusee")
    ErrDejaFait        = errors.New("psp : reference deja traitee")
    ErrConfiguration   = errors.New("psp : configuration ou autorisation invalide")
    ErrNonClasse       = errors.New("psp : reponse non classee")
)

// errAuthExpiree n'est PAS exportee.
//
// Le depouillement montre qu'elle n'est testee que par ce paquet lui-meme :
// c'est un detail de son fonctionnement interne — il renouvelle son jeton et
// rejoue. Un symbole exporte que seul son paquet utilise est un contrat que
// personne n'a demande et qu'on ne peut plus retirer.
var errAuthExpiree = errors.New("psp : jeton expire")

// Code est le code d'origine du prestataire. Il ne sert PAS a decider : il
// sert a diagnostiquer, a compter et a regrouper dans un tableau de bord.
//
// C'est la ou vont les douze sentinelles supprimees. L'information est
// conservee ; ce qui est supprime, c'est l'illusion qu'un appelant doit en
// tenir compte.
type Code string

// Detail est l'erreur typee du client.
//
// Is la fait correspondre a l'une des sept sentinelles : la conduite se teste
// avec errors.Is, le code d'origine se lit avec errors.As.
type Detail struct {
    Conduite error // l'une des sept sentinelles
    Code     Code  // le code du prestataire, tel quel
    Statut   int   // le statut HTTP, tel quel
    Message  string
}

func (d Detail) Error() string {
    return fmt.Sprintf("%v (code %q, statut %d) : %s", d.Conduite, d.Code, d.Statut, d.Message)
}

func (d Detail) Is(cible error) bool { return cible == d.Conduite }
func (d Detail) Unwrap() error       { return d.Conduite }

// Reessayable est la seule question que la plupart des appelants posent.
//
// ErrIssueIncertaine n'y figure pas, et c'est le point de la reduction : une
// defaillance dont on ne sait pas si elle a produit un effet n'est jamais
// reessayable, quelle que soit sa nature.
func Reessayable(err error) bool {
    return errors.Is(err, ErrIndisponible) || errors.Is(err, ErrQuota)
}

// AvecRenouvellement execute f, et rejoue une fois apres avoir renouvele le
// jeton si f a echoue sur un jeton expire.
//
// C'est le seul endroit du programme ou errAuthExpiree est observee, et c'est
// pourquoi elle n'a pas besoin d'etre publique : aucun appelant n'a de
// conduite a tenir, puisque le client s'en occupe. Un appelant qui la testait
// faisait le travail du client, en double.
func AvecRenouvellement(f func() error, renouveler func() error) error {
    err := f()
    if !errors.Is(err, errAuthExpiree) {
        return err
    }
    if err := renouveler(); err != nil {
        return fmt.Errorf("%w : renouvellement du jeton : %v", ErrConfiguration, err)
    }
    return f()
}
```

| Sentinelle | Conduite | Ce qu'elle absorbe |
|---|---|---|
| `ErrIndisponible` | réessayer avec recul | `ErrConnexion`, `ErrTLS`, `ErrDNS`, `ErrMaintenance`, `ErrInterne` |
| `ErrQuota` | attendre puis réessayer | `ErrQuota` |
| `ErrIssueIncertaine` | **ne pas réessayer**, reconcilier | `ErrTimeout` — voir question 2 |
| `ErrRefus` | le dire à l'utilisateur | `ErrSoldeInsuffisant`, `ErrPlafondAtteint`, `ErrCompteInconnu`, `ErrCompteBloque` |
| `ErrDejaFait` | opération acquise | `ErrReferenceDupliquee` |
| `ErrConfiguration` | alerter, ne pas insister | `ErrAuth`, `ErrVersionAPI` |
| `ErrNonClasse` | alerter, compléter la table | `ErrReponseIllisible` |

Et **deux ne sont pas réduites : elles sont supprimées.**

`ErrMontantInvalide` et `ErrDeviseNonSupportee` sont des **fautes de
l'appelant**, nature 2 de la leçon. Leur conduite n'est ni « le dire à
l'utilisateur » ni « réessayer » : c'est « corriger le code appelant ». Et la
bonne façon de le faire, c'est de rendre la faute impossible :

```go
func ParserMontant(fcfa int64) (Montant, error)  // dans le vocabulaire
```

Un client qui ne peut recevoir qu'un `Montant` et une `Devise` déjà analysés
ne peut plus produire ces deux erreurs. Elles ne sont pas fusionnées, elles
**disparaissent**.

> Avant de ranger une erreur, demande si elle doit exister. Une faute de
> l'appelant qu'un type peut interdire n'a pas besoin d'une sentinelle : elle a
> besoin d'un constructeur.

## Question 2 — Les deux sentinelles de même conduite

### Lesquelles

`ErrTimeout` et `ErrConnexion`. Les deux sont testées par `paiement`, et les
deux déclenchent « réessaie 3 fois ».

### À charge pour la fusion

Même conduite dans tous les appelants, donc le test décisif de la leçon dit de
fusionner : *une distinction sans conséquence est une dette*. On aurait une
sentinelle au lieu de deux, un `switch` plus court, et un appelant qui n'a
plus à savoir ce qu'est un `TLS handshake`.

### À décharge, et c'est ce qui l'emporte

Les deux ne disent pas la même chose du **monde** :

| | Ce qui s'est passé | Ce qui reste vrai |
|---|---|---|
| `ErrConnexion` | la requête n'est **jamais partie** | rien n'a bougé |
| `ErrTimeout` | la requête est partie, la réponse n'est pas revenue | **on ne sait pas** |

Un délai dépassé sur un débit signifie que le débit a peut-être eu lieu.
Réessayer trois fois, c'est risquer trois débits — c'est exactement la
question 3 de la correction 1.5 / 1.

### Le verdict, et la leçon de méthode

**Ne pas fusionner.** `ErrConnexion` devient `ErrIndisponible`, réessayable.
`ErrTimeout` devient `ErrIssueIncertaine`, qui ne l'est pas.

Et il faut dire pourquoi le dépouillement s'est trompé :

> Le dépouillement des conduites dit ce que les appelants **font**, pas ce
> qu'ils **devraient** faire. Si deux issues ont la même conduite et qu'elles
> ne devraient pas, la mesure vient de révéler un bug chez les deux appelants,
> pas une redondance dans ton API.

C'est le contrepoids de la méthode empirique de l'exercice 1.2 / 3. Là-bas,
l'historique git disait la vérité sur le passé et il fallait l'écouter. Ici, le
`grep` dit la vérité sur les conduites actuelles — et deux d'entre elles sont
fausses.

> Une mesure ne te dit jamais ce qu'il faut faire. Elle te dit ce qui est, et
> c'est à toi de décider si ce qui est est bien.

Et l'épreuve de vérité : après la séparation, `paiement` et `remboursement`
**ne compilent plus** sur ces deux branches. C'est voulu. Chacun doit
rouvrir sa politique de réessai, ce qui est précisément le travail qu'il faut
faire.

## Question 3 — `ErrPlafondAtteint` et le `strings.Contains`

### La situation

Personne ne teste la sentinelle. Mais `web` fait
`strings.Contains(err.Error(), "plafond")`.

Donc `ErrPlafondAtteint` **est** publique. Pas par son identité, par son
libellé.

> Une sentinelle que personne ne teste mais dont tout le monde lit le message
> est publique quand même. Et elle est publique par sa partie la plus
> fragile : celle qu'on a le droit de changer sans prévenir.

### Ce que je fais, et dans quel ordre

L'ordre est toute la réponse.

**1. D'abord, corriger `web`.** Il teste désormais la sentinelle :

```go
var refus clientpsp.Detail
if errors.As(err, &refus) && refus.Code == "DAILY_LIMIT_EXCEEDED" { ... }
```

Ce changement est local à `web`, se déploie seul, et ne casse rien :
`err.Error()` contient toujours « plafond » à ce stade.

**2. Ensuite, et seulement ensuite, toucher à la sentinelle** — la fondre dans
`ErrRefus` avec son motif.

Dans l'autre ordre, `web` cesse silencieusement de reconnaître le plafond.
Pas d'erreur de compilation, pas de test en échec : le `strings.Contains`
rend simplement `false`, et l'utilisateur reçoit « une erreur inattendue est
survenue » au lieu de « plafond atteint, payez en deux fois ». Personne ne le
verra avant une réclamation.

> Quand un appelant dépend d'un message, on ne corrige pas le message : on
> corrige l'appelant d'**abord**. L'ordre est tout, parce que ce couplage est
> invisible et qu'aucune compilation ne te rattrapera.

**3. Et dans l'intervalle, un garde-fou.** Un test en CI qui refuse
l'apparition de nouveaux `strings.Contains(err.Error()` dans le dépôt :

```sh
grep -rn 'Contains(err.Error()' --include='*.go' . | grep -v '_test.go'
```

Zéro ligne attendue. C'est 🟡, c'est trois lignes de CI, et ça empêche la
situation de se reproduire — ce qui est plus utile que de l'avoir corrigée une
fois.

## Question 4 — `ErrAuthExpiree`, testée seulement par `clientpsp`

### Est-ce une erreur publique ?

Non. Et le dépouillement le dit sans ambiguïté : elle n'est testée que par le
paquet qui la définit.

Un symbole exporté que seul son paquet utilise est un contrat que **personne
n'a demandé** et dont on ne peut plus se débarrasser.

### Ce qu'elle devient

Non exportée, et le renouvellement devient une affaire interne :

```go
// errAuthExpiree n'est PAS exportee.
//
// Le depouillement montre qu'elle n'est testee que par ce paquet lui-meme :
// c'est un detail de son fonctionnement interne — il renouvelle son jeton et
// rejoue. Un symbole exporte que seul son paquet utilise est un contrat que
// personne n'a demande et qu'on ne peut plus retirer.
var errAuthExpiree = errors.New("psp : jeton expire")
```

Avec la mécanique qui va avec, publiée dans le même fichier :

```go
func AvecRenouvellement(f func() error, renouveler func() error) error {
    err := f()
    if !errors.Is(err, errAuthExpiree) {
        return err
    }
    if err := renouveler(); err != nil {
        return fmt.Errorf("%w : renouvellement du jeton : %v", ErrConfiguration, err)
    }
    return f()
}
```

Et si le renouvellement échoue, l'appelant reçoit `ErrConfiguration` — une
conduite qu'il comprend — et non l'erreur interne.

### Le test, et où il vit

```go
package clientpsp

import (
    "errors"
    "testing"
)

// Ce test est dans le paquet, et pas dans clientpsp_test, pour une raison
// qui est elle-meme la lecon : errAuthExpiree n'est pas exportee, donc un
// test externe ne peut pas la nommer — exactement comme un appelant.
func TestLeRenouvellementEstInterne(t *testing.T) {
    var appels, renouvellements int

    err := AvecRenouvellement(
        func() error {
            appels++
            if appels == 1 {
                return errAuthExpiree
            }
            return nil
        },
        func() error { renouvellements++; return nil },
    )

    if err != nil {
        t.Fatalf("err = %v", err)
    }
    if appels != 2 || renouvellements != 1 {
        t.Errorf("%d appels, %d renouvellements, attendu 2 et 1", appels, renouvellements)
    }
}

// Si le renouvellement echoue, l'appelant recoit une conduite qu'il
// comprend — alerter, ne pas insister — et non l'erreur interne.
func TestUnRenouvellementEchoueDevientUneConduitePublique(t *testing.T) {
    err := AvecRenouvellement(
        func() error { return errAuthExpiree },
        func() error { return errors.New("serveur d'autorisation injoignable") },
    )

    if !errors.Is(err, ErrConfiguration) {
        t.Fatalf("err = %v, attendu ErrConfiguration", err)
    }
    if errors.Is(err, errAuthExpiree) {
        t.Error("l'erreur interne a fui chez l'appelant")
    }
    if Reessayable(err) {
        t.Error("un probleme d'autorisation ne se regle pas en reessayant")
    }
}
```

Il est **dans** le paquet, pas dans `clientpsp_test`. Et c'est volontaire :

> Un test externe ne peut pas nommer `errAuthExpiree`, exactement comme un
> appelant. Le choix du paquet de test est lui-même une vérification de la
> frontière.

C'est un détail de Go qu'on utilise rarement à bon escient : `package x` et
`package x_test` ne sont pas deux conventions de rangement, ce sont deux
**périmètres**. Mettre un test dans `x_test` est une façon de déclarer qu'il
ne teste que ce qui est public.

## Question 5 — Les onze que personne ne teste

Elles ne disparaissent pas. L'information qu'elles portent est précieuse —
pour le **diagnostic**, pas pour la **décision**.

```go
// Code est le code d'origine du prestataire. Il ne sert PAS a decider : il
// sert a diagnostiquer, a compter et a regrouper dans un tableau de bord.
//
// C'est la ou vont les douze sentinelles supprimees. L'information est
// conservee ; ce qui est supprime, c'est l'illusion qu'un appelant doit en
// tenir compte.
type Code string

// Detail est l'erreur typee du client.
//
// Is la fait correspondre a l'une des sept sentinelles : la conduite se teste
// avec errors.Is, le code d'origine se lit avec errors.As.
type Detail struct {
    Conduite error // l'une des sept sentinelles
    Code     Code  // le code du prestataire, tel quel
    Statut   int   // le statut HTTP, tel quel
    Message  string
}

func (d Detail) Error() string {
    return fmt.Sprintf("%v (code %q, statut %d) : %s", d.Conduite, d.Code, d.Statut, d.Message)
}

func (d Detail) Is(cible error) bool { return cible == d.Conduite }
func (d Detail) Unwrap() error       { return d.Conduite }
```

Le code d'origine du prestataire part dans `Detail.Code`, avec le statut HTTP
et le message. Donc :

- un tableau de bord peut grouper par `Code` et montrer que les échecs de
  `DNS_FAILURE` ont triplé cette semaine ;
- l'astreinte lit le code exact dans le journal ;
- et **aucun appelant n'a à s'en soucier**, parce que tous les codes de la même
  famille mènent à la même conduite.

```go
package clientpsp_test

import (
    "errors"
    "strings"
    "testing"

    "exemple/psp/clientpsp"
)

// La conduite se teste sur la sentinelle, le code d'origine se lit avec
// errors.As. Les deux a la fois, sur une seule valeur.
func TestLaConduiteEtLeDiagnosticCoexistent(t *testing.T) {
    err := clientpsp.Detail{
        Conduite: clientpsp.ErrRefus,
        Code:     "DAILY_LIMIT_EXCEEDED",
        Statut:   429,
        Message:  "plafond journalier",
    }

    if !errors.Is(err, clientpsp.ErrRefus) {
        t.Error("la conduite n'est pas testable")
    }
    if errors.Is(err, clientpsp.ErrIndisponible) {
        t.Error("un refus classe comme indisponibilite")
    }
    if clientpsp.Reessayable(err) {
        t.Error("un refus n'est pas reessayable, meme en 429")
    }

    var d clientpsp.Detail
    if !errors.As(err, &d) {
        t.Fatal("errors.As echoue : le diagnostic est perdu")
    }
    if d.Code != "DAILY_LIMIT_EXCEEDED" || d.Statut != 429 {
        t.Errorf("detail = %+v", d)
    }
    // Le code d'origine reste dans le message, pour celui qui lit un journal.
    if !strings.Contains(err.Error(), "DAILY_LIMIT_EXCEEDED") {
        t.Errorf("le code d'origine a disparu du message : %v", err)
    }
}

// Les douze sentinelles supprimees restent distinguables dans un tableau de
// bord : on groupe par Code, pas par type d'erreur.
func TestOnPeutToujoursGrouperParCodeDOrigine(t *testing.T) {
    erreurs := []error{
        clientpsp.Detail{Conduite: clientpsp.ErrIndisponible, Code: "TLS_HANDSHAKE_FAILED"},
        clientpsp.Detail{Conduite: clientpsp.ErrIndisponible, Code: "DNS_FAILURE"},
        clientpsp.Detail{Conduite: clientpsp.ErrIndisponible, Code: "DNS_FAILURE"},
        clientpsp.Detail{Conduite: clientpsp.ErrRefus, Code: "INSUFFICIENT_FUNDS"},
    }

    parCode := map[clientpsp.Code]int{}
    for _, err := range erreurs {
        var d clientpsp.Detail
        if errors.As(err, &d) {
            parCode[d.Code]++
        }
    }

    if parCode["DNS_FAILURE"] != 2 || parCode["TLS_HANDSHAKE_FAILED"] != 1 {
        t.Errorf("regroupement = %v", parCode)
    }
    // Et pourtant les trois premieres menent a la MEME conduite.
    for _, err := range erreurs[:3] {
        if !clientpsp.Reessayable(err) {
            t.Error("les trois defaillances de transport sont reessayables")
        }
    }
}

// Un delai depasse n'est pas une indisponibilite : la requete est peut-etre
// arrivee. C'est la separation que l'historique des appelants ne montrait
// pas, parce que les deux appelants avaient le meme bug.
func TestUnDelaiDepasseNEstPasReessayable(t *testing.T) {
    delai := clientpsp.Detail{
        Conduite: clientpsp.ErrIssueIncertaine,
        Code:     "REQUEST_TIMEOUT",
        Statut:   0,
        Message:  "context deadline exceeded",
    }
    connexion := clientpsp.Detail{
        Conduite: clientpsp.ErrIndisponible,
        Code:     "CONNECTION_REFUSED",
        Message:  "dial tcp: connection refused",
    }

    if clientpsp.Reessayable(delai) {
        t.Error("un delai depasse reessaye peut debiter deux fois")
    }
    if !clientpsp.Reessayable(connexion) {
        t.Error("une connexion refusee n'a rien envoye : le reessai est legitime")
    }
    if errors.Is(delai, clientpsp.ErrIndisponible) {
        t.Error("les deux conduites sont confondues")
    }
}
```

Le second test est la démonstration : trois erreurs de codes d'origine
différents, une seule conduite, et un regroupement par code toujours
possible.

```go
if parCode["DNS_FAILURE"] != 2 || parCode["TLS_HANDSHAKE_FAILED"] != 1 {
```

> On ne jette pas l'information, on la **déclasse**. Elle passe de « ce sur
> quoi on décide » à « ce sur quoi on compte ». Une erreur peut être
> diagnostiquée finement et traitée grossièrement, et c'est le cas le plus
> fréquent.

Note la mécanique qui raccorde les deux :

```go
func (d Detail) Is(cible error) bool { return cible == d.Conduite }
func (d Detail) Unwrap() error       { return d.Conduite }
```

`Is` fait correspondre le `Detail` à sa conduite pour `errors.Is`, et `Unwrap`
raccroche la chaîne. Une seule valeur porte la conduite et le diagnostic.

## Question 6 — Le `%w` sur une erreur de transport

### Ce que ça a rendu public

```go
fmt.Errorf("psp : %w", err)   // err est une net.Error
```

Tout ce que l'erreur du transport permet de tester. Donc :

- `errors.Is(err, os.ErrDeadlineExceeded)` ;
- `errors.Is(err, syscall.ECONNREFUSED)` ;
- `errors.As(err, &netErr)` puis `netErr.Timeout()` ;
- `errors.As(err, &urlErr)` puis la lecture de `urlErr.URL` — **qui peut
  contenir un jeton en paramètre de requête**.

Le dernier point n'est pas théorique. Un `*url.Error` porte l'URL appelée, et
une URL appelée porte parfois une clé d'API.

### Veux-tu le révoquer ?

Oui. Mais il faut regarder ce que ça coûte avant de le dire.

Passer de `%w` à `%v` est un **changement cassant** pour tout appelant qui
s'appuyait sur la chaîne. Et le problème n'est pas l'ampleur du changement,
c'est l'ignorance :

> Si `clientpsp` est consommé hors de ce dépôt, tu **ne peux pas savoir** qui
> dépendait de la chaîne. Il n'y a pas de `grep` possible sur le code des
> autres.

Et il n'existe pas de période de transition : on ne peut pas enlever `%w` « à
moitié ». Soit l'identité est testable, soit elle ne l'est pas.

Donc la révocation coûte une version majeure, avec une note de version qui dit
explicitement *« les erreurs du transport ne sont plus enveloppées ; utilisez
`errors.Is(err, ErrIndisponible)` »*.

### La leçon pratique

> `%w` est le seul engagement qu'on prend sans s'en apercevoir, et qu'on ne
> peut pas révoquer sans casser quelqu'un qu'on ne connaît pas.

Deux conséquences concrètes :

- **dans une bibliothèque**, chaque `%w` est une décision d'API. Elle mérite la
  même attention qu'une méthode exportée ;
- **dans un paquet neuf**, commence par `%v` partout, et promeus en `%w`
  délibérément, erreur par erreur, quand un appelant en a besoin. L'inverse —
  `%w` par défaut — publie des identités par inadvertance.

## Question 7 — Ce qui rendrait ma réduction fausse

### Le changement

> Le métier décide qu'un paiement refusé pour **plafond atteint** doit être
> automatiquement scindé en deux paiements de la moitié, étalés sur deux jours.

Ce jour-là, `PlafondAtteint` n'a plus la même conduite que
`SoldeInsuffisant`. L'un déclenche un traitement automatique, l'autre un
message à l'utilisateur. Le motif est devenu une **conduite**, donc il lui faut
sa sentinelle, et ma fusion est fausse.

### Le signal, et il est précis

Ce n'est pas une intuition, et ce n'est pas une surprise : il y a un signal
mécanique, visible dans un `grep`.

> Le signal qu'une fusion est devenue fausse : un appelant utilise
> `errors.As` sur le motif pour **décider** au lieu d'**afficher**.

Concrètement, le jour où quelqu'un écrit :

```go
var d clientpsp.Detail
if errors.As(err, &d) && d.Code == "DAILY_LIMIT_EXCEEDED" {
    return scinderEnDeux(p)   // ← une décision, pas un texte
}
```

…le motif a cessé d'être une donnée de présentation. Il faut alors sortir
`ErrPlafondAtteint` de `ErrRefus`.

Et c'est vérifiable en CI, comme le reste :

```sh
# Les errors.As sur Detail ne doivent apparaître que dans les paquets de
# présentation. Partout ailleurs, c'est le signe qu'une conduite manque.
grep -rln 'errors.As' --include='*.go' . | grep -v -e '/web/' -e '/api/' -e '_test.go'
```

> Une réduction d'erreurs est une hypothèse sur les conduites, exactement
> comme une découpe est une hypothèse sur les changements. Elle est donc
> falsifiable, et il faut écrire par quoi on la verra tomber.

C'est la même conclusion qu'à la correction 1.2 / 3, sur un autre objet : la
mesure qui a servi à décider doit pouvoir être refaite.

## À retenir

1. On réduit une taxonomie d'erreurs en comptant les **conduites**, pas les
   erreurs. Dix-huit sentinelles, six conduites observées, sept retenues.
2. Avant de ranger une erreur, demande si elle doit exister. Une faute de
   l'appelant qu'un type peut interdire a besoin d'un constructeur, pas d'une
   sentinelle.
3. Le dépouillement dit ce que les appelants **font**, pas ce qu'ils
   **devraient** faire. Deux conduites identiques peuvent révéler deux bugs
   identiques.
4. Une mesure ne dit jamais quoi faire. Elle dit ce qui est.
5. Une connexion refusée et un délai dépassé ne disent pas la même chose du
   monde : l'un n'a rien envoyé, l'autre ne sait pas.
6. Une sentinelle que personne ne teste mais dont tout le monde lit le message
   est publique quand même — par sa partie la plus fragile.
7. Quand un appelant dépend d'un message, corrige l'appelant **d'abord**.
   L'ordre inverse casse en silence.
8. Un symbole exporté que seul son paquet utilise est un contrat que personne
   n'a demandé.
9. `package x` et `package x_test` sont deux périmètres, pas deux conventions
   de rangement.
10. On ne jette pas l'information : on la déclasse. De « ce sur quoi on
    décide » vers « ce sur quoi on compte ».
11. `%w` est le seul engagement qu'on prend sans s'en apercevoir. Dans une
    bibliothèque, commence par `%v` et promeus délibérément.
12. Le signal qu'une fusion est devenue fausse : un `errors.As` qui sert à
    décider au lieu d'afficher. Ça se cherche avec un `grep`.
