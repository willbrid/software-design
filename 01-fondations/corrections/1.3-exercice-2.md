# Correction — Exercice 1.3 / 2 (code)

## Ce qui était demandé

Réécrire le paquet `catalog`, avec sept contraintes. Les six premières sont
mécaniques. La septième — *nomme un couplage que tu as délibérément gardé* —
est celle qui sépare quelqu'un qui a compris la leçon 1.3 de quelqu'un qui a
seulement compris la 1.2.

## La découpe

| Module | Raison de changer | Dépendances internes | Détient un état ? |
|---|---|---|---|
| `price` | la règle de remise | **aucune** | non |
| `article` | ce qu'est un article vendable, et le prélèvement de stock | **aucune** | non |
| `display` | la présentation d'un prix | `article` | non |
| `catalog` | l'ordre des étapes et la politique de réessai | `article`, `price` | **oui, et il est seul** |

Quatre modules, et le tableau dit l'essentiel : **trois d'entre eux ne
détiennent rien.** Ce sont des règles et des valeurs. Un seul détient l'état,
et c'est celui dont le nom dit qu'il tient un catalogue.

## Contrainte 1 et 2 — la règle, sans rien, et le test qui le prouve

```go
// Package price holds the discount rule.
//
// Reason to change: how a discount applies to a price.
//
// No internal dependency, no package state, no clock. The grid
// is a value it is given, not a file it reads.
package price

import "errors"

var (
    ErrPercent       = errors.New("price: percent outside [0, 100]")
    ErrNegativePrice = errors.New("price: negative net price")
)

// Grid is the table of discounts, in percent, by article code.
//
// It is an immutable value: NewGrid copies the map it is given, so
// that the caller cannot modify the grid afterwards. It is lesson
// 1.1 applied to a construction parameter.
type Grid struct {
    byCode   map[string]int64
    fallback int64
}

func NewGrid(fallback int64, byCode map[string]int64) (Grid, error) {
    if fallback < 0 || fallback > 100 {
        return Grid{}, ErrPercent
    }
    cp := make(map[string]int64, len(byCode))
    for code, pct := range byCode {
        if pct < 0 || pct > 100 {
            return Grid{}, ErrPercent
        }
        cp[code] = pct
    }
    return Grid{byCode: cp, fallback: fallback}, nil
}

// Percent returns the discount that applies to a code.
func (g Grid) Percent(code string) int64 {
    if pct, ok := g.byCode[code]; ok {
        return pct
    }
    return g.fallback
}

// Discount applies the discount to the net price.
//
// Rounding favors the seller least, and it is a decision
// made explicitly: integer division truncates, so the client pays the cent
// below. If accounting wants the opposite, it changes this line and
// it knows where to find it.
func (g Grid) Discount(code string, netPrice int64) (int64, error) {
    if netPrice < 0 {
        return 0, ErrNegativePrice
    }
    return netPrice - netPrice*g.Percent(code)/100, nil
}
```

Le point à ne pas manquer est dans `NewGrid` :

```go
cp := make(map[string]int64, len(byCode))
for code, pct := range byCode {
```

La grille **recopie** la `map` qu'on lui donne. Sans cette copie, `Grid` ne
serait pas une valeur : ce serait un alias vers la `map` de l'appelant, qui
pourrait la modifier après coup. C'est un couplage de degré 5, et c'est
exactement la leçon 1.1 appliquée à un paramètre de construction.

```go
package price

import (
    "errors"
    "testing"
)

func TestDiscount(t *testing.T) {
    g, err := NewGrid(5, map[string]int64{"PROMO": 20, "FULL": 0})
    if err != nil {
        t.Fatal(err)
    }

    tc := []struct {
        name string
        code string
        ht   int64
        want int64
    }{
        {"discount by code", "PROMO", 10000, 8000},
        {"explicit zero discount", "FULL", 10000, 10000},
        {"default discount", "UNKNOWN", 10000, 9500},
        {"rounding: truncated in the client's favor", "PROMO", 333, 267},
        {"zero", "PROMO", 0, 0},
    }
    for _, c := range tc {
        t.Run(c.name, func(t *testing.T) {
            got, err := g.Discount(c.code, c.ht)
            if err != nil {
                t.Fatal(err)
            }
            if got != c.want {
                t.Errorf("Discount(%q, %d) = %d, want %d", c.code, c.ht, got, c.want)
            }
        })
    }
}

// The grid copies the map: changing the original map after construction does not
// change the grid. Without this copy, the grid would be a coupling through
// identity: degree 5.
func TestTheGridIsNotAliased(t *testing.T) {
    source := map[string]int64{"PROMO": 20}
    g, err := NewGrid(0, source)
    if err != nil {
        t.Fatal(err)
    }

    source["PROMO"] = 90
    delete(source, "PROMO")
    source["OTHER"] = 50

    if got := g.Percent("PROMO"); got != 20 {
        t.Errorf("the grid followed the original map: %d", got)
    }
    if got := g.Percent("OTHER"); got != 0 {
        t.Errorf("the grid picked up an entry added afterwards: %d", got)
    }
}

func TestInvalidPercentIsRefused(t *testing.T) {
    if _, err := NewGrid(101, nil); !errors.Is(err, ErrPercent) {
        t.Errorf("default out of bounds: err = %v", err)
    }
    if _, err := NewGrid(0, map[string]int64{"X": -1}); !errors.Is(err, ErrPercent) {
        t.Errorf("entry out of bounds: err = %v", err)
    }
}
```

`TestTheGridIsNotAliased` est le test que personne n'écrit. Il ne vérifie
aucune règle métier : il vérifie qu'une valeur est bien une valeur. Modifie la
`map` source après la construction, et la grille ne doit pas bouger.

### Le test de structure

```go
// Package guard holds only structure tests.
package guard

import (
    "os/exec"
    "strings"
    "testing"
)

// Constraint 2 of the statement: the module that holds the computation has no
// internal dependency.
//
// The test does not name the forbidden packages one by one: it requires that there be
// be none. It is a stronger rule, and simpler to keep.
func TestPriceHasNoInternalDependency(t *testing.T) {
    const module = "example/shop"

    out, err := exec.Command("go", "list", "-deps", module+"/price").Output()
    if err != nil {
        t.Fatalf("go list: %v", err)
    }

    for _, dep := range strings.Split(strings.TrimSpace(string(out)), "\n") {
        dep = strings.TrimSpace(dep)
        if dep == module+"/price" || !strings.HasPrefix(dep, module+"/") {
            continue
        }
        t.Errorf("price depends on %q: the rule has stopped being a rule", dep)

```

Note la différence avec le test équivalent de la correction 1.2 / 2 : celui-là
listait les paquets interdits, celui-ci n'en liste aucun. Il exige qu'il n'y
en ait **aucun** du module.

> Une liste d'interdits est toujours incomplète : il faut l'étendre à chaque
> nouvelle tentation. Une exigence de zéro n'a pas ce défaut.

C'est une règle générale des garde-fous : chaque fois que tu peux remplacer
une liste noire par une liste blanche vide, fais-le.

## Contrainte 3 — un consommateur ne peut pas modifier le stock

```go
// Package article holds the catalog article and the rule for taking
// stock.
//
// Reason to change: what a sellable article is and what allows a
// withdrawal.
//
// A consumer cannot modify an article's stock: the fields
// are unexported and Reserve returns a new value. It is not a
// convention, it is an absence of means.
package article

import "errors"

type Code string

// Article is a value, not an object.
type Article struct {
    code     Code
    netPrice int64
    stock    int
}

var (
    ErrEmptyCode     = errors.New("article: empty code")
    ErrNegativePrice = errors.New("article: negative net price")
    ErrNegativeStock = errors.New("article: negative stock")
    ErrQuantity      = errors.New("article: quantity not strictly positive")
    ErrStockTooLow   = errors.New("article: stock too low")
)

func New(code Code, netPrice int64, stock int) (Article, error) {
    switch {
    case code == "":
        return Article{}, ErrEmptyCode
    case netPrice < 0:
        return Article{}, ErrNegativePrice
    case stock < 0:
        return Article{}, ErrNegativeStock
    }
    return Article{code: code, netPrice: netPrice, stock: stock}, nil
}

func (a Article) Code() Code       { return a.code }
func (a Article) NetPrice() int64  { return a.netPrice }
func (a Article) Stock() int       { return a.stock }
func (a Article) OutOfStock() bool { return a.stock == 0 }

// Reserve returns a new Article whose stock is decreased.
//
// The original is not touched. So there is no "after" version that
// overwrites the "before" version behind someone's back, and the returned value
// can be compared with the one read: that is what makes possible a
// compare-and-swap in the caller.
func (a Article) Reserve(n int) (Article, error) {
    if n <= 0 {
        return a, ErrQuantity
    }
    if n > a.stock {
        return a, ErrStockTooLow
    }
    a.stock -= n
    return a, nil
}
```

**Le mécanisme : ⚫, l'absence de moyen.** Les champs sont non exportés, il n'y
a aucun *setter*, et `Reserve` est une méthode **à récepteur valeur** qui rend
un nouvel `Article`.

Un consommateur ne peut donc pas modifier le stock d'un article. Pas parce
qu'on le lui a interdit : parce qu'il n'y a rien à modifier — il détient une
copie, et le type ne lui offre aucun chemin.

Trois conséquences qui vont plus loin que la contrainte :

- **Aucune méthode ne peut mentir sur ce qu'elle touche.** Un récepteur valeur
  ne peut rien faire fuir.
- **La valeur rendue est comparable à la valeur lue.** C'est ce qui rend
  possible le compare-and-swap de `catalog` — et ce n'était pas dans
  l'énoncé, c'est un bénéfice qu'on découvre après.
- **Un article à stock négatif n'est pas représentable**, parce que `New` est
  le seul constructeur et qu'il refuse.

```go
package article

import (
    "errors"
    "testing"
)

// The central test of this module: reserving does not modify the original article.
//
// It checks a design property, not a business behavior. If
// someone one day turns Reserve into a pointer method "to avoid a
// copy", this test fails, and that is its whole point.
func TestReserveLeavesTheOriginal(t *testing.T) {
    a, err := New("CIM50", 6500, 10)
    if err != nil {
        t.Fatal(err)
    }

    b, err := a.Reserve(3)
    if err != nil {
        t.Fatal(err)
    }

    if a.Stock() != 10 {
        t.Errorf("original's stock = %d, want 10", a.Stock())
    }
    if b.Stock() != 7 {
        t.Errorf("result's stock = %d, want 7", b.Stock())
    }
}

func TestReserveRefuses(t *testing.T) {
    a, _ := New("CIM50", 6500, 2)

    if _, err := a.Reserve(3); !errors.Is(err, ErrStockTooLow) {
        t.Errorf("quantity > stock: err = %v", err)
    }
    if _, err := a.Reserve(0); !errors.Is(err, ErrQuantity) {
        t.Errorf("zero quantity: err = %v", err)
    }
    if _, err := a.Reserve(-1); !errors.Is(err, ErrQuantity) {
        t.Errorf("negative quantity: err = %v", err)
    }
}

// An article with negative stock cannot be represented.
func TestConstructorRefusesImpossibleStates(t *testing.T) {
    if _, err := New("", 100, 1); !errors.Is(err, ErrEmptyCode) {
        t.Errorf("empty code: err = %v", err)
    }
    if _, err := New("X", 100, -1); !errors.Is(err, ErrNegativeStock) {
        t.Errorf("negative stock: err = %v", err)
    }
}
```

Le premier test est le cœur du module, et il mérite d'être lu deux fois :

```go
func TestReserveLeavesTheOriginal(t *testing.T)
```

Il ne vérifie pas une règle métier. Il vérifie une **propriété de
conception**. Et son vrai intérêt est dans l'avenir : le jour où quelqu'un
passera `Reserve` en méthode à pointeur « pour éviter une copie », ce test
échouera, et la revue portera sur la bonne question.

> Une propriété de conception qu'on n'a pas testée est une propriété qu'on
> perdra. Pas par malveillance : par optimisation bien intentionnée.

## Contrainte 4 — ni rendre ni modifier

```go
// Package display formats a price for a human.
//
// Reason to change: how a price is shown: currency, separator,
// out-of-stock label. Requester: marketing and the product team.
//
// It receives an amount already computed: it knows neither the discount grid,
// nor the VAT. The question it asks is "how much and in what state", not
// "how did you get it".
package display

import (
    "fmt"
    "strings"

    "example/shop/article"
)

type Formatter struct {
    Currency  string
    Separator string
}

// Price returns only a string. It modifies nothing, least of all the article
// it is passed: it is constraint 4 of the statement.
func (f Formatter) Price(a article.Article, amount int64) string {
    s := f.group(amount) + " " + f.Currency
    if a.OutOfStock() {
        s += " (out of stock)"
    }
    return s
}

func (f Formatter) group(n int64) string {
    sep := f.Separator
    if sep == "" {
        return fmt.Sprintf("%d", n)
    }
    sign := ""
    if n < 0 {
        sign, n = "-", -n
    }
    digits := fmt.Sprintf("%d", n)
    var b strings.Builder
    for i, c := range digits {
        if i > 0 && (len(digits)-i)%3 == 0 {
            b.WriteString(sep)
        }
        b.WriteRune(c)
    }
    return sign + b.String()
}
```

`Price` rend une chaîne et ne touche à rien. Et il reçoit le **montant déjà
calculé** au lieu de la grille de remises.

Cette seconde décision est plus importante qu'elle n'y paraît. `display`
pourrait recevoir la `Grid` et faire le calcul lui-même — ce serait plus
pratique à l'appel. Mais alors la présentation dépendrait de la règle de
remise, et deux demandeurs qui n'ont rien à voir — le marketing et le
commerce — se retrouveraient dans le même module.

> La question qu'`display` pose est « combien, et dans quel état ». Pas
> « comment l'as-tu obtenu ». Une frontière se dessine en choisissant la
> question, pas en choisissant les types.

## Contrainte 5 — les dépendances sont déclarées

Il ne reste **aucune** variable de paquet. Le relevé :

| Avant | Après |
|---|---|
| `var Currency = "XAF"` | `display.Formatter{Currency: ...}`, un champ |
| `var Discounts` + `init()` | `price.Grid`, construite par l'appelant |
| `var Index` | l'état est derrière `catalog.Repo` |
| `var cache sync.Map` | supprimé — voir plus bas |
| `init()` lisant un fichier | supprimé : c'est au point d'entrée de lire la configuration et de construire la grille |

Le cache a disparu, et ce n'est pas un oubli. Il était la cause de trois des
treize couplages de l'exercice 1 : l'espace de clés partagé, l'invalidation
par motif, et la composition non atomique du `Load`/`Store`.

S'il faut un cache — et sur un catalogue, il en faudra un —, il se place
**derrière `Repo`**, comme un décorateur, dans le module qui possède cet état.
C'est la proposition de la correction 1.2 / 3, et le raisonnement est le même.

## L'orchestrateur, et le compare-and-swap

```go
// Package catalog holds the stock state and orchestrates a withdrawal.
//
// Reason to change: the order of steps of a reservation and the policy of
// retry on contention.
//
// It is the only one of the four modules that holds state. The other three are
// rules and values.
package catalog

import (
    "context"
    "errors"
    "fmt"

    "example/shop/article"
    "example/shop/price"
)

// Repo is declared here, on the consumer side.
//
// Replace is a compare-and-swap: it writes only if the value in place
// is still the one we read. It is the only assumption the
// correctness of this module under concurrency, and it is exactly the mechanism
// of correction 1.1 / 5.
type Repo interface {
    Read(ctx context.Context, code article.Code) (article.Article, error)
    Replace(ctx context.Context, before, after article.Article) (swap bool, err error)
}

var ErrContention = errors.New("catalog: too much contention on the article")

// tries bounds the retry.
//
// An unbounded loop turns contention into unavailability; a
// bound that is too low turns contention into refusal. The bound must exceed
// the number of successful concurrent writes we agree to serve on one
// same article: beyond it, we prefer to refuse explicitly rather than
// looping.
const tries = 32

type Service struct {
    Repo Repo
    Grid price.Grid
}

// Line is what a reservation produces: enough to fill a cart.
type Line struct {
    Code   article.Code
    Qty    int
    Amount int64
}

// Reserve takes n units and returns the matching line.
//
// Nothing is modified in place: we read a value, compute a
// new one, and we ask the repo to swap one for the other. If
// someone came in meanwhile, the swap fails and we start again on the
// fresh value.
func (s *Service) Reserve(ctx context.Context, code article.Code, n int) (Line, error) {
    for attempt := 0; attempt < tries; attempt++ {
        before, err := s.Repo.Read(ctx, code)
        if err != nil {
            return Line{}, fmt.Errorf("catalog: read %q: %w", code, err)
        }

        after, err := before.Reserve(n)
        if err != nil {
            return Line{}, err
        }

        swap, err := s.Repo.Replace(ctx, before, after)
        if err != nil {
            return Line{}, fmt.Errorf("catalog: swap %q: %w", code, err)
        }
        if !swap {
            continue
        }

        amount, err := s.Grid.Discount(string(code), after.NetPrice())
        if err != nil {
            return Line{}, err
        }
        return Line{Code: code, Qty: n, Amount: amount * int64(n)}, nil
    }
    return Line{}, fmt.Errorf("%w: %q", ErrContention, code)
}
```

Le cycle `Read` → calculer → `Replace` est le même que celui de la
correction 1.1 / 5 : l'écriture ne réussit que si la valeur en place est
encore celle qu'on a lue.

Et il n'est possible que grâce à la contrainte 3. Comme `article.Reserve` rend
une **nouvelle** valeur sans toucher à l'ancienne, on détient les deux, donc on
peut demander au dépôt de substituer l'une à l'autre. Avec un `*Article` muté
en place, il n'y a plus d'« avant » à comparer : on l'a écrasé.

> L'immuabilité n'est pas une élégance : c'est ce qui rend possible un
> compare-and-swap. On ne peut pas comparer à un état qu'on a détruit.

### La borne de réessai

```go
const tries = 32
```

Une boucle non bornée transforme une contention en indisponibilité : sous
charge, tout le monde boucle et personne n'avance. Une borne trop basse
transforme une contention en refus, et le client voit une erreur alors que
l'article était disponible.

La borne doit donc dépasser le nombre d'écritures concurrentes réussies qu'on
accepte de servir sur un même article. Et surtout, dans les deux cas, **le
comportement est explicite et nommé** : `ErrContention` est une réponse, pas
un symptôme.

```go
package catalog

import (
    "context"
    "errors"
    "runtime"
    "sync"
    "testing"

    "example/shop/article"
    "example/shop/price"
)

// memRepo implements the compare-and-swap with a lock. In a database, it is
// an UPDATE ... WHERE stock = $old.
type memRepo struct {
    mu       sync.Mutex
    articles map[article.Code]article.Article
    failures int
}

func (d *memRepo) Read(_ context.Context, code article.Code) (article.Article, error) {
    d.mu.Lock()
    a, ok := d.articles[code]
    d.mu.Unlock()
    if !ok {
        return article.Article{}, errors.New("unknown")
    }

    // In a database, the window between reading and swapping is a network
    // round trip. In memory it is almost zero, so the test would never see
    // the contention it claims to exercise. We widen it explicitly.
    runtime.Gosched()
    return a, nil
}

func (d *memRepo) Replace(_ context.Context, before, after article.Article) (bool, error) {
    d.mu.Lock()
    defer d.mu.Unlock()
    if d.articles[before.Code()] != before {
        d.failures++
        return false, nil
    }
    d.articles[after.Code()] = after
    return true, nil
}

func service(t *testing.T, stock int) (*Service, *memRepo) {
    t.Helper()
    a, err := article.New("CIM50", 6500, stock)
    if err != nil {
        t.Fatal(err)
    }
    g, err := price.NewGrid(0, map[string]int64{"CIM50": 10})
    if err != nil {
        t.Fatal(err)
    }
    d := &memRepo{articles: map[article.Code]article.Article{"CIM50": a}}
    return &Service{Repo: d, Grid: g}, d
}

func TestReserveComputesTheLine(t *testing.T) {
    s, _ := service(t, 10)
    l, err := s.Reserve(context.Background(), "CIM50", 2)
    if err != nil {
        t.Fatal(err)
    }
    if l.Amount != 11700 { // (6500 - 10 %) x 2
        t.Errorf("amount = %d, want 11700", l.Amount)
    }
}

// The test that justifies the compare-and-swap. Run with -race.
//
// Fifty concurrent requests on twenty units: exactly twenty
// succeed, the final stock is zero, and no unit is sold two
// times. It is the exact opposite of the behavior of the package of exercise 1.
func TestFiftyConcurrentRequestsOnTwentyUnits(t *testing.T) {
    s, d := service(t, 20)

    var wg sync.WaitGroup
    successes := make(chan struct{}, 50)
    contentions := make(chan struct{}, 50)
    for i := 0; i < 50; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            switch _, err := s.Reserve(context.Background(), "CIM50", 1); {
            case err == nil:
                successes <- struct{}{}
            case errors.Is(err, ErrContention):
                contentions <- struct{}{}
            }
        }()
    }
    wg.Wait()
    close(successes)
    close(contentions)

    if n := len(contentions); n != 0 {
        t.Errorf("%d refusals for contention: the retry bound is too low", n)
    }
    if n := len(successes); n != 20 {
        t.Errorf("%d successful reservations, want 20", n)
    }
    final, err := d.Read(context.Background(), "CIM50")
    if err != nil {
        t.Fatal(err)
    }
    if final.Stock() != 0 {
        t.Errorf("final stock = %d, want 0", final.Stock())
    }
    t.Logf("swaps refused by the compare-and-swap: %d", d.failures)
}
```

Le second test est celui qui justifie tout le reste : cinquante demandes
concurrentes sur vingt unités donnent **exactement vingt** réservations et un
stock final de zéro, sous `-race`. C'est l'inverse exact du comportement du
paquet de l'exercice 1, qui finissait à `-1`.

Et regarde le détail dans le faux dépôt :

```go
// In a database, the window between reading and swapping is a network
// round trip. In memory it is almost zero, so the test would never see
// the contention it claims to exercise. We widen it explicitly.
runtime.Gosched()
```

Sans cette ligne, le test passe en zéro conflit : les goroutines s'enchaînent
trop vite pour se croiser, et le test ne prouve rien. Avec elle, le compteur
affiche une quarantaine d'échanges refusés, et le résultat reste exact.

> Un test de concurrence qui passe sans jamais provoquer de conflit ne teste
> rien. Si tu n'as pas vu le mécanisme de défense se déclencher, tu ne sais pas
> s'il existe.

## Contrainte 6 — le couplage que je garde

**`display` dépend de `article` par signature, degré 1, et je ne le découple
pas.** Les quatre critères :

- **Même demandeur ?** Oui. Celui qui décide qu'un article en rupture s'affiche
  avec une mention est le même qui décide qu'un article a un stock.
- **Même rythme ?** Oui. Les deux bougent quand l'offre change.
- **L'un a-t-il un sens sans l'autre ?** Non. « Afficher un prix » sans savoir
  de quoi, ce n'est rien.
- **Quelqu'un voudra-t-il remplacer `article` ?** Non. Personne n'a deux
  implémentations d'« article ».

Quatre fois la bonne réponse. L'interface `Affichable` que la leçon 1.2 mal
digérée suggérerait ici coûterait un fichier, une indirection et une
traduction, à chaque changement, pour un droit dont personne n'usera.

**Le second couplage que je garde, et qui est plus discutable :** `catalog`
dépend de `price`. Ici je prends un pari assumé — si un jour le prix dépend du
client, de l'heure ou du canal de vente, `price.Grid` ne suffira plus et
`catalog` devra recevoir un calculateur en paramètre. Ce jour-là, le
changement coûtera une interface et trois lignes. C'est un prix raisonnable
pour ne pas le payer aujourd'hui.

> Garder un couplage n'est pas le subir. C'est l'avoir examiné, chiffré le coût
> du jour où on aura tort, et décidé que c'était moins cher que de payer tout
> de suite.

## Contrainte 7 — les hypothèses muettes supprimées

| Hypothèse de l'exercice 1 | Ce qui l'a remplacée |
|---|---|
| « quelqu'un a appelé `Load` avant moi » | `Repo` est un champ : sans lui, le service ne se construit pas |
| « personne ne modifie l'article que j'ai obtenu » | `Article` est une valeur |
| « tous les articles ont la même devise » | `Formatter.Currency`, un champ par formateur |
| « le fichier de remises est en place » | `price.NewGrid` rend une erreur, lue par le point d'entrée |
| « la grille n'a pas changé entre nos deux lectures » | la grille est immuable |
| « tout le monde construit les clés du cache pareil » | il n'y a plus de clé partagée |
| « celui qui m'appelle connaît le format de mes clés » | `InvalidateCache` n'existe plus |
| « `Show` ne touche pas à mon article » | `Price` ne touche à rien |
| « l'appel dont j'ignore le résultat ne sert à rien » | toute fonction est soit une commande, soit une requête |
| « je suis le seul à détenir ce panier » | plus de pointeur en paramètre : `Reserve` rend une `Line` |
| « le stock que je lis est encore à jour quand j'écris » | le compare-and-swap le vérifie |
| « `*` n'est pas un code article » | `Grid.fallback`, un champ, dans un autre domaine de valeurs |

Douze hypothèses muettes, douze paramètres, champs ou types explicites. Il en
reste une, et une seule :

> `Repo.Replace` est atomique.

C'est la seule hypothèse de tout le système, elle est écrite dans le
commentaire de l'interface, et c'est à l'implémentation de la tenir — un
`UPDATE articles SET stock = $nouveau WHERE code = $code AND stock = $ancien`.

> Un bon système n'a pas zéro hypothèse. Il en a **une**, elle est écrite, et
> on sait qui la tient.

## À retenir

1. Trois modules sur quatre ne détiennent aucun état. C'est le résultat
   normal d'une bonne découpe, pas une prouesse.
2. Un constructeur qui reçoit une `map` ou une *slice* la copie. Sinon son type
   n'est pas une valeur, c'est un alias.
3. Préfère une exigence de zéro à une liste d'interdits : la liste est toujours
   incomplète.
4. ⚫ = champs non exportés, aucun *setter*, récepteur valeur. Le consommateur
   ne peut pas modifier parce qu'il ne détient qu'une copie.
5. L'immuabilité rend possible le compare-and-swap : on ne peut pas comparer à
   un état qu'on a écrasé.
6. Une propriété de conception non testée est une propriété qu'on perdra — par
   optimisation bien intentionnée.
7. Une frontière se dessine en choisissant la **question** du consommateur, pas
   ses types.
8. Borne tes réessais, et nomme l'erreur qui en sort. Non borné =
   indisponibilité ; borné trop court = refus.
9. Un test de concurrence qui ne provoque jamais de conflit ne teste rien.
10. Garder un couplage, c'est l'avoir examiné et chiffré le coût du jour où on
    aura tort.
11. Un bon système n'a pas zéro hypothèse : il en a une, écrite, et dont on
    sait qui la tient.
