# Correction — Exercice 1.3 / 2 (code)

## Ce qui était demandé

Réécrire le paquet `catalogue`, avec sept contraintes. Les six premières sont
mécaniques. La septième — *nomme un couplage que tu as délibérément gardé* —
est celle qui sépare quelqu'un qui a compris la leçon 1.3 de quelqu'un qui a
seulement compris la 1.2.

## La découpe

| Module | Raison de changer | Dépendances internes | Détient un état ? |
|---|---|---|---|
| `prix` | la règle de remise | **aucune** | non |
| `article` | ce qu'est un article vendable, et le prélèvement de stock | **aucune** | non |
| `affichage` | la présentation d'un prix | `article` | non |
| `catalogue` | l'ordre des étapes et la politique de réessai | `article`, `prix` | **oui, et il est seul** |

Quatre modules, et le tableau dit l'essentiel : **trois d'entre eux ne
détiennent rien.** Ce sont des règles et des valeurs. Un seul détient l'état,
et c'est celui dont le nom dit qu'il tient un catalogue.

## Contrainte 1 et 2 — la règle, sans rien, et le test qui le prouve

```go
// Package prix porte la regle de remise.
//
// Raison de changer : la facon dont une remise s'applique a un prix.
//
// Aucune dependance interne, aucun etat de paquet, aucune horloge. La grille
// est une valeur qu'on lui donne, pas un fichier qu'il va lire.
package prix

import "errors"

var (
    ErrPourcentage = errors.New("prix : pourcentage hors de [0, 100]")
    ErrPrixNegatif = errors.New("prix : prix hors taxe negatif")
)

// Grille est la table des remises, en pourcentage, par code article.
//
// C'est une valeur immuable : NewGrille copie la map qu'on lui donne, pour
// que l'appelant ne puisse pas modifier la grille apres coup. C'est la lecon
// 1.1 appliquee a un parametre de construction.
type Grille struct {
    parCode map[string]int64
    defaut  int64
}

func NewGrille(defaut int64, parCode map[string]int64) (Grille, error) {
    if defaut < 0 || defaut > 100 {
        return Grille{}, ErrPourcentage
    }
    copie := make(map[string]int64, len(parCode))
    for code, pct := range parCode {
        if pct < 0 || pct > 100 {
            return Grille{}, ErrPourcentage
        }
        copie[code] = pct
    }
    return Grille{parCode: copie, defaut: defaut}, nil
}

// Pourcentage rend la remise applicable a un code.
func (g Grille) Pourcentage(code string) int64 {
    if pct, ok := g.parCode[code]; ok {
        return pct
    }
    return g.defaut
}

// Remise applique la remise au prix hors taxe.
//
// L'arrondi est au moins favorable au vendeur, et c'est une decision
// explicite : la division entiere tronque, donc le client paie le centime
// inferieur. Si la comptabilite veut l'inverse, elle change cette ligne et
// elle sait ou la trouver.
func (g Grille) Remise(code string, prixHT int64) (int64, error) {
    if prixHT < 0 {
        return 0, ErrPrixNegatif
    }
    return prixHT - prixHT*g.Pourcentage(code)/100, nil
}
```

Le point à ne pas manquer est dans `NewGrille` :

```go
copie := make(map[string]int64, len(parCode))
for code, pct := range parCode {
```

La grille **recopie** la `map` qu'on lui donne. Sans cette copie, `Grille` ne
serait pas une valeur : ce serait un alias vers la `map` de l'appelant, qui
pourrait la modifier après coup. C'est un couplage de degré 5, et c'est
exactement la leçon 1.1 appliquée à un paramètre de construction.

```go
package prix

import (
    "errors"
    "testing"
)

func TestRemise(t *testing.T) {
    g, err := NewGrille(5, map[string]int64{"PROMO": 20, "PLEIN": 0})
    if err != nil {
        t.Fatal(err)
    }

    cas := []struct {
        nom  string
        code string
        ht   int64
        want int64
    }{
        {"remise par code", "PROMO", 10000, 8000},
        {"remise nulle explicite", "PLEIN", 10000, 10000},
        {"remise par defaut", "INCONNU", 10000, 9500},
        {"arrondi : tronque en faveur du client", "PROMO", 333, 267},
        {"zero", "PROMO", 0, 0},
    }
    for _, c := range cas {
        t.Run(c.nom, func(t *testing.T) {
            got, err := g.Remise(c.code, c.ht)
            if err != nil {
                t.Fatal(err)
            }
            if got != c.want {
                t.Errorf("Remise(%q, %d) = %d, attendu %d", c.code, c.ht, got, c.want)
            }
        })
    }
}

// La grille recopie la map : modifier la map d'origine apres construction ne
// change pas la grille. Sans cette copie, la grille serait un couplage par
// identite — degre 5.
func TestLaGrilleNEstPasAliasee(t *testing.T) {
    source := map[string]int64{"PROMO": 20}
    g, err := NewGrille(0, source)
    if err != nil {
        t.Fatal(err)
    }

    source["PROMO"] = 90
    delete(source, "PROMO")
    source["AUTRE"] = 50

    if got := g.Pourcentage("PROMO"); got != 20 {
        t.Errorf("la grille a suivi la map d'origine : %d", got)
    }
    if got := g.Pourcentage("AUTRE"); got != 0 {
        t.Errorf("la grille a recupere une entree ajoutee apres coup : %d", got)
    }
}

func TestPourcentageInvalideEstRefuse(t *testing.T) {
    if _, err := NewGrille(101, nil); !errors.Is(err, ErrPourcentage) {
        t.Errorf("defaut hors bornes : err = %v", err)
    }
    if _, err := NewGrille(0, map[string]int64{"X": -1}); !errors.Is(err, ErrPourcentage) {
        t.Errorf("entree hors bornes : err = %v", err)
    }
}
```

`TestLaGrilleNEstPasAliasee` est le test que personne n'écrit. Il ne vérifie
aucune règle métier : il vérifie qu'une valeur est bien une valeur. Modifie la
`map` source après la construction, et la grille ne doit pas bouger.

### Le test de structure

```go
// Package garde ne contient que des tests de structure.
package garde

import (
    "os/exec"
    "strings"
    "testing"
)

// Contrainte 2 de l'enonce : le module qui porte le calcul n'a aucune
// dependance interne.
//
// Le test ne nomme pas les paquets interdits un par un : il exige qu'il n'y
// en ait aucun. C'est une regle plus forte et plus simple a tenir.
func TestPrixNaAucuneDependanceInterne(t *testing.T) {
    const module = "exemple/boutique"

    out, err := exec.Command("go", "list", "-deps", module+"/prix").Output()
    if err != nil {
        t.Fatalf("go list : %v", err)
    }

    for _, dep := range strings.Split(strings.TrimSpace(string(out)), "\n") {
        dep = strings.TrimSpace(dep)
        if dep == module+"/prix" || !strings.HasPrefix(dep, module+"/") {
            continue
        }
        t.Errorf("prix depend de %q : la regle a cesse d'etre une regle", dep)
    }
}
```

Note la différence avec le test équivalent de la correction 1.2 / 2 : celui-là
listait les paquets interdits, celui-ci n'en liste aucun. Il exige qu'il n'y
en ait **aucun** du module.

> Une liste d'interdits est toujours incomplète : il faut l'étendre à chaque
> nouvelle tentation. Une exigence de zéro n'a pas ce défaut.

C'est une règle générale des garde-fous : chaque fois que tu peux remplacer
une liste noire par une liste blanche vide, fais-le.

## Contrainte 3 — un consommateur ne peut pas modifier le stock

```go
// Package article porte l'article du catalogue et la regle de prelevement de
// stock.
//
// Raison de changer : ce qu'est un article vendable et ce qui autorise un
// prelevement.
//
// Un consommateur ne peut pas modifier le stock d'un article : les champs
// sont non exportes et Reserver rend une nouvelle valeur. Ce n'est pas une
// convention, c'est une absence de moyen.
package article

import "errors"

type Code string

// Article est une valeur, pas un objet.
type Article struct {
    code   Code
    prixHT int64
    stock  int
}

var (
    ErrCodeVide      = errors.New("article : code vide")
    ErrPrixNegatif   = errors.New("article : prix hors taxe negatif")
    ErrStockNegatif  = errors.New("article : stock negatif")
    ErrQuantite      = errors.New("article : quantite non strictement positive")
    ErrStockInsuffis = errors.New("article : stock insuffisant")
)

func New(code Code, prixHT int64, stock int) (Article, error) {
    switch {
    case code == "":
        return Article{}, ErrCodeVide
    case prixHT < 0:
        return Article{}, ErrPrixNegatif
    case stock < 0:
        return Article{}, ErrStockNegatif
    }
    return Article{code: code, prixHT: prixHT, stock: stock}, nil
}

func (a Article) Code() Code      { return a.code }
func (a Article) PrixHT() int64   { return a.prixHT }
func (a Article) Stock() int      { return a.stock }
func (a Article) EnRupture() bool { return a.stock == 0 }

// Reserver rend un nouvel Article dont le stock est decremente.
//
// L'original n'est pas touche. Il n'y a donc pas de version « apres » qui
// ecrase la version « avant » dans le dos de quelqu'un, et la valeur rendue
// peut etre comparee a celle lue : c'est ce qui rend possible un
// compare-and-swap chez l'appelant.
func (a Article) Reserver(n int) (Article, error) {
    if n <= 0 {
        return a, ErrQuantite
    }
    if n > a.stock {
        return a, ErrStockInsuffis
    }
    a.stock -= n
    return a, nil
}
```

**Le mécanisme : ⚫, l'absence de moyen.** Les champs sont non exportés, il n'y
a aucun *setter*, et `Reserver` est une méthode **à récepteur valeur** qui rend
un nouvel `Article`.

Un consommateur ne peut donc pas modifier le stock d'un article. Pas parce
qu'on le lui a interdit : parce qu'il n'y a rien à modifier — il détient une
copie, et le type ne lui offre aucun chemin.

Trois conséquences qui vont plus loin que la contrainte :

- **Aucune méthode ne peut mentir sur ce qu'elle touche.** Un récepteur valeur
  ne peut rien faire fuir.
- **La valeur rendue est comparable à la valeur lue.** C'est ce qui rend
  possible le compare-and-swap de `catalogue` — et ce n'était pas dans
  l'énoncé, c'est un bénéfice qu'on découvre après.
- **Un article à stock négatif n'est pas représentable**, parce que `New` est
  le seul constructeur et qu'il refuse.

```go
package article

import (
    "errors"
    "testing"
)

// Le test central de ce module : reserver ne modifie pas l'article d'origine.
//
// Il verifie une propriete de conception, pas un comportement metier. Si
// quelqu'un passe un jour Reserver en methode a pointeur « pour eviter une
// copie », ce test echoue — et c'est tout son interet.
func TestReserverNeModifiePasLOriginal(t *testing.T) {
    a, err := New("CIM50", 6500, 10)
    if err != nil {
        t.Fatal(err)
    }

    b, err := a.Reserver(3)
    if err != nil {
        t.Fatal(err)
    }

    if a.Stock() != 10 {
        t.Errorf("stock de l'original = %d, attendu 10", a.Stock())
    }
    if b.Stock() != 7 {
        t.Errorf("stock du resultat = %d, attendu 7", b.Stock())
    }
}

func TestReserverRefuse(t *testing.T) {
    a, _ := New("CIM50", 6500, 2)

    if _, err := a.Reserver(3); !errors.Is(err, ErrStockInsuffis) {
        t.Errorf("quantite > stock : err = %v", err)
    }
    if _, err := a.Reserver(0); !errors.Is(err, ErrQuantite) {
        t.Errorf("quantite nulle : err = %v", err)
    }
    if _, err := a.Reserver(-1); !errors.Is(err, ErrQuantite) {
        t.Errorf("quantite negative : err = %v", err)
    }
}

// Un article a stock negatif n'est pas representable.
func TestConstructeurRefuseLesEtatsImpossibles(t *testing.T) {
    if _, err := New("", 100, 1); !errors.Is(err, ErrCodeVide) {
        t.Errorf("code vide : err = %v", err)
    }
    if _, err := New("X", 100, -1); !errors.Is(err, ErrStockNegatif) {
        t.Errorf("stock negatif : err = %v", err)
    }
}
```

Le premier test est le cœur du module, et il mérite d'être lu deux fois :

```go
func TestReserverNeModifiePasLOriginal(t *testing.T)
```

Il ne vérifie pas une règle métier. Il vérifie une **propriété de
conception**. Et son vrai intérêt est dans l'avenir : le jour où quelqu'un
passera `Reserver` en méthode à pointeur « pour éviter une copie », ce test
échouera, et la revue portera sur la bonne question.

> Une propriété de conception qu'on n'a pas testée est une propriété qu'on
> perdra. Pas par malveillance : par optimisation bien intentionnée.

## Contrainte 4 — ni rendre ni modifier

```go
// Package affichage met en forme un prix pour un humain.
//
// Raison de changer : la facon dont un prix se presente — devise, separateur,
// mention de rupture. Demandeur : le marketing et l'equipe produit.
//
// Il recoit un montant deja calcule : il ne connait ni la grille de remises,
// ni la TVA. La question qu'il pose est « combien et dans quel etat », pas
// « comment l'as-tu obtenu ».
package affichage

import (
    "fmt"
    "strings"

    "exemple/boutique/article"
)

type Formateur struct {
    Devise     string
    Separateur string
}

// Prix ne rend qu'une chaine. Il ne modifie rien, et surtout pas l'article
// qu'on lui passe — c'est la contrainte 4 de l'enonce.
func (f Formateur) Prix(a article.Article, montant int64) string {
    s := f.grouper(montant) + " " + f.Devise
    if a.EnRupture() {
        s += " (rupture)"
    }
    return s
}

func (f Formateur) grouper(n int64) string {
    sep := f.Separateur
    if sep == "" {
        return fmt.Sprintf("%d", n)
    }
    signe := ""
    if n < 0 {
        signe, n = "-", -n
    }
    chiffres := fmt.Sprintf("%d", n)
    var b strings.Builder
    for i, c := range chiffres {
        if i > 0 && (len(chiffres)-i)%3 == 0 {
            b.WriteString(sep)
        }
        b.WriteRune(c)
    }
    return signe + b.String()
}
```

`Prix` rend une chaîne et ne touche à rien. Et il reçoit le **montant déjà
calculé** au lieu de la grille de remises.

Cette seconde décision est plus importante qu'elle n'y paraît. `affichage`
pourrait recevoir la `Grille` et faire le calcul lui-même — ce serait plus
pratique à l'appel. Mais alors la présentation dépendrait de la règle de
remise, et deux demandeurs qui n'ont rien à voir — le marketing et le
commerce — se retrouveraient dans le même module.

> La question qu'`affichage` pose est « combien, et dans quel état ». Pas
> « comment l'as-tu obtenu ». Une frontière se dessine en choisissant la
> question, pas en choisissant les types.

## Contrainte 5 — les dépendances sont déclarées

Il ne reste **aucune** variable de paquet. Le relevé :

| Avant | Après |
|---|---|
| `var Devise = "XAF"` | `affichage.Formateur{Devise: ...}`, un champ |
| `var Remises` + `init()` | `prix.Grille`, construite par l'appelant |
| `var Index` | l'état est derrière `catalogue.Depot` |
| `var cache sync.Map` | supprimé — voir plus bas |
| `init()` lisant un fichier | supprimé : c'est au point d'entrée de lire la configuration et de construire la grille |

Le cache a disparu, et ce n'est pas un oubli. Il était la cause de trois des
treize couplages de l'exercice 1 : l'espace de clés partagé, l'invalidation
par motif, et la composition non atomique du `Load`/`Store`.

S'il faut un cache — et sur un catalogue, il en faudra un —, il se place
**derrière `Depot`**, comme un décorateur, dans le module qui possède cet état.
C'est la proposition de la correction 1.2 / 3, et le raisonnement est le même.

## L'orchestrateur, et le compare-and-swap

```go
// Package catalogue tient l'etat du stock et orchestre un prelevement.
//
// Raison de changer : l'ordre des etapes d'une reservation et la politique de
// reessai en cas de contention.
//
// C'est le seul module des quatre qui detient un etat. Les trois autres sont
// des regles et des valeurs.
package catalogue

import (
    "context"
    "errors"
    "fmt"

    "exemple/boutique/article"
    "exemple/boutique/prix"
)

// Depot est declare ici, cote consommateur.
//
// Remplacer est un compare-and-swap : il n'ecrit que si la valeur en place
// est encore celle qu'on a lue. C'est la seule hypothese dont depend la
// correction de ce module en concurrence, et c'est exactement le mecanisme
// de la correction 1.1 / 5.
type Depot interface {
    Lire(ctx context.Context, code article.Code) (article.Article, error)
    Remplacer(ctx context.Context, avant, apres article.Article) (echange bool, err error)
}

var ErrContention = errors.New("catalogue : trop de contention sur l'article")

// essais borne le reessai.
//
// Une boucle non bornee transforme une contention en indisponibilite ; une
// borne trop basse transforme une contention en refus. La borne doit depasser
// le nombre d'ecritures concurrentes reussies qu'on accepte de servir sur un
// meme article : au-dela, on prefere refuser explicitement plutot que de
// boucler.
const essais = 32

type Service struct {
    Depot  Depot
    Grille prix.Grille
}

// Ligne est ce qu'une reservation produit : de quoi remplir un panier.
type Ligne struct {
    Code     article.Code
    Quantite int
    Montant  int64
}

// Reserver preleve n unites et rend la ligne correspondante.
//
// Rien n'est modifie en place : on lit une valeur, on en calcule une
// nouvelle, et on demande au depot de substituer l'une a l'autre. Si
// quelqu'un est passe entre-temps, l'echange echoue et on recommence sur la
// valeur a jour.
func (s *Service) Reserver(ctx context.Context, code article.Code, n int) (Ligne, error) {
    for tentative := 0; tentative < essais; tentative++ {
        avant, err := s.Depot.Lire(ctx, code)
        if err != nil {
            return Ligne{}, fmt.Errorf("catalogue : lecture %q : %w", code, err)
        }

        apres, err := avant.Reserver(n)
        if err != nil {
            return Ligne{}, err
        }

        echange, err := s.Depot.Remplacer(ctx, avant, apres)
        if err != nil {
            return Ligne{}, fmt.Errorf("catalogue : echange %q : %w", code, err)
        }
        if !echange {
            continue
        }

        montant, err := s.Grille.Remise(string(code), apres.PrixHT())
        if err != nil {
            return Ligne{}, err
        }
        return Ligne{Code: code, Quantite: n, Montant: montant * int64(n)}, nil
    }
    return Ligne{}, fmt.Errorf("%w : %q", ErrContention, code)
}
```

Le cycle `Lire` → calculer → `Remplacer` est le même que celui de la
correction 1.1 / 5 : l'écriture ne réussit que si la valeur en place est
encore celle qu'on a lue.

Et il n'est possible que grâce à la contrainte 3. Comme `article.Reserver` rend
une **nouvelle** valeur sans toucher à l'ancienne, on détient les deux, donc on
peut demander au dépôt de substituer l'une à l'autre. Avec un `*Article` muté
en place, il n'y a plus d'« avant » à comparer : on l'a écrasé.

> L'immuabilité n'est pas une élégance : c'est ce qui rend possible un
> compare-and-swap. On ne peut pas comparer à un état qu'on a détruit.

### La borne de réessai

```go
const essais = 32
```

Une boucle non bornée transforme une contention en indisponibilité : sous
charge, tout le monde boucle et personne n'avance. Une borne trop basse
transforme une contention en refus, et le client voit une erreur alors que
l'article était disponible.

La borne doit donc dépasser le nombre d'écritures concurrentes réussies qu'on
accepte de servir sur un même article. Et surtout, dans les deux cas, **le
comportement est explicite et nommé** : `ErrContention` est une réponse, pas
un symptôme.

```go
package catalogue

import (
    "context"
    "errors"
    "runtime"
    "sync"
    "testing"

    "exemple/boutique/article"
    "exemple/boutique/prix"
)

// depotMemoire implemente le compare-and-swap avec un verrou. En base, c'est
// un UPDATE ... WHERE stock = $ancien.
type depotMemoire struct {
    mu       sync.Mutex
    articles map[article.Code]article.Article
    echecs   int
}

func (d *depotMemoire) Lire(_ context.Context, code article.Code) (article.Article, error) {
    d.mu.Lock()
    a, ok := d.articles[code]
    d.mu.Unlock()
    if !ok {
        return article.Article{}, errors.New("inconnu")
    }

    // En base, la fenetre entre la lecture et l'echange est un aller-retour
    // reseau. En memoire elle est quasi nulle, donc le test ne verrait jamais
    // la contention qu'il pretend exercer. On l'elargit explicitement.
    runtime.Gosched()
    return a, nil
}

func (d *depotMemoire) Remplacer(_ context.Context, avant, apres article.Article) (bool, error) {
    d.mu.Lock()
    defer d.mu.Unlock()
    if d.articles[avant.Code()] != avant {
        d.echecs++
        return false, nil
    }
    d.articles[apres.Code()] = apres
    return true, nil
}

func service(t *testing.T, stock int) (*Service, *depotMemoire) {
    t.Helper()
    a, err := article.New("CIM50", 6500, stock)
    if err != nil {
        t.Fatal(err)
    }
    g, err := prix.NewGrille(0, map[string]int64{"CIM50": 10})
    if err != nil {
        t.Fatal(err)
    }
    d := &depotMemoire{articles: map[article.Code]article.Article{"CIM50": a}}
    return &Service{Depot: d, Grille: g}, d
}

func TestReserverCalculeLaLigne(t *testing.T) {
    s, _ := service(t, 10)
    l, err := s.Reserver(context.Background(), "CIM50", 2)
    if err != nil {
        t.Fatal(err)
    }
    if l.Montant != 11700 { // (6500 - 10 %) x 2
        t.Errorf("montant = %d, attendu 11700", l.Montant)
    }
}

// Le test qui justifie le compare-and-swap. A lancer avec -race.
//
// Cinquante demandes concurrentes sur vingt unites : exactement vingt
// reussissent, le stock final est zero, et aucune unite n'est vendue deux
// fois. C'est l'inverse exact du comportement du paquet de l'exercice 1.
func TestCinquanteDemandesConcurrentesSurVingtUnites(t *testing.T) {
    s, d := service(t, 20)

    var wg sync.WaitGroup
    reussites := make(chan struct{}, 50)
    contentions := make(chan struct{}, 50)
    for i := 0; i < 50; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            switch _, err := s.Reserver(context.Background(), "CIM50", 1); {
            case err == nil:
                reussites <- struct{}{}
            case errors.Is(err, ErrContention):
                contentions <- struct{}{}
            }
        }()
    }
    wg.Wait()
    close(reussites)
    close(contentions)

    if n := len(contentions); n != 0 {
        t.Errorf("%d refus pour contention : la borne de reessai est trop basse", n)
    }
    if n := len(reussites); n != 20 {
        t.Errorf("%d reservations reussies, attendu 20", n)
    }
    final, err := d.Lire(context.Background(), "CIM50")
    if err != nil {
        t.Fatal(err)
    }
    if final.Stock() != 0 {
        t.Errorf("stock final = %d, attendu 0", final.Stock())
    }
    t.Logf("echanges refuses par le compare-and-swap : %d", d.echecs)
}
```

Le second test est celui qui justifie tout le reste : cinquante demandes
concurrentes sur vingt unités donnent **exactement vingt** réservations et un
stock final de zéro, sous `-race`. C'est l'inverse exact du comportement du
paquet de l'exercice 1, qui finissait à `-1`.

Et regarde le détail dans le faux dépôt :

```go
// En base, la fenetre entre la lecture et l'echange est un aller-retour
// reseau. En memoire elle est quasi nulle, donc le test ne verrait jamais
// la contention qu'il pretend exercer. On l'elargit explicitement.
runtime.Gosched()
```

Sans cette ligne, le test passe en zéro conflit : les goroutines s'enchaînent
trop vite pour se croiser, et le test ne prouve rien. Avec elle, le compteur
affiche une quarantaine d'échanges refusés, et le résultat reste exact.

> Un test de concurrence qui passe sans jamais provoquer de conflit ne teste
> rien. Si tu n'as pas vu le mécanisme de défense se déclencher, tu ne sais pas
> s'il existe.

## Contrainte 6 — le couplage que je garde

**`affichage` dépend de `article` par signature, degré 1, et je ne le découple
pas.** Les quatre critères :

- **Même demandeur ?** Oui. Celui qui décide qu'un article en rupture s'affiche
  avec une mention est le même qui décide qu'un article a un stock.
- **Même rythme ?** Oui. Les deux bougent quand l'offre change.
- **L'un a-t-il un sens sans l'autre ?** Non. « Afficher un prix » sans savoir
  de quoi, ce n'est rien.
- **Quelqu'un voudra-t-il remplacer `article` ?** Non. Personne n'a deux
  implémentations d'« article ».

Quatre fois la bonne réponse. L'interface `Affichable` que la leçon 1.2 mal
digérée suggérerait ici coûterait un fichier, une indirection et une
traduction, à chaque changement, pour un droit dont personne n'usera.

**Le second couplage que je garde, et qui est plus discutable :** `catalogue`
dépend de `prix`. Ici je prends un pari assumé — si un jour le prix dépend du
client, de l'heure ou du canal de vente, `prix.Grille` ne suffira plus et
`catalogue` devra recevoir un calculateur en paramètre. Ce jour-là, le
changement coûtera une interface et trois lignes. C'est un prix raisonnable
pour ne pas le payer aujourd'hui.

> Garder un couplage n'est pas le subir. C'est l'avoir examiné, chiffré le coût
> du jour où on aura tort, et décidé que c'était moins cher que de payer tout
> de suite.

## Contrainte 7 — les hypothèses muettes supprimées

| Hypothèse de l'exercice 1 | Ce qui l'a remplacée |
|---|---|
| « quelqu'un a appelé `Charger` avant moi » | `Depot` est un champ : sans lui, le service ne se construit pas |
| « personne ne modifie l'article que j'ai obtenu » | `Article` est une valeur |
| « tous les articles ont la même devise » | `Formateur.Devise`, un champ par formateur |
| « le fichier de remises est en place » | `prix.NewGrille` rend une erreur, lue par le point d'entrée |
| « la grille n'a pas changé entre nos deux lectures » | la grille est immuable |
| « tout le monde construit les clés du cache pareil » | il n'y a plus de clé partagée |
| « celui qui m'appelle connaît le format de mes clés » | `InvaliderCache` n'existe plus |
| « `Afficher` ne touche pas à mon article » | `Prix` ne touche à rien |
| « l'appel dont j'ignore le résultat ne sert à rien » | toute fonction est soit une commande, soit une requête |
| « je suis le seul à détenir ce panier » | plus de pointeur en paramètre : `Reserver` rend une `Ligne` |
| « le stock que je lis est encore à jour quand j'écris » | le compare-and-swap le vérifie |
| « `*` n'est pas un code article » | `Grille.defaut`, un champ, dans un autre domaine de valeurs |

Douze hypothèses muettes, douze paramètres, champs ou types explicites. Il en
reste une, et une seule :

> `Depot.Remplacer` est atomique.

C'est la seule hypothèse de tout le système, elle est écrite dans le
commentaire de l'interface, et c'est à l'implémentation de la tenir — un
`UPDATE articles SET stock = $nouveau WHERE code = $code AND stock = $ancien`.

> Un bon système n'a pas zéro hypothèse. Il en a **une**, elle est écrite, et
> on sait qui la tient.

## À retenir

1. Trois modules sur quatre ne détiennent aucun état. C'est le résultat
   normal d'une bonne découpe, pas une prouesse.
2. Un constructeur qui reçoit une `map` ou une *slice* la copie. Sinon son type
   n'est pas une valeur, c'est un alias.
3. Préfère une exigence de zéro à une liste d'interdits : la liste est toujours
   incomplète.
4. ⚫ = champs non exportés, aucun *setter*, récepteur valeur. Le consommateur
   ne peut pas modifier parce qu'il ne détient qu'une copie.
5. L'immuabilité rend possible le compare-and-swap : on ne peut pas comparer à
   un état qu'on a écrasé.
6. Une propriété de conception non testée est une propriété qu'on perdra — par
   optimisation bien intentionnée.
7. Une frontière se dessine en choisissant la **question** du consommateur, pas
   ses types.
8. Borne tes réessais, et nomme l'erreur qui en sort. Non borné =
   indisponibilité ; borné trop court = refus.
9. Un test de concurrence qui ne provoque jamais de conflit ne teste rien.
10. Garder un couplage, c'est l'avoir examiné et chiffré le coût du jour où on
    aura tort.
11. Un bon système n'a pas zéro hypothèse : il en a une, écrite, et dont on
    sait qui la tient.
