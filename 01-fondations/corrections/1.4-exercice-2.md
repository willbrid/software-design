# Correction — Exercice 1.4 / 2 (code)

## Ce qui était demandé

Réécrire le contrat de la file et le consommateur, avec sept contraintes. La
cinquième est le cœur de l'exercice :

> L'une des deux implémentations est délibérément **hostile** : elle duplique
> les messages, les réordonne, et en livre un deux fois sur trois. Le
> consommateur doit passer le même test de contrat avec elle. Si ce n'est pas
> le cas, ce n'est pas l'implémentation qui est fautive.

Cette dernière phrase est la leçon. Dupliquer une livraison est **conforme**
à « au moins une fois ». Un consommateur qui n'y survit pas est en tort, et
l'implémentation hostile est l'outil qui l'établit.

## Contrainte 1 — le contrat énonce ses garanties

```go
// Package file porte le vocabulaire de la messagerie et le contrat.
//
// Raison de changer : les garanties de livraison qu'on accepte d'offrir.
//
// Le contrat est ici, avec les erreurs et les verdicts. Aucune
// implementation n'exporte quoi que ce soit que l'appelant doive connaitre.
package file

import (
    "context"
    "errors"
    "fmt"
)

type (
    Sujet string
    // ID est l'identite du message, fournie par le producteur. Elle est la
    // cle d'idempotence : le consommateur s'en sert pour savoir s'il a deja
    // traite ce message. Le producteur seul sait si deux messages identiques
    // sont un rejeu ou deux evenements.
    ID string
)

type Message struct {
    ID    ID
    Sujet Sujet
    Corps []byte
    // Essais est le nombre de livraisons deja tentees, celle-ci comprise.
    // Il est expose parce que le traitement peut legitimement vouloir en
    // dependre : abandonner plus tot, journaliser differemment, alerter.
    Essais int
}

// Verdict est ce que le traitement rend a la file. Il remplace un simple
// error, dont la signification etait ambigue : « j'ai echoue » ne dit pas
// s'il faut reessayer.
type Verdict int

const (
    // Traite : ne plus livrer.
    Traite Verdict = iota
    // AReessayer : livrer a nouveau lors d'un tour ulterieur.
    AReessayer
    // Rejete : ne plus livrer, mettre au rebut. C'est le verdict des messages
    // qu'aucun nombre de tentatives ne sauvera.
    Rejete
)

func (v Verdict) String() string {
    switch v {
    case Traite:
        return "traite"
    case AReessayer:
        return "a-reessayer"
    case Rejete:
        return "rejete"
    }
    return fmt.Sprintf("verdict(%d)", int(v))
}

// Traitement rend un verdict et, facultativement, l'erreur qui l'explique.
// Le verdict est l'instruction, l'erreur est la raison : la file obeit au
// premier et journalise la seconde.
type Traitement func(ctx context.Context, m Message) (Verdict, error)

var (
    ErrSansIdentite  = errors.New("file : message sans identite")
    ErrSujetVide     = errors.New("file : sujet vide")
    ErrCorpsTropGros = errors.New("file : corps au-dela de la taille maximale")
    ErrConflit       = errors.New("file : identite deja utilisee pour un autre corps")
    ErrLot           = errors.New("file : taille de lot invalide")
    ErrLimites       = errors.New("file : limites invalides")
)

// Limites fait partie du contrat. Les champs sont exportes sans danger : ce
// sont des scalaires, donc une copie est une copie.
type Limites struct {
    TailleMaxCorps int
    MaxEssais      int
}

func NewLimites(tailleMaxCorps, maxEssais int) (Limites, error) {
    if tailleMaxCorps <= 0 || maxEssais <= 0 {
        return Limites{}, fmt.Errorf("%w : %d octets, %d essais",
            ErrLimites, tailleMaxCorps, maxEssais)
    }
    return Limites{TailleMaxCorps: tailleMaxCorps, MaxEssais: maxEssais}, nil
}

// File est le contrat.
//
// Ce qu'il ne dit pas : le transport, le format de stockage, la facon dont
// les messages sont retenus entre deux tours, le nombre de processus qui
// consomment.
//
// Ce qu'il dit, parce que ca ne se cache pas :
//
//   - Publier est idempotent sur l'ID. Publier deux fois le meme ID avec le
//     meme corps ne cree qu'un message ; avec un corps different, c'est
//     ErrConflit.
//   - La livraison est AU MOINS UNE FOIS. Un message peut etre livre
//     plusieurs fois, y compris plusieurs fois dans un meme tour. Le
//     traitement doit donc etre idempotent — ce n'est pas une
//     recommandation, c'est une obligation du contrat.
//   - AUCUN ORDRE n'est garanti, ni entre messages, ni entre livraisons d'un
//     meme message.
//   - Un message dont le verdict est Traite ou Rejete n'est plus livre lors
//     des tours SUIVANTS. Une livraison deja en cours ne peut pas etre
//     rappelee.
//   - Apres MaxEssais livraisons sans verdict Traite, le message part au
//     rebut. Le rebut est consultable, et c'est a un humain de le regarder.
//   - Traiter rend la main : c'est l'appelant qui decide de la cadence et du
//     parallelisme. La file ne possede aucune goroutine.
type File interface {
    Publier(ctx context.Context, m Message) error
    Traiter(ctx context.Context, s Sujet, lot int, h Traitement) (livres int, err error)
    Rebutes(ctx context.Context, s Sujet) ([]Message, error)
    Limites() Limites
}

// Valider est le controle commun a toutes les implementations. Il vit ici
// pour que deux implementations ne puissent pas refuser des messages
// differents.
func Valider(m Message, l Limites) error {
    switch {
    case m.ID == "":
        return ErrSansIdentite
    case m.Sujet == "":
        return ErrSujetVide
    case len(m.Corps) > l.TailleMaxCorps:
        return fmt.Errorf("%w : %d > %d", ErrCorpsTropGros, len(m.Corps), l.TailleMaxCorps)
    }
    return nil
}
```

Trois décisions à relever.

### `ID` est fournie par le producteur

```go
// ID est l'identite du message, fournie par le producteur. Elle est la
// cle d'idempotence [...] Le producteur seul sait si deux messages
// identiques sont un rejeu ou deux evenements.
```

C'est la correction 1.1 / 5, mot pour mot, dans un autre domaine. Sans cette
ligne, la contrainte 2 est impossible à satisfaire — et c'était précisément
l'absence relevée à la question 1 de l'exercice 1.

### `Verdict` remplace `error`

```go
type Traitement func(ctx context.Context, m Message) (Verdict, error)
```

Trois verdicts : `Traite`, `AReessayer`, `Rejete`. Le verdict est
l'**instruction**, l'erreur est la **raison**. La file obéit au premier et
journalise la seconde.

Les six significations ambiguës de la question 3 de l'exercice 1 se réduisent
à trois choix explicites. Et surtout, il n'existe plus de chemin où l'on rend
une erreur sans dire quoi faire du message.

> Quand une valeur de retour doit répondre à deux questions, ajoute une valeur
> de retour. C'est moins cher qu'une convention.

### `Essais` est exposé

Ce n'est pas un détail d'implémentation qui fuit : c'est une exposition
délibérée, et la leçon donne le critère — *expose ce dont l'appelant a besoin
pour tenir ses propres garanties*. Un traitement peut légitimement vouloir
abandonner plus tôt, journaliser différemment au cinquième essai, ou alerter.

### Et `Valider` vit dans le contrat

```go
func Valider(m Message, l Limites) error
```

Pas dans les implémentations. Sans ça, deux implémentations pourraient refuser
des messages différents — et le test de contrat ne l'attraperait pas, parce
qu'il ne verrait qu'une des deux à la fois.

> Ce qui doit être identique dans toutes les implémentations ne doit être
> écrit qu'une fois, et pas dans une implémentation.

### Le choix de `Traiter` plutôt que `Consommer`

```go
Traiter(ctx context.Context, s Sujet, lot int, h Traitement) (livres int, err error)
```

L'énoncé partait d'un `Consommer(sujet, h)` qui ne rend jamais la main. J'ai
choisi l'inverse : la file traite un lot puis rend la main, et **c'est
l'appelant qui boucle**.

Pourquoi : un `Consommer` bloquant oblige l'implémentation à posséder une
goroutine, un cycle de vie, une politique d'arrêt, et une stratégie d'attente.
Ce sont quatre promesses supplémentaires, et c'étaient quatre des douze
absences du relevé de l'exercice 1.

> Rendre la main est la promesse la plus facile à tenir. Chaque fois qu'une
> abstraction peut laisser la cadence à son appelant, elle doit le faire : la
> boucle est une décision, et une décision appartient à qui peut l'arbitrer.

C'est la même idée que le `Tour` de la boîte d'envoi de la correction 1.3 / 4.

## Contrainte 2 — le consommateur survit aux doublons et au désordre

```go
// Package confirmation envoie le SMS de confirmation d'une reservation.
//
// Raison de changer : le texte du message et la politique de reessai.
//
// Il est ecrit pour une livraison AU MOINS UNE FOIS et sans ordre, parce que
// c'est ce que le contrat de la file promet. Son idempotence n'est pas une
// precaution : c'est une obligation contractuelle.
package confirmation

import (
    "context"
    "encoding/json"
    "errors"
    "log/slog"

    "exemple/messagerie/file"
)

// ErrCharge est exportee parce qu'elle peut se retrouver dans le rebut : qui
// regarde le rebut doit pouvoir la reconnaitre.
var ErrCharge = errors.New("confirmation : charge incomplete")

// Etat est ce que le depot observe pour un message, AVANT la tentative de
// reservation.
type Etat int

const (
    Libre Etat = iota
    EnCours
    Termine
)

// Depot est l'etat durable qui porte l'idempotence. C'est lui, et pas la
// file, qui sait ce qui a deja ete fait — parce que « deja envoye » est un
// fait metier, pas un fait de transport.
type Depot interface {
    // Reserver tente de prendre l'exclusivite du traitement et rend l'etat
    // observe avant la tentative. Si l'etat rendu est Libre, l'appelant
    // detient desormais la reservation.
    Reserver(ctx context.Context, id file.ID) (Etat, error)
    Terminer(ctx context.Context, id file.ID) error
    Liberer(ctx context.Context, id file.ID) error
}

type Expediteur interface {
    Envoyer(ctx context.Context, numero, texte string) error
}

// Charge est le corps du message. C'est un format de transport, donc un
// contrat : on n'y retire jamais un champ, on en ajoute des facultatifs.
type Charge struct {
    Reservation string `json:"reservation"`
    Telephone   string `json:"telephone"`
    Place       string `json:"place"`
}

type Traiteur struct {
    Depot Depot
    SMS   Expediteur
    Log   *slog.Logger
}

// Traiter est le traitement passe a file.Traiter.
//
// Chaque sortie rend un verdict explicite. Il n'y a aucun chemin ou l'on rend
// une erreur sans dire quoi faire du message : c'est tout l'interet d'avoir
// remplace `error` par un Verdict.
func (t *Traiteur) Traiter(ctx context.Context, m file.Message) (file.Verdict, error) {
    var c Charge
    if err := json.Unmarshal(m.Corps, &c); err != nil {
        // Un corps illisible ne le deviendra jamais lisible : le rejeter est
        // la seule conduite honnete. Il part au rebut, ou un humain le verra.
        // Le `return nil` de l'enonce le faisait disparaitre.
        return file.Rejete, err
    }
    if c.Telephone == "" || c.Place == "" {
        return file.Rejete, ErrCharge
    }

    etat, err := t.Depot.Reserver(ctx, m.ID)
    if err != nil {
        return file.AReessayer, err
    }
    switch etat {
    case Termine:
        // Le doublon normal d'une livraison au moins une fois.
        return file.Traite, nil
    case EnCours:
        // Un autre traitement le tient. On ne double pas le travail, et on ne
        // declare pas « fait » quelque chose qu'on n'a pas constate : s'il
        // echoue, le message doit survivre.
        return file.AReessayer, nil
    }

    texte := "Votre place " + c.Place + " est confirmee."
    if err := t.SMS.Envoyer(ctx, c.Telephone, texte); err != nil {
        if err := t.Depot.Liberer(ctx, m.ID); err != nil {
            // Residu connu : une reservation non liberee bloque le message
            // jusqu'a l'expiration du bail. Le depot doit donc en avoir un —
            // une reservation sans echeance est un verrou definitif.
            t.Log.Error("liberation", "message", m.ID, "err", err)
        }
        return file.AReessayer, err
    }

    if err := t.Depot.Terminer(ctx, m.ID); err != nil {
        // Le SMS est parti mais la trace n'est pas ecrite : le message sera
        // relivre et le client recevra un second SMS. Au moins une fois,
        // jamais zero — pour une confirmation, c'est le bon sens de l'erreur.
        t.Log.Error("marquage", "message", m.ID, "err", err)
        return file.AReessayer, err
    }
    return file.Traite, nil
}
```

### Où vit l'état qui le permet

Pas dans la file. Dans un **dépôt**, celui du consommateur.

```go
type Depot interface {
    Reserver(ctx context.Context, id file.ID) (Etat, error)
    Terminer(ctx context.Context, id file.ID) error
    Liberer(ctx context.Context, id file.ID) error
}
```

Et le commentaire dit pourquoi :

> « deja envoye » est un fait métier, pas un fait de transport.

C'est la réponse à une tentation très courante : demander au courtier de
garantir « exactement une fois ». Aucun ne le fait réellement, et même s'il le
faisait, ce ne serait pas la bonne place — ce que le système doit éviter, ce
n'est pas une double livraison, c'est un **double SMS**. Le seul endroit où
l'on sait si un SMS est parti, c'est chez celui qui l'envoie.

### Les trois états, et pourquoi deux ne suffisent pas

```go
switch etat {
case Termine:
    return file.Traite, nil
case EnCours:
    return file.AReessayer, nil
}
```

Un booléen « déjà traité ? » ne suffit pas, et c'est l'erreur qu'on fait
d'abord. Il faut distinguer :

- **`Termine`** — c'est fait. Le doublon normal d'une livraison au moins une
  fois. Verdict : `Traite`, sans rien refaire.
- **`EnCours`** — un autre traitement le tient. On ne double pas le travail, et
  on ne déclare surtout pas « fait » quelque chose qu'on n'a pas constaté : si
  l'autre échoue, le message doit survivre. Verdict : `AReessayer`.

Rendre `Traite` pour un `EnCours` est le bug subtil de cet exercice. Il perd
le message exactement quand le traitement concurrent échoue — donc au pire
moment, et seulement sous charge.

> Ne déclare jamais « fait » un travail que tu n'as pas fait et dont tu n'as
> pas constaté l'achèvement. L'optimisme sur l'état d'autrui est la source la
> plus régulière des pertes silencieuses.

### Et le désordre ?

Il est sans effet ici, et il faut dire pourquoi plutôt que de s'en féliciter :
**l'opération est commutative.** Envoyer la confirmation du message A puis
celle de B donne le même résultat que l'inverse.

> La bonne réponse à « sois correct dans le désordre » est presque toujours de
> rendre l'opération **indépendante de l'ordre**, pas de rétablir l'ordre.
> Rétablir l'ordre coûte un point de sérialisation ; s'en passer coûte une
> réflexion.

Résidu honnête : le jour où un message « annulation » suivra un message
« confirmation », l'ordre comptera, et aucune astuce d'idempotence ne
suffira. Il faudra un numéro de version dans la charge, et le consommateur
devra ignorer tout message plus vieux que l'état qu'il détient. C'est une
autre machinerie, et c'est le sujet du niveau 7.

## Contrainte 3 — aucune erreur d'implémentation ne traverse

Toutes les erreurs que l'appelant peut tester sont dans `package file` :
`ErrSansIdentite`, `ErrSujetVide`, `ErrCorpsTropGros`, `ErrConflit`, `ErrLot`.
Plus `ErrCharge` dans `confirmation`, exportée **parce qu'elle peut se
retrouver dans le rebut** — et qui regarde le rebut doit pouvoir la
reconnaître.

Aucune erreur Redis, AMQP, `os` ou `sql` ne franchit la frontière. C'est la
traduction de trois lignes de la leçon, appliquée partout.

## Contrainte 4 — le contrat sous forme de test partagé

```go
// Package filetest est le contrat, sous forme executable.
//
// Il n'affirme QUE ce que le contrat promet. C'est une discipline plus dure
// qu'il n'y parait : la tentation permanente est de verifier qu'un message
// est livre « une fois », parce que c'est ce que fait l'implementation
// honnete. Ce serait tester une coincidence.
package filetest

import (
    "bytes"
    "context"
    "errors"
    "testing"

    "exemple/messagerie/file"
)

const sujet = file.Sujet("confirmations")

// Verifier execute le contrat. `nouvelle` doit rendre une file vide dont les
// limites sont (TailleMaxCorps: 32, MaxEssais: 3).
func Verifier(t *testing.T, nouvelle func(t *testing.T) file.File) {
    t.Helper()

    cas := []struct {
        nom string
        f   func(*testing.T, file.File)
    }{
        {"aller-retour", allerRetour},
        {"idempotence du producteur", idempotenceProducteur},
        {"meme identite, autre corps", conflit},
        {"message refuse avant publication", refus},
        {"un message traite n'est plus livre", plusLivre},
        {"un message a reessayer est relivre", relivre},
        {"le rebut apres MaxEssais", rebutApresEssais},
        {"un rejet part au rebut tout de suite", rejetImmediat},
        {"lot invalide", lotInvalide},
        {"contexte annule", annule},
    }
    for _, c := range cas {
        t.Run(c.nom, func(t *testing.T) { c.f(t, nouvelle(t)) })
    }
}

func publier(t *testing.T, f file.File, id file.ID, corps string) {
    t.Helper()
    m := file.Message{ID: id, Sujet: sujet, Corps: []byte(corps)}
    if err := f.Publier(context.Background(), m); err != nil {
        t.Fatalf("Publier(%q) : %v", id, err)
    }
}

// tour execute un tour et rend les messages vus, dans l'ordre ou ils sont
// arrives. Le verdict est le meme pour tous.
func tour(t *testing.T, f file.File, v file.Verdict) []file.Message {
    t.Helper()
    var vus []file.Message
    _, err := f.Traiter(context.Background(), sujet, 10,
        func(_ context.Context, m file.Message) (file.Verdict, error) {
            vus = append(vus, m)
            return v, nil
        })
    if err != nil {
        t.Fatalf("Traiter : %v", err)
    }
    return vus
}

func identites(msgs []file.Message) map[file.ID]int {
    n := map[file.ID]int{}
    for _, m := range msgs {
        n[m.ID]++
    }
    return n
}

func allerRetour(t *testing.T, f file.File) {
    publier(t, f, "c-1", "place 12A")

    vus := tour(t, f, file.Traite)

    // « Au moins une fois » : on verifie au moins, jamais exactement.
    n := identites(vus)
    if n["c-1"] < 1 {
        t.Fatal("le message n'a pas ete livre")
    }
    if len(n) != 1 {
        t.Fatalf("des messages inattendus ont ete livres : %v", n)
    }
    for _, m := range vus {
        if !bytes.Equal(m.Corps, []byte("place 12A")) {
            t.Errorf("corps = %q, attendu %q", m.Corps, "place 12A")
        }
        if m.Sujet != sujet {
            t.Errorf("sujet = %q", m.Sujet)
        }
        if m.Essais < 1 {
            t.Errorf("Essais = %d, attendu au moins 1", m.Essais)
        }
    }
}

func idempotenceProducteur(t *testing.T, f file.File) {
    publier(t, f, "c-1", "identique")
    publier(t, f, "c-1", "identique")

    if n := identites(tour(t, f, file.Traite)); len(n) != 1 {
        t.Fatalf("deux publications du meme ID ont cree %d message(s) distinct(s)", len(n))
    }
}

func conflit(t *testing.T, f file.File) {
    publier(t, f, "c-1", "premier")

    m := file.Message{ID: "c-1", Sujet: sujet, Corps: []byte("second")}
    if err := f.Publier(context.Background(), m); !errors.Is(err, file.ErrConflit) {
        t.Fatalf("err = %v, attendu file.ErrConflit", err)
    }
}

func refus(t *testing.T, f file.File) {
    l := f.Limites()
    trop := file.Message{ID: "c-1", Sujet: sujet, Corps: bytes.Repeat([]byte("x"), l.TailleMaxCorps+1)}
    if err := f.Publier(context.Background(), trop); !errors.Is(err, file.ErrCorpsTropGros) {
        t.Errorf("corps trop gros : err = %v", err)
    }

    sansID := file.Message{Sujet: sujet, Corps: []byte("x")}
    if err := f.Publier(context.Background(), sansID); !errors.Is(err, file.ErrSansIdentite) {
        t.Errorf("sans identite : err = %v", err)
    }

    // Un message refuse n'est pas publie : rien ne doit etre livre.
    if vus := tour(t, f, file.Traite); len(vus) != 0 {
        t.Errorf("%d message(s) livre(s) alors que tout a ete refuse", len(vus))
    }
}

func plusLivre(t *testing.T, f file.File) {
    publier(t, f, "c-1", "x")

    if n := identites(tour(t, f, file.Traite)); n["c-1"] < 1 {
        t.Fatal("premier tour : rien livre")
    }
    // La promesse porte sur les tours SUIVANTS : une livraison deja en cours
    // ne peut pas etre rappelee, et le contrat ne pretend pas le contraire.
    if vus := tour(t, f, file.Traite); len(vus) != 0 {
        t.Fatalf("second tour : %d livraison(s) apres un verdict Traite", len(vus))
    }
}

func relivre(t *testing.T, f file.File) {
    publier(t, f, "c-1", "x")

    if n := identites(tour(t, f, file.AReessayer)); n["c-1"] < 1 {
        t.Fatal("premier tour : rien livre")
    }
    if n := identites(tour(t, f, file.AReessayer)); n["c-1"] < 1 {
        t.Fatal("second tour : un message a reessayer doit etre relivre")
    }
}

func rebutApresEssais(t *testing.T, f file.File) {
    max := f.Limites().MaxEssais
    publier(t, f, "c-1", "x")

    for i := 0; i < max; i++ {
        if n := identites(tour(t, f, file.AReessayer)); n["c-1"] < 1 {
            t.Fatalf("tour %d : rien livre avant d'avoir atteint MaxEssais", i+1)
        }
    }

    if vus := tour(t, f, file.AReessayer); len(vus) != 0 {
        t.Errorf("%d livraison(s) apres MaxEssais = %d", len(vus), max)
    }

    rebutes, err := f.Rebutes(context.Background(), sujet)
    if err != nil {
        t.Fatal(err)
    }
    if len(rebutes) != 1 || rebutes[0].ID != "c-1" {
        t.Errorf("rebut = %v, attendu le seul message", rebutes)
    }
}

func rejetImmediat(t *testing.T, f file.File) {
    publier(t, f, "c-1", "x")

    if n := identites(tour(t, f, file.Rejete)); n["c-1"] < 1 {
        t.Fatal("premier tour : rien livre")
    }
    if vus := tour(t, f, file.Rejete); len(vus) != 0 {
        t.Errorf("%d livraison(s) apres un rejet", len(vus))
    }

    rebutes, err := f.Rebutes(context.Background(), sujet)
    if err != nil {
        t.Fatal(err)
    }
    if len(rebutes) != 1 {
        t.Errorf("rebut = %v, attendu un message", rebutes)
    }
}

func lotInvalide(t *testing.T, f file.File) {
    _, err := f.Traiter(context.Background(), sujet, 0,
        func(context.Context, file.Message) (file.Verdict, error) { return file.Traite, nil })
    if !errors.Is(err, file.ErrLot) {
        t.Fatalf("err = %v, attendu file.ErrLot", err)
    }
}

func annule(t *testing.T, f file.File) {
    ctx, annuler := context.WithCancel(context.Background())
    annuler()

    m := file.Message{ID: "c-1", Sujet: sujet, Corps: []byte("x")}
    if err := f.Publier(ctx, m); !errors.Is(err, context.Canceled) {
        t.Errorf("Publier : err = %v", err)
    }

    var livre bool
    if _, err := f.Traiter(ctx, sujet, 10, func(context.Context, file.Message) (file.Verdict, error) {
        livre = true
        return file.Traite, nil
    }); !errors.Is(err, context.Canceled) {
        t.Errorf("Traiter : err = %v", err)
    }
    if livre {
        t.Error("un message a ete livre sur un contexte annule")
    }
}
```

### La discipline la plus dure de l'exercice

Regarde `allerRetour` :

```go
// « Au moins une fois » : on verifie au moins, jamais exactement.
n := identites(vus)
if n["c-1"] < 1 {
    t.Fatal("le message n'a pas ete livre")
}
```

La tentation permanente est d'écrire `if n["c-1"] != 1`. C'est ce que fait
l'implémentation honnête, et le test passerait. Il échouerait avec
l'implémentation hostile.

Et là est le point :

> Si ton test de contrat échoue sur une implémentation conforme, ce n'est pas
> l'implémentation qui est fautive : c'est ton test qui affirme plus que ton
> contrat ne promet. **Le test de contrat est aussi un test de l'honnêteté du
> contrat.**

C'est la propriété qui fait toute la valeur de l'exercice. Sans la seconde
implémentation, rien ne t'empêche d'écrire un contrat qui dit « au moins une
fois » et un test qui vérifie « exactement une fois » — et de construire un
consommateur fragile en croyant l'avoir prouvé robuste.

### La promesse qu'il faut affaiblir, et le dire

```go
// La promesse porte sur les tours SUIVANTS : une livraison deja en cours
// ne peut pas etre rappelee, et le contrat ne pretend pas le contraire.
```

On voudrait écrire « un message traité n'est plus jamais livré ». C'est
intenable : au moment où le verdict est rendu, une autre livraison du même
message peut déjà être en vol. Donc le contrat promet moins, explicitement.

> Une promesse que l'implémentation ne peut pas tenir n'est pas une promesse
> ambitieuse, c'est un mensonge. Écris celle que tu peux tenir, et dis à
> l'appelant ce qu'il doit faire du reste — ici : être idempotent.

## Contrainte 5 — l'implémentation hostile

```go
// Package filehostile enveloppe n'importe quelle file et se comporte aussi
// mal que le contrat l'autorise.
//
// Elle ne triche pas : livrer un message plusieurs fois, y compris dans le
// meme tour, est explicitement permis par « au moins une fois ». Son role est
// de rendre cette permission visible, et de la faire payer tout de suite a
// celui qui aurait ecrit un consommateur non idempotent.
//
// C'est un decorateur de dix-huit lignes utiles, et il remplace une equipe de
// test.
package filehostile

import (
    "context"
    "math/rand"

    "exemple/messagerie/file"
)

type File struct {
    dessous file.File
    alea    *rand.Rand
    max     int
}

// Autour enveloppe une file. Chaque livraison est repetee de 1 a max fois.
func Autour(dessous file.File, graine int64, max int) *File {
    if max < 1 {
        max = 1
    }
    return &File{dessous: dessous, alea: rand.New(rand.NewSource(graine)), max: max}
}

func (f *File) Limites() file.Limites { return f.dessous.Limites() }

func (f *File) Publier(ctx context.Context, m file.Message) error {
    return f.dessous.Publier(ctx, m)
}

func (f *File) Rebutes(ctx context.Context, s file.Sujet) ([]file.Message, error) {
    return f.dessous.Rebutes(ctx, s)
}

func (f *File) Traiter(ctx context.Context, s file.Sujet, lot int, h file.Traitement) (int, error) {
    return f.dessous.Traiter(ctx, s, lot, func(ctx context.Context, m file.Message) (file.Verdict, error) {
        repetitions := 1 + f.alea.Intn(f.max)

        // Les livraisons supplementaires precedent celle dont on rendra le
        // verdict : c'est le cas reel d'un message redelivre avant que
        // l'accuse de reception du precedent soit arrive.
        for i := 1; i < repetitions; i++ {
            if _, err := h(ctx, m); err != nil {
                _ = err // le verdict des livraisons en doublon est ignore
            }
        }
        return h(ctx, m)
    })
}
```

Dix-huit lignes utiles, et un décorateur : il enveloppe **n'importe quelle**
file.

```go
return f.dessous.Traiter(ctx, s, lot, func(ctx context.Context, m file.Message) (file.Verdict, error) {
    repetitions := 1 + f.alea.Intn(f.max)

    for i := 1; i < repetitions; i++ {
        if _, err := h(ctx, m); err != nil {
            _ = err
        }
    }
    return h(ctx, m)
})
```

Les livraisons supplémentaires **précèdent** celle dont on rendra le verdict :
c'est le cas réel d'un message redélivré avant que l'accusé de réception du
précédent soit arrivé.

Et il passe le même contrat :

```go

    "exemple/messagerie/filemem"

)

// La file hostile passe le MEME contrat que la file honnete.
//
// C'est la demonstration : dupliquer les livraisons est conforme, donc tout
// consommateur correct doit y survivre. Si ce test echouait, ce ne serait pas
// l'implementation qui serait fautive — ce serait le contrat qui promettrait
// plus qu'il ne peut tenir.
func TestContrat(t *testing.T) {

        l, err := file.NewLimites(32, 3)
```

### Combien de doublons, réellement

Un test instrumenté sur cinq messages publiés :

```
5 messages distincts, 12 livraisons au traitement, detail map[a:1 b:3 c:3 d:3 e:2]
```

Douze livraisons pour cinq messages. Le mécanisme est exercé, ce n'est pas une
hostilité de façade — même leçon que le `runtime.Gosched()` de la correction
1.3 / 2.

### Le détail de l'implémentation honnête qui compte

```go
// Package filemem est l'implementation en memoire.
//
// Elle melange volontairement l'ordre de livraison : le contrat ne garantit
// aucun ordre, donc l'implementation prend acte et rend cet ordre visiblement
// arbitraire. C'est le meme choix que Go pour l'iteration des map — il
// empeche quiconque de prendre l'habitude d'un ordre qui ne lui a jamais ete
// promis.
package filemem
```

`filemem` **mélange** volontairement l'ordre de livraison.

C'est le même choix que Go pour l'itération des `map`, et pour la même raison :
le contrat ne garantit aucun ordre, donc l'implémentation rend cet ordre
visiblement arbitraire, pour qu'aucun appelant ne prenne l'habitude d'un ordre
qui ne lui a jamais été promis.

> Si ton contrat ne promet pas une propriété, ton implémentation de référence
> doit activement la violer. Sinon la propriété non promise devient une
> propriété acquise, et tu ne pourras plus changer d'implémentation.

Et un second détail, dans `Traiter` :

```go
// h est appele SANS le verrou : un traitement peut etre long, et il
// peut republier. Tenir le verrou pendant l'appel transformerait
// cette file en point de serialisation global.
```

## Contrainte 6 — le message qu'on ne traitera jamais

```go
if err := json.Unmarshal(m.Corps, &c); err != nil {
    return file.Rejete, err
}
```

Verdict `Rejete`, et il part au **rebut** — consultable par `Rebutes`, et c'est
à un humain de le regarder. Le `return nil` de l'énoncé le faisait disparaître.

Le test le vérifie :

```go
func TestUnCorpsIllisiblePartAuRebut(t *testing.T)
```

Et après `MaxEssais` livraisons sans succès, un message part aussi au rebut :
une boucle de réessai non bornée est une indisponibilité, exactement comme à
la correction 1.3 / 2.

> Le rebut est la pièce que personne n'écrit et que tout le monde découvre en
> incident. Un système de messages sans rebut a deux comportements possibles
> face à un message empoisonné : le perdre, ou se bloquer. Les deux sont
> mauvais.

```go
    "context"
    "encoding/json"

const sujet = file.Sujet("confirmations")

type depotMemoire struct {
    mu    sync.Mutex
    etats map[file.ID]confirmation.Etat
}

func nouveauDepot() *depotMemoire {
    return &depotMemoire{etats: map[file.ID]confirmation.Etat{}}
}

func (d *depotMemoire) Reserver(_ context.Context, id file.ID) (confirmation.Etat, error) {
    d.mu.Lock()
    defer d.mu.Unlock()
    avant := d.etats[id]
    if avant == confirmation.Libre {
        d.etats[id] = confirmation.EnCours
    }
    return avant, nil
}

func (d *depotMemoire) Terminer(_ context.Context, id file.ID) error {
    d.mu.Lock()
    defer d.mu.Unlock()
    d.etats[id] = confirmation.Termine
    return nil
}

func (d *depotMemoire) Liberer(_ context.Context, id file.ID) error {
    d.mu.Lock()
    defer d.mu.Unlock()
    d.etats[id] = confirmation.Libre
    return nil
}

type smsCompteur struct {
    mu       sync.Mutex
    envoyes  map[string]int
    casseUne string
}

func (s *smsCompteur) Envoyer(_ context.Context, numero, _ string) error {
    s.mu.Lock()
    defer s.mu.Unlock()
    if numero == s.casseUne {
        s.casseUne = "" // il echoue une seule fois
        return errors.New("operateur injoignable")
    }
    if s.envoyes == nil {
        s.envoyes = map[string]int{}
    }
    s.envoyes[numero]++
    return nil
}

func charge(t *testing.T, reservation, tel, place string) []byte {
    t.Helper()
```

## Contrainte 7 — ce que j'ai refusé, et ce que j'ai accepté à contrecœur

### Refusé : `Longueur`

Pour la raison de l'exercice 1 : Kafka ne peut pas la tenir, SQS ne la rend
qu'approximative. Elle réduirait l'ensemble des implémentations pour servir un
tableau de bord.

Le besoin est réel ; il va dans une interface séparée, déclarée par le module
d'exploitation, et qu'une implémentation a le droit de ne pas satisfaire. Le
compilateur dira alors clairement « ce courtier ne sait pas faire ça », ce qui
est une information utile plutôt qu'une approximation silencieuse.

### Refusé aussi : les délais de réessai

Pas de `AReessayerDans(d time.Duration)`. Ce serait exiger de toute
implémentation une gestion d'échéances par message, que beaucoup n'ont pas. Le
contrat se contente de « lors d'un tour ultérieur », et la cadence appartient à
l'appelant — qui boucle.

### Accepté à contrecœur : `Rebutes`

C'est une quatrième méthode, donc une contrainte de plus sur les
implémentations, et elle expose une notion — le rebut — qui ressemble à un
détail de mécanique.

Je l'ai gardée parce que l'alternative est pire. Sans elle, les messages
rejetés vont quelque part que le contrat ne nomme pas, donc personne ne les
regarde, donc le rebut devient un trou noir avec une interface par
fournisseur.

Son coût est réel : une implémentation sur un courtier dont la file de rebut
est un autre sujet devra la traduire, et une implémentation qui n'a pas de
rebut du tout ne peut pas tenir le contrat.

> Quand tu acceptes une méthode à contrecœur, écris pourquoi dans le
> commentaire. C'est la seule façon pour que le prochain sache si la raison
> tient toujours.

## À retenir

1. Dupliquer une livraison est conforme à « au moins une fois ». Un
   consommateur qui n'y survit pas est en tort, pas l'implémentation.
2. Une implémentation délibérément hostile, en dix-huit lignes de décorateur,
   remplace une équipe de test.
3. Si ton test de contrat échoue sur une implémentation conforme, c'est ton
   test qui promet plus que ton contrat. Le test de contrat teste aussi
   l'honnêteté du contrat.
4. Si ton contrat ne promet pas une propriété, ton implémentation de référence
   doit activement la violer — comme Go mélange l'itération des `map`.
5. Quand une valeur de retour doit répondre à deux questions, ajoute une
   valeur de retour. Le verdict est l'instruction, l'erreur est la raison.
6. L'idempotence vit chez le consommateur, dans un état durable : « déjà
   envoyé » est un fait métier, pas un fait de transport.
7. Trois états, pas deux : `Libre`, `EnCours`, `Termine`. Déclarer « fait » un
   travail en cours chez un autre le perd exactement quand cet autre échoue.
8. La bonne réponse au désordre est de rendre l'opération indépendante de
   l'ordre, pas de rétablir l'ordre.
9. Rendre la main est la promesse la plus facile à tenir. Laisse la cadence à
   l'appelant.
10. Ce qui doit être identique dans toutes les implémentations s'écrit une
    fois, dans le contrat, pas dans une implémentation.
11. Un système de messages sans rebut n'a que deux conduites face à un message
    empoisonné : le perdre ou se bloquer.
12. Écris dans le commentaire pourquoi tu as accepté une méthode à
    contrecœur. C'est ce qui permettra de la retirer un jour.
