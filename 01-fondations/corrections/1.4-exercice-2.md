# Correction — Exercice 1.4 / 2 (code)

## Ce qui était demandé

Réécrire le contrat de la file et le consommateur, avec sept contraintes. La
cinquième est le cœur de l'exercice :

> L'une des deux implémentations est délibérément **hostile** : elle duplique
> les messages, les réordonne, et en livre un deux fois sur trois. Le
> consommateur doit passer le même test de contrat avec elle. Si ce n'est pas
> le cas, ce n'est pas l'implémentation qui est fautive.

Cette dernière phrase est la leçon. Dupliquer une livraison est **conforme**
à « au moins une fois ». Un consommateur qui n'y survit pas est en tort, et
l'implémentation hostile est l'outil qui l'établit.

## Contrainte 1 — le contrat énonce ses garanties

```go
// Package queue holds the messaging vocabulary and the contract.
//
// Reason to change: the delivery guarantees we agree to offer.
//
// The contract is here, with the errors and the verdicts. No
// implementation exports anything the caller must know.
package queue

import (
    "context"
    "errors"
    "fmt"
)

type (
    Subject string
    // ID is the message's identity, provided by the producer. It is the
    // idempotency key: the consumer uses it to know whether it already
    // handled this message. Only the producer knows whether two identical messages
    // are a replay or two events.
    ID string
)

type Message struct {
    ID      ID
    Subject Subject
    Body    []byte
    // Attempts is the number of deliveries already tried, this one included.
    // It is exposed because the handling may legitimately want to
    // depend on it: give up earlier, log differently, alert.
    Attempts int
}

// Verdict is what the handling returns to the queue. It replaces a plain
// error, whose meaning was ambiguous: "I failed" does not say
// whether to retry.
type Verdict int

const (
    // Handled: deliver no more.
    Handled Verdict = iota
    // Retry: deliver again in a later round.
    Retry
    // Rejected: deliver no more, dead-letter it. It is the verdict of messages
    // that no number of attempts will save.
    Rejected
)

func (v Verdict) String() string {
    switch v {
    case Handled:
        return "handled"
    case Retry:
        return "retry"
    case Rejected:
        return "rejected"
    }
    return fmt.Sprintf("verdict(%d)", int(v))
}

// Handling returns a verdict and, optionally, the error that explains it.
// The verdict is the instruction, the error is the reason: the queue obeys the
// first and logs the second.
type Handling func(ctx context.Context, m Message) (Verdict, error)

var (
    ErrNoIdentity   = errors.New("queue: message without identity")
    ErrEmptySubject = errors.New("queue: empty subject")
    ErrBodyTooLarge = errors.New("queue: body over the maximum size")
    ErrConflict     = errors.New("queue: identity already used for another body")
    ErrBatch        = errors.New("queue: invalid batch size")
    ErrLimits       = errors.New("queue: invalid limits")
)

// Limits is part of the contract. The fields are safely exported: they
// are scalars, so a copy is a copy.
type Limits struct {
    MaxBodySize int
    MaxAttempts int
}

func NewLimits(maxBodySize, maxAttempts int) (Limits, error) {
    if maxBodySize <= 0 || maxAttempts <= 0 {
        return Limits{}, fmt.Errorf("%w: %d bytes, %d attempts",
            ErrLimits, maxBodySize, maxAttempts)
    }
    return Limits{MaxBodySize: maxBodySize, MaxAttempts: maxAttempts}, nil
}

// Queue is the contract.
//
// What it does not say: the transport, the storage format, how
// messages are held between two rounds, the number of processes that
// consume.
//
// What it says, because it cannot be hidden:
//
//   - Publish is idempotent on the ID. Publishing the same ID twice with the
//     same body creates only one message; with a different body, it is
//     ErrConflict.
//   - Delivery is AT LEAST ONCE. A message may be delivered
//     several times, including several times in one round. The
//     handling must therefore be idempotent: it is not a
//     recommendation, it is an obligation of the contract.
//   - NO ORDER is guaranteed, neither between messages nor between deliveries of the
//     same message.
//   - A message whose verdict is Handled or Rejected is no longer delivered in
//     in the NEXT rounds. A delivery already in progress cannot be
//     recalled.
//   - After MaxAttempts deliveries without a Handled verdict, the message goes to
//     dead letters. Dead letters can be read, and a human must look at them.
//   - Handle returns: the caller decides the pace and the
//     parallelism. The queue owns no goroutine.
type Queue interface {
    Publish(ctx context.Context, m Message) error
    Handle(ctx context.Context, s Subject, lot int, h Handling) (delivered int, err error)
    DeadLetters(ctx context.Context, s Subject) ([]Message, error)
    Limits() Limits
}

// Validate is the check common to every implementation. It lives here
// so that two implementations cannot refuse
// different.
func Validate(m Message, l Limits) error {
    switch {
    case m.ID == "":
        return ErrNoIdentity
    case m.Subject == "":
        return ErrEmptySubject
    case len(m.Body) > l.MaxBodySize:
        return fmt.Errorf("%w: %d > %d", ErrBodyTooLarge, len(m.Body), l.MaxBodySize)
    }
    return nil
}
```

Trois décisions à relever.

### `ID` est fournie par le producteur

```go
// ID is the message's identity, provided by the producer. It is the
// idempotency key [...] Only the producer knows whether two messages
// that are identical are a replay or two events.
```

C'est la correction 1.1 / 5, mot pour mot, dans un autre domaine. Sans cette
ligne, la contrainte 2 est impossible à satisfaire — et c'était précisément
l'absence relevée à la question 1 de l'exercice 1.

### `Verdict` remplace `error`

```go
type Handling func(ctx context.Context, m Message) (Verdict, error)
```

Trois verdicts : `Handled`, `Retry`, `Rejected`. Le verdict est
l'**instruction**, l'erreur est la **raison**. La file obéit au premier et
journalise la seconde.

Les six significations ambiguës de la question 3 de l'exercice 1 se réduisent
à trois choix explicites. Et surtout, il n'existe plus de chemin où l'on rend
une erreur sans dire quoi faire du message.

> Quand une valeur de retour doit répondre à deux questions, ajoute une valeur
> de retour. C'est moins cher qu'une convention.

### `Attempts` est exposé

Ce n'est pas un détail d'implémentation qui fuit : c'est une exposition
délibérée, et la leçon donne le critère — *expose ce dont l'appelant a besoin
pour tenir ses propres garanties*. Un traitement peut légitimement vouloir
abandonner plus tôt, journaliser différemment au cinquième essai, ou alerter.

### Et `Validate` vit dans le contrat

```go
func Validate(m Message, l Limits) error
```

Pas dans les implémentations. Sans ça, deux implémentations pourraient refuser
des messages différents — et le test de contrat ne l'attraperait pas, parce
qu'il ne verrait qu'une des deux à la fois.

> Ce qui doit être identique dans toutes les implémentations ne doit être
> écrit qu'une fois, et pas dans une implémentation.

### Le choix de `Handle` plutôt que `Consume`

```go
Handle(ctx context.Context, s Subject, lot int, h Handling) (delivered int, err error)
```

L'énoncé partait d'un `Consume(subject, h)` qui ne rend jamais la main. J'ai
choisi l'inverse : la file traite un lot puis rend la main, et **c'est
l'appelant qui boucle**.

Pourquoi : un `Consume` bloquant oblige l'implémentation à posséder une
goroutine, un cycle de vie, une politique d'arrêt, et une stratégie d'attente.
Ce sont quatre promesses supplémentaires, et c'étaient quatre des douze
absences du relevé de l'exercice 1.

> Rendre la main est la promesse la plus facile à tenir. Chaque fois qu'une
> abstraction peut laisser la cadence à son appelant, elle doit le faire : la
> boucle est une décision, et une décision appartient à qui peut l'arbitrer.

C'est la même idée que le `Tour` de la boîte d'envoi de la correction 1.3 / 4.

## Contrainte 2 — le consommateur survit aux doublons et au désordre

```go
// Package confirmation sends the confirmation SMS of a reservation.
//
// Reason to change: the message text and the retry policy.
//
// It is written for AT LEAST ONCE delivery without order, because
// it is what the queue's contract promises. Its idempotence is not a
// precaution: it is a contractual obligation.
package confirmation

import (
    "context"
    "encoding/json"
    "errors"
    "log/slog"

    "example/messaging/queue"
)

// ErrPayload is exported because it can end up in the dead letters: whoever
// looks at dead letters must be able to recognize it.
var ErrPayload = errors.New("confirmation: incomplete payload")

// State is what the repo sees for a message, BEFORE the attempt to
// reservation.
type State int

const (
    Free State = iota
    InFlight
    Done
)

// Repo is the durable state that carries idempotence. It, and not the
// queue, that knows what was already done, because "already sent" is a
// business fact, not a transport fact.
type Repo interface {
    // Reserve tries to take exclusive handling and returns the state
    // seen before the attempt. If the returned state is Free, the caller
    // now holds the reservation.
    Reserve(ctx context.Context, id queue.ID) (State, error)
    Finish(ctx context.Context, id queue.ID) error
    Release(ctx context.Context, id queue.ID) error
}

type Sender interface {
    Send(ctx context.Context, number, text string) error
}

// Payload is the message body. It is a transport format, so a
// contract: we never remove a field, we add optional ones.
type Payload struct {
    Reservation string `json:"reservation"`
    Phone       string `json:"phone"`
    Seat        string `json:"seat"`
}

type Handler struct {
    Repo Repo
    SMS  Sender
    Log  *slog.Logger
}

// Handle is the handling passed to queue.Handle.
//
// Each exit returns an explicit verdict. There is no path that returns
// an error without saying what to do with the message: that is the whole point of
// replaces `error` with a Verdict.
func (t *Handler) Handle(ctx context.Context, m queue.Message) (queue.Verdict, error) {
    var c Payload
    if err := json.Unmarshal(m.Body, &c); err != nil {
        // An unreadable body will never become readable: rejecting it is
        // the only honest course. It goes to dead letters, where a human will see it.
        // The statement's `return nil` made it disappear.
        return queue.Rejected, err
    }
    if c.Phone == "" || c.Seat == "" {
        return queue.Rejected, ErrPayload
    }

    state, err := t.Repo.Reserve(ctx, m.ID)
    if err != nil {
        return queue.Retry, err
    }
    switch state {
    case Done:
        // The normal duplicate of an at-least-once delivery.
        return queue.Handled, nil
    case InFlight:
        // Another handling holds it. We do not double the work, and we do not
        // declare "done" something we have not seen: if it
        // fails, the message must survive.
        return queue.Retry, nil
    }

    text := "Your seat " + c.Seat + " is confirmed."
    if err := t.SMS.Send(ctx, c.Phone, text); err != nil {
        if err := t.Repo.Release(ctx, m.ID); err != nil {
            // Known leftover: an unreleased reservation blocks the message
            // until the lease expires. So the repo must have one:
            // a reservation without a deadline is a permanent lock.
            t.Log.Error("release", "message", m.ID, "err", err)
        }
        return queue.Retry, err
    }

    if err := t.Repo.Finish(ctx, m.ID); err != nil {
        // The SMS left but the trace is not written: the message will be
        // redelivered and the client will get a second SMS. At least once,
        // never zero: for a confirmation, it is the right direction for the error.
        t.Log.Error("marking", "message", m.ID, "err", err)
        return queue.Retry, err
    }
    return queue.Handled, nil
}
```

### Où vit l'état qui le permet

Pas dans la file. Dans un **dépôt**, celui du consommateur.

```go
type Repo interface {
    Reserve(ctx context.Context, id queue.ID) (State, error)
    Finish(ctx context.Context, id queue.ID) error
    Release(ctx context.Context, id queue.ID) error
}
```

Et le commentaire dit pourquoi :

> « deja envoye » est un fait métier, pas un fait de transport.

C'est la réponse à une tentation très courante : demander au courtier de
garantir « exactement une fois ». Aucun ne le fait réellement, et même s'il le
faisait, ce ne serait pas la bonne place — ce que le système doit éviter, ce
n'est pas une double livraison, c'est un **double SMS**. Le seul endroit où
l'on sait si un SMS est parti, c'est chez celui qui l'envoie.

### Les trois états, et pourquoi deux ne suffisent pas

```go
switch state {
case Done:
    return queue.Handled, nil
case InFlight:
    return queue.Retry, nil
}
```

Un booléen « déjà traité ? » ne suffit pas, et c'est l'erreur qu'on fait
d'abord. Il faut distinguer :

- **`Done`** — c'est fait. Le doublon normal d'une livraison au moins une
  fois. Verdict : `Handled`, sans rien refaire.
- **`InFlight`** — un autre traitement le tient. On ne double pas le travail, et
  on ne déclare surtout pas « fait » quelque chose qu'on n'a pas constaté : si
  l'autre échoue, le message doit survivre. Verdict : `Retry`.

Rendre `Handled` pour un `InFlight` est le bug subtil de cet exercice. Il perd
le message exactement quand le traitement concurrent échoue — donc au pire
moment, et seulement sous charge.

> Ne déclare jamais « fait » un travail que tu n'as pas fait et dont tu n'as
> pas constaté l'achèvement. L'optimisme sur l'état d'autrui est la source la
> plus régulière des pertes silencieuses.

### Et le désordre ?

Il est sans effet ici, et il faut dire pourquoi plutôt que de s'en féliciter :
**l'opération est commutative.** Envoyer la confirmation du message A puis
celle de B donne le même résultat que l'inverse.

> La bonne réponse à « sois correct dans le désordre » est presque toujours de
> rendre l'opération **indépendante de l'ordre**, pas de rétablir l'ordre.
> Rétablir l'ordre coûte un point de sérialisation ; s'en passer coûte une
> réflexion.

Résidu honnête : le jour où un message « annulation » suivra un message
« confirmation », l'ordre comptera, et aucune astuce d'idempotence ne
suffira. Il faudra un numéro de version dans la charge, et le consommateur
devra ignorer tout message plus vieux que l'état qu'il détient. C'est une
autre machinerie, et c'est le sujet du niveau 8.

## Contrainte 3 — aucune erreur d'implémentation ne traverse

Toutes les erreurs que l'appelant peut tester sont dans `package queue` :
`ErrNoIdentity`, `ErrEmptySubject`, `ErrBodyTooLarge`, `ErrConflict`, `ErrBatch`.
Plus `ErrPayload` dans `confirmation`, exportée **parce qu'elle peut se
retrouver dans le rebut** — et qui regarde le rebut doit pouvoir la
reconnaître.

Aucune erreur Redis, AMQP, `os` ou `sql` ne franchit la frontière. C'est la
traduction de trois lignes de la leçon, appliquée partout.

## Contrainte 4 — le contrat sous forme de test partagé

```go
// Package queuetest is the contract, in executable form.
//
// It asserts ONLY what the contract promises. It is a harder discipline
// than it looks: the constant temptation is to check that a message
// is delivered "once", because it is what the implementation
// honest one. It would be testing a coincidence.
package queuetest

import (
    "bytes"
    "context"
    "errors"
    "testing"

    "example/messaging/queue"
)

const subject = queue.Subject("confirmations")

// Check runs the contract. `fresh` must return an empty queue whose
// limits are (MaxBodySize: 32, MaxAttempts: 3).
func Check(t *testing.T, fresh func(t *testing.T) queue.Queue) {
    t.Helper()

    cas := []struct {
        name string
        f    func(*testing.T, queue.Queue)
    }{
        {"round-trip", roundTrip},
        {"producer idempotence", producerIdempotence},
        {"same identity, other body", conflict},
        {"message refused before publication", refusals},
        {"a handled message is no longer delivered", noLongerDelivered},
        {"a message to retry is redelivered", redelivered},
        {"dead letter after MaxAttempts", deadAfterAttempts},
        {"a rejection goes to dead letters at once", immediateReject},
        {"invalid batch", badBatch},
        {"canceled context", cancelled},
    }
    for _, c := range cas {
        t.Run(c.name, func(t *testing.T) { c.f(t, fresh(t)) })
    }
}

func publish(t *testing.T, f queue.Queue, id queue.ID, body string) {
    t.Helper()
    m := queue.Message{ID: id, Subject: subject, Body: []byte(body)}
    if err := f.Publish(context.Background(), m); err != nil {
        t.Fatalf("Publish(%q): %v", id, err)
    }
}

// round runs one round and returns the messages seen, in the order they
// arrived. The verdict is the same for all.
func round(t *testing.T, f queue.Queue, v queue.Verdict) []queue.Message {
    t.Helper()
    var vus []queue.Message
    _, err := f.Handle(context.Background(), subject, 10,
        func(_ context.Context, m queue.Message) (queue.Verdict, error) {
            vus = append(vus, m)
            return v, nil
        })
    if err != nil {
        t.Fatalf("Handle: %v", err)
    }
    return vus
}

func identities(msgs []queue.Message) map[queue.ID]int {
    n := map[queue.ID]int{}
    for _, m := range msgs {
        n[m.ID]++
    }
    return n
}

func roundTrip(t *testing.T, f queue.Queue) {
    publish(t, f, "c-1", "seat 12A")

    vus := round(t, f, queue.Handled)

    // "At least once": we check at least, never exactly.
    n := identities(vus)
    if n["c-1"] < 1 {
        t.Fatal("the message was not delivered")
    }
    if len(n) != 1 {
        t.Fatalf("unexpected messages were delivered: %v", n)
    }
    for _, m := range vus {
        if !bytes.Equal(m.Body, []byte("seat 12A")) {
            t.Errorf("body = %q, want %q", m.Body, "seat 12A")
        }
        if m.Subject != subject {
            t.Errorf("subject = %q", m.Subject)
        }
        if m.Attempts < 1 {
            t.Errorf("Attempts = %d, want at least 1", m.Attempts)
        }
    }
}

func producerIdempotence(t *testing.T, f queue.Queue) {
    publish(t, f, "c-1", "identical")
    publish(t, f, "c-1", "identical")

    if n := identities(round(t, f, queue.Handled)); len(n) != 1 {
        t.Fatalf("two publications of the same ID created %d distinct message(s)", len(n))
    }
}

func conflict(t *testing.T, f queue.Queue) {
    publish(t, f, "c-1", "first")

    m := queue.Message{ID: "c-1", Subject: subject, Body: []byte("second")}
    if err := f.Publish(context.Background(), m); !errors.Is(err, queue.ErrConflict) {
        t.Fatalf("err = %v, want queue.ErrConflict", err)
    }
}

func refusals(t *testing.T, f queue.Queue) {
    l := f.Limits()
    tooMuch := queue.Message{ID: "c-1", Subject: subject, Body: bytes.Repeat([]byte("x"), l.MaxBodySize+1)}
    if err := f.Publish(context.Background(), tooMuch); !errors.Is(err, queue.ErrBodyTooLarge) {
        t.Errorf("body too large: err = %v", err)
    }

    noID := queue.Message{Subject: subject, Body: []byte("x")}
    if err := f.Publish(context.Background(), noID); !errors.Is(err, queue.ErrNoIdentity) {
        t.Errorf("without identity: err = %v", err)
    }

    // A refused message is not published: nothing must be delivered.
    if vus := round(t, f, queue.Handled); len(vus) != 0 {
        t.Errorf("%d message(s) delivered although everything was refused", len(vus))
    }
}

func noLongerDelivered(t *testing.T, f queue.Queue) {
    publish(t, f, "c-1", "x")

    if n := identities(round(t, f, queue.Handled)); n["c-1"] < 1 {
        t.Fatal("first round: nothing delivered")
    }
    // The promise is about the NEXT rounds: a delivery already in progress
    // cannot be recalled, and the contract does not pretend otherwise.
    if vus := round(t, f, queue.Handled); len(vus) != 0 {
        t.Fatalf("second round: %d delivery(ies) after a Handled verdict", len(vus))
    }
}

func redelivered(t *testing.T, f queue.Queue) {
    publish(t, f, "c-1", "x")

    if n := identities(round(t, f, queue.Retry)); n["c-1"] < 1 {
        t.Fatal("first round: nothing delivered")
    }
    if n := identities(round(t, f, queue.Retry)); n["c-1"] < 1 {
        t.Fatal("second round: a message to retry must be redelivered")
    }
}

func deadAfterAttempts(t *testing.T, f queue.Queue) {
    max := f.Limits().MaxAttempts
    publish(t, f, "c-1", "x")

    for i := 0; i < max; i++ {
        if n := identities(round(t, f, queue.Retry)); n["c-1"] < 1 {
            t.Fatalf("round %d: nothing delivered before reaching MaxAttempts", i+1)
        }
    }

    if vus := round(t, f, queue.Retry); len(vus) != 0 {
        t.Errorf("%d delivery(ies) after MaxAttempts = %d", len(vus), max)
    }

    dead, err := f.DeadLetters(context.Background(), subject)
    if err != nil {
        t.Fatal(err)
    }
    if len(dead) != 1 || dead[0].ID != "c-1" {
        t.Errorf("dead letters = %v, want the only message", dead)
    }
}

func immediateReject(t *testing.T, f queue.Queue) {
    publish(t, f, "c-1", "x")

    if n := identities(round(t, f, queue.Rejected)); n["c-1"] < 1 {
        t.Fatal("first round: nothing delivered")
    }
    if vus := round(t, f, queue.Rejected); len(vus) != 0 {
        t.Errorf("%d delivery(ies) after a rejection", len(vus))
    }

    dead, err := f.DeadLetters(context.Background(), subject)
    if err != nil {
        t.Fatal(err)
    }
    if len(dead) != 1 {
        t.Errorf("dead letters = %v, want one message", dead)
    }
}

func badBatch(t *testing.T, f queue.Queue) {
    _, err := f.Handle(context.Background(), subject, 0,
        func(context.Context, queue.Message) (queue.Verdict, error) { return queue.Handled, nil })
    if !errors.Is(err, queue.ErrBatch) {
        t.Fatalf("err = %v, want queue.ErrBatch", err)
    }
}

func cancelled(t *testing.T, f queue.Queue) {
    ctx, cancel := context.WithCancel(context.Background())
    cancel()

    m := queue.Message{ID: "c-1", Subject: subject, Body: []byte("x")}
    if err := f.Publish(ctx, m); !errors.Is(err, context.Canceled) {
        t.Errorf("Publish: err = %v", err)
    }

    var delivered bool
    if _, err := f.Handle(ctx, subject, 10, func(context.Context, queue.Message) (queue.Verdict, error) {
        delivered = true
        return queue.Handled, nil
    }); !errors.Is(err, context.Canceled) {
        t.Errorf("Handle: err = %v", err)
    }
    if delivered {
        t.Error("a message was delivered on a canceled context")
    }
}
```

### La discipline la plus dure de l'exercice

Regarde `roundTrip` :

```go
// "At least once": we check at least, never exactly.
n := identities(vus)
if n["c-1"] < 1 {
    t.Fatal("the message was not delivered")
}
```

La tentation permanente est d'écrire `if n["c-1"] != 1`. C'est ce que fait
l'implémentation honnête, et le test passerait. Il échouerait avec
l'implémentation hostile.

Et là est le point :

> Si ton test de contrat échoue sur une implémentation conforme, ce n'est pas
> l'implémentation qui est fautive : c'est ton test qui affirme plus que ton
> contrat ne promet. **Le test de contrat est aussi un test de l'honnêteté du
> contrat.**

C'est la propriété qui fait toute la valeur de l'exercice. Sans la seconde
implémentation, rien ne t'empêche d'écrire un contrat qui dit « au moins une
fois » et un test qui vérifie « exactement une fois » — et de construire un
consommateur fragile en croyant l'avoir prouvé robuste.

### La promesse qu'il faut affaiblir, et le dire

```go
// The promise is about the NEXT rounds: a delivery already in progress
// cannot be recalled, and the contract does not pretend otherwise.
```

On voudrait écrire « un message traité n'est plus jamais livré ». C'est
intenable : au moment où le verdict est rendu, une autre livraison du même
message peut déjà être en vol. Donc le contrat promet moins, explicitement.

> Une promesse que l'implémentation ne peut pas tenir n'est pas une promesse
> ambitieuse, c'est un mensonge. Écris celle que tu peux tenir, et dis à
> l'appelant ce qu'il doit faire du reste — ici : être idempotent.

## Contrainte 5 — l'implémentation hostile

```go
// Package hostilequeue wraps any queue and behaves as
// badly as the contract allows.
//
// It does not cheat: delivering a message several times, including in the
// same round, is explicitly allowed by "at least once". Its role is
// to make this permission visible, and to make the caller pay for it at once,
// whoever would have written a non-idempotent consumer.
//
// It is a decorator of eighteen useful lines, and it replaces a team of
// test.
package hostilequeue

import (
    "context"
    "math/rand"

    "example/messaging/queue"
)

type Queue struct {
    below queue.Queue
    rnd   *rand.Rand
    max   int
}

// Around wraps a queue. Each delivery is repeated 1 to max times.
func Around(below queue.Queue, seed int64, max int) *Queue {
    if max < 1 {
        max = 1
    }
    return &Queue{below: below, rnd: rand.New(rand.NewSource(seed)), max: max}
}

func (f *Queue) Limits() queue.Limits { return f.below.Limits() }

func (f *Queue) Publish(ctx context.Context, m queue.Message) error {
    return f.below.Publish(ctx, m)
}

func (f *Queue) DeadLetters(ctx context.Context, s queue.Subject) ([]queue.Message, error) {
    return f.below.DeadLetters(ctx, s)
}

func (f *Queue) Handle(ctx context.Context, s queue.Subject, lot int, h queue.Handling) (int, error) {
    return f.below.Handle(ctx, s, lot, func(ctx context.Context, m queue.Message) (queue.Verdict, error) {
        repeats := 1 + f.rnd.Intn(f.max)

        // The extra deliveries come before the one whose verdict
        // we will return: it is the real case of a message redelivered before
        // the acknowledgement of the previous one arrived.
        for i := 1; i < repeats; i++ {
            if _, err := h(ctx, m); err != nil {
                _ = err // the verdict of duplicate deliveries is ignored
            }
        }
        return h(ctx, m)
    })
}
```

Dix-huit lignes utiles, et un décorateur : il enveloppe **n'importe quelle**
file.

### Le détail de l'implémentation honnête qui compte

```go
// Package queuemem is the in-memory implementation.
//
// It deliberately shuffles the delivery order: the contract guarantees
// no order, so the implementation takes note and makes that order visibly
// arbitrary. It is the same choice as Go for map iteration: it
// stops anyone from getting used to an order that was never
// promised.
package queuemem
```

`queuemem` **mélange** volontairement l'ordre de livraison.

C'est le même choix que Go pour l'itération des `map`, et pour la même raison :
le contrat ne garantit aucun ordre, donc l'implémentation rend cet ordre
visiblement arbitraire, pour qu'aucun appelant ne prenne l'habitude d'un ordre
qui ne lui a jamais été promis.

> Si ton contrat ne promet pas une propriété, ton implémentation de référence
> doit activement la violer. Sinon la propriété non promise devient une
> propriété acquise, et tu ne pourras plus changer d'implémentation.

Et un second détail, dans `Handle` :

```go
// h is called WITHOUT the lock: a handling can be long, and it
// may republish. Holding the lock during the call would turn
// this queue into a global serialization point.
```

## Contrainte 6 — le message qu'on ne traitera jamais

```go
if err := json.Unmarshal(m.Body, &c); err != nil {
    return queue.Rejected, err
}
```

Verdict `Rejected`, et il part au **rebut** — consultable par `DeadLetters`, et c'est
à un humain de le regarder. Le `return nil` de l'énoncé le faisait disparaître.

Le test le vérifie :

```go

```

Et après `MaxAttempts` livraisons sans succès, un message part aussi au rebut :
une boucle de réessai non bornée est une indisponibilité, exactement comme à
la correction 1.3 / 2.

> Le rebut est la pièce que personne n'écrit et que tout le monde découvre en
> incident. Un système de messages sans rebut a deux comportements possibles
> face à un message empoisonné : le perdre, ou se bloquer. Les deux sont
> mauvais.

package confirmation_test

import (
    "context"
    "encoding/json"
    "errors"
    "io"
    "log/slog"
    "sync"
    "testing"

    "example/messaging/confirmation"
    "example/messaging/hostilequeue"
    "example/messaging/queue"
    "example/messaging/queuemem"
)

const subject = queue.Subject("confirmations")

type memRepo struct {
    mu     sync.Mutex
    states map[queue.ID]confirmation.State
}

func newRepo() *memRepo {
    return &memRepo{states: map[queue.ID]confirmation.State{}}
}

func (d *memRepo) Reserve(_ context.Context, id queue.ID) (confirmation.State, error) {
    d.mu.Lock()
    defer d.mu.Unlock()
    before := d.states[id]
    if before == confirmation.Free {
        d.states[id] = confirmation.InFlight
    }
    return before, nil
}

func (d *memRepo) Finish(_ context.Context, id queue.ID) error {
    d.mu.Lock()
    defer d.mu.Unlock()
    d.states[id] = confirmation.Done
    return nil
}

func (d *memRepo) Release(_ context.Context, id queue.ID) error {
    d.mu.Lock()
    defer d.mu.Unlock()
    d.states[id] = confirmation.Free
    return nil
}

type smsCounter struct {
    mu        sync.Mutex
    sent      map[string]int
    breakOnce string
}

func (s *smsCounter) Send(_ context.Context, number, _ string) error {
    s.mu.Lock()
    defer s.mu.Unlock()
    if number == s.breakOnce {
        s.breakOnce = "" // it fails only once
        return errors.New("operator unreachable")
    }
    if s.sent == nil {
        s.sent = map[string]int{}
    }
    s.sent[number]++
    return nil
}

func payload(t *testing.T, reservation, tel, seat string) []byte {
    t.Helper()
    b, err := json.Marshal(confirmation.Payload{Reservation: reservation, Phone: tel, Seat: seat})
    if err != nil {
        t.Fatal(err)
    }
    return b
}

func drain(t *testing.T, f queue.Queue, h queue.Handling) {
    t.Helper()
    for i := 0; i < 50; i++ {
        n, err := f.Handle(context.Background(), subject, 10, h)
        if err != nil {
            t.Fatal(err)
        }
        if n == 0 {
            return
        }
    }
    t.Fatal("the queue does not drain")
}

// THE test of the exercise: the consumer is correct under a queue that
// duplicates and shuffles, because it is what the contract allows.
func TestOneSMSPerReservationUnderHostileQueue(t *testing.T) {
    l, err := queue.NewLimits(256, 3)
    if err != nil {
        t.Fatal(err)
    }
    f := hostilequeue.Around(queuemem.New(l, 7), 42, 3)

    numbers := []string{"690000001", "690000002", "690000003", "690000004", "690000005"}
    for i, num := range numbers {
        m := queue.Message{
            ID:      queue.ID("c-" + num),
            Subject: subject,
            Body:    payload(t, "R-"+num, num, "12A"),
        }
        if err := f.Publish(context.Background(), m); err != nil {
            t.Fatalf("Publish %d: %v", i, err)
        }
    }

    sms := &smsCounter{}
    tr := &confirmation.Handler{
        Repo: newRepo(),
        SMS:  sms,
        Log:  slog.New(slog.NewTextHandler(io.Discard, nil)),
    }

    drain(t, f, tr.Handle)

    if len(sms.sent) != len(numbers) {
        t.Fatalf("%d recipients, want %d", len(sms.sent), len(numbers))
    }
    for num, n := range sms.sent {
        if n != 1 {
            t.Errorf("%s got %d SMS, want 1", num, n)
        }
    }

    dead, err := f.DeadLetters(context.Background(), subject)
    if err != nil {
        t.Fatal(err)
    }
    if len(dead) != 0 {
        t.Errorf("%d dead-lettered message(s), want 0", len(dead))
    }
}

// A send failure releases the reservation, so the message goes again and succeeds.
func TestASendFailureIsRetried(t *testing.T) {
    l, err := queue.NewLimits(256, 3)
    if err != nil {
        t.Fatal(err)
    }
    f := queuemem.New(l, 1)

    m := queue.Message{ID: "c-1", Subject: subject, Body: payload(t, "R-1", "690000001", "12A")}
    if err := f.Publish(context.Background(), m); err != nil {
        t.Fatal(err)
    }

    sms := &smsCounter{breakOnce: "690000001"}
    tr := &confirmation.Handler{
        Repo: newRepo(),
        SMS:  sms,
        Log:  slog.New(slog.NewTextHandler(io.Discard, nil)),
    }

    drain(t, f, tr.Handle)

    if sms.sent["690000001"] != 1 {
        t.Errorf("%d SMS, want 1 after a failure then a retry", sms.sent["690000001"])
    }
}

// An unreadable body goes to dead letters, and stays there: it does not disappear.
func TestAnUnreadableBodyGoesToDeadLetters(t *testing.T) {
    l, err := queue.NewLimits(256, 3)
    if err != nil {
        t.Fatal(err)
    }
    f := queuemem.New(l, 1)

    if err := f.Publish(context.Background(), queue.Message{
        ID: "c-rotten", Subject: subject, Body: []byte("{this is not json"),
    }); err != nil {
        t.Fatal(err)
    }

    tr := &confirmation.Handler{
        Repo: newRepo(),
        SMS:  &smsCounter{},
        Log:  slog.New(slog.NewTextHandler(io.Discard, nil)),
    }
    drain(t, f, tr.Handle)

    dead, err := f.DeadLetters(context.Background(), subject)
    if err != nil {
        t.Fatal(err)
    }
    if len(dead) != 1 || dead[0].ID != "c-rotten" {
        t.Fatalf("dead letters = %v, want the unreadable message", dead)
    }
}

## Contrainte 7 — ce que j'ai refusé, et ce que j'ai accepté à contrecœur

### Refusé : `Length`

Pour la raison de l'exercice 1 : Kafka ne peut pas la tenir, SQS ne la rend
qu'approximative. Elle réduirait l'ensemble des implémentations pour servir un
tableau de bord.

Le besoin est réel ; il va dans une interface séparée, déclarée par le module
d'exploitation, et qu'une implémentation a le droit de ne pas satisfaire. Le
compilateur dira alors clairement « ce courtier ne sait pas faire ça », ce qui
est une information utile plutôt qu'une approximation silencieuse.

### Refusé aussi : les délais de réessai

Pas de `AReessayerDans(d time.Duration)`. Ce serait exiger de toute
implémentation une gestion d'échéances par message, que beaucoup n'ont pas. Le
contrat se contente de « lors d'un tour ultérieur », et la cadence appartient à
l'appelant — qui boucle.

### Accepté à contrecœur : `DeadLetters`

C'est une quatrième méthode, donc une contrainte de plus sur les
implémentations, et elle expose une notion — le rebut — qui ressemble à un
détail de mécanique.

Je l'ai gardée parce que l'alternative est pire. Sans elle, les messages
rejetés vont quelque part que le contrat ne nomme pas, donc personne ne les
regarde, donc le rebut devient un trou noir avec une interface par
fournisseur.

Son coût est réel : une implémentation sur un courtier dont la file de rebut
est un autre sujet devra la traduire, et une implémentation qui n'a pas de
rebut du tout ne peut pas tenir le contrat.

> Quand tu acceptes une méthode à contrecœur, écris pourquoi dans le
> commentaire. C'est la seule façon pour que le prochain sache si la raison
> tient toujours.

## À retenir

1. Dupliquer une livraison est conforme à « au moins une fois ». Un
   consommateur qui n'y survit pas est en tort, pas l'implémentation.
2. Une implémentation délibérément hostile, en dix-huit lignes de décorateur,
   remplace une équipe de test.
3. Si ton test de contrat échoue sur une implémentation conforme, c'est ton
   test qui promet plus que ton contrat. Le test de contrat teste aussi
   l'honnêteté du contrat.
4. Si ton contrat ne promet pas une propriété, ton implémentation de référence
   doit activement la violer — comme Go mélange l'itération des `map`.
5. Quand une valeur de retour doit répondre à deux questions, ajoute une
   valeur de retour. Le verdict est l'instruction, l'erreur est la raison.
6. L'idempotence vit chez le consommateur, dans un état durable : « déjà
   envoyé » est un fait métier, pas un fait de transport.
7. Trois états, pas deux : `Free`, `InFlight`, `Done`. Déclarer « fait » un
   travail en cours chez un autre le perd exactement quand cet autre échoue.
8. La bonne réponse au désordre est de rendre l'opération indépendante de
   l'ordre, pas de rétablir l'ordre.
9. Rendre la main est la promesse la plus facile à tenir. Laisse la cadence à
   l'appelant.
10. Ce qui doit être identique dans toutes les implémentations s'écrit une
    fois, dans le contrat, pas dans une implémentation.
11. Un système de messages sans rebut n'a que deux conduites face à un message
    empoisonné : le perdre ou se bloquer.
12. Écris dans le commentaire pourquoi tu as accepté une méthode à
    contrecœur. C'est ce qui permettra de la retirer un jour.
