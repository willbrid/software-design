# Correction — Exercice 1.5 / 2 (code)

## Ce qui était demandé

Réécrire `Pay`, avec sept contraintes. Les deux qui portent la leçon :

> **5.** L'état « peut-être payé, peut-être pas » doit être **représentable** et
> ne doit **pas** être réessayable à l'aveugle.
>
> **6.** La réessayabilité ne doit pas être une propriété de l'erreur seule.

Si tu n'as traité que les cinq autres, tu as écrit du code propre qui débite
toujours deux fois.

## La découpe

| Module | Raison de changer | Ce qu'il connaît |
|---|---|---|
| `tuition` | ce qu'est un matricule, un numéro, un montant | rien |
| `payment` | les règles d'encaissement et la politique de réessai | ses contrats, pas HTTP |
| `operatorhttp` | le protocole de l'opérateur et le **classement** de ses réponses | les codes HTTP et les codes métier de l'opérateur |
| `api` | le contrat HTTP et les textes vus par l'utilisateur | les statuts et le français |

Le troisième est le seul paquet du programme qui connaisse un code HTTP de
l'opérateur. Le quatrième est le seul qui connaisse le français.

```go
// Package tuition holds the vocabulary as types that
// be invalid.
//
// Reason to change: what a student ID, a number, an amount are.
package tuition

import (
    "errors"
    "fmt"
    "regexp"
    "strings"
)

var (
    ErrStudentIDFormat = errors.New("tuition: invalid student ID format")
    ErrPhoneFormat     = errors.New("tuition: invalid number format")
    ErrInvalidAmount   = errors.New("tuition: amount not strictly positive")
)

type StudentID struct{ s string }

var formeMatricule = regexp.MustCompile(`^[A-Z]{2}[0-9]{6}$`)

func ParseStudentID(s string) (StudentID, error) {
    s = strings.ToUpper(strings.TrimSpace(s))
    if !formeMatricule.MatchString(s) {
        return StudentID{}, fmt.Errorf("%w: %q", ErrStudentIDFormat, s)
    }
    return StudentID{s: s}, nil
}

func (m StudentID) String() string { return m.s }

// Phone is a Cameroonian mobile number.
type Phone struct{ s string }

var formeTelephone = regexp.MustCompile(`^6[0-9]{8}$`)

func ParsePhone(s string) (Phone, error) {
    s = strings.NewReplacer(" ", "", "-", "", "+237", "").Replace(strings.TrimSpace(s))
    if !formeTelephone.MatchString(s) {
        return Phone{}, fmt.Errorf("%w: %q", ErrPhoneFormat, s)
    }
    return Phone{s: s}, nil
}

func (t Phone) String() string { return t.s }

// Masked returns the number partly hidden, for logs: a phone
// number is personal data, and a log is kept for
// months.
func (t Phone) Masked() string {
    if len(t.s) != 9 {
        return "***"
    }
    return t.s[:3] + "***" + t.s[6:]
}

// Amount is an integer of CFA francs, strictly positive.
type Amount struct{ fcfa int64 }

func ParseAmount(fcfa int64) (Amount, error) {
    if fcfa <= 0 {
        return Amount{}, fmt.Errorf("%w: %d", ErrInvalidAmount, fcfa)
    }
    return Amount{fcfa: fcfa}, nil
}

func (m Amount) FCFA() int64            { return m.fcfa }
func (m Amount) String() string         { return fmt.Sprintf("%d FCFA", m.fcfa) }
func (m Amount) Exceeded(n Amount) bool { return m.fcfa > n.fcfa }
```

Rien de neuf par rapport à la leçon, sauf un détail qui mérite d'exister :

```go
// Masked returns the number partly hidden, for logs: a phone
// number is personal data, and a log is kept for
// months.
func (t Phone) Masked() string
```

Le type est le bon endroit pour ça. Si la méthode n'existe pas, quelqu'un
écrira `log.Info("payment", "tel", tel)` un jour, et le numéro partira dans
un système de journalisation tiers avec une rétention de treize mois.

> Quand une donnée est sensible, le type qui la porte doit fournir sa forme
> **publiable**. Sinon la forme complète est la seule disponible, donc c'est
> celle qui sera utilisée.

## Contraintes 2, 3, 5, 6 — l'état et les issues

```go
// Package payment collects tuition fees.
//
// Reason to change: the collection rules and the retry policy.
package payment

import (
    "context"
    "errors"
    "fmt"

    "example/fees/tuition"
)

// Reference is the payment's identity, provided by the caller: only
// the sender of the intent knows whether two identical requests are a replay or
// two payments.
type Reference string

// State says what is true of the money. It is returned WITH the error, and it is
// the central point of this correction: an error alone is not enough to
// decide on a retry.
type State int

const (
    // Failed: nothing moved. It is checked, not assumed.
    Failed State = iota
    // Confirmed: the money moved and it is saved on our side.
    Confirmed
    // Uncertain: the money MAY have moved. Nobody knows, and only a
    // reconciliation with the operator can settle it.
    Uncertain
)

func (e State) String() string {
    switch e {
    case Failed:
        return "failed"
    case Confirmed:
        return "confirmed"
    case Uncertain:
        return "uncertain"
    }
    return fmt.Sprintf("state(%d)", int(e))
}

type Receipt struct {
    Reference   Reference
    State       State
    Amount      tuition.Amount
    Transaction string // operator ID; empty if Failed
    Replay      bool   // true if this call had no effect
}

// The outcomes of Pay.
//
//    outcome                | kind            | caller's conduct        | state
//    -----------------------|-----------------|-------------------------|----------
//    success                | —               | go on                   | Confirmed
//    Receipt.Replay == true | —               | go on, redo nothing     | Confirmed
//    ErrReferenceReused     | caller at fault | fix the calling code    | Failed
//    ErrRefused (+ Refusal) | business answer | tell the user           | Failed
//    ErrAmountAboveDue      | business answer | tell the user           | Failed
//    ErrUnavailable         | environment     | retry with backoff      | Failed
//    ErrUncertainOutcome    | environment     | do NOT retry, reconcile | Uncertain
//    ErrUnclassified        | unknown         | alert, do NOT retry     | Uncertain
//
// The last two lines are what set this design apart from
// that of the statement. A failure where we know nothing moved and a
// failure we know nothing about do not lead to the same conduct, so they
// are two outcomes.
var (
    ErrNoReference      = errors.New("payment: empty reference")
    ErrReferenceReused  = errors.New("payment: reference already used for another payment")
    ErrRefused          = errors.New("payment: refused by the operator")
    ErrAmountAboveDue   = errors.New("payment: amount above the amount due")
    ErrUnavailable      = errors.New("payment: operator or database unavailable")
    ErrUncertainOutcome = errors.New("payment: undetermined outcome, reconciliation required")
    ErrUnclassified     = errors.New("payment: unclassified operator response")
)

// RefusalReason says WHY the operator refused.
//
// There is only one sentinel, ErrRefused, because the caller's conduct
// is always the same: tell the user, do not retry. The reason
// changes the TEXT, and the text is the business of presentation, which
// got back with errors.As. It is the rule "sentinel for the conduct, type
// for the data".
type RefusalReason int

const (
    InsufficientBalance RefusalReason = iota
    WrongPIN
    LimitReached
    AccountLocked
)

func (m RefusalReason) String() string {
    switch m {
    case InsufficientBalance:
        return "insufficient balance"
    case WrongPIN:
        return "wrong PIN"
    case LimitReached:
        return "daily limit reached"
    case AccountLocked:
        return "account locked"
    }
    return fmt.Sprintf("reason(%d)", int(m))
}

// Refusal is a typed error: it carries data that presentation
// needs to choose its text.
type Refusal struct{ Reason RefusalReason }

func (r Refusal) Error() string { return ErrRefused.Error() + " : " + r.Reason.String() }

// Is makes errors.Is(err, ErrRefused) true for every Refusal: the conduct is tested
// on the sentinel, the reason is read with errors.As.
func (r Refusal) Is(target error) bool { return target == ErrRefused }

// Operator is the contract of the mobile money operator.
//
// Its implementations MUST translate their errors into the vocabulary of
// this package: the adapter knows the HTTP codes, not the service.
//
// Collect may return ErrUncertainOutcome, and that is what sets it apart: a
// timeout does not say whether the debit happened.
type Operator interface {
    Collect(ctx context.Context, ref Reference, t tuition.Phone, m tuition.Amount) (transaction string, err error)
    // Fate asks the operator what became of a reference. It is what
    // makes the Uncertain state RESOLVABLE instead of final.
    Fate(ctx context.Context, ref Reference) (transaction string, paid bool, err error)
}

// Journal is our durable state. Reserve and Confirm are atomic.
type Journal interface {
    // Reserve records the intent. If the reference already exists with the same
    // content, it returns the existing receipt and replay = true; with a different
    // content, ErrReferenceReused.
    Reserve(ctx context.Context, ref Reference, m tuition.StudentID, mt tuition.Amount) (rcpt Receipt, replay bool, err error)
    // MarkUncertain records that an outcome is undetermined. It is this
    // line, and only it, that makes reconciliation possible: an
    // uncertain state that is not persisted is a lost state.
    MarkUncertain(ctx context.Context, ref Reference) error
    Confirm(ctx context.Context, ref Reference, transaction string) (Receipt, error)
    Due(ctx context.Context, m tuition.StudentID) (tuition.Amount, error)
}

type Service struct {
    Operator Operator
    Journal  Journal
}

// Pay collects a tuition fee payment.
//
// GUARANTEED
//
//   - The returned Receipt always carries a usable State, INCLUDING with a
//     non-nil error. Read the state, not only the error: it is the one that
//     says whether the money moved.
//   - Two calls with the same Reference and the same content produce at
//     most one debit. The second returns Replay = true.
//   - An Uncertain State is PERSISTED before it is returned. It will be picked up by
//     reconciliation, even if this process dies on the next line.
//   - Every error returned matches one of the sentinels of this package.
//     No driver, network or operator error crosses.
//
// WHAT STAYS TRUE, BY OUTCOME
//
//    outcome             | state     | did the money move?
//    --------------------|-----------|----------------------------
//    nil                 | Confirmed | yes, and it is saved
//    nil (Replay)        | Confirmed | yes, in an earlier call
//    ErrNoReference      | Failed    | no
//    ErrReferenceReused  | Failed    | no
//    ErrRefused          | Failed    | no: the operator answered
//    ErrAmountAboveDue   | Failed    | no: refused before the call
//    ErrUnavailable      | Failed    | no: checked, not assumed
//    ErrUncertainOutcome | Uncertain | MAYBE
//    ErrUnclassified     | Uncertain | MAYBE
//
// NOT GUARANTEED
//
//   - That an Uncertain State resolves itself. Resolve exists for that, and
//     someone must call it.
//   - Atomicity between the debit at the operator and the write on our side.
//     It is IMPOSSIBLE: they are two systems separated by a network.
//     That is precisely why Uncertain exists, and it will not go away.
//   - A bound on how long a State stays Uncertain. It is guaranteed by the
//     reconciliation and its alert, not by this function.
//
// CALLER'S CONDUCT
//
//   - Use Retryable(rcpt, err). NEVER retry on the sole basis of
//     the error: ErrUnavailable and ErrUncertainOutcome are both
//     environment failures, and only one of the two is retryable.
//   - On Uncertain, show neither success nor failure. Say "being
//     checked" and explicitly discourage trying again.
//
// COST
//
//   - A network call to the operator, hence the context. The context's deadline
//     bounds the wait; it does not bound the uncertainty.
//
// SAFETY
//
//   - Safe for concurrent use. Two simultaneous calls on the same
//     Reference produce at most one debit.
func (s *Service) Pay(ctx context.Context, ref Reference, m tuition.StudentID, mt tuition.Amount, t tuition.Phone) (Receipt, error) {
    if ref == "" {
        return Receipt{State: Failed}, ErrNoReference
    }

    due, err := s.Journal.Due(ctx, m)
    if err != nil {
        return Receipt{Reference: ref, State: Failed}, unavailable("amount due", err)
    }
    if mt.Exceeded(due) {
        return Receipt{Reference: ref, State: Failed}, fmt.Errorf("%w: %s > %s",
            ErrAmountAboveDue, mt, due)
    }

    rcpt, replay, err := s.Journal.Reserve(ctx, ref, m, mt)
    if err != nil {
        if errors.Is(err, ErrReferenceReused) {
            return Receipt{Reference: ref, State: Failed}, err
        }
        return Receipt{Reference: ref, State: Failed}, unavailable("reservation", err)
    }
    if replay {
        rcpt.Replay = true
        return rcpt, nil
    }

    transaction, err := s.Operator.Collect(ctx, ref, t, mt)
    if err != nil {
        return s.afterOperatorFailure(ctx, ref, mt, err)
    }

    confirmed, err := s.Journal.Confirm(ctx, ref, transaction)
    if err != nil {
        // The money moved, our write failed. It is the most
        // nasty case, and it is Uncertain from the caller's point of view:
        // it must above all not retry.
        if err := s.Journal.MarkUncertain(ctx, ref); err != nil {
            return Receipt{Reference: ref, State: Uncertain, Transaction: transaction},
                fmt.Errorf("%w: cannot mark: %v", ErrUncertainOutcome, err)
        }
        return Receipt{Reference: ref, State: Uncertain, Transaction: transaction},
            fmt.Errorf("%w: debit done, saving failed", ErrUncertainOutcome)
    }
    return confirmed, nil
}

// afterOperatorFailure tells "nothing moved" from "we do not know".
func (s *Service) afterOperatorFailure(ctx context.Context, ref Reference, mt tuition.Amount, err error) (Receipt, error) {
    switch {
    case errors.Is(err, ErrRefused), errors.Is(err, ErrUnavailable):
        // The operator answered: nothing moved.
        return Receipt{Reference: ref, State: Failed, Amount: mt}, err

    default:
        // ErrUncertainOutcome, ErrUnclassified, or anything that has not been
        // classified: we do not know, so we persist the uncertainty BEFORE
        // returning.
        if markErr := s.Journal.MarkUncertain(ctx, ref); markErr != nil {
            return Receipt{Reference: ref, State: Uncertain, Amount: mt},
                fmt.Errorf("%w: cannot mark: %v", ErrUncertainOutcome, markErr)
        }
        if errors.Is(err, ErrUncertainOutcome) || errors.Is(err, ErrUnclassified) {
            return Receipt{Reference: ref, State: Uncertain, Amount: mt}, err
        }
        return Receipt{Reference: ref, State: Uncertain, Amount: mt},
            fmt.Errorf("%w: %v", ErrUncertainOutcome, err)
    }
}

// Resolve settles an uncertain outcome by asking the operator.
//
// It is the piece that turns Uncertain into a TEMPORARY state. Without it, the
// contract would expose a permanent uncertainty, which would be a bad
// abstraction: we would have returned a problem without its remedy.
func (s *Service) Resolve(ctx context.Context, ref Reference) (Receipt, error) {
    transaction, paid, err := s.Operator.Fate(ctx, ref)
    if err != nil {
        return Receipt{Reference: ref, State: Uncertain}, unavailable("sort", err)
    }
    if !paid {
        return Receipt{Reference: ref, State: Failed}, nil
    }
    return s.Journal.Confirm(ctx, ref, transaction)
}

// Retryable takes the receipt AND the error.
//
// It is the signature the lesson announces: retryability is a
// property of the pair (error, state). A timeout is "retryable" as
// an error and not at all as a state, because the money
// may have moved.
func Retryable(r Receipt, err error) bool {
    if err == nil {
        return false
    }
    if r.State == Uncertain {
        return false
    }
    return errors.Is(err, ErrUnavailable)
}

func unavailable(step string, cause error) error {
    // %w on our sentinel, %v on the cause: the identity does not become
    // public, the message stays readable.
    return fmt.Errorf("%w: %s: %v", ErrUnavailable, step, cause)
}
```

### Le tableau des issues, qui est le livrable principal

```
issue                   | nature          | conduite de l'appelant        | etat
------------------------|-----------------|-------------------------------|-----------
succes                  | —               | continuer                     | Confirmed
Receipt.Replay == true      | —               | continuer, sans rien refaire  | Confirmed
ErrReferenceReused  | appelant fautif | corriger le code appelant     | Failed
ErrRefused (+ Refusal)      | reponse metier  | le dire a l'utilisateur       | Failed
ErrAmountAboveDue | reponse metier  | le dire a l'utilisateur       | Failed
ErrUnavailable         | environnement   | reessayer avec recul          | Failed
ErrUncertainOutcome      | environnement   | NE PAS reessayer, reconcilier | Uncertain
ErrUnclassified            | inconnue        | alerter, NE PAS reessayer     | Uncertain
```

Les deux dernières lignes sont la réponse à l'exercice. `ErrUnavailable` et
`ErrUncertainOutcome` sont **deux défaillances d'environnement** et elles
mènent à des conduites **opposées**. Les confondre — ce que fait l'énoncé —
produit le triple débit de la correction 1.5 / 1.

### `State` est rendu **avec** l'erreur

```go
func (s *Service) Pay(...) (Receipt, error)
```

Et `Receipt` porte un `State`, même quand l'erreur n'est pas nulle. C'est
inhabituel — on apprend qu'en cas d'erreur la valeur de retour n'a pas de
sens — et c'est ici indispensable :

> Une erreur dit ce qui a échoué. Elle ne peut pas dire ce qui reste vrai,
> parce que « ce qui reste vrai » n'est pas une propriété de l'échec : c'est
> une propriété du **système**. Il faut donc une seconde valeur.

Le commentaire du contrat le dit à l'appelant, parce que c'est contre-intuitif :

```
//   - Le Receipt rendu porte toujours un State exploitable, y compris avec une
//     erreur. Lis l'etat, pas seulement l'erreur.
```

### La signature de `Retryable`

```go
func Retryable(r Receipt, err error) bool {
    if err == nil {
        return false
    }
    if r.State == Uncertain {
        return false
    }
    return errors.Is(err, ErrUnavailable)
}
```

Deux arguments, et c'est la contrainte 6. L'ordre des tests n'est pas
anodin : **l'état passe avant l'erreur.** Un `ErrUnavailable` rendu avec un
état `Uncertain` ne serait pas réessayable, et c'est la bonne réponse — le
doute sur l'argent prime sur la nature de la panne.

### L'incertitude est persistée avant d'être rendue

```go
if markErr := s.Journal.MarkUncertain(ctx, ref); markErr != nil {
    return Receipt{...State: Uncertain...},
        fmt.Errorf("%w: cannot mark: %v", ErrUncertainOutcome, markErr)
}
```

C'est la réponse à la question 2 de la correction 1.5 / 1. Et remarque le cas
où le marquage lui-même échoue : on rend quand même `Uncertain`, en disant que
le marquage a échoué. On ne prétend pas que tout va bien parce qu'on n'a pas
réussi à écrire qu'on ne va pas bien.

> Quand l'enregistrement d'un problème échoue, le problème ne disparaît pas :
> il devient seulement invisible. Rends-le, et dis que tu n'as pas pu l'écrire.

### `Resolve` : l'incertitude doit avoir une issue

```go
// It is the piece that turns Uncertain into a TEMPORARY state. Without it, the
// contract would expose a permanent uncertainty, which would be a bad
// abstraction: we would have returned a problem without its remedy.
func (s *Service) Resolve(ctx context.Context, ref Reference) (Receipt, error)
```

C'est le point de conception le plus important après l'état lui-même.

Exposer `Uncertain` sans fournir `Resolve` serait honnête et inutilisable :
l'appelant saurait qu'il y a un problème et n'aurait aucun moyen de le
régler. C'est la leçon 1.4 par l'autre bout — on expose ce dont l'appelant a
besoin pour **tenir ses propres garanties**.

> Si tu exposes une incertitude, expose aussi le moyen de la lever. Une
> abstraction qui rend un problème sans son moyen n'a pas résolu le problème,
> elle l'a délégué.

### `Refusal` : une sentinelle pour la conduite, un type pour la donnée

```go
type Refusal struct{ Reason RefusalReason }

func (r Refusal) Is(target error) bool { return target == ErrRefused }
```

Quatre motifs, une conduite, donc **une** sentinelle. `errors.Is(err, ErrRefused)`
pour décider, `errors.As(err, &refus)` pour choisir le texte. La méthode `Is`
sur le type est ce qui raccorde les deux.

C'est la contrainte 3 — *une sentinelle par conduite, pas une de plus* — et
c'est la seule fusion que je revendique. Les autres issues ont toutes des
conduites réellement distinctes.

## Contrainte 4 — le classement, et là où il vit

```go
// Package operatorhttp talks to the mobile money operator over HTTP.
//
// Reason to change: the operator's protocol and the classification of its
// responses.
//
// It is the only package of the program that knows HTTP codes of
// the operator. Everything that leaves here speaks the payment vocabulary.
package operatorhttp

import (
    "context"
    "encoding/json"
    "fmt"
    "io"
    "net/http"
    "strings"

    "example/fees/payment"
    "example/fees/tuition"
)

// reasons maps the operator's business codes to our refusal reasons.
//
// It is an EXPLICIT list. A code absent from this table is not
// "probably transient": it is unclassified, and it makes noise.
var reasons = map[string]payment.RefusalReason{
    "INSUFFICIENT_FUNDS": payment.InsufficientBalance,
    "WRONG_PIN":          payment.WrongPIN,
    "LIMIT_EXCEEDED":     payment.LimitReached,
    "ACCOUNT_LOCKED":     payment.AccountLocked,
}

// unavailableStatuses is the EXPLICIT list of statuses on which we
// agree to retry. Everything else is not retryable.
//
// The opposite, retrying by default on everything we do not understand, is what
// produced the incident of exercise 5: a business refusal sent as 429
// triggered three retries per payment, and the merchant account's quota was
// burned in four minutes.
var unavailableStatuses = map[int]bool{
    http.StatusServiceUnavailable: true, // 503
    http.StatusBadGateway:         true, // 502
    http.StatusGatewayTimeout:     true, // 504
}

type Client struct {
    HTTP *http.Client
    Base string
}

// Classify translates an operator response into our vocabulary.
//
// The order of the two steps is the most important decision of this file:
// the BUSINESS CODE wins over the HTTP STATUS. The code says what happened;
// the status says how transport behaved, and the operator may
// change without a new major version.
func Classify(status int, body []byte) error {
    if status == http.StatusOK {
        return nil
    }

    var payload struct {
        Code    string `json:"code"`
        Message string `json:"message"`
    }
    _ = json.Unmarshal(body, &payload) // an unreadable body leaves Code empty

    if reason, known := reasons[payload.Code]; known {
        return payment.Refusal{Reason: reason}
    }

    if unavailableStatuses[status] {
        return fmt.Errorf("%w: status %d: %s",
            payment.ErrUnavailable, status, excerpt(body))
    }

    // Default: unclassified, so not retryable, so noisy. It is the
    // detector: a response that lands here is a response that
    // nobody has thought about yet.
    return fmt.Errorf("%w: status %d, code %q: %s",
        payment.ErrUnclassified, status, payload.Code, excerpt(body))
}

// excerpt bounds and cleans the body before putting it in an
// error message: an operator response may hold a phone number, a
// token, or two thousand lines of HTML.
func excerpt(body []byte) string {
    s := strings.TrimSpace(string(body))
    s = strings.ReplaceAll(s, "\n", " ")
    if len(s) > 200 {
        return s[:200] + "…"
    }
    return s
}

func (c *Client) Collect(ctx context.Context, ref payment.Reference, t tuition.Phone, m tuition.Amount) (string, error) {
    body, err := json.Marshal(map[string]any{
        "reference": string(ref), "msisdn": t.String(), "amount": m.FCFA(),
    })
    if err != nil {
        return "", fmt.Errorf("%w: encoding: %v", payment.ErrUnclassified, err)
    }

    req, err := http.NewRequestWithContext(ctx, http.MethodPost,
        c.Base+"/collect", strings.NewReader(string(body)))
    if err != nil {
        return "", fmt.Errorf("%w: request: %v", payment.ErrUnclassified, err)
    }
    req.Header.Set("Content-Type", "application/json")

    rep, err := c.HTTP.Do(req)
    if err != nil {
        // A request sent and without response: we do NOT know whether the debit
        // happened. It is the uncertain outcome, and it is not retryable.
        // The %v protects the identity of the transport error; its message
        // stays for diagnosis.
        return "", fmt.Errorf("%w: call without response: %v", payment.ErrUncertainOutcome, err)
    }
    defer rep.Body.Close()

    raw, err := readBounded(rep)
    if err != nil {
        // Response cut while reading: the operator may have
        // debited. Uncertain, there too.
        return "", fmt.Errorf("%w: reading the response: %v", payment.ErrUncertainOutcome, err)
    }

    if err := Classify(rep.StatusCode, raw); err != nil {
        return "", err
    }

    var resp struct {
        Transaction string `json:"transaction_id"`
    }
    if err := json.Unmarshal(raw, &resp); err != nil || resp.Transaction == "" {
        // Status 200 but unusable body: the debit very probably
        // happened and we do not know under which reference. Uncertain.
        return "", fmt.Errorf("%w: 200 without a transaction ID: %s",
            payment.ErrUncertainOutcome, excerpt(raw))
    }
    return resp.Transaction, nil
}

func (c *Client) Fate(ctx context.Context, ref payment.Reference) (string, bool, error) {
    req, err := http.NewRequestWithContext(ctx, http.MethodGet,
        c.Base+"/collect/"+string(ref), nil)
    if err != nil {
        return "", false, fmt.Errorf("%w: request: %v", payment.ErrUnclassified, err)
    }

    rep, err := c.HTTP.Do(req)
    if err != nil {
        // Here, the retry is legitimate: a lookup modifies nothing.
        return "", false, fmt.Errorf("%w: lookup: %v", payment.ErrUnavailable, err)
    }
    defer rep.Body.Close()

    raw, err := readBounded(rep)
    if err != nil {
        return "", false, fmt.Errorf("%w: read: %v", payment.ErrUnavailable, err)
    }
    if rep.StatusCode == http.StatusNotFound {
        return "", false, nil // the operator does not know the reference: nothing moved
    }
    if err := Classify(rep.StatusCode, raw); err != nil {
        return "", false, err
    }

    var resp struct {
        Transaction string `json:"transaction_id"`
        Status      string `json:"status"`
    }
    if err := json.Unmarshal(raw, &resp); err != nil {
        return "", false, fmt.Errorf("%w: unreadable response: %v", payment.ErrUnavailable, err)
    }
    return resp.Transaction, resp.Status == "SUCCESS", nil
}

const maxBody = 1 << 20

func readBounded(rep *http.Response) ([]byte, error) {
    return io.ReadAll(io.LimitReader(rep.Body, maxBody))
}
```

### La décision centrale

```go
// The order of the two steps is the most important decision of this file:
// the BUSINESS CODE wins over the HTTP STATUS. The code says what happened;
// the status says how transport behaved, and the operator may
// change without a new major version.
```

Le code métier d'abord, le statut HTTP ensuite. C'est ce qui rend le
classement robuste au changement de l'exercice 5 — un refus passé de `402` à
`429` reste un refus.

### Les deux listes sont explicites, et le défaut est « non classé »

```go
var unavailableStatuses = map[int]bool{
    http.StatusServiceUnavailable: true, // 503
    http.StatusBadGateway:         true, // 502
    http.StatusGatewayTimeout:     true, // 504
}
```

Trois statuts, listés à la main. Tout le reste tombe dans `ErrUnclassified`, qui
n'est **pas** réessayable et qui fait du bruit.

> Une liste blanche vide par défaut vaut mieux qu'une liste noire. Avec une
> liste noire, chaque nouveauté du tiers est réessayable jusqu'à ce que
> quelqu'un l'interdise ; avec une liste blanche, elle est refusée jusqu'à ce
> que quelqu'un l'autorise. C'est la différence entre échouer ouvert et
> échouer fermé.

Et `429` n'est **pas** dans la liste, volontairement :

```go
// 429 is not there, on purpose: "too many requests" means we
// already send too many. Retrying is exactly the wrong conduct.
```

### Les trois endroits qui produisent `ErrUncertainOutcome`

C'est la partie qu'on oublie en écrivant un adaptateur :

| Où | Pourquoi l'issue est incertaine |
|---|---|
| `HTTP.Do` rend une erreur | la requête est peut-être partie, et l'opérateur a peut-être débité |
| la lecture du corps échoue | l'opérateur a répondu, donc il a traité |
| statut 200 sans `transaction_id` | il a très probablement débité, et nous ne savons pas sous quelle référence |

Le troisième est le plus facile à manquer. Un `200` est un succès, donc on
suppose que tout va bien — mais un `200` avec un corps inexploitable est
exactement le cas où l'argent a bougé et où nous avons perdu la trace.

### Le corps est borné avant d'entrer dans un message

```go

// error message: an operator response may hold a phone number, a
// token, or two thousand lines of HTML.
```

Un message d'erreur finit dans un journal, et un journal se conserve. Mettre
un corps de réponse brut dans une erreur, c'est accepter d'y mettre ce que le
tiers voudra bien y écrire.

Quatre tests méritent un commentaire.

**`TestAnUncertainOutcomeIsNotRetryableAndIsPersisted`** vérifie trois
choses d'un coup : l'erreur, l'état, et le fait que le marquage a eu lieu. Les
trois sont nécessaires : un état `Uncertain` non persisté est un état perdu.

**`TestUnavailabilityIsRetryableBecauseNothingMoved`** est son
symétrique, et il contient l'assertion qu'on n'écrit pas :

```go
if len(j.uncertain) != 0 {
    t.Errorf("%d useless marking(s): there is nothing to reconcile", len(j.uncertain))
}
```

Marquer `Uncertain` une panne dont on sait que rien n'a bougé n'est pas
prudent, c'est bruyant : ça remplit la file de réconciliation de cas qui n'ont
rien à y faire, et au bout d'un mois personne ne la regarde plus.

**`TestDebitDoneAndSaveFailedGivesUncertain`** vérifie que
l'identifiant de transaction **survit** dans le reçu :

```go
if rcpt.Transaction != "T-42" {
    t.Errorf("transaction = %q: the operator ID must survive, it is what allows reconciliation", rcpt.Transaction)
```

Sans lui, la réconciliation n'a rien pour chercher. C'est la donnée dont
l'appelant a besoin pour tenir sa garantie.

**`TestDriverIdentityDoesNotCrossButItsMessageDoes`** est le test de la
leçon, avec une assertion de plus : `op.calls == 0`. Une vérification
préalable qui échoue ne doit pas avoir appelé l'opérateur — sinon « rien n'a
bougé » est faux.

## Contrainte 7 — la table de correspondance

```go
// Package api translates payment outcomes into HTTP responses.
//
// Reason to change: the HTTP contract and the texts the user sees.
package api

import (
    "errors"
    "log/slog"
    "net/http"

    "example/fees/payment"
    "example/fees/tuition"
)

// Response takes the receipt AND the error.
//
// It is the direct consequence of the design of package payment: the
// HTTP response depends on the state as much as on the error. An uncertain outcome
// is not a failure (it is a "we are checking"), and no signature
// that took only the error could say it.
func Response(r payment.Receipt, err error) (status int, message string, level slog.Level) {
    status = statusOf(r, err)
    return status, messageOf(r, err), levelOf(status)
}

func statusOf(r payment.Receipt, err error) int {
    // The state comes before the error: a payment we know nothing about is neither
    // a success nor a failure, and telling the client is the only
    // honest course.
    if r.State == payment.Uncertain {
        return http.StatusAccepted // 202: accepted, outcome being checked
    }

    switch {
    case err == nil:
        return http.StatusOK

    // Caller faults: retrying as is will not help.
    case errors.Is(err, tuition.ErrStudentIDFormat),
        errors.Is(err, tuition.ErrPhoneFormat),
        errors.Is(err, tuition.ErrInvalidAmount),
        errors.Is(err, payment.ErrNoReference):
        return http.StatusBadRequest
    case errors.Is(err, payment.ErrReferenceReused):
        return http.StatusConflict

    // Business answers: the request is correct, the answer is "no".
    case errors.Is(err, payment.ErrRefused),
        errors.Is(err, payment.ErrAmountAboveDue):
        return http.StatusUnprocessableEntity

    // Environment failure: the only category that counts against the
    // against the announced availability.
    case errors.Is(err, payment.ErrUnavailable):
        return http.StatusServiceUnavailable

    // Unclassified: by construction, it is a hole in this table or in
    // that of the adapter. It must make noise.
    case errors.Is(err, payment.ErrUnclassified),
        errors.Is(err, payment.ErrUncertainOutcome):
        return http.StatusInternalServerError
    }
    return http.StatusInternalServerError
}

func messageOf(r payment.Receipt, err error) string {
    if r.State == payment.Uncertain {
        return "Votre paiement est en cours de verification aupres de l'operateur. " +
            "Ne recommencez pas : vous recevrez une confirmation d'ici quelques minutes."
    }

    // The refusal's reason is read with errors.As: one sentinel for the
    // conduct, a type for the text.
    var refus payment.Refusal
    if errors.As(err, &refus) {
        switch refus.Reason {
        case payment.InsufficientBalance:
            return "Solde insuffisant sur votre compte mobile money."
        case payment.WrongPIN:
            return "Code secret errone. Verifiez votre code et recommencez."
        case payment.LimitReached:
            return "Plafond journalier atteint. Reessayez demain ou payez en deux fois."
        case payment.AccountLocked:
            return "Votre compte mobile money est bloque. Contactez votre operateur."
        }
    }

    switch {
    case err == nil:
        return "Paiement enregistre."
    case errors.Is(err, tuition.ErrStudentIDFormat):
        return "Matricule invalide : deux lettres suivies de six chiffres."
    case errors.Is(err, tuition.ErrPhoneFormat):
        return "Numero invalide : neuf chiffres commencant par 6."
    case errors.Is(err, tuition.ErrInvalidAmount):
        return "Le montant doit etre strictement positif."
    case errors.Is(err, payment.ErrNoReference):
        return "Requete incomplete : reference de paiement manquante."
    case errors.Is(err, payment.ErrReferenceReused):
        return "Cette reference a deja servi pour un autre paiement."
    case errors.Is(err, payment.ErrAmountAboveDue):
        return "Le montant depasse le reste a payer."
    case errors.Is(err, payment.ErrUnavailable):
        return "Service momentanement indisponible. Reessayez dans quelques instants."
    }
    return "Une erreur inattendue est survenue. Nos equipes sont prevenues."
}

// levelOf derives the log level from the status, instead of choosing it site
// by site. A developer who writes log.Error case by case will end up
// put it everywhere.
func levelOf(status int) slog.Level {
    switch {
    case status == http.StatusAccepted:
        // An uncertain outcome is not an outage, but someone must
        // reconcile it: WARN, and an alert on the RATE, not on each one.
        return slog.LevelWarn
    case status < 400:
        return slog.LevelDebug
    case status < 500:
        return slog.LevelInfo
    case status == http.StatusServiceUnavailable:
        return slog.LevelWarn
    default:
        return slog.LevelError
    }
}
```

### La signature prend le reçu **et** l'erreur

```go
func Response(r payment.Receipt, err error) (status int, message string, level slog.Level)
```

C'est la conséquence directe de la conception de `payment`, et c'est ce qui
permet le choix suivant.

### Une issue incertaine donne **202**, pas 500

```go
if r.State == payment.Uncertain {
    return http.StatusAccepted // 202: accepted, outcome being checked
}
```

Avec le message qui va avec :

> « Votre paiement est en cours de vérification auprès de l'opérateur. **Ne
> recommencez pas** : vous recevrez une confirmation d'ici quelques minutes. »

C'est la décision de produit la plus importante de tout l'exercice. Un `500`
dit « ça a échoué », donc le parent recommence, donc il paie deux fois. Un
`202` avec cette phrase est la seule réponse qui évite le second débit —
**et aucun contrat qui ne rendrait que l'erreur ne pourrait la produire.**

> La bonne réponse HTTP dépend de l'état, pas seulement de l'erreur. C'est la
> raison technique pour laquelle `State` est dans le reçu.

### Et un 202 n'est pas un succès pour autant

```go
case status == http.StatusAccepted:
    // An uncertain outcome is not an outage, but someone must
    // reconcile it: WARN, and an alert on the RATE, not on each one.
    return slog.LevelWarn
```

`WARN`, et une alerte sur le **taux**. Un paiement incertain par jour est
normal ; trente en dix minutes est un incident. L'alerte porte sur la
grandeur, pas sur l'événement.

```go
package api

import (
    "errors"
    "log/slog"
    "net/http"
    "strings"
    "testing"

    "example/fees/payment"
    "example/fees/tuition"
)

// Every outcome declared by the domain must be classified. A 500 is a hole
// in this table.
func TestEveryOutcomeIsClassified(t *testing.T) {
    outcomes := []struct {
        name string
        err  error
    }{
        {"student_id", tuition.ErrStudentIDFormat},
        {"phone", tuition.ErrPhoneFormat},
        {"amount", tuition.ErrInvalidAmount},
        {"without reference", payment.ErrNoReference},
        {"reference reused", payment.ErrReferenceReused},
        {"refusal balance", payment.Refusal{Reason: payment.InsufficientBalance}},
        {"refusal pin", payment.Refusal{Reason: payment.WrongPIN}},
        {"refusal limit", payment.Refusal{Reason: payment.LimitReached}},
        {"refusal locked", payment.Refusal{Reason: payment.AccountLocked}},
        {"amount above", payment.ErrAmountAboveDue},
        {"unavailable", payment.ErrUnavailable},
    }

    const fallback = "Une erreur inattendue est survenue. Nos equipes sont prevenues."
    for _, c := range outcomes {
        t.Run(c.name, func(t *testing.T) {
            status, message, level := Response(payment.Receipt{State: payment.Failed}, c.err)
            if status == http.StatusInternalServerError {
                t.Errorf("classified 500: hole in the table")
            }
            if message == fallback {
                t.Errorf("no user message")
            }
            if level == slog.LevelError {
                t.Errorf("logged at ERROR: it would wake someone for nothing")
            }
        })
    }
}

// An uncertain outcome is neither a success nor a failure: 202, and a message
// that says explicitly not to try again.
func TestAnUncertainOutcomeGives202AndSaysDoNotRetry(t *testing.T) {
    rcpt := payment.Receipt{State: payment.Uncertain, Transaction: "T-42"}
    status, message, level := Response(rcpt, payment.ErrUncertainOutcome)

    if status != http.StatusAccepted {
        t.Errorf("status = %d, want 202", status)
    }
    if level != slog.LevelWarn {
        t.Errorf("level = %v, want WARN", level)
    }
    if !strings.Contains(message, "Ne recommencez pas") {
        t.Errorf("the message must discourage retrying: %q", message)
    }
}

// An unknown error makes noise. It is intended.
func TestAnUnknownErrorMakesNoise(t *testing.T) {
    status, _, level := Response(payment.Receipt{State: payment.Failed},
        errors.New("something nobody classified"))
    if status != http.StatusInternalServerError {
        t.Errorf("status = %d, want 500", status)
    }
    if level != slog.LevelError {
        t.Errorf("level = %v, want ERROR", level)
    }
}

// The four refusal reasons share a sentinel and give four
// different texts: sentinel for the conduct, type for the data.
func TestTheFourReasonsGiveFourTexts(t *testing.T) {
    seen := map[string]bool{}
    for _, m := range []payment.RefusalReason{
        payment.InsufficientBalance, payment.WrongPIN,
        payment.LimitReached, payment.AccountLocked,
    } {
        status, message, _ := Response(payment.Receipt{State: payment.Failed}, payment.Refusal{Reason: m})
        if status != http.StatusUnprocessableEntity {
            t.Errorf("reason %v: status = %d, want 422", m, status)
        }
        if seen[message] {
            t.Errorf("reason %v: message already seen, presentation cannot tell them apart", m)
        }
        seen[message] = true
    }
    if len(seen) != 4 {
        t.Errorf("%d distinct texts, want 4", len(seen))
    }
}
```

Le dernier test vérifie une propriété qu'on ne pense pas à tester :

```go
func TestTheFourReasonsGiveFourTexts(t *testing.T)
```

Les quatre motifs partagent une sentinelle — donc le `switch` sur `errors.Is`
ne les distingue pas — et doivent produire quatre textes distincts. Si
quelqu'un supprime un jour le `errors.As`, les quatre motifs donneront le même
message générique, et **aucun autre test ne le verrait**.

## Ce que ça ne règle pas

- **La réconciliation n'est pas écrite.** `Resolve` existe, mais le processus
  qui l'appelle sur les références marquées incertaines, à quelle cadence, et
  qui regarde celles qu'il n'arrive pas à trancher : c'est l'exercice 4.
- **`ErrScolariteInconnue` manque.** Un matricule inconnu tombe dans
  `ErrUnavailable` via `Journal.Due`. C'est le trou signalé à la
  correction 1.5 / 1, et il est réel.
- **L'atomicité entre `paiements` et `scolarites`** est reportée sur
  l'implémentation de `Journal.Confirm`, qui doit les écrire dans une seule
  transaction. Le contrat le dit ; rien ne le vérifie, et un test de contrat
  partagé serait le bon outil — c'est la leçon 1.4 et l'objet de la 1.6.
- **Le quota de l'opérateur n'est pas borné.** Rien n'empêche mille paiements
  simultanés de saturer le compte marchand. Il faudrait le budget de la
  correction 1.4 / 5.

## À retenir

1. Une erreur dit ce qui a échoué ; elle ne peut pas dire ce qui reste vrai.
   Il faut une seconde valeur de retour, et le contrat doit dire de la lire.
2. Deux défaillances d'environnement peuvent exiger des conduites opposées :
   `ErrUnavailable` se réessaie, `ErrUncertainOutcome` jamais.
3. `Retryable` prend l'erreur **et** l'état, et l'état passe en premier.
4. Une incertitude se persiste avant d'être rendue. Et si le marquage échoue,
   on le dit au lieu de prétendre que tout va bien.
5. Si tu exposes une incertitude, expose le moyen de la lever. Sinon tu as
   délégué le problème, pas résolu.
6. Une sentinelle pour la conduite, un type pour la donnée. La méthode `Is`
   sur le type raccorde les deux.
7. Le code métier prime sur le statut HTTP. Le statut peut changer sans
   version majeure ; le code, rarement.
8. Liste blanche vide par défaut, pas liste noire. Échoue fermé.
9. `429` n'est pas réessayable : « trop de requêtes » signifie qu'on en envoie
   déjà trop.
10. Un `200` au corps inexploitable est une issue incertaine, pas un succès.
11. Borne et nettoie un corps de réponse avant de le mettre dans une erreur :
    un journal se conserve des mois.
12. Un type qui porte une donnée sensible doit fournir sa forme publiable,
    sinon c'est la forme complète qui sera journalisée.
13. Une issue incertaine se répond en 202 avec « ne recommencez pas », jamais
    en 500. Un 500 fait payer deux fois.
14. Alerte sur le **taux** d'issues incertaines, pas sur l'événement.
