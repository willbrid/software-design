## Contrainte 1 — l'analyse à la frontière

```go
// Package scolarite porte le vocabulaire sous forme de types qui ne peuvent
// pas etre invalides.
//
// Raison de changer : ce qu'est un matricule, un numero, un montant.
package scolarite

import (
    "errors"
    "fmt"
    "regexp"
    "strings"
)

var (
    ErrMatriculeFormat = errors.New("scolarite : format de matricule invalide")
    ErrTelephoneFormat = errors.New("scolarite : format de numero invalide")
    ErrMontantInvalide = errors.New("scolarite : montant non strictement positif")
)

type Matricule struct{ s string }

var formeMatricule = regexp.MustCompile(`^[A-Z]{2}[0-9]{6}$`)

func ParserMatricule(s string) (Matricule, error) {
    s = strings.ToUpper(strings.TrimSpace(s))
    if !formeMatricule.MatchString(s) {
        return Matricule{}, fmt.Errorf("%w : %q", ErrMatriculeFormat, s)
    }
    return Matricule{s: s}, nil
}

func (m Matricule) String() string { return m.s }

// Telephone est un numero mobile camerounais.
type Telephone struct{ s string }

var formeTelephone = regexp.MustCompile(`^6[0-9]{8}$`)

func ParserTelephone(s string) (Telephone, error) {
    s = strings.NewReplacer(" ", "", "-", "", "+237", "").Replace(strings.TrimSpace(s))
    if !formeTelephone.MatchString(s) {
        return Telephone{}, fmt.Errorf("%w : %q", ErrTelephoneFormat, s)
    }
    return Telephone{s: s}, nil
}

func (t Telephone) String() string { return t.s }

// Masque rend le numero partiellement cache, pour les journaux : un numero
// de telephone est une donnee personnelle, et un journal se conserve des
// mois.
func (t Telephone) Masque() string {
    if len(t.s) != 9 {
        return "***"
    }
    return t.s[:3] + "***" + t.s[6:]
}

// Montant est un entier de francs CFA, strictement positif.
type Montant struct{ fcfa int64 }

func ParserMontant(fcfa int64) (Montant, error) {
    if fcfa <= 0 {
        return Montant{}, fmt.Errorf("%w : %d", ErrMontantInvalide, fcfa)
    }
    return Montant{fcfa: fcfa}, nil
}

func (m Montant) FCFA() int64            { return m.fcfa }
func (m Montant) String() string         { return fmt.Sprintf("%d FCFA", m.fcfa) }
func (m Montant) Depasse(n Montant) bool { return m.fcfa > n.fcfa }
```

Rien de neuf par rapport à la leçon, sauf un détail qui mérite d'exister :

```go
// Masque rend le numero partiellement cache, pour les journaux : un numero
// de telephone est une donnee personnelle, et un journal se conserve des
// mois.
func (t Telephone) Masque() string
```

Le type est le bon endroit pour ça. Si la méthode n'existe pas, quelqu'un
écrira `log.Info("paiement", "tel", tel)` un jour, et le numéro partira dans
un système de journalisation tiers avec une rétention de treize mois.

> Quand une donnée est sensible, le type qui la porte doit fournir sa forme
> **publiable**. Sinon la forme complète est la seule disponible, donc c'est
> celle qui sera utilisée.

## Contraintes 2, 3, 5, 6 — l'état et les issues

```go
// Package paiement encaisse les frais de scolarite.
//
// Raison de changer : les regles d'encaissement et la politique de reessai.
package paiement

import (
    "context"
    "errors"
    "fmt"

    "exemple/frais/scolarite"
)

// Reference est l'identite du paiement, fournie par l'appelant : seul
// l'emetteur de l'intention sait si deux demandes identiques sont un rejeu ou
// deux paiements.
type Reference string

// Etat dit ce qui est vrai de l'argent. Il est rendu AVEC l'erreur, et c'est
// le point central de cette correction : une erreur seule ne suffit pas a
// decider d'un reessai.
type Etat int

const (
    // Echoue : rien n'a bouge. C'est verifie, pas suppose.
    Echoue Etat = iota
    // Confirme : l'argent a bouge et c'est enregistre chez nous.
    Confirme
    // Incertain : l'argent a PEUT-ETRE bouge. Personne ne sait, et seule une
    // reconciliation avec l'operateur peut trancher.
    Incertain
)

func (e Etat) String() string {
    switch e {
    case Echoue:
        return "echoue"
    case Confirme:
        return "confirme"
    case Incertain:
        return "incertain"
    }
    return fmt.Sprintf("etat(%d)", int(e))
}

type Recu struct {
    Reference   Reference
    Etat        Etat
    Montant     scolarite.Montant
    Transaction string // identifiant operateur ; vide si Echoue
    Rejeu       bool   // vrai si cet appel n'a produit aucun effet
}

// Les issues de Payer.
//
//    issue                   | nature          | conduite de l'appelant        | etat
//    ------------------------|-----------------|-------------------------------|-----------
//    succes                  | —               | continuer                     | Confirme
//    Recu.Rejeu == true      | —               | continuer, sans rien refaire  | Confirme
//    ErrReferenceReutilisee  | appelant fautif | corriger le code appelant     | Echoue
//    ErrRefus (+ Refus)      | reponse metier  | le dire a l'utilisateur       | Echoue
//    ErrMontantSuperieurAuDu | reponse metier  | le dire a l'utilisateur       | Echoue
//    ErrIndisponible         | environnement   | reessayer avec recul          | Echoue
//    ErrIssueIncertaine      | environnement   | NE PAS reessayer, reconcilier | Incertain
//    ErrNonClasse            | inconnue        | alerter, NE PAS reessayer     | Incertain
//
// Les deux dernieres lignes sont celles qui distinguent cette conception de
// celle de l'enonce. Une defaillance dont on sait que rien n'a bouge et une
// defaillance dont on ne sait rien ne menent pas a la meme conduite, donc ce
// sont deux issues.
var (
    ErrSansReference        = errors.New("paiement : reference vide")
    ErrReferenceReutilisee  = errors.New("paiement : reference deja utilisee pour un autre paiement")
    ErrRefus                = errors.New("paiement : refuse par l'operateur")
    ErrMontantSuperieurAuDu = errors.New("paiement : montant superieur au reste a payer")
    ErrIndisponible         = errors.New("paiement : operateur ou base indisponible")
    ErrIssueIncertaine      = errors.New("paiement : issue indeterminee, reconciliation requise")
    ErrNonClasse            = errors.New("paiement : reponse de l'operateur non classee")
)

// MotifRefus precise POURQUOI l'operateur a refuse.
//
// Il n'y a qu'une sentinelle — ErrRefus — parce que la conduite de l'appelant
// est toujours la meme : le dire a l'utilisateur, ne pas reessayer. Le motif
// change le TEXTE, et le texte est l'affaire de la presentation, qui le
// recupere avec errors.As. C'est la regle « sentinelle pour la conduite, type
// pour la donnee ».
type MotifRefus int

const (
    SoldeInsuffisant MotifRefus = iota
    CodeSecretErrone
    PlafondAtteint
    CompteBloque
)

func (m MotifRefus) String() string {
    switch m {
    case SoldeInsuffisant:
        return "solde insuffisant"
    case CodeSecretErrone:
        return "code secret errone"
    case PlafondAtteint:
        return "plafond journalier atteint"
    case CompteBloque:
        return "compte bloque"
    }
    return fmt.Sprintf("motif(%d)", int(m))
}

// Refus est une erreur typee : elle porte une donnee dont la presentation a
// besoin pour choisir son texte.
type Refus struct{ Motif MotifRefus }

func (r Refus) Error() string { return ErrRefus.Error() + " : " + r.Motif.String() }

// Is rend errors.Is(err, ErrRefus) vrai pour tout Refus : la conduite se teste
// sur la sentinelle, le motif se lit avec errors.As.
func (r Refus) Is(cible error) bool { return cible == ErrRefus }

// Operateur est le contrat de l'operateur mobile money.
//
// Ses implementations DOIVENT traduire leurs erreurs dans le vocabulaire de
// ce paquet : c'est l'adaptateur qui connait les codes HTTP, pas le service.
//
// Collecter peut rendre ErrIssueIncertaine, et c'est sa particularite : un
// delai depasse ne dit pas si le debit a eu lieu.
type Operateur interface {
    Collecter(ctx context.Context, ref Reference, t scolarite.Telephone, m scolarite.Montant) (transaction string, err error)
    // Sort interroge l'operateur sur le destin d'une reference. C'est ce qui
    // rend l'etat Incertain RESOLUBLE au lieu d'etre definitif.
    Sort(ctx context.Context, ref Reference) (transaction string, paye bool, err error)
}

// Journal est notre etat durable. Reserver et Confirmer sont atomiques.
type Journal interface {
    // Reserver inscrit l'intention. Si la reference existe deja avec le meme
    // contenu, il rend le recu existant et rejeu = true ; avec un contenu
    // different, ErrReferenceReutilisee.
    Reserver(ctx context.Context, ref Reference, m scolarite.Matricule, mt scolarite.Montant) (recu Recu, rejeu bool, err error)
    // MarquerIncertain enregistre qu'une issue est indeterminee. C'est cette
    // ligne, et elle seule, qui rend la reconciliation possible : un etat
    // incertain qui n'est pas persiste est un etat perdu.
    MarquerIncertain(ctx context.Context, ref Reference) error
    Confirmer(ctx context.Context, ref Reference, transaction string) (Recu, error)
    ResteAPayer(ctx context.Context, m scolarite.Matricule) (scolarite.Montant, error)
}

type Service struct {
    Operateur Operateur
    Journal   Journal
}

// Payer encaisse un paiement de frais de scolarite.
//
// GARANTI
//
//   - Le Recu rendu porte toujours un Etat exploitable, Y COMPRIS avec une
//     erreur non nulle. Lis l'etat, pas seulement l'erreur : c'est lui qui
//     dit si l'argent a bouge.
//   - Deux appels avec la meme Reference et le meme contenu produisent au
//     plus un debit. Le second rend Rejeu = true.
//   - Un Etat Incertain est PERSISTE avant d'etre rendu. Il sera repris par
//     la reconciliation, meme si ce processus-ci meurt a la ligne suivante.
//   - Toute erreur rendue satisfait l'une des sentinelles de ce paquet.
//     Aucune erreur de pilote, de reseau ou de l'operateur ne traverse.
//
// CE QUI RESTE VRAI, PAR ISSUE
//
//    issue                   | etat      | l'argent a-t-il bouge ?
//    ------------------------|-----------|-------------------------
//    nil                     | Confirme  | oui, et c'est enregistre
//    nil (Rejeu)             | Confirme  | oui, lors d'un appel anterieur
//    ErrSansReference        | Echoue    | non
//    ErrReferenceReutilisee  | Echoue    | non
//    ErrRefus                | Echoue    | non — l'operateur a repondu
//    ErrMontantSuperieurAuDu | Echoue    | non — refuse avant l'appel
//    ErrIndisponible         | Echoue    | non — verifie, pas suppose
//    ErrIssueIncertaine      | Incertain | PEUT-ETRE
//    ErrNonClasse            | Incertain | PEUT-ETRE
//
// NON GARANTI
//
//   - Qu'un Etat Incertain se resolve tout seul. Resoudre existe pour ca, et
//     quelqu'un doit l'appeler.
//   - L'atomicite entre le debit chez l'operateur et l'ecriture chez nous.
//     Elle est IMPOSSIBLE : ce sont deux systemes separes par un reseau.
//     C'est precisement pourquoi Incertain existe, et il ne disparaitra pas.
//   - Une borne sur la duree d'un Etat Incertain. Elle est garantie par la
//     reconciliation et son alerte, pas par cette fonction.
//
// CONDUITE DE L'APPELANT
//
//   - Utilise Reessayable(recu, err). Ne reessaie JAMAIS sur la seule base de
//     l'erreur : ErrIndisponible et ErrIssueIncertaine sont toutes deux des
//     defaillances d'environnement, et une seule des deux est reessayable.
//   - Sur Incertain, n'affiche ni succes ni echec. Dis « en cours de
//     verification » et dissuade explicitement de recommencer.
//
// COUT
//
//   - Un appel reseau vers l'operateur, d'ou le context. Le delai du context
//     borne l'attente ; il ne borne pas l'incertitude.
//
// SURETE
//
//   - Sur pour un usage concurrent. Deux appels simultanes sur la meme
//     Reference produisent au plus un debit.
func (s *Service) Payer(ctx context.Context, ref Reference, m scolarite.Matricule, mt scolarite.Montant, t scolarite.Telephone) (Recu, error) {
    if ref == "" {
        return Recu{Etat: Echoue}, ErrSansReference
    }

    reste, err := s.Journal.ResteAPayer(ctx, m)
    if err != nil {
        return Recu{Reference: ref, Etat: Echoue}, indisponible("reste a payer", err)
    }
    if mt.Depasse(reste) {
        return Recu{Reference: ref, Etat: Echoue}, fmt.Errorf("%w : %s > %s",
            ErrMontantSuperieurAuDu, mt, reste)
    }

    recu, rejeu, err := s.Journal.Reserver(ctx, ref, m, mt)
    if err != nil {
        if errors.Is(err, ErrReferenceReutilisee) {
            return Recu{Reference: ref, Etat: Echoue}, err
        }
        return Recu{Reference: ref, Etat: Echoue}, indisponible("reservation", err)
    }
    if rejeu {
        recu.Rejeu = true
        return recu, nil
    }

    transaction, err := s.Operateur.Collecter(ctx, ref, t, mt)
    if err != nil {
        return s.apresEchecOperateur(ctx, ref, mt, err)
    }

    confirme, err := s.Journal.Confirmer(ctx, ref, transaction)
    if err != nil {
        // L'argent a bouge, notre ecriture a echoue. C'est le cas le plus
        // desagreable, et il est Incertain du point de vue de l'appelant :
        // il ne doit surtout pas reessayer.
        if err := s.Journal.MarquerIncertain(ctx, ref); err != nil {
            return Recu{Reference: ref, Etat: Incertain, Transaction: transaction},
                fmt.Errorf("%w : marquage impossible : %v", ErrIssueIncertaine, err)
        }
        return Recu{Reference: ref, Etat: Incertain, Transaction: transaction},
            fmt.Errorf("%w : debit effectue, enregistrement echoue", ErrIssueIncertaine)
    }
    return confirme, nil
}

// apresEchecOperateur distingue « rien n'a bouge » de « on ne sait pas ».
func (s *Service) apresEchecOperateur(ctx context.Context, ref Reference, mt scolarite.Montant, err error) (Recu, error) {
    switch {
    case errors.Is(err, ErrRefus), errors.Is(err, ErrIndisponible):
        // L'operateur a repondu : rien n'a bouge.
        return Recu{Reference: ref, Etat: Echoue, Montant: mt}, err

    default:
        // ErrIssueIncertaine, ErrNonClasse, ou tout ce qui n'a pas ete
        // classe : on ne sait pas, donc on persiste l'incertitude AVANT de
        // rendre la main.
        if erreurMarquage := s.Journal.MarquerIncertain(ctx, ref); erreurMarquage != nil {
            return Recu{Reference: ref, Etat: Incertain, Montant: mt},
                fmt.Errorf("%w : marquage impossible : %v", ErrIssueIncertaine, erreurMarquage)
        }
        if errors.Is(err, ErrIssueIncertaine) || errors.Is(err, ErrNonClasse) {
            return Recu{Reference: ref, Etat: Incertain, Montant: mt}, err
        }
        return Recu{Reference: ref, Etat: Incertain, Montant: mt},
            fmt.Errorf("%w : %v", ErrIssueIncertaine, err)
    }
}

// Resoudre tranche une issue incertaine en interrogeant l'operateur.
//
// C'est la piece qui transforme Incertain en etat TEMPORAIRE. Sans elle, le
// contrat exposerait une incertitude definitive, ce qui serait une mauvaise
// abstraction : on aurait rendu un probleme sans rendre son moyen.
func (s *Service) Resoudre(ctx context.Context, ref Reference) (Recu, error) {
    transaction, paye, err := s.Operateur.Sort(ctx, ref)
    if err != nil {
        return Recu{Reference: ref, Etat: Incertain}, indisponible("sort", err)
    }
    if !paye {
        return Recu{Reference: ref, Etat: Echoue}, nil
    }
    return s.Journal.Confirmer(ctx, ref, transaction)
}

// Reessayable prend le recu ET l'erreur.
//
// C'est la signature que la lecon annonce : la reessayabilite est une
// propriete du couple (erreur, etat). Un delai depasse est « reessayable » en
// tant qu'erreur et ne l'est pas du tout en tant qu'etat, parce que l'argent
// a peut-etre bouge.
func Reessayable(r Recu, err error) bool {
    if err == nil {
        return false
    }
    if r.Etat == Incertain {
        return false
    }
    return errors.Is(err, ErrIndisponible)
}

func indisponible(etape string, cause error) error {
    // %w sur notre sentinelle, %v sur la cause : l'identite ne devient pas
    // publique, le message reste lisible.
    return fmt.Errorf("%w : %s : %v", ErrIndisponible, etape, cause)
}
```

### Le tableau des issues, qui est le livrable principal

```
issue                   | nature          | conduite de l'appelant        | etat
------------------------|-----------------|-------------------------------|-----------
succes                  | —               | continuer                     | Confirme
Recu.Rejeu == true      | —               | continuer, sans rien refaire  | Confirme
ErrReferenceReutilisee  | appelant fautif | corriger le code appelant     | Echoue
ErrRefus (+ Refus)      | reponse metier  | le dire a l'utilisateur       | Echoue
ErrMontantSuperieurAuDu | reponse metier  | le dire a l'utilisateur       | Echoue
ErrIndisponible         | environnement   | reessayer avec recul          | Echoue
ErrIssueIncertaine      | environnement   | NE PAS reessayer, reconcilier | Incertain
ErrNonClasse            | inconnue        | alerter, NE PAS reessayer     | Incertain
```

Les deux dernières lignes sont la réponse à l'exercice. `ErrIndisponible` et
`ErrIssueIncertaine` sont **deux défaillances d'environnement** et elles
mènent à des conduites **opposées**. Les confondre — ce que fait l'énoncé —
produit le triple débit de la correction 1.5 / 1.

### `Etat` est rendu **avec** l'erreur

```go
func (s *Service) Payer(...) (Recu, error)
```

Et `Recu` porte un `Etat`, même quand l'erreur n'est pas nulle. C'est
inhabituel — on apprend qu'en cas d'erreur la valeur de retour n'a pas de
sens — et c'est ici indispensable :

> Une erreur dit ce qui a échoué. Elle ne peut pas dire ce qui reste vrai,
> parce que « ce qui reste vrai » n'est pas une propriété de l'échec : c'est
> une propriété du **système**. Il faut donc une seconde valeur.

Le commentaire du contrat le dit à l'appelant, parce que c'est contre-intuitif :

```
//   - Le Recu rendu porte toujours un Etat exploitable, y compris avec une
//     erreur. Lis l'etat, pas seulement l'erreur.
```

### La signature de `Reessayable`

```go
func Reessayable(r Recu, err error) bool {
    if err == nil {
        return false
    }
    if r.Etat == Incertain {
        return false
    }
    return errors.Is(err, ErrIndisponible)
}
```

Deux arguments, et c'est la contrainte 6. L'ordre des tests n'est pas
anodin : **l'état passe avant l'erreur.** Un `ErrIndisponible` rendu avec un
état `Incertain` ne serait pas réessayable, et c'est la bonne réponse — le
doute sur l'argent prime sur la nature de la panne.

### L'incertitude est persistée avant d'être rendue

```go
if erreurMarquage := s.Journal.MarquerIncertain(ctx, ref); erreurMarquage != nil {
    return Recu{...Etat: Incertain...},
        fmt.Errorf("%w : marquage impossible : %v", ErrIssueIncertaine, erreurMarquage)
}
```

C'est la réponse à la question 2 de la correction 1.5 / 1. Et remarque le cas
où le marquage lui-même échoue : on rend quand même `Incertain`, en disant que
le marquage a échoué. On ne prétend pas que tout va bien parce qu'on n'a pas
réussi à écrire qu'on ne va pas bien.

> Quand l'enregistrement d'un problème échoue, le problème ne disparaît pas :
> il devient seulement invisible. Rends-le, et dis que tu n'as pas pu l'écrire.

### `Resoudre` : l'incertitude doit avoir une issue

```go
// C'est la piece qui transforme Incertain en etat TEMPORAIRE. Sans elle, le
// contrat exposerait une incertitude definitive, ce qui serait une mauvaise
// abstraction : on aurait rendu un probleme sans rendre son moyen.
func (s *Service) Resoudre(ctx context.Context, ref Reference) (Recu, error)
```

C'est le point de conception le plus important après l'état lui-même.

Exposer `Incertain` sans fournir `Resoudre` serait honnête et inutilisable :
l'appelant saurait qu'il y a un problème et n'aurait aucun moyen de le
régler. C'est la leçon 1.4 par l'autre bout — on expose ce dont l'appelant a
besoin pour **tenir ses propres garanties**.

> Si tu exposes une incertitude, expose aussi le moyen de la lever. Une
> abstraction qui rend un problème sans son moyen n'a pas résolu le problème,
> elle l'a délégué.

### `Refus` : une sentinelle pour la conduite, un type pour la donnée

```go
type Refus struct{ Motif MotifRefus }

func (r Refus) Is(cible error) bool { return cible == ErrRefus }
```

Quatre motifs, une conduite, donc **une** sentinelle. `errors.Is(err, ErrRefus)`
pour décider, `errors.As(err, &refus)` pour choisir le texte. La méthode `Is`
sur le type est ce qui raccorde les deux.

C'est la contrainte 3 — *une sentinelle par conduite, pas une de plus* — et
c'est la seule fusion que je revendique. Les autres issues ont toutes des
conduites réellement distinctes.

## Contrainte 4 — le classement, et là où il vit

```go
// Package operateurhttp parle a l'operateur mobile money en HTTP.
//
// Raison de changer : le protocole de l'operateur et le classement de ses
// reponses.
//
// C'est le seul paquet du programme qui connaisse des codes HTTP de
// l'operateur. Tout ce qui sort d'ici parle le vocabulaire de paiement.
package operateurhttp

import (
    "context"
    "encoding/json"
    "fmt"
    "io"
    "net/http"
    "strings"

    "exemple/frais/paiement"
    "exemple/frais/scolarite"
)

// motifs associe les codes metier de l'operateur a nos motifs de refus.
//
// C'est une liste EXPLICITE. Un code absent de cette table n'est pas
// « probablement transitoire » : il est non classe, et ca fait du bruit.
var motifs = map[string]paiement.MotifRefus{
    "INSUFFICIENT_FUNDS": paiement.SoldeInsuffisant,
    "WRONG_PIN":          paiement.CodeSecretErrone,
    "LIMIT_EXCEEDED":     paiement.PlafondAtteint,
    "ACCOUNT_LOCKED":     paiement.CompteBloque,
}

// statutsIndisponibles est la liste EXPLICITE des statuts sur lesquels on
// accepte de reessayer. Tout le reste est non reessayable.
//
// L'inverse — reessayer par defaut sur tout ce qu'on ne comprend pas — est ce
// qui a produit l'incident de l'exercice 5 : un refus metier renvoye en 429 a
// declenche trois reessais par paiement, et le quota du compte marchand a
// ete brule en quatre minutes.
var statutsIndisponibles = map[int]bool{
    http.StatusServiceUnavailable: true, // 503
    http.StatusBadGateway:         true, // 502
    http.StatusGatewayTimeout:     true, // 504
}

type Client struct {
    HTTP *http.Client
    Base string
}

// Classer traduit une reponse de l'operateur dans notre vocabulaire.
//
// L'ordre des deux etapes est la decision la plus importante de ce fichier :
// le CODE METIER prime sur le STATUT HTTP. Le code dit ce qui s'est passe ;
// le statut dit comment le transport s'est comporte, et l'operateur peut le
// changer sans changer de version majeure.
func Classer(statut int, corps []byte) error {
    if statut == http.StatusOK {
        return nil
    }

    var charge struct {
        Code    string `json:"code"`
        Message string `json:"message"`
    }
    _ = json.Unmarshal(corps, &charge) // un corps illisible laisse Code vide

    if motif, connu := motifs[charge.Code]; connu {
        return paiement.Refus{Motif: motif}
    }

    if statutsIndisponibles[statut] {
        return fmt.Errorf("%w : statut %d : %s",
            paiement.ErrIndisponible, statut, extrait(corps))
    }

    // Defaut : non classe, donc non reessayable, donc bruyant. C'est le
    // detecteur : une reponse qui arrive ici est une reponse a laquelle
    // personne n'a encore reflechi.
    return fmt.Errorf("%w : statut %d, code %q : %s",
        paiement.ErrNonClasse, statut, charge.Code, extrait(corps))
}

// extrait borne et nettoie le corps avant de le mettre dans un message
// d'erreur : une reponse d'operateur peut contenir un numero de telephone, un
// jeton, ou deux mille lignes de HTML.
func extrait(corps []byte) string {
    s := strings.TrimSpace(string(corps))
    s = strings.ReplaceAll(s, "\n", " ")
    if len(s) > 200 {
        return s[:200] + "…"
    }
    return s
}

func (c *Client) Collecter(ctx context.Context, ref paiement.Reference, t scolarite.Telephone, m scolarite.Montant) (string, error) {
    corps, err := json.Marshal(map[string]any{
        "reference": string(ref), "msisdn": t.String(), "amount": m.FCFA(),
    })
    if err != nil {
        return "", fmt.Errorf("%w : encodage : %v", paiement.ErrNonClasse, err)
    }

    req, err := http.NewRequestWithContext(ctx, http.MethodPost,
        c.Base+"/collect", strings.NewReader(string(corps)))
    if err != nil {
        return "", fmt.Errorf("%w : requete : %v", paiement.ErrNonClasse, err)
    }
    req.Header.Set("Content-Type", "application/json")

    rep, err := c.HTTP.Do(req)
    if err != nil {
        // Une requete partie et sans reponse : on ne sait PAS si le debit a
        // eu lieu. C'est l'issue incertaine, et elle n'est pas reessayable.
        // Le %v protege l'identite de l'erreur de transport ; son message
        // reste pour le diagnostic.
        return "", fmt.Errorf("%w : appel sans reponse : %v", paiement.ErrIssueIncertaine, err)
    }
    defer rep.Body.Close()

    brut, err := lireBorne(rep)
    if err != nil {
        // Reponse coupee en cours de lecture : l'operateur a peut-etre
        // debite. Incertain, la aussi.
        return "", fmt.Errorf("%w : lecture de la reponse : %v", paiement.ErrIssueIncertaine, err)
    }

    if err := Classer(rep.StatusCode, brut); err != nil {
        return "", err
    }

    var reponse struct {
        Transaction string `json:"transaction_id"`
    }
    if err := json.Unmarshal(brut, &reponse); err != nil || reponse.Transaction == "" {
        // Statut 200 mais corps inexploitable : le debit a tres probablement
        // eu lieu et nous ne savons pas sous quelle reference. Incertain.
        return "", fmt.Errorf("%w : 200 sans identifiant de transaction : %s",
            paiement.ErrIssueIncertaine, extrait(brut))
    }
    return reponse.Transaction, nil
}

func (c *Client) Sort(ctx context.Context, ref paiement.Reference) (string, bool, error) {
    req, err := http.NewRequestWithContext(ctx, http.MethodGet,
        c.Base+"/collect/"+string(ref), nil)
    if err != nil {
        return "", false, fmt.Errorf("%w : requete : %v", paiement.ErrNonClasse, err)
    }

    rep, err := c.HTTP.Do(req)
    if err != nil {
        // Ici, le reessai est legitime : une consultation ne modifie rien.
        return "", false, fmt.Errorf("%w : consultation : %v", paiement.ErrIndisponible, err)
    }
    defer rep.Body.Close()

    brut, err := lireBorne(rep)
    if err != nil {
        return "", false, fmt.Errorf("%w : lecture : %v", paiement.ErrIndisponible, err)
    }
    if rep.StatusCode == http.StatusNotFound {
        return "", false, nil // l'operateur ne connait pas la reference : rien n'a bouge
    }
    if err := Classer(rep.StatusCode, brut); err != nil {
        return "", false, err
    }

    var reponse struct {
        Transaction string `json:"transaction_id"`
        Statut      string `json:"status"`
    }
    if err := json.Unmarshal(brut, &reponse); err != nil {
        return "", false, fmt.Errorf("%w : reponse illisible : %v", paiement.ErrIndisponible, err)
    }
    return reponse.Transaction, reponse.Statut == "SUCCESS", nil
}

const maxCorps = 1 << 20

func lireBorne(rep *http.Response) ([]byte, error) {
    return io.ReadAll(io.LimitReader(rep.Body, maxCorps))
}
```

### La décision centrale

```go
// L'ordre des deux etapes est la decision la plus importante de ce fichier :
// le CODE METIER prime sur le STATUT HTTP. Le code dit ce qui s'est passe ;
// le statut dit comment le transport s'est comporte, et l'operateur peut le
// changer sans changer de version majeure.
```

Le code métier d'abord, le statut HTTP ensuite. C'est ce qui rend le
classement robuste au changement de l'exercice 5 — un refus passé de `402` à
`429` reste un refus.

### Les deux listes sont explicites, et le défaut est « non classé »

```go
var statutsIndisponibles = map[int]bool{
    http.StatusServiceUnavailable: true, // 503
    http.StatusBadGateway:         true, // 502
    http.StatusGatewayTimeout:     true, // 504
}
```

Trois statuts, listés à la main. Tout le reste tombe dans `ErrNonClasse`, qui
n'est **pas** réessayable et qui fait du bruit.

> Une liste blanche vide par défaut vaut mieux qu'une liste noire. Avec une
> liste noire, chaque nouveauté du tiers est réessayable jusqu'à ce que
> quelqu'un l'interdise ; avec une liste blanche, elle est refusée jusqu'à ce
> que quelqu'un l'autorise. C'est la différence entre échouer ouvert et
> échouer fermé.

Et `429` n'est **pas** dans la liste, volontairement :

```go
// 429 n'y est pas, volontairement : « trop de requetes » signifie qu'on
// en envoie deja trop. Reessayer est exactement la mauvaise conduite.
```

### Les trois endroits qui produisent `ErrIssueIncertaine`

C'est la partie qu'on oublie en écrivant un adaptateur :

| Où | Pourquoi l'issue est incertaine |
|---|---|
| `HTTP.Do` rend une erreur | la requête est peut-être partie, et l'opérateur a peut-être débité |
| la lecture du corps échoue | l'opérateur a répondu, donc il a traité |
| statut 200 sans `transaction_id` | il a très probablement débité, et nous ne savons pas sous quelle référence |

Le troisième est le plus facile à manquer. Un `200` est un succès, donc on
suppose que tout va bien — mais un `200` avec un corps inexploitable est
exactement le cas où l'argent a bougé et où nous avons perdu la trace.

### Le corps est borné avant d'entrer dans un message

```go
    }
    // L'erreur porte les deux montants : l'appelant peut composer son message
    // sans relire la base.
    if !strings.Contains(err.Error(), "50000") || !strings.Contains(err.Error(), "10000") {
        t.Errorf("l'erreur devrait porter les deux montants : %v", err)
    }
}
```

Quatre tests méritent un commentaire.

**`TestUneIssueIncertaineNEstPasReessayableEtEstPersistee`** vérifie trois
choses d'un coup : l'erreur, l'état, et le fait que le marquage a eu lieu. Les
trois sont nécessaires : un état `Incertain` non persisté est un état perdu.

**`TestUneIndisponibiliteEstReessayableParceQueRienNaBouge`** est son
symétrique, et il contient l'assertion qu'on n'écrit pas :

```go
if len(j.incertains) != 0 {
    t.Errorf("%d marquage(s) inutile(s) : il n'y a rien a reconcilier", len(j.incertains))
}
```

Marquer `Incertain` une panne dont on sait que rien n'a bougé n'est pas
prudent, c'est bruyant : ça remplit la file de réconciliation de cas qui n'ont
rien à y faire, et au bout d'un mois personne ne la regarde plus.

**`TestDebitReussiEtEnregistrementEchoueDonneIncertain`** vérifie que
l'identifiant de transaction **survit** dans le reçu :

```go
if recu.Transaction != "T-42" {
    t.Errorf("transaction = %q : l'identifiant operateur doit survivre, c'est lui qui permet de reconcilier", recu.Transaction)
}
```

Sans lui, la réconciliation n'a rien pour chercher. C'est la donnée dont
l'appelant a besoin pour tenir sa garantie.

**`TestLIdentiteDuPiloteNeTraversePasMaisSonMessageOui`** est le test de la
leçon, avec une assertion de plus : `ope.appels == 0`. Une vérification
préalable qui échoue ne doit pas avoir appelé l'opérateur — sinon « rien n'a
bougé » est faux.

## Contrainte 7 — la table de correspondance

```go
// Package api traduit les issues de paiement en reponses HTTP.
//
// Raison de changer : le contrat HTTP et les textes vus par l'utilisateur.
package api

import (
    "errors"
    "log/slog"
    "net/http"

    "exemple/frais/paiement"
    "exemple/frais/scolarite"
)

// Reponse prend le recu ET l'erreur.
//
// C'est la consequence directe de la conception du paquet paiement : la
// reponse HTTP depend de l'etat autant que de l'erreur. Une issue incertaine
// n'est pas un echec — c'est un « on verifie » —, et aucune signature
// n'acceptant que l'erreur ne pourrait le dire.
func Reponse(r paiement.Recu, err error) (statut int, message string, niveau slog.Level) {
    statut = statutDe(r, err)
    return statut, messageDe(r, err), niveauDe(statut)
}

func statutDe(r paiement.Recu, err error) int {
    // L'etat passe avant l'erreur : un paiement dont on ne sait rien n'est ni
    // un succes ni un echec, et le dire au client est la seule conduite
    // honnete.
    if r.Etat == paiement.Incertain {
        return http.StatusAccepted // 202 : pris en compte, issue en cours de verification
    }

    switch {
    case err == nil:
        return http.StatusOK

    // Fautes de l'appelant : reessayer a l'identique ne servira a rien.
    case errors.Is(err, scolarite.ErrMatriculeFormat),
        errors.Is(err, scolarite.ErrTelephoneFormat),
        errors.Is(err, scolarite.ErrMontantInvalide),
        errors.Is(err, paiement.ErrSansReference):
        return http.StatusBadRequest
    case errors.Is(err, paiement.ErrReferenceReutilisee):
        return http.StatusConflict

    // Reponses metier : la requete est correcte, la reponse est « non ».
    case errors.Is(err, paiement.ErrRefus),
        errors.Is(err, paiement.ErrMontantSuperieurAuDu):
        return http.StatusUnprocessableEntity

    // Defaillance d'environnement : la seule categorie qui compte contre la
    // disponibilite annoncee.
    case errors.Is(err, paiement.ErrIndisponible):
        return http.StatusServiceUnavailable

    // Non classe : par construction, c'est un trou dans cette table ou dans
    // celle de l'adaptateur. Il doit faire du bruit.
    case errors.Is(err, paiement.ErrNonClasse),
        errors.Is(err, paiement.ErrIssueIncertaine):
        return http.StatusInternalServerError
    }
    return http.StatusInternalServerError
}

func messageDe(r paiement.Recu, err error) string {
    if r.Etat == paiement.Incertain {
        return "Votre paiement est en cours de verification aupres de l'operateur. " +
            "Ne recommencez pas : vous recevrez une confirmation d'ici quelques minutes."
    }

    // Le motif du refus se lit avec errors.As : une seule sentinelle pour la
    // conduite, un type pour le texte.
    var refus paiement.Refus
    if errors.As(err, &refus) {
        switch refus.Motif {
        case paiement.SoldeInsuffisant:
            return "Solde insuffisant sur votre compte mobile money."
        case paiement.CodeSecretErrone:
            return "Code secret errone. Verifiez votre code et recommencez."
        case paiement.PlafondAtteint:
            return "Plafond journalier atteint. Reessayez demain ou payez en deux fois."
        case paiement.CompteBloque:
            return "Votre compte mobile money est bloque. Contactez votre operateur."
        }
    }

    switch {
    case err == nil:
        return "Paiement enregistre."
    case errors.Is(err, scolarite.ErrMatriculeFormat):
        return "Matricule invalide : deux lettres suivies de six chiffres."
    case errors.Is(err, scolarite.ErrTelephoneFormat):
        return "Numero invalide : neuf chiffres commencant par 6."
    case errors.Is(err, scolarite.ErrMontantInvalide):
        return "Le montant doit etre strictement positif."
    case errors.Is(err, paiement.ErrSansReference):
        return "Requete incomplete : reference de paiement manquante."
    case errors.Is(err, paiement.ErrReferenceReutilisee):
        return "Cette reference a deja servi pour un autre paiement."
    case errors.Is(err, paiement.ErrMontantSuperieurAuDu):
        return "Le montant depasse le reste a payer."
    case errors.Is(err, paiement.ErrIndisponible):
        return "Service momentanement indisponible. Reessayez dans quelques instants."
    }
    return "Une erreur inattendue est survenue. Nos equipes sont prevenues."
}

// niveauDe derive le niveau de journal du statut, au lieu de le choisir site
// par site. Un developpeur qui ecrit log.Error au cas par cas finira par en
// mettre partout.
func niveauDe(statut int) slog.Level {
    switch {
    case statut == http.StatusAccepted:
        // Une issue incertaine n'est pas une panne, mais quelqu'un doit la
        // reconcilier : WARN, et une alerte sur le TAUX, pas sur l'unite.
        return slog.LevelWarn
    case statut < 400:
        return slog.LevelDebug
    case statut < 500:
        return slog.LevelInfo
    case statut == http.StatusServiceUnavailable:
        return slog.LevelWarn
    default:
        return slog.LevelError
    }
}
```

### La signature prend le reçu **et** l'erreur

```go
func Reponse(r paiement.Recu, err error) (statut int, message string, niveau slog.Level)
```

C'est la conséquence directe de la conception de `paiement`, et c'est ce qui
permet le choix suivant.

### Une issue incertaine donne **202**, pas 500

```go
if r.Etat == paiement.Incertain {
    return http.StatusAccepted // 202 : pris en compte, issue en cours de verification
}
```

Avec le message qui va avec :

> « Votre paiement est en cours de vérification auprès de l'opérateur. **Ne
> recommencez pas** : vous recevrez une confirmation d'ici quelques minutes. »

C'est la décision de produit la plus importante de tout l'exercice. Un `500`
dit « ça a échoué », donc le parent recommence, donc il paie deux fois. Un
`202` avec cette phrase est la seule réponse qui évite le second débit —
**et aucun contrat qui ne rendrait que l'erreur ne pourrait la produire.**

> La bonne réponse HTTP dépend de l'état, pas seulement de l'erreur. C'est la
> raison technique pour laquelle `Etat` est dans le reçu.

### Et un 202 n'est pas un succès pour autant

```go
case statut == http.StatusAccepted:
    // Une issue incertaine n'est pas une panne, mais quelqu'un doit la
    // reconcilier : WARN, et une alerte sur le TAUX, pas sur l'unite.
    return slog.LevelWarn
```

`WARN`, et une alerte sur le **taux**. Un paiement incertain par jour est
normal ; trente en dix minutes est un incident. L'alerte porte sur la
grandeur, pas sur l'événement.

Le dernier test vérifie une propriété qu'on ne pense pas à tester :

```go
func TestLesQuatreMotifsDonnentQuatreTextes(t *testing.T)
```

Les quatre motifs partagent une sentinelle — donc le `switch` sur `errors.Is`
ne les distingue pas — et doivent produire quatre textes distincts. Si
quelqu'un supprime un jour le `errors.As`, les quatre motifs donneront le même
message générique, et **aucun autre test ne le verrait**.

## Ce que ça ne règle pas

- **La réconciliation n'est pas écrite.** `Resoudre` existe, mais le processus
  qui l'appelle sur les références marquées incertaines, à quelle cadence, et
  qui regarde celles qu'il n'arrive pas à trancher : c'est l'exercice 4.
- **`ErrScolariteInconnue` manque.** Un matricule inconnu tombe dans
  `ErrIndisponible` via `Journal.ResteAPayer`. C'est le trou signalé à la
  correction 1.5 / 1, et il est réel.
- **L'atomicité entre `paiements` et `scolarites`** est reportée sur
  l'implémentation de `Journal.Confirmer`, qui doit les écrire dans une seule
  transaction. Le contrat le dit ; rien ne le vérifie, et un test de contrat
  partagé serait le bon outil — c'est la leçon 1.4 et l'objet de la 1.6.
- **Le quota de l'opérateur n'est pas borné.** Rien n'empêche mille paiements
  simultanés de saturer le compte marchand. Il faudrait le budget de la
  correction 1.4 / 5.

## À retenir

1. Une erreur dit ce qui a échoué ; elle ne peut pas dire ce qui reste vrai.
   Il faut une seconde valeur de retour, et le contrat doit dire de la lire.
2. Deux défaillances d'environnement peuvent exiger des conduites opposées :
   `ErrIndisponible` se réessaie, `ErrIssueIncertaine` jamais.
3. `Reessayable` prend l'erreur **et** l'état, et l'état passe en premier.
4. Une incertitude se persiste avant d'être rendue. Et si le marquage échoue,
   on le dit au lieu de prétendre que tout va bien.
5. Si tu exposes une incertitude, expose le moyen de la lever. Sinon tu as
   délégué le problème, pas résolu.
6. Une sentinelle pour la conduite, un type pour la donnée. La méthode `Is`
   sur le type raccorde les deux.
7. Le code métier prime sur le statut HTTP. Le statut peut changer sans
   version majeure ; le code, rarement.
8. Liste blanche vide par défaut, pas liste noire. Échoue fermé.
9. `429` n'est pas réessayable : « trop de requêtes » signifie qu'on en envoie
   déjà trop.
10. Un `200` au corps inexploitable est une issue incertaine, pas un succès.
11. Borne et nettoie un corps de réponse avant de le mettre dans une erreur :
    un journal se conserve des mois.
12. Un type qui porte une donnée sensible doit fournir sa forme publiable,
    sinon c'est la forme complète qui sera journalisée.
13. Une issue incertaine se répond en 202 avec « ne recommencez pas », jamais
    en 500. Un 500 fait payer deux fois.
14. Alerte sur le **taux** d'issues incertaines, pas sur l'événement.
