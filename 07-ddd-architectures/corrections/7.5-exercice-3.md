# Correction 7.5 — Exercice 3 : les règles en fonction

> Rappel de l'énoncé : sortir la vérification des dépendances du test,
> en une fonction qui signale les dépendances interdites, l'intérieur
> d'un autre module, et les dépendances dans les deux sens.

La solution est dans `ex3` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Une fonction pure**, des imports et une table d'autorisations en
  entrée, une liste triée en sortie : testable sans `go list`.
- **Trois règles** : la dépendance autorisée, la face publique seulement,
  pas de dépendance dans les deux sens.
- **Le test d'architecture** n'a plus qu'à lire `go list` et appeler
  `Check`.

## 1. La solution

```go
func Check(root string, imports map[string][]string, allowed map[string][]string) []string {
    moduleOf := func(pkg string) (string, bool) {
        rest, inside := strings.CutPrefix(pkg, root)
        if !inside {
            return "", false
        }
        name, _, _ := strings.Cut(rest, "/")
        return name, true
    }
    var broken []string
    for pkg, imps := range imports {
        from, checked := moduleOf(pkg)
        if !checked {
            continue
        }
        for _, imp := range imps {
            to, isModule := moduleOf(imp)
            if !isModule || to == from {
                continue
            }
            switch {
            case !slices.Contains(allowed[from], to):
                broken = append(broken, fmt.Sprintf("%s imports %s: the module %s may not use the module %s", pkg, imp, from, to))
            case imp != root+to:
                broken = append(broken, fmt.Sprintf("%s imports %s: the inside of the module %s", pkg, imp, to))
            }
        }
    }
    for a, tos := range allowed {
        for _, b := range tos {
            if a < b && slices.Contains(allowed[b], a) {
                broken = append(broken, fmt.Sprintf("the modules %s and %s use each other", a, b))
            }
        }
    }
    slices.Sort(broken)
    return broken
}
```

```text
--- PASS: TestWhatBreaksTheRules (0.00s)
ok      example/modular75/ex3   1.019s
```

La condition `a < b` ne signale chaque paire qu'une fois. La liste est
triée pour que le résultat ne dépende pas de l'ordre aléatoire des tables
de Go, et que le test puisse le comparer.

## 2. Pourquoi signaler `internal/`, que le compilateur refuse

Pour trois raisons :

- le compilateur ne connaît que les répertoires nommés `internal`. Une
  équipe qui range son intérieur dans `modules/payments/store`, sans
  `internal/`, n'est protégée que par `Check` ;
- `Check` signale **toutes** les violations d'un coup, avec la règle
  enfreinte, là où le compilateur s'arrête à la première erreur ;
- la même fonction peut servir à vérifier un projet dans un autre
  langage, ou des appels entre services, à partir d'une autre source que
  `go list`.

## Ce qu'il faut retenir

- Une règle d'architecture est une fonction qu'on teste comme une autre.
- La face publique d'un module est son seul point d'entrée, autorisé ou
  non.
- Deux modules qui dépendent l'un de l'autre n'en font qu'un, ou
  attendent un événement.
