# Correction 7.4 — Exercice 5 : les reçus qui ne partaient pas

> Rappel de l'énoncé : l'envoi des reçus lit le membre par une passerelle
> qui perd l'e-mail ; mesurer, expliquer, corriger.

L'audit, la correction et le test qui manquait sont dans `ex5` du module
de correction, verts sous `go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **237 membres** ont donné leur e-mail ; **aucun reçu** n'est parti en
  trois semaines. Il aurait dû en partir 489.
- **La cause** : la correspondance de la ligne vers l'entité, écrite avant
  l'e-mail, ne le copiait pas. Rien ne la traversait jusqu'aux reçus.
- **La correction tient en un champ**, et le test qui l'aurait vue en une
  fonction : une ligne enregistrée revient entière.

## 1. L'audit

```go
func Audit(table *db.Table, ids []string, last Week) Report {
    r := Report{Sent: last.Sent}
    for _, id := range ids {
        if row, err := table.Get(id); err == nil && row.Email != "" {
            r.WithEmail++
        }
    }
    r.Missed = r.WithEmail - r.Sent
    return r
}
```

## 2. Les chiffres

`cmd/december` rejoue les trois semaines avec la passerelle de
production, puis avec la passerelle corrigée :

```text
production [{2026-W49 0 600} {2026-W50 0 600} {2026-W51 0 600}]  audit {WithEmail:237 Sent:0 Missed:237}
fixed      [{2026-W49 82 518} {2026-W50 170 430} {2026-W51 237 363}]  audit {WithEmail:237 Sent:237 Missed:0}
```

- avec la passerelle de production, chaque dimanche : **0 envoyé, 600
  ignorés**, puisque chaque membre revient sans e-mail ;
- en fin de mois, **237 lignes** ont un e-mail, et **237 membres** n'ont
  rien reçu ;
- avec la passerelle corrigée : 82, puis 170, puis 237 reçus, soit
  **489 reçus** qui auraient dû partir.

## 3. Pourquoi seulement en décembre

L'e-mail avait été ajouté au profil des semaines plus tôt. L'écran de
profil l'écrivait (par la correspondance de l'entité vers la ligne, qui
était juste), et le réaffichait à partir de la **requête**, pas de la
ligne. La correspondance fausse, celle de la ligne vers l'entité, n'avait
**aucun lecteur** jusqu'aux reçus. C'est la survivante « ligne lue sans
e-mail » de la leçon, arrivée en production : une copie fausse, que
personne ne traverse, ne se voit que le jour où quelqu'un la traverse.

Et le cas d'utilisation des reçus traite l'absence d'e-mail comme un
choix du membre (« ignoré »), pas comme une anomalie : 600 membres
ignorés sur 600 n'ont alerté personne.

## 4. La correction et le test

```go
// Find reads a member.
func (g Whole) Find(id string) (entity.Member, error) {
    r, err := g.Table.Get(id)
    if err != nil {
        return entity.Member{}, err
    }
    return entity.Member{ID: r.ID, Name: r.Name, Phone: r.Phone, Town: r.Town, Email: r.Email}, nil
}
```

```go
// The test that was missing: a row comes back whole, every field of it.
func TestTheGatewayLosesNothing(t *testing.T) {
    table := db.NewTable()
    row := db.MemberRow{ID: "m1", Name: "Awa", Phone: "+237677123456", Town: "Douala", Email: "awa@example.org"}
    table.Put(row)
    m, err := Whole{table}.Find("m1")
    if err != nil || (db.MemberRow{ID: m.ID, Name: m.Name, Phone: m.Phone, Town: m.Town, Email: m.Email}) != row {
        t.Errorf("%+v %v", m, err)
    }
    if m, _ := (Members{table}).Find("m1"); m.Email != "" {
        t.Errorf("production gateway: %q", m.Email)
    }
}
```

Le test de l'exercice 2, `Survives`, appliqué à chaque paire de

## 5. Le compte rendu

1. **Quoi** : du 30 novembre au 20 décembre 2026 (semaines 49 à 51),
   aucun reçu hebdomadaire n'est
   parti ; 237 membres avaient donné leur e-mail, et 489 reçus manquent.
2. **Cause** : dans le profil en cercles, la correspondance de la ligne
   de la base vers l'entité ne copiait pas l'e-mail ; l'envoi des reçus
   était le premier cas d'utilisation à le lire depuis la base.
3. **Détection** : par les membres, trois semaines plus tard. L'envoi
   comptait 600 membres « sans e-mail » sur 600 sans que rien ne
   s'alarme.
4. **Correction** : la correspondance copie l'e-mail ; les 489 reçus sont
   envoyés en rattrapage.
5. **Prévention** : un test `Survives` pour chaque paire de
   correspondances du profil ; une alerte quand un envoi ignore plus de la
   moitié de ses destinataires ; et une question pour la suite : le profil
   mérite-t-il ses six cercles (exercice 3) ? Sans eux, il n'y aurait pas
   eu de correspondance à oublier.

## Ce qu'il faut retenir

- Une copie que personne ne traverse cache son erreur jusqu'à son premier
  lecteur.
- Un test générique de correspondance voit le champ oublié le jour où il
  est ajouté.
- Moins de copies, c'est moins d'endroits où perdre un champ.
