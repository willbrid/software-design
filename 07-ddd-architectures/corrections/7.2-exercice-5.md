# Correction 7.2 — Exercice 5 : les annulations comptées payées

> Rappel de l'énoncé : la version 2 de l'API de l'opérateur ajoute
> `REVERSED` ; le modèle partagé compte des cotisations dont l'argent
> est reparti ; auditer, corriger, rédiger.

L'audit, le rejeu et leurs tests sont dans `ex5` du module de
correction, verts sous `go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **71 cotisations comptées payées sans l'argent, 900 000 FCFA**, dans la
  première semaine de la version 2.
- **La cause est une ligne** : `c.Status != operator.Failed && c.Status !=
  operator.Pending`, qui fait de tout statut inconnu un paiement.
- **Par la couche anti-corruption**, le registre ne compte que les
  cotisations dont le dernier statut est un succès, et met de côté les 7
  rappels `EXPIRED`.

## 1. L'audit

```go
func Audit(log []Logged) Report {
    r := Report{ByTontine: map[int]int64{}, Unknown: map[string]int{}}
    type seen struct {
        tontine int
        amount  string
        counted bool // by the shared member
        last    operator.Status
    }
    byID := map[string]*seen{}
    var order []string
    for _, l := range log {
        c := l.Callback
        s := byID[c.ExternalID]
        if s == nil {
            s = &seen{tontine: l.Tontine, amount: c.Amount}
            byID[c.ExternalID] = s
            order = append(order, c.ExternalID)
        }
        s.last = c.Status
        if c.Status != operator.Failed && c.Status != operator.Pending {
            s.counted = true
        }
        switch c.Status {
        case operator.Successful, operator.Failed, operator.Pending, operator.Reversed:
        default:
            r.Unknown[string(c.Status)]++
        }
    }
    r.Contributions = len(byID)
    for _, id := range order {
        s := byID[id]
        if !s.counted || s.last == operator.Successful {
            continue
        }
        amount := amountOf(s.amount)
        r.Wrong++
        r.MissingFCFA += amount
        r.ByTontine[s.tontine] += amount
    }
    return r
}
```

L'audit reproduit les **deux** lectures : celle du modèle partagé (tout ce
qui n'est ni échoué ni en attente compte) et la vraie (le dernier statut
est un succès). Les cotisations où elles divergent sont l'écart.

## 2. Les chiffres

`cmd/week` :

```text
  tontine 7: 60000 FCFA missing

```

- **71 cotisations**, **900 000 FCFA** : les paiements réussis puis
  annulés (64), et les 7 `EXPIRED` ;
- les tontines les plus touchées perdent 60 000 FCFA chacune, de quoi
  rendre un versement impossible ;
- **7 rappels `EXPIRED`**, un statut que la documentation de la version 2
  ne mentionne même pas.

## 3. La cause

```go
    if c.Status != operator.Failed && c.Status != operator.Pending {
        m.PaidRounds[round]++
    }
```

La ligne définit « payé » **par exclusion** : est payé ce qui n'est pas un
échec connu. Pendant des années, l'opérateur n'avait que trois statuts,
et l'exclusion valait la liste. Le jour où il en a ajouté deux, ils sont
devenus des paiements. Une règle écrite par exclusion sur les mots d'un
autre système dépend de **tous ses mots futurs**.

Et la ligne était dans le domaine : chaque paquet qui lisait `LastPayment`
avait sa propre définition, et aucune n'était au même endroit que la
connaissance de l'opérateur.

## 4. La correction

```go
// Replay sends the callbacks of the week through the anti-corruption layer
// to the ledger of the payments context. It returns the contributions it
// counts as paid, and the callbacks it kept aside.
func Replay(log []Logged) (paid int, aside int) {
    ledger := payments.NewLedger()
    ids := map[string]bool{}
    for _, l := range log {
        c := l.Callback
        if !ids[c.ExternalID] {
            ids[c.ExternalID] = true
            ledger.Expect(c.ExternalID, amountOf(c.Amount))
        }
        e, err := acl.Translate(c)
        if err != nil {
            aside++
            continue
        }
        _ = ledger.Apply(e)
    }
    for id := range ids {
        if ledger.Confirmed(id) {
            paid++
        }
    }
    return paid, aside
}
```

Le test vérifie que le registre compte **exactement** les cotisations
dont le dernier statut est un succès, et met de côté autant de rappels
que d'`EXPIRED`. Les 64 annulations deviennent des `Reversed`, que le
registre retire.

## 5. Le compte rendu

1. **Quoi** : du 19 au 25 octobre 2026, 71 cotisations ont été comptées
   payées alors que l'argent n'était pas, ou plus, sur le compte :
   900 000 FCFA d'écart entre les cagnottes affichées et le compte.
2. **Cause** : la version 2 de l'API de l'opérateur a ajouté les statuts
   `REVERSED` et `EXPIRED` ; l'application comptait comme payé tout
   statut autre que `FAILED` et `PENDING`.
3. **Détection** : par les trésorières, en comparant la cagnotte et le
   compte. Rien ne signalait un statut inconnu.
4. **Correction** : les rappels passent par une couche anti-corruption
   qui traduit chaque statut connu et met de côté les autres ; le registre
   des paiements est rejoué sur la semaine ; les 71 membres sont prévenus
   que leur cotisation n'est pas payée.
5. **Prévention** : une alerte au premier rappel mis de côté ; la règle
   « payé » est définie une fois, dans le contexte des paiements, par la
   liste de ce qui confirme, jamais par exclusion ; un test d'architecture
   interdit d'importer le SDK de l'opérateur hors de la couche
   anti-corruption.

## Ce qu'il faut retenir

- Une règle écrite par exclusion sur les mots d'un autre dépend de tous
  ses mots futurs.
- Les mots d'un système extérieur s'arrêtent à la couche anti-corruption.
- Un statut inconnu se met de côté, et prévient quelqu'un.
