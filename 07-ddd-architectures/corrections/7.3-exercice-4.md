# Correction 7.3 — Exercice 4 : les ports de toute l'application

> Rappel de l'énoncé : lister les ports de l'application, leurs
> adaptateurs, dessiner l'hexagone, décrire `main`.

## En bref

- **Quatre canaux pilotent** l'application : HTTP, USSD, les rappels des
  opérateurs, la tâche de nuit.
- **Sept ports pilotés** : le stockage, l'outbox, les opérateurs, les SMS,
  l'identité, l'horloge, les identifiants.
- **`main` choisit et branche** ; aucun autre paquet ne connaît les
  adaptateurs de production.

## Les ports

| Port | Sens | Adaptateur de production | Adaptateur de test |
|---|---|---|---|
| le service (`app.Service`) | piloté par les canaux | — | — |
| HTTP | pilote | `httpapi` | `httptest` |
| USSD | pilote | `ussd` (exercice 2) | appel direct de `Handle` |
| rappels des opérateurs | pilote | un gestionnaire par opérateur, avec sa couche anti-corruption | appel direct |
| tâche de nuit (rappels) | pilote | une commande lancée par cron | appel direct de `Send` |
| `Rounds`, `Loans`… (stockage) | piloté | `pgstore` | `memstore`, et le contrat |
| `Outbox` (ordres à envoyer) | piloté | une table PostgreSQL, dans la transaction du tour | en mémoire, et le contrat |
| `Operator` (payer) | piloté | un client par opérateur | un faux qui répond selon un scénario |
| `Notifier` (SMS) | piloté | `sms.Gateway` | `sms.Recorder` |
| `Identity` (KYC) | piloté | le client du prestataire | un faux |
| `Clock` | piloté | `time.Now` | une heure fixée |
| `IDs` | piloté | identifiants aléatoires | une suite prévisible |

## L'hexagone

```text
   HTTP   USSD   rappels opérateurs   tâche de nuit
     \      |          |                  /
      v     v          v                 v
   +----------------------------------------+
   |   app.Service       (les cas)          |
   |      |                                 |
   |   domain : round, loan, membership     |
   |                                        |
   |  ports : Rounds Outbox Operator        |
   |          Notifier Identity Clock IDs   |
   +----------------------------------------+
        |      |       |       |      |
        v      v       v       v      v
    pgstore  outbox  opérateurs  SMS  KYC
     (PG)    (PG)    (HTTP)   (HTTP) (HTTP)
```

## `main`

1. lit la configuration (adresse de la base, des passerelles, secrets) ;
2. ouvre le pool PostgreSQL ;
3. construit les adaptateurs pilotés : `pgstore`, l'outbox, les clients
   des opérateurs, `sms.Gateway`, le client KYC, `time.Now` ;
4. construit `app.Service` avec eux ;
5. construit les adaptateurs qui pilotent : `httpapi`, l'USSD, les
   gestionnaires des rappels, et démarre le serveur HTTP ;
6. démarre le travailleur qui envoie l'outbox aux opérateurs.

C'est le seul fichier qui importe à la fois pgx, les clients HTTP et
l'application. Une version de test (`cmd/demo`) fait la même chose avec
les adaptateurs en mémoire, pour une démonstration sans aucune
dépendance.

## Ce qu'il faut retenir

- Un port par frontière, piloté ou qui pilote.
- Chaque port a un adaptateur de test, et un contrat quand il a un état.
- `main` assemble ; tout le reste ignore les adaptateurs de production.
