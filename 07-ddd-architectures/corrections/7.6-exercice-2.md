# Correction 7.6 — Exercice 2 : regrouper les questions

> Rappel de l'énoncé : un regroupeur qui rassemble les appels d'une
> fenêtre en une seule question au service.

La solution est dans `ex2` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Le premier appel ouvre une fenêtre** ; ceux qui arrivent pendant
  qu'elle est ouverte s'ajoutent au même lot.
- **À la fin de la fenêtre**, une seule question part, et chaque appelant
  lit sa réponse dans le résultat commun.
- **L'erreur du lot va à tous** ses appelants.

## 1. La solution

```go
// Confirmed reports whether a contribution is paid.
func (b *Batcher) Confirmed(ctx context.Context, contribution string) (bool, error) {
    b.mu.Lock()
    cur := b.pending
    if cur == nil {
        cur = &batch{done: make(chan struct{})}
        b.pending = cur
        time.AfterFunc(b.Window, func() { b.send(ctx, cur) })
    }
    cur.ids = append(cur.ids, contribution)
    b.mu.Unlock()
    select {
    case <-cur.done:
        return cur.out[contribution], cur.err
    case <-ctx.Done():
        return false, ctx.Err()
    }
}
```

```go
// send closes the window, asks the question, and wakes every caller.
func (b *Batcher) send(ctx context.Context, cur *batch) {
    b.mu.Lock()
    if b.pending == cur {
        b.pending = nil
    }
    ids := cur.ids
    b.mu.Unlock()
    cur.out, cur.err = b.Many.ConfirmedAmong(context.WithoutCancel(ctx), ids)
    close(cur.done)
}
```

Le lot est fermé (`b.pending = nil`) **avant** de poser la question :
un appel qui arrive pendant que la question est en route ouvre un nouveau
lot, au lieu de s'ajouter à un lot déjà parti.

La question part avec `context.WithoutCancel` : si le premier appelant
abandonne, les autres attendent toujours leur réponse. Chaque appelant
garde son propre contexte pour attendre, comme le chargement partagé de
la leçon 5.6.

## 2. Ce que coûte la fenêtre

Un appel **isolé** attend la fin de la fenêtre avant que la question ne
parte : 10 ou 20 ms de plus, pour rien. Le regroupeur échange la latence
de chaque appel contre le nombre d'appels. Il convient au code qui fait
beaucoup d'appels simultanés (un écran qui affiche un tour) ; pour un
appel seul, on appelle `ConfirmedAmong` directement. La bonne correction,
à terme, reste de réécrire la boucle en une question groupée, comme
l'exercice 3.

## Ce qu'il faut retenir

- Un regroupeur transforme N appels simultanés en un seul.
- Il fait payer une fenêtre à chaque appel isolé.
- C'est un pont pour le code qu'on n'a pas encore réécrit.
