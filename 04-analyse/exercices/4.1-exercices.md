# Exercices 4.1 — Comprendre le problème

Cinq exercices, du plus simple au plus ouvert. Traite-les **dans l'ordre** et
écris tes réponses dans `mes-reponses/` avant d'ouvrir les corrections.

Les exercices s'appuient sur les paquets `tontine`, `acceptance` et `v1` de
la [leçon 4.1](../cours/4.1-comprendre-le-probleme.md), recopiés tels quels
dans le module des exercices. Tout le code ci-dessous compile et passe
`go vet` ; les tontines, leurs membres et leurs présidentes sont
**fictifs**.

## Exercice 1 — Compréhension : lire les décisions

*Niveau 1. Aucune ligne de code à écrire.*

### 1.a — Qui a décidé ça ?

La trésorière a demandé, en une phrase : « *envoyez un rappel à ceux qui
sont en retard* ». Un développeur a écrit, le jour même :

```go
// Reminder is one SMS.
type Reminder struct {
    To   string
    Text string
}
```

```go
// Due returns the reminders to send at now for month m. The job runs every
// day at 08:00.
func Due(c *tontine.Cycle, m int, now time.Time) []Reminder {
    s, err := c.Settle(m, now)
    if err != nil || s.Pay {
        return nil
    }
    if now.Before(c.Due(m).AddDate(0, 0, -1)) {
        return nil
    }
    var out []Reminder
    for _, name := range s.Missing {
        text := fmt.Sprintf("Bonjour %s, votre cotisation de %s n'est pas arrivée. Merci de payer avant le %d.",
            name, c.Due(m).Format("01/2006"), c.Due(m).Day())
        out = append(out, Reminder{To: name, Text: text})
    }
    return out
}
```

Dresse le tableau de la section 3 de la leçon : pour chaque décision métier
que ce code prend, la ligne qui la prend, et ce que dit la demande. Il y en
a au moins sept. Marque celles qui te semblent **contraires** à la
demande, et pas seulement absentes.

### 1.b — INVEST

Pour chacun de ces récits, dis quelle lettre d'INVEST il manque le plus
nettement, en une phrase, puis réécris le plus mauvais :

1. « En tant que membre, je veux une appli rapide. »
2. « En tant que trésorière, je veux gérer la tontine. »
3. « En tant que développeur, je veux une table `payments` indexée par
   mois. »
4. « En tant que membre, je veux voir mon historique, une fois que la
   page de connexion par empreinte digitale sera faite. »
5. « En tant que présidente, je veux recevoir chaque soir à 20 h la liste
   des parts reçues dans la journée, afin de suivre la collecte. »

### 1.c — Les niveaux de Cockburn

Range chaque objectif au niveau « nuage », « mer » ou « poisson », et
justifie d'un mot :

1. Cotiser pour le mois.
2. Vérifier qu'un numéro Mobile Money a neuf chiffres.
3. Faire vivre la tontine pendant un cycle complet.
4. Tirer au sort l'ordre des bénéficiaires.
5. Calculer la pénalité d'un retard.
6. Rembourser un membre qui part.

// A share never paid is owed with its penalty, counted on the due date of

## Exercice 5 — Incident : les paiements de minuit

*Niveau 7. Un incident réel, à expliquer et à corriger.*

**Les faits.** La tontine du marché de Bonamoussadi (24 membres, 25 000
FCFA par mois) utilise depuis janvier le code de la leçon. En décembre, un
membre écrit au groupe :

```text
En juin j'ai payé le 6 à 14 h 45, j'ai eu 1 250 de pénalité. En juillet,
M02 a payé le 6 à 0 h 16 et il n'a rien eu. Et je ne suis pas le seul à
avoir remarqué : depuis juillet, tout le monde paie à minuit. C'est quoi
cette histoire ?
```

L'opérateur Mobile Money envoie l'heure de chaque paiement en UTC. Le
serveur enregistre la cotisation avec cette heure. L'écran de la
trésorière, rejoué sur l'année (`go run ./ex5/cmd/replay M02 M16`) :

```text
288 payments recorded, 66250 FCFA of penalties charged over the year
M02 month  7: callback 2026-07-05T23:16:00Z, penalty 0
M16 month  6: callback 2026-06-06T13:45:00Z, penalty 1250
```

Le paquet qui fabrique l'année de paiements, avec l'heure de l'opérateur :

```go
// Year returns the payments of twelve months. Most members pay in the four
// days before the due date; one in four is late, half of them by one day, the others by two to
// twelve days. The
// hour of the day is spread evenly, in Douala, except that from July on,
// the members one day late pay between midnight and one o'clock.
func Year() []Payment {
    r := rand.New(rand.NewPCG(41, 5))
    var out []Payment
    for m := 1; m <= 12; m++ {
        due := FirstDue.AddDate(0, m-1, 0)
        for _, name := range Members() {
            day := -r.IntN(5)
            if r.IntN(4) == 0 {
                day = 1 // half of the late are one day late
                if r.IntN(2) == 0 {
                    day = 2 + r.IntN(11)
                }
            }
            minute := r.IntN(24 * 60)
            if day == 1 && m >= 7 {
                minute %= 60 // the word went round on WhatsApp
            }
            at := due.AddDate(0, 0, day).Add(time.Duration(minute) * time.Minute)
            out = append(out, Payment{m, name, at.UTC()})
        }
    }
    return out
}
```

1. **Explique** pourquoi M02 n'a pas eu de pénalité. Montre la ligne de
   `tontine` responsable, et le calcul qu'elle fait sur le paiement de
   M02.
2. Le critère AC7 de la leçon disait « *payer le 5 à n'importe quelle
   heure, c'est à l'heure* », et son test passait. **Qu'est-ce qui manquait
   au critère**, et à ses exemples ?
3. **Combien** de paiements sont concernés sur l'année, et combien de
   pénalités n'ont pas été facturées ? Écris l'outil qui le mesure.
4. **Corrige** `tontine`, et écris le critère d'acceptation qui manquait.
5. La correction change le passé : faut-il réclamer les pénalités aux
   membres concernés ? Ce n'est pas à toi de décider ; prépare la décision
   pour le bureau, en trois options chiffrées.
6. Écris le **compte rendu** de l'incident en cinq lignes.
