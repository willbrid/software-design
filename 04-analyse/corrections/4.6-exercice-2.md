# Correction 4.6 — Exercice 2 : traduire les mots de l'opérateur

> Rappel de l'énoncé : écrire `callback.Translate`, qui traduit un code de
> statut et un montant de l'opérateur en événement du versement ; dire
> pourquoi un code inconnu est `Unknown` ; dire qui décide pour
> « 300000.00 ».

La solution est dans `ex2/callback` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Une liste blanche pour les refus**, tout le reste en `Unknown` : seul
  un refus explicite rend l'argent.
- Le montant est vérifié seulement quand l'opérateur dit « payé » : c'est
  le seul cas où l'argent a bougé.
- « 300000.00 » est refusé parce que le contrat ne l'a pas prévu ; c'est au
  contrat avec l'opérateur de trancher, pas au code.

## 1. La solution

```go
// Translate returns the event for answer a about a transfer of want FCFA.
// Only an explicit refusal gives the money back: every code it does not
// know is Unknown, and the reconciliation will ask.
func Translate(a Answer, want int64) (Event, error) {
    switch a.Status {
    case "00":
        got, err := strconv.ParseInt(a.Amount, 10, 64)
        if err != nil || got != want {
            return 0, fmt.Errorf("%w: %q for %d", ErrAmount, a.Amount, want)
        }
        return Confirm, nil
    case "05", "51":
        return Decline, nil
    default:
        return Unknown, nil
    }
}
```

Les mots de l'opérateur (« 00 », « 51 », un montant en texte) s'arrêtent
ici. Le cycle de vie du versement ne connaît que `Confirm`, `Decline` et
`Unknown`. Le jour où l'opérateur ajoute un code, seule cette fonction
change.

## 2. Pourquoi un code inconnu est `Unknown`

Traduire un code inconnu en `Decline`, c'est rendre l'argent au client
alors que l'opérateur a peut-être payé : exactement l'erreur de la
version 2 de l'exercice 5 de la leçon 3.5, qui avait payé deux fois
6 132 000 FCFA. `Unknown` met le versement en attente du rapprochement,
qui demandera à l'opérateur. La mutation « inconnu pris pour un refus »
est tuée par `TestAnythingElseIsUnknown`, dont c'est le seul rôle.

## 3. « 300000.00 »

Le contrat dit « un montant en FCFA », et la tontine n'a jamais vu de
centimes : le franc CFA n'en a pas en usage. Accepter « 300000.00 », ce
serait **deviner** que l'opérateur a voulu dire 300 000. Peut-être ; mais
le jour où il envoie « 300000.50 », que fait-on ? La traduction refuse ce
qu'elle ne connaît pas, avec `ErrAmount`, et l'alerte qui va avec fait
poser la question à l'opérateur. La décision appartient au **contrat**
entre la banque et l'opérateur ; le code la suit.

## 4. La campagne

Au premier passage, deux mutations ne compilaient pas (une variable, puis
un import devenus inutiles) ; elles ont été réécrites. Rejouée :

```text
erreur prise pour un refus                   tuee
51 oublié                                    tuee
inconnu pris pour un refus                   tuee
montant non comparé                          tuee
montant non lu                               tuee
5/5 tuees
```

## Ce qu'il faut retenir

1. Une couche anti-corruption traduit les mots de l'autre côté en
   événements de son propre modèle, et rien de plus.
2. Pour l'argent, on liste ce qui rend l'argent ; tout le reste attend.
3. Une donnée qui ne respecte pas le contrat se refuse et se signale ; on
   ne devine pas.
