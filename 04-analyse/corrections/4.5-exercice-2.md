# Correction 4.5 — Exercice 2 : les cycles entre couches

> Rappel de l'énoncé : écrire `layers.Cycles` ; dire si les règles
> d'`arch.Tontine` interdisent déjà les cycles ; proposer l'ADR qui en
> ferait une règle.

La solution est dans `ex2/layers` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Un graphe des couches**, puis une recherche de cycles qui ne part de
  chaque couche que vers les couches **suivantes** : chaque cycle est
  trouvé une fois, depuis sa première couche.
- **Oui, les règles de la tontine interdisent déjà tout cycle** : elles ne
  permettent que des flèches « vers le bas ». `Cycles` sert quand les règles
  ne sont pas encore écrites, ou pour un système plus libre, à **montrer**
  ce qui tourne en rond.

## 1. La solution

```go
// Cycles returns each cycle between the layers of a, starting from its
// layer that comes first in a.Layers. Each cycle is found once: from its
// first layer, the walk only goes through layers that come after it.
func Cycles(a arch.Architecture, edges []arch.Edge) [][]string {
    index := map[string]int{}
    for i, l := range a.Layers {
        index[l.Name] = i
    }
    next := map[int][]int{}
    for _, e := range edges {
        from, ok1 := index[a.LayerOf(e.From)]
        to, ok2 := index[a.LayerOf(e.To)]
        if ok1 && ok2 && from != to && !slices.Contains(next[from], to) {
            next[from] = append(next[from], to)
        }
    }
    for k := range next {
        slices.Sort(next[k])
    }
    var out [][]int
    for start := range a.Layers {
        var path []int
        var walk func(at int)
        walk = func(at int) {
            path = append(path, at)
            defer func() { path = path[:len(path)-1] }()
            for _, n := range next[at] {
                switch {
                case n == start:
                    out = append(out, slices.Clone(path))
                case n > start && !slices.Contains(path, n):
                    walk(n)
                }
            }
        }
        walk(start)
    }
    slices.SortStableFunc(out, func(x, y []int) int {
        if x[0] != y[0] {
            return x[0] - y[0]
        }
        return len(x) - len(y)
    })
    names := make([][]string, len(out))
    for i, c := range out {
        for _, l := range c {
            names[i] = append(names[i], a.Layers[l].Name)
        }
    }
    return names
}
```

Le cœur est la condition `n > start` : depuis la couche `start`, on ne
passe que par des couches qui viennent **après** elle. Un cycle n'est donc
trouvé que depuis sa couche la plus haute dans la liste, une seule fois, et
déjà dans l'ordre demandé. Sans cette condition (la mutation « cycles
trouvés plusieurs fois »), le cycle App ⇄ Adapt serait trouvé depuis App
**et** depuis Adapt.

## 2. Les règles de la tontine suffisent-elles ?

`arch.Tontine.Allow` ne permet que des flèches vers le domaine, ou de la
racine vers tout le monde : aucune couche n'importe une couche qui
l'importe. Tout cycle contient donc au moins une flèche interdite, que
`Violations` signale déjà. `Cycles` n'ajoute rien **pour ce projet**.

Il sert dans deux cas :

- **avant** d'avoir écrit les règles, sur un code existant : il montre les
  couches qui dépendent l'une de l'autre, c'est-à-dire celles qu'il faudra
  séparer, ou fusionner ;
- dans un système où les règles sont plus libres (des modules qui se
  parlent entre eux, au niveau 7), où l'on n'interdit pas chaque flèche,
  mais où l'on interdit **les boucles**.

## 3. L'ADR

```text
# ADR-0008 — Pas de cycle entre couches

- Statut : Proposée
- Date : 2027-03-10
- Vérifiée par : TestTheProjectHasNoCycle

## Contexte

Go refuse les cycles entre paquets, pas entre couches. Une couche qui
dépend d'une autre qui dépend d'elle ne peut plus être changée, testée ou
remplacée seule.

## Décision

Nous n'acceptons aucun cycle entre les couches de `arch.Tontine`.

## Conséquences

Une dépendance « vers le haut » se fait par une interface déclarée dans la
couche du bas (comme les ports de `app/closing`). Le test échoue à la
première boucle.
```

Le statut est « Proposée » : pour la tontine, la règle existe déjà dans
`Allow`, et l'équipe peut décider que cet ADR est inutile. Il prendrait
tout son sens le jour où `Allow` serait assoupli.

## 4. La campagne

```text
couche vers elle-même comptée                tuee
cycles trouvés plusieurs fois                tuee
les plus longs d'abord                       SURVIT
première couche à l'envers                   tuee
cycles de deux couches ignorés               tuee
4/5 tuees
```

« les plus longs d'abord » survit : aucun test n'avait deux cycles partant
de la même couche, de longueurs différentes. Un test de plus :

```go
// Added after the campaign: two cycles from the same first layer, the

func TestTheShorterCycleComesFirst(t *testing.T) {

```

## Ce qu'il faut retenir

1. Les cycles d'un graphe se trouvent une fois chacun si l'on ne part de
   chaque nœud que vers les nœuds suivants.
2. Des règles « vers le bas » interdisent déjà les cycles ; la recherche de
   cycles sert à explorer un code sans règles, ou des règles plus libres.
3. Un ADR peut rester « Proposée » : c'est aussi une trace utile, celle
   d'une règle envisagée et de la raison pour laquelle elle n'a pas été
   nécessaire.
