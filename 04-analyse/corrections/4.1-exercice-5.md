# Correction 4.1 — Exercice 5 : les paiements de minuit

> Rappel de l'énoncé : M02 a payé le 6 à 0 h 16, heure de Douala, sans
> pénalité ; M16 a payé le 6 à 14 h 45 et en a eu une. Expliquer, dire ce
> qui manquait au critère AC7, mesurer, corriger, préparer la décision du
> bureau, rédiger le compte rendu.

L'outil de mesure est `ex5/cmd/audit`, la correction `ex5/tontinefix`, et
le critère ajouté est un test de ce paquet ; tout est vert sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **La cause** : `daysLate` lit le jour du paiement **dans le fuseau du
  paiement**. L'opérateur envoie de l'UTC : 23 h 16 UTC le 5, c'est 0 h 16
  le 6 à Douala, mais pour le code c'est encore le 5.
- **Le critère AC7 était juste**, ses exemples étaient tous écrits à
  l'heure de Douala. Il manquait un exemple **tel que le monde extérieur
  l'envoie**.
- **15 paiements** concernés sur l'année, tous depuis juillet, et
  **18 750 FCFA** de pénalités non facturées. Le montant est faible ;
  l'injustice, elle, est visible par tous.
- **Trois options** pour le bureau, chiffrées. Ce n'est pas au
  développeur de choisir.

## 1. Pourquoi M02 n'a pas eu de pénalité

La fonction de la leçon :

```go
// daysLate counts calendar days after the due date: paying any time on the
// due date is on time.
func daysLate(due, at time.Time) int {
    day := time.Date(at.Year(), at.Month(), at.Day(), 0, 0, 0, 0, due.Location())
    if !day.After(due) {
        return 0
    }
    return int(day.Sub(due).Hours() / 24)
}
```

Le paiement de M02 arrive avec `at = 2026-07-05 23:16 UTC`. La ligne
`time.Date(at.Year(), at.Month(), at.Day(), ...)` lit l'année, le mois et
le jour **de `at` dans son propre fuseau**, l'UTC : le 5 juillet. Elle
fabrique le 5 juillet à minuit, heure de Douala, qui n'est pas après
l'échéance : zéro jour de retard. Le paiement de M16, à 13 h 45 UTC le 6
juin, est le 6 dans les deux fuseaux : un jour de retard, 1 250 FCFA.

Le défaut ne touche qu'une heure par jour, de minuit à 1 h à Douala, et
seulement les paiements en retard. C'est pourquoi il est resté invisible
six mois, jusqu'à ce que l'astuce circule sur WhatsApp. Les membres ont
trouvé le défaut avant les tests.

## 2. Ce qui manquait au critère

AC7 disait : « *payer le 5 à n'importe quelle heure, c'est à l'heure* ».
Ses exemples :

```go
// AC7. A late share costs 5 % per started week: one day late, 2 500; seven
// days, 2 500; eight days, 5 000. Paying on the due date, at any hour, is on
// time.
func TestAC7APenaltyPerStartedWeek(t *testing.T) {
    for _, c := range []struct {
        at   time.Time
        want int64
    }{
        {time.Date(2026, 11, 5, 23, 59, 0, 0, douala), 0},
        {nov(6), 2_500},
        {nov(12), 2_500},
        {nov(13), 5_000},
    } {
        d := given(t)
        pay(t, d, c.at, "Fon")
        got, err := d.Owed("Fon", nov(20))
        if err != nil || got != c.want {
            t.Errorf("paid %s: owes %d, %v; want %d", c.at.Format("Jan 2 15:04"), got, err, c.want)
        }
    }
}
```

Tous les instants sont construits avec `douala`. Le critère est juste ;
ses exemples supposent que l'heure arrive **déjà** dans le fuseau de la
tontine. Or l'heure ne vient pas d'un membre : elle vient de l'opérateur,
qui l'envoie en UTC. La question « l'heure de qui ? » n'a jamais été
posée, parce que la phrase « le 5 à n'importe quelle heure » semblait
claire.

La leçon à retenir pour l'analyse : **les exemples d'un critère doivent
avoir la forme des vraies entrées.** Si l'heure arrive en UTC, au moins un
exemple doit être écrit en UTC, et de préférence autour de minuit.

## 4. La correction, et le critère qui manquait

Une ligne :

```go
// daysLate counts calendar days after the due date, on the calendar of the
// due date: paying any time on the due date, in the tontine's zone, is on
// time. at may come in any zone (the operator sends UTC): it is read in the
// zone of the due date first.
func daysLate(due, at time.Time) int {
    at = at.In(due.Location())
    day := time.Date(at.Year(), at.Month(), at.Day(), 0, 0, 0, 0, due.Location())
    if !day.After(due) {
        return 0
    }
    return int(day.Sub(due).Hours() / 24)
}
```

Et le critère, écrit cette fois avec des instants tels que l'opérateur les
envoie :

```go
// AC14, the criterion that was missing: the examples are written as the
// operator sends them, in UTC.
//
// Given a due date on 5 November in Douala, when the operator reports a
// payment at 23:16 UTC on the 5th (00:16 on the 6th in Douala), then it is
// one day late: 2 500. At 23:30 UTC on the 4th (00:30 on the 5th in
// Douala), it is on time.
func TestAC14AnOperatorTimeInUTCIsReadInDouala(t *testing.T) {
    due := time.Date(2026, 11, 5, 0, 0, 0, 0, douala)
    for at, want := range map[time.Time]int64{
        time.Date(2026, 11, 5, 23, 16, 0, 0, time.UTC): 2_500,
        time.Date(2026, 11, 4, 23, 30, 0, 0, time.UTC): 0,
        time.Date(2026, 11, 5, 22, 59, 0, 0, time.UTC): 0, // 23:59 in Douala
        time.Date(2026, 11, 12, 23, 1, 0, 0, time.UTC): 5_000,
    } {
        c, err := tontine.NewCycle([]tontine.Member{{Name: "M02", Shares: 1}, {Name: "M16", Shares: 1}}, 50_000, due, 1)
        if err != nil {
            t.Fatal(err)
        }
        c.Contribute(1, "M02", at)
        if got, _ := c.Owed("M02", due.AddDate(0, 0, 20)); got != want {
            t.Errorf("callback %s: owes %d, want %d", at.Format(time.RFC3339), got, want)
        }
    }
}
```

Contre le code de la leçon (`go test -tags probe ./ex5/probe`, qui
exécute le même test sur `tontine`) :

```text
--- FAIL: TestAC14AnOperatorTimeInUTCIsReadInDouala (0.00s)
    midnight_probe_test.go:35: callback 2026-11-05T23:16:00Z: owes 0, want 2500
    midnight_probe_test.go:35: callback 2026-11-12T23:01:00Z: owes 2500, want 5000
FAIL
FAIL    example/corrections41/ex5/probe 0.003s
FAIL
```

Les deux exemples autour de minuit échouent, y compris un cas que
l'incident n'avait pas montré : un paiement le 13 juste après minuit,
compté sept jours au lieu de huit, donc **une** semaine de pénalité au lieu
de deux.

La correction ne change rien aux critères de la leçon, écrits à l'heure de
Douala. Les treize critères et les tests unitaires, rejoués avec le
`daysLate` corrigé à la place de l'ancien :

```text
ok      example/exercises41/acceptance  0.004s
ok      example/exercises41/tontine     0.004s
```

Une règle de conception en sort, plus générale que ce défaut : **convertir
à la frontière**. Toute heure qui entre dans le système (un *callback*, un
fichier, une saisie) est convertie dans le fuseau du métier à l'endroit où
elle entre, une fois, et le reste du code ne voit que des heures de
Douala.

## 5. La décision du bureau

| Option | Ce qu'on fait | Coût | Juste pour qui ? |
|---|---|---|---|
| A. Réclamer | facturer les 15 pénalités manquantes, 18 750 FCFA, aux 13 membres concernés | 18 750 FCFA récupérés ; des membres mécontents, qui ont suivi une astuce que le système acceptait | pour ceux qui ont payé leur pénalité |
| B. Tourner la page | corriger pour janvier, ne rien réclamer ni rendre, annoncer la correction | 18 750 FCFA perdus pour la caisse | pour personne en particulier ; le plus simple |
| C. Amnistie | rendre les 20 pénalités d'un jour déjà facturées, 25 000 FCFA, pour traiter tout le monde comme les payeurs de minuit | 25 000 FCFA de moins dans la caisse, en plus des 18 750 | pour tous, mais au prix de la caisse |

Le développeur prépare le tableau, et peut dire ce que chaque option
demande au système (A : quinze pénalités à ajouter à la main ; C : vingt
remboursements). Il ne choisit pas : c'est une question d'équité entre
membres, et elle appartient au bureau.

## Le compte rendu, en cinq lignes

1. **Quoi** : de juillet à décembre, 15 cotisations payées entre minuit et
   1 h, heure de Douala, le lendemain de l'échéance, ont été comptées à
   l'heure ; 18 750 FCFA de pénalités non facturées, et une inégalité
   visible entre membres.
2. **Pourquoi** : le calcul des jours de retard lisait le jour dans le
   fuseau de l'heure reçue ; l'opérateur envoie l'UTC, une heure de moins
   que Douala.
3. **Pourquoi personne ne l'a vu** : les exemples du critère de pénalité
   étaient tous écrits à l'heure de Douala, jamais dans la forme où
   l'opérateur envoie l'heure.
4. **Correction** : conversion dans le fuseau de la tontine à l'entrée du
   calcul ; nouveau critère AC14 avec des heures UTC autour de minuit.
5. **Ce qui reste ouvert** : la décision du bureau sur les pénalités
   passées (trois options chiffrées), et la revue des autres heures qui
   entrent dans le système.

## Ce qu'il faut retenir

1. Un critère juste peut avoir des exemples qui ne ressemblent pas aux
   vraies entrées. Écris au moins un exemple dans la forme exacte où le
   monde extérieur envoie la donnée.
2. Les heures se convertissent dans le fuseau du métier **à la
   frontière**, une fois.
3. Les utilisateurs trouvent les défauts qui les arrangent. Un écart
   d'une heure, connu de tous, coûte plus en confiance qu'en argent.
4. Réparer le passé est une décision d'équité, pas une décision
   technique : on chiffre les options, on ne choisit pas.
