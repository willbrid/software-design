# Correction 4.6 — Exercice 3 : séparer les contextes

> Rappel de l'énoncé : ranger chaque élément de `shared.Member` dans un
> contexte, écrire les deux contextes et la traduction, puis dire ce qui
> se passe quand un client change de téléphone à la banque.

La séparation est celle de la leçon, dans `contexts/` ; cette correction
la justifie élément par élément et répond à la question du téléphone.

## En bref

- **Deux champs sont communs**, le nom et le téléphone ; trois
  appartiennent chacun à un seul contexte.
- La règle « pas de pièce expirée » va à la banque ; « au moins une part »
  va à la tontine.
- Le changement de téléphone ne se **synchronise** pas automatiquement :
  c'est au membre de dire à la tontine où il veut recevoir sa cagnotte.

## 1. Élément par élément

| Élément de `shared` | Contexte | Pourquoi |
|---|---|---|
| `Name` | les deux | chacun en a besoin, avec le même sens |
| `Phone` | les deux, **mais pas le même** | pour la banque, le téléphone du titulaire du compte ; pour la tontine, le portefeuille où verser la cagnotte |
| `Shares` | tontine | la banque ne connaît pas les parts |
| `IDNumber`, `IDExpiry` | kyc | la tontine n'a jamais demandé de pièce |
| `Validate` (nom, téléphone) | les deux, chacun le sien | même forme, deux raisons |
| `Validate` (pièce expirée) | kyc | une règle de la conformité de la banque |
| `Register`, `Pot` | tontine | les règles de la tontine |

La ligne du téléphone est la découverte de l'exercice : le même champ a
**deux sens**, que le modèle partagé confondait.

## 2. Les contextes et la traduction

Ceux de la leçon :

```go
type Member struct {
    Name   string
    Phone  string
    Shares int
}
```

```go
type Customer struct {
    Name     string
    Phone    string
    IDNumber string
    IDExpiry time.Time
}
```

```go
func Member(c kyc.Customer, shares int) tontine.Member {
    return tontine.Member{Name: c.Name, Phone: c.Phone, Shares: shares}
}
```

Avec et sans la règle de la banque, les tests de la tontine passent : la
section 6 de la leçon le mesure (`go test -tags kycrule ./contexts/...`).

## 3. Le téléphone qui change à la banque

Trois mécanismes possibles :

| Mécanisme | Ce qui se passe | Problème |
|---|---|---|
| synchroniser : la banque met à jour la tontine | la cagnotte part vers le nouveau numéro | le membre voulait peut-être garder l'ancien portefeuille pour la tontine ; la banque décide pour la tontine |
| un événement « téléphone changé », que la tontine écoute | la tontine **prévient** le membre et lui demande s'il faut changer | un message de plus ; mais chaque contexte garde sa décision |
| rien | la tontine garde l'ancien numéro | si l'ancien portefeuille est fermé, le versement échoue (et la leçon 4.4 sait gérer un refus) |

La proposition est la deuxième. Le téléphone a deux sens, donc deux
propriétaires : la banque publie un fait (« le client a changé de
numéro »), la tontine décide ce qu'elle en fait, avec le membre. C'est la
réaction à un événement de la leçon 3.4, entre deux contextes ; le
niveau 8 la rendra fiable entre deux services.

## Ce qu'il faut retenir

1. Séparer des contextes commence par une liste, champ par champ, avec
   « à qui appartient ce sens ? ».
2. Un champ commun peut avoir deux sens : c'est souvent là que naissent
   les incidents.
3. Entre deux contextes, on publie des faits, et chacun décide de ce
   qu'il en fait.
