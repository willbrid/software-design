# Correction 4.5 — Exercice 3 : défaire le raccourci

> Rappel de l'énoncé : le domaine importe l'adaptateur de l'opérateur
> pour connaître ses frais. Refactorer sans changer le comportement,
> dire où vivent le barème et la règle, écrire l'ADR-0006.

La solution est dans `ex3` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **La règle reste dans le domaine, le barème en sort.** « Les frais sont
  retenus sur chaque virement » est une décision du bureau : elle est au
  domaine. « 1 %, au moins 100, au plus 2 000 » est le prix d'un
  opérateur : il est à l'adaptateur.
- Le domaine **reçoit** le barème, sous la forme d'une fonction
  `payout.Fees` ; la racine de composition lui donne `mobilemoney.FeeOf`.
- Les tests du domaine gardent leurs valeurs, avec un barème de test écrit
  dans le test : ils n'importent pas l'adaptateur non plus.
- La campagne a trouvé deux cas que les tests d'origine ne pouvaient pas
  voir.

## 1. Le refactoring

```go
// Fees is what the operator takes on a transfer. The adapter of each
// operator gives its own.
type Fees func(amount int64) int64
```

```go
// Split gives each holder their part, less the fee; the franc left by
// rounding goes to the first holder.
func Split(s tontine.Share, pot int64, fee Fees) []Transfer {
    out := make([]Transfer, len(s.Holders))
    var given int64
    for i, h := range s.Holders {
        part := pot * int64(h.Num) / int64(h.Den)
        out[i] = Transfer{To: h.Person, Amount: part}
        given += part
    }
    if len(out) > 0 {
        out[0].Amount += pot - given
    }
    for i := range out {
        out[i].Fee = fee(out[i].Amount)
        out[i].Amount -= out[i].Fee
    }
    return out
}
```

La racine de composition, seul endroit qui connaît les deux :

```go
func main() {
    svc := closing.Service{Fees: mobilemoney.FeeOf}
    half := tontine.Share{ID: "P05", Holders: []tontine.Holding{{Person: "Divine", Num: 1, Den: 2}, {Person: "Ebai", Num: 1, Den: 2}}}
    fmt.Println(svc.Transfers(half, 600_000))
}
```

```text
[{Divine 298000 2000} {Ebai 298000 2000}]
```

Le même résultat qu'avant le refactoring : 298 000 et 2 000 de frais pour
chacune. Le test d'architecture passe : six imports, aucun interdit.

Les tests du domaine changent seulement leur **appel** : ils passent un
barème écrit dans le test, avec les mêmes chiffres que l'opérateur.

```go
// kola is the schedule of the test: 1 %, at least 100, at most 2 000. The
// domain's tests do not import the adapter either.
func kola(amount int64) int64 { return min(max(amount/100, 100), 2_000) }
```

## 2. Où vivent le barème et la règle

| | Où | Pourquoi |
|---|---|---|
| la règle : « les frais sont retenus sur chaque virement, sur la part de chacun » | `domain/payout` | une décision du bureau, qui change avec lui |
| le barème : « 1 %, au moins 100, au plus 2 000 » | `adapter/mobilemoney` | le prix d'un opérateur, qui change avec lui ; Baobab Pay aura le sien |
| le lien entre les deux | `cmd/tontined` | la racine de composition : le seul endroit qui sait quel opérateur sert la tontine |

Le raccourci mélangeait les deux, avec une conséquence concrète : le jour
où un membre est servi par Baobab Pay (ADR-0004), le domaine aurait
appliqué le barème de Kola à son virement. La séparation rend ce cas
possible : la racine de composition passe le barème de l'opérateur du
membre.

## 3. L'ADR-0006

```text
# ADR-0006 — Les frais de l'opérateur sont retenus sur chaque virement

- Statut : Acceptée
- Date : 2027-03-03
- Vérifiée par : TestTheFeeIsTakenFromEachTransfer

## Contexte

Les frais de Mobile Money étaient payés par la caisse de la tontine, et
représentaient 4 % de ses dépenses en 2026. Le bureau a décidé, le 3 mars,
que chaque bénéficiaire les paie sur ce qu'il reçoit.

## Décision

Nous retenons les frais de l'opérateur sur chaque virement d'une
cagnotte, calculés sur la part de chaque titulaire. La règle est dans le
domaine ; le barème est donné par l'adaptateur de l'opérateur.

## Conséquences

Un bénéficiaire reçoit moins que la cagnotte, et le message au groupe doit
le dire. Un membre servi par un autre opérateur paie les frais de cet
opérateur. Une demi-part paie deux fois les frais minimaux sur une petite
cagnotte : le bureau l'a accepté.
```

Le chiffre de 4 % est un exemple : dans un vrai ADR, c'est le chiffre réel
de la tontine. La dernière conséquence est de celles qu'on oublie : la
règle « sur la part de chacun » fait payer **deux** minimums à une
demi-part. Elle est vraie, elle a un coût, et elle doit être écrite.

## 4. La campagne

```text
frais non retenus                            tuee
frais calculés sur la cagnotte               SURVIT
franc au dernier titulaire                   SURVIT
1/3 tuees
```

Deux survivantes, que les tests d'origine ne pouvaient pas voir :

- **« frais calculés sur la cagnotte »** : avec 600 000, la part (300 000)
  et la cagnotte donnent le même frais, le plafond de 2 000 ; et la petite
  cagnotte du second test est une part entière. Aucun test ne distinguait
  « frais sur la part » de « frais sur la cagnotte ».
- **« franc au dernier titulaire »** : aucun test n'avait de cagnotte
  impaire.

```go
// Added after the campaign: under the 2 000 cap, the fee of each half is
// on the half, not on the pot. With 600 000, both give the cap, and the
// first tests could not tell.
func TestTheFeeIsOnEachPartNotOnThePot(t *testing.T) {
    half := tontine.Share{ID: "P05", Holders: []tontine.Holding{{Person: "Divine", Num: 1, Den: 2}, {Person: "Ebai", Num: 1, Den: 2}}}
    got := payout.Split(half, 100_000, kola)
    want := []payout.Transfer{{To: "Divine", Amount: 49_500, Fee: 500}, {To: "Ebai", Amount: 49_500, Fee: 500}}
    if !slices.Equal(got, want) {
        t.Fatalf("%v", got)
    }
}
```

Rejouée :

```text
frais non retenus                            tuee
frais calculés sur la cagnotte               tuee
franc au dernier titulaire                   tuee
3/3 tuees
```

## Ce qu'il faut retenir

1. Un raccourci vers un adaptateur mélange souvent une **règle** (au
   domaine) et une **donnée d'un fournisseur** (à l'adaptateur) : sépare-les.
2. Le domaine reçoit ce qu'il ne doit pas connaître, sous la forme la plus
   simple qui suffit, ici une fonction.
3. Les tests du domaine n'importent pas les adaptateurs non plus : ils
   écrivent leurs propres données.
4. Un test dont les chiffres tombent sur un plafond ne distingue pas deux
   calculs : choisis des chiffres sous le plafond.
