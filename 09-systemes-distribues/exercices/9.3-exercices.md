# Exercices 9.3 — La surcharge

Cinq exercices, du plus simple au plus ouvert. Traite-les **dans l'ordre** et
écris tes réponses dans `mes-reponses/` avant d'ouvrir les corrections.

Les exercices s'appuient sur les paquets de la
[leçon 9.3](../cours/9.3-la-surcharge.md) (`work`, `admit`, `limit`,
`loadgen`), recopiés tels quels dans le module des exercices. Ils n'ont
besoin que de la bibliothèque standard. Tout le code ci-dessous compile
et passe `go vet` ; les tontines et l'incident sont **fictifs**.

## Exercice 1 — Compréhension : refuser, et comment

*Niveau 1. Aucune ligne de code à écrire.*

### 1.a — Six situations

Pour chacune, dis s'il faut servir, faire attendre, ou refuser, et avec
quel statut.

1. Un membre envoie sa troisième cotisation de la seconde (il appuie
   nerveusement).
2. Le serveur a 4 requêtes en cours et 4 en file ; une cotisation arrive.
3. Même situation ; une demande de rapport annuel arrive.
4. Le script d'un partenaire dépasse sa limite de 10 requêtes par seconde.
5. Une requête attend dans la file depuis 900 ms ; le membre a 1 s de
   patience.
6. Le serveur a 1 requête en cours sur 4 places ; une demande de rapport
   arrive.

### 1.b — Les paramètres

Le serveur des paiements a une capacité mesurée de 400 requêtes par
seconde (leçon 9.1), avec 16 connexions utiles, et des requêtes de 40 ms.
Les membres attendent 2 s au plus. Propose `MaxInFlight`, `MaxQueue`,
`MaxWait`, et justifie.

### 1.c — Trois pourquoi

1. Pourquoi le serveur qui laisse tout entrer sert-il moins que celui qui
   refuse ?
2. Pourquoi l'admission seule ne protège-t-elle pas les membres du script
   du partenaire ?
3. Pourquoi les rapports gardent-ils une part de la file, au lieu de
   n'avoir droit qu'aux places libres ?

## Exercice 5 — Incident : le script du partenaire du 7 décembre

*Niveau 7. Un incident à mesurer, puis à rejouer comme il aurait dû
être fait.*

Le lundi 7 décembre 2026 à 9 h, une banque partenaire lance un script de
rapprochement qui interroge l'API 300 fois par seconde. Pendant deux
heures, les membres voient « service surchargé » à chaque paiement.

```go
// Morning sends the traffic for d, with or without a limit per client of
// 10 per second, and returns the outcomes of "members" and "partner".
func Morning(d time.Duration, perClient bool) map[string]*loadgen.Class {
    s := work.New(4, 40*time.Millisecond)
    c := &admit.Controller{MaxInFlight: 4, MaxQueue: 4, MaxWait: 100 * time.Millisecond, LowShare: 1}
    l := &limit.PerClient{Rate: 10, Burst: 10}
    return loadgen.Run(360, d, time.Second,
        func(i int) loadgen.Request {
            if i%6 == 0 {
                return loadgen.Request{Client: fmt.Sprintf("phone-%03d", (i/6)%600), Priority: admit.High}
            }
            return loadgen.Request{Client: "partner-script", Priority: admit.High}
        },
        func(r loadgen.Request) string {
            if r.Client == "partner-script" {
                return "partner"
            }
            return "members"
        },
        func(ctx context.Context, r loadgen.Request) error {
            if perClient && !l.Allow(r.Client, time.Now()) {
                return loadgen.ErrLimited
            }
            release, err := c.Admit(ctx, r.Priority)
            if err != nil {
                return err
            }
            defer release()
            return s.Do(ctx)
        })
}
```
