# Correction 9.2 — Exercice 2 : écouter le service

> Rappel de l'énoncé : `Retryable`, qui décide si l'échec se réessaie, et
> `Pause`, qui suit le `Retry-After` du service.

La solution est dans `ex2` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **D'abord la méthode** : une écriture sans clé ne se réessaie jamais.
- **Ensuite le statut** : 429, 502, 503, 504, ou pas de réponse.
- **`Retry-After`** a deux formes, des secondes ou une date ; on plafonne
  au maximum de la politique.

## 1. La solution

```go
func Retryable(c Call) bool {
    if c.Method != http.MethodGet && !c.HasKey {
        return false
    }
    if c.Resp == nil {
        return true
    }
    switch c.Resp.StatusCode {
    case http.StatusTooManyRequests, http.StatusBadGateway, http.StatusServiceUnavailable, http.StatusGatewayTimeout:
        return true
    }
    return false
}
```

```go
func Pause(c Call, n int, p retry.Policy, now time.Time) time.Duration {
    if c.Resp == nil {
        return p.Pause(n)
    }
    h := c.Resp.Header.Get("Retry-After")
    if s, err := strconv.Atoi(h); err == nil && s >= 0 {
        return min(time.Duration(s)*time.Second, p.Max)
    }
    if at, err := http.ParseTime(h); err == nil {
        return min(max(at.Sub(now), 0), p.Max)
    }
    return p.Pause(n)
}
```


`http.ParseTime` lit les trois formats de date que HTTP admet. Une date
déjà passée donne une pause de 0 ; une valeur illisible (`soon`) retombe
sur la pause de la politique, plutôt que d'échouer.

## 2. Le 500 et le 502

Un **502** (*Bad Gateway*) dit qu'un intermédiaire n'a pas obtenu de
réponse du service : la requête n'a probablement pas été traitée, et la
clé protège de toute façon. Un **500** dit que le service lui-même a
échoué **en traitant** la requête : il a peut-être fait une partie du
travail. Avec une clé, la seconde tentative serait sans danger en
théorie ; mais un 500 est un défaut, pas une panne passagère, et le
réessayer en boucle cache le défaut et charge un service malade. On le
remonte, et on le surveille.

## 3. Le plafond

`Retry-After: 120` est plafonné à 30 s. Un service peut demander deux
minutes ; l'écran ne les a pas. Le plafond garde la décision chez
l'appelant : attendre ce qu'il peut, ou renoncer et le dire.

## Ce qu'il faut retenir

- La méthode d'abord, le statut ensuite.
- Le service dit quand revenir ; l'appelant décide s'il peut attendre.
- Un 500 est un défaut, pas une panne passagère.
