# Correction 9.6 — Exercice 3 : l'expiration lue sur la bonne horloge

> Rappel de l'énoncé : vérifier une session ouverte par une autre
> instance sans dépendre de l'horloge de l'instance qui vérifie.

La solution est dans `ex3` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **La base compare** l'échéance avec son `now()`, l'horloge qui l'a
  écrite.
- **L'instance ne lit plus l'heure** pour décider.
- **Une erreur de la base** remonte au lieu de dire « session invalide ».

## 1. La solution

```go
func Valid(ctx context.Context, pool *pgxpool.Pool, clock Clock, token string) (bool, error) {
    var ok bool
    err := pool.QueryRow(ctx, `SELECT exists (SELECT 1 FROM sessions WHERE token = $1 AND expires_at > now())`, token).Scan(&ok)
    return ok, err
}
```

```text
ok      example/corrections96/ex3       1.372s
```

Le code d'origine avait un second défaut : il transformait **toute**
erreur en « session invalide », y compris une base injoignable. Un
membre déconnecté par une panne de la base croit que sa session a
expiré. La correction renvoie l'erreur ; `exists` répond `false` pour
une session absente, sans erreur.

## 2. Garder `clock` ?

Le paramètre ne sert plus. Le garder trompe le lecteur, qui croira que
l'horloge de l'instance compte, et les tests, qui croiront tester un
décalage. On le retire, et on retire `Clock` du paquet s'il ne sert
nulle part ailleurs. Il reste ici pour que les tests de l'exercice
compilent avec la même signature ; dans un vrai code, sa disparition
serait le signe le plus clair que la décision a changé de place.

## Ce qu'il faut retenir

- Une échéance se compare avec l'horloge qui l'a écrite.
- Une erreur n'est pas une réponse négative.
- Un paramètre inutile ment au lecteur.
