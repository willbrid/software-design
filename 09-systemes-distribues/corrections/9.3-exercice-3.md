# Correction 9.3 — Exercice 3 : ne pas travailler pour personne

> Rappel de l'énoncé : arrêter le calcul du rapport dès que l'appelant
> est parti.

La solution est dans `ex3` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Le contexte se vérifie avant chaque morceau**.
- **L'erreur du contexte** remonte telle quelle : l'appelant sait
  pourquoi le calcul s'est arrêté.
- **Le morceau en cours** finit : on ne peut pas arrêter une requête de
  20 ms au milieu, sauf à lui passer le contexte.

## 1. La solution

```go
func Report(ctx context.Context) (int64, error) {
    var total int64
    for i := range 10 {
        if err := ctx.Err(); err != nil {
            return 0, err
        }
        total += chunk(i)
    }
    return total, nil
}
```

## 2. Avant, et pas après

Vérifier **avant** un morceau évite de le commencer ; vérifier **après**
constate qu'il a été fait pour rien. Le troisième test le montre : un
appelant déjà parti ne doit faire calculer **aucun** morceau. Avec une
vérification après, il en ferait calculer un.

Dans le code réel, chaque morceau est une requête SQL : on lui passe le
contexte (`pool.Query(ctx, ...)`), et PostgreSQL l'annule elle-même
quand l'appelant part. La vérification entre les morceaux protège ce
qui ne prend pas de contexte (un calcul en Go, un appel à une
bibliothèque).

## Ce qu'il faut retenir

- On vérifie le contexte avant de commencer un travail.
- On passe le contexte à tout ce qui l'accepte.
- Le travail pour personne est la part invisible de la surcharge.
