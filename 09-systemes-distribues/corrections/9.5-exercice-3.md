# Correction 9.5 — Exercice 3 : un tri qui ne parle pas SQL

> Rappel de l'énoncé : un tri choisi par l'écran, qu'on ne peut pas
> passer en paramètre, sans laisser le texte reçu devenir du SQL.

La solution est dans `ex3` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Un nom de colonne ne peut pas être un paramètre** : PostgreSQL
  n'accepte de paramètres que pour les valeurs.
- **Une liste fermée** traduit ce que l'écran demande en SQL écrit dans le
  code.
- **Le texte reçu ne sert que de clé** : il n'entre jamais dans la
  requête.

## 1. La solution

```go
// sorts maps what the screen may ask to SQL written here, never to text
// received: the only strings pasted into the query are these.
var sorts = map[string]string{
    "name": "name, id", "name desc": "name DESC, id",
    "joined": "joined_on, id", "joined desc": "joined_on DESC, id",
    "balance": "balance, id", "balance desc": "balance DESC, id",
}
```

```go
func List(ctx context.Context, pool *pgxpool.Pool, sort string) ([]string, error) {
    order, ok := sorts[sort]
    if !ok {
        return nil, ErrSort
    }
    rows, err := pool.Query(ctx, "SELECT id FROM members ORDER BY "+order)
    if err != nil {
        return nil, err
    }
    return pgx.CollectRows(rows, pgx.RowTo[string])
}
```

```text
ok      example/corrections95/ex3       1.132s
```

Chaque tri finit par `id` : deux membres de même nom, ou de même solde,
sortent toujours dans le même ordre, et la pagination (leçon 5.5) reste
stable.

## 2. Ce qu'apprend le tri par `CASE`

Le deuxième cas ne lit aucune colonne interdite dans le résultat : il
renvoie des identifiants, comme un tri normal. Mais **l'ordre** dépend
d'une question posée à la base : « la première lettre de l'empreinte du
code PIN de `m2` est-elle `b` ? ». Si oui, la liste est triée par nom ;
sinon, par solde. En regardant l'ordre, l'attaquant lit la réponse. En
posant la question lettre par lettre, il reconstitue l'empreinte, sans
qu'elle apparaisse jamais dans une réponse. C'est une injection
**aveugle** : la sortie de l'exercice d'origine montre que la requête est
passée.

Le rôle limité de la leçon l'aurait arrêtée ici (il ne lit pas
`pin_hash`) ; la liste fermée l'arrête avant même la base.

## Ce qu'il faut retenir

- Valeurs : des paramètres ; noms : une liste fermée.
- Une injection peut fuir par l'ordre, le temps ou les erreurs, pas
  seulement par le résultat.
- Un tri se termine par une clé unique.
