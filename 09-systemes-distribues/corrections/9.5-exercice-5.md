# Correction 9.5 — Exercice 5 : les confirmations rejouées du 14 décembre

> Rappel de l'énoncé : un webhook qui ne vérifie que la signature,
> des renvois de l'opérateur et des copies capturées ; mesurer, rejouer,
> rédiger.

L'audit et le rejeu sont dans `ex5` du module de correction, verts sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **109 cotisations créditées plusieurs fois, 4 820 000 FCFA de trop** :
  680 crédits en plus pour 2 000 confirmations.
- **La plupart des cotisations doublées viennent de l'opérateur lui-même**
  (80 renvois honnêtes) ; les 30 copies capturées pèsent plus lourd en
  argent (600 crédits de trop).
- **Avec l'horodatage et l'identifiant**, aucun crédit de trop.

## 1. L'audit

```go
func Audit(credits []Credit, truth map[string]int64) Report {
    r := Report{Confirmed: len(truth), Credits: len(credits)}
    times := map[string]int{}
    for _, c := range credits {
        times[c.Contribution]++
        amount, known := truth[c.Contribution]
        switch {
        case !known:
            r.Unknown++
            r.OverFCFA += c.Amount
        case times[c.Contribution] > 1:
            r.OverFCFA += amount
        }
    }
    for id, n := range times {
        if _, known := truth[id]; known && n > 1 {
            r.CreditedTwice++
        }
    }
    return r
}
```

## 2. Les chiffres, et le rejeu

`cmd/monday` rejoue la journée deux fois :

```text
2,000 confirmations; the operator sends 4 % again; 30 captured confirmations are sent 20 more times each

receiver checks               confirmed  credits  credited twice  over FCFA  unknown
the signature                      2000     2680             109    4820000        0
signature, time, and id            2000     2000               0          0        0
```

- **La signature seule** : 2 680 crédits pour 2 000 confirmations.
  L'opérateur renvoie 80 confirmations après un délai de son côté (4 %) :
  ce sont des renvois **honnêtes**, et la signature les accepte, puisqu'ils
  sont vrais. Les 30 confirmations capturées sont renvoyées 20 fois
  chacune : 600 crédits de plus, signés eux aussi. **109 cotisations**
  sont créditées plusieurs fois (80 + 30, une se retrouvant dans les deux
  groupes), pour **4 820 000 FCFA**.
- **Signature, horodatage et identifiant** : les renvois de l'opérateur
  arrivent 40 s après, dans la fenêtre, mais avec un identifiant déjà vu ;
  les copies arrivent 17 minutes et plus après, hors de la fenêtre. Aucun
  crédit de trop.

La leçon 8.3 l'avait dit pour les messages : tout ce qui arrive « au
moins une fois » arrive parfois deux fois. Un webhook est un message
comme un autre ; la protection contre le rejeu malveillant et contre la
livraison en double est la même : un identifiant qu'on ne traite qu'une
fois.

## 3. La cause

**En une phrase** : l'adresse de confirmation acceptait toute
confirmation correctement signée, autant de fois qu'elle arrivait, et le
tableau créditait chaque arrivée.

**La cause de la cause** : la signature avait été prise pour une
protection complète. Elle prouve **qui** a écrit le message, pas **combien
de fois** il est arrivé ni **quand** il a été écrit. Personne n'avait
pensé aux renvois de l'opérateur, documentés pourtant dans son contrat
d'interface, et un serveur intermédiaire mal configuré gardait les
confirmations.

## 4. Le compte rendu

1. **Quoi** : le lundi 14 décembre 2026, 109 cotisations ont été
   créditées plusieurs fois sur le tableau des tours, pour 4 820 000 FCFA
   de plus que les versements de l'opérateur.
2. **Cause** : l'adresse de confirmation ne vérifiait que la signature ;
   les 80 renvois de l'opérateur et les 600 copies envoyées depuis un
   serveur intermédiaire ont tous été crédités.
3. **Détection** : par la trésorière, le soir, au rapprochement avec le
   relevé de l'opérateur.
4. **Correction** : les crédits en double sont annulés d'après le relevé ;
   l'adresse vérifie désormais l'horodatage (5 minutes) et n'accepte un
   identifiant qu'une fois ; le serveur intermédiaire est retiré, et le
   secret du webhook renouvelé.
5. **Prévention** : chaque entrée externe suit la grille de la leçon
   (signée, datée, unique) ; le tableau crédite par identifiant de
   confirmation dans une inbox (leçon 8.3) ; le rapprochement avec
   l'opérateur devient automatique et quotidien, avec une alerte au
   premier écart.

## Ce qu'il faut retenir

- Une signature dit qui, pas combien de fois ni quand.
- Les renvois honnêtes et les copies malveillantes se traitent pareil.
- Un rapprochement avec l'extérieur voit ce que la cryptographie ne voit
  pas.
