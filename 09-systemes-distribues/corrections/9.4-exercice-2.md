# Correction 9.4 — Exercice 2 : les signaux de chaque route

> Rappel de l'énoncé : un intergiciel qui compte, par route, les
> requêtes, les erreurs du service et un histogramme de latence.

La solution est dans `ex2` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Un `ResponseWriter` enveloppé** retient le statut écrit ; sans
  statut écrit, c'est 200.
- **Seuls les 5xx** sont des erreurs du service.
- **La route est un nom fixe**, pas l'URL : `/members/42` ferait une série
  par membre.

## 1. La solution

```go
func (g *Registry) Instrument(route string, next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        rec := &status{ResponseWriter: w, code: http.StatusOK}
        start := time.Now()
        next.ServeHTTP(rec, r)
        took := time.Since(start)
        g.mu.Lock()
        defer g.mu.Unlock()
        if g.requests == nil {
            g.requests, g.errors, g.latency = map[string]int{}, map[string]int{}, map[string]*metrics.Histogram{}
        }
        if g.latency[route] == nil {
            g.latency[route] = &metrics.Histogram{Bounds: Bounds}
        }
        g.requests[route]++
        if rec.code >= 500 {
            g.errors[route]++
        }
        g.latency[route].Observe(took)
    })
}
```

```go
// status remembers the status the handler wrote.
type status struct {
    http.ResponseWriter
    code    int
    written bool
}
```

```text
ok      example/corrections94/ex2       1.072s
```

`written` garde le **premier** statut écrit : un gestionnaire qui
appelle `WriteHeader` deux fois a envoyé le premier, le second est
ignoré par `net/http`.

## 2. Pourquoi un 400 n'est pas une erreur du service

Un `400` dit que la requête était fausse : un montant négatif, un champ
manquant. Le service a fait son travail en la refusant. Le compter comme
une erreur ferait dépendre l'objectif du service de la qualité des
requêtes de ses clients : une application boguée chez un partenaire
brûlerait le budget de l'API. On compte les `4xx` à part : une hausse
soudaine dit qu'un client a changé, ou qu'une validation est trop
stricte, mais elle ne réveille personne.

Il y a une exception : un `429` qui vient de la protection du service
(leçon 9.3) quand le membre n'a rien fait de mal est, du point de vue du
membre, un échec. On le surveille avec les erreurs.

## Ce qu'il faut retenir

- On retient le statut en enveloppant le `ResponseWriter`.
- Les erreurs du service sont les 5xx.
- Une étiquette de route, pas une URL.
