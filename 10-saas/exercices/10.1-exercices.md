## Exercice 1 — Compréhension : qui arrête la fuite ?

*Niveau 1. Aucune ligne de code à écrire.*

### 1.a — Six situations

Pour chacune, dis ce qui arrête la fuite parmi : le filtre dans la
requête, la politique de sécurité par ligne, la clé étrangère composite,
le réglage par transaction, le rôle d'application. Dis aussi si rien ne
l'arrête.

1. Une nouvelle requête de statistiques oublie `WHERE tenant_id = $1`.
2. Le travail de nuit qui calcule les pénalités ne déclare pas
   l'association.
3. L'API reçoit une cotisation de l'association `t004` au nom d'un membre
   de `t009`.
4. Un développeur lance l'application avec l'utilisateur `postgres`
   « pour aller plus vite ».
5. Le middleware lit l'association dans un paramètre `?tenant=` de la
   requête.
6. Une vieille route fait encore `SET app.tenant = ...` au début de
   chaque appel.

### 1.b — Trois pourquoi

1. Pourquoi la clé primaire commence-t-elle par `tenant_id`, et pas par
   `id` ?
2. Pourquoi un travail de fond qui ne voit aucune ligne vaut-il mieux
   qu'un travail qui voit celles d'une autre association ?
3. Pourquoi les migrations tournent-elles avec un autre rôle que
   l'application ?

### 1.c — Le sens des mesures

Dans `cmd/leak`, avec le réglage de session, 2 à 4 rappels sur 198
reviennent vides, et aucun ne fuit. Pourquoi ceux-là ? Que se passerait-il
avec un pool de 64 connexions au lieu de 8 ?

## Exercice 3 — Refactoring : les prêts d'une seule tontine

*Niveau 3. Réécrire un schéma ; les tests sont fournis.*

Le module des prêts a été écrit quand l'application ne servait qu'une
tontine. Réécris le schéma pour qu'un prêt ou une garantie ne puisse
jamais désigner un membre ou un prêt d'une autre association, que deux
associations puissent avoir chacune un membre `m1`, et que le rôle de
l'application ne voie que les lignes de son association :

```go
// Schema is the loans as they were written for a single tontine. Rewrite
// it so that a loan or a guarantee can never point to a member or a loan
// of another association, so that two associations may both have a
// member m1, and so that the application's role sees only the rows of the
// association set in app.tenant.
const Schema = `
CREATE TABLE members (
    id        text PRIMARY KEY,
    tenant_id text NOT NULL,
    name      text NOT NULL

CREATE TABLE loans (
    id        text PRIMARY KEY,
    tenant_id text   NOT NULL,
    borrower  text   NOT NULL REFERENCES members (id),
    amount    bigint NOT NULL
);
CREATE TABLE guarantees (
    loan_id   text NOT NULL REFERENCES loans (id),
    guarantor text NOT NULL REFERENCES members (id),
    PRIMARY KEY (loan_id, guarantor)
);`
```

## Exercice 4 — Design : trois clients, trois modèles ?

*Niveau 4. Aucune ligne de code : une page.*

Trois clients signent le même mois :

1. **La tontine des commerçants de Mokolo** : 35 membres, l'offre
   gratuite.
2. **Une mutuelle de santé** de 40 000 adhérents, dont le contrat exige
   que ses données soient dans une base à part, sauvegardée et
   restaurable seule.
3. **Une fédération** de 200 tontines de village, qui veut un tableau
   consolidé de toutes ses tontines, et que chaque tontine ne voie que
   ses membres.

Pour chacun : quel modèle (pool, bridge, silo), pourquoi, et ce que ce
choix coûte. Puis : comment le code de l'application trouve-t-il les
données d'une association sans savoir dans quel modèle elle est ?
Comment la fédération voit-elle ses 200 tontines sans voir les autres ?

## Exercice 5 — Incident : les rappels du 1er décembre

*Niveau 7. Un incident à mesurer, puis à rejouer comme il aurait dû
être fait.*

Le mardi 1er décembre 2026, une semaine après l'activation des politiques
de sécurité par ligne, des membres reçoivent des rappels de paiement
d'associations dont ils n'ont jamais entendu parler. Le support reçoit
ses premiers appels à 9 h 40. La matinée se rejoue ainsi :

```go
// December1 plays the morning of 1 December 2026 on 40 associations of
// 100 members, 50 of them unpaid, with a pool of 8 connections for the
// application's role: 600 requests of the treasurers, then the reminders
// job of each association. reader makes the reader the platform uses.
func December1(ctx context.Context, reader func(*pgxpool.Pool) tenancy.Reader) ([]Sent, error) {
    owner, drop, err := pg.Fresh(ctx, tenancy.Schema+tenancy.Policies)
    if err != nil {
        return nil, err
    }
    defer drop()
    if err := tenancy.Seed(ctx, owner, 40, 100); err != nil {
        return nil, err
    }
    role, unrole, err := tenancy.AppRole(ctx, owner, pg.Schema(owner), "app")
    if err != nil {
        return nil, err
    }
    defer unrole()
    app, err := pg.OpenConfig(ctx, pg.Schema(owner), func(c *pgxpool.Config) {
        c.ConnConfig.User, c.ConnConfig.Password = role, "app"
        c.MaxConns = 8
    })
    if err != nil {
        return nil, err
    }
    defer app.Close()
    rd := reader(app)

    type call struct{ tenant, route string }
    r := rand.New(rand.NewPCG(2026, 12))
    var morning, jobs []call
    for range 600 {
        route := []string{"members", "unpaid"}[r.IntN(2)]
        morning = append(morning, call{fmt.Sprintf("t%03d", 1+r.IntN(40)), route})
    }
    for t := 1; t <= 40; t++ {
        jobs = append(jobs, call{fmt.Sprintf("t%03d", t), "reminders"})
    }

    var mu sync.Mutex
    var sent []Sent
    var first error
    for _, calls := range [][]call{morning, jobs} {
        work := make(chan call)
        var wg sync.WaitGroup
        for range 8 {
            wg.Go(func() {
                for c := range work {
                    rows, err := rd(ctx, c.tenant, c.route)
                    mu.Lock()
                    if err != nil && first == nil {
                        first = err
                    }
                    if c.route == "reminders" {
                        for _, row := range rows {
                            sent = append(sent, Sent{c.tenant, row.Tenant, row.ID})
                        }
                    }
                    mu.Unlock()
                }
            })
        }
        for _, c := range calls {
            work <- c
        }
        close(work)
        wg.Wait()
    }
    return sent, first
}
```
