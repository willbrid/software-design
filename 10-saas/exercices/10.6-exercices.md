Cinq exercices, du plus simple au plus ouvert. Traite-les **dans l'ordre** et
écris tes réponses dans `mes-reponses/` avant d'ouvrir les corrections.

Les exercices s'appuient sur les paquets de la
[leçon 10.6](../cours/10.6-les-webhooks-sortants.md) (`deliver`, `order`,

besoin que de la bibliothèque standard. Tout le code ci-dessous compile

## Exercice 1 — Compréhension : quelle règle manque ?

*Niveau 1. Aucune ligne de code à écrire.*

### 1.a — Six situations

Pour chacune, dis quelle règle de la leçon manque, et ce qu'elle aurait
changé.

1. Le serveur de la comptabilité d'une mutuelle met 12 s à répondre ;
   chaque versement de la plateforme prend 12 s.
2. Un abonné en panne depuis vendredi soir ; le lundi matin, tous les
   abonnés reçoivent leurs événements avec une heure de retard.
3. Un abonné en panne depuis trois semaines reçoit encore trois
   tentatives par événement.
4. Un abonné enregistre `https://hooks.exemple.cm`, qui pointe le
   lendemain vers `10.0.3.7`.
5. Le tableau d'une fédération affiche le statut « en attente » pour une
   cotisation pourtant confirmée : l'événement « en attente », réessayé,
   est arrivé après « confirmée ».
6. Un abonné découvre que des événements lui ont été envoyés par
   quelqu'un d'autre que la plateforme.

### 1.b — Trois pourquoi

1. Pourquoi la vérification des adresses se fait-elle dans `Control` du
   `net.Dialer`, et pas sur l'URL avant l'appel ?
2. Pourquoi couper un abonné ne doit-il jamais jeter ses événements ?
3. Pourquoi un événement-signal (« le membre m417 a changé ») résout-il
   aussi un problème de confidentialité ?

### 1.c — Le sens des mesures

Dans `cmd/isolate`, l'abonné `s00` reçoit 306 tentatives dans les deux
premières lignes, mais les autres abonnés passent de 3,9 s à 6 ms. Les
tentatives vers `s00` sont les mêmes ; qu'est-ce qui a changé ? Et
pourquoi `s00` garde-t-il 102 événements, alors qu'il en a reçu 102 ?

## Exercice 3 — Refactoring : le versement qui attend la comptabilité

*Niveau 3. Réécrire deux méthodes ; les tests sont fournis.*

Le versement prévient le système de l'association pendant la requête :

```go
// ExecutePayout records a payout and tells the association's system.
// Rewrite it so that it never waits for that system: the event goes into
// the outbox with the payout, and Deliver sends it later.
func (p *Platform) ExecutePayout(ctx context.Context, tenant, id string, amount int64) error {
    body := fmt.Sprintf(`{"type":"payout.executed","id":%q,"amount":%d}`, id, amount)
    req, err := http.NewRequestWithContext(ctx, "POST", p.Subscribers[tenant], strings.NewReader(body))
    if err != nil {
        return err
    }
    resp, err := p.Client.Do(req)
    if err != nil {
        return err
    }
    resp.Body.Close()
    p.mu.Lock()
    p.Payouts = append(p.Payouts, id)
    p.mu.Unlock()
    return nil
}
```

## Exercice 5 — Incident : les numéros d'octobre

*Niveau 7. Un incident à mesurer, puis à rejouer comme il aurait dû
être fait.*

Une fédération reçoit les changements de numéro de ses membres par
webhook, et envoie chaque soir à 18 h un rappel à chaque membre. Fin
octobre 2026, des membres se plaignent de ne plus recevoir les rappels ;
d'autres disent qu'un ancien numéro, rendu à l'opérateur, en reçoit.
Le mois se rejoue ainsi :

```go
// October returns the phone changes of 800 members during October 2026
// (in the order they were made), and the webhooks as the federation's
// system received them: about one attempt in eight fails, and is tried
// again 10 minutes later.
func October() (history []order.Update, arrivals []order.Arrival) {
    r := rand.New(rand.NewPCG(2026, 10))
    oct1 := time.Date(2026, 10, 1, 0, 0, 0, 0, time.UTC)
    for m := range 800 {
        at := oct1.Add(time.Duration(r.Int64N(int64(24 * time.Hour))))
        for v := 1; v <= 1+r.IntN(4); v++ {
            if v > 1 {
                // A member who changes phone often does it within minutes:
                // a wrong number corrected, a second SIM card.
                at = at.Add(time.Duration(r.Int64N(int64(30*time.Minute))) + time.Duration(r.IntN(10))*24*time.Hour)
            }
            u := order.Update{Member: fmt.Sprintf("m%03d", m), Version: v, Phone: fmt.Sprintf("+237 6%02d%06d", v, m), Sent: at}
            history = append(history, u)
            arrive := at
            for {
                arrive = arrive.Add(time.Duration(r.ExpFloat64() * float64(time.Second)))
                if r.IntN(8) != 0 {
                    break
                }
                arrive = arrive.Add(10 * time.Minute)
            }
            arrivals = append(arrivals, order.Arrival{Update: u, At: arrive})
        }
    }
    return history, arrivals
}
```
