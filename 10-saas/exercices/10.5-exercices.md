## Exercice 1 — Compréhension : qu'est-ce qui le voit ?

*Niveau 1. Aucune ligne de code à écrire.*

### 1.a — Six situations

Pour chacune, dis ce qui la détecte ou l'empêche parmi : la même
transaction, les droits du rôle, les déclencheurs, la chaîne, l'ancre.
Dis aussi si rien ne la voit.

1. Le processus meurt juste après avoir validé un versement.
2. Une injection SQL dans la recherche lance `DELETE FROM audit_log`.
3. Un administrateur de la base change le montant d'une entrée, sans
   toucher aux hachages.
4. Le même administrateur change l'entrée et recalcule toute la chaîne.
5. Une migration lancée sur la mauvaise base vide le journal avec
   `TRUNCATE`.
6. Quelqu'un qui a les clés de la base **et** la boîte aux lettres de la
   présidente réécrit le journal et les ancres reçues.

### 1.b — Trois pourquoi

1. Pourquoi la position de l'entrée fait-elle partie du hachage ?
2. Pourquoi chaque champ est-il écrit avec sa longueur avant d'être
   haché ?
3. Pourquoi chaque association a-t-elle sa propre chaîne, et pas une
   seule chaîne pour toute la plateforme ?

### 1.c — Le sens des mesures

Dans `cmd/tamper`, la modification simple de l'entrée 4 321 casse la
chaîne, mais **l'ancre tient**. Pourquoi ? Que faudrait-il que fasse
celui qui modifie pour que la chaîne ne casse pas, et que se passe-t-il
alors ?

*Niveau 2. Écrire une fonction ; les tests sont fournis.*

```go
    return ""
```

## Exercice 3 — Refactoring : un rôle donné, et une ligne de journal

*Niveau 3. Réécrire une fonction ; les tests sont fournis.*

Le don d'un rôle est « journalisé » par une ligne de journal technique,
après la transaction :

```go
// Grant gives role in tenant to user, on behalf of actor. Rewrite it so
// that the grant and its entry in the journal (action "role.grant",
// object the user, detail "role: (none) -> <role>") are written in one
// transaction: both, or neither.
func Grant(ctx context.Context, pool *pgxpool.Pool, tenant, actor, user, role string) error {
    err := pgx.BeginFunc(ctx, pool, func(tx pgx.Tx) error {
        _, err := tx.Exec(ctx, `INSERT INTO grants (tenant_id, user_id, role) VALUES ($1, $2, $3)`, tenant, user, role)
        return err
    })
    log.Printf("audit: %s granted %s to %s in %s (err=%v)", actor, role, user, tenant, err)
    return err
}
```

## Exercice 4 — Design : le journal et le droit à l'oubli

*Niveau 4. Aucune ligne de code : une page.*

Un ancien membre demande que la plateforme efface ses données
personnelles. Le journal d'audit est en ajout seul, chaîné, et contient
son nom dans des centaines d'entrées (« Awa Ngono a reçu 200 000 FCFA »).

Propose une conception qui permette d'effacer ce qui doit l'être sans
casser la chaîne ni perdre la preuve des versements : que met-on dans le
journal à la place des noms ? Où vivent les noms ? Que reste-t-il,
après l'effacement, pour un auditeur qui vérifie un versement de 2025 ?
Combien de temps garde-t-on le journal, et qui peut le lire ?

## Exercice 5 — Incident : la nuit du 9 octobre

*Niveau 7. Un incident à mesurer, puis à rejouer comme il aurait dû
être fait.*

Le 20 octobre 2026, la présidente de `t07` conteste un versement de
septembre : le journal dit 1 000 FCFA, elle se souvient de plus. La
chaîne du journal se vérifie sans erreur. Mais elle a gardé les ancres
reçues chaque nuit. Les deux mois se rejouent ainsi :

```go
// October plays September and October 2026 in t07: 40 payouts a day,
// each written with audit.Record; every night at 23:59, the last link is
// mailed to the president. On 9 October at 02:10, someone logged in with
// the application's credentials changes the amount of payout p00874
// (22 September) in the journal, and recomputes the chain from there.
// grants are the rights the application's role has on audit_log. October
// returns the journal on 31 October, and the anchors mailed.
func October(ctx context.Context, grants string) ([]Stored, []Night, error) {
    owner, drop, err := pg.Fresh(ctx, audit.Schema)
    if err != nil {
        return nil, nil, err
    }
    defer drop()
    schema := pg.Schema(owner)
    role := "app_" + schema
    for _, sql := range []string{
        fmt.Sprintf("CREATE ROLE %s LOGIN PASSWORD 'app'", role),
        fmt.Sprintf("GRANT USAGE ON SCHEMA %s TO %s", schema, role),
        fmt.Sprintf("GRANT %s ON %s.audit_log TO %s", grants, schema, role),
        fmt.Sprintf("GRANT SELECT, INSERT, UPDATE ON %s.audit_heads TO %s", schema, role),
    } {
        if _, err := owner.Exec(ctx, sql); err != nil {
            return nil, nil, err
        }
    }
    defer owner.Exec(context.Background(), fmt.Sprintf("DROP OWNED BY %s; DROP ROLE %s", role, role))
    app, err := pg.OpenConfig(ctx, schema, func(c *pgxpool.Config) { c.ConnConfig.User, c.ConnConfig.Password = role, "app" })
    if err != nil {
        return nil, nil, err
    }
    defer app.Close()

    var nights []Night
    n := 0
    for day := sep1; day.Month() <= time.October; day = day.AddDate(0, 0, 1) {
        if day.Equal(time.Date(2026, 10, 9, 0, 0, 0, 0, time.UTC)) {
            tamper(ctx, app) // the error, if any, is what the attacker sees
        }
        for k := range 40 {
            n++
            e := audit.Entry{Tenant: "t07", Actor: fmt.Sprintf("treasurer-%d", k%2), Action: "payout.execute",
                Object: fmt.Sprintf("p%05d", n), Detail: fmt.Sprintf("amount=%d", 10000+(n*37)%90*1000),
                At: day.Add(8*time.Hour + time.Duration(k)*10*time.Minute)}
            if err := pgx.BeginFunc(ctx, app, func(tx pgx.Tx) error { return audit.Record(ctx, tx, e) }); err != nil {
                return nil, nil, err
            }
        }
        c, err := audit.Verify(ctx, owner, "t07")
        if err != nil {
            return nil, nil, err
        }
        nights = append(nights, Night{day.Add(23*time.Hour + 59*time.Minute), audit.Anchor{Seq: int64(c.Entries), Hash: c.Head}})
    }
    journal, err := read(ctx, owner)
    return journal, nights, err
}
```
