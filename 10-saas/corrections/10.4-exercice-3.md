# Correction 10.4 — Exercice 3 : les SMS du mois

> Rappel de l'énoncé : réécrire `Send` avec le compteur `sms_usage`, dans
> la même transaction que le journal.

La solution est dans `ex3` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Une seule instruction** crée le compteur du mois ou l'incrémente,
  seulement s'il reste des SMS.
- **L'offre à zéro SMS est refusée avant** : la création du compteur ne
  regarde pas la limite.
- **Le journal suit, dans la même transaction.**

## 1. La solution

```go
// Send records one SMS of tenant to member in month, if the offer's limit
// allows it: it takes one SMS from the month's counter, only while some
// are left, in the same transaction as the log.
func Send(ctx context.Context, pool *pgxpool.Pool, tenant string, month time.Time, member string, limit int) error {
    if limit <= 0 {
        return ErrQuota
    }
    return pgx.BeginFunc(ctx, pool, func(tx pgx.Tx) error {
        tag, err := tx.Exec(ctx, `
            INSERT INTO sms_usage (tenant_id, month, used) VALUES ($1, $2, 1)
            ON CONFLICT (tenant_id, month) DO UPDATE SET used = sms_usage.used + 1
            WHERE sms_usage.used < $3`, tenant, month, limit)
        if err != nil {
            return err
        }
        if tag.RowsAffected() == 0 {
            return ErrQuota
        }
        _, err = tx.Exec(ctx, `INSERT INTO sms_log (tenant_id, month, member) VALUES ($1, $2, $3)`,
            tenant, month, member)
        return err
    })
}
```

## 2. Le premier SMS du mois

Deux premiers SMS simultanés font chacun un `INSERT`. Le premier crée la
ligne ; le second rencontre la clé primaire `(tenant_id, month)`, et
`ON CONFLICT` le transforme en `UPDATE` de la ligne, après avoir attendu
la fin de la première transaction. Il n'y a ni deux lignes, ni erreur de
doublon, ni compteur perdu. La clause `WHERE sms_usage.used < $3` ne
s'applique qu'à la branche `UPDATE` : quand elle est fausse, aucune
ligne n'est touchée, et `RowsAffected` vaut 0.

## 3. L'offre à zéro

La branche `INSERT` crée le compteur à 1 sans regarder la limite. Avec
une limite de 0, le premier SMS passerait. D'où le refus avant la
transaction : c'est le cas que le test `TestNoSMSInTheFreeOffer`
vérifie, et la mutation « offre gratuite oubliée » le confirme.

## 4. Ce que l'énoncé montrait

La version d'origine laissait partir entre 20 et 31 SMS pour une limite
de 20 (le nombre change à chaque exécution), et n'écrivait jamais le
compteur. C'est la course de la leçon, avec un `count(*)` sur le
journal au lieu des membres.

## Ce qu'il faut retenir

- `INSERT ... ON CONFLICT DO UPDATE ... WHERE` prend une place, ou crée
  le compteur, en une instruction.
- La branche qui crée ne voit pas la condition : les cas limites se
  traitent avant.
- Le compteur et ce qu'il compte changent ensemble.
