# Correction 10.1 — Exercice 2 : une seule porte vers les données

> Rappel de l'énoncé : écrire `WithTenant`, qui ouvre une transaction ne
> voyant que les lignes d'une association.

La solution est dans `ex2` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Refuser l'association vide avant tout travail.**
- **Régler l'association dans la transaction**, avec `set_config(...,
  true)`.
- **Laisser `pgx.BeginFunc` valider ou annuler** selon l'erreur de `fn`.

## 1. La solution

```go
// WithTenant runs fn in a transaction that sees only the rows of tenant,
// and commits if fn returns nil. The setting ends with the transaction;
// an empty tenant is refused before anything runs.
func WithTenant(ctx context.Context, pool *pgxpool.Pool, tenant string, fn func(pgx.Tx) error) error {
    if tenant == "" {
        return ErrNoTenant
    }
    return pgx.BeginFunc(ctx, pool, func(tx pgx.Tx) error {
        if _, err := tx.Exec(ctx, "SELECT set_config('app.tenant', $1, true)", tenant); err != nil {
            return err
        }
        return fn(tx)
    })
}
```

## 2. Pourquoi refuser l'association vide

`set_config('app.tenant', '', true)` est accepté par PostgreSQL : la
transaction ne verrait aucune ligne, ce qui est fermé, mais `fn`
tournerait, écrirait peut-être, et l'erreur arriverait loin de sa cause.
`ErrNoTenant` nomme le bug là où il est : quelqu'un a appelé la porte
sans savoir pour quelle association.

## 3. Le test qui passait sans rien prouver

`TestCannotWriteForAnother` attend une erreur ; la fonction vide en
renvoie une, pour une tout autre raison. Le test passe, et ne prouve
rien. C'est le défaut que la campagne de la leçon a trouvé sur le rôle
d'application : un test d'isolement doit vérifier qu'on refuse ce qui
est interdit **et** qu'on accepte ce qui est permis.
`TestCommitsOrRollsBack` joue le second rôle : il écrit pour `t001`
dans une session de `t001`, et vérifie que la ligne est là.

Une version plus stricte du test vérifierait aussi la **nature** de
l'erreur : `new row violates row-level security policy`, et non « not
implemented ».

## 4. Une seule porte

Si `WithTenant` est le seul chemin vers le pool de l'application, une
recherche dans le code suffit à vérifier la règle : aucun autre appel à
`pool.Query`, `pool.Exec` ou `pool.Begin`. Un test d'architecture (leçon
7.5) peut le faire automatiquement.

## Ce qu'il faut retenir

- Une seule fonction ouvre les transactions d'une association.
- L'association vide est un bug, signalé tout de suite.
- Un test d'isolement prouve le refus **et** l'accord.
