# Correction 10.2 — Exercice 3 : des noms de rôles dans chaque route

> Rappel de l'énoncé : remplacer les tests sur les noms de rôles par une
> permission par route et une table des rôles.

La solution est dans `ex3` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **Chaque route déclare une permission** ; une route absente est
  refusée.
- **Une table dit ce que chaque rôle permet** ; un rôle absent ne peut
  rien.
- **Ajouter un rôle, c'est une ligne**, et la matrice de tests le
  vérifie.

## 1. La solution

```go
// Needs says which permission each route needs. A route that is not
// listed is refused.
var Needs = map[Route]Permission{
    ListMembers: "members.read",
    Invite:      "members.invite",
    Record:      "contributions.record",
    Report:      "reports.read",
    Export:      "reports.export",
    Approve:     "payouts.approve",
    Execute:     "payouts.execute",
    Settings:    "settings.edit",
}
```

```go
// Roles says what each role may do. A role that is not listed may do
// nothing: the guest is listed only to say so.
var Roles = map[string][]Permission{
    "member":    {"members.read"},
    "treasurer": {"members.read", "contributions.record", "reports.read", "reports.export", "payouts.execute"},
    "president": {"members.read", "members.invite", "reports.read", "reports.export", "payouts.approve", "settings.edit"},
    "auditor":   {"members.read", "reports.read", "reports.export"},
    "deputy":    {"members.read", "contributions.record", "reports.read"},
    "guest":     {},
}
```

```go
// Allowed says whether a holder of role may call route.
func Allowed(role string, route Route) bool {
    p, ok := Needs[route]
    return ok && slices.Contains(Roles[role], p)
}
```

## 2. Le droit que personne n'avait vu

La première ligne rouge de l'énoncé est `president POST /contributions
true, want false`. Ce droit existait **depuis le premier jour** :
`role != "member"` laissait passer tout ce qui n'est pas membre, donc la
présidente. Personne ne l'avait vu parce que personne ne l'avait écrit :
il était la conséquence d'une négation. Une liste qui interdit donne
tout le reste, y compris ce qui n'existe pas encore (la commissaire, et
même l'invité).

C'est le rôle de la matrice : elle écrit, pour chaque rôle et chaque
route, ce qu'on attend. Elle a trouvé sept écarts, dont un ancien.

## 3. La route inconnue

`Allowed` vérifie `ok` (la route a une permission). Sans cette
vérification, une route absente de `Needs` demanderait la permission
vide `""`, qu'aucun rôle n'a : elle serait refusée quand même. La
vérification ne change donc rien aujourd'hui ; elle dit au lecteur que
l'absence est un refus voulu, et protège du jour où quelqu'un écrirait
une liste de permissions avec une chaîne vide.

## Ce qu'il faut retenir

- Le code demande des permissions ; les rôles sont des données.
- Une négation sur un nom de rôle donne des droits à tout rôle futur.
- La matrice rôle × route est le test qui trouve les droits oubliés.
