# Correction 10.2 — Exercice 5 : les versements de l'été 2026

> Rappel de l'énoncé : comparer le journal des versements de 2026 aux
> mandats, rejouer avec des rôles datés, rédiger.

L'audit et le rejeu sont dans `ex5` du module de correction, verts sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **21 versements exécutés par d'anciens trésoriers**, pour **3 600 000
  FCFA**, dans trois associations.
- **9 d'entre eux approuvés par la personne qui les exécutait** : la
  trésorière de 2023, présidente en 2024, avait gardé les deux rôles.
- **Des mandats datés les auraient tous refusés** ; une règle de
  séparation des tâches aurait arrêté les 9 de `t007` même avec un
  mandat en cours.

## 1. L'audit

```go
func Audit(offices []Office, payouts []Payout) Report {
    r := Report{Payouts: len(payouts)}
    for _, p := range payouts {
        if !held(offices, p.Tenant, "treasurer", p.ExecutedBy, p.At) {
            r.ByFormer++
            r.ByFormerFCFA += p.Amount
        }
        if p.ApprovedBy == p.ExecutedBy {
            r.SelfApproved++
        }
    }
    return r
}
```

```go
// held says whether user held role in tenant at at.
func held(offices []Office, tenant, role, user string, at time.Time) bool {
    for _, o := range offices {
        if o.Tenant == tenant && o.Role == role && o.User == user && !at.Before(o.From) && at.Before(o.To) {
            return true
        }
    }
    return false
}
```

```go
func Mandates(offices []Office) []authz.Grant {
    grants := make([]authz.Grant, 0, len(offices))
    for _, o := range offices {
        grants = append(grants, authz.Grant{User: o.User, Tenant: o.Tenant, Role: o.Role, Until: o.To})
    }
    return grants
}
```

## 2. Les chiffres, et le rejeu

`cmd/payouts` audite le journal, puis le rejoue :

```text
30 associations, 1 January to 31 October 2026: 621 payouts
executed by someone who was not treasurer then: 21, 3600000 FCFA
approved by the one who executed them:          9

replayed with                       refused
the grants of the platform                0
grants until the mandate ends            21  (t007: 9, t013: 6, t021: 6)
```

- **Les rôles de la plateforme ne refusent rien** : chaque élection
  depuis 2022 a donné des rôles, aucune n'en a retiré. Les 21 versements
  sont passés normalement ; aucune alerte ne pouvait les signaler.
- **Des rôles jusqu'à la fin du mandat** refusent exactement les 21, et
  aucun versement ordinaire : ceux du 5 janvier, exécutés par les
  trésoriers de 2025 dix jours avant la passation, passent.
- **`t007`** : la personne a été trésorière en 2023 et présidente en
  2024. Avec des rôles sans fin, elle pouvait exécuter **et** approuver.
  Une règle « celle qui exécute n'approuve pas » (l'approfondissement de
  la leçon) l'aurait arrêtée même en plein mandat, si elle avait cumulé
  les deux fonctions.

## 3. La cause

**En une phrase** : les rôles donnés à chaque élection n'avaient pas de
fin, et aucune passation ne retirait ceux des sortants ; trois anciens
membres du bureau ont pu verser pendant des mois.

**La cause de la cause** : le modèle des rôles avait été conçu pour une
tontine dont le bureau ne change pas dans l'application ; l'élection
était un événement du domaine, la passation des droits n'en était pas
une. Et l'approbation, censée protéger, vérifiait un rôle et non une
relation : approuver son propre versement était permis.

## 4. Le compte rendu

1. **Quoi** : de janvier à octobre 2026, 21 versements (3 600 000 FCFA)
   ont été exécutés dans trois associations par d'anciens trésoriers,
   dont 9 approuvés par leur auteure.
2. **Cause** : les rôles donnés aux élections n'avaient pas de fin, et
   l'approbation ne vérifiait pas qu'elle venait d'une autre personne.
3. **Détection** : par le rapprochement annuel de novembre, plusieurs
   mois après les premiers versements ; aucune alerte.
4. **Correction** : les rôles des sortants sont terminés à la date de
   chaque passation passée ; l'élection appelle la passation
   (`Handover`) dans la même transaction ; l'approbation refuse un
   versement exécuté par la même personne ; les associations concernées
   sont prévenues pour engager le recouvrement.
5. **Prévention** : chaque rôle a une fin ; un rapport mensuel liste, par
   association, les personnes qui peuvent verser, envoyé au bureau ; une
   alerte se déclenche quand un versement est exécuté hors des horaires
   habituels de l'association ou approuvé par son auteur.
