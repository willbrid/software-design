# Correction 10.6 — Exercice 2 : l'adresse enregistrée

> Rappel de l'énoncé : écrire `CheckURL`, qui refuse à l'enregistrement
> les adresses évidemment mauvaises.

La solution est dans `ex2` du module de correction, verte sous
`go vet ./...` et `go test -race -count=1 ./...`.

## En bref

- **`https`, un port attendu, pas d'identifiants, un hôte.**
- **Le nom `localhost` refusé sous toutes ses écritures**, une adresse
  IP vérifiée avec `safehttp.Internal`.
- **Un nom ordinaire est accepté** : on ne sait pas encore où il mène,
  et c'est le client qui le vérifiera.

## 1. La solution

```go
func CheckURL(raw string) error {
    u, err := url.Parse(raw)
    if err != nil || u.Scheme != "https" || u.User != nil || u.Hostname() == "" {
        return ErrAddress
    }
    switch u.Port() {
    case "", "443", "8443":
    default:
        return ErrAddress
    }
    host := strings.TrimSuffix(strings.ToLower(u.Hostname()), ".")
    if host == "localhost" || strings.HasSuffix(host, ".localhost") {
        return ErrAddress
    }
    if ip, err := netip.ParseAddr(host); err == nil && safehttp.Internal(ip) {
        return ErrAddress
    }
    return nil
}
```

## 2. Pourquoi vérifier deux fois

La vérification à la connexion est celle qui protège. Celle de
l'enregistrement sert l'abonné et le support :

- **l'abonné** apprend tout de suite que `http://` ou `localhost` ne
  marchera jamais, au lieu de découvrir trois jours plus tard qu'aucun
  événement n'est arrivé ;
- **le support** n'a pas, dans sa liste d'abonnés coupés, des adresses
  qui n'avaient aucune chance ;
- **les tentatives d'abus** se voient à l'enregistrement : un abonné qui
  essaie `169.254.169.254` mérite une alerte, pas seulement un refus
  silencieux plus tard.

Mais elle ne suffit pas : `hooks.exemple.cm` est accepté aujourd'hui,
et peut pointer vers une adresse interne demain.

## 3. Les écritures de localhost

`LOCALHOST.` (majuscules, point final) désigne le même hôte que
`localhost`. La version qui comparait le nom brut l'acceptait ; la
mutation « LOCALHOST. passe » le vérifie. Et tout nom en `.localhost`
est réservé à la machine elle-même : il est refusé aussi.

## Ce qu'il faut retenir

- La vérification à l'enregistrement informe ; celle de la connexion
  protège.
- Un même hôte s'écrit de plusieurs façons : on normalise avant de
  comparer.
- Un nom ordinaire ne se juge qu'à la connexion.
